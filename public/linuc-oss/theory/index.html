理論編 — オープンソースの文化

LinuC レベル1 102 試験・主題1.11（オープンソースの概念とライセンス / コミュニティとエコシステム）を、 どの Ubuntu にも入っているライセンスの実物を読んで確かめる4章。 知識問題の主題ですが、条文を覚える前に、条文がどこにあるかを先に手元で見ます。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この4章を貫いている1つの事実

オープンソースは、権利を手放したソフトではない。持ち主が条件を書いて出した許可で、その条件と連絡先はソフトと一緒に配られている。

ls --version には持ち主の名前と NO WARRANTY が出る。マニュアルを全部捨てた最小構成の Ubuntu でも、 /usr/share/doc/*/copyright だけは 92 個残っている。GPL の条件は「配るとき」に効き、MIT の条件は「表示を残すこと」で、 条件の無いパブリックドメインは「持ち主がいない」状態だった。不具合の報告先も --help と /etc/os-release に書いてある。 だから主題1.11 は知識問題でありながら、答えの根拠が手元の1台に全部入っています。

ここで覚えなくていいこと: ライセンス同士の互換性の一覧、「リンクすると派生物になるか」の法的な議論、国ごとの著作権法の違い、 GPL-2 と GPL-3 の細かい差（機器への組み込み・特許の報復）、各プロジェクトの投稿の作法。 どれもレベル1の範囲外で、この4章では深入りしません。

このコースに演習が無い理由

主題1.11 は知識問題で、出題範囲の「詳細」欄に打つコマンドが1つもありません。 このシリーズの演習は、lab check が状態を実際に観測して合否を出す形で作っています （ファイルの中の文字列を探すだけの判定は、挙動で確かめられないときの最後の手段です）。 ライセンスを理解したかどうかは、コンテナの中の状態として観測できません。 檻を作っても、観測型の判定を持つ演習が作れないので、演習と専用の檻は作りませんでした。

そのかわり、本文の端末表示はすべて、Docker Hub の公式の素の Ubuntu イメージ （ubuntu:24.04@sha256:008173c2…、シリーズの他のコースの土台と同じもの）で記録してあります。 同じイメージを起動すれば同じ画面が出ます。打つのは grep・sed・ls・dpkg など、 読むだけのコマンドです（影響度 A）。起動のしかたは入口にあります。

ライセンスを、条件の重い順に1枚にまとめるとこうなります。

ライセンス種類改変版を配るときの条件ソースを出す範囲条件が生まれるとき
AGPLコピーレフト同じライセンス・ソースを渡す作品全体配布、改変版をネットワーク越しに使わせるとき
GPLコピーレフト同じライセンス・ソースを渡す・改変を明記作品全体配布
LGPLコピーレフト（ライブラリ）ライブラリ部分は同じライセンス。組み合わせた作品は自由ライブラリ部分配布
MPLコピーレフト（ファイル単位）改変した MPL のファイルは同じライセンス改変したファイル配布
Apache 2.0許可型写し・改変の明記・表示・NOTICE。特許の許可あり出さなくてよい配布
BSD（3条項）許可型表示を残す（バイナリでも）・名前を宣伝に使わない出さなくてよい配布
MIT（Expat）許可型著作権表示と許諾文を含める出さなくてよい配布
パブリックドメイン権利なしなし出さなくてよい—

特許について条文で触れているかは、grep -ic patent で数えた行数で見分けられました（BSD 0・MIT 0・Apache-2.0 6・GPL-3 26）。 コピーレフトの条件が生まれるのは配るとき（AGPL は、改変した版をネットワーク越しに使わせるときも）で、許可型の条件は写しに表示を含めることです。

章

  1. オープンソースには、持ち主がいる — ls --version に Copyright の行。最小構成のイメージがマニュアルを捨てて、copyright だけは 92 個残していた（16分）
  2. コピーレフトは、配るときに効く — GPL は「配らないなら条件なし」と書いている。ネットワーク越しにも効かせるのが AGPL（18分）
  3. 「何をしてもいい」は、パブリックドメインだけ — MIT にも Beerware にも条件がある。同じ許諾文に名前が5つ。ls 1つに4つのライセンス（16分）
  4. 報告先は、ソフトの中に書いてある — bash の報告先は2つ。版番号 5.2.21-2ubuntu4 に3つの層。ここで4章が1本になる（15分）

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの4つに集まります。

場面ここで効く理由見落としやすい点関連する章
オープンソースを改変して社内で使う GPL の義務は配布（convey）で生まれる。社内で使うだけなら条件はない グループ会社や取引先に写しを渡すと、それは配布になる2
製品に組み込んで出荷する 許可型でも、表示とライセンスの写しを付ける条件がある バイナリだけの出荷でも、表示を文書などに載せる（BSD の条件2・GPL の第6条）1・3
Web サービスを作る GPL は写しを渡さない利用を配布と見なさない AGPL のソフトを改変して動かしていると、使わせるだけで条件が生まれる2
不具合を見つけた 窓口は層ごとにあり、連絡先はソフトの中に書いてある 上流か配布元かを切り分け、版・環境・再現の手順を添える4

この教材でしないことも1つあります。個別の製品についてのライセンスの判断 （ライセンス同士を組み合わせてよいか、リンクの仕方で条件が変わるか）です。 この教材が教えるのは条文の読み方と試験の範囲までで、製品の判断は組織の法務の仕事になります。
