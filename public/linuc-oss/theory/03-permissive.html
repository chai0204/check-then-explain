3. 持ち主がいないのは、パブリックドメインだけ

MIT も BSD も Apache も、許可の文のあとに条件が付いている。「この表示を残すこと」。条件の無い許可もまれにあるが、それにも持ち主がいる。素の Ubuntu 1台を探して、持ち主のいない「好きにしてよい」が見つかったのは、パブリックドメインのファイルだけだった。

前提: 第2章まで読了前提: 素の Ubuntu を起動できる（任意）所要 16分影響度 A出題範囲 1.11.1（重要度2）最終検証 2026-10-13

この章のゴール

  • MIT・BSD・Apache が再配布のときに求めるものを、条文から言える
  • Apache License 2.0 の特許条項が何を許し、いつ失効するかを言える
  • パブリックドメインが、条件の少ないライセンスとどこで違うか（持ち主がいるかどうか）を説明できる
ここで覚えなくていいこと: BSD の各版の歴史（宣伝の条件が外れた経緯）、Apache の NOTICE ファイルの書き方、パブリックドメインの国ごとの扱い、ライセンス同士の互換性の一覧は扱わない。試験に要るのは、条件の数と中身、そして特許条項があるかどうかである。

MIT にも、条件がある

この節で分かること: コピーレフトの無いライセンスにも条件があること。

第2章の最後の表で、BSD・MIT・Apache は「コピーレフトが及ばない」側にあった。改変版を同じ条件で配る義務が無いライセンスで、非コピーレフト型、または許可型（パーミッシブ）と呼ぶ。LinuC の出題範囲は「BSD 系（MIT、Apache V2）」とまとめている。

ふつうこう考える

コピーレフトが無いなら、ソースを公開する義務も無い。MIT のコードは、何も気にせず自分の製品に入れてよい。守ることは何もない。

だめな理由: 使う・写す・改変する・配る・売るまで全部許したあとに、subject to the following conditions:（次の条件のもとで）と続いている。 条件は1つ。The above copyright notice and this permission notice shall be included in all copies or substantial portions of the Software. — 上の著作権表示とこの許諾文を、すべての写し（または主要な部分）に含めること。 製品に組み込んで配るなら、表示も一緒に配る。何も書かずに使えば、許可の条件を満たしていない。 ここで Expat と呼ばれているのが、試験で MIT ライセンスと呼ばれるものである（名前の話は後の節で数える）。

「好きにしてよい」とそのまま書いたライセンスもある。冗談のようなものだ。

たとえ: 人の写真を「撮影: ○○」と添えれば自由に使ってよい、という条件で貸してもらうのに近い。 トリミングしても、広告に使っても、売ってもよい。添え書きだけは外さない。
ただし崩れる点: 写真の添え書きは見える場所に1行あれば済むが、ソフトでは「すべての写し」に許諾文ごと含める。バイナリしか配らない製品でも、文書などに載せて一緒に渡す（次の節の BSD の条件2）。

ただし崩れる点: 休戦は双方が合意して結ぶが、この条項は貢献者から使う人へ一方的に出される。使う人は何にも署名せず、受け取った時点で効いている。

持ち主がいないのは、パブリックドメインだけ

この節で分かること: パブリックドメインが「許可」ではなく「持ち主がいない」状態であること。

条件の付かない許可も、まれにある。

$ grep -B2 -A2 '^License: configure' /usr/share/doc/sensible-utils/copyright
Files: configure
Copyright: 1992-1996, 1998-2012, Free Software Foundation, Inc.
License: configure
 This configure script is free software; the Free Software Foundation
 gives unlimited permission to copy, distribute and modify it.

「この configure スクリプトについて、FSF は写すこと・配ること・改変することを無制限に許す」。表示を残せという条件すら無い。イメージの外にも、0BSD のように条件を1つも持たない許可型のライセンスがある。それでも Copyright: の行には持ち主（FSF）がいて、許しているのはその持ち主である。条件が無いことと、持ち主がいないことは別の話である。

持ち主そのものがいないのが、パブリックドメインである。xz の圧縮ライブラリ（liblzma5）の copyright を見る。

$ grep -n 'is in the public domain' /usr/share/doc/liblzma5/copyright | head -3
23:   - liblzma is in the public domain.
217: This file is in the public domain
$ grep -B5 -A1 'do whatever you want with this file' /usr/share/doc/liblzma5/copyright | head -7
           2003, Kevin Springle
           2009, Jonathan Nieder
           2010, Anders F Björklund
License: PD
 This file has been put in the public domain.
 You can do whatever you want with this file.
Comment:

You can do whatever you want with this file. — Beerware と同じ「好きにしてよい」だが、前にも後ろにも条件が付いていない。その前の行は This file has been put in the public domain.（このファイルはパブリックドメインに置かれた）。License: PD の PD は public domain の略である。

パブリックドメインは、著作権が無い状態を指す。持ち主がいないので、許可を出す人も、条件を付ける人もいない。ここが、許可型のライセンスや、上の configure のような条件の無い許可との決定的な違いである。どちらも「持ち主が許す」形で、パブリックドメインは「許す持ち主がいない」。

SELinux のライブラリ（libselinux1。ls がこれを使っていることは、この章の最後で確かめる）も、そう書いている。

public domain software, i.e. not copyrighted（パブリックドメインのソフト、つまり著作権が無い）。作ったのは米国家安全保障局（NSA）で、米国では連邦政府の職員が職務で作った著作物には著作権が生じない。持ち主がいないことにも、こうして理由がある。それでも直後に Warranty Exclusion（保証の除外）を置き、may contain "bugs"（バグを含むかもしれない）と書いている。パブリックドメインのソフトでも、libselinux のように無保証の文を付けているものがある（上の liblzma の段落には付いていない）。

パブリックドメインになる道は3つある。持ち主が権利を手放す、保護期間が切れる、そして上のように最初から著作権が生じない。1つ目のための文書が CC0 で、第1章で冒頭を読んだ。

the purpose of contributing to a commons of creative, cultural and
scientific works ("Commons") that the public can reliably and without fear
of later claims of infringement build upon, modify, incorporate in other

たとえ: 道端に置かれた「ご自由にお持ちください」の箱に近い。持ち帰る人に条件は無く、誰の許可もいらない。
ただし崩れる点: 箱の中身は持っていけば無くなるが、パブリックドメインのコードは誰が使っても減らない。また、箱の品物は置いた人が手放したものだが、パブリックドメインには「最初から誰のものにもならなかった」もの（NSA のライブラリ）も含まれる。

書き出しが同じ許諾文に、5つの名前

この節で分かること: ライセンスの名前が揃っていないこと、だから本文で判断すること。

第1章で、License: の書き方が 155 通りあった。その中には、書き出しが同じ許諾文に別々の名前を付けた例が混じっている。MIT の許諾文の書き出し Permission is hereby granted, free of charge で探して、直前の License: 行を数える。

$ grep -B1 -h '^ Permission is hereby granted, free of charge' /usr/share/doc/*/copyright | grep '^License:' | sort | uniq -c | sort -rn

11 行目と 15 行目は「どのファイルがどのライセンスか」を示す行で、本文は 21 行目（MIT/X11）と 46 行目（X11）から始まる。どちらの本文も、最後に Except as contained in this notice で始まる段落を持っている。「著作権者（X11 では X Consortium）の名前を、書面の許可なく宣伝に使わない」という、もう1つの条件である。Expat の apt と MIT の util-linux の許諾文には、この段落が無い（0件）。名前が違うと、中身も違うことがある。BSD でも BSD-3-clause と BSD-3-Clause が別の行として数えられていた（こちらは大文字と小文字の違いだけ）。

ライセンスは名前ではなく本文で判断する。名前は人が付けたラベルで、効力を持つのは本文である。copyright ファイルが全文を載せるか、/usr/share/common-licenses/ の全文を指しているのはそのためである。

たとえ: 書き出しが同じレシピが、店によって「肉じゃが」「牛じゃが」と呼ばれ、牛じゃがの店だけ最後に一手間足している状態に近い。名前を見ても、どちらに一手間があるかは分からない。
ただし崩れる点: 料理の一手間は味が少し変わるだけだが、ライセンスの1段落は、守る条件が1つ増えることを意味する。だから名前で「たぶん同じ」と済ませず、本文を突き合わせる。

1つのコマンドに、4つのライセンス

この節で分かること: 種類の違うライセンスが、1つのプログラムの中で組み合わさっていること。

ここまでの全部が、ls 1つの中で同居している。ls が動くときに読み込む共有ライブラリを並べる。

ldd の出力の1列目だけを awk で取り出した（2列目以降にはメモリ上の番地が出て、起動のたびに変わる）。linux-vdso.so.1 はカーネルが用意する仮想的なもので、ld-linux は読み込みを担う部品なので、ここでは残りの3つを見る。libc6 のライセンスは第2章で見た。

GPL のプログラムが、LGPL・BSD 系・パブリックドメインの部品を使って動いている。ここにある BSD 3条項の一種やパブリックドメインのコードは、GPL のプログラムと組み合わせられている。ただし、許可型ならどれでも GPL と組み合わせられるわけではない。FSF は、宣伝の条件を持つ4条項の BSD や、GPLv2 のプログラムに Apache 2.0 のコードを組み合わせることを、条件がぶつかるとして認めていない。そしてこの ls をバイナリで配る人は、持ち主のいる3つの部品それぞれの条件を守る必要がある（パブリックドメインの部品には条件が無い）。GPL-3 第4条の「ライセンスの写しを渡す」、BSD の条件2の「文書などに載せる」。/usr/share/doc/*/copyright が最小のイメージにも残っているのは、そのためである。

手を動かす: このコースには演習がない。素の Ubuntu で ldd /bin/ls | awk '{print $1}' から始めて、この表の4行を自分で辿る。 /bin/ls を /usr/bin/grep や /bin/tar に変えると、部品の組み合わせが変わる。どれも読むだけのコマンドである。起動のしかたは入口にある。
確認

MIT ライセンスのソフトウェアを自社製品に組み込んで販売する。このとき必要なことはどれか。

  1. 自社製品のソースコードを公開する
  2. 著作権表示と許諾文を製品に含める
  3. 自社製品全体を MIT ライセンスにする
  4. 著作権者に使用料を支払う
答え

B。許諾文は subject to the following conditions: のあとに The above copyright notice and this permission notice shall be included in all copies or substantial portions of the Software. と書いている。 コピーレフトが無いので A と C は要らず、free of charge なので D も要らない。

確認

貢献者が持つ特許の利用を明示的に許可し、その作品について特許訴訟を起こした者への許可は終了すると定めているライセンスはどれか。

  1. BSD ライセンス
  2. MIT ライセンス
  3. Apache License 2.0
  4. パブリックドメイン
答え

C。Apache License 2.0 の第3条 Grant of Patent License に、特許の許可と shall terminate as of the date such litigation is filed（訴えた日に終わる）がある。 BSD と MIT は特許について1語も書いていない（grep -ic patent で 0）。

確認

パブリックドメインの説明として正しいものはどれか。

  1. 著作権者が、無償での利用を許諾したもの
  2. 著作権が放棄された、または存在しないもの
  3. 改変を禁止したうえで公開したもの
  4. 非営利の目的でのみ使えるもの
答え

B。libselinux の copyright は public domain software, i.e. not copyrighted（著作権が無い）と書いている。 A は許可型のライセンスの説明で、持ち主がいる点がパブリックドメインと違う。

確認

BSD ライセンス（3条項）のソフトウェアを、ソースコードを付けずにバイナリだけで再配布する。必要なことを2つ挙げよ。

答え

著作権表示・条件の一覧・免責文を、配布物の文書などに載せる（条件2 Redistributions in binary form must reproduce the above copyright notice ... in the documentation and/or other materials provided with the distribution）。 そして、大学や貢献者の名前を許可なく宣伝に使わない（条件3）。ソースコードを公開する必要は無い。

この章で分かったこと

持ち帰ってほしいこと

  • 非コピーレフト型（許可型・BSD 系）にも条件はある。MIT（Expat）は「著作権表示と許諾文をすべての写しに含める」、Beerware でさえ「表示を残す限り」
  • BSD（3条項）の条件は、表示を残す・バイナリなら文書に載せる・名前を宣伝に使わない、の3つ。4条項版には宣伝の条件がもう1つある
  • Apache License 2.0 の条件は、写しを渡す・改変したファイルに明記・表示を残す・NOTICE を含める、の4つ。改変版の条件は自分で決めてよい
  • Apache の特許条項は、貢献者の特許を無償で使わせ、その作品で特許訴訟を起こした者への許可を訴えた日に終わらせる。許可型の中では Apache だけで、MIT と BSD は特許に触れていない（MPL-2.0 と GPL-3 にも特許の条項がある）
  • パブリックドメインは「許可」ではなく「著作権が無い」状態。持ち主がいないので条件も無い。条件の無い許可（FSF の configure など）とは、持ち主がいるかどうかで違う。libselinux のように無保証の文を付けているものもある
  • 書き出しが同じ許諾文に X11・Expat・MIT など5つの名前が付いていた。X11 と MIT/X11 の本文には、名前を宣伝に使わないという条件がもう1つあった。ライセンスは名前ではなく本文で判断する
  • ls 1つの中に GPL・LGPL・BSD 系・パブリックドメインが同居している。配る人は、持ち主のいる部品すべての条件を守る
