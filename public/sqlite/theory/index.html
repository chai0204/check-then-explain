壊して覚える SQLite

サーバのいないデータベースが、どこまで普通のファイルなのかを手で確かめる。全5章・約2時間。

この教材が向かない人

読み終わったらできること

  • DB がファイル1個であることを、ヘッダのバイト列とプロセス一覧の両方で示せる
  • database is locked と readonly database が出る条件を、原因まで切り分けられる
  • SQLite を選ぶ場面と、選ばない場面を自分の言葉で言える
ここで覚えなくていいこと: B-tree のページ構造 / ヘッダ100バイトの全フィールド / WAL ファイルの内部形式 / ロックの5状態の遷移図 / PRAGMA の一覧 / SQL の文法そのもの

この教材が回収する1つの原理

この節で分かること: 5章すべてが、たった1つの事実から出てくること
背骨: SQLite はサーバではなくライブラリである。データベースを動かしているのは 常駐プロセスではなく、いまあなたが起動したそのプロセス自身が、ファイルを直接読み書きしている。
ただし崩れる点: 「だから遅い」わけではない。読み取りは、サーバへの往復が無いぶん速い。

各章で出会う挙動は、ほぼ全部この1点から導けます。最終章でまとめて回収します。
