確かめて説明する LinuC 主題1.10

LinuC レベル1 102 試験・主題1.10「セキュリティ」 （セキュリティ管理業務 / ホストの設定 / 暗号化 / クラウドの基礎）を、 コンテナの中で動く仮想マシンの練習機で実際に手を動かして確かめます。 iptables も /etc/nologin も ssh-keygen も、本物のカーネルの上で動く練習機で試せます。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: コマンドは打てる。写経すれば動く。 でも「なぜ動くのか」を人に説明できない人。
LinuC を受ける人向けには: 出題範囲を読んで「そういうことができるんだな」で止まっている人。

影響度 B（変更は練習機の中だけ。母艦にも外側コンテナにも波及しません）。 演習は練習機の /etc やアカウント・ファイアウォールを書き換えます。 締め出されても練習機は消えません。vm reset --yes で工場出荷時に戻せます。 演習を始めるときの lab の案内にも、この戻し方が出ます（起動し直すだけでは練習機は戻りません。ディスクはボリュームに残ります）。 なぜ仮想マシンか: ファイアウォールやログイン制御・シャドウパスワードは、コンテナ（ホストのカーネルを借りる）では読者ごとに違う画面になります。 QEMU の完全エミュレーションなら、本物のカーネルの上で全員に同じ画面が出て、--cap-add も --privileged も要りません。

はじめる

Docker の場合。2行です（練習機は起動時に自動で立ち上がります）。

docker run -d --name lab-linuc-security --hostname host --stop-timeout 30 \
  -v lab-linuc-security-vm:/home/lab/vm \
  -v lab-linuc-security-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:security-1.0.3@sha256:3ee338b0f4960d568caa4fa815891918973ba4014cb845fa9d456d9a3f5c268b

docker exec -it lab-linuc-security bash -l

--stop-timeout 30 を付けてください。練習機の正常停止に十数秒かかるので、既定の猶予（10秒）だと電源断になり、次の起動でディスクの回復が走ります。

Podman の場合も同じオプションで動きます（podman 5.8.6・rootless で、同じ土台を使う主題1.08 の檻により、練習機の起動・lab-guest・停止まで確認。権限の追加は要りません）。

podman run -d --name lab-linuc-security --hostname host --stop-timeout 30 \
  -v lab-linuc-security-vm:/home/lab/vm \
  -v lab-linuc-security-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:security-1.0.3@sha256:3ee338b0f4960d568caa4fa815891918973ba4014cb845fa9d456d9a3f5c268b

podman exec -it lab-linuc-security bash -l

外側（lab@host）と練習機（student@linuc）の2層があります。

プロンプトが lab@host なら外側のコンテナ、student@linuc なら練習機の中です。いまどちらにいるかは、この名前で分かります。

vm status        練習機の状態を見る
vm ssh           練習機に入る（ssh linuc。抜けるのは exit）
vm console        シリアルコンソールにつなぐ（ssh を壊したとき。抜けるのは Ctrl+]）
vm reset --yes   練習機を工場出荷時に戻す（ディスクの変更が全部消える）

入ると、現在地と演習の進捗が出ます。練習機の中でも lab check NN で答え合わせができます （判定は外側のコンテナがゲストエージェント経由で行うので、ネットワークや ssh を壊しても採点できます）。

1.0.2 で始めた人は、「終わったら」の手順で檻を止めてから（ボリュームは消さずに）、上の起動コマンドで起動し直すだけで構いません。1.0.3 で変わったのは lab コマンドだけなので、進み具合と作業ファイルはそのまま使えます。

締め出されたら

この主題は、自分を締め出す操作（/etc/nologin・sshd やファイアウォールの設定）を扱います。ssh で入れなくなっても、外側のコンテナから戻せます。

まず次に最後の手段
vm ssh でまだ入れるか試すvm console でシリアルから入る／lab-guest 'コマンド' で root として直すvm reset --yes で工場出荷時に戻す

演習は、管理用の ssh（enp0s16 の 22 番）を塞がない手順になっています。もし塞いでも、上のどれかで必ず戻せます。

演習

lab は sudo を付けずに打ちます。付けると root として動き、作業ディレクトリと進み具合が /root の下にできて檻を抜けると消えてしまうので、理由を出して何もせずに止まります。~/work や ~/.lab の持ち主が自分でなくなっていたら、lab が見つけて戻し、そのことを画面に出します。
