理論編 — セキュリティ

LinuC レベル1 102 試験・主題1.10（セキュリティ管理 / ホストの設定 / 暗号化 / クラウド）を、 コンテナの中で動く仮想マシンの練習機で実際に手を動かして確かめる9章。 練習機を壊して自分を締め出す操作（/etc/nologin・ファイアウォール）も、外から安全に戻せる構えで扱います。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この9章を貫いている1つの事実

「止めたつもり」は、たいてい止まっていない。Linux の制限は、正しい対象に・信用できる持ち主の設定で書けたときだけ効く。

パスワードをロックしても鍵では入れる。find -perm 4000 では SUID が1つも出ない。 other に書ける sudoers は丸ごと読まれない。ulimit -n 512 はハードまで下げて戻せなくする。 firewall-cmd で開けたポートは再読み込みで消える。 だから監査は、意図ではなくいま実際に効いているものを数えることから始まります。

ここで覚えなくていいこと: 強制アクセス制御（SELinux・AppArmor）、PAM モジュールの細部、nftables のネイティブ構文、 gpg の信頼の輪。どれもレベル1の範囲外で、この9章には深追いしません。

試験の直前に見る表

出題範囲に並ぶ語の「一行の意味」と、説明している章です。詰まったらその章へ。

語一行の意味章
find -perm -4000SUID の棚卸し。4000（ちょうど）ではなく -4000（含む）。-u+s も同じ。SGID は -2000、いずれかは /60001
passwd -l / usermod -eロックはパスワードだけ止める（鍵では入れる）。無効化は有効期限を過去に2
chageパスワードエージングと有効期限（/etc/shadow の3〜8列目）。-l で表示、-E でアカウント期限、-I で猶予2
ulimitシェルとその子の資源上限。表示の既定はソフト、設定で -S/-H を省くと両方。ハードは一般ユーザには一方通行3
TMOUT無操作での自動ログアウト秒数。/etc/profile で readonly TMOUT にすれば変更も unset もできない3
who / w / lastいまの端末ログイン（utmp）／logind のセッションと実行中のコマンド／過去の履歴（wtmp）。lastb は root3
ss / netstat / lsof / fuser自分のホストの待ち受けと、それを出すプロセスを辿る4
nmapネットワーク越しにポートを調べる（他のホストも）。SERVICE 列は nmap-services の当て推量、既定は約1000ポート4
sudo / /etc/sudoers / visudo1コマンドを代理実行。% はグループ、(ALL) は誰としてでも。sudoers.d は 440・root:root、visudo -c で構文と権限を検査5
シャドウパスワード/etc/passwd の x が指す /etc/shadow（一般ユーザは読めない）6
/etc/nologinroot 以外の全ログインを止める。自分も次から入れない6
xinetd / inetdスーパーサーバ。/etc/xinetd.d/名前 の disable = yes、/etc/inetd.conf は行を # にして HUP。Debian/Ubuntu では同時に入らない6
systemctl / service / chkconfigサービスの起動・自動起動。chkconfig は RHEL 系（Ubuntu は update-rc.d）6
iptables / firewalldどちらも netfilter にルールを入れる道具。状態はルールを入れた道具で見る。22 を巻き込まない7
firewall-cmd --permanent付けない変更は再読み込み・再起動で消える。付けた変更は --reload まで反映されない7
ssh-keygen（rsa/ecdsa/ed25519）強さはアルゴリズムと鍵長で決まる。ed25519 は約128ビット相当（RSA 3072 と同程度）で、OpenSSH 9.5 からの既定8
ssh-agent / ssh-add秘密鍵を預かる。eval $(ssh-agent -s) で取り込み、eval $(ssh-agent -k) で止める（ログアウトでは止まらない）8
SSH ポート転送（-L / -R）トンネル越しに、相手から見たサービスを手元に出す（-R は逆向き）8
gpg / gpg-agent / ~/.gnupg/-e -r は相手の公開鍵で暗号化、-c はパスフレーズの共通鍵暗号。鍵束は ~/.gnupg8
クラウド（責任共有・多要素認証）届くのはセキュリティグループと OS の両方が通すものだけ。設定は利用者。管理コンソールは多要素認証で9

章

  1. SUID は、実行する人ではなく持ち主で動く — find -perm 4000 では0件。SUID はスクリプトには効かない（15分）
  2. 「ロックした」は「無効化した」ではない — passwd -l の後も鍵で入れる。usermod -e で PAM が拒否する（16分）
  3. 入っている人と、入れる上限 — ulimit -n 512 はハードまで下げる。readonly TMOUT。who と w の違い（16分）
  4. 開いているポートは、数えないと見えない — nmap の SERVICE は当て推量（2323 が 3d-nfsd）。22 はソケット起動（15分）
  5. sudo は、許したものだけに絞る — other に書ける sudoers は読まれない。visudo -c は権限も見る（16分）
  6. シャドウと、使っていないサービスを止める — /etc/nologin は自分も締め出す。xinetd の disable（18分）
  7. ファイアウォールは、自分を締め出せる — iptables -L が空でも firewalld が守る。--permanent の有無（18分）
  8. 鍵は、持ち主で非対称になっている — ビット数では強さを比べられない。エージェントは残る。共通鍵の gpg -c（22分）
  9. クラウドでは、守る範囲が分かれている — 届くのは2つの層が通すものだけ。設定は利用者。理論のみ（14分）
