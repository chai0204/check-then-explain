6. シャドウと、使っていないサービスを止める

「メンテナンス中はログインを止めたい」。/etc/nologin にメッセージを置けばよい——と思うと、自分（管理者）も次から入れなくなる。nologin は root 以外のすべてのログインを止めるからだ。いま開いているセッションだけが生き残る。締め出されたときにどう戻すかを、先に知っておく必要がある。

この章のゴールと前提所要 18分
前提: 第5章まで読了前提: 練習機が起動している所要 18分影響度 B出題範囲 1.10.2（重要度3）最終検証 2026-10-13

この章のゴール

  • シャドウパスワード（/etc/passwd の x と /etc/shadow の分離）を説明できる
  • /etc/nologin の効き方と、締め出されたときの戻し方を言える
  • 使っていないネットワークサービスを止める方法（xinetd の disable・inetd.conf・systemctl・service・/etc/init.d）を説明できる
ここで覚えなくていいこと: systemd のユニットファイルの書き方、SysV 初期化スクリプトの中身、xinetd のアクセス制御（only_from など）やログ設定の細部はレベル1では深追いしない。ここでは「どこを見れば有効/無効が分かり、どう止めるか」を扱う。

パスワードは passwd に無い

この節で分かること: x が指す先と、分離の理由。
$ grep '^student:' /etc/passwd
student:x:1000:1000:LinuC student:/home/student:/bin/bash
$ sudo grep '^student:' /etc/shadow | cut -c1-30
student:$y$j9T$zeB7kAA87DbMW.l
$ ls -l /etc/passwd /etc/shadow
-rw-r--r-- 1 root root   1580 Oct 13 19:26 /etc/passwd
-rw-r----- 1 root shadow 1026 Oct 13 19:26 /etc/shadow

/etc/passwd の2列目は x で、パスワードそのものは入っていない。実体（試験では「暗号化されたパスワード」と呼ぶ。中身はハッシュで、$y$... は yescrypt）は /etc/shadow にある。これがシャドウパスワードである。なぜ分けるか——権限を見れば分かる。/etc/passwd は 644（誰でも読める。ls -l の持ち主の表示などに名前⇔UID の対応が要る）。/etc/shadow は、この練習機（Ubuntu）では 640・root:shadow で、一般ユーザは読めない（RHEL 系では 000）。ハッシュを誰でも読める表から追い出し、総当たりの材料を渡さないために分離した。

たとえ: /etc/passwd は会社の内線電話帳（誰でも見られる名前と番号）、/etc/shadow は人事だけが持つパスワード台帳に近い。電話帳の各行には「詳細は人事へ」（x）とだけ書いてある。
ただし崩れる点: 電話帳と台帳は別の棚だが、両方とも1つの建物（サーバ）の中にある。読めるかどうかは鍵（ファイル権限）が分けているだけで、物理的に離れてはいない。

nologin は、自分も締め出す

この節で分かること: /etc/nologin の効く範囲と戻し方。

ふつうこう考える

メンテナンス中に一般ユーザのログインを止めたい。/etc/nologin にメッセージを置けばよい。管理者の自分は、これまでどおり ssh で入れるだろう。

$ echo 'メンテナンス中です' | sudo tee /etc/nologin
メンテナンス中です
$ vm ssh echo hello
▶ ssh linuc echo hello
メンテナンス中です

Connection closed by 127.0.0.1 port 2222
だめな理由: vm ssh（＝新しい ssh ログイン）が、/etc/nologin の中身を表示して接続を閉じられた。 /etc/nologin はroot 以外のすべてのログインを止める。student で入ろうとした自分も弾かれる。 救いは、すでに開いているセッションは生き残ることと、root は例外で入れること。 だから「置いた瞬間に全員追い出し」ではないが、いま開いている窓を閉じたら、もう新しくは入れない。

締め出されたときの戻し方を知っておく。この教材の練習機では、外側のコンテナから次の手が使える。

$ lab-guest 'rm -f /etc/nologin && echo removed_by_root'
removed_by_root
$ vm ssh echo hello
▶ ssh linuc echo hello
hello
戻し方どういう経路かいつ使うか
開いているセッションまだ入っている端末から sudo rm /etc/nologin窓を閉じる前
vm consoleシリアルコンソール（画面）から直接ログインssh が塞がれたとき（ただし nologin はコンソールのログインも止める）
lab-guest '…'ゲストエージェント経由で root としてコマンド実行ネットワークも ssh もログインも駄目なとき
vm reset --yes練習機を工場出荷時に戻す最後の手段

lab-guest は ssh を通らない（仮想マシンのエージェント経由）ので、ネットワークや sshd やログインを壊しても root として直せる。実践編の判定（lab check）もこの経路を使うので、読者が自分を締め出しても採点は止まらない。

たとえ: /etc/nologin は、店の入口に貼る「本日休業」の札に近い。来た客（新しいログイン）は札を見て帰る。だがすでに店内にいる人は追い出されない。
ただし崩れる点: 店主は裏口の鍵を持っているが、nologin で「本日休業」を貼った管理者も、いったん外に出たら正面（ssh）からは入れない。裏口（開いたままの端末・lab-guest）を確保してから貼る。

xinetd のサービスは、1行で止まる

この節で分かること: スーパーサーバの設定の読み方と、サービスの止め方。

xinetd はスーパーサーバ——自分が代表して待ち受け、接続が来たら対応するサービスを動かす仕組みである。全体の設定は /etc/xinetd.conf、サービスごとの設定は /etc/xinetd.d/ にある。この練習機では入っているが止めてある。

$ cat /etc/xinetd.conf
# Simple configuration file for xinetd
#
# Some defaults, and include /etc/xinetd.d/

defaults
{

# Please note that you need a log_type line to be able to use log_on_success
# and log_on_failure. The default is the following :
# log_type = SYSLOG daemon info

}

includedir /etc/xinetd.d
$ ls -1 /etc/xinetd.d/
chargen
chargen-udp
daytime
daytime-udp
discard
discard-udp
echo
echo-udp
servers
services
time
time-udp
$ cat /etc/xinetd.d/echo
# default: off
# description: An xinetd internal service which echo's characters back to
# clients.
# This is the tcp version.
service echo
{
	disable		= yes
	type		= INTERNAL
	id		= echo-stream
	socket_type	= stream
	protocol	= tcp
	user		= root
	wait		= no
}

# This is the udp version.
service echo
{
	disable		= yes
	type		= INTERNAL
	id		= echo-dgram
	socket_type	= dgram
	protocol	= udp
	user		= root
	wait		= yes
}
$ systemctl is-enabled xinetd; systemctl is-active xinetd
disabled
inactive

/etc/xinetd.conf は既定値と includedir /etc/xinetd.d だけで、各サービスはファイルごとに service 名前 { … } で書く。止めるか動かすかは disable の1行で決まる（yes で止める）。socket_type・protocol・wait・user は接続の受け方と実行ユーザ、type = INTERNAL は xinetd 自身が応答する組み込みサービスを表す（外部のプログラムを動かすなら server にパスを書く）。試しに echo を動かし、それから止める。

$ sudo sed -i 's/^\(\s*disable\s*=\s*\)yes/\1no/' /etc/xinetd.d/echo
$ grep disable /etc/xinetd.d/echo
	disable		= no
	disable		= no
$ sudo systemctl start xinetd; sleep 2
$ sudo ss -ltnp | grep ':7 '
LISTEN 0      64                 *:7               *:*    users:(("xinetd",pid=1689,fd=5))                      
$ printf 'hello\n' | nc -N -w 2 127.0.0.1 7
hello

7 番（echo）で待ち受けているのは xinetd 自身で、送った hello がそのまま返ってきた。使わないなら disable = yes に戻し、xinetd に設定を読み直させる（再起動、または HUP で再読込）。

$ sudo sed -i 's/^\(\s*disable\s*=\s*\)no/\1yes/' /etc/xinetd.d/echo
$ sudo systemctl restart xinetd; sleep 2
$ sudo ss -ltn | grep ':7 ' || echo '（7 番は閉じた）'
（7 番は閉じた）
$ sudo systemctl stop xinetd; systemctl is-active xinetd
inactive

試験範囲にはもう1つのスーパーサーバ inetd（設定は /etc/inetd.conf・/etc/inetd.d/）も並ぶ。こちらは1サービスが1行で、止めるにはその行の先頭に # を付けてコメントにし、inetd に HUP を送って読み直させる（Debian 系には update-inetd --disable 名前 という道具もある）。

# /etc/inetd.conf の書式（1行 = 1サービス）
# サービス名  ソケット型  プロトコル  待ち方   実行ユーザ  サーバ           引数
echo          stream      tcp         nowait   root        internal
#telnet       stream      tcp         nowait   root        /usr/sbin/tcpd   /usr/sbin/in.telnetd
                                                              ↑ 先頭の # でこの行を無効にしている

だがこの練習機には /etc/inetd.conf が無い。

$ ls /etc/inetd.conf
ls: cannot access '/etc/inetd.conf': No such file or directory
$ dpkg -s xinetd | grep -E '^(Package|Status|Provides|Conflicts):'
Package: xinetd
Status: install ok installed
Provides: inet-superserver
Conflicts: inet-superserver
$ sudo apt-get update -qq
$ apt-get -s install openbsd-inetd | grep -A2 REMOVED
The following packages will be REMOVED:
  xinetd
The following NEW packages will be installed:

xinetd は Provides: inet-superserver と Conflicts: inet-superserver を同時に持っている。「自分はスーパーサーバの役を提供する。同じ役を名乗る別のパッケージとは共存しない」という、Debian/Ubuntu のパッケージの取り決めである（inet-superserver は仮想パッケージ名）。openbsd-inetd も同じ役を提供するので、入れようとすると xinetd が消される（-s は実際には入れずに計画だけを出す。apt-get update にはネットワークが要る）。主題1.09 の chrony と ntpsec（どちらも time-daemon）と同じ型で、試験には両方の名前が並ぶが、この練習機に入れられるのは片方だけである。だから inetd.conf は書式を知識として押さえ、手で触るのは xinetd で行う。

たとえ: xinetd と inetd は、同じ部署に1人しか置かない決まりの受付係に近い。どちらも「来客を取り次ぐ」役なので、新しい受付（openbsd-inetd）を雇うと前任（xinetd）は外される。
ただし崩れる点: 1人しか置けないのは技術の制約ではなく、配布元（Debian/Ubuntu）のパッケージの決まりである。別々に手で入れれば、ポートが重ならない限り同時に動かすこともできる。

サービスの止め方いろいろ

この節で分かること: systemctl・service・/etc/init.d・chkconfig の関係。

いまの Ubuntu では systemctl が中心で、古い service コマンドと /etc/init.d/ のスクリプトも互換のために残っている。

$ command -v update-rc.d service
/usr/sbin/update-rc.d
/usr/sbin/service
$ ls /etc/init.d/ | head -6
anacron
apparmor
apport
atd
console-setup.sh
cron
$ service --status-all 2>&1 | head -4
 [ + ]  anacron
 [ + ]  apparmor
 [ + ]  apport
 [ + ]  atd
$ command -v chkconfig || echo 'chkconfig: なし'
chkconfig: なし
道具何をする系統
systemctl start/stopいま起動/停止systemd（現行）
systemctl enable/disable次の起動で上がる/上がらない（--now で両方）systemd（現行）
service 名前 startsystemctl へのラッパ（/etc/init.d のスクリプトも扱う）互換
/etc/init.d/名前 stopSysV 初期化スクリプトを直接呼ぶ互換
update-rc.dSysV スクリプトの自動起動を登録/解除Debian 系
chkconfig同じことを RHEL 系で行う（Ubuntu には無い）RHEL 系
たとえ: systemctl は新しい集中管理盤、service と /etc/init.d は昔ながらの個別スイッチに近い。今は個別スイッチを押しても、裏で集中管理盤に回される。
ただし崩れる点: 管理盤と個別スイッチの対応は配布元ごとに違い、chkconfig のように片方の系統にしか無い道具もある。
手を動かす: 実践編の演習03で、使っていないサービス（lab-echo）を systemctl disable --now で止め、次の起動でも上がらないことを確かめる。stop だけだと enabled のまま次回また上がることも、判定で分かる。
確認

/etc/nologin にメッセージを置いた。誰がログインできなくなるか。すでに入っている自分のセッションはどうなるか。

答え

root 以外のすべての新規ログインが止まる（メッセージを表示して接続が閉じる）。 すでに開いているセッションは生き残り、root は例外で入れる。自分も次からは入れないので、戻し方を用意してから置く。

確認

xinetd で動いている daytime サービスを止めたい。何をするか。inetd ならどうするか。

答え

/etc/xinetd.d/daytime の disable を yes にし、xinetd を再起動（または HUP で再読込）する。 inetd なら /etc/inetd.conf の daytime の行の先頭に # を付けてコメントにし、inetd に HUP を送る。

確認

Ubuntu に xinetd が入っている。openbsd-inetd（inetd）を apt install するとどうなるか。

答え

xinetd が削除される。どちらも inet-superserver という役を提供し、Debian/Ubuntu のパッケージの取り決めで同時には入らない。 dpkg -s xinetd の Provides/Conflicts と apt-get -s install で確かめられる。

この章で分かったこと

持ち帰ってほしいこと

  • /etc/passwd の x は「パスワードは /etc/shadow にある」印。passwd は 644、shadow は一般ユーザが読めない（Ubuntu は 640・root:shadow、RHEL 系は 000）
  • /etc/nologin は root 以外の全ログインを止める。自分も次から入れない。既存セッションと root は例外。戻し方を先に用意する
  • xinetd は /etc/xinetd.d/名前 の disable = yes で止め、再起動か HUP で読み直させる。inetd は /etc/inetd.conf の行を # でコメントにして HUP
  • xinetd と openbsd-inetd は Debian/Ubuntu のパッケージの取り決め（inet-superserver）で同時に入らない
  • サービスは systemctl が中心。service・/etc/init.d は互換、update-rc.d は Debian 系、chkconfig は RHEL 系
