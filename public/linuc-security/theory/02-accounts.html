2. 「ロックした」は「無効化した」ではない

退職者のアカウントを止めるとき、まず思いつくのは passwd -l（ロック）である。ところがロックしても、SSH 鍵を登録している相手はそのまま入れてしまう。パスワードをロックしたのに、である。鍵が効くのは、ロックが止めたのが「パスワードという1つの入口」だけだからだ。

前提: 第1章まで読了前提: 練習機が起動している所要 14分影響度 B出題範囲 1.10.1（重要度3）最終検証 2026-10-13

この章のゴール

  • passwd -S と chage -l が別のものを見ていることを説明できる
  • パスワードのロックとアカウントの有効期限の違いを言える
  • /etc/shadow の主要なフィールド（ロックの !、有効期限の列）を読める
ここで覚えなくていいこと: PAM モジュール（pam_tally2 / faillock）によるログイン失敗ロックや、パスワードの複雑さ要件（pam_pwquality）はレベル1の範囲外である。ここでは passwd・usermod・chage の3つと /etc/shadow だけを扱う。

passwd はパスワード、chage はアカウント

この節で分かること: 2つのコマンドが見ている対象の違い。

退職者 olduser がまだ生きている。2つのコマンドで状態を見る。

$ sudo passwd -S olduser
olduser P 2026-10-13 0 99999 7 -1

先頭の olduser に続く P が「パスワードが使える（Password）」の意味である（ロックされていれば L、パスワード未設定なら NP）。一方 chage -l はアカウントそのものの期限を見る。

$ sudo chage -l olduser

この出力には「最終パスワード変更日」「パスワードの有効期限」「アカウント有効期限」などが並ぶ。初期状態はどれも never（無期限）である。passwd はパスワードという鍵の話、chage はアカウントの寿命の話で、見ているものが違う。

たとえ: passwd は玄関の鍵の話、chage は賃貸契約そのものの話に近い。鍵を1本交換しても契約は生きているし、契約が切れれば鍵が何本あっても入れない。
ただし崩れる点: 家の鍵は1種類だが、Linux のアカウントにはパスワード・SSH 鍵・sudo 経由など複数の入口がある。だから「鍵1本」を止めても塞ぎきれない。

ロックしても、鍵では入れてしまう

この節で分かること: passwd -l が止めるのはパスワードだけだということ。

この olduser には SSH 公開鍵が登録してある（退職前に鍵で入っていた、という設定である）。実際に鍵で入れることを確かめる。

$ ssh -i ~/.ssh/id_demo -o BatchMode=yes -o StrictHostKeyChecking=no -o LogLevel=ERROR olduser@localhost id
uid=1001(olduser) gid=1001(olduser) groups=1001(olduser)

ふつうこう考える

退職者を止めるなら passwd -l でパスワードをロックすればよい。ロックすれば、もうこのアカウントでは入れないはずだ。

$ sudo passwd -l olduser
passwd: password changed.
$ sudo passwd -S olduser
olduser L 2026-10-13 0 99999 7 -1
$ sudo grep "^olduser" /etc/shadow | cut -c1-20
olduser:!$y$j9T$U8mv
$ ssh -i ~/.ssh/id_demo -o BatchMode=yes -o StrictHostKeyChecking=no -o LogLevel=ERROR olduser@localhost id
uid=1001(olduser) gid=1001(olduser) groups=1001(olduser)
だめな理由: passwd -S は L（ロック済み）になり、/etc/shadow のパスワード欄の先頭にも ! が付いた。 それでも鍵では入れたまま（uid=1001(olduser) が出ている）。 passwd -l がしたのは、パスワード欄の先頭に ! を足して「このハッシュと一致するパスワードは存在しない」状態にしただけである。 公開鍵認証はパスワード欄を見ないので、素通りする。man passwd にも「これはアカウントを無効化しない（鍵では入れる）」と明記されている。

無効化は、有効期限でしか達成できない

この節で分かること: アカウントそのものを止める方法。

全部の入口を塞ぐには、アカウントの有効期限を過去にする。期限は /etc/shadow の8列目（1970-01-01 からの日数）に入る。まず今は空（＝期限なし）で、usermod -e 1 を打つと 1（1970-01-02）になる。

$ sudo grep "^olduser" /etc/shadow | cut -d: -f8
$ sudo usermod -e 1 olduser; sudo grep "^olduser" /etc/shadow | cut -d: -f8
1

usermod -e 1 で8列目が 1（1970-01-02）になった。はるか過去なので、このアカウントは期限切れである。鍵でもう一度入ってみる。

$ ssh -i ~/.ssh/id_demo -o BatchMode=yes -o StrictHostKeyChecking=no -o LogLevel=ERROR olduser@localhost id; echo rc=$?
rc=255

今度は入れない（rc=255）。sshd は認証の前に「アカウントが有効か」を見て、期限切れなら鍵が正しくても拒否する。日付で指定するなら chage -E 2020-01-01 olduser でも同じである。

操作変える場所鍵ログインは
passwd -lパスワード欄に ! を足す止まらない
usermod -e 1 / chage -E有効期限（8列目）を過去に止まる
シェルを /usr/sbin/nologin に/etc/passwd のシェル欄対話ログインは止まる（コマンド実行は要注意）
たとえ: passwd -l は、社員証の暗証番号だけを無効にするのに近い。番号は使えなくなるが、顔認証（鍵）が登録されていれば入れてしまう。usermod -e は社員資格そのものを失効させるので、どの認証手段でも入れない。
ただし崩れる点: 社員証は1枚だが、Linux の有効期限は日付という1つの数で全入口に効く。番号失効（ロック）と資格失効（期限切れ）を混同すると、止めたつもりで入られる。
たとえ: /etc/shadow の ! は、鍵穴に接着剤を詰めたようなもの。その鍵穴（パスワード）は使えないが、裏口（SSH 鍵）には触れていない。
ただし崩れる点: 接着剤は物理的に塞ぐが、! は「一致するパスワードが存在しない」だけで、裏口の存在を知らない。

/etc/shadow の列を読む

この節で分かること: パスワードエージングがどの列に入っているか。
$ sudo grep -E "^(root|olduser):" /etc/shadow | cut -c1-30
root:*:20701:0:99999:7:::
olduser:$y$j9T$U8mvgo0rhrEdHwN

/etc/shadow は : 区切りで9列ある。覚えるべきは次である。

列意味chage での指定
2 パスワードハッシュ。* や ! はログイン不可（root:* はパスワード未設定）passwd
3 最終変更日最後にパスワードを変えた日（1970 からの日数）chage -d
4 最短変更してから次に変えられるまでの最短日数chage -m
5 最長パスワードの有効日数（過ぎると変更を要求）chage -M
6 警告期限の何日前から警告するかchage -W
7 猶予期限切れ後、無効になるまでの猶予日数chage -I
8 アカウント有効期限この日を過ぎるとアカウントが使えないchage -E / usermod -e

root:* の * は「パスワードでは入れない」印である。クラウドイメージの root は *（パスワードなし）で、コンソールや鍵でしか入れないようになっている。これがシャドウパスワード（第6章）の実際の姿である。

たとえ: /etc/shadow の各列は、免許証の裏面にある有効期限・更新日・条件欄に近い。表（/etc/passwd）には名前と番号しか無く、期限などの機微な情報は裏（shadow）に分けてある。
ただし崩れる点: 免許証は1枚だが、Linux は表（passwd・誰でも読める）と裏（shadow・root だけ）を別ファイルに物理的に分けている。だから裏を読むには権限が要る。
手を動かす: 実践編の演習02は、この olduser を本当にログインできなくする課題である。判定は「パスワードをロックしただけ」では通らない。有効期限が切れているかを、アカウントデータベースから実際に読んで確かめる。
確認

退職した olduser を、SSH 鍵を持っていてもログインできないようにしたい。確実なのはどれか。

ア passwd -l olduser　イ usermod -e 1 olduser　ウ passwd -d olduser

答え

イ。passwd -l（ア）はパスワード欄に ! を足すだけで、鍵では入れてしまう。 passwd -d（ウ）はパスワードを空にするのでむしろ危険。 アカウントの有効期限を過去にする usermod -e 1（または chage -E）が、全入口を閉じる。

確認

/etc/shadow の各行の8列目は何を表すか。

答え

アカウントの有効期限（1970-01-01 からの日数）。この日を過ぎるとアカウントが使えなくなる。 chage -E / usermod -e で設定する。パスワードの有効期限（5列目）とは別物。

この章で分かったこと

持ち帰ってほしいこと

  • passwd -l（ロック）は /etc/shadow のパスワード欄に ! を足すだけ。SSH 鍵では入れたまま
  • アカウントそのものを止めるには有効期限を過去にする（usermod -e 1 / chage -E）。sshd は期限切れを鍵より先に見て拒否する
  • passwd -S はパスワードの状態（P/L/NP）、chage -l はアカウントの期限。見ているものが違う
  • /etc/shadow の8列目がアカウント有効期限。* や ! のパスワード欄はログイン不可の印
