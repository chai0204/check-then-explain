4. 開いているポートは、数えないと見えない

開いているポートを nmap で調べると、2323/tcp open 3d-nfsd と出る。だが 3d-nfsd というサービスは動いていない。そこで実際に動いているのは ncat である。nmap の「サービス名」は、ポート番号から自分の表を引いた当て推量にすぎない。

前提: 第3章まで読了前提: 練習機が起動している所要 15分影響度 C出題範囲 1.10.1（重要度3）最終検証 2026-10-13

この章のゴール

  • ss・netstat で待ち受けポートと、それを出しているプロセスを辿れる
  • nmap の「SERVICE」列が当て推量であること、既定スキャンの範囲を説明できる
  • lsof・fuser でポートからプロセスを特定できる
ここで覚えなくていいこと: nmap の高度なスキャン（-sS SYN スキャン、OS 判定 -O、NSE スクリプト）はレベル1の範囲外である。ここでは「開いているポートを数え、プロセスまで辿る」ことだけを扱う。

まず待ち受けを並べる

この節で分かること: ss -ltn の読み方。

ss で TCP の待ち受け（-l）を数字のまま（-n）出す（行の並び順は実行のたびに変わることがある）。

$ ss -ltn
State    Recv-Q   Send-Q     Local Address:Port     Peer Address:Port  Process  
LISTEN   0        10               0.0.0.0:2323          0.0.0.0:*              
LISTEN   0        4096       127.0.0.53%lo:53            0.0.0.0:*              
LISTEN   0        4096             0.0.0.0:22            0.0.0.0:*              
LISTEN   0        4096          127.0.0.54:53            0.0.0.0:*              
LISTEN   0        10                  [::]:2323             [::]:*              
LISTEN   0        4096                [::]:22               [::]:*

22（ssh）と 53（名前解決）のほかに、2323 が 0.0.0.0（全アドレス）で開いている。53 が 127.0.0.53・127.0.0.54 なのは systemd-resolved のスタブで、ローカル専用である。外から届きうるのは 0.0.0.0（と [::]）で待つ 22 と 2323 だ。2323 に心当たりがなければ、これが調査対象になる。

nmap のサービス名は当て推量

この節で分かること: nmap が何を見て「サービス名」を出しているか。

ふつうこう考える

nmap はポートスキャンの定番だ。SERVICE 列を見れば、そのポートで何が動いているか分かるはずだ。

$ nmap 127.0.0.1
...
Not shown: 998 closed tcp ports (conn-refused)
PORT     STATE SERVICE
22/tcp   open  ssh
2323/tcp open  3d-nfsd
だめな理由: 2323/tcp が 3d-nfsd と出た。だがこの練習機で 3d-nfsd は動いていない。 動いているのは ncat である（次の節で確かめる）。nmap は既定では応答の中身を調べず、 ポート番号を自前のサービス表 /usr/share/nmap/nmap-services で引いて「このポートはよく何に使われるか」を表示しているだけである （-sV を付けて初めてバナーを取りに行く）。OS の /etc/services には 2323 は載っていない。 SERVICE 列は「よくある用途」であって「いま動いているもの」ではない。誰かが 2323 で別のものを動かしていても、ここには正体が出ない。
$ grep -w 2323 /etc/services; echo rc=$?
rc=1
$ grep -w 2323/tcp /usr/share/nmap/nmap-services
3d-nfsd	2323/tcp	0.000228

もう1つ。Not shown: 998 closed tcp ports とある。nmap の既定は全 65535 ポートではなく、よく使われる約 1000 ポートだけを見る。そこに入らない番号（たとえば 50000 番台）で待ち受けているものは、既定のスキャンでは見えない。全部見るには nmap -p- が要る。「nmap で何も出なかった＝安全」ではない。

たとえ: nmap のサービス名は、部屋番号から「ここはふつう会議室」と手元の案内図を見て答えているのに近い。実際にその部屋で何が行われているかは、扉を開けて（-sV でバナーを取って）確かめないと分からない。
ただし崩れる点: 建物の案内図はその建物の持ち主が作るが、nmap-services は世界中の調査から作った「よくある用途」の表で、その部屋の実際の使い方とは無関係である。

ポートからプロセスを辿る

この節で分かること: 待ち受けを出している実プロセスの特定。

正体を知るには、自分のホストの中で「どのプロセスがそのポートを開いているか」を見る。ss -p・netstat -p・lsof・fuser のどれでもよい（他人のプロセスまで見るには root が要る）。

$ sudo lsof -iTCP:2323 -sTCP:LISTEN -P -n
COMMAND PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
ncat    704 root    3u  IPv6   6807      0t0  TCP *:2323 (LISTEN)
ncat    704 root    4u  IPv4   6808      0t0  TCP *:2323 (LISTEN)
$ sudo fuser 2323/tcp
2323/tcp:              704

どちらも ncat を指した。nmap の言う 3d-nfsd ではない。外から当てた名前（nmap）より、自分のホストの中から見たプロセス（ss・lsof・fuser）のほうが正しい。

ss -p と netstat -p で全体を見ると、22 番の持ち主の見え方が2つで違う。

$ sudo ss -ltnp
State     Recv-Q    Send-Q       Local Address:Port        Peer Address:Port    Process                                                                         
LISTEN    0         10                 0.0.0.0:2323             0.0.0.0:*        users:(("ncat",pid=704,fd=4))                                                  
LISTEN    0         4096         127.0.0.53%lo:53               0.0.0.0:*        users:(("systemd-resolve",pid=309,fd=15))                                      
LISTEN    0         4096               0.0.0.0:22               0.0.0.0:*        users:(("sshd",pid=510,fd=3),("systemd",pid=1,fd=109))                         
LISTEN    0         4096            127.0.0.54:53               0.0.0.0:*        users:(("systemd-resolve",pid=309,fd=17))                                      
LISTEN    0         10                    [::]:2323                [::]:*        users:(("ncat",pid=704,fd=3))                                                  
LISTEN    0         4096                  [::]:22                  [::]:*        users:(("sshd",pid=510,fd=4),("systemd",pid=1,fd=110))                         
$ sudo netstat -ltnp | grep -E ':22 |:2323 '
tcp        0      0 0.0.0.0:2323            0.0.0.0:*               LISTEN      704/ncat            
tcp        0      0 0.0.0.0:22              0.0.0.0:*               LISTEN      1/init              
tcp6       0      0 :::2323                 :::*                    LISTEN      704/ncat            
tcp6       0      0 :::22                   :::*                    LISTEN      1/init              
$ systemctl is-active ssh.socket ssh.service
active
active

ss -p は 22 番に sshd と systemd（PID 1）の両方を出す。netstat -p は1つのソケットに1つのプロセスしか出さないので 1/init（systemd）だけが見える。これは ssh がソケット起動になっているためで、systemd（ssh.socket）が 22 番を開いて持ち続け、最初の接続が来たときに sshd（ssh.service）を起動して、同じソケットを渡す。起動した sshd はその後も常駐する（両方 active）。だから一方の道具だけ見て「sshd が待ち受けていない」と判断しない。

たとえ: ss／lsof は、建物の中から「どの部屋の誰が窓を開けているか」を名簿で確かめるのに近い。nmap は外から開いている窓の数を数え、案内図で用途を推測する。
ただし崩れる点: 外からの観察（nmap）は攻撃者と同じ視点なので価値があるが、正体の特定には中からの名簿（ss・lsof）が要る。両方の視点が要る。
たとえ: ソケット起動の 22 番は、受付の呼び鈴を管理会社が設置し、最初の来客で担当者を呼び出す窓口に近い。担当者（sshd）は一度来たら常駐し、呼び鈴（ソケット）は管理会社（systemd）と担当者が両方握っている。
ただし崩れる点: 窓口なら誰が握っているか見れば分かるが、netstat -p は1人しか表示しないので、管理会社（PID 1）だけが握っているように見える。
手を動かす: 実践編の演習03は、この 2323 を出している lab-echo サービスを見つけて止める課題である。判定は、練習機の中で 2323 が待ち受けていないことを実際に見る。
確認

nmap で 2323/tcp open 3d-nfsd と出た。そのポートで実際に動いているプログラムを特定するには、どれが確実か。

ア nmap の SERVICE 列をそのまま信じる　イ ホストの中で ss -ltnp / lsof -i　ウ /etc/services を見る

答え

イ。nmap の SERVICE 列（ア）は、ポート番号を nmap 自前の nmap-services で引いた当て推量で、実体とは限らない。 /etc/services（ウ）も番号と名前の対応表にすぎず、いま動いているものは分からない（この練習機では 2323 は載ってすらいない）。 確実なのは自分のホストの中から ss -p・lsof・fuser でプロセスを見ること。

確認

netstat -ltnp で 22 番の持ち主が sshd ではなく 1/init と出た。sshd は動いていないのか。

答え

動いていないとは限らない。ソケット起動では systemd（PID 1）がソケットを持ち続け、最初の接続で sshd を起こして同じソケットを渡す。 netstat -p は1つのソケットに1つのプロセスしか出さないので PID 1 だけに見える。ss -ltnp なら sshd と systemd の両方が出る。

この章で分かったこと

持ち帰ってほしいこと

  • ss -ltn で TCP の待ち受けを数える。0.0.0.0/[::] は外から届きうる、127.0.0.x はローカル専用
  • nmap の SERVICE 列は、ポート番号を自前の nmap-services で引いた当て推量。実体は -sV かホスト内の ss/lsof で確かめる
  • nmap の既定はよく使われる約 1000 ポートだけ。全部見るのは nmap -p-
  • ポートからプロセスは ss -p・netstat -p・lsof -i・fuser で辿る（他人のプロセスには root）
  • 22 番はソケット起動。ss -p は sshd と systemd の両方、netstat -p は PID 1 だけを出す。sshd は最初の接続で起動し、以後常駐する
