9. クラウドでは、守る範囲が分かれている

パブリッククラウドにサーバを置くと、「サーバの OS の中だけ守れば安全」という感覚が崩れる。外から何が届くかを決めるのは、OS の中のファイアウォールではなく、その外側にある事業者のファイアウォール（セキュリティグループ）だからだ。守る範囲が、利用者と事業者で分かれている。

前提: 第8章まで読了理論のみ（檻の外）所要 12分影響度 A出題範囲 1.10.4（重要度3）最終検証 2026-10-13

この章のゴール

  • パブリッククラウドとオンプレミスで、セキュリティの責任分担がどう違うかを言える
  • 管理コンソール・事業者のファイアウォール・ルーティング・リージョン・揮発性ストレージの意味を説明できる
  • 管理コンソールへの経路と、多要素認証・ワンタイムパスワードの位置づけを言える
ここで覚えなくていいこと: 特定のクラウド事業者（AWS・Azure・GCP など）の固有のサービス名・画面・料金体系はレベル1では問われない。ここでは事業者を問わない共通の考え方（責任分担・管理コンソール・事業者側ファイアウォール・リージョン・揮発性ストレージ・多要素認証）だけを扱う。

OS の中だけ見ても、塞がらない

この節で分かること: 利用者と事業者の責任分担。

ふつうこう考える

サーバのセキュリティは、その OS の中で完結する。ファイアウォールも、第7章でやったように OS の中で iptables や firewalld を設定すればよい。外からの到達も、それで決まるはずだ。

だめな理由: この教材の練習機でも、外側のホストから届くポートを決めていたのは練習機の OS ではなかった。 第7章で練習機の iptables を操作しても、第8章で見たとおり、外側から練習機に届くのは転送された 22 だけだった。 到達を決めていたのは練習機の外側の転送設定である。 クラウドではこれがセキュリティグループ（事業者側のファイアウォール）に当たり、サーバの OS の外にある。 だから OS の iptables を全開にしても、事業者のファイアウォールが閉じていれば外からは届かない。逆に OS で閉じても、 事業者側が開いていれば経路は存在する。守りは OS の中と事業者側の両方にあり、片方だけ見ても塞がらない。これが責任分担である。

おおまかには、事業者がハードウェア・物理ネットワーク・仮想化基盤・（多くは）ネットワーク境界のファイアウォールを持ち、利用者が OS から上（パッチ・アカウント・OS 内のファイアウォール・アプリ）を持つ。オンプレミスでは全部が自分の責任だったので、この線引きを知らずにクラウドへ移ると「OS は固めたのに侵入された（事業者側の設定が開いていた）」「OS は開けたのに繋がらない（セキュリティグループが閉じていた）」が起きる。

たとえ: クラウドのサーバは、管理人のいる集合住宅の一室に近い。部屋の鍵（OS のファイアウォール）は自分で掛けるが、建物の正面オートロック（セキュリティグループ）は管理人（事業者）の管轄である。部屋だけ施錠しても、オートロックが開けっ放しなら共用廊下までは誰でも来る。
ただし崩れる点: 集合住宅では管理の線引きが契約書で曖昧なこともあるが、クラウドの責任分担モデルは「どの層が誰の責任か」が明示されている。見落とすのは線引きの存在を知らないときである。
たとえ: ルーティング（経路）は、建物の廊下やエレベーターの配置に近い。どの部屋からどの部屋へ行けるかは、事業者が引いた仮想ネットワークの経路で決まる。
ただし崩れる点: 実際の廊下は目で見えるが、クラウドの経路は管理コンソールの設定画面でしか見えない。図と実態がずれていても、現地を歩いて確かめることができない。

リージョンと、消える前提のストレージ

この節で分かること: 場所の選択と、ストレージの揮発性。

リージョンは、サーバを置く地理的な地域（データセンターの所在）である。どのリージョンを選ぶかで、利用者からの遅延、適用される法律（個人情報を国外に置けるか等の国内外の制約）、使えるサービスが変わる。日本の個人情報を国外リージョンに置くと規制に触れることがあるので、場所の選択はセキュリティとコンプライアンスの問題でもある。

もう1つ注意が要るのが揮発性ストレージである。クラウドの仮想サーバには、インスタンスを停止・再作成すると中身が消える一時的なディスク（インスタンスストア等）が付くことがある。速くて安いが、電源を切る前提で使う。永続させたいデータは、別の永続ストレージ（ブロックストレージ・オブジェクトストレージ）に置く。「再起動したらデータが消えた」はこの取り違えで起きる。

たとえ: 揮発性ストレージは、ホテルの部屋の机の上に近い。滞在中は使えるが、チェックアウト（インスタンスの停止・破棄）で片付けられる。残したいものは金庫やフロント預かり（永続ストレージ）に移す。
ただし崩れる点: ホテルは忘れ物を一時保管してくれることがあるが、揮発性ストレージは停止と同時に確実に消える。猶予は無い。

事業者の都合で、止まる・再起動する

この節で分かること: 自分の意思と無関係に起きる停止。

オンプレミスなら、サーバをいつ止めるかは自分で決める。クラウドでは、事業者のメンテナンスや基盤の障害で、利用者の都合と関係なく仮想サーバが再起動・移動・停止されることがある。事前に通知される計画メンテナンスもあれば、ハードウェア障害による突然のものもある。だから「いつ落ちても自動で復旧する」前提で組む（起動時に設定が戻る、データは永続ストレージにある、など）。第6章で見た「止めたサービスが次の起動でも止まっているか（enable/disable）」が、クラウドでは自分の意思と無関係な再起動で効いてくる。

たとえ: クラウドのサーバは、管理人が点検で一時的にブレーカーを落とすことがある部屋に近い。自分が消していなくても電気が切れ、また入る。だから「電源が入り直しても元どおりになる」ように普段から備える。
ただし崩れる点: 住宅の点検は事前通知が普通だが、クラウドの障害起因の再起動は突然で、通知が間に合わないこともある。計画と突発の両方に備える。

管理コンソールと、その鍵

この節で分かること: 管理コンソールへの経路と認証。

クラウドのサーバやファイアウォール・ルーティングを設定するのは、管理コンソール（システムコンソール）——ふつうはインターネット経由でアクセスする Web の管理画面である。ここを握られると、OS をどれだけ固めていても、仮想サーバの作り直し・ファイアウォールの開放・データの持ち出しまで全部できてしまう。管理コンソールは最大の攻撃対象である。

だから管理コンソールへのログインには、パスワードだけに頼らず多要素認証（MFA）を併用する。知識（パスワード）に加えて、所持（スマートフォンのアプリやハードウェアキー）や生体を組み合わせ、パスワードが漏れても単独では入れないようにする。所持の要素としてよく使われるのがワンタイムパスワード（一定時間だけ有効な使い捨ての数字。TOTP）である。OS の ssh 鍵をいくら厳重にしても、管理コンソールが素のパスワード1つなら、守りの一番太い入口が弱点になる。

たとえ: 管理コンソールは、建物全体のマスターキーと制御室に近い。各部屋の鍵（OS の ssh）より、制御室の鍵のほうがはるかに重い。だから制御室には、鍵（パスワード）に加えて本人の携帯に届く暗証（ワンタイムパスワード）など二重の確認を課す。
ただし崩れる点: 物理の制御室は中に入らないと操作できないが、管理コンソールはインターネット経由で世界中から届く。だから物理の建物より、認証の多重化が決定的に重要になる。
手を動かす: この章は理論で、クラウドの管理コンソールは檻に入らない（アカウント作成と課金が発生するため）。かわりに、第8章のssh -L のポート転送をもう一度見てほしい。練習機の外から届くのは転送した 22 だけで、練習機の中のサービス（2323）には直接届かなかった。この「外側の転送設定が到達を決める」構図が、そのままクラウドのセキュリティグループのたとえになっている。
確認

クラウドの仮想サーバで、OS の iptables を全開（すべて ACCEPT）にした。外からそのサーバの全ポートに届くようになるか。

答え

ならない。外からの到達は、サーバ OS の外側にある事業者のファイアウォール（セキュリティグループ）とルーティングが別に決める。 OS を全開にしても、セキュリティグループが閉じていれば届かない。守りは両方の層にある（責任分担）。

確認

クラウドの管理コンソールを守るうえで、パスワードに加えて導入すべきものはどれか。また、なぜ特に重要か。

答え

多要素認証（MFA。所持要素としてワンタイムパスワードなど）。管理コンソールはインターネット経由でアクセスでき、 握られるとサーバの作り直し・ファイアウォールの開放・データ持ち出しまでできる最大の攻撃対象なので、パスワード単独では危うい。

この章で分かったこと

持ち帰ってほしいこと

  • クラウドはセキュリティの責任が分担されている。外からの到達を決めるのは OS の中ではなく、事業者側のファイアウォール（セキュリティグループ）とルーティング
  • オンプレミスは全部が自分の責任。クラウドへ移るときは線引きを知らないと「固めたのに開いていた／開けたのに繋がらない」が起きる
  • リージョンは遅延・法律（国内外の制約）・使えるサービスを左右する。揮発性ストレージは停止で消えるので永続データは別に置く
  • 事業者の都合（メンテナンス・障害）で、自分の意思と無関係に再起動・停止される。復旧前提で組む
  • 管理コンソールはインターネット経由の最大の攻撃対象。多要素認証とワンタイムパスワードで守る
