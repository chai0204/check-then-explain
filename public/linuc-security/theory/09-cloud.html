9. クラウドでは、守る範囲が分かれている

パブリッククラウドにサーバを置くと、「サーバの OS の中だけ守れば安全」という感覚が崩れる。外から届くのは、OS の中のファイアウォールと、OS の外側にあるファイアウォール（セキュリティグループ）の両方が通すものだけだからだ。しかもその外側の設定をするのは、事業者ではなく利用者自身である。

前提: 第8章まで読了理論のみ（檻の外）所要 14分影響度 A出題範囲 1.10.4（重要度3）最終検証 2026-10-13

この章のゴール

  • パブリッククラウドとオンプレミスで、セキュリティの責任分担がどう違うかを言える
  • 管理コンソール・セキュリティグループ（ファイアウォール）・ルーティング・リージョン・揮発性ストレージの意味を説明できる
  • 管理コンソールへの経路と、多要素認証・多段階認証・ワンタイムパスワードの違いを言える
ここで覚えなくていいこと: 特定のクラウド事業者（AWS・Azure・Google Cloud など）の固有のサービス名・画面・料金体系はレベル1では問われない。ここでは事業者を問わない共通の考え方だけを扱う。

OS の中だけ見ても、到達は決まらない

この節で分かること: 外からの到達を決める層と、利用者と事業者の責任分担。

ふつうこう考える

サーバのセキュリティは、その OS の中で完結する。ファイアウォールも、第7章でやったように OS の中で iptables や firewalld を設定すれば、外から何が届くかはそれで決まるはずだ。

だめな理由: この教材の練習機でも、外側のホストから届くポートを決めていたのは練習機の OS だけではなかった。 練習機の中では 2323 が待ち受けていたが、外側から直接は届かず（第8章）、届くのは外側で転送を設定した 22 だけだった。 クラウドの仮想サーバでも同じで、OS の外側にセキュリティグループ（仮想サーバごとのファイアウォール）があり、 外から届くのはセキュリティグループと OS のファイアウォールの両方が通すものだけである。 OS を全開にしてもセキュリティグループが閉じていれば届かないし、セキュリティグループを開けても OS が落とせば届かない。 そして IaaS（仮想サーバを借りる形）では、セキュリティグループの設定は利用者の責任である。

責任の分け方（責任共有モデル）は、おおまかに次のとおりである。事業者は「仕組み」を、利用者は「その上の設定と中身」を持つ。

層オンプレミスパブリッククラウド（IaaS）
建物・電源・物理サーバ・物理ネットワーク自分事業者
仮想化の基盤、ファイアウォール（セキュリティグループ）の仕組み自分事業者
セキュリティグループの設定（どのポートを誰に開けるか）・ルーティングの設定自分利用者
OS（パッチ・アカウント・OS のファイアウォール）・アプリ・データ自分利用者

オンプレミスでは全部が自分の責任だったので、この線引きを知らずにクラウドへ移ると「OS は固めたのに、セキュリティグループで全開にしていた」「OS は開けたのに繋がらない（セキュリティグループが閉じていた）」が起きる。

たとえ: クラウドのサーバは、管理会社のある集合住宅の一室に近い。正面のオートロックの設備（セキュリティグループの仕組み）は管理会社が用意するが、誰を通すかの登録（設定）は住人がする。部屋の鍵（OS のファイアウォール）も住人が掛ける。
ただし崩れる点: 集合住宅では管理の線引きが契約書で曖昧なこともあるが、クラウドの責任共有モデルは「どの層が誰の責任か」が明示されている。見落とすのは、線引きの存在を知らないときである。
たとえ: ルーティング（経路）は、建物の廊下やエレベーターの配置に近い。どの部屋からどの部屋へ行けるかは、仮想ネットワークの経路の設定で決まり、その設定もセキュリティグループと同じく利用者が管理コンソールで行う。
ただし崩れる点: 実際の廊下は目で見えるが、クラウドの経路は管理コンソールの設定画面でしか見えない。図と実態がずれていても、現地を歩いて確かめることができない。

リージョンと、消える前提のストレージ

この節で分かること: 場所の選択と、ストレージの揮発性。

リージョンは、サーバを置く地理的な地域（データセンターの所在地）である。どのリージョンを選ぶかで、利用者からの遅延、データに適用される法律、使えるサービスや料金が変わる。国内のデータでも海外のリージョンを選ぶこと自体は一律に禁じられてはいないが、業種の規制・契約・個人情報の扱い（国外へ移すときの要件）によっては国内に置く必要がある。1つの国に複数のリージョンを持つ事業者もある（日本なら東京と大阪など）。場所の選択は、セキュリティとコンプライアンスの問題でもある。

もう1つ注意が要るのが揮発性ストレージである。クラウドの仮想サーバには、仮想サーバを停止・休止・終了（削除）すると中身が消える一時的なディスク（インスタンスストアなど）が付くことがある。OS の再起動では消えないが、停止して起動し直すと別の物理サーバに移ることがあり、そのときは空になる。速くて安いが、消える前提で使う。残したいデータは、別の永続ストレージ（ブロックストレージ・オブジェクトストレージ）に置く。

たとえ: 揮発性ストレージは、ホテルの部屋の机の上に近い。滞在中（再起動しても同じ部屋にいる間）は使えるが、チェックアウト（停止・終了）で片付けられる。残したいものはフロントの預かり（永続ストレージ）に移す。
ただし崩れる点: ホテルは忘れ物を一時保管してくれることがあるが、揮発性ストレージは停止と同時に消える。猶予は無い。

事業者の都合で、止まる・再起動する

この節で分かること: 自分の意思と無関係に起きる停止。

オンプレミスなら、サーバをいつ止めるかは自分で決める。クラウドでは、事業者のメンテナンスや基盤の障害で、利用者の都合と関係なく仮想サーバが再起動・別の物理サーバへの移動・停止されることがある。事前に通知される計画メンテナンスもあれば、ハードウェア障害による突然のものもある。だから「いつ止まっても自動で元に戻る」前提で組む（起動時にサービスが上がる、データは永続ストレージにある、など）。第6章で見た「止めたサービスが次の起動でも止まっているか（enable/disable）」が、クラウドでは自分の意思と無関係な再起動で効いてくる。

たとえ: クラウドのサーバは、管理会社が点検で一時的にブレーカーを落とすことがある部屋に近い。自分が消していなくても電気が切れ、また入る。だから「電源が入り直しても元どおりになる」ように普段から備える。
ただし崩れる点: 住宅の点検は事前通知が普通だが、クラウドの障害起因の再起動は突然で、通知が間に合わないこともある。計画と突発の両方に備える。

管理コンソールと、その鍵

この節で分かること: 管理コンソールへの経路と認証の方式。

クラウドの仮想サーバ・セキュリティグループ・ルーティングを設定するのは、管理コンソール（システムコンソール）——ふつうはインターネット経由でアクセスする Web の管理画面（とその API）である。ここを握られると、OS をどれだけ固めていても、仮想サーバの作り直し・セキュリティグループの全開放・データの持ち出しまでできてしまう。管理コンソールは最大の攻撃対象である。

だから管理コンソールへのログインには、事業者が提供する認証方式を使い、パスワードだけに頼らない。言葉が似ている2つを区別する。

方式中身例
多要素認証（MFA）種類の違う要素を組み合わせる。知識（知っているもの）・所持（持っているもの）・生体（本人の特徴）のうち2つ以上パスワード＋スマートフォンのアプリのワンタイムパスワード、パスワード＋ハードウェアキー
多段階認証認証を複数の段階に分ける。要素の種類は同じでもよいパスワードの後に「秘密の質問」（どちらも知識）

ワンタイムパスワードは、一定時間（多くは 30 秒）だけ有効な使い捨ての数字で、スマートフォンのアプリやハードウェアの装置が作る（所持の要素）。パスワードが漏れても、それを持っていなければ入れない。同じ種類の要素を重ねるだけの多段階認証は、まとめて盗まれやすい（知識はどれもフィッシングで盗める）ので、管理コンソールには多要素認証を使う。OS の ssh 鍵をいくら厳重にしても、管理コンソールが素のパスワード1つなら、守りの一番太い入口が弱点になる。

たとえ: 管理コンソールは、建物全体のマスターキーと制御室に近い。各部屋の鍵（OS の ssh）より、制御室の鍵のほうがはるかに重い。だから制御室には、鍵（パスワード）に加えて本人の携帯に出る番号（ワンタイムパスワード）という種類の違う確認を課す。
ただし崩れる点: 物理の制御室は中に入らないと操作できないが、管理コンソールはインターネット経由で世界中から届く。だから物理の建物より、認証の組み合わせが決定的に重要になる。
手を動かす: この章は理論で、クラウドの管理コンソールは檻に入らない（アカウント作成と課金が発生するため）。かわりに、第8章の ssh -L のポート転送をもう一度見てほしい。練習機の外から届くのは外側で転送した 22 だけで、練習機の中のサービス（2323）には直接届かなかった。この「OS の外側の設定も到達を決める」構図が、クラウドのセキュリティグループのたとえになっている。
確認

クラウドの仮想サーバで、OS の iptables を全開（すべて ACCEPT）にした。外からそのサーバの全ポートに届くようになるか。

答え

届くとは限らない。外から届くのは、OS の外側のセキュリティグループと OS のファイアウォールの両方が通すものだけである。 セキュリティグループで閉じているポートには届かない。セキュリティグループの設定も利用者の責任（IaaS の場合）。

確認

パスワードを入れた後に「秘密の質問」に答えさせる方式は、多要素認証か。

答え

多要素認証ではなく多段階認証である。パスワードも秘密の質問も「知識」という同じ種類の要素なので、段階は2つでも要素は1種類。 多要素認証は、パスワード（知識）とワンタイムパスワードを出すスマートフォン（所持）のように、種類の違う要素を組み合わせる。

確認

インスタンスストア（揮発性ストレージ）に置いたデータは、OS の再起動で消えるか。仮想サーバを停止して起動し直したらどうか。

答え

OS の再起動では消えない。停止・休止・終了で消える（停止して起動し直すと別の物理サーバに移ることがあり、そのときは空になる）。 残したいデータは永続ストレージに置く。

この章で分かったこと

持ち帰ってほしいこと

  • 外から届くのは、OS の外側のセキュリティグループと OS のファイアウォールの両方が通すものだけ
  • 責任共有モデル: 事業者は設備・基盤・ファイアウォールの仕組み、利用者はセキュリティグループやルーティングの設定と OS・アプリ・データ（IaaS）。オンプレミスは全部が自分
  • リージョンは遅延・法律・使えるサービスを左右する。国内のデータの海外リージョンは一律禁止ではないが、規制や契約で国内が必要なこともある
  • 揮発性ストレージは停止・休止・終了で消える（再起動では残る）。事業者のメンテナンスや障害で再起動・停止されうるので、復旧前提で組む
  • 管理コンソールはインターネット経由の最大の攻撃対象。種類の違う要素を組み合わせる多要素認証（ワンタイムパスワードなど）で守る。多段階認証とは別物
