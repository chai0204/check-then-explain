確かめて説明する LinuC 主題1.06

LinuC レベル1 102 試験・主題1.06「シェルおよびスクリプト」 （シェル環境のカスタマイズ / シェルスクリプト）を、 全部コンテナの中で実際に打って確かめます。 1.06.2 は重要度 6 で、レベル1 の全39副題の中で最も重い副題です。 ~/.bashrc を書き換えても、su - alice と打っても、母艦には何も起きない檻です。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: コマンドは打てる。写経すれば動く。 でも「なぜ動くのか」を人に説明できない人。
LinuC を受ける人向けには: ~/.bash_profile と ~/.bashrc の違いや $@ と $* の違いを、 表で覚えようとして覚えきれない人。

はじめる

Docker の場合。1行（4行に折り返しています）です。

docker run --rm -it --name lab-linuc-shell --hostname linuc \
  -v lab-linuc-shell-work:/home/lab/work \
  -v lab-linuc-shell-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:shell-1.0.4@sha256:__DIGEST__

権限を追加するオプション（--privileged や --cap-add）は使いません。 --hostname linuc は、プロンプトや出力に出るホスト名を本文と揃えるためです。

入ると現在地が出ます。この案内がなぜ出るのか（なぜ bash と打ち直すと出ないのか）が、第1章の入口です。

lab-linuc-shell  進捗 0/8
  次 → 01 「ログインしたときだけ挨拶を出す」 (目安 10分 / 影響度 B)
  lab start 01 で課題を開く
  進捗の保存先: /home/lab/.lab/progress.json（消すには docker volume rm lab-linuc-shell-state）
  lab ls      演習一覧 / lab start NN  課題を開く / lab check  答え合わせ

端末を2つ使いたいときの注意

別の端末から docker exec -it lab-linuc-shell bash -l で入ることもできます。 ただしそちらの端末は umask が 0000 になり、作ったファイルの権限が本文（docker run で入った端末・0022）と変わります。

docker run で入った端末で作ったファイル   -rw-r--r--   （umask 0022）
docker exec で入った端末で作ったファイル   -rw-rw-rw-   （umask 0000）

第4章の ls -l の結果を本文と揃えたいときは、docker run で入った最初の端末を使うか、 2つ目の端末で umask 022 と打ってから始めてください。lab env の umask の行で確かめられます。

シェルは章をまたいで同じまま使う前提です。檻に入ったときのシェル（PID 1 の bash -l）で、第1章から順に打っていく書き方にしてあります（PID 1 で exit するとコンテナごと消えるので、入り直す必要はありません）。章の中で変えたシェルの状態のうち、後の章の画面を変えるもの（第2章で足した PATH と、上書きした ls の alias）は、その章の中で元に戻す行を本文に出してあります。理論編の第2〜8章はどれも ~/try に必要なファイルを自分で作ってから始まるので、前の章から続けても、檻を起動し直した直後からその章を始めても、同じ画面になります。本文の記録は、第1章から第8章までを1つのシェルで通して打った記録とも突き合わせてあります。

先に読む場合は 理論編（8章）へ。 章と演習は対応しているので、どちらから始めても構いません。

lab reset NN で演習を配られたときの状態に戻すと、~/work/NN はディレクトリごと作り直されます。 そのディレクトリの中にいたなら、続けて cd ~/work/NN と打ち直してください（打たないと、消えた古いディレクトリに残ったままになり、ls は何も出さず、cat などは No such file or directory になります）。

終わったら

--rm を付けて起動しているので、exit で抜ければコンテナは消えます。

docker volume rm lab-linuc-shell-work lab-linuc-shell-state     # 作業と進捗も消す場合だけ

イメージは docker rmi で消せます。 母艦には何も残りません（名前付きボリューム以外のファイルを作っていないため）。
