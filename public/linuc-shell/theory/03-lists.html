3. && と || は、直前の数だけを見ている

mkdir newdir && cp … newdir/ || echo "mkdir に失敗した" と打った。mkdir は成功してディレクトリができているのに、「mkdir に失敗した」と出る。|| は mkdir の結果を見ていない。直前のコマンドが返した数（終了ステータス）だけを見ている。コマンド置換 $( ) も同じ形をしていて、中のコマンドから受け取れるのは、標準出力の文字とその数だけである。

前提: 第2章まで読了所要 15分影響度 A出題範囲 1.06.1（重要度4）最終検証 2026-10-13

この章のゴール

  • リストの ;・&&・|| がそれぞれ何を見て次へ進むかを、終了ステータスで説明できる
  • A && B || C が「A が成功なら B、失敗なら C」と同じにならない場合を挙げられる
  • $( ) と ` ` でコマンドの出力を文字列や変数に入れられ、引用符の有無で改行がどう変わるかを言える
  • ( ) と { } の違いを、カレントディレクトリが残るかで説明できる
ここで覚えなくていいこと: パイプ | とリダイレクトの細部（主題1.03）、& による後回し実行とジョブ制御、プロセス置換 <( )、$(( )) の算術展開（第7章で使う分だけ触れる）。$? の詳しい値は第6章で扱う。ここでは「0 が成功、それ以外が失敗」だけ分かればよい。

どのコマンドも、終わるときに数を1つ返す

この節で分かること: リストが判断に使っているもの。

この章も ~/try で作業する。コマンドは終わるときに 0〜255 の数を1つ返す。これを終了ステータスと呼び、直前の値は $? で読める。0 が成功、それ以外が失敗である。

$ mkdir -p ~/try && cd ~/try
$ true; echo $?
0
$ false; echo $?
1

true は何もせず 0 を、false は何もせず 1 を返すコマンドである。次のリストは、この数だけを見て進む。

; は続け、&& は成功なら続け、|| は失敗なら続ける

この節で分かること: 3つのつなぎ方の違いと、組み合わせたときの落とし穴。

コマンドを ;・&&・|| でつないだものをリストと呼ぶ。存在しないディレクトリに移ろうとして、続けて pwd を打つ。

$ cd /nonexistent; pwd
bash: cd: /nonexistent: No such file or directory
/home/lab/try
$ cd /nonexistent && pwd
bash: cd: /nonexistent: No such file or directory

; は前の結果を見ずに続ける。cd は失敗したのに pwd が動き、元の場所が出た。もしこれが cd の後に「中身を消す」コマンドだったら、元の場所で実行される。&& は前が成功（0）したときだけ続けるので、pwd は動かなかった。

$ mkdir /forbidden || echo "作れなかった"
mkdir: cannot create directory ‘/forbidden’: Permission denied
作れなかった
$ grep -q '^alice:' /etc/passwd && echo いる || echo いない
いる
書き方B が実行される条件使いどころ
A ; Bいつでも（A の結果を見ない）関係の無いコマンドを1行に並べる
A && BA の終了ステータスが 0（成功）前の準備が済んだときだけ進む
A || BA の終了ステータスが 0 以外（失敗）失敗したときだけ知らせる・代わりをする

では && と || を並べて、「成功なら次へ、失敗なら知らせる」を1行で書く。

ふつうこう考える

A && B || C は「A が成功したら B、A が失敗したら C」と読める。mkdir が成功してディレクトリができたなら、「mkdir に失敗した」とは出ないはずだ。

$ mkdir newdir && cp /nonexistent newdir/ || echo "mkdir に失敗した"
cp: cannot stat '/nonexistent': No such file or directory
mkdir に失敗した
$ ls -d newdir
newdir
だめな理由: ls -d newdir が示すとおり、mkdir は成功している。それでも「mkdir に失敗した」と出た。 リストは左から順に評価され、|| が見るのはすぐ左までをまとめた結果、つまり最後に実行された cp の終了ステータスである。 mkdir 成功 → && なので cp を実行 → cp 失敗 → || なので echo を実行、という流れで、 メッセージの文言が mkdir の話をしているのは書いた人の思い込みにすぎない。A && B || C は if 文ではない。

「B の失敗だけを C で拾う」と書きたいなら、{ } で範囲をはっきりさせる。

$ mkdir newdir2 && { cp /nonexistent newdir2/ || echo "cp に失敗した"; }
cp: cannot stat '/nonexistent': No such file or directory
cp に失敗した

A の成否で分けたいなら if を使う（第6章）。

if mkdir newdir; then
    cp /nonexistent newdir/ || echo "cp に失敗した"
else
    echo "mkdir に失敗した"
fi
たとえ: リレーのバトンに旗が1本だけ付いているのに近い。各走者は走り終わると旗を「成功（0）」か「失敗」に立てて渡す。&& と || の係は、いま手元に来た旗しか見ない。
ただし崩れる点: リレーなら誰が転んだかは見ていれば分かるが、ここでは前の走者の旗は次の走者に上書きされて残らない。どこで失敗したかを知りたければ、走者ごとに分けて確かめるしかない。

コマンド置換は、子の出力を文字として受け取る

この節で分かること: $( ) と ` ` が返すものと、返さないもの。

$(コマンド) と書くと、そこがコマンドの標準出力に置き換わる。これをコマンド置換と呼ぶ。古い書き方の `コマンド`（バッククォート）も同じ意味である。

$ echo "今日は $(date +%F)"
今日は 2026-10-13
$ echo "わたしは `id -un`"
わたしは lab
$ echo "外 $(echo "内 $(id -un)")"
外 内 lab
$ n=$(wc -l < /etc/passwd); echo "passwd は $n 行"
passwd は 21 行

$( ) は中に $( ) をそのまま書ける（入れ子）。バッククォートは入れ子にするとき内側を \` とエスケープする必要があり、読みにくいので、いまは $( ) が勧められている。

$ echo "外 `echo \`id -un\``"
外 lab

出力に改行があるときは、引用符の有無で結果が変わる。

$ ls -A1 /etc/skel
.bash_logout
.bashrc
.profile
$ files=$(ls -A1 /etc/skel); echo $files
.bash_logout .bashrc .profile
$ echo "$files"
.bash_logout
.bashrc
.profile

変数の中身は3行のままである。引用符で囲まずに echo $files と書くと、展開された後に空白や改行で単語に切り分けられ（第5章の「ワード分割」）、1行にまとまった。"$files" と囲めば改行が残る。

そしてコマンド置換の中は、子のシェル（サブシェル）で動く。

$ x=1; y=$(x=2; echo $x); echo "x=$x y=$y"
x=1 y=2
$ v=$(false); echo "終了ステータス $?"
終了ステータス 1
$ echo "[$(printf 'a\n\n\n')]"
[a]
コマンド置換から受け取れるもの受け取れないもの
標準出力の文字（末尾の改行はすべて削られる）中で作った・変えた変数（x は 1 のまま）
終了ステータス（v=$(false) の直後の $? は 1）中で移ったディレクトリ

第2章の「子は親を書き換えられない」が、ここでも成り立っている。

たとえ: 別室の担当者にメモ用紙を渡して答えを書いてもらうのに近い。戻ってくるのは紙に書かれた文字だけで、担当者が別室で何を広げて片づけたか（変数）は持ち帰れない。
ただし崩れる点: メモ用紙なら末尾の空行もそのまま戻るが、コマンド置換は末尾の改行をすべて削って返す。printf 'a\n\n\n' の答えは a だけになった。

( ) は子のシェル、{ } はいまのシェル

この節で分かること: 2種類のかっこの違い。
$ (cd /tmp; pwd); pwd
/tmp
/home/lab/try
$ { cd /tmp; pwd; }; pwd
/tmp
/tmp

( ) の中は子のシェルで動くので、cd /tmp は外に残らない。{ } はいまのシェルでまとめて実行するだけなので、外に出ても /tmp のままである。{ の後には空白が、} の前には ; か改行が要る。

たとえ: ( ) は別の部屋で作業してもらうこと、{ } は自分の机の上で作業をひとまとめにする付箋である。別の部屋で模様替えをしても自分の部屋は変わらないが、付箋でまとめた作業は自分の机の上で起きる。
ただし崩れる点: どちらも終了ステータスは外に返ってくる。別の部屋でも、成功したか失敗したかだけは伝わる。
手を動かす: この章には専用の演習が無い。&& と || と $( ) は、実践編の演習04・05（引数の検査と終了ステータス）でそのまま使う。 bash mkbak.sh && echo ok || echo ng のように、自分のスクリプトの終了ステータスをリストで確かめてみること。
確認

date +%F の出力を変数 d に入れる書き方を2つ挙げよ。

答え

d=$(date +%F) と d=`date +%F`。どちらもコマンド置換で、出力の末尾の改行は削られる。 入れ子にするなら $( ) のほうが書きやすい。

確認

cmd1 || cmd2 で cmd2 が実行されるのはどんなときか。

答え

cmd1 の終了ステータスが 0 以外（失敗）のとき。cmd1 && cmd2 は 0 のとき。cmd1 ; cmd2 は結果に関係なく常に実行する。

確認

mkdir a && cp x a/ || echo NG を実行したら NG と出た。考えられる原因を2つ挙げよ。

答え

(1) mkdir a が失敗した（cp は実行されず、|| へ進んだ）。(2) mkdir a は成功したが cp x a/ が失敗した。 || は直前に実行されたコマンドの終了ステータスしか見ないので、出力の NG だけでは区別できない。ls -d a で確かめる。

確認

(cd /tmp; ls) を実行した後と、{ cd /tmp; ls; } を実行した後で、pwd の結果はどう違うか。

答え

( ) の後は元のディレクトリのまま、{ } の後は /tmp になる。( ) は子のシェルで動き、子が移ったディレクトリは親に残らない。

この章で分かったこと

持ち帰ってほしいこと

  • コマンドは終わるときに 0〜255 の数（終了ステータス）を1つ返す。0 が成功。直前の値は $?
  • ; は常に続け、&& は 0 なら続け、|| は 0 以外なら続ける。見るのは直前に実行されたコマンドの数だけ
  • A && B || C は if 文ではない。B が失敗しても C が動く。分けたいなら if か { }
  • $(コマンド) と `コマンド` はコマンド置換。返るのは標準出力の文字（末尾の改行は削られる）と終了ステータスだけ
  • echo $var は改行と空白で切り直され、echo "$var" はそのまま出る
  • ( ) とコマンド置換の中は子のシェル。変数もディレクトリも外に残らない。{ } はいまのシェル
