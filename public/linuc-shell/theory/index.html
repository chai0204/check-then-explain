理論編 — シェルおよびスクリプト

LinuC レベル1 102 試験・主題1.06（シェル環境のカスタマイズ / シェルスクリプト）を、 全部コンテナの中で実際に打って確かめる8章。 1.06.2 は重要度 6 で、LinuC レベル1 の全39副題の中で最も重い副題です。 読むだけで終わらせないために、1章ごとに「実際に打つと何が出るか」を先に置いています。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この8章を貫いている1つの事実

新しく起動したシェルやスクリプトは、親の環境変数のコピーを受け取って始まる。終わるときに親へ返せるのは、0〜255 の終了ステータス1つだけである。

bash ~/.bashrc では alias が残らない。cat f | while で数えた合計は 0 になる。exit 256 は「成功」として届く。 どれも同じ事実の現れで、主題1.06 の「詳細」欄に並ぶ source・~/.profile と ~/.bashrc・$?・exit・"$@"・PATH は、 ほとんどがこの事実への対処として存在しています。だから「いまどのシェルの中で動いているか」を見分けられれば、語を丸暗記しなくても答えが組み立てられます。 例外は関数だけで、関数は子ではない（第8章）。

ここで覚えなくていいこと: zsh・csh などほかのシェル、getopts、配列の操作（要素の取り出し方だけは第5章で扱う）、[[ ]] の詳しい文法、trap とシグナル、set -e、 プロセス置換、select 文。どれもレベル1の詳細欄に無く、この8章には出てこないか、名前だけです。

例題の解説が本文と違う言い方をしているところが3つある。先頭行（#!）が無いスクリプトは「ログインシェルで実行される」のではなく起動した側のシェルが読む（第4章）。「$@ は引数ごとに "" で囲まれる」のは "$@" と書いたときだけ（第5章）。/etc/profile にも alias は書ける（第2章）。どれも記録で確かめてある。

章

  1. 起動ファイルはシェルの生まれ方で決まる — ~/.bash_profile を1つ作ると、~/.profile と ~/.bashrc が読まれなくなり、ll が消える（20分）
  2. 子のシェルは親を書き換えられない — bash ~/.bashrc はエラーを出して何も残さない。読み直しは source（18分）
  3. && と || は直前の数だけを見る — ディレクトリはできているのに「mkdir に失敗した」と出る（15分）
  4. 先頭行を読むのはカーネル — bash hello.sh で動くのに ./hello.sh は文法エラー。alice の ~/bin/date が全員用のスクリプトに割り込む（22分）
  5. 引数は渡す側で切られている — "my file.txt" が $* で2つに割れる。$10 は a0（15分）
  6. 返せるのは 0〜255 の数1つ — exit 256 は成功（0）として届く（18分）
  7. パイプの先で数えた数は持ち帰れない — ループの中では 3 まで数えたのに、合計は 0（20分）
  8. 関数は子ではない — 番号が 1 の次に 21 へ飛ぶ。bash -x で原因の行を見つける。ここで8章が1本になる（20分）

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの4つに集まります。

場面ここで効く理由見落としやすい点関連する章
新しいサーバで自分の環境を整える PATH は ~/.profile、alias は ~/.bashrc と書き分ければ、ログインして使う限り（端末・ssh・su -・sudo -i）同じ環境になる ~/.bash_profile を新しく作ると ~/.profile が読まれなくなる。su（- なし）や sudo -u では ~/.profile は読まれない1・2
スクリプトを他の人や cron に使わせる 実行するのは別の人・別の環境なので、PATH も権限も自分の端末と違う 先頭行・r と x・所有者・PATH の4つを揃える。sudo -i と su - でも PATH が違う4
「成功したのに結果が無い」を調べる スクリプトは最後のコマンドの値で終わり、途中の失敗を伝えない A && B || C や exit の書き忘れで、失敗が 0 として届く3・6
ログやファイルを集計する while read と for で1行・1ファイルずつ処理できる cat f | while で数えた合計は 0。done < f でつなぐ7・8

この主題を使わない方がよい場面も1つあります。 数百行を超える処理や、数値計算・データ構造が要る処理をシェルスクリプトで書き続けることです。 この8章で見た落とし穴（ワード分割・サブシェル・終了ステータスの丸め）は、行が増えるほど踏む回数が増えます。 そうなったら Python などに移るのが、シェルを分かっている人の判断です。
