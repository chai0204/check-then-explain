5. 引数は、渡す側のシェルが切ってから渡す

スクリプトが受け取る引数は、あなたが打った1行の文字列ではない。呼んだ側のシェルが空白で切り、引用符を外したあとの「語の並び」である。スクリプトの中でそれを "$@" と書けば区切りが保たれ、$* と書くともう一度切り直される。"my file.txt" が my と file.txt に割れるのは、この切り直しのときである。

前提: 第4章まで読了所要 15分影響度 A出題範囲 1.06.2（重要度6）最終検証 2026-10-13

この章のゴール

  • $0・$1〜$n・$#・$@・$* が何を表すかを、実際の出力で説明できる
  • "$@"・"$*"・$* の違いを言い、受け取った引数を別のコマンドへ渡すときに "$@" を使う理由を言える
  • shift と $# で引数を1つずつ処理でき、10個目以降の書き方（${10}）を知っている
  • 引数の数を確かめて、使い方を標準エラーに出して終われる
ここで覚えなくていいこと: getopts によるオプションの解析、$$・$!・$- など他の特殊パラメータ（$- は第1章で使った）、IFS の細かい規則、配列。

my file.txt が、2つに割れる

この節で分かること: $* で引数を渡すと何が起きるか。

この章も ~/try で作業する。名前に空白を含むファイルを1つ作り、渡されたファイルを全部 /tmp へコピーするスクリプトを書く。

$ mkdir -p ~/try && cd ~/try
$ touch "my file.txt"

ふつうこう考える

$* は「渡された引数ぜんぶ」である。"my file.txt" と引用符で囲んで渡したのだから、cp $* /tmp/ は1つのファイルとしてコピーするはずだ。

$ cat > cpall.sh <<'END'
> #!/bin/bash
> cp $* /tmp/
> END
$ bash cpall.sh "my file.txt"; echo "終了ステータス $?"
cp: cannot stat 'my': No such file or directory
cp: cannot stat 'file.txt': No such file or directory
終了ステータス 1
だめな理由: 引用符はあなたのシェルが外し、スクリプトは my file.txt を1つの引数として受け取っている。 ところがスクリプトの中で、引用符で囲まない $* は、展開した後にもう一度空白で語に切られる（ワード分割）。 cp に届いたのは my と file.txt の2つで、どちらも存在しない。 引数を受け取ったとおりの区切りで渡すには "$@" と書く。
$ sed -i 's/\$\*/"$@"/' cpall.sh; cat cpall.sh
#!/bin/bash
cp "$@" /tmp/
$ bash cpall.sh "my file.txt"; ls -l "/tmp/my file.txt"
-rw-r--r-- 1 lab lab 0 Oct 13 10:46 '/tmp/my file.txt'
たとえ: 引数は、呼ぶ側が箱詰めして渡した荷物に近い。"$@" は箱のまま次へ回す。$* は箱を全部開けて中身を床に並べ、空白のところで改めて箱に詰め直す。"$*" は全部を1つの大箱にまとめる。
ただし崩れる点: 荷物なら詰め直しても中身は変わらないが、引数は詰め直すと区切りの位置が変わる。my file.txt は2つの別の名前になり、どちらも存在しないファイルを指す。

$0・$1・$#・$@・$*

この節で分かること: スクリプトの中で引数を表す変数と、誰が引数を切っているか。

受け取った引数を全部見せるスクリプトで確かめる。

$ cat > args.sh <<'END'
> #!/bin/bash
> echo "\$0 = $0"
> echo "\$# = $#"
> echo "\$1 = $1"
> echo "\$2 = $2"
> echo '--- for a in "$@"'
> for a in "$@"; do echo "[$a]"; done
> echo '--- for a in "$*"'
> for a in "$*"; do echo "[$a]"; done
> echo '--- for a in $*'
> for a in $*; do echo "[$a]"; done
> END
$ chmod +x args.sh
$ ./args.sh "my file.txt" b
$0 = ./args.sh
$# = 2
$1 = my file.txt
$2 = b
--- for a in "$@"
[my file.txt]
[b]
--- for a in "$*"
[my file.txt b]
--- for a in $*
[my]
[file.txt]
[b]

同じスクリプトを、引用符を付けずに呼ぶ。

$ ./args.sh my file.txt b
$0 = ./args.sh
$# = 3
$1 = my
$2 = file.txt
--- for a in "$@"
[my]
[file.txt]
[b]
--- for a in "$*"
[my file.txt b]
--- for a in $*
[my]
[file.txt]
[b]

$# が 2 から 3 に変わった。スクリプトの中身は同じで、変わったのは呼んだ側のシェルの切り方だけである。引用符で囲めば1つの引数、囲まなければ空白で別々の引数になる。

書き方意味記録（./args.sh "my file.txt" b）
$0スクリプト自身の名前（呼ばれたときの書き方のまま）./args.sh
$1・$2 …1つ目・2つ目の引数（位置パラメータ）my file.txt・b
$#引数の数2
"$@"全部の引数を、受け取った区切りのまま並べる[my file.txt] [b]
"$*"全部の引数を空白でつないだ1つの文字列[my file.txt b]
$*・$@（引用符なし）全部を並べてから、空白でもう一度切り直す[my] [file.txt] [b]

$#・$@・$*・$0・$? のように、記号1文字の名前を持つものは特殊パラメータと呼ばれる。$0 は呼ばれ方で変わる（第4章の記録では ./hello.sh・hello.sh・/usr/local/bin/hello だった）。

たとえ: $0 は呼び出しのときに呼ばれた名前、$1 以降は受付の番号札に近い。同じ人でも「おーい」と呼ばれるか、フルネームで呼ばれるかで $0 は変わる。
ただし崩れる点: 番号札は配った後で数字が変わらないが、位置パラメータは shift で全員の番号が1つずつ繰り上がる（次の節）。

10個目は ${10}

この節で分かること: 2桁の位置パラメータの書き方。
$ cat > ten.sh <<'END'
> #!/bin/bash
> echo "\$# = $#"
> echo "\$10 = $10"
> echo "\${10} = ${10}"
> END
$ bash ten.sh a b c d e f g h i j
$# = 10
$10 = a0
${10} = j

$10 は「$1 の後ろに文字 0」と読まれ、a0 になった。10個目以降は ${10} のように波かっこで囲む。

shift で、引数を前に詰める

この節で分かること: shift の働きと、それを使った引数の処理のしかた。
$ cat > sh.sh <<'END'
> #!/bin/bash
> echo "はじめ:     \$# = $#  \$1 = $1  \$@ = $@"
> shift
> echo "shift 後:   \$# = $#  \$1 = $1  \$@ = $@"
> shift 2
> echo "shift 2 後: \$# = $#  \$1 = $1"
> shift 5
> echo "shift 5 の終了ステータス = $?  \$# = $#"
> END
$ bash sh.sh a b c d
はじめ:     $# = 4  $1 = a  $@ = a b c d
shift 後:   $# = 3  $1 = b  $@ = b c d
shift 2 後: $# = 1  $1 = d
shift 5 の終了ステータス = 1  $# = 1

shift は $1 を捨てて全員を1つずつ前に詰め、$# を1減らす。shift 2 なら2つ詰める。残っている数より多く詰めようとすると、何も変えずに終了ステータス 1 を返した。

$# が 0 になるまで shift を繰り返すと、引数を1つずつ処理できる。

$ cat > each.sh <<'END'
> #!/bin/bash
> while [ $# -gt 0 ]; do
>     echo "残り $# 個: [$1]"
>     shift
> done
> END
$ bash each.sh one "two three" four
残り 3 個: [one]
残り 2 個: [two three]
残り 1 個: [four]

対話シェルでは set -- で位置パラメータを自分で入れて試せる。

$ set -- x "y z"; echo $#; echo "$2"
2
y z
たとえ: shift は行列の先頭の人が抜けて、全員が一歩前に詰める動きである。いつでも先頭（$1）だけを見ていれば、順番に全員を案内できる。
ただし崩れる点: 行列から抜けた人はまだどこかにいるが、shift で捨てた引数はもう取り出せない。後で使うなら、詰める前に変数に移しておく。

引数の数を確かめて、使い方を出す

この節で分かること: 引数が足りないときの、行儀のよい終わり方。
$ cat > need.sh <<'END'
> #!/bin/bash
> if [ $# -ne 1 ]; then
>     echo "使い方: $(basename "$0") 名前" >&2
>     exit 1
> fi
> echo "こんにちは、$1"
> END
$ bash need.sh; echo "終了ステータス $?"
使い方: need.sh 名前
終了ステータス 1
$ bash need.sh alice
こんにちは、alice
$ bash need.sh alice bob 2> /dev/null; echo "終了ステータス $?"
終了ステータス 1

引数がちょうど1つでなければ、使い方を出して終了ステータス 1 で終わる。使い方は >&2 で標準エラー出力に出す。2> /dev/null で標準エラーを捨てると、使い方は表示されず、終了ステータスだけが残った。結果を保存したりパイプでつないだりするときに、使い方の文がデータに混ざらないようにするためである。$(basename "$0") は $0 からディレクトリ部分を除いた名前で、どう呼ばれても need.sh と出る。

手を動かす: 実践編の演習04は、引数のファイルそれぞれの .bak を作り、引数が無ければ使い方を出して 1 で終わるスクリプトを書く課題である。 判定は空のディレクトリに a.txt と「my notes.txt」を用意して実際に実行し、できたファイルと終了ステータスを見る。$* で書くと、この章の cpall.sh と同じ割れ方をする。
確認

./s.sh a "b c" d と実行した。スクリプトの中での $# と $2 の値を答えよ。

答え

$# は 3、$2 は b c。引用符は呼んだ側のシェルが外し、b c は1つの引数として渡る。

確認

スクリプトが受け取った引数を、区切りを変えずにそのまま ls -l に渡したい。正しい書き方はどれか。
(A) ls -l $*　(B) ls -l "$*"　(C) ls -l "$@"　(D) ls -l $@

答え

(C)。(A) と (D) は空白を含む引数を切り直す。(B) は全部を1つの文字列にまとめるので、引数が2つ以上あると1つの存在しないファイル名になる。

確認

引数が a b c d e のスクリプトで shift 2 を実行した。その直後の $1 と $# を答えよ。

答え

$1 は c、$# は 3。shift 2 は先頭の2つを捨てて全員を2つ前に詰める。

確認

スクリプトの中で echo $10 と書いたら、10個目の引数ではなく別の文字が出た。何が出たのか、正しくはどう書くか。

答え

$1 の値の後ろに 0 を付けたもの（記録では a0）。正しくは ${10}。

この章で分かったこと

持ち帰ってほしいこと

  • 引数を空白で切り、引用符を外すのは呼んだ側のシェル。スクリプトは切られた後の語の並びを受け取る
  • $0 は呼ばれた名前、$1〜$9 と ${10} 以降が位置パラメータ、$# が数
  • "$@" は受け取った区切りのまま、"$*" は1つにまとめ、引用符なしの $*・$@ は切り直す。渡すなら "$@"
  • shift は先頭を捨てて詰め、$# を減らす。詰めすぎると何もせず 1 を返す
  • 引数の数は [ $# -ne 1 ] などで確かめ、使い方は >&2、終了は exit 1
