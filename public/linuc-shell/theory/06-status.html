6. スクリプトが返せるのは、0〜255 の数1つ

スクリプトの最後に exit 256 と書くと、呼んだ側の $? は 0、つまり「成功」になる。終了ステータスは 0〜255 の数で、それより大きい値は 256 で割った余りしか残らない。子のプロセスが親に返せるものは、この小さな数1つしかない。だから if も test も、この数だけを見て動く。

前提: 第5章まで読了所要 18分影響度 A出題範囲 1.06.2（重要度6）最終検証 2026-10-13

この章のゴール

  • $? が何をいつまで持っているかを説明できる。0・1・2・126・127 の意味を言える
  • exit の値と、exit を書かないスクリプトの終了ステータスを言える
  • test と [ ] でファイル・文字列・数を比べられ、よくある書き間違い（空白・引用符）を見分けられる
  • if・elif・else が、条件のコマンドの終了ステータスで分かれることを説明できる
ここで覚えなくていいこと: [[ ]] の詳しい文法（正規表現の =~ など）、(( )) による数の比較、set -e・trap、シグナルで終わったときの 128+n の値。test の演算子は下の表にあるものだけで足りる。

$? は、直前の1つしか覚えていない

この節で分かること: 終了ステータスの値の意味と、$? の寿命。
$ mkdir -p ~/try && cd ~/try
$ ls /nonexistent; echo $?
ls: cannot access '/nonexistent': No such file or directory
2
$ echo $?
0
$ grep -q lab /etc/passwd; echo $?
0
$ grep -q nosuchuser /etc/passwd; echo $?
1
$ grep -q lab /nonexistent; echo $?
grep: /nonexistent: No such file or directory
2
$ nosuchcommand; echo $?
bash: nosuchcommand: command not found
127

ls の失敗で 2 だった $? が、次の行では 0 になった。$? が持っているのは直前に終わったコマンドの値1つだけで、1行前の echo $? が成功した時点で上書きされている。値を後で使うなら、すぐ rc=$? のように変数へ移す。

値意味この教材の記録
0成功grep -q lab /etc/passwd
1失敗（何が「失敗」かはコマンドが決める）grep の「見つからない」
2使い方の誤り・ファイルが無いなど（grep・ls の場合）grep … /nonexistent・ls /nonexistent
126見つかったが実行できない第4章の Permission denied
127コマンドが見つからないnosuchcommand・第2章のスクリプトの中の alias

exit は 0〜255。それより大きい数は丸められる

この節で分かること: スクリプトが親に返す値の決まり方。

exit 数 はスクリプトを終わらせ、その数を終了ステータスとして親に返す。

ふつうこう考える

0 以外は失敗なのだから、大きな数を返せば確実に失敗として伝わるはずだ。exit 256 と書けば、呼んだ側の $? は 256 になり、&& の先は動かない。

$ printf '#!/bin/bash\nexit 3\n' > ret.sh; bash ret.sh; echo $?
3
$ sed -i 's/exit 3/exit 255/' ret.sh; bash ret.sh; echo $?
255
$ sed -i 's/exit 255/exit 256/' ret.sh; cat ret.sh; bash ret.sh; echo $?
#!/bin/bash
exit 256
0
$ sed -i 's/exit 256/exit 257/' ret.sh; bash ret.sh; echo $?
1
$ bash -c 'exit -1'; echo $?
255
だめな理由: exit 256 の結果は 0、つまり成功として伝わった。exit 257 は 1、exit -1 は 255 になった。 終了ステータスは 0〜255 の範囲（8ビット）しか運べず、それを超えた値は 256 で割った余りになる。 親が受け取れるのはこの小さな数1つだけで、文字列も変数も、大きな数も返せない。 失敗を返したいなら 1〜255 の中で決める（慣習では 1 か 2）。

exit を書かないスクリプトは、最後に実行したコマンドの値で終わる。

$ printf '#!/bin/bash\nls /nonexistent\necho おわり\n' > last.sh; bash last.sh; echo "終了ステータス $?"
ls: cannot access '/nonexistent': No such file or directory
おわり
終了ステータス 0

ls は失敗したが、最後の echo が成功したので、スクリプト全体は 0（成功）を返した。途中の失敗を伝えたいなら、自分で exit する。

たとえ: 終了ステータスは、子が帰るときに親へ渡す0〜255 の番号が書ける札1枚に近い。札に書けるのは3桁までで、256 と書こうとすると桁があふれて 0 になる。
ただし崩れる点: 札なら「あふれました」と気づけるが、bash は何も言わずに余りを渡す。exit 256 は警告もなく「成功」として届く。
手を動かす: 実践編の演習05は、最後が echo で終わっているせいで常に 0 を返すスクリプトを直す課題である。 判定は 4 通りの引数で実際に実行し、毎回の $? を読む。

test と [ ] も、終了ステータスを返すコマンドである

この節で分かること: 条件の書き方と、よくある書き間違い。

test 式 と [ 式 ] は同じもので、中に書いた条件式が正しければ 0、正しくなければ 1 を返す。

$ test -f /etc/passwd; echo $?
0
$ [ -f /etc/passwd ]; echo $?
0
$ [ -d /etc/passwd ]; echo $?
1
$ [ -e /nonexistent ]; echo $?
1
$ [ ! -e /nonexistent ]; echo $?
0
$ [ -r /etc/shadow ]; echo $?
1
$ [ -x /usr/bin/ls ]; echo $?
0
$ [ -s /etc/passwd ]; echo $?
0
$ [ -z "" ]; echo $?; [ -n "" ]; echo $?
0
1
$ [ 1 -eq 01 ]; echo $?; [ 1 = 01 ]; echo $?
0
1
$ [ 10 -gt 9 ]; echo $?; [ 10 \> 9 ]; echo $?
0
1
$ [ "abc" != "abd" ]; echo $?
0
式0（真）になる条件
-e ファイル / -f / -d在る / ふつうのファイル / ディレクトリ
-r / -w / -x / -s読める / 書ける / 実行できる / 大きさが 0 でない
-z 文字列 / -n 文字列空 / 空でない
文字列1 = 文字列2 / !=文字列として同じ / 違う
数1 -eq 数2 / -ne -lt -le -gt -ge数として = ≠ < ≤ > ≥
! 式 / 式1 -a 式2 / 式1 -o 式2否定 / かつ / または

1 -eq 01 は数として同じなので 0、1 = 01 は文字列として違うので 1 になった。10 \> 9 は文字列の比較（辞書順で 1 は 9 より前）なので 1 になる。数を比べるときは -gt などを使う。/etc/shadow は lab に読めないので -r は 1 だった。

書き間違いは2つが定番である。

$ x=; [ $x = yes ]; echo $?
bash: [: =: unary operator expected
2
$ [ "$x" = yes ]; echo $?
1
$ [1 -eq 1]; echo $?
bash: [1: command not found
127

変数が空のとき、[ $x = yes ] は [ = yes ] になり、[ が文法の誤りを報告して 2 を返した。"$x" と引用符で囲めば、空でも1つの語として残る。[1 -eq 1] は [1 という名前のコマンドを探して 127 になった。[ は記号ではなくコマンドの名前なので、前後に空白が要る。

$ type [ test [[
[ is a shell builtin
test is a shell builtin
[[ is a shell keyword
$ ls -l /usr/bin/[ /usr/bin/test
-rwxr-xr-x 1 root root 55744 Aug 26 00:09 '/usr/bin/['
-rwxr-xr-x 1 root root 47552 Aug 26 00:09  /usr/bin/test

[ と test は bash の組み込みコマンドで、同じものが /usr/bin/[ という実行ファイルとしても在る。[[ は bash のキーワードで、別の文法を持つ（ここでは扱わない）。

たとえ: [ ははい・いいえだけで答える係員に近い。[ -f /etc/passwd ] と聞くと、係員は札（終了ステータス）を上げるだけで何も話さない。
ただし崩れる点: 係員なら聞き取れなかった質問を聞き返すが、[ は空の変数で質問の形が崩れると「文法がおかしい（2）」と返すだけで、if から見るとそれも「いいえ」と同じ扱いになる。

if は、コマンドの終了ステータスで分かれる

この節で分かること: if・elif・else の形と、条件に何でも置ける理由。
$ cat > kind.sh <<'END'
> #!/bin/bash
> if [ -d "$1" ]; then
>     echo "$1 はディレクトリ"
> elif [ -f "$1" ]; then
>     echo "$1 はふつうのファイル"
> else
>     echo "$1 は見つからない"
>     exit 1
> fi
> END
$ bash kind.sh /etc; bash kind.sh /etc/passwd; bash kind.sh /nonexistent; echo "終了ステータス $?"
/etc はディレクトリ
/etc/passwd はふつうのファイル
/nonexistent は見つからない
終了ステータス 1

if の後ろに置くのは「式」ではなくコマンドである。そのコマンドが 0 を返せば then へ、そうでなければ elif か else へ進む。[ ] もコマンドの1つにすぎないので、grep -q のような普通のコマンドもそのまま置ける。

$ if grep -q '^alice:' /etc/passwd; then echo "alice は居る"; fi
alice は居る
$ [ -f /etc/passwd ] && [ -r /etc/passwd ] && echo "読める"
読める
$ [ -f /etc/passwd -a -r /etc/shadow ]; echo $?
1
if コマンド1; then      ← コマンド1 が 0 なら
    …
elif コマンド2; then    ← そうでなく、コマンド2 が 0 なら
    …
else                    ← どれも 0 でなければ
    …
fi                      ← if を逆から綴って閉じる

&& で [ ] を2つつなぐ書き方と、1つの [ ] の中で -a を使う書き方は、どちらも「かつ」になる。

たとえ: if は前の係員が上げた札の色だけを見て、右か左の通路へ案内する誘導係に近い。札を上げたのが「はい・いいえ」係（[）でも、検索係（grep）でも、見るのは色だけである。
ただし崩れる点: 札の色は 0 か「それ以外」の2通りしか見ない。grep の 1（見つからない）と 2（ファイルが無い）は、if からは区別できない。分けたいなら $? を変数に取って比べる。
確認

直前に実行したコマンドの終了ステータスを表示するコマンドはどれか。また、そのコマンドを2回続けて打つと、2回目は何を表示するか。

答え

echo $?。2回目は 1回目の echo 自身の終了ステータス（ふつうは 0）を表示する。$? は直前の1つしか持たない。

確認

スクリプトの最後の行が exit 300 だった。呼んだ側で echo $? と打つと何が出るか。

答え

44（300 を 256 で割った余り）。終了ステータスは 0〜255 しか運べない。記録では exit 256 が 0、exit 257 が 1 になった。

$ bash -c 'exit 300'; echo $?
44
確認

変数 ans が空のとき、if [ $ans = yes ]; then … はどうなるか。直し方も答えよ。

答え

[ = yes ] と解釈されて [: =: unary operator expected というエラーになり、[ は 2 を返すので then には進まない。 [ "$ans" = yes ] と引用符で囲めば、空でも1つの語として比べられる。

確認

ファイル /etc/hosts が在り、かつ読めるときだけ OK と出す1行を書け。

答え

[ -f /etc/hosts ] && [ -r /etc/hosts ] && echo OK、または [ -f /etc/hosts -a -r /etc/hosts ] && echo OK、または if [ -f /etc/hosts ] && [ -r /etc/hosts ]; then echo OK; fi。

この章で分かったこと

持ち帰ってほしいこと

  • $? は直前に終わったコマンドの終了ステータスを1つだけ持つ。echo $? 自身が次の値で上書きする
  • 0 が成功。1・2 はコマンドごとの失敗、126 は実行できない、127 は見つからない
  • exit で返せるのは 0〜255。exit 256 は 0（成功）になる。exit を書かなければ最後のコマンドの値
  • test と [ ] は同じコマンド。[ の前後には空白、変数は "$x" と囲む。数は -eq -gt、文字列は = !=
  • if の後ろはコマンド。0 なら then、それ以外は elif・else。閉じるのは fi
