1. 読まれる起動ファイルは、シェルの生まれ方で決まる

この檻に入ったとき、入口の案内が出た。同じ端末で bash と打っても出ない。同じ bash なのに、起動したときに読むファイルが違うからである。どれを読むかは「ログインしたのか」「人と対話しているのか」で決まる。そして ~/.bash_profile を1つ作るだけで、~/.profile と ~/.bashrc が両方とも読まれなくなる。

前提: 檻が起動している所要 20分影響度 B出題範囲 1.06.1（重要度4）最終検証 2026-10-13

この章のゴール

  • いまのシェルがログインシェルか、対話シェルかを、shopt login_shell と $- で確かめられる
  • /etc/profile・/etc/bash.bashrc・~/.bash_profile・~/.bash_login・~/.profile・~/.bashrc・~/.bash_logout が、どの起動のしかたで読まれるかを表で言える
  • ~/.bash_profile を作ると何が読まれなくなるかを、理由まで説明できる
ここで覚えなくていいこと: zsh や csh の起動ファイル（~/.zshrc など）、BASH_ENV と --posix の細かい規則、/etc/environment を読む PAM の仕組み、ssh でのログイン（この檻に sshd は入れていない）。覚えるのは bash が読む7つのファイルと、その読まれ方だけでよい。

同じ bash なのに、案内が出るときと出ないときがある

この節で分かること: ログインシェルと、そうでないシェルの見分け方。

本文の $ は、あなたが入口で入ったシェルのプロンプトを短く書いたものです。途中で別のシェルを起動したときは、その中のプロンプトを画面どおり（lab@linuc:~$ など）に書きます。

まず、いまいるシェルが何者かを聞く。

$ echo $0
/bin/bash
$ shopt login_shell
login_shell    	on
$ echo $-
himBHs

shopt login_shell が on ならログインシェルである。入口の docker run は /bin/bash -l を起動していて、-l（--login）が「ログインシェルとして起動せよ」という指定になっている。$- は、いま有効になっているシェルのオプションを1文字ずつ並べたもので、i が入っていれば対話シェル（人がプロンプトに打ち込んでいるシェル）である。

この中で、もう1つ bash を起動してみる。-l を付けた場合と付けない場合で比べる。

$ bash -l
（略）   ← 入口で見たのと同じ案内がもう一度出る
lab@linuc:~$ shopt login_shell
login_shell    	on
lab@linuc:~$ exit
logout
$ bash
lab@linuc:~$ shopt login_shell
login_shell    	off
lab@linuc:~$ exit
exit

bash -l では入口の案内がもう一度出て、bash では出ない。終わるときの表示も違う。ログインシェルは logout、そうでないシェルは exit と出る。

案内を出しているのは /etc/profile である。正確には、/etc/profile が /etc/profile.d/ の *.sh を順に読み込み、その中の 99-lab.sh が案内を出している。

$ grep -n -A6 'profile.d' /etc/profile
20:if [ -d /etc/profile.d ]; then
21:  for i in /etc/profile.d/*.sh; do
22-    if [ -r $i ]; then
23-      . $i
24-    fi
25-  done
26-  unset i
27-fi
$ ls -1 /etc/profile.d/
01-locale-fix.sh
99-lab.sh
bash_completion.sh
gawk.csh
gawk.sh
$ head -3 /etc/profile.d/99-lab.sh
# ログイン時に現在地を必ず出す。読者が「いま何をすればいいか」を探さずに済むようにする。
# 非対話シェル（docker run … lab check 03 のような素通し）では出さない。
case $- in *i*) ;; *) return ;; esac

99-lab.sh の3行目は「$- に i が無ければ（対話シェルでなければ）何もせずに戻る」という意味である。案内はログインシェルで、かつ対話シェルのときだけ出る。この2つは別々の性質で、組み合わせは4通りある。

対話（人が打つ）非対話（スクリプトや -c）
ログインログインした直後の端末（bash -l・su -・sudo -i）sudo -iu alice コマンド・bash -l -c …
非ログイン端末で bash と打った・su（- なし）bash x.sh・bash -c …

ログインしたときに使われるシェルそのものは /etc/passwd の最後の欄が決めている。

$ grep -E '^(lab|alice|bob):' /etc/passwd
lab:x:1000:1000::/home/lab:/bin/bash
alice:x:1001:1001::/home/alice:/bin/bash
bob:x:1002:1002::/home/bob:/bin/bash
$ grep SHELL /etc/default/useradd
# The SHELL variable specifies the default login shell on your
# Similar to DSHELL in adduser. However, we use "sh" here because
SHELL=/bin/sh

この檻のユーザはみな /bin/bash である。ただし Ubuntu の useradd は、-s を付けずに作ると /bin/sh（Ubuntu では dash）をログインシェルにする。dash は bash の起動ファイルの多くを読まないので、この章の表が当てはまらない。この檻の alice と bob は -s /bin/bash を付けて作ってある。

たとえ: 会社に出社することと、自分の席で新しいウィンドウを開くことの違いに近い。 出社したときだけ受付を通り、入館証と今日の連絡（環境）を受け取る。席でウィンドウを何枚開いても受付は通らない。
ただし崩れる点: 出社は1日1回だが、ログインシェルは何個でも同時に作れる。bash -l と打てば、席に座ったままもう一度「出社」できてしまう。ログインかどうかは、実際に入館したかではなく、起動のしかただけで決まる。

印を仕込んで、読まれたファイルを数える

この節で分かること: 7つの起動ファイルが、どの起動のしかたで読まれるか。

起動ファイルの先頭に「読まれたら名前を出す」1行を足して、起動のしかたごとにどれが出るかを見る。自分（lab）の起動ファイルを壊すと端末が使えなくなるので、実験の相手はユーザ alice にする。

$ sudo sed -i '1i echo "[/etc/profile]"' /etc/profile
$ sudo sed -i '1i echo "[/etc/bash.bashrc]"' /etc/bash.bashrc
$ sudo sed -i '1i echo "[~/.profile]"' /home/alice/.profile
$ sudo sed -i '1i echo "[~/.bashrc]"' /home/alice/.bashrc
$ sudo sed -i '1i echo "[~/.bash_logout]"' /home/alice/.bash_logout
$ sudo head -1 /etc/profile /etc/bash.bashrc /home/alice/.profile /home/alice/.bashrc /home/alice/.bash_logout
==> /etc/profile <==
echo "[/etc/profile]"

==> /etc/bash.bashrc <==

==> /home/alice/.profile <==

==> /home/alice/.bashrc <==

==> /home/alice/.bash_logout <==

$ sudo -iu alice
[/etc/profile]
[/etc/bash.bashrc]
（略）   ← 入口の案内（/etc/profile.d/99-lab.sh）
[~/.profile]
[~/.bashrc]
alice@linuc:~$ exit
logout
[~/.bash_logout]

ログインした瞬間に4つ、exit したときに1つ出た。su - alice（- 付き）でも同じになる。パスワードは alice で、打った文字は表示されない。

$ su - alice
Password: 
[/etc/profile]
[/etc/bash.bashrc]
（略）
[~/.profile]
[~/.bashrc]
alice@linuc:~$ exit
logout
[~/.bash_logout]

案内の1行目が lab-base になっているのは、sudo -i と su - が環境変数をほぼ空にしてから alice のシェルを始めるからである（あなたのシェルにある LAB_THEME が alice には渡っていない）。このことは第2章で扱う。

- を付けない su alice は、ログインシェルにならない。

$ su alice
Password: 
[/etc/bash.bashrc]
[~/.bashrc]
alice@linuc:/home/lab$ pwd
/home/lab
alice@linuc:/home/lab$ exit
exit

読まれたのは2つだけで、ディレクトリも lab のホームのまま、exit の表示も logout ではない。ログインした alice の中で bash と打った子のシェルも、同じ2つだけを読む。

$ sudo -iu alice
[/etc/profile]
[/etc/bash.bashrc]
（略）
[~/.profile]
[~/.bashrc]
alice@linuc:~$ bash
[/etc/bash.bashrc]
[~/.bashrc]
alice@linuc:~$ exit
exit
alice@linuc:~$ exit
logout
[~/.bash_logout]

最後に、人が打たない（非対話の）シェルを2つ試す。

$ sudo -iu alice true
[/etc/profile]
[~/.profile]
[~/.bashrc]
$ sudo -u alice bash -c 'echo こんにちは'
こんにちは

bash 自身が読むのは、そのうちの一部

この節で分かること: 表の ✔ のうち、bash が自分で読んだものと、別のファイルに読み込まれたもの。

表には、説明のつかない ✔ が2つある。ログインシェルなのに /etc/bash.bashrc と ~/.bashrc が読まれている。bash の man は、ログインシェルが読むのは /etc/profile と、3つの候補のうち1つだけだと書いている。

$ MANWIDTH=80 man bash | grep -A6 'invoked as an interactive login shell'
       When bash is invoked as an interactive login shell, or as a  non-inter‐
       active  shell with the --login option, it first reads and executes com‐
       mands from the file /etc/profile, if that file exists.   After  reading
       that file, it looks for ~/.bash_profile, ~/.bash_login, and ~/.profile,
       in  that order, and reads and executes commands from the first one that
       exists and is readable.  The --noprofile option may be  used  when  the
       shell is started to inhibit this behavior.

ログインしない対話シェルについては、こう書いてある。

       When an interactive shell that is not a login shell  is  started,  bash
       reads  and  executes  commands  from /etc/bash.bashrc and ~/.bashrc, if
       these files exist.  This may be inhibited by using the  --norc  option.
       The  --rcfile  file option will force bash to read and execute commands
       from file instead of /etc/bash.bashrc and ~/.bashrc.

では、ログインシェルで出た残りの2つはどこから来たのか。/etc/profile の頭を読む。

$ sed -n '1,12p' /etc/profile
echo "[/etc/profile]"
# /etc/profile: system-wide .profile file for the Bourne shell (sh(1))
# and Bourne compatible shells (bash(1), ksh(1), ash(1), ...).

if [ "${PS1-}" ]; then
  if [ "${BASH-}" ] && [ "$BASH" != "/bin/sh" ]; then
    # The file bash.bashrc already sets the default PS1.
    # PS1='\h:\w\$ '
    if [ -f /etc/bash.bashrc ]; then
      . /etc/bash.bashrc
    fi
  else

/etc/profile 自身が、PS1（プロンプト）が設定されているとき、つまり対話シェルのときだけ /etc/bash.bashrc を読み込んでいる。だから非対話のログイン（sudo -iu alice true）では出なかった。~/.bashrc も同じで、Ubuntu の ~/.profile が読み込んでいる。

$ sudo grep -n -A5 'if running bash' /home/alice/.profile
12:# if running bash
13-if [ -n "$BASH_VERSION" ]; then
14-    # include .bashrc if it exists
15-    if [ -f "$HOME/.bashrc" ]; then
16-	. "$HOME/.bashrc"
17-    fi
$ sudo grep -n -B1 -A3 'not running interactively' /home/alice/.bashrc
5-
6:# If not running interactively, don't do anything
7-case $- in
8-    *i*) ;;
9-      *) return;;

~/.bashrc の先頭には「対話シェルでなければ何もせずに戻る」が書いてある。非対話のログインで [~/.bashrc] が出たのは、印がその判定より前の1行目にあるからで、中身はほとんど実行されていない。

ログインシェル（bash -l・su -・sudo -i）
  1. /etc/profile                  ← bash が読む
       ├ /etc/bash.bashrc          ← /etc/profile が読み込む（対話のときだけ）
       └ /etc/profile.d/*.sh       ← /etc/profile が読み込む
  2. ~/.bash_profile → ~/.bash_login → ~/.profile のうち、最初に見つかった1つ   ← bash が読む
       └ ~/.bashrc                 ← Ubuntu の ~/.profile が読み込む
  終了時 ~/.bash_logout             ← bash が読む

ログインしない対話シェル（bash・su）
  1. /etc/bash.bashrc              ← bash が読む（Debian・Ubuntu の bash）
  2. ~/.bashrc                     ← bash が読む

/etc/bash.bashrc は Debian 系の名前である。Red Hat 系では /etc/bashrc という名前で、~/.bashrc の中から読み込む作りになっている（AlmaLinux 9.7 のコンテナで確かめた。この檻の外なので記録は載せていない）。選択肢に /etc/bashrc が出たら、同じ役目の別名だと分かればよい。

たとえ: 書類の中に「別紙を参照」と書いてあるのに近い。 受付（bash）が読むと決めているのは本紙（/etc/profile と ~/.profile）だけで、別紙（/etc/bash.bashrc と ~/.bashrc）は本紙に書かれた指示で読まれている。
ただし崩れる点: 書類の別紙は本紙と一緒に綴じられているが、ここでは本紙を差し替えると別紙への参照ごと消える。次の節で起きるのがそれである。

~/.bash_profile を1つ作ると、2つ消える

この節で分かること: 3つの候補のうち、最初に見つかった1つしか読まれないことと、その帰結。

alice が自分のコマンド置き場 ~/bin を PATH に足したくなった。よく見る書き方は ~/.bash_profile に1行書くことである。

ふつうこう考える

PATH を足すための ~/.bash_profile を新しく作った。~/.bashrc は「シェルが起動するたびに読まれるファイル」なのだから、そこに書いてある ll などの alias はこれまでどおり使えるはずだ。

$ sudo -iu alice
[/etc/profile]
[/etc/bash.bashrc]
（略）
[~/.profile]
[~/.bashrc]
alice@linuc:~$ ll -d ~
drwxr-x--- 1 alice alice 4096 Oct 13 10:43 /home/alice/
alice@linuc:~$ printf 'echo "[~/.bash_profile]"\nPATH="$HOME/bin:$PATH"\n' > ~/.bash_profile
alice@linuc:~$ cat ~/.bash_profile
echo "[~/.bash_profile]"
PATH="$HOME/bin:$PATH"
alice@linuc:~$ exit
logout
[~/.bash_logout]
$ sudo -iu alice
[/etc/profile]
[/etc/bash.bashrc]
（略）
[~/.bash_profile]
alice@linuc:~$ ll -d ~
-bash: ll: command not found
alice@linuc:~$ type ll
-bash: type: ll: not found
alice@linuc:~$ exit
logout
[~/.bash_logout]
だめな理由: ログインしたときに出た印は [~/.bash_profile] だけで、[~/.profile] と [~/.bashrc] が消えた。 ログインシェルは ~/.bash_profile → ~/.bash_login → ~/.profile の順に探し、最初に見つかった1つしか読まない。 ~/.profile が読まれないので、~/.profile が読み込んでいた ~/.bashrc も読まれず、そこで定義されていた ll が消えた。 「~/.bashrc は毎回読まれる」が正しいのは、ログインしない対話シェルのときだけである。 ログインシェルで読まれていたのは、~/.profile が読み込んでいたからにすぎない。

順番も確かめる。~/.bash_login を足してから、上から順に消していく。

$ echo 'echo "[~/.bash_login]"' | sudo tee /home/alice/.bash_login
echo "[~/.bash_login]"
$ sudo -iu alice true
[/etc/profile]
[~/.bash_profile]
$ sudo rm /home/alice/.bash_profile
$ sudo -iu alice true
[/etc/profile]
[~/.bash_login]
$ sudo rm /home/alice/.bash_login
$ sudo -iu alice true
[/etc/profile]
[~/.profile]
[~/.bashrc]

3つが揃っていても、読まれるのは常に1つである。直すには、~/.bash_profile の中で ~/.profile を読み込む。

$ printf 'echo "[~/.bash_profile]"\nPATH="$HOME/bin:$PATH"\n. ~/.profile\n' | sudo -u alice tee /home/alice/.bash_profile
echo "[~/.bash_profile]"
PATH="$HOME/bin:$PATH"
. ~/.profile
$ sudo -iu alice
[/etc/profile]
[/etc/bash.bashrc]
（略）
[~/.bash_profile]
[~/.profile]
[~/.bashrc]
alice@linuc:~$ ll -d ~
drwxr-x--- 1 alice alice 4096 Oct 13 10:44 /home/alice/
alice@linuc:~$ exit
logout
[~/.bash_logout]

. ~/.profile の . は「このファイルを、いまのシェルで読み込む」というコマンドで、source と同じ意味である（第2章）。これで ~/.profile → ~/.bashrc の連鎖が戻り、ll も使える。

たとえ: 窓口が3つ並んだ役所で、最初に開いていた窓口1つだけで手続きが済んでしまう運用に近い。 これまで3番窓口（~/.profile）が「ついでに別の課（~/.bashrc）へも回しておきます」と気を利かせていた。1番窓口（~/.bash_profile）を新しく開けたら、3番には誰も来なくなった。
ただし崩れる点: 役所なら「3番にも寄ってください」と案内が出るが、bash は何も言わない。エラーも警告も出ず、alias が黙って消えるだけである。
手を動かす: 演習01 の bob には、前任者が置いた ~/.bash_profile が最初からある。 ~/.profile にあいさつを書くと、この節と同じ理由で出ない。

終わるときに読まれる ~/.bash_logout と、印の片づけ

この節で分かること: ~/.bash_logout がいつ読まれるか。実験の後始末。

これまでの記録では、[~/.bash_logout] は logout と表示されたとき、つまりログインシェルが終わるときにだけ出ていた。su alice の終わり（exit）では出ていない。man もそう書いている。

$ MANWIDTH=80 man bash | grep -A2 'When an interactive login shell exits'
       When an interactive login shell exits, or a non-interactive login shell
       executes  the  exit  builtin  command, bash reads and executes commands
       from the file ~/.bash_logout, if it exists.

Ubuntu の ~/.bash_logout は、最後のシェルを抜けるときに画面を消す処理だけを持っている。

$ sudo cat /home/alice/.bash_logout
echo "[~/.bash_logout]"
# ~/.bash_logout: executed by bash(1) when login shell exits.

# when leaving the console clear the screen to increase privacy

if [ "$SHLVL" = 1 ]; then
    [ -x /usr/bin/clear_console ] && /usr/bin/clear_console -q
fi

実験が終わったら印を外す。外さないと、以降の章でも [/etc/profile] などが出続ける（檻を起動し直しても消える）。

$ sudo sed -i '/^echo "\[.*\]"$/d' /etc/profile /etc/bash.bashrc /home/alice/.profile /home/alice/.bashrc /home/alice/.bash_logout
$ sudo rm /home/alice/.bash_profile
$ sudo -iu alice true
$ head -1 /etc/profile
# /etc/profile: system-wide .profile file for the Bourne shell (sh(1))
確認

bash をログインシェルとして起動した。ホームディレクトリに ~/.bash_login と ~/.profile があり、~/.bash_profile は無い。読まれるユーザ側のファイルはどれか。

答え

~/.bash_login だけである。ログインシェルは ~/.bash_profile → ~/.bash_login → ~/.profile の順に探し、最初に見つかった1つだけを読む。 この章の記録でも、~/.bash_profile を消すと [~/.bash_login] だけが出た。 ~/.profile は読まれないので、Ubuntu の ~/.profile が読み込んでいる ~/.bashrc も読まれない。

確認

ログインした後、端末で bash と打って新しいシェルを起動した。このとき bash が読むファイルを2つ選べ。
(A) /etc/profile　(B) /etc/bash.bashrc　(C) ~/.bash_profile　(D) ~/.bashrc　(E) ~/.bash_logout

答え

(B) と (D)。ログインしない対話シェルは /etc/bash.bashrc と ~/.bashrc を読む（/etc/bash.bashrc は Debian 系の名前）。 (A) と (C) はログインシェルだけが読み、(E) はログインシェルが終わるときに読まれる。

確認

次のうち、ログインシェルにならない起動のしかたはどれか。
(A) su - alice　(B) su alice　(C) sudo -iu alice　(D) bash -l

答え

(B)。-（-l・--login）を付けない su は、ログインしない対話シェルを起動する。 記録では [/etc/bash.bashrc] と [~/.bashrc] しか出ず、作業ディレクトリも元の /home/lab のままだった。 終わるときの表示も logout ではなく exit になる。

確認

ユーザが ~/.bash_logout に書いた処理が実行されるのはいつか。

答え

ログインシェルが終了するとき（exit や logout、Ctrl-D）。ログインしない対話シェルを抜けても実行されない。 この章の記録でも、[~/.bash_logout] は logout と表示された直後にだけ出ていた。

この章で分かったこと

持ち帰ってほしいこと

  • ログインシェルかどうかは shopt login_shell、対話シェルかどうかは $- の i で分かる。終わるときの表示も logout と exit で違う
  • ログインシェルが読むのは /etc/profile と、~/.bash_profile → ~/.bash_login → ~/.profile のうち最初に見つかった1つ。終わるときに ~/.bash_logout
  • ログインしない対話シェルが読むのは /etc/bash.bashrc と ~/.bashrc
  • ログインシェルで ~/.bashrc が読まれるのは、Ubuntu の ~/.profile が読み込んでいるから。~/.bash_profile を作るとこの連鎖が切れる
  • su - と sudo -i はログインシェル、- の無い su はログインしない対話シェル
  • ログインシェルそのものは /etc/passwd の最後の欄が決める。Ubuntu の useradd の既定は /bin/sh
