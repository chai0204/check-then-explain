理論編 — 重要なシステムサービス

LinuC レベル1 102 試験・主題1.09（時刻・ログ・メール）を、 全部コンテナの中で実際に打って確かめる7章。 読むだけで終わらせないために、1章ごとに「実際に打つと何が出るか」を先に置いています。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この7章を貫いている1つの事実

送り手は、中身とラベルだけを渡す。宛先を決めているのは、受け手側にある設定ファイルである。

logger は facility と priority しか渡さない。chronyd はずれを測るだけで時計は動かさない。 メールの To: は希望でしかない。だから主題1.09 の「詳細」欄には、コマンドよりファイルパスが多く並んでいます。 判断がそこに置かれているからです。

ここで覚えなくていいこと: SMTP のやりとり、NTP のパケット形式、rsyslog の RainerScript、journal のバイナリ形式、 リモート転送と TLS。どれもレベル1の範囲外で、この7章には1行も出てきません。

章

  1. 時計は2つある — hwclock は失敗するのに /proc/driver/rtc には時刻がある。しかも32秒ずれている（12分）
  2. タイムゾーンは表示の都合だけ — date と timedatectl と /etc/timezone が3つ違うことを言う。全部正しい（12分）
  3. 基準を渡されるまで始まらない — デーモンは active。それでも Not synchronised。設定1行で Stratum : 9 になる（15分）
  4. 宛先は受け手の表が決める — local3 に投げた行が /var/log/syslog に入る理由。1行が2箇所に入る（18分）
  5. journald は隣にある別の箱 — 同じ1行が両方に1件ずつ。保存先はディレクトリの有無で決まる（16分）
  6. 捨てる判断も受け手側にある — 1つ目の拒否はエラーを出しながら終了コード 0 で終わる。止まる原因は2つあり、どちらも権限（16分）
  7. 宛先に書いた名前は希望にすぎない — 2回書き換わる。書き換わったことはログにしか残らない。ここで7章が1本になる（18分）

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの4つに集まります。

場面ここで効く理由見落としやすい点関連する章
障害の時系列を組み立てる 複数ホストのログを並べるとき、ゾーンとオフセットが揃っていないと順序が狂う rsyslog と journald で時刻の書式が違う。ログの時刻はオフセット付きかを先に見る2・4・5
アプリのログを分離する local0〜local7 は用途が決まっていないので自分のアプリに割り当てられる 設定を足すと「移る」のではなく「増える」。既定の catch-all は残り続ける4
ディスクが埋まった ログは放っておくと増える一方で、捨てる仕組みは2つに分かれている journal は logrotate の対象外。SystemMaxUse= を別に見る5・6
システムからの通知を受け取る cron・smartd・logrotate などは失敗を root 宛のメールで知らせる mailq が空でも成功ではない。差し戻しは /var/mail/root に溜まる7

この主題を使わない方がよい場面も1つあります。 コンテナで動くアプリのログを rsyslog や logrotate で扱おうとすることです。 コンテナは標準出力をそのままランタイムに渡す設計なので、 中に rsyslog を立てると二重管理になります （この教材の檻が systemd を立てているのは、試験範囲を再現するための例外です）。
