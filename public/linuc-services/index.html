確かめて説明する LinuC 主題1.09

LinuC レベル1 102 試験・主題1.09「重要なシステムサービス」 （システム時刻の管理 / システムのログ / MTA の基本）を、 全部コンテナの中で実際に打って確かめます。 timedatectl も journalctl も systemctl も動く檻です。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: コマンドは打てる。写経すれば動く。 でも「なぜ動くのか」を人に説明できない人。
LinuC を受ける人向けには: 出題範囲を読んで「そういうことができるんだな」で止まっている人。

はじめる

Docker の場合。2行です。

docker run -d -t --name lab-linuc --hostname linuc \
  --cap-add SYS_ADMIN \
  -v lab-linuc-services-state:/root/.lab \
  ghcr.io/chai0204/lab-linuc-services:1.0.1@sha256:da71ddd5786ef105ed8dfa8836c5fdfb3c94a9d9fedbfc0b52b2d56f19ab6ded

docker exec -it lab-linuc bash -l

--cap-add SYS_ADMIN を打たせている理由（この教材で唯一、読者に権限を渡してもらう箇所です）

この主題は timedatectl と journalctl と systemctl を扱います。 どれも systemd が PID 1 で動いていないと1つも試せません。 ところが docker は /sys/fs/cgroup を読み取り専用でマウントするため、 systemd は起動の最初に /init.scope を作れずに即死します（実測 2026-10-12・docker 29.8.0）。

Failed to create /init.scope control group: Read-only file system
Failed to allocate manager object.
[!!!!!!] Failed to allocate manager object.
→ 終了コード 255

--cgroupns=host でも --security-opt systempaths=unconfined でも読み取り専用のままでした。 書き込みに戻すには CAP_SYS_ADMIN が必要で、無いまま remount を試すと mount: /sys/fs/cgroup: permission denied になります。

増える権限は1ビットだけです。渡す前と後を自分で比べられます。

$ docker run --rm ubuntu:24.04 grep CapEff /proc/1/status
CapEff:	00000000a80425fb
$ docker exec lab-linuc grep CapEff /proc/1/status
CapEff:	00000000a82425fb
                ^
          差は 0x00200000 = bit 21 = CAP_SYS_ADMIN だけ

Podman なら権限を1つも渡さずに済みます。rootless の podman は systemd 用に cgroup を書き込み可でマウントするので、専用のオプション1つで足ります。

podman run -d -t --name lab-linuc --hostname linuc \
  --systemd=always \
  -v lab-linuc-services-state:/root/.lab \
  ghcr.io/chai0204/lab-linuc-services:1.0.1@sha256:da71ddd5786ef105ed8dfa8836c5fdfb3c94a9d9fedbfc0b52b2d56f19ab6ded

podman exec -it lab-linuc bash -l

podman 5.8.6（rootless・uid 1100）で、起動と演習6本の完走を確認しました。 --cap-add は要りません。この違いそのものが、出題範囲 1.01.2「仮想マシン・コンテナの概念」の実物です。

もう1つ違いがあります。podman exec で入ったシェルは umask が 0022 で、docker exec の 0000 と違います（2026-10-13 実測）。そのため第6章の1つ目の拒否（設定ファイルの権限）と、第7章の .forward の拒否が、podman では起きません。該当する箇所に、podman で何が出るかを書いてあります。演習のヒントと模範解答も、どちらの入り方でも通るように書いてあります（どちらでも模範解答どおりに全問 ✔ になることを確認済み）。
