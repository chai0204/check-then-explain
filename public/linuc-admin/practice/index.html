確かめて説明する LinuC 主題1.08

LinuC レベル1 102 試験・主題1.08「システム管理」 （アカウント管理 / ジョブスケジューリング / ローカライゼーションと国際化）を、 コンテナの中で動く練習機（仮想マシン）で実際に打って確かめます。 ユーザを作って止め、cron と at に本物の時刻でジョブを走らせ、ロケールを生成します。

このページのコマンドは、あなたの画面に本文と同じ文字を出します（時刻や日付など、打った日時で変わるものを除く）。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: コマンドは打てる。写経すれば動く。 でも「なぜ動くのか」を人に説明できない人。
LinuC を受ける人向けには: useradd や crontab のオプションを、読んでも覚えられない人。

この教材の檻

檻準備ここで触れるここでは触れない（逃がす先）
仮想マシン型（コンテナの中で QEMU が Ubuntu 24.04 の練習機を1台動かす）イメージ（約 2GB）の取得と、練習機の起動（KVM なしで 30 秒〜1分半） useradd usermod passwd crontab anacron at locale-gen iconv、外からの ssh LDAP などの外部のユーザ管理、メールでの通知（練習機に MTA はありません）、RHEL 系の挙動（本文の表で扱います）

影響度 B（変更はコンテナの中の練習機だけ。母艦の設定もファイルも書き換えません）。 演習は練習機の /etc やユーザを書き換えますが、読者がホストに渡す特権はありません（--privileged も --cap-add も使いません）。 練習機は QEMU の完全エミュレーション（TCG）で動くので、ホストのカーネルの機能を借りません。 やり直したいときは、外の端末で vm reset --yes と打てば練習機が最初の状態に戻ります。 演習を始めるときの lab の案内にも、この戻し方が出ます（起動し直すだけでは練習機は戻りません。ディスクはボリュームに残ります）。

はじめる

Docker の場合。起動して、入ります。

docker run -d --name lab-linuc-admin --hostname host --stop-timeout 30 \
  -v lab-linuc-admin-vm:/home/lab/vm \
  -v lab-linuc-admin-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:admin-1.0.3@sha256:119e7b8da7cdc2ec69f80db8604d78db6bb1d6289f80cad05ec0b922e0d4866d

docker exec -it lab-linuc-admin bash -l

--stop-timeout 30 は特権ではなく、docker stop のときに待つ秒数です。練習機を正常に停止するのに KVM なしで十数秒かかり、 docker の既定の10秒では電源を抜くのと同じ止まり方になります（次の起動でディスクの検査が走ります）。 付けずに作った場合は docker stop -t 30 lab-linuc-admin で止めてください。

podman でも、同じオプションのまま動きます。権限を足すオプションは要りません。

podman run -d --name lab-linuc-admin --hostname host --stop-timeout 30 \
  -v lab-linuc-admin-vm:/home/lab/vm \
  -v lab-linuc-admin-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:admin-1.0.3@sha256:119e7b8da7cdc2ec69f80db8604d78db6bb1d6289f80cad05ec0b922e0d4866d

podman exec -it lab-linuc-admin bash -l

podman 5.8.6（rootless）で、この檻（1.0.0。1.0.1 との違いは演習の文面だけ）を起動して確かめました。練習機に ssh で入れるまで 32 秒、podman stop は 4 秒で終了コード 0 でした（logs/linuc-machine-podman.log）。

入ると、練習機の状態と現在地が出ます。起動の直後は練習機がまだ立ち上がっていないことがあります（KVM なしで 30〜90 秒）。

  vm start / vm ssh / vm console / vm stop   練習機の操作（中身は virsh と ssh）

lab-linuc-admin  進捗 0/8
  次 → 01 「ユーザを1人、使える状態で作る」 (目安 12分 / 影響度 B)

いるのは外側のコンテナ（lab@host）です。練習機（student@linuc）には ssh linuc で入ります。

$ ssh linuc

  LinuC 練習機（Ubuntu 24.04 / 仮想マシン）
  - 採点は外のコンテナが持っています。この中でも lab check NN で答え合わせできます
  - 管理用の NIC（enp0s16）を止めると ssh が切れます。そのときは外で vm console

student@linuc:~$ exit
logout

プロンプトが lab@host なら外、student@linuc なら練習機の中です。本文の端末表示には、どちらで打つかを見出しで付けてあります。 student は sudo をパスワード無しで使えます。lab check などの lab コマンドは、外でも練習機の中でも打てます。

起動コマンドに --device /dev/kvm を足しても速くはなりません。練習機の定義が、KVM を使わない完全エミュレーション（libvirt の type='qemu'）に固定されているからです。 /dev/kvm を渡しても QEMU は TCG のまま動きます（KVM の記事の6章で測っています）。本文の出力はすべて KVM なしで取ったもので、何も足さずに起動すれば同じ条件になります。

1.0.2 で始めた人は、「終わったら」の手順で檻を止めてから（ボリュームは消さずに）、上の起動コマンドで起動し直すだけで構いません。1.0.3 で変わったのは lab コマンドだけなので、進み具合と作業ファイルはそのまま使えます。

練習機の操作

外（lab@host）で打つすること中身
vm status練習機の状態を見るvirsh domstate linuc
vm start / vm stop起動する / 正常に停止するvirsh start / virsh shutdown
ssh linuc（vm ssh）練習機に入る（抜けるのは exit）127.0.0.1:2222 → 練習機の 22

演習の相手（ユーザ bob・dave・eve や、演習用のファイル）は、練習機を初めて起動したときに自動で用意されます。 演習04 は cron が実際に動くのを確かめるので、判定が最大 75 秒待つことがあります（待っている間はそう表示します）。

先に読む場合は 理論編（9章）へ。章と演習は対応しているので、どちらから始めても構いません。

lab は sudo を付けずに打ちます。付けると root として動き、作業ディレクトリと進み具合が /root の下にできて檻を抜けると消えてしまうので、理由を出して何もせずに止まります。~/work や ~/.lab の持ち主が自分でなくなっていたら、lab が見つけて戻し、そのことを画面に出します。

終わったら

docker stop lab-linuc-admin        # 練習機を正常に止めてから止まる（docker start で続きから）
docker rm -f lab-linuc-admin
docker volume rm lab-linuc-admin-vm lab-linuc-admin-state     # 練習機のディスクと進捗も消す場合だけ

イメージは docker rmi で消せます。 母艦には何も残りません（名前付きボリューム以外のファイルを作っていないため）。
