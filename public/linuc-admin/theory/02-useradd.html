2. useradd は、頼まれたことしかしない

sudo useradd alice は何も言わずに成功する。台帳の6列目には /home/alice と書かれる。ところが、そのディレクトリはどこにも無い。useradd が書いたのは台帳の行だけで、ホームを作れとは頼まれていないからである。

前提: 第1章まで読了所要 16分影響度 B出題範囲 1.08.1（重要度5）最終検証 2026-10-13

この章のゴール

  • useradd の主なオプション（-m -s -d -g -G -u -c -k -D）を使い分けられる
  • 既定値が /etc/default/useradd・/etc/login.defs・/etc/skel のどこから来るかを言える
  • useradd と adduser の違いを説明できる
ここで覚えなくていいこと: /etc/login.defs の全項目、newusers による一括作成、ホームディレクトリの暗号化は扱わない。パスワードの付け方と止め方は第4章でまとめて扱う。

作ったのに、ホームが無い

この節で分かること: useradd が実際にやったことと、やらなかったこと。

ふつうこう考える

useradd alice でユーザができたなら、ホーム /home/alice もできていて、 そのユーザとしてすぐに使える状態になっているはずだ。

$ sudo useradd alice
$ getent passwd alice
alice:x:1004:1004::/home/alice:/bin/sh
$ ls -ld /home/alice
ls: cannot access '/home/alice': No such file or directory
$ sudo -iu alice pwd
sudo: unable to change directory to /home/alice: No such file or directory
/home/student
だめな理由: 台帳の6列目に /home/alice と書かれただけで、ディレクトリは作られていない。 alice として入ろうとすると cd に失敗し、元の場所（/home/student）に取り残される。 7列目のシェルも /bin/bash ではなく /bin/sh になっている。 useradd は台帳に行を書くコマンドで、ホームを作るのは -m を付けたときだけである （Ubuntu の場合。RHEL 系は /etc/login.defs の CREATE_HOME yes により -m なしでも作る）。

書かれたのは /etc/passwd の1行だけではない。主グループと、パスワードの欄も作られている。

$ id alice
uid=1004(alice) gid=1004(alice) groups=1004(alice)
$ sudo grep '^alice:' /etc/shadow
alice:!:20739:0:99999:7:::

UID と同じ番号 1004 の私的グループ alice ができ、/etc/shadow の2列目は !（パスワードが無い・ロック）である。パスワードも頼まれていないので付けていない。

たとえ: 住民票に住所を登録するのに近い。登録すれば住所は書類に載るが、その部屋が建つわけではない。
ただし崩れる点: 役所は実在しない住所を受け付けないが、useradd は存在しないディレクトリをそのまま台帳に書き、警告も出さない。確かめる役は自分にある。

既定値は3か所から来る

この節で分かること: /bin/sh や UID 1004 がどこで決まったか。

オプションを付けなかった項目は既定値になる。既定値は useradd -D で見られる。

$ useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/sh
SKEL=/etc/skel
CREATE_MAIL_SPOOL=no
LOG_INIT=yes
$ ls -l /etc/default/useradd
-rw-r--r-- 1 root root 1117 Feb 22  2024 /etc/default/useradd
$ grep -vE '^\s*#|^\s*$' /etc/default/useradd
SHELL=/bin/sh

/etc/default/useradd で有効な行は SHELL=/bin/sh の1行だけで、残りは useradd に組み込まれた値である。 ところが GROUP=100（users）と出ているのに、alice の主グループは 1004 だった。これを決めているのはもう1つのファイルである。

$ grep -E '^(UID_MIN|UID_MAX|GID_MIN|USERGROUPS_ENAB|HOME_MODE)' /etc/login.defs
HOME_MODE	0750
UID_MIN			 1000
UID_MAX			60000
GID_MIN			 1000
USERGROUPS_ENAB yes

USERGROUPS_ENAB yes のとき、useradd はユーザと同じ名前のグループを作って主グループにする（ユーザプライベートグループ）。GROUP=100 は、これを切ったとき（-N）にだけ使われる。

既定決めている場所この練習機の値
ログインシェル/etc/default/useradd の SHELL=/bin/sh
ホームの親/etc/default/useradd の HOME=（無ければ組み込みの値）/home
ホームに写すひな形/etc/default/useradd の SKEL=/etc/skel
UID・GID の範囲/etc/login.defs の UID_MIN / UID_MAX / GID_MIN1000〜60000
同名の私的グループを作るか/etc/login.defs の USERGROUPS_ENAByes
ホームの権限/etc/login.defs の HOME_MODE0750

-m を付けると、ひな形が写される

この節で分かること: /etc/skel がいつ、どう使われるか。

いったん消して、ホームとシェルを頼んで作り直す。

$ sudo userdel alice
$ sudo useradd -m -s /bin/bash alice
$ getent passwd alice
alice:x:1004:1004::/home/alice:/bin/bash
$ ls -ld /home/alice
drwxr-x--- 2 alice alice 4096 Oct 13 11:39 /home/alice
$ sudo ls -la /home/alice
total 20
drwxr-x--- 2 alice alice 4096 Oct 13 11:39 .
drwxr-xr-x 7 root  root  4096 Oct 13 11:39 ..
-rw-r--r-- 1 alice alice  220 Mar 31  2024 .bash_logout
-rw-r--r-- 1 alice alice 3771 Mar 31  2024 .bashrc
-rw-r--r-- 1 alice alice  807 Mar 31  2024 .profile

ホームができ、権限は HOME_MODE どおり drwxr-x---（0750）になった。中の3つのファイルは /etc/skel（スケルトンディレクトリ。新しいホームのひな形）から写されたもので、日付は元のファイルのまま、所有者だけが alice に変わっている。

$ ls -la /etc/skel
total 20
drwxr-xr-x  2 root root 4096 Oct 13 09:56 .
drwxr-xr-x 85 root root 4096 Oct 13 11:39 ..
-rw-r--r--  1 root root  220 Mar 31  2024 .bash_logout
-rw-r--r--  1 root root 3771 Mar 31  2024 .bashrc
-rw-r--r--  1 root root  807 Mar 31  2024 .profile

ひな形にファイルを1つ足してから、もう1人作る。

$ echo 'ようこそ。困ったことがあれば管理者へ。' | sudo tee /etc/skel/memo.txt
ようこそ。困ったことがあれば管理者へ。
$ sudo useradd -m -s /bin/bash -c 'Carol Lab' carol
$ sudo ls -1A /home/alice /home/carol
/home/alice:
.bash_logout
.bashrc
.profile

/home/carol:
.bash_logout
.bashrc
.profile
memo.txt
$ getent passwd carol
carol:x:1005:1005:Carol Lab:/home/carol:/bin/bash

carol には memo.txt があり、先に作った alice には無い。/etc/skel はホームを作るその瞬間にだけ写される。あとからひな形を変えても、もういるユーザには届かない。-c で渡した文字列は5列目（コメント）に入った。

オプション意味
-m / -Mホームを作る（/etc/skel を写す）／作らない
-d /pathホームの場所（既定は /home/ユーザ名）
-k /dir/etc/skel の代わりに写すひな形（-m と一緒に使う）
-s /bin/bashログインシェル
-u 1500UID を指定する
-g グループ主グループ（すでにあるグループを指定）
-G a,b副グループ（カンマ区切り）
-c 'コメント'5列目のコメント（GECOS）
-e 2026-12-31アカウントの有効期限（/etc/shadow の8列目。第4章）
-D既定値を表示する。-D -s /bin/bash のように付けると既定値を変える
たとえ: 新入社員に渡す「初期配布セット」のひな形に近い。人事が箱の中身を決めておき、入社した日に同じものを1箱ずつ渡す。
ただし崩れる点: 配布物は会社の備品のままだが、写されたファイルは所有者ごと新しいユーザのものになる（alice alice）。本人が書き換えても消しても、ひな形には影響しない。
手を動かす: 実践編の演習01は、ホーム・シェル・ひな形に足したファイル・パスワードがそろったユーザを1人作る課題である。 判定は台帳の行だけでなく、ホームの実物と中身を見る。

useradd -D で既定を変えると、一般ユーザには読めなくなる

この節で分かること: 既定値の確かめ方には落とし穴があること。

既定のシェルを /bin/bash に変えてみる。

$ sudo useradd -D -s /bin/bash
$ sudo useradd -D | grep SHELL
SHELL=/bin/bash
$ ls -l /etc/default/useradd
-rw------- 1 root root 1209 Oct 13 11:39 /etc/default/useradd

値は変わった。ところがファイルの権限が -rw-r--r-- から -rw------- に変わり、大きさも日付も変わっている。useradd -D はファイルを書き直すときに、root しか読めない権限で作り直す。元に戻してから、一般ユーザのまま既定値を見る。

$ sudo useradd -D -s /bin/sh
$ useradd -D | grep SHELL
SHELL=/bin/bash
$ sudo useradd -D | grep SHELL
SHELL=/bin/sh

同じコマンドが、sudo の有無で違うことを言う。本当の値は /bin/sh である。student の useradd はファイルを読めず、読めないとは言わずに組み込みの値（/bin/bash）を表示した。権限を戻すと一致する。

$ sudo chmod 644 /etc/default/useradd
$ useradd -D | grep SHELL
SHELL=/bin/sh

既定値を確かめるときは sudo useradd -D で見るか、ファイルそのものを sudo で読む。表示しているプログラムが台帳を読めているかどうかは、出力からは分からない。

adduser は、まとめてやる別の道具

この節で分かること: useradd と adduser の関係。

Debian 系には adduser という別のコマンドがある。ふつうは対話でパスワードや氏名を聞いてくるが、ここでは聞かれないように2つのオプションを付ける。

$ sudo adduser --disabled-password --comment '' kai
info: Adding user `kai' ...
info: Selecting UID/GID from range 1000 to 59999 ...
info: Adding new group `kai' (1006) ...
info: Adding new user `kai' (1006) with group `kai (1006)' ...
info: Creating home directory `/home/kai' ...
info: Copying files from `/etc/skel' ...
info: Adding new user `kai' to supplemental / extra groups `users' ...
info: Adding user `kai' to group `users' ...
$ getent passwd kai
kai:x:1006:1006:,,,:/home/kai:/bin/bash
$ id kai
uid=1006(kai) gid=1006(kai) groups=1006(kai),100(users)

何も頼んでいないのに、ホームを作り、/etc/skel を写し、シェルを /bin/bash にし、users グループにも入れた。adduser は /etc/adduser.conf の方針に従って、中で useradd などを順に呼ぶ「窓口」である。5列目の ,,, は、対話で聞くはずだった氏名・部屋番号・電話番号の欄が空のまま書かれた跡である。

useraddadduser（Debian 系）
位置づけ台帳を書く本体（全ディストリビューション共通）方針どおりに本体を呼ぶ窓口
ホーム-m を付けたときだけ作る
シェル/etc/default/useradd（ここでは /bin/sh）/etc/adduser.conf（既定 /bin/bash）
パスワード付けない（!）対話で聞く
設定ファイル/etc/default/useradd・/etc/login.defs/etc/adduser.conf

RHEL 系の adduser は useradd への別名（シンボリックリンク）で、動きは useradd と同じになる。試験で問われるのは useradd のオプションである。最後に kai を消しておく。

$ sudo userdel -r kai
userdel: kai mail spool (/var/mail/kai) not found

-r はホームとメールスプールも消す指定で、メールスプールは最初から無かったと言っている（CREATE_MAIL_SPOOL=no）。userdel は第3章で詳しく見る。

たとえ: 書類に直接書き込む（useradd）か、窓口の係員に「新人1名」と頼む（adduser）かの違いに近い。係員は社内の決まり（/etc/adduser.conf）に従って、必要な書類を順に書いてくれる。
ただし崩れる点: 係員は書き終えた書類を見せてくれるが、adduser も最終的には同じ台帳（/etc/passwd など）に同じ形の行を書くだけで、別の種類のユーザができるわけではない。
確認

ユーザ taro を、ホームディレクトリを作成し、ログインシェルを /bin/bash、副グループを wheel と dev にして作成したい。正しいコマンドはどれか。

A. useradd -d -s /bin/bash -g wheel,dev taro　B. useradd -m -s /bin/bash -G wheel,dev taro　C. useradd -k -b /bin/bash -G wheel,dev taro　D. useradd -m -s /bin/bash -g wheel -g dev taro

答え

B。ホームを作るのは -m、シェルは -s、副グループは -G（カンマ区切り）。 -g は主グループで、1つしか指定できない。-d はホームの場所を指定するだけで、作るかどうかは -m で決まる。

確認

/etc/skel に .vimrc を追加した。すでにいるユーザ alice のホームにも .vimrc が配られるか。

答え

配られない。/etc/skel は useradd -m がホームを作る瞬間にだけ写される。この章では memo.txt を足したあとに作った carol だけが持っていた。 既存のユーザに配るなら、管理者が手でコピーして所有者を直す（cp と chown）。

確認

useradd で作成するユーザの既定のログインシェルを確認・変更するコマンドと、その値が書かれるファイルを答えよ。

答え

確認は useradd -D、変更は useradd -D -s /bin/bash。値は /etc/default/useradd の SHELL= に書かれる。 この練習機では useradd -D -s がファイルを root だけが読める権限で書き直したので、確認は sudo useradd -D で行う。

この章で分かったこと

持ち帰ってほしいこと

  • useradd は台帳（/etc/passwd・/etc/shadow・/etc/group）に行を書く。ホームは -m を付けたときだけ作る
  • 既定値は /etc/default/useradd（シェル・ひな形）と /etc/login.defs（UID の範囲・私的グループ・ホームの権限）から来る。確かめるのは useradd -D
  • /etc/skel はホームを作る瞬間にだけ写される。所有者は新しいユーザになる
  • 作ったばかりのユーザはパスワードが無い（/etc/shadow の2列目が !）
  • adduser は Debian 系の窓口で、ホーム・シェル・パスワードまでまとめて面倒を見る。本体は useradd
