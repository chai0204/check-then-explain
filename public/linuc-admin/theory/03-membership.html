3. 所属は、書いたとおりに置き換わる

usermod -G ops alice は「alice を ops にも入れる」ではなく「alice の副グループを ops だけにする」。それまでの所属は黙って消える。そして userdel で消えるのは台帳の名前だけで、ファイルには番号が残り、次に同じ番号をもらった人がそれを受け継ぐ。

この章のゴールと前提所要 18分
前提: 第2章まで読了（alice と carol がいる）所要 18分影響度 B出題範囲 1.08.1（重要度5）最終検証 2026-10-13

この章のゴール

  • groupadd・groupmod・groupdel でグループを作り・変え・消せる
  • usermod -G と usermod -aG の違いを、結果の台帳で説明できる
  • 所属の変更が、ログイン中のシェルにいつ効くかを言える
  • userdel と userdel -r の違いと、消したあとに残るものを説明できる
ここで覚えなくていいこと: gpasswd のグループ管理者の機能、newgrp、/etc/gshadow のグループパスワード、vipw / vigr による直接編集は扱わない（gpasswd -d だけ、片づけに1回使う）。

グループを作る

この節で分かること: groupadd が GID をどう決めるか。
$ sudo groupadd proj-x
$ sudo groupadd -g 1200 proj-y
$ getent group proj-x proj-y
proj-x:x:1103:
proj-y:x:1200:

番号を指定しないと、いまある最大の GID（演習用の proj-b の 1102）の次が振られる。-g で指定もできる。alice を2つに入れる。

$ sudo usermod -aG proj-x,proj-y alice
$ id alice
uid=1004(alice) gid=1004(alice) groups=1004(alice),1103(proj-x),1200(proj-y)

-G は「足す」ではなく「この一覧にする」

この節で分かること: usermod -G が何を書き換えるか。

もう1つグループを作り、alice をそこにも入れたい。

ふつうこう考える

usermod -G ops alice と打てば、alice が ops に入る。 proj-x と proj-y にはさっき入れたのだから、そのまま残っているはずだ。

$ sudo groupadd ops
$ sudo usermod -G ops alice
$ id alice
uid=1004(alice) gid=1004(alice) groups=1004(alice),1201(ops)
$ getent group proj-x proj-y ops
proj-x:x:1103:
proj-y:x:1200:
ops:x:1201:alice
だめな理由: proj-x と proj-y から alice が消えた。エラーも警告も出ていない。 -G に渡した一覧は「副グループをこれにする」という意味で、usermod は /etc/group の全部の行を見て、 一覧に無いグループのメンバー欄から alice を消し、一覧にあるグループに足す。足すだけのつもりなら -a（append）が要る。
$ sudo usermod -aG proj-x,proj-y alice
$ id alice
uid=1004(alice) gid=1004(alice) groups=1004(alice),1103(proj-x),1200(proj-y),1201(ops)

主グループ（gid=1004(alice)）は最初から最後まで変わっていない。第1章で見たとおり主グループは /etc/passwd の4列目にあり、-G が触るのは /etc/group の4列目だけだからである。主グループを変えるのは小文字の -g である。

usermod のオプション書き換える場所
-g グループ主グループ（/etc/passwd の4列目）
-G a,b副グループの一覧を置き換える（/etc/group の4列目）
-aG a,b副グループに足す
-l 新しい名前ユーザ名（1列目）。ホームの場所は変わらない
-d /新しいホーム -mホームの場所（6列目）。-m で中身も移す
-s / -u / -cシェル（7列目）／UID（3列目）／コメント（5列目）
-e / -L / -U有効期限／ロック／ロック解除（/etc/shadow。第4章）
たとえ: 部署の兼務を申請する書類が「兼務先を全部書く」様式になっているのに近い。新しい兼務先だけを書いて出すと、書かなかった兼務は解除されたものとして処理される。
ただし崩れる点: 人事なら「本当に外しますか」と確認してくれるが、usermod -G は確認せずにその場で書き換え、何を外したかも言わない。結果は id で確かめるしかない。
手を動かす: 実践編の演習02は、今の所属を残したまま bob をグループに足す課題である。 判定は id bob で、最初からあった所属が残っているかまで見る。

ログイン中のシェルには、すぐには効かない

この節で分かること: 所属の変更がいつ読まれるか。

自分（student）を proj-x に入れ、同じ端末でそのまま確かめる。

$ sudo usermod -aG proj-x student
$ id -nG
student adm sudo
$ id -nG student
student adm sudo proj-x

名前を付けない id には proj-x が出ず、名前を付けた id student には出る。名前を付けないといま動いているシェルが持っている番号を表示し、名前を付けると台帳を引くからである。シェルの所属グループは、ログインしたときに台帳から読み込まれ、そのあとは変わらない。exit して ssh linuc で入り直すと出る。

$ id -nG
student adm sudo proj-x

「グループに入れたのに、まだ権限が無いと言われる」ときは、たいていこれである。入り直すまで、プロセスは古い所属のまま動く。確かめ終えたので外しておく。

$ sudo gpasswd -d student proj-x
Removing user student from group proj-x
たとえ: 入館証に近い。入館するときに、その時点の権限を書き込んだカードを受け取る。名簿で権限を足しても、いま首から下げているカードは変わらない。出て入り直すと、新しいカードになる。
ただし崩れる点: 入館証は1人1枚だが、プロセスは子プロセスを作るたびに同じ所属を写していく。古い所属のまま動き続けるプロセスは、ログアウトしても残っていることがある（cron やデーモンが起動したもの）。

グループの名前を変える・消す

この節で分かること: groupmod と groupdel が台帳のどこを変えるか。
$ sudo groupmod -n operators ops
$ getent group operators
operators:x:1201:alice
$ id alice
uid=1004(alice) gid=1004(alice) groups=1004(alice),1103(proj-x),1200(proj-y),1201(operators)

-n で名前だけが変わり、GID 1201 とメンバーはそのままである。ファイルの所有グループも番号で記録されているので、ls -l の表示が新しい名前に変わる（番号を変える groupmod -g は逆で、ファイルの側は古い番号のまま取り残される）。消すのは groupdel である。

$ sudo groupdel alice
groupdel: cannot remove the primary group of user 'alice'

誰かの主グループになっているグループは、そのままでは消せない。消すと、その人の /etc/passwd の4列目が名前の無い番号を指すことになるからである。それでも消すのが -f（--force）である。alice で試すと後の章の画面が変わるので、使い捨てのユーザで確かめる。

$ sudo useradd -m temp1
$ sudo groupdel -f temp1
$ id temp1
uid=1006(temp1) gid=1006 groups=1006
$ ls -ld /home/temp1
drwxr-x--- 2 temp1 1006 4096 Oct 13 19:19 /home/temp1
$ sudo userdel -r temp1
userdel: temp1 mail spool (/var/mail/temp1) not found

消えた。temp1 の /etc/passwd の4列目（1006）はそのままなので、主グループは名前を引けない番号だけになり、id も ls -l も番号で表示した。副グループ（operators）なら、-f が無くてもメンバーごと消せる。

$ sudo groupdel operators
$ id alice
uid=1004(alice) gid=1004(alice) groups=1004(alice),1103(proj-x),1200(proj-y)

userdel で消えるのは名前で、番号は残る

この節で分かること: userdel と userdel -r の違いと、消したあとに起きること。

carol に、ホームの外にもファイルを1つ作らせてから、-r を付けずに消す。

$ sudo -u carol touch /tmp/carol-was-here
$ ls -l /tmp/carol-was-here
-rw-rw-r-- 1 carol carol 0 Oct 13 19:19 /tmp/carol-was-here
$ sudo userdel carol
$ ls -ld /home/carol
drwxr-x--- 2 1005 1005 4096 Oct 13 19:18 /home/carol
$ ls -l /tmp/carol-was-here
-rw-rw-r-- 1 1005 1005 0 Oct 13 19:19 /tmp/carol-was-here

ホームも /tmp のファイルも残り、所有者の欄が名前から番号（1005）に変わった。ファイルに書かれていたのは最初から番号で、ls が台帳を引いて名前に直していただけである。台帳の行が消えたので、番号がそのまま出た。持ち主のいないファイルは find で探せる。

$ sudo find / -xdev -nouser
/home/carol
/home/carol/.profile
/home/carol/memo.txt
/home/carol/.bashrc
/home/carol/.bash_logout
/tmp/carol-was-here

ここで新しいユーザを1人作る。

$ sudo useradd -m erin
$ id erin
uid=1005(erin) gid=1005(erin) groups=1005(erin)
$ ls -l /home
total 28
drwxr-x--- 2 alice   alice   4096 Oct 13 19:18 alice
drwxr-x--- 2 bob     bob     4096 Oct 13 19:18 bob
drwxr-x--- 2 erin    erin    4096 Oct 13 19:18 carol
drwxr-x--- 3 dave    dave    4096 Oct 13 19:18 dave
drwxr-x--- 2 erin    erin    4096 Oct 13 19:19 erin
drwxr-x--- 2 eve     eve     4096 Oct 13 19:18 eve
drwxr-x--- 5 student student 4096 Oct 13 19:18 student
$ ls -l /tmp/carol-was-here
-rw-rw-r-- 1 erin erin 0 Oct 13 19:19 /tmp/carol-was-here

erin は carol と同じ UID 1005 をもらい、carol のホームと /tmp のファイルの持ち主になった。useradd は「いまある最大の UID の次」を振るので、いちばん新しいユーザを消すと、次に作った人がその番号を引き継ぐ。会社なら、退職者のファイルを新人が丸ごと読める状態である。

消すときは -r を付けてホーム（とメールスプール）も消し、ホームの外に残ったものは find / -nouser や find / -uid 番号 で探して始末する。

$ sudo userdel -r erin
userdel: erin mail spool (/var/mail/erin) not found
$ sudo rm -r /home/carol /tmp/carol-was-here
$ ls -1 /home
alice
bob
dave
eve
student

userdel -r が消すのはホームとメールスプールだけで、/tmp など他の場所のファイルは消さない。

たとえ: 番号で管理しているロッカーに近い。退職者の名札を外しても、ロッカーの中身は番号ごと残る。次にその番号を割り当てられた人は、中身ごと受け取る。
ただし崩れる点: 会社なら新人に渡す前に中を空けるが、useradd は番号が空いているかを台帳でしか確かめない。ディスクにその番号のファイルが残っていても気にしない。
確認

ユーザ hanako は副グループ sales に所属している。sales の所属を保ったまま、developers にも所属させたい。正しいコマンドはどれか。

A. usermod -G developers hanako　B. usermod -g developers hanako　C. usermod -aG developers hanako　D. groupmod -a developers hanako

答え

C。-G だけだと副グループが developers だけに置き換わり、sales から外れる（この章の proj-x と proj-y がその実物）。 -g は主グループを変える。D は書式が誤りで、groupmod でメンバーを足すなら groupmod -a -U hanako developers という別の形になる（-U でメンバーの一覧を渡し、-a で足す。-a が無いと一覧が置き換わる）。

確認

userdel taro と userdel -r taro の違いを答えよ。また、どちらの場合も残りうるものは何か。

答え

-r を付けるとホームディレクトリとメールスプールも消す。付けないと台帳の行だけが消え、ホームは所有者が番号表示のまま残る。 どちらの場合も、ホームの外（/tmp など）にある taro のファイルは残る。find / -nouser で探せる。

確認

groupdel staff が cannot remove the primary group of user 'ken' で失敗した。何が原因で、どうすれば消せるか。

答え

staff が ken の主グループ（/etc/passwd の4列目）になっている。先に usermod -g 別のグループ ken で ken の主グループを変えるか、ken を消してから groupdel する。groupdel -f staff でも消せるが、ken の主グループは名前の無い GID を指したまま残る（この章の temp1）。副グループとしてのメンバーがいるだけなら、-f が無くても消せる。

この章で分かったこと

持ち帰ってほしいこと

  • groupadd（-g で GID 指定）・groupmod（-n で改名）・groupdel（誰かの主グループは -f を付けないと消せない。付けると名前の無い GID が残る）
  • usermod -G は副グループを置き換え、-aG は足す。主グループは -g
  • 所属の変更はログインのときに読まれる。id（名前なし）はいまのシェル、id ユーザ名 は台帳
  • userdel は台帳の行を消す。-r でホームとメールスプールも消す。ほかの場所のファイルは番号のまま残る
  • UID は「最大の次」から振られるので、消した番号は再利用されうる。残ったファイルは新しい持ち主のものになる
