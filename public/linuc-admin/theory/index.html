理論編 — システム管理

LinuC レベル1 102 試験・主題1.08（アカウント管理・ジョブスケジューリング・ローカライゼーション）を、 コンテナの中で動く練習機（仮想マシン）で実際に打って確かめる9章。 1章ごとに「実際に打つと何が出るか」を先に置いています。

このページのコマンドは、あなたの画面に本文と同じ文字を出します（時刻や日付など、打った日時で変わるものを除く）。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この9章を貫いている1つの事実

管理コマンドが書き換えるのは、台帳（/etc やスプールにあるテキスト）の1行だけである。 その1行が効くかどうかは、台帳を読む側（ログイン・cron・at・プログラム）が、いつ・どの列を読むかで決まる。

useradd は台帳にホームを書くが、ディレクトリは作らない。passwd -l はパスワードの列を閉じるが、鍵の ssh はその列を読まない。 /etc/cron.daily に置いたスクリプトは、run-parts が名前で選ばなければ走らない。LANG は名前を書くだけで、実体が無ければ黙って無視される。 だから主題1.08 の「詳細」欄には、コマンドと同じくらいファイルのパスが並んでいます。それぞれが誰かに読まれる台帳だからです。

ここで覚えなくていいこと: PAM の設定ファイルの書き方、LDAP などの外部のユーザ管理、systemd のタイマーの書き方、gettext の仕組み、Unicode の正規化。 どれもレベル1の主題1.08 の範囲外で、この9章では名前が出る程度です。

  3. 所属は、書いたとおりに置き換わる — usermod -G で2つのグループから黙って外れる。消したユーザのファイルを新人が受け継ぐ（18分）

なぜ仮想マシンで確かめるのか

この主題は、ログイン（sshd と PAM）、時刻で動くデーモン（cron・atd・anacron）、システム全体のロケールを扱います。 コンテナの中ではこれらが動いていないか、ホストの設定を借りているので、本物と同じ画面になりません。 そこで、コンテナの中で QEMU の完全エミュレーションを使って Ubuntu 24.04 の練習機を1台動かし、その中で打ちます。 読者がホストに渡す特権はありません（--privileged も --cap-add も使いません）。

  • 第4章の「ロックしても鍵で入れる」は、外のコンテナから練習機へ本物の ssh をつないで確かめています
  • 第5〜7章の cron と at は、時刻を書き換えずに、本当に次の分まで待って動いた結果です（待つ時間は本文に書いてあります）
  • 練習機の起動から15分ほどは、起動時の anacron が順番待ちをしています。第6章はその後に読んでください

実務のどこで効くか

場面ここで効く理由見落としやすい点関連する章
退職者・休職者のアカウントを止める 消すか止めるかで、残るものと止まる入口が変わる passwd -l では鍵の ssh が止まらない。userdel したあとの UID は再利用される3・4
新しいメンバーに権限を足す グループの所属で権限を渡すのが基本 -G だけだと既存の所属が外れる。ログイン中の端末には次のログインまで効かない1・3
定期処理が「動いていない」 cron・anacron・run-parts のどこで落ちているかを、ログと --test で切り分けられる ユーザの表に6列目を書く、.sh の名前、SHELL=/bin/sh。エラーはメールで捨てられて見えないことが多い5・6
スクリプトが人によって違う結果を出す 出力の形はロケールで変わる LANG=C だけでは呼ぶ側の LC_ALL に負ける8
取引先から届いた CSV が化けている 文字コードを推定して iconv で直せる file の判定はあてにならない。化けた結果を上書き保存すると戻せなくなる9
