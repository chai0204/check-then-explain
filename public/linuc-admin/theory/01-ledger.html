1. ユーザの台帳は3枚に分かれている

「ユーザ」という1つのものがあるように見えるが、実体は3枚のテキストファイルに散らばった行である。名前と番号は /etc/passwd、パスワードは /etc/shadow、グループは /etc/group。しかもグループの名簿には、そのグループを主グループにしている人が載らない。

この章のゴールと前提所要 15分
前提: 実践編の「はじめる」で練習機に入れた所要 15分影響度 A出題範囲 1.08.1（重要度5）最終検証 2026-10-13

この章のゴール

  • /etc/passwd（7列）・/etc/shadow（9列）・/etc/group（4列）の各列を読める
  • あるユーザの所属グループが、2つの台帳に分けて書かれていることを説明できる
  • id と getent が、台帳をどう引いているかを言える
ここで覚えなくていいこと: パスワードのハッシュの計算方法（yescrypt の中身）、/etc/gshadow の各列、LDAP や SSSD の設定は扱わない。/etc/nsswitch.conf の書き方は主題1.07（ネットワークの基礎。1.07.2 と 1.07.4）で問われるので、ここでは「どこを引くかの順番表」と分かれば足りる。この章は読むだけで、何も書き換えない。

自分が誰かは、番号で決まっている

この節で分かること: カーネルが見ているのは名前ではなく番号であること。

外の端末で ssh linuc と打って練習機に入り、自分が誰かを聞く。

$ id
uid=1000(student) gid=1000(student) groups=1000(student),4(adm),27(sudo)

3つの欄がある。uid（ユーザの番号）、gid（主グループの番号）、groups（所属しているグループ全部の番号）。かっこの中の名前は、番号を台帳で引いて付け足した飾りである。番号だけを出すこともできる。

$ id -u
1000
$ id -g
1000
$ id -G
1000 4 27
$ id -nG
student adm sudo

プロセスが持っているのは、この番号の組だけである。ファイルの所有者も番号で記録されている。名前を出しているのは id や ls が表示するときに台帳を引いたからで、台帳の行が消えれば名前も出なくなる（第3章で実際に消す）。

/etc/passwd は、誰でも読める7列の名簿

この節で分かること: /etc/passwd の7列それぞれの意味。
$ grep '^student:' /etc/passwd
student:x:1000:1000:LinuC student:/home/student:/bin/bash

: で区切られた7列である。試験ではこの順番と意味がそのまま問われる。

列この行の値意味
1studentユーザ名
2xパスワード欄。x は「/etc/shadow を見よ」の印（シャドウパスワード）
31000UID
41000主グループの GID
5LinuC studentコメント（GECOS。氏名など。空でもよい）
6/home/studentホームディレクトリ
7/bin/bashログインシェル

先頭の数行はシステムのユーザである。

$ head -3 /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin

root は UID 0。daemon や bin のシェルは /usr/sbin/nologin で、人がログインするためのユーザではない。人のユーザは UID 1000 から振られる（第2章で /etc/login.defs の UID_MIN を見る）。3列目が 1000 以上の行だけを抜き出す。

$ awk -F: '$3 >= 1000' /etc/passwd
nobody:x:65534:65534:nobody:/nonexistent:/usr/sbin/nologin
student:x:1000:1000:LinuC student:/home/student:/bin/bash
bob:x:1001:1001:Bob (lab 02):/home/bob:/bin/bash
dave:x:1002:1002:Dave (lab 03):/home/dave:/bin/bash
eve:x:1003:1003:Eve (lab 06):/home/eve:/bin/bash

bob・dave・eve は、実践編の演習で使うために最初から作ってある。nobody（65534）は「誰でもない」ことを表す特別なユーザで、範囲の外に置かれている。

たとえ: 会社の受付に置いてある社員名簿に近い。名前・社員番号・所属・席の場所が載っていて、誰でも閲覧できる。
ただし崩れる点: 社員名簿は人が読むためのものだが、/etc/passwd はプログラムが1行ずつ読むためのもので、列の順番が1つずれただけで別人の扱いになる。だから手で編集せず、useradd や usermod に書かせる。

パスワードは、別の台帳にしまってある

この節で分かること: /etc/shadow が分かれている理由と、9列の読み方。
$ ls -l /etc/passwd /etc/shadow /etc/group /etc/gshadow
-rw-r--r-- 1 root root    804 Oct 13 19:18 /etc/group
-rw-r----- 1 root shadow  669 Oct 13 19:18 /etc/gshadow
-rw-r--r-- 1 root root   1642 Oct 13 19:18 /etc/passwd
-rw-r----- 1 root shadow  901 Oct 13 19:18 /etc/shadow

/etc/passwd と /etc/group は誰でも読める（-rw-r--r--）。/etc/shadow と /etc/gshadow は root と shadow グループしか読めない（-rw-r-----）。ls -l も id もユーザ名を出すために /etc/passwd を読むので、こちらは全員に読ませる必要がある。だからハッシュだけを別のファイルに逃がした。

この権限は Ubuntu（Debian 系）のものである。RHEL 系では shadow グループが無く、権限は 000（----------）で、root だけが読む。比較のために AlmaLinux 9.7 のコンテナで打った記録を添える（この教材の練習機では打てない）。

$ ls -l /etc/shadow /etc/gshadow
---------- 1 root root 315 May 24 12:07 /etc/gshadow
---------- 1 root root 417 May 24 12:07 /etc/shadow
$ grep '^student:' /etc/shadow
grep: /etc/shadow: Permission denied
$ sudo grep '^student:' /etc/shadow
student:$y$j9T$zeB7kAA87DbMW.lomNUkh1$NBqSAf/88BS9vHtwcATjPukJ8Y3XB3oXLNYtJHmdSi4:20739:0:99999:7:::
列この行の値意味
1studentユーザ名
2$y$j9T$…パスワードのハッシュ。$y$ は yescrypt、$6$ なら SHA-512。! や * で始まるとパスワードでは入れない（第4章）
320739最後にパスワードを変えた日（1970-01-01 からの日数）。0 なら「次のログインで変更を強制」
40変更してから次に変えられるまでの最短日数
599999パスワードの有効日数（99999 は事実上無期限）
67期限切れの何日前から警告するか
7（空）期限切れのあと、ログインできなくなるまでの猶予日数
8（空）アカウント自体の有効期限（1970-01-01 からの日数）
9（空）予約

3列目の 20739 を日付に直すと、練習機を作った日になる。

$ date -d '1970-01-01 +20739 days' +%F
2026-10-13

日付が「日数」で入っているのが /etc/shadow の読みにくさで、人が読むときは chage -l（第4章）で変換して表示させる。

たとえ: 名簿とは別に、金庫の中にしまってある暗証番号の控えに近い。名簿は誰でも見られるが、控えは管理者しか見られない。名簿の暗証番号の欄には「金庫を見よ」とだけ書いてある（それが x）。
ただし崩れる点: 金庫の控えには暗証番号そのものが書いてあるが、/etc/shadow にあるのはハッシュ（元に戻せない変換の結果）で、パスワードそのものは誰も持っていない。それでも盗まれると総当たりで割られうるので、読める人を絞っている。

グループの名簿には、主グループの人が載らない

この節で分かること: 所属グループが2つの台帳に分けて書かれていること。

/etc/group は4列（グループ名・x・GID・メンバー）である。id に出た3つのグループの行を見る。

$ grep -E '^(adm|sudo|student):' /etc/group
adm:x:4:student
sudo:x:27:student
student:x:1000:

ふつうこう考える

グループに誰が入っているかは、/etc/group のそのグループの行の4列目（メンバー）を見れば分かる。 student は student グループに入っているのだから、student の行のメンバー欄には student と書いてあるはずだ。

$ getent group student
student:x:1000:
$ id student
uid=1000(student) gid=1000(student) groups=1000(student),4(adm),27(sudo)
だめな理由: メンバー欄は空である。それでも id は 1000(student) に入っていると言う。 /etc/group の4列目に書かれるのは副グループとして入っている人だけで、主グループはそこに書かれない。 主グループは /etc/passwd の4列目に GID で書かれている。つまり所属は2枚の台帳に分かれていて、 /etc/group だけを見ると主グループの人を数え落とす。

主グループの側から引くとこうなる。

$ getent passwd student | cut -d: -f4
1000
$ getent group 1000
student:x:1000:

演習用の bob でも同じ形になっている。proj-a と proj-b の行にはメンバーとして bob が載り、bob グループの行のメンバー欄は空である。

$ getent group proj-a proj-b bob
proj-a:x:1101:bob
proj-b:x:1102:bob
bob:x:1001:
$ id bob
uid=1001(bob) gid=1001(bob) groups=1001(bob),1101(proj-a),1102(proj-b)
主グループ   /etc/passwd の4列目（GID）      bob:x:1001:1001:…
副グループ   /etc/group  の4列目（メンバー）  proj-a:x:1101:bob
id bob       両方を引いて1行にまとめる       groups=1001(bob),1101(proj-a),1102(proj-b)

だから「ユーザの所属を全部」知りたいときは grep ではなく id ユーザ名（または groups ユーザ名）を使う。そして第3章で見るとおり、所属を変える usermod も、この2つの台帳を別々のオプションで書き換える。

たとえ: 社員証に印刷された所属部署（本務）と、プロジェクトごとの参加者名簿（兼務）に近い。参加者名簿に載るのは兼務で入った人だけで、その部署が本務の人はわざわざ書かれない。
ただし崩れる点: 会社なら本務の部署にも名簿があるのがふつうだが、/etc/group では本務（主グループ）の人は名簿に一切載らない。名簿の行数を数えても人数にはならない。

getent は、ログインと同じ道で台帳を引く

この節で分かること: grep と getent の違い。

ここまで getent を使ってきた。getent はファイルを直接読むのではなく、ログインや id が使うのと同じ「名前解決の仕組み（NSS）」に問い合わせる。どこを引くかの順番表が /etc/nsswitch.conf にある。

$ grep -E '^(passwd|group|shadow|gshadow):' /etc/nsswitch.conf
passwd:         files
group:          files
shadow:         files
gshadow:        files

この練習機ではどれも files（/etc のファイル）だけなので、getent と grep の結果は同じになる。会社のサーバのように LDAP などからユーザを引く設定では、/etc/passwd に1行も無いユーザがログインできる。そのとき grep では見つからず、getent では見つかる。

$ getent passwd bob
bob:x:1001:1001:Bob (lab 02):/home/bob:/bin/bash
$ getent passwd 1002
dave:x:1002:1002:Dave (lab 03):/home/dave:/bin/bash
$ getent passwd nosuchuser; echo $?
2
$ sudo getent shadow bob
bob:!:20739:0:99999:7:::

番号からも引ける（1002 は dave）。見つからないときは何も出さず、終了コード 2 を返す。shadow を引くには root の権限が要る。bob の2列目が ! なのは、パスワードを一度も設定していないからである（第4章）。

たとえ: 電話番号を、手元の電話帳をめくって探す（grep）か、番号案内に聞く（getent）かの違いに近い。番号案内は手元の電話帳も、ほかの地域の電話帳も、決まった順に調べてくれる。
ただし崩れる点: 番号案内は人が判断して答えるが、getent は /etc/nsswitch.conf の順番どおりに機械的に引き、最初に見つかったものを返すだけである。2か所に同じ名前があれば、後ろの方は見えない。
手を動かす: 実践編の演習01・02で、ここで読んだ列を自分で書き換える。 判定は getent と id を引いて、台帳の行と実物（ホームディレクトリ）を確かめる。
確認

次の行は /etc/passwd の1行である。ログインシェルと、主グループの GID を答えよ。

carol:x:1005:1005:Carol Lab:/home/carol:/bin/bash
答え

ログインシェルは7列目の /bin/bash、主グループの GID は4列目の 1005。 3列目（UID）と4列目（GID）はどちらも 1005 だが、意味が違う。5列目の Carol Lab はコメント（GECOS）。

確認

ユーザ alice が所属するグループを、主グループも含めてすべて表示したい。最も適切なコマンドはどれか。

A. grep alice /etc/group　B. id alice　C. grep alice /etc/passwd　D. cat /etc/gshadow

答え

B。id は /etc/passwd の4列目（主グループ）と /etc/group の4列目（副グループ）の両方を引いて1行にまとめる。 A は副グループしか拾えず、主グループの行には alice の名前が載らない（この章の student:x:1000: がその実物）。groups alice でも同じ情報が出る。

確認

/etc/shadow の3列目が 20739 だった。これは何を表すか。また、0 だったら何が起きるか。

答え

最後にパスワードを変更した日を、1970-01-01 からの日数で表したもの（20739 日目 = 2026-10-13）。 0 は「パスワードを最後に変えたのが 1970-01-01」という扱いになり、次のログインでパスワードの変更を強制される（passwd -e がこれを書く。第4章）。

この章で分かったこと

持ち帰ってほしいこと

  • プロセスとファイルが持っているのは番号（UID・GID）で、名前は台帳を引いて付けた表示にすぎない
  • /etc/passwd は7列（名前:x:UID:GID:コメント:ホーム:シェル）。誰でも読める
  • /etc/shadow は9列。ハッシュと、日数で書かれた期限の情報。Ubuntu では root と shadow グループだけが読める（RHEL 系は権限 000 で root だけ）
  • /etc/group は4列。4列目のメンバーは副グループの人だけで、主グループは /etc/passwd の4列目に書かれる
  • 所属を全部知るには id ユーザ名。台帳を引くなら getent（ログインと同じ道を通る）
