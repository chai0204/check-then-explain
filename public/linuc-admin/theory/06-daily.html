6. 毎日の仕事は、名前で選ばれる

実行権を付けたスクリプトを /etc/cron.daily に置いても、名前が hello.sh なら毎日の実行に選ばれない。中身を選んでいるのは run-parts で、Debian 系の run-parts は名前に . を含むファイルを黙って飛ばす。そして「いつ走らせるか」を決めているのは、この Ubuntu では cron ではなく anacron である。

前提: 第5章まで読了前提: 練習機を起動してから15分以上たっている（理由は本文）所要 16分影響度 B出題範囲 1.08.2（重要度4）最終検証 2026-10-13

この章のゴール

  • /etc/cron.hourly・/etc/cron.daily・/etc/cron.weekly・/etc/cron.monthly を、誰がいつ走らせるかを説明できる
  • run-parts がディレクトリの中から何を選ぶか（実行権と名前）を、--test で確かめられる
  • /etc/anacrontab の4列と、anacron の主なオプション（-f -n -s -d -T -u）を読める
ここで覚えなくていいこと: systemd のタイマーの書き方（anacron.timer の中身は読むだけ）、電源（AC/バッテリー）による抑止は扱わない。

cron.daily を走らせているのは誰か

この節で分かること: 毎時・毎日・毎週・毎月のディレクトリの実行経路。
$ ls -l /etc/cron.daily
total 24
-rwxr-xr-x 1 root root  311 Sep 25  2023 0anacron
-rwxr-xr-x 1 root root  376 Jul 29 23:09 apport
-rwxr-xr-x 1 root root 1478 Mar 22  2024 apt-compat
-rwxr-xr-x 1 root root  123 Feb  5  2024 dpkg
-rw-r--r-- 1 root root  165 Oct 13 19:18 lab-backup.sh
-rwxr-xr-x 1 root root 1395 Mar 30  2024 man-db
$ grep run-parts /etc/crontab
17 *	* * *	root	cd / && run-parts --report /etc/cron.hourly
25 6	* * *	root	test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.daily; }
47 6	* * 7	root	test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.weekly; }
52 6	1 * *	root	test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.monthly; }

第5章で見た /etc/crontab の4行である。毎時（17 *）は cron が run-parts を直接呼ぶ。毎日・毎週・毎月の行は test -x /usr/sbin/anacron || … で始まっていて、anacron が入っていれば何もしない。代わりに anacron が自分の表を読む。

$ grep -vE '^\s*#|^\s*$' /etc/anacrontab
SHELL=/bin/sh
HOME=/root
LOGNAME=root
1	5	cron.daily	run-parts --report /etc/cron.daily
7	10	cron.weekly	run-parts --report /etc/cron.weekly
@monthly	15	cron.monthly	run-parts --report /etc/cron.monthly
列例（1行目）意味
1 周期1何日ごとか（7 なら週1回。@monthly は月1回）
2 遅延5anacron が起きてから、何分待って始めるか
3 ジョブ名cron.daily識別子。前回の実行日を /var/spool/anacron/ のこの名前のファイルに書く
4 コマンドrun-parts --report /etc/cron.daily実行するもの

先頭の3行（SHELL・HOME・LOGNAME）は、ジョブを走らせるときの環境変数である。RHEL 系の /etc/anacrontab には、さらに RANDOM_DELAY=45（2列目の遅延に、0〜45分の乱数を足す）と START_HOURS_RANGE=3-22（3時台から21時台のあいだだけ実行する。終わりの22は含まない）が書かれている。この練習機の Ubuntu には無い。

anacron は常駐しない。起動したとき（anacron.service）と、7時から23時までの毎時30分（anacron.timer。最大5分のずれを足す）に起こされ、「前回から周期の日数がたっていれば、遅延の分だけ待ってから実行する」。この練習機が起動したときの記録が残っている。

起動した時点で3つとも「まだ一度も走っていない」扱いだったので、5分後・10分後・15分後に順に走らせ、そのたびにジョブ名のファイルへ今日の日付を書いた。起動時の anacron は3つのジョブを終えて Normal exit (3 jobs run) と書き、systemd がサービスを止めた。この記録ではその直後に、anacron.timer が起こした2回目の anacron（PID が違う）が Normal exit (0 jobs run) と書いている。今日の分は済んでいるので何もしない。2回目が出るかどうか、いつ出るかは、練習機を起動した時刻で変わる（出ない記録も取れた）。15分たつまでは、起動時の anacron が順番待ちのまま残っている。そのあいだに手で anacron を打つと、ロックされたジョブを locked by another anacron - skipping と言って飛ばす。この章の前提を「起動から15分以上」にしたのはそのためである。

ここまでは Ubuntu のしくみである。RHEL 系では anacron を起こすのも cron で、/etc/cron.d/0hourly が毎時01分に /etc/cron.hourly を走らせ、その中の 0anacron が「今日まだなら」anacron を起動する（LinuC の例題も「cron によって anacron を定期実行する」と書く）。比較のために AlmaLinux 9.7 のコンテナで見た記録を添える（この教材の練習機では打てない）。

$ cat /etc/cron.d/0hourly
# Run the hourly jobs
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
01 * * * * root run-parts /etc/cron.hourly
$ grep -vE '^#|^$' /etc/cron.hourly/0anacron | tail -3
    exit 0
fi
/usr/sbin/anacron -s
$ grep -vE '^#|^$' /etc/anacrontab
SHELL=/bin/sh
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
RANDOM_DELAY=45
START_HOURS_RANGE=3-22
1	5	cron.daily		nice run-parts /etc/cron.daily
7	25	cron.weekly		nice run-parts /etc/cron.weekly
@monthly 45	cron.monthly		nice run-parts /etc/cron.monthly
たとえ: cron は目覚まし時計で、anacron は日めくりカレンダーに印を付ける当番に近い。目覚ましは鳴る時刻に電源が切れていたら、その日は鳴らない。当番は来たときにカレンダーを見て、今日の印が無ければ仕事をして印を付ける。
ただし崩れる点: 当番は1日に何度来ても、印があれば何もしない。だから1日より細かい周期は anacron では作れない（毎時の cron.hourly は cron が直接走らせている）。

実行権を付けても、選ばれない名前がある

この節で分かること: run-parts がディレクトリの中から何を選ぶか。

ふつうこう考える

/etc/cron.daily にスクリプトを置いて実行権を付ければ、毎日1回走る。 名前はなんでもよいはずで、シェルスクリプトだと分かるように .sh を付けておく。

$ printf '#!/bin/sh\ndate >> /tmp/daily.txt\n' | sudo tee /etc/cron.daily/hello.sh
#!/bin/sh
date >> /tmp/daily.txt
$ sudo chmod 755 /etc/cron.daily/hello.sh
$ run-parts --test /etc/cron.daily
/etc/cron.daily/0anacron
/etc/cron.daily/apport
/etc/cron.daily/apt-compat
/etc/cron.daily/dpkg
/etc/cron.daily/man-db
$ run-parts --list /etc/cron.daily
/etc/cron.daily/0anacron
/etc/cron.daily/apport
/etc/cron.daily/apt-compat
/etc/cron.daily/dpkg
/etc/cron.daily/man-db
だめな理由: run-parts --test は「実際には走らせずに、走らせるものの名前だけ出す」オプションである。そこに hello.sh が無い。実行権を見ずに名前の条件だけで選ぶ --list にも無い。 Debian 系の run-parts は、名前が英大文字・小文字・数字・_・- だけでできているファイルしか選ばない。 .sh の . で外れた。パッケージの更新で残る foo.dpkg-old や foo.dpkg-dist を誤って実行しないための決まりで、 飛ばしたことはどこにも記録されない。ディレクトリに置いたことと、毎日の実行に入ったことは別である。

この名前の決まりは Debian 系の run-parts のものである。RHEL 系の run-parts は別の実装（crontabs パッケージのシェルスクリプト）で、hello.sh も走らせる。比較の記録を添える。

$ run-parts /tmp/rp
/tmp/rp/hello.sh:

hello.sh ran

（/tmp/rp には、実行権を付けた hello.sh を1つだけ置いてある。）

$ sudo mv /etc/cron.daily/hello.sh /etc/cron.daily/hello
$ run-parts --test /etc/cron.daily
/etc/cron.daily/0anacron
/etc/cron.daily/apport
/etc/cron.daily/apt-compat
/etc/cron.daily/dpkg
/etc/cron.daily/hello
/etc/cron.daily/man-db

名前から .sh を外すと選ばれた。もう1つの条件は実行権である。外して比べる。

$ sudo chmod 644 /etc/cron.daily/hello
$ run-parts --test /etc/cron.daily
/etc/cron.daily/0anacron
/etc/cron.daily/apport
/etc/cron.daily/apt-compat
/etc/cron.daily/dpkg
/etc/cron.daily/man-db
$ run-parts --list /etc/cron.daily
/etc/cron.daily/0anacron
/etc/cron.daily/apport
/etc/cron.daily/apt-compat
/etc/cron.daily/dpkg
/etc/cron.daily/hello
/etc/cron.daily/man-db
$ sudo chmod 755 /etc/cron.daily/hello
オプション出すものhello（実行権なし）hello.sh（実行権あり）
run-parts --test DIR実際に走らせるもの（名前の条件と実行権の両方）出ない出ない
run-parts --list DIR名前の条件に合うもの（実行権は見ない）出る出ない
run-parts --report DIR実際に走らせ、何か出力したものの名前を添える（/etc/crontab と /etc/anacrontab が使っている形）
たとえ: 決まった書式の伝票だけを処理する事務の係に近い。書式の違う伝票は、受け付けたとも断ったとも言わずに箱に残しておく。
ただし崩れる点: 人なら「この伝票は書式が違います」と戻してくれるが、run-parts は何も言わない。自分から --test で聞かない限り、外れたことに気づけない。
手を動かす: 実践編の演習05は、置いてあるのに一度も走っていない lab-backup.sh を毎日の実行に入れ、今日の分を走らせる課題である。 判定は run-parts --test に選ばれるかと、走った跡（ログの行）を見る。

今日の分を、いま走らせる

この節で分かること: 時刻を待たずに anacron の動きを確かめる方法。

-n は「遅延の分数を待たない」、-d は「バックグラウンドに回らず、経過を端末に出す」。

$ sudo anacron -n -d
Anacron 2.3 started on 2026-10-13
Normal exit (0 jobs run)

何も走らなかった。今日の日付がもう書かれているからである。日付を無視させるのが -f、ジョブを1つずつ順に走らせるのが -s である。

$ sudo anacron -f -n -s -d
Anacron 2.3 started on 2026-10-13
Will run job `cron.daily'
Will run job `cron.weekly'
Will run job `cron.monthly'
Jobs will be executed sequentially
Job `cron.daily' started
Job `cron.daily' terminated
Job `cron.weekly' started
Job `cron.weekly' terminated
Job `cron.monthly' started
Job `cron.monthly' terminated
Normal exit (3 jobs run)
$ cat /tmp/daily.txt
Tue Oct 13 19:33:20 JST 2026
$ sudo cat /var/spool/anacron/cron.daily
20261013

3つのジョブが順に走り、hello も run-parts に選ばれて1行書いた。cron.daily の先頭にある 0anacron は、run-parts が cron.daily を走らせたとき（anacron からでも cron からでも、手で打っても）に、anacron の日付を今日にそろえる部品である。anacron が入っていなければ何もしない。

$ grep -vE '^#|^$' /etc/cron.daily/0anacron
test -x /usr/sbin/anacron || exit 0
anacron -u cron.daily
$ sudo anacron -T; echo $?
0
$ sudo rm /etc/cron.daily/hello

-T は /etc/anacrontab の書き方だけを検査する（正しければ何も出さずに 0）。

オプション意味
-f前回の日付を無視して、全部のジョブを走らせる
-n遅延（2列目の分数）を待たずにすぐ始める
-sジョブを1つずつ順に走らせる（Ubuntu の既定の起動でも付いている）
-d端末に経過を出し、バックグラウンドに回らない
-u走らせずに、日付だけを今日に更新する
-T/etc/anacrontab（-t ファイル で別のファイル）の書き方を検査する
たとえ: anacron -f は、日めくりカレンダーの印を見ないで当番に今日の仕事をさせることに近い。終われば今日の印は付く。
ただし崩れる点: 当番の仕事はカレンダー1枚につき1つだが、anacron のジョブは「ディレクトリの中身を全部」である。-f で走らせると、置いてあるほかのスクリプトも全部走る。
確認

/etc/anacrontab の次の行の、7 と 10 の意味を答えよ。

7	10	cron.weekly	run-parts --report /etc/cron.weekly
答え

7 は周期（前回の実行から7日たっていれば実行する）、10 は遅延（anacron が起きてから10分待って始める）。 3列目の cron.weekly はジョブ名で、前回の実行日は /var/spool/anacron/cron.weekly に書かれる。

確認

/etc/cron.daily/backup.sh を置き、chmod 755 もした。しかし毎日の実行で走っていない。Debian 系で最も考えられる原因はどれか。

A. 所有者が root ではない　B. 名前に . が含まれている　C. /etc/crontab に登録していない　D. crontab -e で登録していない

答え

B。run-parts は名前に . を含むファイルを選ばない。run-parts --test /etc/cron.daily で選ばれるかを確かめられる。 C・D は不要で、ディレクトリに置くこと自体が登録になっている（ただし名前と実行権の条件を満たすとき）。

確認

夜は電源を切るノート PC で、1日1回の処理を取りこぼさずに実行したい。cron と anacron のどちらが向いているか。理由も答えよ。

答え

anacron。cron は決まった時刻に動いていなければ、その回は実行しない。anacron は起動したとき（と定期的に）前回の実行日を見て、 周期の日数がたっていれば実行する。ただし anacron の周期は日単位で、1日より細かい間隔には使えない。

この章で分かったこと

持ち帰ってほしいこと

  • この Ubuntu では、/etc/cron.hourly は cron が毎時17分に、/etc/cron.daily・weekly・monthly は anacron が走らせる（anacron が入っていれば /etc/crontab の該当行は何もしない）。RHEL 系は cron が毎時01分に /etc/cron.hourly を走らせ、その中の 0anacron が anacron を起こす
  • 中身を選ぶのは run-parts。Debian 系の run-parts は実行権があり、名前が英数字・_・- だけのものしか選ばない。.sh は外れる（RHEL 系の run-parts は選ぶ）
  • 選ばれるかは run-parts --test、名前の条件だけなら --list で確かめる
  • /etc/anacrontab は「周期（日） 遅延（分） ジョブ名 コマンド」の4列。前回の実行日は /var/spool/anacron/ジョブ名
  • 今日の分を走らせるのは anacron -f -n（-s 順に、-d 経過を表示）。書き方の検査は anacron -T
