7. ハードリンクは名前を増やし、シンボリックリンクは道順を書く

rm memo.txt の後も、hard.txt から同じ中身が読めた。rm が消すのは名前1つで、中身は最後の名前が消えるまで残る。ハードリンクは同じ中身にもう1つ名前を付け、シンボリックリンクは「この道順で行け」と書いた別のファイルを置く。第1章で見つけた「名前と中身は別の場所にある」が、ここで正面から使える。

前提: 第6章まで読了前提: 檻が起動している所要 20分影響度 B出題範囲 1.02.3（重要度2）最終検証 2026-10-13

この章のゴール

  • ls -li と ls -F の表示から、ハードリンクとシンボリックリンクを見分けられる
  • 元のファイルを消したとき・別のファイルシステムをまたぐとき・ディレクトリのとき、それぞれどちらが使えるかを言える
  • シンボリックリンクで「いま使う版」を切り替える手順を、ln -sfn の意味とともに書ける
ここで覚えなくていいこと: inode の中の構造（データブロックへのポインタ）、debugfs、update-alternatives の操作、readlink と realpath の細かい違いは扱わない。update-alternatives は「シンボリックリンクを2段つないで実体を切り替えている」と分かれば足りる。

ハードリンクは、同じ中身のもう1つの名前

この節で分かること: ln で作った名前が、元の名前と何を共有しているか。

この章は ~/work/ch7 で作業する。1つのファイルに、2種類のリンクを作る。

$ mkdir -p ~/work/ch7
$ cd ~/work/ch7
$ echo "第1版" > memo.txt
$ ln memo.txt hard.txt
$ ln -s memo.txt soft.txt
$ ls -li memo.txt hard.txt soft.txt
18128446 -rw-r--r-- 2 lab lab 8 Oct 13 11:43 hard.txt
18128446 -rw-r--r-- 2 lab lab 8 Oct 13 11:43 memo.txt
18128447 lrwxrwxrwx 1 lab lab 8 Oct 13 11:43 soft.txt -> memo.txt

ls -i の -i は、行頭に inode 番号を出す。第1章で「名前の先にある実体の番号」と呼んだものである。memo.txt と hard.txt は同じ番号を指していて、3列目（リンク数）が 2 になっている。「この中身を指している名前が2つある」という意味である。番号そのものは環境ごとに違う値になる。2つが同じであることが要点である。

$ echo "追記" >> hard.txt
$ cat memo.txt
第1版
追記

hard.txt に足したものが memo.txt から読める。ハードリンクは写しではなく、同じ中身に付いた2つ目の名前なので、どちらから書いても同じ1つが変わる。どちらが元でどちらがリンクかという区別も無い。

ふつうこう考える

rm memo.txt でファイルを消せば、その中身はディスクから消える。 hard.txt も同じ中身を指していたのだから、一緒に読めなくなるはずだ。

$ rm memo.txt
$ ls -li hard.txt soft.txt
18128446 -rw-r--r-- 1 lab lab 15 Oct 13 11:43 hard.txt
18128447 lrwxrwxrwx 1 lab lab  8 Oct 13 11:43 soft.txt -> memo.txt
$ cat hard.txt
第1版
追記
だめな理由: 中身は残っていて、hard.txt から全部読める。変わったのはリンク数が 2 から 1 になったことだけである。 rm は「ディレクトリの表から名前を1行消す」操作で（第1章）、中身はリンク数が 0 になったときに初めて片づけられる。 rm の正体は「消す」ではなく「名前を1つ外す」である。
たとえ: 1人の人が、名簿に本名と通称の2行で載っている状態に近い。 どちらの名前で呼んでも同じ1人に届き、片方の行を名簿から消しても、その人はもう1つの名前で呼べる。
ただし崩れる点: 人には本名と通称の区別があるが、ハードリンクの名前はすべて対等で、どれが「元」かは記録されていない。 そして名簿から最後の1行が消えた時点で、その人（中身）も片づけられる。

シンボリックリンクは、道順を書いた別のファイル

この節で分かること: シンボリックリンクが何を中身に持ち、元が消えるとどうなるか。

同じ rm の後で、soft.txt を読む。

$ cat soft.txt
cat: soft.txt: No such file or directory
$ file soft.txt
soft.txt: broken symbolic link to memo.txt

soft.txt は自分の inode 番号を持つ、別のファイルである。中身は memo.txt という道順（パス）の文字列だけで、大きさの 8 は「memo.txt」の8文字である。シンボリックリンクを開くと、カーネルがその道順をたどり直す。道の先の名前が消えたので、壊れたリンクになった。同じ名前でファイルを作り直すと、どうなるか。

$ echo "新しい memo" > memo.txt
$ cat soft.txt
新しい memo
$ ls -li memo.txt hard.txt
18128446 -rw-r--r-- 1 lab lab 15 Oct 13 11:43 hard.txt
18128448 -rw-r--r-- 1 lab lab 15 Oct 13 11:43 memo.txt

soft.txt は新しい memo.txt を読むようになった。道順は名前で書かれているので、その名前に何があるかしか見ない。一方 hard.txt は古い中身（番号 18128446）を指したままで、新しい memo.txt とは別のファイルである。

$ ls -F
hard.txt  memo.txt  soft.txt@
$ ls -i hard.txt
18128446 hard.txt

ls -F は名前の後ろに種類の印を付ける。@ はシンボリックリンク、/ はディレクトリ、* は実行できるファイルである。ハードリンクには印が付かない。普通のファイルと見分けが付かないのが、ハードリンクの性質そのものである（見分けるにはリンク数か inode 番号を見る）。

シンボリックリンクの権限は、いつも lrwxrwxrwx と表示される。

$ touch target; chmod 600 target; ln -s target lnk
$ ls -l target lnk
lrwxrwxrwx 1 lab lab 6 Oct 13 11:43 lnk -> target
-rw------- 1 lab lab 0 Oct 13 11:43 target
$ chmod 644 lnk
$ ls -l target lnk
lrwxrwxrwx 1 lab lab 6 Oct 13 11:43 lnk -> target
-rw-r--r-- 1 lab lab 0 Oct 13 11:43 target

リンクに chmod をかけたのに、変わったのは行き先の target だった。リンク自身の権限は使われず、読み書きできるかどうかは行き先の権限で決まる。lrwxrwxrwx は「誰でも読み書きできる」という意味ではない。

たとえ: 「この書類は 3階の B 棚へ」と書いた案内の付箋に近い。 付箋そのものは書類ではなく、行き方が書いてあるだけ。書類が別の棚へ移されると、付箋は嘘になる。
ただし崩れる点: 付箋は誰が見ても読めるが、たどった先の書類を読めるかどうかは書類の側の鍵で決まる。 lrwxrwxrwx は付箋の見た目で、書類の鍵ではない。

ハードリンクにできないこと

この節で分かること: ハードリンクが作れない2つの場合と、その理由。
$ mkdir d
$ ln d dlink
ln: d: hard link not allowed for directory
$ ln -s d dsoft
$ ls -ld d dsoft
drwxr-xr-x 2 lab lab 4096 Oct 13 11:43 d
lrwxrwxrwx 1 lab lab    1 Oct 13 11:43 dsoft -> d
$ ln ~/.bashrc bashrc-link
ln: failed to create hard link 'bashrc-link' => '/home/lab/.bashrc': Invalid cross-device link
$ ln -s ~/.bashrc bashrc-link
$ ls -l bashrc-link
lrwxrwxrwx 1 lab lab 17 Oct 13 11:43 bashrc-link -> /home/lab/.bashrc
$ df --output=target ~/work/ch7 ~/.bashrc
Mounted on
/home/lab/work
/

ディレクトリにハードリンクは作れない。木の形が崩れて、たどると同じところを回り続ける道ができてしまうからである。そして、別のファイルシステムにあるものにも作れない。inode 番号は1つのファイルシステムの中でしか意味を持たず、~/work（ボリューム）の表から / 側の番号は指せないからである（第4章で mv が番号を変えたのと同じ理由）。シンボリックリンクは道順を文字で書くだけなので、どちらも作れる。

ディレクトリは、ハードリンクを自分で作れない代わりに、システムが自動で名前を足している。

$ stat -c "%h %n" d
2 d
$ mkdir d/a d/b d/c; touch d/f
$ stat -c "%h %n" d
5 d

空のディレクトリのリンク数は 2（親の表にある d と、自分の中の .）で、サブディレクトリを1つ作るごとに、その中の .. の分だけ 1 増える。ファイル（f）は数えない。だから ext4 では「リンク数 − 2 ＝ サブディレクトリの数」になる。ただしこれはファイルシステムの流儀で、法則ではない。

$ stat -c "%h %n" /etc ~
1 /etc
1 /home/lab

檻の / 側は、イメージの層を重ねて見せる overlay というファイルシステムで、複数の層にまたがるディレクトリ（/etc やホームのように、イメージの層と書き込み層の両方に中身があるもの）のリンク数を 1 と報告する。btrfs はすべてのディレクトリで 1 と報告する。あなたの作業ボリュームが btrfs の上にあれば、d も 1 と出る。試験では「2 ＋ サブディレクトリ数」で答えてよい。

ハードリンク（ln）シンボリックリンク（ln -s）根拠にした記録
inode 番号元と同じ自分の番号を持つls -li の1列目
ls -l の見た目元と同じ種類。リンク数が増える種類 l、-> 行き先リンク数の欄が 2（ls -li では inode 番号の分だけ右へずれる）/ soft.txt -> memo.txt
ls -F印なし@soft.txt@
元の名前を消すと中身は残る壊れるcat hard.txt は読め、soft.txt は No such file
ディレクトリ作れない作れるhard link not allowed for directory
別のファイルシステム作れない作れるInvalid cross-device link
権限中身と共有（同じもの）lrwxrwxrwx。行き先の権限が効くchmod 644 lnk で target が変わった

相対パスのリンクは、リンクの置き場所から読む

この節で分かること: 相対パスのシンボリックリンクが、どこを起点にたどられるか。
$ mkdir sub
$ ln -s memo.txt sub/bad
$ ls -l sub/bad
lrwxrwxrwx 1 lab lab 8 Oct 13 11:43 sub/bad -> memo.txt
$ cat sub/bad
cat: sub/bad: No such file or directory
$ ln -s ../memo.txt sub/good
$ cat sub/good
新しい memo
$ ln -sr memo.txt sub/auto
$ ls -l sub/auto
lrwxrwxrwx 1 lab lab 11 Oct 13 11:43 sub/auto -> ../memo.txt

ln -s memo.txt sub/bad は、sub/bad に「memo.txt」という文字をそのまま書く。たどるときの起点はリンクが置かれた場所（sub/）なので、sub/memo.txt を探して見つからない。打ったときにいた場所（~/work/ch7）ではない。../memo.txt と書くか、-r を付けて ln に相対パスを計算させる。絶対パス（/home/lab/...）で書けば起点の問題は無くなるが、ディレクトリごと移したときに壊れる。

バージョン管理 — current を付け替える

この節で分かること: 版の切り替えにシンボリックリンクを使う方法と、ln -sfn が要る理由。

版ごとのディレクトリを並べておき、「いま使う版」をシンボリックリンクで指す形は、ソフトウェアのバージョン管理でよく使われる。切り替えはリンク1本の書き換えで済み、戻すのも同じ1行である。

$ mkdir -p releases/v1 releases/v2; echo 1.0 > releases/v1/VERSION; echo 2.0 > releases/v2/VERSION
$ ln -s releases/v1 current
$ cat current/VERSION
1.0
$ ln -sf releases/v2 current; echo "exit=$?"
exit=0
$ ls -l current
lrwxrwxrwx 1 lab lab 11 Oct 13 11:43 current -> releases/v1
$ ls -l releases/v1
total 4
-rw-r--r-- 1 lab lab  4 Oct 13 11:43 VERSION
lrwxrwxrwx 1 lab lab 11 Oct 13 11:43 v2 -> releases/v2

-f（あれば消してから作る）を付けたのに、current は v1 のままで、releases/v1 の中に v2 というリンクができていた。終了コードは 0 である。ln は最後の引数がディレクトリなら「その中に作れ」と解釈し（cp と同じ規則）、current はディレクトリを指すリンクなので、たどった先のディレクトリとして扱われた。リンクそのものとして扱わせるのが -n である。

$ rm releases/v1/v2
$ ln -sfn releases/v2 current
$ ls -l current
lrwxrwxrwx 1 lab lab 11 Oct 13 11:43 current -> releases/v2
$ cat current/VERSION
2.0

システムの中も、この仕組みであふれている。

$ ls -l /bin /sbin /lib
lrwxrwxrwx 1 root root 7 Apr 22  2024 /bin -> usr/bin
lrwxrwxrwx 1 root root 7 Apr 22  2024 /lib -> usr/lib
lrwxrwxrwx 1 root root 8 Apr 22  2024 /sbin -> usr/sbin
$ ls -li /bin/ls /usr/bin/ls
1859260 -rwxr-xr-x 1 root root 142312 Aug 26 00:09 /bin/ls
1859260 -rwxr-xr-x 1 root root 142312 Aug 26 00:09 /usr/bin/ls
$ ls -l /usr/bin/vi /etc/alternatives/vi
lrwxrwxrwx 1 root root 18 Aug 25 07:13 /etc/alternatives/vi -> /usr/bin/vim.basic
lrwxrwxrwx 1 root root 20 Aug 25 07:13 /usr/bin/vi -> /etc/alternatives/vi
$ readlink -f /usr/bin/vi
/usr/bin/vim.basic

/bin は usr/bin へのシンボリックリンクで、/bin/ls と /usr/bin/ls は同じ1つのファイルである（リンク数は 1。ハードリンクではなく、道が2本あるだけ）。vi は /etc/alternatives/vi を経由する2段のリンクで、真ん中の1本を付け替えると、vi と打ったときに動くエディタが変わる。alternatives という仕組みで（Debian 系は update-alternatives、Red Hat 系は alternatives というコマンドで管理し、どちらも /etc/alternatives を使う）、current と同じ考え方である。

$ ls -li /usr/bin/gunzip /usr/bin/uncompress
1859225 -rwxr-xr-x 2 root root 2346 Jul  3 20:53 /usr/bin/gunzip
1859225 -rwxr-xr-x 2 root root 2346 Jul  3 20:53 /usr/bin/uncompress
$ file /usr/bin/gunzip
/usr/bin/gunzip: POSIX shell script, ASCII text executable
$ grep -n "exec gzip" /usr/bin/gunzip
57:exec gzip -d "$@"
$ ls -li /usr/bin/bzip2 /usr/bin/bunzip2 /usr/bin/bzcat
18229064 -rwxr-xr-x 3 root root 39296 Aug 27 13:05 /usr/bin/bunzip2
18229064 -rwxr-xr-x 3 root root 39296 Aug 27 13:05 /usr/bin/bzcat
18229064 -rwxr-xr-x 3 root root 39296 Aug 27 13:05 /usr/bin/bzip2
$ ls -l /usr/bin/xz /usr/bin/unxz /usr/bin/xzcat
lrwxrwxrwx 1 root root     2 May 29 01:06 /usr/bin/unxz -> xz
-rwxr-xr-x 1 root root 89008 May 29 01:06 /usr/bin/xz
lrwxrwxrwx 1 root root     2 May 29 01:06 /usr/bin/xzcat -> xz

第6章の圧縮コマンドにも、1つの中身に複数の名前が付いている。gunzip は最後に gzip -d を呼ぶだけの小さなシェルスクリプトで、uncompress はそれへのハードリンク（リンク数 2）である。bzip2・bunzip2・bzcat は1つのプログラムにハードリンクで3つの名前（リンク数 3）、unxz と xzcat は xz へのシンボリックリンクで、この2組は呼ばれた名前を見て動きを変える。名前を増やすだけなら、2種類のリンクのどちらでもできる。

たとえ: 受付に掛けた「本日の担当: 田中」の札に近い。 担当が替わるときは札の名前を書き換えるだけで、田中さんの席も鈴木さんの席も動かさない。
ただし崩れる点: 人間は札を掛け替えるとき迷わないが、ln は札（current）が指している先を「部屋」と見なして、 部屋の中に新しい札を置いてしまう。札そのものを掛け替えさせるには -n で「札は札として扱え」と言う必要がある。
手を動かす: 実践編の演習07は、current を releases/v2 に切り替える課題である。 判定は current がリンクのままか、どこへ辿り着くか、releases/ の中に余計なリンクができていないかを見る。
確認

ハードリンクの説明として正しいものを2つ選べ。
a. 元のファイルを削除すると、ハードリンクからも内容を読めなくなる
b. 元のファイルと同じ inode 番号を持つ
c. 別のファイルシステムのファイルに対しても作成できる
d. ディレクトリに対しては作成できない

答え

b と d。ハードリンクは同じ中身へのもう1つの名前なので、inode 番号が同じで、元の名前を消しても中身は残る。 ディレクトリ（hard link not allowed for directory）と、別のファイルシステム（Invalid cross-device link）には作れない。

確認

ln -s /etc/hosts myhosts で作ったリンクについて、ls -l myhosts の先頭10文字と、 /etc/hosts が消えたときに cat myhosts がどうなるかを答えよ。

答え

先頭は lrwxrwxrwx。元が消えると No such file or directory になる（壊れたリンク）。 リンクの中身は道順の文字列だけで、その名前の先に何も無ければたどれない。

確認

ls -F で名前の後ろに付く @・/・* は、それぞれ何を表すか。また、ハードリンクを見分けるには何を見るか。

答え

@ はシンボリックリンク、/ はディレクトリ、* は実行できるファイル。ハードリンクには印が付かないので、 ls -l のリンク数（2 以上か）か、ls -i の inode 番号が他と同じかで見分ける。

確認

ext4 上のディレクトリ proj に、サブディレクトリが3つとファイルが5つある。ls -ld proj のリンク数はいくつか。

答え

5。自分の名前（親の表の proj）と自分の中の . で 2、サブディレクトリの .. が1つずつで 3。ファイルは数えない。 実測でも、サブディレクトリ3つとファイル1つで 5 になった。

この章で分かったこと

持ち帰ってほしいこと

  • ハードリンク（ln）は同じ inode へのもう1つの名前。リンク数が増え、どの名前も対等
  • rm は名前を1つ外すだけ。中身はリンク数が 0 になったときに片づけられる
  • シンボリックリンク（ln -s）は道順を中身に持つ別のファイル。元が消えると壊れ、ls -F では @、ls -l では lrwxrwxrwx ... ->
  • ハードリンクはディレクトリと別のファイルシステムには作れない。シンボリックリンクは作れる
  • 相対パスのリンクは、リンクの置き場所から読まれる（ln -sr で計算させられる）
  • 版の切り替えは ln -sfn 新しい版 current。-n が無いと、古い版の中にリンクができる
