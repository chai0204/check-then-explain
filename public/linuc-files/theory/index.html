理論編 — ファイル・ディレクトリの操作と管理

LinuC レベル1 101 試験・主題1.02（パーミッション・ファイル操作・リンク・検索）を、 全部コンテナの中で実際に打って確かめる8章。 読むだけで終わらせないために、1章ごとに「実際に打つと何が出るか」を先に置いています。

この8章を貫いている1つの事実

ファイルの名前は、ディレクトリの中に書かれた1行にすぎない。権限・所有者・時刻・中身は、名前ではなく inode の側にある。コマンドがどちらを触るかで、結果が決まる。

ディレクトリに r だけ渡すと名前しか見えない。書き込めないファイルでも、ディレクトリに w があれば消せる。 cp は新しい中身を作るので時刻が変わり、mv は名前を書き換えるだけなので変わらない。 rm は名前を外すだけで、ハードリンクがあれば中身は残る。locate は名前の一覧を引くだけなので、消したファイルも出す。 主題1.02 に並ぶ chmod と find と tar と ln は、全部この1つの構造で説明できます。

ここで覚えなくていいこと: ACL（getfacl / setfacl）、ファイルシステムの作り方（mkfs、主題1.05 の範囲）、inode の内部構造、 SELinux。どれも主題1.02 の範囲外で、この8章には出てきません。

章

  1. 名前と中身は、別の場所にある — r だけのディレクトリでは ls -l が ? だらけになる。書き込めないファイルを消せる。1文字目の7種類が何のためにあるか（24分）
  2. umask は引き算ではなく、ビットを落とす印 — umask 033 のファイルは 633 ではなく 644。chmod +w だけは umask を見る（16分）
  3. 特殊なビットは「誰として動くか」と「誰が消せるか」を変える — SUID のスクリプトは lab のまま動く。rm -f でも /tmp の他人のファイルは消せない（20分）
  4. コピーは中身を作り直し、移動は名前を書き換える — cp の写しは 664 が 644 に、時刻がいまに変わる。* は隠しファイルを拾わない（20分）
  5. find は名前をたどり、中身の属性で選ぶ — 36時間前のファイルは -mtime +1 に入らない。引用符を忘れると黙って結果が減る（20分）
  6. tar は束ねるだけで、縮めるのは別のプログラム — 6バイト2つが 10240 バイトになる。gzip は元のファイルを消す（18分）
  7. ハードリンクは名前を増やし、シンボリックリンクは道順を書く — rm しても中身が残る。ln -sf では current が切り替わらない（20分）
  8. locate が探すのは、索引を作った時点の写真 — 消したファイルが出続け、/tmp は何度作り直しても出ない。ここで8章が1本になる（20分）

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの6つに集まります。

場面ここで効く理由見落としやすい点関連する章
他人に自分のファイルを1つだけ読ませる 経路のディレクトリに x だけ渡せば、中を一覧させずに読ませられる 途中のディレクトリ全部に x が要る。1段でも欠けると届かない1
チームの共有ディレクトリを作る SGID でグループを揃え、スティッキービットで他人のファイルを守る グループの札は付いても、作った人の umask 次第で仲間が書けない2・3
設定やデータを控えておく cp -a や tar は権限と時刻ごと残せる cp は所有者を写せない（root 以外）。tar は一般ユーザが展開すると umask がかかる（-p が要る）。中のパスは渡したパスのまま4・6
ディスクの掃除 find -size / -mtime と -delete で条件どおりに消せる 大きさは切り上げ、日数は切り捨て。境界がずれるので、一覧してから消す5
版の切り替え（デプロイ） current のリンク1本で、切り替えも戻しも一瞬で済む ln -sf では切り替わらず、古い版の中にリンクが増える。-n が要る7
「打ったコマンドが思ったものと違う」 type でエイリアスや組み込みを確かめられる which はエイリアスを知らない。locate は今日のファイルを知らない8
