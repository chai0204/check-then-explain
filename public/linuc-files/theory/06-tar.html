6. tar は束ねるだけで、縮めるのは別のプログラム

6バイトのファイル2つを tar で1つにまとめると、10240 バイトになった。tar は名前と属性と中身を1本に並べるだけで、縮めはしない。縮めるのは gzip・bzip2・xz で、そのうえ gzip は元のファイルを消して置き換える。

前提: 第5章まで読了前提: 檻が起動している所要 18分影響度 B出題範囲 1.02.2（重要度3）最終検証 2026-10-13

この章のゴール

  • tar のオプション（c・x・t・z・j・J・v・f・C）を組み合わせて、作る・一覧する・展開するを書ける
  • gzip・bzip2・xz の圧縮・展開・中を見るコマンドを、対応表なしで言える
  • dd が何をどの単位で写すかを、出力の読み方とともに説明できる
ここで覚えなくていいこと: cpio、zip/unzip、zstd、tar の増分バックアップ（-g）、圧縮率と速度の細かい比較は扱わない。dd でディスクそのものを写す手順は、この檻にディスクが無いので理論として読むだけでよい。

tar は縮めない

この節で分かること: tar が作る1本のファイルに、何が入っているか。

この章は ~/work/ch6 で作業する。6バイトのファイルを2つ作って、tar でまとめる。

$ mkdir -p ~/work/ch6
$ cd ~/work/ch6
$ echo hello > a.txt; echo world > b.txt
$ ls -l a.txt b.txt
-rw-r--r-- 1 lab lab 6 Oct 13 11:43 a.txt
-rw-r--r-- 1 lab lab 6 Oct 13 11:43 b.txt

ふつうこう考える

tar は「まとめて小さくする」ためのコマンドだ。2つで 12 バイトなら、まとめれば 12 バイト以下になるはずだ。

$ tar -cvf small.tar a.txt b.txt
a.txt
b.txt
$ ls -l small.tar
-rw-r--r-- 1 lab lab 10240 Oct 13 11:43 small.tar
だめな理由: 12 バイトが 10240 バイトになった。tar は圧縮しない。ファイル1つごとに 512 バイトの見出し（名前・権限・所有者・大きさ・時刻）を付け、 中身を 512 バイト単位に詰めて並べ、最後に 10240 バイト単位に切りそろえる。 「たくさんのファイルを、属性ごと1本のファイルにする」のが tar の仕事で、縮めるのは別のプログラムである。
$ tar -tvf small.tar
-rw-r--r-- lab/lab           6 2026-10-13 11:43 a.txt
-rw-r--r-- lab/lab           6 2026-10-13 11:43 b.txt

-t で中を一覧すると、ls -l とほとんど同じ情報が並ぶ。権限・所有者・時刻は、第1章で見た「名前の先」にある情報で、tar はそれを名前と一緒に記録している。ただし展開したときに記録どおりに戻るかどうかは、誰が展開するかで変わる（この章の後半で確かめる）。

ハイフンを省いた古い書き方も、GNU tar では同じ意味で通る。試験の選択肢にもこの形で出る。

$ tar tvf small.tar
-rw-r--r-- lab/lab           6 2026-10-13 11:43 a.txt
-rw-r--r-- lab/lab           6 2026-10-13 11:43 b.txt
オプション意味
c / t / x作る（create）/ 一覧する（list）/ 展開する（extract）。どれか1つ
f アーカイブ名アーカイブのファイル名。直後に名前が来るので、まとめて書くときは最後に置く（-cvf small.tar）
v処理した名前を表示する（t と組むと ls -l 風になる）
z / j / Jgzip / bzip2 / xz を通す（次の次の節）
C ディレクトリそのディレクトリに移ってから処理する（展開先の指定に使う）
p展開するとき、記録された権限をそのまま戻す（root では最初からそう動く。後の節）
たとえ: 引っ越しの段ボールに、荷札を付けて品物を詰める作業に近い。 荷札には品名だけでなく、持ち主や取り扱い注意の印も書く。箱と荷札の分だけ、荷物は少し重くなる。
ただし崩れる点: 段ボールは品物の数に合わせて大きさを選べるが、tar の箱は 10240 バイト単位でしか作れない。 6 バイトの品物2つでも、最小の箱1つ分の大きさになる。

gzip は元のファイルを置き換える

この節で分かること: 圧縮コマンドが元のファイルをどう扱うか。
$ seq 1 2000 > num.txt
$ ls -l num.txt
-rw-r--r-- 1 lab lab 8893 Oct 13 11:43 num.txt
$ gzip num.txt
$ ls -l num.txt*
-rw-r--r-- 1 lab lab 4226 Oct 13 11:43 num.txt.gz
$ gzip -l num.txt.gz
         compressed        uncompressed  ratio uncompressed_name
               4226                8893  52.8% num.txt

gzip の後には num.txt.gz しか無い。元の num.txt は消えた。gzip は「圧縮した写しを作る」のではなく、圧縮したものに置き換える。展開する gunzip も同じで、.gz を消して元の名前に戻す。

$ gunzip num.txt.gz
$ ls -l num.txt*
-rw-r--r-- 1 lab lab 8893 Oct 13 11:43 num.txt
$ gzip -k num.txt
$ ls -l num.txt*
-rw-r--r-- 1 lab lab 8893 Oct 13 11:43 num.txt
-rw-r--r-- 1 lab lab 4226 Oct 13 11:43 num.txt.gz
$ zcat num.txt.gz | tail -1
2000
$ gzip num.txt
gzip: num.txt.gz already exists; do you wish to overwrite (y or n)? n
	not overwritten

元を残したいときは -k（keep）を付けるか、gzip -c num.txt > num.txt.gz のように標準出力へ出して自分で受ける。zcat は展開した中身を画面に出すだけで、ファイルは変えない。すでに .gz があると、上書きしてよいかを聞いてくる（n は自分で打つ）。

bzip2 と xz も、使い方は同じ形である。

$ bzip2 -k num.txt; xz -k num.txt
$ ls -l num.txt*
-rw-r--r-- 1 lab lab 8893 Oct 13 11:43 num.txt
-rw-r--r-- 1 lab lab 2140 Oct 13 11:43 num.txt.bz2
-rw-r--r-- 1 lab lab 4226 Oct 13 11:43 num.txt.gz
-rw-r--r-- 1 lab lab  948 Oct 13 11:43 num.txt.xz
$ bzcat num.txt.bz2 | tail -1; xzcat num.txt.xz | tail -1
2000
2000
$ rm num.txt num.txt.gz
$ bunzip2 num.txt.bz2
$ ls -l num.txt*
-rw-r--r-- 1 lab lab 8893 Oct 13 11:43 num.txt
-rw-r--r-- 1 lab lab  948 Oct 13 11:43 num.txt.xz
$ rm num.txt
$ unxz num.txt.xz
$ ls -l num.txt*
-rw-r--r-- 1 lab lab 8893 Oct 13 11:43 num.txt
形式圧縮展開中を見る拡張子tar の文字8893 バイトが（実測）
gzipgzipgunzip / gzip -dzcat.gzz4226
bzip2bzip2bunzip2 / bzip2 -dbzcat.bz2j2140
xzxzunxz / xz -dxzcat.xzJ948

どれも1つのファイルを1つの圧縮ファイルにする道具で、ディレクトリを1本にまとめることはしない。

$ mkdir -p notes/2026; cp num.txt notes/2026/log.txt
$ gzip notes
gzip: notes is a directory -- ignored
$ gzip -r notes
$ find notes | sort
notes
notes/2026
notes/2026/log.txt.gz
$ gunzip -r notes
$ find notes | sort
notes
notes/2026
notes/2026/log.txt
$ bzip2 -r notes
bzip2: Bad flag `-r'
（略）
$ xz -r notes
xz: Try `xz --help' for more information.

gzip には -r（再帰）があり、ディレクトリの中のファイルを1つずつ圧縮する（gunzip -r で戻せる）。それでも .gz がファイルの数だけできるだけで、1本にはならない。bzip2 と xz には -r が無く、bzip2 は Bad flag と言って使い方を並べ（ここでは略した）、xz も断った。だから「束ねる tar」と「縮める gzip など」は組で使われる。

もう1つ、gunzip は名前の終わりも見る。

$ gzip -c num.txt > packed
$ file packed
packed: gzip compressed data, was "num.txt", last modified: Tue Oct 13 02:43:13 2026, from Unix, original size modulo 2^32 8893
$ gunzip packed
gzip: packed: unknown suffix -- ignored
$ ls packed*
packed

中身は gzip だと file が言っているのに、gunzip は展開しなかった。展開した後の名前を「.gz などの決まった拡張子を外した名前」で作るので、拡張子が無いと名前を決められないからである。第4章で「拡張子は人間のための目印」と書いたのは file とカーネルにとっての話で、拡張子を見るプログラムもある。

たとえ: 衣類を真空パックの袋に詰め替える作業に近い。 詰め替えた後に、元の畳んだ衣類が棚に残っているわけではない。中身は袋の中に移っている。
ただし崩れる点: 真空パックは中身を出せば袋が空で残るが、gunzip は袋（.gz）ごと消して元に戻す。 どちらの向きも「置き換え」で、両方を残すには -k が要る。

tar の z・j・J — 束ねて縮めるを1回で

この節で分かること: 圧縮つきのアーカイブの作り方・確かめ方・展開のしかた。
$ tar -czvf notes.tar.gz notes
notes/
notes/2026/
notes/2026/log.txt
$ tar -cjf notes.tar.bz2 notes
$ tar -cJf notes.tar.xz notes
$ ls -l notes.tar.*
-rw-r--r-- 1 lab lab 2462 Oct 13 11:43 notes.tar.bz2
-rw-r--r-- 1 lab lab 4472 Oct 13 11:43 notes.tar.gz
-rw-r--r-- 1 lab lab 1136 Oct 13 11:43 notes.tar.xz
$ file notes.tar.gz notes.tar.bz2 notes.tar.xz
notes.tar.gz:  gzip compressed data, from Unix, original size modulo 2^32 20480
notes.tar.bz2: bzip2 compressed data, block size = 900k
notes.tar.xz:  XZ compressed data, checksum CRC64

file が言う「original size 20480」が、縮める前の tar の大きさである。tar の中には作った時刻が入るので、あなたが作ると圧縮後の大きさは少し違う（著者が記録を取り直すたびに、数十バイトずつ変わった）。一覧は t に同じ文字を添える。

$ tar -tzf notes.tar.gz
notes/
notes/2026/
notes/2026/log.txt
$ tar -tjf notes.tar.bz2
notes/
notes/2026/
notes/2026/log.txt
$ tar -tJf notes.tar.xz
notes/
notes/2026/
notes/2026/log.txt
$ tar -tzf notes.tar.xz

gzip: stdin: not in gzip format
tar: Child returned status 1
tar: Error is not recoverable: exiting now
$ tar -tf notes.tar.xz
notes/
notes/2026/
notes/2026/log.txt

文字を間違えると、tar は言われたとおり gzip を呼び、gzip が「gzip 形式ではない」と断る。一方、文字を省くと GNU tar は中身を見て形式を自分で判断した。読むとき（t・x）だけのことで、作るとき（c）は文字を書かないと圧縮されない。試験では z・j・J を書き分ける形で問われる。

$ mkdir out
$ tar -xzvf notes.tar.gz -C out
notes/
notes/2026/
notes/2026/log.txt
$ ls -R out
out:
notes

out/notes:
2026

out/notes/2026:
log.txt
$ mkdir out2
$ tar -xjf notes.tar.bz2 -C out2
$ cat out2/notes/2026/log.txt | wc -l
2000

-C は展開先を決める。中に記録されているパス（notes/...）が、展開先の下にそのまま掘られる。では、作るときに絶対パスを渡すとどうなるか。

$ tar -czf abs.tar.gz ~/work/ch6/a.txt
tar: Removing leading `/' from member names
$ tar -tzf abs.tar.gz
home/lab/work/ch6/a.txt

先頭の / だけが外され、残りのパスがそのまま記録された。外さないと、展開した人のシステムの /home/... を上書きしかねないからである。代わりに、展開すると展開先に home/lab/work/ch6/ が掘られる。アーカイブの中のパスは、作るときにどう渡したかで決まる。

手を動かす: 実践編の演習06は、project/ を xz で圧縮した project.tar.xz にまとめる課題である。 判定はアーカイブを xz -t で実際に検査し、一覧と展開をして元のディレクトリと比べる。 名前だけ .xz にしたものや、中のパスが home/lab/... で始まるものは通らない。

展開したとき、権限と所有者は戻るか

この節で分かること: 一般ユーザと root で、展開した結果の権限と所有者が違うこと。

誰でも書ける（666）alice のファイルを束ねて、3通りに展開する。

$ echo "誰でも書ける" > shared.txt
$ chmod 666 shared.txt
$ sudo chown alice shared.txt
$ ls -l shared.txt
-rw-rw-rw- 1 alice lab 19 Oct 13 11:43 shared.txt
$ tar -cf shared.tar shared.txt
$ tar -tvf shared.tar
-rw-rw-rw- alice/lab        19 2026-10-13 11:43 shared.txt
$ mkdir x1 x2 x3
$ tar -xf shared.tar -C x1
$ tar -xpf shared.tar -C x2
$ sudo tar -xf shared.tar -C x3
$ ls -l x1/shared.txt x2/shared.txt x3/shared.txt
-rw-r--r-- 1 lab   lab 19 Oct 13 11:43 x1/shared.txt
-rw-rw-rw- 1 lab   lab 19 Oct 13 11:43 x2/shared.txt
-rw-rw-rw- 1 alice lab 19 Oct 13 11:43 x3/shared.txt

アーカイブには 666 と alice が記録されているのに、一般ユーザの lab が -xf で展開すると 644 になった。展開は「ファイルを新しく作る」操作なので、第2章の umask がかかる（第4章の cp と同じ理由）。-p（--preserve-permissions）を足すと、記録された 666 がそのまま戻った。所有者はどちらも lab のままで、alice に戻ったのは root で展開したときだけである。root では権限の復元も所有者の復元も最初から有効で、一般ユーザは所有者を他人にできない（第3章）。

展開のしかた権限所有者実測
一般ユーザが tar -xf記録から umask を落としたもの展開した自分x1: 644・lab
一般ユーザが tar -xpf記録どおり展開した自分x2: 666・lab
root が tar -xf記録どおり記録どおりx3: 666・alice

更新時刻は、どの場合も記録された時刻で戻すのが GNU tar の既定である（ここでは作った直後に展開したので、見分けは付かない）。バックアップを戻すときに「権限が変わった」と言われたら、まず誰が -p 無しで展開したかを疑う。

dd はバイト列をそのまま写す

この節で分かること: dd の if・of・bs・count と、出力の読み方。
$ dd if=/dev/zero of=zero.img bs=1M count=4
4+0 records in
4+0 records out
4194304 bytes (4.2 MB, 4.0 MiB) copied, 0.00134678 s, 3.1 GB/s
$ ls -l zero.img
-rw-r--r-- 1 lab lab 4194304 Oct 13 11:43 zero.img
$ dd if=num.txt of=head.bin bs=512 count=1
1+0 records in
1+0 records out
512 bytes copied, 2.1249e-05 s, 24.1 MB/s
$ ls -l head.bin
-rw-r--r-- 1 lab lab 512 Oct 13 11:43 head.bin
$ head -3 head.bin
1
2
3

dd は if=（入力）から bs=（1回に読む大きさ）ずつ count= 回読んで、of=（出力）へ書く。中身の意味を一切解釈せず、バイト列を区切りどおりに写す。4+0 records in は「満杯のブロックを4回、端数のブロックを0回読んだ」という意味である。最後の行の秒数と速度は、打つたびに変わる。

中身を解釈しないので、dd はファイルシステムを持たない相手、つまり第1章のブロックデバイスを丸ごと写すのに使われる。

dd if=/dev/sda of=mbr.img bs=512 count=1     ディスクの先頭 512 バイト（MBR）を写し取る
dd if=/dev/sda of=disk.img bs=4M             ディスク全体をイメージファイルにする
dd if=disk.img of=/dev/sdb bs=4M             イメージを別のディスクに書き戻す（相手の中身は全部消える）

この檻にはディスクの装置が無いので、これらは打てない（第1章で b が 0 個だった）。of= に装置を書くと、確認なしで中身を上書きする。実機で試すときは、if= と of= を取り違えていないかを必ず読み返す。変換もできる。

$ echo hello | dd conv=ucase 2>/dev/null
HELLO
たとえ: 原稿を読まずに、決まった枚数ずつ機械的に写すコピー機に近い。 何が書いてあるかを理解しないので、白紙でも、読めない文字でも、同じように写す。
ただし崩れる点: コピー機は原稿を傷めないが、dd は出力先を確認なしで上書きする。 入力と出力を取り違えると、写したかった原本のほうが消える。
確認

bzip2 で圧縮された backup.tar.bz2 を、/tmp の下に展開するコマンドを書け。 また、一般ユーザが展開するときに、アーカイブに記録された権限どおりに戻すには、何を足すか。

答え

tar -xjf backup.tar.bz2 -C /tmp。x で展開、j で bzip2、f の直後にアーカイブ名、-C で展開先。 gzip なら z、xz なら J（大文字）。記録どおりの権限にするには p を足す（tar -xjpf backup.tar.bz2 -C /tmp）。 足さないと umask を落とした権限になる（実測: 666 が 644 になった）。

確認

アーカイブ data.tar.gz を展開せずに、中のファイルを権限や大きさ付きで一覧するには。

答え

tar -tvzf data.tar.gz（-tzvf などの順でもよいが、f の直後はアーカイブ名）。 t が一覧、v が詳しく。読むときは GNU tar が形式を判断するので tar -tvf data.tar.gz でも読める。

確認

gzip report.txt を実行した後、カレントディレクトリにあるのはどれか。
a. report.txt だけ　b. report.txt.gz だけ　c. 両方　d. どちらも無い

答え

b。gzip は元のファイルを圧縮したものに置き換える（実測）。両方残すには gzip -k report.txt か gzip -c report.txt > report.txt.gz。

確認

中身が全部 0 の、1MiB × 10 個ぶん（10MiB）のファイル blank.img を作る dd のコマンドを書け。

答え

dd if=/dev/zero of=blank.img bs=1M count=10。/dev/zero は第1章のスペシャルファイルで、読むと 0 を返し続ける。

この章で分かったこと

持ち帰ってほしいこと

  • tar は束ねるだけで縮めない。名前と一緒に権限・所有者・時刻を記録する（6バイト×2が 10240 バイトになった）
  • tar は c（作る）・t（一覧）・x（展開）のどれか ＋ f（直後にアーカイブ名）。v で詳しく、C で場所を指定
  • z = gzip、j = bzip2、J = xz。読むときは GNU tar が形式を判断するが、作るときは文字が要る
  • gzip・bzip2・xz は元のファイルを置き換える。残すなら -k。展開は gunzip・bunzip2・unxz（または -d）、中を見るのは zcat・bzcat・xzcat
  • アーカイブの中のパスは、作るときの渡し方で決まる。先頭の / は外される
  • 一般ユーザが展開すると権限に umask がかかる。記録どおりに戻すには -p。所有者まで戻るのは root で展開したときだけ
  • dd は if から bs ずつ count 回読んで of へ写す。中身を解釈しないので、ディスクの装置をそのまま写せる
