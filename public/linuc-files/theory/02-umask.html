2. umask は引き算ではなく、ビットを落とす印

umask 033 のもとで作ったファイルは、666 − 033 = 633 にはならず 644 で作られる。umask は「新しく作るときに落とすビット」の印で、数の引き算ではない。そして作られた後の chmod には、1つの書き方を除いて効かない。

この章のゴールと前提所要 16分
前提: 第1章まで読了前提: 檻が起動している所要 16分影響度 B出題範囲 1.02.1（重要度3）最終検証 2026-10-13

この章のゴール

  • chmod の数値の書き方と記号の書き方を、相互に読み替えられる
  • umask の値から、新しいファイルとディレクトリのパーミッションをビットで求められる
  • umask がどこで決まり、どこに書けば次のシェルでも効くかを言える
ここで覚えなくていいこと: pam_umask の細かいオプション、ACL の既定値（default ACL）、mount の umask= オプション（FAT など Linux の権限を持たないファイルシステム用）は扱わない。umask の中身を2進数で暗記する必要もない。1桁ずつ rwx に分けて読めれば足りる。

chmod の2つの書き方

この節で分かること: 数値（640）と記号（u=rw,g=r）が同じものを指す仕組み。

この章は ~/work/ch2 で作業する。chmod には、全部を数で言い切る書き方と、差分を記号で言う書き方がある。

$ mkdir -p ~/work/ch2
$ cd ~/work/ch2
$ touch f.txt
$ chmod 640 f.txt
$ ls -l f.txt
-rw-r----- 1 lab lab 0 Oct 13 11:43 f.txt
$ chmod u=rwx,g=rx,o= f.txt
$ ls -l f.txt
-rwxr-x--- 1 lab lab 0 Oct 13 11:43 f.txt
$ chmod g+w,o+r f.txt
$ ls -l f.txt
-rwxrwxr-- 1 lab lab 0 Oct 13 11:43 f.txt
$ chmod a-x f.txt
$ ls -l f.txt
-rw-rw-r-- 1 lab lab 0 Oct 13 11:43 f.txt
$ stat -c "%a %A %n" f.txt
664 -rw-rw-r-- f.txt

数値は 8 進数で、1桁が rwx の3ビットに当たる。r=4、w=2、x=1 を足したものが1桁になる。

-rw-r-----  →  rw- r-- ---  →  4+2+0  4+0+0  0+0+0  →  640
-rwxr-x---  →  rwx r-x ---  →  4+2+1  4+0+1  0+0+0  →  750
記号の部品意味
u g o a所有者 / グループ / その他 / 全員
+ - =足す / 外す / ちょうどこれにする（指定した相手の rwx を、書いたものだけにする）
r w x読む / 書く / 実行（ディレクトリなら通り抜け）
,複数の指定を並べる（u=rwx,g=rx,o=）

-R を付けると、ディレクトリの下にあるもの全部に同じ変更をかける。

$ mkdir -p tree/sub
$ touch tree/a tree/sub/b
$ chmod -R go-rwx tree
$ stat -c "%A %n" tree tree/a tree/sub tree/sub/b
drwx------ tree
-rw------- tree/a
drwx------ tree/sub
-rw------- tree/sub/b
たとえ: 数値は「全部の欄を書き直す申請書」、記号は「訂正したい欄だけ書く訂正届」に近い。 chmod 640 は元が何であっても 640 にし（ディレクトリの SUID・SGID だけは例外で、数値では外れない。第3章）、chmod g+w はグループの w だけを足して残りに触らない。
ただし崩れる点: 役所は申請書も訂正届も同じ規則で処理するが、chmod は違う。 記号の書き方で「誰に」を省くと、その人の umask を見て結果を変える（2つ先の節）。数値の書き方には、この例外が無い。

umask は落とすビットの印

この節で分かること: 新しく作られるファイルの権限が、どこから来ているか。
$ umask
0022
$ umask -S
u=rwx,g=rx,o=rx
$ touch new.txt
$ mkdir new.d
$ ls -ld new.txt new.d
drwxr-xr-x 2 lab lab 4096 Oct 13 11:43 new.d
-rw-r--r-- 1 lab lab    0 Oct 13 11:43 new.txt

作るプログラム（touch や mkdir）は、ファイルなら 666、ディレクトリなら 777 を要求する。そこから umask に立っているビットが落とされて、644 と 755 になった。umask -S は、落とした後に残るほうを記号で見せる。

666 − 022 = 644、777 − 022 = 755。引き算と同じ答えなので、こう覚えている人は多い。値を変えて試す。

ふつうこう考える

umask は、666（ディレクトリなら 777）から引く数である。umask を 033 にすれば、 ファイルは 666 − 033 = 633、ディレクトリは 777 − 033 = 744 で作られるはずだ。

$ umask 033
$ touch u033.txt
$ mkdir u033.d
$ ls -ld u033.txt u033.d
drwxr--r-- 2 lab lab 4096 Oct 13 11:43 u033.d
-rw-r--r-- 1 lab lab    0 Oct 13 11:43 u033.txt
$ stat -c "%a %n" u033.txt u033.d
644 u033.txt
744 u033.d
だめな理由: ディレクトリは予想どおり 744 だが、ファイルは 633 ではなく 644 になった。 umask は数ではなく「このビットは渡さない」という印で、桁ごとに rwx を照らし合わせて、印のあるビットを落とす。 3 は -wx なので、グループとその他から w と x を落とす。ファイルの 6（rw-）には最初から x が無いので、 落とせるのは w だけで、残りは r-- = 4 になる。引き算は「無いものまで引いて」しまうので答えがずれる。
ファイル     6 = rw-      ディレクトリ  7 = rwx
umask の桁   3 = -wx      umask の桁    3 = -wx
残る         4 = r--      残る          4 = r--

よく使う3つの値も、同じ規則で決まる。

$ umask 027
$ touch u027.txt
$ mkdir u027.d
$ stat -c "%a %n" u027.txt u027.d
640 u027.txt
750 u027.d
$ umask 077
$ touch u077.txt
$ mkdir u077.d
$ stat -c "%a %n" u077.txt u077.d
600 u077.txt
700 u077.d
umaskファイル（666 から）ディレクトリ（777 から）引き算で考えると
022644 rw-r--r--755 rwxr-xr-x644 / 755（偶然一致）
027640 rw-r-----750 rwxr-x---ファイルの最後の桁が 6 − 7 で破綻
077600 rw-------700 rwx------ファイルが 6 − 7 で破綻
033644 rw-r--r--744 rwxr--r--633 と外れる

試験では「umask が 027 のとき作られるファイル」のように問われる。迷ったら1桁ずつ rwx に開いて、印のあるビットを消せばよい。なお、試験の例題の解説は「666 から umask を引く」と書くことが多い。umask の各桁が 0・2・4・6（x のビットを含まない）なら、ファイルでも引き算と同じ答えになる（ディレクトリは 777 から引くので、いつでも同じになる）。答えがずれるのは、033 や 027 のように umask の桁に奇数（1・3・5・7）があるときの、ファイルの計算だけである。

たとえ: 型紙に貼るマスキングテープに近い。 666 という色を吹き付けるとき、テープを貼った場所（umask のビット）には色が付かない。 もともと色を吹かない場所（ファイルの x）にテープを貼っても、何も起きない。
ただし崩れる点: テープは吹き付ける瞬間にしか効かない。乾いた後に chmod で塗り直せば、 テープの位置に関係なく色が付く（次の節）。

chmod は umask を見ない。ただし1つの書き方だけ見る

この節で分かること: umask が作った後の変更に効く場合と、効かない場合。

umask が 077 のまま、数値で 777 にする。

$ chmod 777 u077.txt
$ stat -c "%a %n" u077.txt
777 u077.txt

umask は関係なく 777 になった。数値の chmod は言われたとおりに書く（例外は、ディレクトリの SUID・SGID を数値では外さないことだけ。第3章で確かめる）。ところが umask を 022 に戻し、記号で「誰に」を省くと様子が変わる。

$ umask 022
$ chmod 444 f.txt
$ chmod +w f.txt
$ ls -l f.txt
-rw-r--r-- 1 lab lab 0 Oct 13 11:43 f.txt
$ chmod a+w f.txt
$ ls -l f.txt
-rw-rw-rw- 1 lab lab 0 Oct 13 11:43 f.txt

chmod +w は「全員に w」ではなく、所有者にしか足さなかった。u g o a を書かないと、chmod は a と書いたつもりで動きつつ、umask に立っているビットには触らない（man chmod に書いてある規則）。umask 022 はグループとその他の w を落とす印なので、触れたのは所有者の w だけである。全員に足したいなら a+w と書く。外すほうも同じである。

$ chmod -w f.txt
chmod: f.txt: new permissions are r--rw-rw-, not r--r--r--
$ ls -l f.txt
-r--rw-rw- 1 lab lab 0 Oct 13 11:43 f.txt
$ chmod a-w f.txt
$ ls -l f.txt
-r--r--r-- 1 lab lab 0 Oct 13 11:43 f.txt

chmod -w は所有者の w しか外さず、chmod 自身が「r--r--r-- にはならず r--rw-rw- になった」と警告した。グループとその他の w は umask に守られて残っている。試験で「全員の書き込みを禁止する」を問われたら、a-w（か ugo-w）と「誰に」を書いたものを選ぶ。

umask はどこから来るか

この節で分かること: umask がプロセスごとの値であり、どこに書けば次のシェルでも効くか。

umask はファイルの属性ではなく、動いているプロセスが持つ値で、子のプロセスにそのまま受け継がれる。

$ umask 027
$ bash -c umask
0027
$ umask 022
$ bash -c umask
0022

いまのシェルで変えた値は、そこから起動したシェルにも渡る。逆に言えば、いまのシェルで打った umask 027 は、ログインし直したシェル（親から受け継がないシェル）には効かない。ログインのたびに決め直されるからである。

$ sudo -u alice bash -c umask
0002
$ grep -E "^(UMASK|USERGROUPS_ENAB)" /etc/login.defs
UMASK		022
USERGROUPS_ENAB yes

sudo で alice として動かしたシェルは 0002 だった。sudo はログインと同じく PAM を通り、pam_umask が /etc/login.defs の UMASK 022 を使う。さらに USERGROUPS_ENAB yes なので、ユーザ名と同じ名前の主グループを持つユーザ（alice の主グループ alice には、alice 1人しかいない）には、グループの w を残した 0002 を設定する。自分専用のグループなら、グループに書かせても困らないからである。

自分のシェルで毎回同じ umask にしたいときは、起動時に読まれるファイルに書く。

$ grep -n umask ~/.profile
7:# the default umask is set in /etc/profile; for setting the umask
8:# for ssh logins, install and configure the libpam-umask package.
9:#umask 022
$ grep -n bashrc ~/.profile
13:    # include .bashrc if it exists
14:    if [ -f "$HOME/.bashrc" ]; then
15:	. "$HOME/.bashrc"
書く場所効く範囲
~/.bashrc自分の対話シェル（起動するたびに読まれる）
~/.profile（~/.bash_profile）自分のログインシェル。Ubuntu の ~/.profile は中で ~/.bashrc も読む
/etc/profile全ユーザのログインシェル
/etc/login.defs の UMASKPAM（pam_umask）がログイン時に設定する既定値

この檻で umask が 0022 なのは、docker run がコンテナの最初のプロセスに 0022 を与えるからで、PAM を通っていない。著者が確かめたところ、別の端末から docker exec で同じコンテナに入ったシェルは umask が 0000 で、touch したファイルが -rw-rw-rw- になった（docker 29.8.0）。この教材は2つ目の端末を使わない前提で記録してある。開くなら、最初に umask 022 を打ってほしい。

たとえ: 家ごとに受け継がれる家訓に近い。 子は親の家訓をそのまま持って家を出て、自分の家で書き換えてもよいが、親の家訓は変えられない。
ただし崩れる点: 家訓は口で伝わるが、umask は書かれた場所（~/.bashrc など）から読み直されることもある。 ログインし直したシェルは親から受け継がず、そのファイルを読んで決め直す。
手を動かす: 実践編の演習02は、「次に開くシェルでも」ファイルが 640、ディレクトリが 750 で作られるようにする課題である。 判定は umask を 0022 に戻してから新しいログインシェルを起動し、その中で実際に作って確かめる。 いまのシェルで umask 027 と打つだけでは通らない。
確認

umask が 027 のとき、touch で作られるファイルと、mkdir で作られるディレクトリのパーミッションを答えよ。

答え

ファイルは 640（-rw-r-----）、ディレクトリは 750（drwxr-x---）。 666 と 777 から、グループの w（2）とその他の rwx（7）を落とす。実測の記録どおりである。

確認

chmod u=rwx,g=rx,o=r file と同じ結果になる数値の指定はどれか。
a. 751　b. 754　c. 755　d. 764

答え

b。u=rwx は 4+2+1=7、g=rx は 4+1=5、o=r は 4。

確認

umask が 022 のシェルで、-r--r--r-- のファイルに chmod +w を打った。結果はどうなるか。

答え

-rw-r--r--。「誰に」を省いた記号指定は、umask に立っているビット（グループとその他の w）に触らない（chmod -w で外すときも同じ）。 全員に足すなら chmod a+w と書く。数値の chmod 666 も umask に関係なく 666 になる。

確認

いまのシェルで umask 077 と打った。この設定を、次にログインしたときにも効かせるにはどうするか。

答え

~/.bashrc か ~/.profile に umask 077 を書く（全ユーザなら /etc/profile）。 umask はプロセスごとの値で、ログインし直したシェルは起動時に読むファイルから決め直すので、 打っただけの値は残らない。

この章で分かったこと

持ち帰ってほしいこと

  • chmod の数値は r=4・w=2・x=1 の足し算を3桁並べたもの。記号は u g o a × + - = × r w x
  • 新しいファイルは 666、ディレクトリは 777 から、umask に立っているビットを落として作られる
  • 引き算ではない。umask 033 のファイルは 633 ではなく 644（実測）
  • umask で値を、umask -S で残る権限を記号で見る
  • 数値の chmod は umask を見ない。「誰に」を省いた記号指定（chmod +w・chmod -w）だけは、umask に立っているビットに触らない
  • umask はプロセスの値で、子に受け継がれる。毎回効かせるなら ~/.bashrc・~/.profile・/etc/profile（PAM なら /etc/login.defs の UMASK）
