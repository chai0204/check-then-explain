4. コピーは中身を作り直し、移動は名前を書き換える

cp で作った写しは、中身が同じでも権限は 664 から 644 に、時刻は写した瞬間に変わった。cp は新しい中身を1つ作る操作で、mv は同じファイルシステムの中なら名前の行を書き換えるだけだからだ。ワイルドカードも同じ目で見ると、広げているのが誰なのかが分かる。

前提: 第3章まで読了前提: 檻が起動している所要 20分影響度 B出題範囲 1.02.2（重要度3）最終検証 2026-10-13

この章のゴール

  • cp の写しで変わるもの（所有者・権限・時刻）と、それを保つオプションを言える
  • mv が中身を動かさない場合と、動かす場合を区別できる
  • ワイルドカードを広げているのがシェルだと分かり、一致しないときの動きを予想できる
ここで覚えなくていいこと: rsync、cp --reflink、install コマンド、shopt でグロブの挙動を変える方法（dotglob・nullglob・extglob）は扱わない。正規表現（grep のパターン）はワイルドカードとは別物で、主題1.03 の範囲である。

cp は新しいファイルを作る

この節で分かること: cp の写しで、何が元と変わるか。

この章は ~/work/ch4 で作業する。権限と時刻にはっきりした印を付けた元ファイルを作る。

$ mkdir -p ~/work/ch4
$ cd ~/work/ch4
$ echo "元の中身" > orig.txt
$ chmod 664 orig.txt
$ touch -d "2025-04-01 09:00" orig.txt
$ ls -l --time-style=long-iso orig.txt
-rw-rw-r-- 1 lab lab 13 2025-04-01 09:00 orig.txt

--time-style=long-iso は時刻を年から表示させるだけのオプションで、意味は変わらない。

ふつうこう考える

cp はファイルを複製するコマンドだから、写しは元と同じもの（中身も、権限も、時刻も）になるはずだ。

$ cp orig.txt copy.txt
$ ls -l --time-style=long-iso orig.txt copy.txt
-rw-r--r-- 1 lab lab 13 2026-10-13 11:43 copy.txt
-rw-rw-r-- 1 lab lab 13 2025-04-01 09:00 orig.txt
だめな理由: 中身は同じだが、時刻は写した瞬間になり、権限は rw-rw-r-- から rw-r--r-- に減った。 cp は元を見ながら新しいファイルを1つ作る。新しく作るので、時刻は作った時刻になり、 権限は「元の権限から umask のビットを落としたもの」になる（第2章の規則がここでも効く。umask 022 がグループの w を落とした）。 「同じものを作る」のではなく「同じ中身の新しいものを作る」と読む。

元の時刻と権限を写したいときは -p（preserve）を付ける。

$ cp -p orig.txt keep.txt
$ ls -l --time-style=long-iso orig.txt keep.txt
-rw-rw-r-- 1 lab lab 13 2025-04-01 09:00 keep.txt
-rw-rw-r-- 1 lab lab 13 2025-04-01 09:00 orig.txt

所有者はどうか。root のファイルを一般ユーザが写す。

$ sudo cp orig.txt rootcopy.txt
$ ls -l --time-style=long-iso rootcopy.txt
-rw-r--r-- 1 root root 13 2026-10-13 11:43 rootcopy.txt
$ cp rootcopy.txt mine.txt
$ ls -l --time-style=long-iso mine.txt
-rw-r--r-- 1 lab lab 13 2026-10-13 11:43 mine.txt
$ cp -p rootcopy.txt mine-p.txt; echo "exit=$?"
exit=0
$ ls -l --time-style=long-iso mine-p.txt
-rw-r--r-- 1 lab lab 13 2026-10-13 11:43 mine-p.txt

写しの所有者は、写した人（lab）になる。-p を付けても所有者だけは写せず、しかもエラーにならない（終了コード 0）。所有者を変えられるのは root だけだからである（第3章）。

書き方写しの時刻写しの権限写しの所有者
cp a b写した時刻元の権限から umask を落としたもの写した人
cp -p a b元と同じ元と同じroot なら元と同じ。一般ユーザは自分
cp -a a b元と同じ元と同じ-p と同じ。加えてディレクトリを再帰し、リンクはリンクのまま写す

上書きの前に確認させるのが -i である（n は自分で打つ）。

$ cp -i copy.txt keep.txt
cp: overwrite 'keep.txt'? n
たとえ: 原本を見ながら、新しい用紙に書き写す作業に近い。 写しは新しい紙なので、受付印（時刻）も持ち主も新しくなる。-p は「原本の日付印も写す」指示である。
ただし崩れる点: 紙の写しなら誰の名義にでもできるが、ファイルの写しは写した人のものにしかならない。 原本の持ち主の名義まで写せるのは root だけである。

mv は名前を書き換えるだけ（同じファイルシステムなら）

この節で分かること: mv が中身を動かさない場合と、動かす場合。

第1章で、名前の先にある実体には番号があると言った。ls -i でその番号（inode 番号）が見える。

$ ls -i orig.txt
18127983 orig.txt
$ mv orig.txt renamed.txt
$ ls -i renamed.txt
18127983 renamed.txt
$ ls -l --time-style=long-iso renamed.txt
-rw-rw-r-- 1 lab lab 13 2025-04-01 09:00 renamed.txt

番号も時刻も権限も変わらない。mv はディレクトリの表で名前の行を書き換えただけで、実体には触れていない。ディレクトリを変えても同じファイルシステムの中なら、表の行を別の表へ移すだけである。番号そのものはあなたの環境では違う値になる。同じ番号のまま残ることが要点である。

ところが、ホームへ移すと番号が変わる。

$ mv renamed.txt ~/renamed.txt
$ ls -i ~/renamed.txt
18371145 /home/lab/renamed.txt
$ mv ~/renamed.txt ~/work/ch4/
$ df --output=target ~/work ~
Mounted on
/home/lab/work
/

~/work は起動コマンドの -v で付けたボリュームで、ホーム（/ と同じファイルシステム）とは別のファイルシステムである。名前の表は1つのファイルシステムの中でしか番号を指せないので、mv は黙って「新しい側に写してから元を消す」に切り替える。外から見ると同じ mv でも、中で起きていることが違う。

たとえ: 同じ建物の中で、部屋の表札を付け替える作業に近い。住人（実体）は1歩も動かない。
ただし崩れる点: 別の建物（別のファイルシステム）へ移るときは表札を付け替えられず、 新しい建物に住人を作り直して、古い建物から消す。名前は同じでも、番号は新しい建物のものになる。

mv の主なオプションも確かめておく。試験には「mv に無いオプション」を選ばせる問題が出る。

$ mkdir -p ~/work/ch4/mvdemo
$ cd ~/work/ch4/mvdemo
$ mkdir backup docs; echo 1 > test.txt; echo 2 > docs/a.txt
$ mv -r test.txt backup/
mv: invalid option -- 'r'
Try 'mv --help' for more information.
$ mv docs backup/
$ ls -R backup
backup:
docs

backup/docs:
a.txt
$ mv -t backup test.txt
$ ls backup
docs  test.txt
$ echo 3 > test.txt
$ mv -i test.txt backup/
mv: overwrite 'backup/test.txt'? n
$ mv -n test.txt backup/; echo "exit=$?"
mv: not replacing 'backup/test.txt'
exit=1
$ cat backup/test.txt; ls test.txt
1
test.txt
$ mv -f test.txt backup/
$ cat backup/test.txt; ls test.txt

ls: cannot access 'test.txt': No such file or directory
$ cd ~/work/ch4

mv に -r は無い（invalid option）。ディレクトリも名前の書き換えで動かすので、再帰の指定が要らないからである（docs は -r 無しで中身ごと移った）。

オプション意味実測
-i上書きする前に確認するoverwrite 'backup/test.txt'?（n は自分で打つ）
-n既にあれば上書きしないnot replacing。中身は 1 のまま（この版の coreutils は終了コード 1 を返す）
-f確認せずに上書きする中身が 3 に替わり、元の test.txt は消えた
-t ディレクトリ移動先を先に書くmv -t backup test.txt で backup/ に入った
-r無いmv: invalid option -- 'r'

mkdir・rmdir・rm と、ディレクトリのコピー

この節で分かること: ディレクトリを作る・消す・写すときに必要なオプション。
$ mkdir a/b/c
mkdir: cannot create directory ‘a/b/c’: No such file or directory
$ mkdir -p a/b/c
$ touch a/b/c/file
$ rmdir a/b/c
rmdir: failed to remove 'a/b/c': Directory not empty
$ rm a
rm: cannot remove 'a': Is a directory
$ rm -r a
$ mkdir -p x/y/z
$ rmdir -p x/y/z
$ ls -d a x
ls: cannot access 'a': No such file or directory
ls: cannot access 'x': No such file or directory
コマンドできることできないこと
mkdir -p a/b/c途中のディレクトリもまとめて作る（-p なしは途中が無いと失敗）
rmdir dir空のディレクトリを消す中身があると失敗する
rmdir -p x/y/zz・y・x の順に、空なら親もたどって消す中身があると止まる
rm dir—ディレクトリは消せない（Is a directory）
rm -r dir中身ごと再帰的に消す（-f を足すと確認も出さない）—
ls -R / -r / -t / -1再帰的に一覧 / 逆順 / 更新時刻の新しい順 / 1行に1つ（-r は逆順で、再帰ではない。下の実測）

ディレクトリを写すには -r が要る。そして、同じコマンドを2回打つと結果が変わる。

$ mkdir -p src/sub
$ echo 1 > src/one; echo 2 > src/sub/two
$ cp src dst
cp: -r not specified; omitting directory 'src'
$ cp -r src dst
$ ls -R dst
dst:
one  sub

dst/sub:
two
$ cp -r src dst
$ ls -R dst
dst:
one  src  sub

dst/src:
one  sub

dst/src/sub:
two

dst/sub:
two

1回目は dst が無かったので「src を dst という名前で写す」になり、2回目は dst が既にあるので「dst の中へ src を写す」になった。最後の引数が既存のディレクトリかどうかで意味が変わる。この「最後の引数」の規則は mv も同じである（ただし mv はディレクトリも -r 無しで動かす）。

ls -R の -R は大文字で「再帰」である。小文字の -r は「逆順」で、意味がまったく違う。並び順を変えるオプションを、時刻をずらした3つのファイルで確かめる。

$ mkdir -p ~/work/ch4/lsdemo
$ cd ~/work/ch4/lsdemo
$ touch -d "2026-01-03 00:00" a.txt; touch -d "2026-01-01 00:00" b.txt; touch -d "2026-01-02 00:00" c.txt
$ ls
a.txt  b.txt  c.txt
$ ls -r
c.txt  b.txt  a.txt
$ ls -t
a.txt  c.txt  b.txt
$ ls -tr
b.txt  c.txt  a.txt
$ ls -1
a.txt
b.txt
c.txt
$ ls -lt --time-style=long-iso
total 0
-rw-r--r-- 1 lab lab 0 2026-01-03 00:00 a.txt
-rw-r--r-- 1 lab lab 0 2026-01-02 00:00 c.txt
-rw-r--r-- 1 lab lab 0 2026-01-01 00:00 b.txt
$ cd ~/work/ch4

-r は名前の逆順、-t は更新時刻の新しい順、-tr は古い順、-1 は1行に1つ。ls -lt で時刻を並べると、-t の順が更新時刻で決まっていることが分かる。

touch と file — 時刻と、中身の種類

この節で分かること: touch が時刻を書き換え、file が名前ではなく中身を見ること。
$ touch -t 202001020304.05 t.txt
$ ls -l --time-style=full-iso t.txt
-rw-r--r-- 1 lab lab 0 2020-01-02 03:04:05.000000000 +0900 t.txt
$ touch t.txt
$ ls -l --time-style=full-iso t.txt
-rw-r--r-- 1 lab lab 0 2026-10-13 11:43:13.052127681 +0900 t.txt

touch は、無ければ空のファイルを作り、あればアクセス時刻と更新時刻の両方をいまにする。-t [[CC]YY]MMDDhhmm[.ss] か -d "日時" で好きな時刻にもできる。片方だけを変えるオプションもある。stat の %x がアクセス時刻（atime）、%y が更新時刻（mtime）である。

$ touch -d "2020-01-01 00:00" t2.txt
$ stat -c "%x | %y" t2.txt
2020-01-01 00:00:00.000000000 +0900 | 2020-01-01 00:00:00.000000000 +0900
$ touch t2.txt
$ stat -c "%x | %y" t2.txt
2026-10-13 11:43:13.055127700 +0900 | 2026-10-13 11:43:13.055127700 +0900
$ touch -d "2020-01-01 00:00" t2.txt; touch -a t2.txt
$ stat -c "%x | %y" t2.txt
2026-10-13 11:43:13.057127714 +0900 | 2020-01-01 00:00:00.000000000 +0900
$ touch -d "2020-01-01 00:00" t2.txt; touch -m t2.txt
$ stat -c "%x | %y" t2.txt
2020-01-01 00:00:00.000000000 +0900 | 2026-10-13 11:43:13.060127734 +0900

何も付けない touch は両方を、-a はアクセス時刻だけを、-m は更新時刻だけをいまにした。時刻は inode が持っている情報なので、データ（ファイルの中身）に1バイトも触れずに書き換えられる。

$ file renamed.txt /usr/bin/passwd /bin /dev/null
renamed.txt:     Unicode text, UTF-8 text
/usr/bin/passwd: setuid ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=2344480b478a675609210ed886207d6cbdc8cdd7, for GNU/Linux 3.2.0, stripped
/bin:            symbolic link to usr/bin
/dev/null:       character special (1/3)
$ echo "ただの文字" > photo.jpg
$ cp /usr/bin/ls notes.txt
$ file photo.jpg notes.txt
photo.jpg: Unicode text, UTF-8 text
notes.txt: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=44900829b39271d878615772bb2a6ffa422f0891, for GNU/Linux 3.2.0, stripped

file は拡張子を見ない。中身の先頭にある特徴的なバイト列（マジックナンバー）で判定するので、.jpg という名前の文字ファイルは文字と、.txt という名前のプログラムはプログラムと答える。file とカーネルにとって、拡張子は人間のための目印にすぎない。ただし、拡張子を見て動きを決めるプログラムもある（第6章の gunzip は、決まった拡張子の無いファイルを展開しない）。

ワイルドカードを広げているのはシェル

この節で分かること: ワイルドカードが誰に、いつ、どう広げられるか。

名前を並べたディレクトリを作り、echo で広がり方を見る。echo は受け取った引数を並べるだけなので、シェルが何を渡したかがそのまま見える。

$ mkdir glob; cd glob
$ touch a.txt b.txt c.log .hidden.txt data1 data2 data10 Data3
$ echo *
Data3 a.txt b.txt c.log data1 data10 data2
$ echo *.txt
a.txt b.txt
$ echo data?
data1 data2
$ echo data*
data1 data10 data2
$ echo data[12]
data1 data2
$ echo [a-c]*
a.txt b.txt c.log
$ echo [!a]*
Data3 b.txt c.log data1 data10 data2
$ echo .*
.hidden.txt
パターン一致するもの実測
*0文字以上の任意の文字列（先頭の . を除く）.hidden.txt は出ない
?任意の1文字data? に data10 は入らない
[12] [a-c]括弧の中のどれか1文字（範囲も書ける）data[12] → data1 data2
[!a]括弧の中以外の1文字（[^a] とも書ける）a.txt だけが外れる
.*. で始まる名前（隠しファイル）.hidden.txt

大文字と小文字は区別する（Data3 は data* に入らない）。並びは名前の順に整えられる。そして . で始まる名前、つまり隠しファイルは、. から書き始めたパターンにしか一致しない。bash 5.2 の .* は . と .. を拾わないが、古い bash やほかのシェルでは .* が .（いまの場所）と ..（親）にも一致するので、.* を消す操作に使うときは必ず echo .* で先に確かめる。

一致する名前が1つも無いときが大事である。

$ echo *.csv
*.csv
$ ls *.csv
ls: cannot access '*.csv': No such file or directory

シェルは一致しないパターンを、そのままの文字列でコマンドに渡す。ls は *.csv という名前のファイルを探して見つからなかった、と言っている。エラーを出したのはシェルではなく ls である。ワイルドカードを広げるのはコマンドではなくシェルで、コマンドが受け取るのは広げた後の名前の並び（か、広がらなかった文字列そのもの）だけなのである。

$ echo {a,b}.txt {x,y}.md
a.txt b.txt x.md y.md
$ rm -v *
removed 'Data3'
removed 'a.txt'
removed 'b.txt'
removed 'c.log'
removed 'data1'
removed 'data10'
removed 'data2'
$ ls -A
.hidden.txt

{a,b} はブレース展開で、ワイルドカードとは別物である。名前を「探す」のではなく「作る」ので、存在しない x.md も並ぶ。最後の rm -v * は、* が隠しファイルを拾わないので .hidden.txt を残した。rm に * を渡すのは、いまいる場所の全部を渡すのと同じなので、打つ前に pwd で場所を確かめる（ここでは ~/work/ch4/glob）。ls -A は . と .. を除いて隠しファイルも見せるオプションである。

たとえ: 宛名ラベルを作る係（シェル）に近い。 「渋谷区の全員」という指示を受け取ると、係が名簿から該当者のラベルを刷り、配達員（コマンド）にはラベルの束だけを渡す。
ただし崩れる点: 該当者が1人もいないとき、この係は「渋谷区の全員」と書いた紙を1枚そのまま渡してしまう。 配達員はその名前の人を探して「いません」と言う。それが ls: cannot access '*.csv' である。
手を動かす: 実践編の演習04は、隠しファイルを含む .conf を、時刻ごと backup/ に写す課題である。 判定は元と写しの中身・更新時刻（ナノ秒まで）・権限を比べる。* と cp の両方で1回ずつ引っかかる作りになっている。
確認

ディレクトリ src を中身ごと backup にコピーしたい。パーミッションと更新時刻も保つには、どのオプションを付けるか。

答え

cp -rp src backup か cp -a src backup。-r（-R）が無いとディレクトリは写らず （-r not specified; omitting directory）、-p が無いと時刻は写した時刻に、権限は umask を落としたものになる。

確認

中にファイルが残っているディレクトリ old を、中身ごと削除するコマンドはどれか。
a. rmdir old　b. rm old　c. rm -r old　d. rmdir -p old

答え

c。rmdir は空のディレクトリしか消せず（Directory not empty）、-r の無い rm はディレクトリを消さない（Is a directory）。

確認

カレントディレクトリに a.txt・b.txt・.c.txt・d10.txt がある。ls *.txt と ls ?.txt で表示されるファイルを、それぞれすべて答えよ。

答え

ls *.txt は a.txt・b.txt・d10.txt。.c.txt は先頭が . なので * に一致しない（隠しファイル）。ls ?.txt は a.txt と b.txt だけで、? は任意の1文字なので d10.txt は長さで外れる。

確認

同じファイルシステムの中で mv a.txt b.txt を実行した。ls -i で見た inode 番号と、更新時刻はどうなるか。

答え

どちらも変わらない。mv は名前の行を書き換えるだけで、中身には触れない。 別のファイルシステムへの mv だけは、写してから元を消すので inode 番号が変わる（実測: ~/work からホームへ移したとき）。

この章で分かったこと

持ち帰ってほしいこと

  • cp は新しいファイルを作る。時刻は写した時刻、権限は umask を落としたもの、所有者は写した人になる
  • -p で時刻と権限を写す。-a はそれに加えて再帰し、リンクをリンクのまま写す。所有者まで写せるのは root だけ
  • mv は同じファイルシステムなら名前を書き換えるだけ（inode 番号も時刻も変わらない）。別のファイルシステムへは写して消す
  • ディレクトリは mkdir -p でまとめて作り、rmdir（空だけ）か rm -r で消す。cp -r の行き先が既にあると、その中へ写す
  • touch はアクセス時刻と更新時刻の両方を書き換える（-a / -m で片方だけ）。file は拡張子ではなく中身で種類を判定する
  • ワイルドカード（* ? [...]）を広げるのはシェル。* は隠しファイルに一致せず、一致しないとパターンがそのまま渡る
