5. find は名前をたどり、中身の属性で選ぶ

36時間前に更新したファイルは find -mtime +1 に引っかからない。find はディレクトリの名前をたどって1つずつ中身の属性を確かめるが、日数は24時間単位に切り捨て、大きさは単位に切り上げてから比べる。しかも find に渡る前に、シェルがパターンを書き換えてしまうことがある。

この章のゴールと前提所要 20分
前提: 第4章まで読了前提: 檻が起動している所要 20分影響度 B出題範囲 1.02.2（重要度3）出題範囲 1.02.4（重要度2）最終検証 2026-10-13

この章のゴール

  • 名前・種類・大きさ・時刻・所有者・権限の条件を組み合わせて find を書ける
  • -mtime と -size の数字の意味を、切り捨て・切り上げの規則から説明できる
  • 見つけたものに -exec で操作し、\; と + の違いを言える
ここで覚えなくていいこと: -printf の書式、-regex、-prune による枝刈り、xargs との組み合わせ、-atime と -ctime の細かい違いは扱わない。-atime（読んだ時刻）と -ctime（属性を変えた時刻）は、-mtime と同じ数え方をすると分かれば足りる。

find の形 — どこから、どんな条件で

この節で分かること: find の書き方の骨格と、結果の並び順。

この章は ~/work/ch5 で作業する。更新時刻をずらしたログを4つ作る。

$ mkdir -p ~/work/ch5/logs/old
$ cd ~/work/ch5
$ touch logs/today.log
$ touch -d "36 hours ago" logs/yesterday.log
$ touch -d "60 hours ago" logs/twodays.log
$ touch -d "10 days ago" logs/old/ancient.log
$ date "+%F %H:%M"
2026-10-13 11:43
$ ls -l --time-style=long-iso logs/*.log logs/old/*.log
-rw-r--r-- 1 lab lab 0 2026-10-03 11:43 logs/old/ancient.log
-rw-r--r-- 1 lab lab 0 2026-10-13 11:43 logs/today.log
-rw-r--r-- 1 lab lab 0 2026-10-10 23:43 logs/twodays.log
-rw-r--r-- 1 lab lab 0 2026-10-11 23:43 logs/yesterday.log

find は「どこから」の後に「どんな条件で」を並べる。条件を並べると「かつ」になる。

$ find logs -name "*.log" | sort
logs/old/ancient.log
logs/today.log
logs/twodays.log
logs/yesterday.log
$ find . -type d | sort
.
./logs
./logs/old
$ find logs -type f -name "t*" | sort
logs/today.log
logs/twodays.log

この教材では find の結果を sort に通している。find は名前を、ディレクトリの表に書かれている順に出す。その順はファイルシステムが決めていて（ext4 では名前から計算した値の順）、あなたの環境では違う順になりうる。ls は自分で名前順に並べ直してから出すので、この差が見えない。

条件意味
-name "*.log"名前がパターンに一致する（大文字小文字を区別。-iname なら区別しない）
-type f / d / l通常ファイル / ディレクトリ / シンボリックリンク
-maxdepth 1何段下までたどるか
! 条件条件の否定
条件 -o 条件または（並べるだけなら「かつ」）

find のパターンは、シェルのワイルドカードと違って先頭の . にも一致する。隠しファイルも拾う。

たとえ: 倉庫の棚を端から順に歩き、品物の札を1枚ずつ確かめていく係に近い。 名前・種類・大きさ・日付と、札に書いてあることなら何でも条件にできる。
ただし崩れる点: 係が歩く順は、倉庫の棚の並び（ファイルシステムの都合）で、品名の五十音順ではない。 名前順が欲しければ、報告を受けてから自分で並べ替える（| sort）。

-mtime は24時間単位に切り捨てて数える

この節で分かること: -mtime +1 が、どの古さのファイルを指すか。

-mtime は更新時刻（mtime）を日数で比べる条件である。

ふつうこう考える

-mtime +1 は「1日より古い」ファイルを探す。36時間前（1日半前）の yesterday.log は1日より古いので、 twodays.log と ancient.log と一緒に見つかるはずだ。

$ find logs -mtime +1 | sort
logs/old/ancient.log
logs/twodays.log
だめな理由: yesterday.log が出ない。find は経過時間を24時間で割って小数点以下を切り捨てた日数で比べる。 36時間は 1.5日 → 1日、60時間は 2.5日 → 2日になる。+1 は「1 より大きい」なので、2日以上（48時間以上前）だけが当たる。 1.5日前のファイルは「ちょうど1」に入る。
$ find logs -mtime 1
logs/yesterday.log
$ find logs -type f -mtime -1
logs/today.log
$ find logs -mtime +2
logs/old/ancient.log
書き方切り捨てた日数経過時間で言うと実測で当たったもの
-mtime -10（1 未満）24時間以内today.log
-mtime 1ちょうど 124〜48時間前yesterday.log（36時間前）
-mtime +12 以上48時間以上前twodays.log（60時間前）・ancient.log
-mtime +23 以上72時間以上前ancient.log だけ

試験の「7日より前に更新されたファイル」は -mtime +7 と書くのが定番だが、正確には「切り捨てて 8日以上」である。分単位で比べる -mmin と、あるファイルより新しいかを比べる -newer もある。

$ find logs -type f -mmin -60
logs/today.log
$ find logs -type f -newer logs/yesterday.log
logs/today.log
たとえ: 満年齢に近い。1歳半の子は「1歳」で、「1歳より上」と言われたら2歳からになる。
ただし崩れる点: 満年齢は誕生日の日付で繰り上がるが、find の日数はカレンダーの日付を見ない。 いまの時刻から24時間ずつ区切って数えるので、「昨日の朝」でも24時間たっていなければ 0日である。

パターンを引用符で囲む理由

この節で分かること: 引用符を忘れたとき、find に何が渡っているか。
$ mkdir docs; touch top.txt docs/a.txt docs/b.txt
$ find . -name "*.txt" | sort
./docs/a.txt
./docs/b.txt
./top.txt
$ find . -name *.txt
./top.txt

引用符を外すと、docs の下の2つが消えた。しかもエラーは出ていない。echo を前に付けて、find が実際に受け取った引数を見る。

$ echo find . -name *.txt
find . -name top.txt

第4章のとおり、ワイルドカードを広げるのはシェルで、しかもいまのディレクトリの名前で広げる。カレントに top.txt が1つあったので、find が受け取ったのは -name top.txt だった。もう1つ増やすと、今度はエラーになる。

$ touch second.txt
$ find . -name *.txt
find: paths must precede expression: `top.txt'
find: possible unquoted pattern after predicate `-name'?
$ echo find . -name *.txt
find . -name second.txt top.txt

一番危ないのは1つだけ一致した場合で、何も言わずに少なく返す。find に渡すパターンは、必ず引用符で囲む。囲めばシェルは広げず、find が自分でたどりながら照らし合わせる。

-size は単位に切り上げてから比べる

この節で分かること: -size -1k が何に当たるか。
$ head -c 1 /dev/zero > one.bin; head -c 1024 /dev/zero > k1.bin; head -c 1025 /dev/zero > k1plus.bin; : > empty.bin
$ ls -l *.bin
-rw-r--r-- 1 lab lab    0 Oct 13 11:43 empty.bin
-rw-r--r-- 1 lab lab 1024 Oct 13 11:43 k1.bin
-rw-r--r-- 1 lab lab 1025 Oct 13 11:43 k1plus.bin
-rw-r--r-- 1 lab lab    1 Oct 13 11:43 one.bin
$ find . -name "*.bin" -size -1k
./empty.bin
$ find . -name "*.bin" -size 1k | sort
./k1.bin
./one.bin
$ find . -name "*.bin" -size +1k
./k1plus.bin
$ find . -name "*.bin" -size -1M
./empty.bin

1バイトのファイルは「1KiB（1024 バイト）未満」のはずなのに、-size -1k に当たったのは空のファイルだけだった。-size は大きさを単位（k なら 1024 バイト）に切り上げてから比べる。1バイトも 1024 バイトも「1k」になり、「1 未満」は 0k、つまり空のファイルしか無い。-size -1M も同じ理由で空のファイルだけになる。

大きさk に切り上げ-size -1k-size 1k-size +1k
0 バイト0当たる——
1 バイト1—当たる—
1024 バイト1—当たる—
1025 バイト2——当たる

バイト単位で正確に比べたいときは c を付ける。

$ find . -name "*.bin" -size -1025c | sort
./empty.bin
./k1.bin
./one.bin

単位は c（バイト）・k（KiB = 1024 バイト）・M（MiB = 1048576 バイト）・G（GiB）。試験や日常では「1KB」「1MB」と書かれるが、find の k と M は 1000 ではなく 1024 の倍数である。何も付けないと 512 バイトのブロック単位になるので、数字だけを書かない。

たとえ: 郵便料金の重さの区分に近い。1グラムでも区分を超えれば、次の区分の料金になる。 -size の「1k」は「1KiB 以下の区分」で、0 グラムの封筒だけが「1k 未満」に入る。
ただし崩れる点: 郵便の区分は上限で区切るだけだが、-size は「ちょうど」も比べられる。 -size 1k は「切り上げてちょうど 1」なので、1 バイトから 1024 バイトまでが全部当たる。
手を動かす: 実践編の演習05は、深い階層まで含めて「1KB より大きい .tmp ファイル」だけを消す課題である。 ちょうど 1024 バイトのもの、ディレクトリの big.tmp、大文字の .TMP、隠しファイルが混ぜてある。 判定は、消えるべきものと残るべきものを1つずつ確かめる。

持ち主と権限で探す

この節で分かること: -user と -perm の3つの書き方。
$ sudo chown alice logs/yesterday.log
$ find logs -user alice
logs/yesterday.log
$ find . -name "*.log" ! -user lab
./logs/yesterday.log
$ chmod 600 k1.bin; chmod 755 k1plus.bin
$ find . -name "*.bin" -perm 600
./k1.bin
$ find . -name "*.bin" -perm -u+x
./k1plus.bin
$ find . -name "*.bin" -perm /111
./k1plus.bin
書き方意味
-perm 600権限がちょうど 600 のもの
-perm -4000（-perm -u+s）指定したビットが全部立っているもの（他のビットは問わない）
-perm /111指定したビットのどれか1つが立っているもの
-user alice / -group devs所有者 / グループ

試験でよく問われるのは、第3章の SUID が付いたファイルを探す形である。

$ find /usr/bin -perm -4000 | sort
/usr/bin/chfn
/usr/bin/chsh
/usr/bin/gpasswd
/usr/bin/mount
/usr/bin/newgrp
/usr/bin/passwd
/usr/bin/su
/usr/bin/sudo
/usr/bin/umount

システム全体（/）から探すと、一般ユーザでは入れないディレクトリで Permission denied が出る。find は、ディレクトリの中の名前を読むのに r を、その先へ進むのに x を使う（第1章）。/home/alice（drwxr-x---）は、lab から見てその他の欄が --- で、どちらも無い。

$ find /home/alice -name ".bashrc"
find: ‘/home/alice’: Permission denied
$ find /home -name ".bashrc" 2>/dev/null
/home/lab/.bashrc

エラーだけを捨てるには 2>/dev/null を付ける。全部を見たいなら sudo find / -perm -4000 -type f のように root で打つ。結果を画面に出しながらファイルにも残したいときは tee を使う（find /usr/share/man -type f | tee result.txt。主題1.03 のコースの第8章で実測している）。

見つけて操作する — -exec と -delete

この節で分かること: -exec ... \; と -exec ... + の違い。

-exec は見つけたものにコマンドを実行する。{} が見つけたパスに置き換わり、終わりの印が2種類ある。

$ find logs -type f -exec echo {} \; | wc -l
4
$ find logs -type f -exec echo {} + | wc -l
1

\; は1件ごとに1回コマンドを実行するので、echo は4回走って4行を出した。+ はまとめて1回実行するので、4つの名前を並べた1行になった。; の前の \ は、; をシェルの区切りとして読ませないためのものである。

$ find logs -name "*.log" -mtime +1 -exec ls -l --time-style=long-iso {} +
-rw-r--r-- 1 lab lab 0 2026-10-03 11:43 logs/old/ancient.log
-rw-r--r-- 1 lab lab 0 2026-10-10 23:43 logs/twodays.log
$ find logs -name "*.log" -mtime +1 -delete
$ find logs -type f | sort
logs/today.log
logs/yesterday.log

消す前に、同じ条件で一覧を出して確かめる。確かめた条件の最後を -delete（または -exec rm {} \;）に替えれば、確かめたものだけが消える。1件ずつ確認しながら実行したいときは、-exec の代わりに -ok を使う。

たとえ: 見つけた相手への連絡のしかたに近い。\; は1人ずつ電話をかけ、+ は全員を宛先に並べてメールを1通送る。
ただし崩れる点: メールの宛先には上限が無いように思えるが、コマンドの引数の長さには上限がある。 + は上限を超えそうになると、自動で何回かに分けて実行する。
確認

ルートディレクトリ以下から、SUID が設定された通常ファイルを探すコマンドを書け。

答え

find / -perm -4000 -type f（-perm -u+s でもよい）。- は「指定したビットが全部立っている」。 一般ユーザで打つと入れないディレクトリでエラーが出るので、2>/dev/null を付けるか root で打つ。

確認

find /var/log -mtime +7 で見つかるファイルはどれか。
a. 更新から7日以内のもの　b. ちょうど7日前に更新したもの　c. 更新から8日以上たったもの　d. 更新から7日以上たったもの

答え

c。経過時間を24時間で割って切り捨てた日数が 7 より大きいもの、つまり 8 以上。 実測でも、36時間前のファイルは -mtime +1 に入らず -mtime 1 に入った。 ただし試験の選択肢や解説は、これを「7日以上前」「7日より前」と緩く書くことがある。その書き方で問われたら +7 を選ぶ（厳密には8日以上）。

確認

find . -name "*.tmp" -exec rm {} \; の {} と \; は、それぞれ何を表すか。

答え

{} は見つかったファイルのパスに置き換わる。\; は -exec に渡すコマンドの終わりで、 1件ごとにコマンドを1回実行する（\ はシェルに ; を解釈させないため）。+ で終えると、まとめて1回実行する。

確認

1MB（find の単位では 1MiB）を超えるファイルを探す条件と、空のファイルを探す条件を書け。

答え

-size +1M と -type f -empty（または -type f -size 0）。-empty だけだと、空のディレクトリにも当たる。+1M は 1048576 バイトを超えるもの。-size -1M は「1MiB 未満」に見えるが、 MiB 単位に切り上げると 1 未満は 0 だけなので、空のファイルにしか当たらない（実測）。

この章で分かったこと

持ち帰ってほしいこと

  • find 場所 条件…。条件を並べると「かつ」、! で否定、-o で「または」
  • 結果はディレクトリの表の順に出る。名前順が欲しければ | sort
  • -mtime は24時間単位に切り捨て。+1 は48時間以上前、1 は24〜48時間前、-1 は24時間以内
  • -size は単位に切り上げ。-size -1k は空のファイルだけ。正確には c（バイト）で
  • -perm 600 はちょうど、-perm -4000 は全部、-perm /111 はどれか
  • パターンは必ず引用符で囲む。囲まないとシェルがカレントの名前で広げ、黙って少なく返すことがある
  • -exec cmd {} \; は1件ずつ、-exec cmd {} + はまとめて。消すのは一覧で確かめてから
