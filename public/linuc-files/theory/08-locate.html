8. locate が探すのは、索引を作った時点の写真

作ったばかりのファイルを locate は見つけず、消したばかりのファイルは見つけ続ける。locate はディスクを探していない。updatedb が作った名前の一覧（索引）を引いているだけで、その索引は作った瞬間の写真である。最後に、この主題の8章を1本につなげる。

前提: 第7章まで読了前提: sudo が打てる所要 20分影響度 B出題範囲 1.02.4（重要度2）最終検証 2026-10-13

この章のゴール

  • locate の結果が実際のディスクとずれる理由を、updatedb と /etc/updatedb.conf から説明できる
  • which・type・whereis の違いを、何を探しているかで言い分けられる
  • FHS の主なディレクトリに、何が置かれるかを言える
ここで覚えなくていいこと: plocate と mlocate・slocate の実装の違い、索引ファイルの形式、locate -r の正規表現、hash コマンド、FHS の版ごとの差分は扱わない。この檻の locate の実体は plocate で、試験で問われる使い方（locate / updatedb / /etc/updatedb.conf）はどの実装でも同じである。

locate は索引を引くだけ

この節で分かること: locate の結果が、いつの時点のものか。

この章はホームで作業する。locate は名前の一部を渡すと、一致するパスを並べる。

$ cd ~
$ ls -l /var/lib/plocate/plocate.db
-rw-r----- 1 root plocate 413089 Oct 13 11:42 /var/lib/plocate/plocate.db
$ locate bashrc
/etc/bash.bashrc
/etc/skel/.bashrc
/home/lab/.bashrc
/usr/share/dot.bashrc
/usr/share/base-files/dot.bashrc
/usr/share/doc/adduser/examples/adduser.local.conf.examples/bash.bashrc
/usr/share/doc/adduser/examples/adduser.local.conf.examples/skel/dot.bashrc

速い。find のように1つずつたどっていない。/var/lib/plocate/plocate.db が引いている索引で、日付はこの檻のイメージを作った時刻である。

ふつうこう考える

locate は名前でファイルを探すコマンドなのだから、いまあるファイルなら見つかり、消したファイルは見つからないはずだ。

$ touch ~/work/new-note.txt
$ locate new-note; echo "exit=$?"
exit=1
$ updatedb
/var/lib/plocate/: Permission denied
$ sudo updatedb
$ locate new-note
/home/lab/work/new-note.txt
$ rm ~/work/new-note.txt
$ locate new-note
/home/lab/work/new-note.txt
だめな理由: 作った直後は見つからず、updatedb の後で見つかり、消した後も見つかり続けた。 locate はディスクを見ていない。updatedb がディスクをたどって作った名前の一覧を引いているだけで、 一覧はその瞬間の写真である。写真の後に作ったものは写っておらず、消したものは写ったまま残る。 updatedb は一覧をシステム全体の場所（/var/lib/plocate/）に書くので、一般ユーザでは打てない。
$ locate -e new-note; echo "exit=$?"
exit=1

-e を付けると、写真に写っているものがいまも存在するかを1つずつ確かめてから出す。実機では updatedb は1日1回、自動で呼ばれる（次の節）。この檻ではそれが動かないので、イメージを作った時刻の写真が残り続けている。

たとえ: 毎晩作り直す、図書館の蔵書カード目録に近い。 今日入った本はまだカードが無く、今日除籍した本はカードが残っている。目録をめくるのは書庫を歩くよりずっと速い。
ただし崩れる点: 図書館の目録は誰が見ても同じだが、locate の目録は見る人によって出てくるカードが変わる（次の節）。

索引に載っていても、見えないものがある

この節で分かること: 一般ユーザの locate に出てこないものがある理由。
$ sudo -u alice touch /home/alice/alice-note.txt
$ sudo updatedb
$ locate alice-note; echo "exit=$?"
exit=1
$ sudo locate alice-note
/home/alice/alice-note.txt
$ ls -ld /home/alice
drwxr-x--- 1 alice alice 4096 Oct 13 11:43 /home/alice

索引には載っているのに、lab の locate には出ず、root には出た。/home/alice は drwxr-x--- で、lab には x が無い。第1章のとおり、x の無いディレクトリの先へは進めない。locate は結果を出す前に、呼んだ人が親ディレクトリすべてに r と x を持っているかを確かめ、持っていないものは出さない（man plocate にそう書いてある）。索引そのものも -rw-r----- root plocate で一般ユーザには直接読めず、locate だけが読める作りになっている。他人の持ち物の名前が漏れないようにしているのである。

/etc/updatedb.conf — 索引から外す場所

この節で分かること: updatedb がどこを索引に入れないか、どこで決まっているか。
$ touch /tmp/tmp-note.txt
$ sudo updatedb
$ locate tmp-note; echo "exit=$?"
exit=1
$ cat /etc/updatedb.conf
PRUNE_BIND_MOUNTS="yes"
# PRUNENAMES=".git .bzr .hg .svn"
PRUNEPATHS="/tmp /var/spool /media /var/lib/os-prober /var/lib/ceph /home/.ecryptfs /var/lib/schroot"
PRUNEFS="NFS afs autofs binfmt_misc ceph cgroup cgroup2 cifs coda configfs curlftpfs debugfs devfs devpts devtmpfs ecryptfs ftpfs fuse.ceph fuse.cryfs fuse.encfs fuse.glusterfs fuse.gocryptfs fuse.gvfsd-fuse fuse.mfs fuse.rclone fuse.rozofs fuse.sshfs fusectl fusesmb hugetlbfs iso9660 lustre lustre_lite mfs mqueue ncpfs nfs nfs4 ocfs ocfs2 proc pstore rpc_pipefs securityfs shfs smbfs sysfs tmpfs tracefs udev udf usbfs"

updatedb を打った後でも、/tmp のファイルは出なかった。/tmp は PRUNEPATHS に入っていて、最初から索引に入れない場所だからである。すぐ消える一時ファイルを毎晩記録しても意味が無い。

設定意味この檻の値
PRUNEPATHS索引に入れないディレクトリ/tmp /var/spool /media など
PRUNEFS索引に入れないファイルシステムの種類proc sysfs tmpfs nfs など
PRUNENAMES索引に入れない名前（コメントアウトされている。例は .git）
PRUNE_BIND_MOUNTSbind mount を入れないか"yes"

locate という名前も、第7章の仕組みで実体につながっている。

$ ls -l /usr/bin/locate /etc/alternatives/locate
lrwxrwxrwx 1 root root 16 Apr 19  2024 /etc/alternatives/locate -> /usr/bin/plocate
lrwxrwxrwx 1 root root 24 Apr 19  2024 /usr/bin/locate -> /etc/alternatives/locate
$ cat /usr/lib/systemd/system/plocate-updatedb.timer
[Unit]
Description=Update the plocate database daily

[Timer]
OnCalendar=daily
RandomizedDelaySec=12h
AccuracySec=20min
Persistent=true

[Install]
WantedBy=timers.target

実機では、systemd のタイマー（OnCalendar=daily）が1日1回 updatedb を呼ぶ。systemd が動いていない環境のために /etc/cron.daily/plocate も置かれていて、こちらは中で「タイマーが使えるなら何もしない」と確かめてから動く。タイマーは毎回、呼ぶ時刻を 0〜12時間の範囲で選び直してずらす（RandomizedDelaySec=12h）。そのため索引の古さは 0 から最大でおよそ1日半（36時間）で、平均すると半日ほどになる。この檻の中では systemd も cron のデーモンも動いていないので、どちらも起動しない。索引は、自分で sudo updatedb を打つまで変わらない。

手を動かす: 実践編の演習08は、locate で見つからない2つのファイルを見つかるようにする課題である。 2つは見つからない理由が違い、片方は /etc/updatedb.conf を直さないと出てこない。 判定は locate needle.txt を実際に引いて確かめる。

which・type・whereis — コマンドの居場所

この節で分かること: 3つのコマンドが、それぞれ何を手がかりに探しているか。

コマンドの名前を打ったとき、シェルは環境変数 PATH に並んだディレクトリを左から順に探す。

$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
$ which ls
/usr/bin/ls
$ which -a ls
/usr/bin/ls
/bin/ls
$ which cd; echo "exit=$?"
exit=1

which は PATH を順に探して、最初に見つかったファイルを出す。-a なら全部出す。/bin/ls も出たのは、第7章のとおり /bin が usr/bin へのリンクだからである。そして cd は見つからなかった。cd はシェルに組み込まれた命令で、Ubuntu には cd という名前のファイルが無いからである（Red Hat 系の bash パッケージには /usr/bin/cd という小さなスクリプトがあり、which cd はそれを返す。それでも、打った cd が動かすのはシェルの組み込みのほうである）。シェルが実際に何を動かすかを答えるのが type である。

$ type ls
ls is aliased to `ls --color=auto'
$ type -a ls
ls is aliased to `ls --color=auto'
ls is /usr/bin/ls
ls is /bin/ls
$ type ll
ll is aliased to `ls -alF'
$ type cd
cd is a shell builtin
$ type type
type is a shell builtin
$ type if
if is a shell keyword

あなたが打つ ls は、実は ls --color=auto というエイリアスだった（Ubuntu の ~/.bashrc が定義している）。Ubuntu の which はファイルしか探さないので、この事実を知らない（Red Hat 系では which 自体が /etc/profile.d/which2.sh の関数になっていて、エイリアスも出す。ディストリビューションで答えが変わる）。type はシェル自身に聞くので、その名前がエイリアス・予約語・関数・組み込みコマンド・PATH 上のファイルのどれに当たるかを答える。-a を付けると、当たるものを全部、シェルが優先する順に並べる。打ったときに実際に動くのは、その先頭である。

$ whereis ls
ls: /usr/bin/ls /usr/share/man/man1/ls.1.gz
$ whereis -b ls
ls: /usr/bin/ls
$ whereis passwd
passwd: /usr/bin/passwd /etc/passwd /usr/share/man/man5/passwd.5.gz /usr/share/man/man1/passwd.1.gz
$ whereis cd
cd:

whereis は Linux の標準の場所（と PATH・MANPATH）を探して、実行ファイル・マニュアル（・ソース）をまとめて出す。-b は実行ファイルだけ。passwd では、同じ名前の設定ファイル /etc/passwd と、その書式を説明する5章のマニュアルまで並んだ。

コマンド何を探すかls の答えcd の答え
whichPATH の上の実行ファイル/usr/bin/lsUbuntu では何も出ない（終了コード 1）
typeシェルが実際に何を動かすかエイリアスshell builtin
whereis標準の場所の実行ファイル・マニュアル・ソース本体とマニュアルUbuntu では cd:（空）
locate索引に載った名前（パスの一部一致）（名前に ls を含むパスが大量に出る）—
たとえ: which は駅の路線図だけを見て駅を探す人、type はこの駅の駅員に聞く人に近い。 路線図には載っていない「駅員の手持ちの近道」（エイリアスや組み込み）を知っているのは駅員だけである。
ただし崩れる点: 駅員はどの駅でも同じ答えを返すが、type の答えはシェルごとに違う。 エイリアスは対話シェルが ~/.bashrc を読んで作るので、スクリプトの中では type ls がファイルを答える。

FHS — どこに何を置くかの約束

この節で分かること: 主なディレクトリの役割と、いまの Linux での形。
$ echo /*
/bin /boot /dev /etc /home /lab /lib /lib64 /media /mnt /opt /proc /root /run /sbin /srv /sys /tmp /usr /var
$ ls -ld /bin /sbin /lib /lib64
lrwxrwxrwx 1 root root 7 Apr 22  2024 /bin -> usr/bin
lrwxrwxrwx 1 root root 7 Apr 22  2024 /lib -> usr/lib
lrwxrwxrwx 1 root root 9 Apr 22  2024 /lib64 -> usr/lib64
lrwxrwxrwx 1 root root 8 Apr 22  2024 /sbin -> usr/sbin
$ ls -ld /tmp /var/tmp
drwxrwxrwt 1 root root 4096 Oct 13 11:43 /tmp
drwxrwxrwt 2 root root 4096 Sep 11 11:10 /var/tmp
$ ls -d /var/log /var/spool /var/lib /usr/local/bin /usr/share/man /etc/skel
/etc/skel  /usr/local/bin  /usr/share/man  /var/lib  /var/log  /var/spool

FHS（Filesystem Hierarchy Standard）は、どのディレクトリに何を置くかの約束である。約束なので、外れても動く。/lab はこの教材が置いたもので、FHS には無い。そして FHS では /bin と /usr/bin は別の場所として説明されるが、いまの Ubuntu では /bin は usr/bin へのリンクで、中身は1つにまとめられている。試験は FHS の役割分担で答える。

ディレクトリ置くもの
/bin /usr/bin一般ユーザも使うコマンド
/sbin /usr/sbin管理用のコマンド
/lib /usr/lib共有ライブラリ
/etcそのマシンの設定ファイル（/etc/skel は新しいユーザのホームの雛形）
/home / /root一般ユーザのホーム / root のホーム
/var変化し続けるデータ。/var/log ログ、/var/spool メールや印刷の待ち行列、/var/lib プログラムの状態（locate の索引もここ）
/tmp / /var/tmp一時ファイル。/tmp は再起動で消えてよく、/var/tmp は再起動後も残す。どちらもスティッキービット付き
/usr読み取り専用で共有できるもの。/usr/share/man マニュアル、/usr/local 管理者が自分で入れたもの
/opt追加のアプリケーションを、パッケージごとのディレクトリで
/bootカーネルとブートローダのファイル
/devデバイスファイル（第1章のスペシャルファイル）
/proc /sysカーネルが見せる仮想のファイル（ディスクには無い）
/mnt / /media一時的なマウント先 / USB メモリなど取り外せる媒体のマウント先
/srvこのマシンが提供するサービスのデータ（第3章で /srv/team を作った）
/run起動してからの実行時のデータ（再起動で消える）
$ man -w hier
/usr/share/man/man7/hier.7.gz
$ whatis hier
hier (7)             - description of the filesystem hierarchy

この表は手元でも読める。man 7 hier が、このシステムのディレクトリの説明である。

たとえ: 町の住居表示の決まりに近い。役所は何丁目、病院は何丁目と決めておけば、初めての町でも迷わない。
ただし崩れる点: 住居表示は法律で決まるが、FHS は約束にすぎない。 いまの Ubuntu のように、2つの町（/bin と /usr/bin）を1つにまとめて、古い住所には案内板（シンボリックリンク）だけを残すこともある。

8章を1つにまとめる

この節で分かること: この主題の8章が、同じ1つの事実から出ていること。

ここまでの8章は、全部同じ事実の上にあった。

ファイルの名前は、ディレクトリの中に書かれた1行にすぎない。権限・所有者・時刻・中身は、名前ではなく inode の側にある。コマンドがどちらを触るかで、結果が決まる。

章名前の側（ディレクトリの表）で起きたこと中身の側（inode）で起きたこと
1r で名前が読め、w で名前を足し引きできる。消せるかどうかはここで決まる権限・所有者・大きさ・時刻はこちら。x が無いと ? になる
2—umask は、中身が作られる瞬間の権限を決める
3スティッキービットは、名前を外せる人を絞る。SGID はグループを受け継がせるSUID は中身に付いた印。それをどう扱うかはカーネルが決める
4mv は名前の行を書き換える。ワイルドカードは名前の一覧から広がるcp は新しい中身を作る（時刻・権限・所有者が新しくなる）
5find は名前をたどる。並び順は表の順-mtime・-size・-perm・-user は中身の属性
6tar は名前を、渡したパスのまま記録する権限・所有者・時刻も一緒に記録する
7ハードリンクは名前を増やし、rm は名前を外す中身はリンク数が 0 になったときに片づけられる
8locate は名前の一覧（索引）を引くだけ中身がいまあるかは確かめない（-e で確かめる）

出題範囲では ls -i や「ハードリンク」と、chmod・find・tar が同じ主題に並んでいる。ばらばらに見えるが、どれもこの構造で説明できる。どのコマンドも、名前と中身のどちらかを触っている。迷ったら「いま触っているのは名前か、中身か」と問えば、たいていの結果は打つ前に予想できる。

確認

locate が使うデータベースを、手動で最新にするコマンドはどれか。また、誰の権限で実行するか。

答え

updatedb。システム全体の索引（/var/lib/plocate/plocate.db）を書き換えるので root で実行する （一般ユーザでは Permission denied）。実機では1日1回、タイマーか cron が呼ぶ。

確認

updatedb が検索の対象から外すディレクトリを指定する、設定ファイルと変数の名前を答えよ。

答え

/etc/updatedb.conf の PRUNEPATHS。ファイルシステムの種類で外すのは PRUNEFS、名前で外すのは PRUNENAMES。 Ubuntu の既定では /tmp が PRUNEPATHS に入っている（実測）。

確認

コマンド ll が、エイリアス・シェルの組み込み・外部コマンドのどれなのかを調べるコマンドはどれか。
a. which　b. whereis　c. type　d. locate

答え

c。type はシェル自身に聞くので、エイリアス（ll is aliased to `ls -alF'）や組み込み（cd is a shell builtin）も答える。 Ubuntu の which は PATH 上のファイルしか探さない（Red Hat 系の which はエイリアスも出すが、組み込みかどうかは答えない）。確実に見分けられるのは type である。

確認

FHS で、次のものを置くディレクトリを答えよ。（1）システムのログ　（2）再起動しても消えない一時ファイル　（3）管理者が自分で入れたプログラム

答え

（1）/var/log　（2）/var/tmp（/tmp は再起動で消えてよい）　（3）/usr/local（実行ファイルは /usr/local/bin）。 パッケージ単位の追加アプリケーションなら /opt。

この章で分かったこと

持ち帰ってほしいこと

  • locate は updatedb が作った索引を引くだけ。作った直後は出ず、消した後も出る（-e で実在を確かめる）
  • updatedb は root で打つ。実機ではタイマーか /etc/cron.daily が1日1回呼ぶ
  • /etc/updatedb.conf の PRUNEPATHS・PRUNEFS・PRUNENAMES が索引から外す。/tmp は最初から外れている
  • 一般ユーザの locate には、親ディレクトリに r と x を持たない場所のものは出ない
  • which は PATH 上のファイル（Ubuntu。Red Hat 系はエイリアスも出す）、type はシェルが実際に動かすもの、whereis は実行ファイルとマニュアルの場所。組み込みかどうかを確かめるのは type
  • FHS は置き場所の約束。/etc 設定、/var/log ログ、/tmp と /var/tmp 一時、/usr/local 自分で入れたもの。いまの Ubuntu では /bin は usr/bin へのリンク
  • この主題の全部が「名前はディレクトリに、それ以外は inode に」の上にある
