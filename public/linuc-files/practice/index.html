確かめて説明する LinuC 主題1.02

LinuC レベル1 101 試験・主題1.02「ファイル・ディレクトリの操作と管理」 （所有者とパーミッション / 基本的なファイル管理 / ハードリンクとシンボリックリンク / ファイルの配置と検索）を、 全部コンテナの中で実際に打って確かめます。 あなたは一般ユーザ lab として入り、他人の立場（alice・bob・carol）と root の立場は sudo で借ります。 パーミッションは「誰として触るか」で結果が変わるので、人を複数用意した檻です。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: コマンドは打てる。写経すれば動く。 でも「なぜ動くのか」を人に説明できない人。
LinuC を受ける人向けには: chmod 4755 や find -mtime +7 を暗記しようとして、 覚えたそばから抜けていく人。

檻準備ここで触れるここでは触れない（逃がす先）

影響度 B（変更はコンテナの中だけ。母艦の設定もファイルも書き換えません）。 演習はホームや /etc・/srv の権限と中身を書き換えるので、母艦では絶対に実行しないでください。 やり直したいときはコンテナを抜けて入り直します。

ユーザ役割

はじめる

Docker の場合。1行です（著者は docker で確かめました。podman は未確認です）。

docker run --rm -it --name lab-linuc-files --hostname linuc \
  -v lab-linuc-files-work:/home/lab/work \
  -v lab-linuc-files-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:files-1.0.1@sha256:6b256ca7b7f40bb879761737a315e018979ae26ab8b0ef71dcaaf0d77031fa69

入ると現在地が出ます。

── lab-linuc-files 1.0.1 ────────────────────────────────────────
lab-linuc-files  進捗 0/8
  次 → 01 「一覧は見せずに、1つのファイルだけ読ませる」 (目安 10分 / 影響度 B)
  lab start 01 で課題を開く
  進捗の保存先: /home/lab/.lab/progress.json（消すには docker volume rm lab-linuc-files-state）
  lab ls      演習一覧 / lab start NN  課題を開く / lab check  答え合わせ
────────────────────────────────────────────────────────────

この檻の約束（画面を本文と揃えるために）

  • --rm で起動しています。抜けると、~/work と進捗（2つのボリューム）以外の変更は消えます。 ホームや /etc の権限をいじって分からなくなったら、抜けて入り直せば元に戻ります。
  • 2つ目の端末を開かないでください。別の端末から docker exec で入ったシェルは umask が 0000 で、 作ったファイルが -rw-rw-rw- になります（著者の実測・docker 29.8.0）。この教材は docker run で入ったシェル （umask 0022）で記録してあります。開くなら、最初に umask 022 を打ってください。
  • 第1〜7章は ~/work/ch1 〜 ~/work/ch7 で、第8章はホームで作業します。第1〜7章を途中からやり直すときは、 その章のディレクトリを消してから（rm -rf ~/work/ch4 のように）最初の行から打ってください。 ~/work はボリュームなので、檻を抜けても残っています。第8章は /tmp と索引を触るので、やり直すなら檻を入り直してください。

演習

8本あります。判定は観測できる結果だけで行い、コマンドの打ち方は見ません。 他人の立場が要るものは、判定が alice・bob・carol として実際に読んだり消したりして確かめます。 詰まったら lab hint NN を何度でも。使い切ったら lab solve NN で模範解答に必ず届きます （見ても構いません。進捗には「solve を見た」として残ります）。

Noやること副題目安
01一覧は見せずに、1つのファイルだけ読ませる1.02.110分
02次に開くシェルでも 640 と 750 で作られるようにする1.02.110分
03devs の共有ディレクトリを作る1.02.112分
04設定ファイルを、時刻ごと控えておく1.02.210分
05大きな .tmp だけを、深いところまで消す1.02.212分
06project を tar.xz にまとめる1.02.210分
07current を v2 に切り替える1.02.310分
08locate で見つからない2つを、見つかるようにする1.02.412分

先に読む場合は 理論編（8章）へ。 章と演習は1対1で対応しているので、どちらから始めても構いません。

lab reset NN で演習を配られたときの状態に戻すと、~/work/NN はディレクトリごと作り直されます。 そのディレクトリの中にいたなら、続けて cd ~/work/NN と打ち直してください（打たないと、消えた古いディレクトリに残ったままになり、ls は何も出さず、cat などは No such file or directory になります）。

もともと環境ごとに変わるものは、違っていても正常です: 時刻、inode 番号、dd の秒数と速度、tar を圧縮した大きさ（中に時刻が入るので、数十バイト変わることがある）。 また本文は、作業ボリュームが ext4 の上にある環境で記録しました。母艦が xfs や btrfs だと、 ディレクトリの大きさの欄（4096）と、ls -l の total、ディレクトリのリンク数が変わることがあります（第7章）。 umask が 0022 以外なら、入り方（docker exec ではないか）から見てください。

docker volume rm lab-linuc-files-work lab-linuc-files-state     # 作業と進捗も消す場合だけ
