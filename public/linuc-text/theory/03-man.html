3. man が説明しているのは、打ったものと別物のことがある

man echo には --version というオプションが書いてある。ところが echo --version と打つと、--version という文字がそのまま出てくる。読んだ説明書は /usr/bin/echo のもので、打ったのはシェルに組み込まれた別の echo だった。

前提: 第2章（type）前提: 檻が起動している所要 14分影響度 A出題範囲 1.03.1（重要度4）最終検証 2026-10-13

この章のゴール

  • 組み込みコマンドの説明は help で、外部コマンドの説明は man で引くと使い分けられる
  • セクション番号（1・5・7・8）を指定して、同じ名前の別のページを開ける
  • 名前を知らないときに man -k（apropos）で、名前を知っているときに man -f（whatis）で探せる
ここで覚えなくていいこと: man ページの書き方（groff）、MANPATH と /etc/manpath.config の細部、info コマンド、mandb による索引の作り直し。日本語の man ページはこの檻には入れていない。

説明書と、打ったものが食い違う

この節で分かること: man が説明していないコマンドがあることと、その見分け方。

ふつうこう考える

man echo に --version と書いてあるのだから、echo --version と打てば版が出るはずだ。 man はそのコマンドの説明書なのだから。

$ man -f echo
echo (1)             - display a line of text
$ man echo | grep -A1 "^NAME"
NAME
       echo - display a line of text
$ man echo | grep -E "^ +--version"
       --version
$ echo --version
--version
だめな理由: 版は出ず、--version という文字が出力された。 打った echo は、man が説明している echo ではなかった。 第2章で見たとおり、シェルは PATH を探す前に組み込みコマンドを使う。 組み込みの echo は --version を知らないので、ただの文字として出した。 man の echo(1) は、/usr/bin/echo という別のプログラムの説明書である。
$ type echo
echo is a shell builtin
$ type -a echo
echo is a shell builtin
echo is /usr/bin/echo
echo is /bin/echo
$ /usr/bin/echo --version | head -1
echo (GNU coreutils) 9.4
$ help echo | head -3
echo: echo [-neE] [arg ...]
    Write arguments to the standard output.

type -a は同じ名前を全部並べる。先頭の「shell builtin」が、名前だけで打ったときに動くものだ。/usr/bin/echo と場所を書けば、man が説明しているほうが動いて版を出す。組み込みのほうの説明は help が出す。

組み込みにしか無いコマンドは、man を引いても何も出てこない。

$ man cd; echo "exit=$?"
No manual entry for cd
exit=16
$ man -f cd; echo "exit=$?"
cd: nothing appropriate.
exit=16
$ type cd
cd is a shell builtin
$ help cd | head -3
cd: cd [-L|[-P [-e]] [-@]] [dir]
    Change the shell working directory.
    
$ man bash | grep -E "^ +history \[n\]"
       history [n]

cd も history も組み込みコマンドで、Ubuntu では独立した man ページが無い（RHEL 系の bash パッケージのように、組み込みコマンドの名前で man ページを入れているディストリビューションもある）。どの環境でも確実に引けるのは help で、まとまった説明は man bash の中（SHELL BUILTIN COMMANDS の節）にある。

たとえ: ホテルの部屋に備え付けのドライヤーと、フロントで貸し出す高機能なドライヤーがあり、 説明書はフロントの機種のものしか置いていない状況に近い。「ターボボタン」と書いてあっても、手元の備え付けには付いていない。
ただし崩れる点: ドライヤーは見た目で別物と分かるが、コマンドは名前が同じで画面からは区別できない。 type で聞くまで、どちらが動くかは分からない。

同じ名前でも、セクションごとに別のページがある

この節で分かること: セクション番号の意味と、指定して開く方法。
$ man -f passwd
passwd (1)           - change user password
passwd (5)           - the password file
$ whatis passwd
passwd (1)           - change user password
passwd (5)           - the password file
$ man -w passwd
/usr/share/man/man1/passwd.1.gz
$ man -w 5 passwd
/usr/share/man/man5/passwd.5.gz
$ man passwd | grep -A1 "^NAME"
NAME
       passwd - change user password
$ man 5 passwd | grep -A1 "^NAME"
NAME
       passwd - the password file

passwd という名前のページは2つある。passwd(1) はパスワードを変えるコマンド、passwd(5) は /etc/passwd というファイルの書式だ。番号を付けずに man passwd と打つと、先に見つかったセクション1が開く。/etc/passwd の書式を読みたいなら man 5 passwd と番号を書く。man -w は、開くファイルの場所を出す。ディレクトリ名の man1 man5 がセクション番号である。

$ ls -1d /usr/share/man/man[0-9]
/usr/share/man/man1
/usr/share/man/man2
/usr/share/man/man3
/usr/share/man/man4
/usr/share/man/man5
/usr/share/man/man6
/usr/share/man/man7
/usr/share/man/man8

-1 は1行に1つずつ並べる指定。付けずに端末で打つと、端末の幅に合わせて横にも並べる（ファイルやパイプに出すときは、付けなくても1行に1つ）。

セクション中身例
1一般ユーザのコマンドls(1) passwd(1) grep(1)
2システムコールopen(2)
3ライブラリ関数printf(3)
4デバイスファイルnull(4)
5設定ファイルの書式passwd(5) crontab(5)
6ゲーム—
7概念・規約・その他regex(7) hier(7)
8管理者用のコマンドuseradd(8) mount(8)

セクション3の中心になる C ライブラリ関数のページ（プログラムを書く人向けの manpages-dev）は、この檻には入れていない。だから printf はセクション1しか見つからない。セクション3の棚が空なのではなく、ほかのパッケージが入れたページ（gawk の拡張など）は20ある。

$ ls /usr/share/man/man3 | wc -l
20
$ ls /usr/share/man/man3 | head -3
filefuncs.3am.gz
fnmatch.3am.gz
fork.3am.gz
$ man -f printf
printf (1)           - format and print data
$ man -w 3 printf; echo "exit=$?"
No manual entry for printf in section 3
exit=16

試験の問題文や man の中では、passwd(5) のように名前の後ろに括弧でセクション番号を書いて区別する。出題範囲の「regex(7)」も、「セクション7の regex のページ」という意味である。

たとえ: 図書館の分類番号に近い。「パスワード」という同じ題の本が、 「使い方の棚（1）」と「様式集の棚（5）」に1冊ずつある。番号を言わずに頼むと、先に見つかった棚の本を渡される。
ただし崩れる点: 図書館なら司書が「どちらの本ですか」と聞き返してくれるが、 man は聞き返さない。黙って最初の1冊を開く。2冊目があることは man -f を打たないと分からない。

名前を知らないときは、説明の一行から探す

この節で分かること: man -k と man -f の違い。
$ man -k "^regex"
regex (7)            - POSIX.2 regular expressions
$ apropos "^regex"
regex (7)            - POSIX.2 regular expressions
$ man -f regex
regex (7)            - POSIX.2 regular expressions
$ man 7 regex | grep -A1 "^NAME"
NAME
       regex - POSIX.2 regular expressions
$ man -k "regular expression" | sort
re_format (7)        - POSIX.2 regular expressions
regex (7)            - POSIX.2 regular expressions
zegrep (1)           - search possibly compressed files for a regular expression
zfgrep (1)           - search possibly compressed files for a regular expression
zgrep (1)            - search possibly compressed files for a regular expression

man -k（apropos と同じ）は、各ページの名前とNAME 欄の一行説明を、正規表現で探す。"regular expression" のように、名前を知らなくても説明の言葉から当たる。man -f（whatis と同じ）は、名前が完全に一致するページだけを、セクション番号付きで出す。

打ち方同じもの探す対象使いどころ
man -k 語apropos 語名前と一行説明（部分一致・正規表現）名前を知らない
man -f 名前whatis 名前名前（完全一致）どのセクションにあるかを知りたい
man -w 名前—開くファイルの場所どのファイルを読んでいるか確かめる
たとえ: man -f は本の題名で引く目録、man -k は帯の宣伝文句まで含めた全文検索に近い。 題名を正確に知っていれば目録が速いが、「正規表現の本はないか」なら宣伝文句から探すしかない。
ただし崩れる点: 全文検索といっても、man -k が見るのは NAME 欄の一行だけで、本文は探さない。 本文にしか出てこない言葉では当たらない。

man の画面の読み方

この節で分かること: man を開いた後の操作と、ページの読む順番。

man ls と打つと、ページャ（既定は less）で画面いっぱいに開く。操作は less と同じである（第4章）。

キー動き
Space / b1画面進む / 戻る
/文字列 Enter下向きに探す。n で次、N で前
g / G先頭 / 末尾へ
h操作の一覧
q閉じる

ページは NAME（一行説明）→ SYNOPSIS（書式）→ DESCRIPTION（説明とオプション）→ SEE ALSO（関連ページ）の順に並ぶ。SYNOPSIS の [ ] は省略できる部分、... は繰り返せる部分を表す。オプションの説明は、/ で -l のように探すのが速い。

$ man ls | grep -E "^ +-l +"
       -l     use a long listing format
$ man ls | grep -A1 -E "^ +-a, --all"
       -a, --all
              do not ignore entries starting with .

man は端末の幅に合わせて文章を折り返す（パイプの先に出すときも、端末の幅を見る）。説明の段落は読者の画面の幅で折り返し位置が変わるので、この教材では幅に左右されない短い行だけを載せている。

確認

/etc/passwd の各欄の意味を man で調べたい。正しい打ち方はどれか。

A. man passwd　B. man 5 passwd　C. man -k /etc/passwd　D. man 1 passwd

答え

B。ファイルの書式はセクション5にある。A と D はセクション1（パスワードを変えるコマンド）を開く。 どのセクションにあるか分からなければ、先に man -f passwd で一覧を見る。

確認

「regular expression」という語を一行説明に含む man ページの一覧を出すコマンドを2つ挙げよ。

答え

man -k "regular expression" と apropos "regular expression"。 実測では re_format(7) regex(7) zgrep(1) などが並んだ。 man -f（whatis）は名前が完全に一致するものしか出さない。

確認

man cd が No manual entry for cd になった。理由と、cd の説明を読む方法を答えよ。

答え

cd は bash の組み込みコマンドで、Ubuntu には独立した man ページが無いため（type cd で shell builtin と出る）。 どの環境でも確実なのは help cd。まとまった説明は man bash の SHELL BUILTIN COMMANDS の節にある。

手を動かす: 実践編の演習03で uniq の数え方に詰まったら、man uniq を開いて /count と探してみる。 ヒントを読む前に man で答えにたどり着けるかが、この章の練習になる。

この章で分かったこと

持ち帰ってほしいこと

  • 名前だけで打ったコマンドが組み込みなら、man の説明は別物（外部コマンド）のもの。type で確かめ、組み込みは help で引く
  • 同じ名前のページがセクションごとにある。1 はコマンド、5 はファイルの書式、7 は概念（regex(7)）、8 は管理コマンド
  • man 5 passwd のように番号を指定して開く。man -f（whatis）でどのセクションにあるかを見る
  • 名前を知らないときは man -k（apropos）で一行説明から探す
  • 開いた後は / で探して n で次、q で閉じる
