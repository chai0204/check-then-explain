2. コマンドを探すのはシェルで、カレントは探さない

ls と打つと動くのに、目の前にある hello.sh と打つと command not found になる。打った名前のファイルを探しているのはシェルで、探す場所は PATH に書かれたディレクトリだけだからだ。この章では、その探し方と、打ったコマンドの記録（履歴）がいつファイルに残るかを確かめる。

前提: 第1章前提: 檻が起動している所要 20分影響度 B出題範囲 1.03.1（重要度4）最終検証 2026-10-13

この章のゴール

  • hello.sh / ./hello.sh / bash hello.sh / . hello.sh の違いを、PATH と実行権とプロセスで説明できる
  • 絶対パスと相対パスを、pwd と . .. から読み解ける
  • history と !! !番号 !文字列 を使えて、.bash_history に書かれるタイミングを言える
ここで覚えなくていいこと: hash の詳しい動き、alias の作り方、fc の細かい使い方、whereis と locate（主題1.02 の側）。履歴の検索キー（Ctrl+R）は便利だが試験では名前だけ知っていればよい。

目の前にあるのに、見つからない

この節で分かること: 名前だけで打ったコマンドを、シェルがどこで探しているか。

ふつうこう考える

今いるディレクトリにあるファイルなのだから、名前を打てば動くはずだ。 ls も cat も名前だけで動いている。

$ cd ~/text
$ pwd
/home/lab/text
$ ls -l hello.sh cdtest.sh
-rw-r--r-- 1 lab lab 48 Oct 13 09:00 cdtest.sh
-rw-r--r-- 1 lab lab 33 Oct 13 09:00 hello.sh
$ cat hello.sh
#!/bin/bash
echo "hello from $0"
$ hello.sh; echo "exit=$?"
bash: hello.sh: command not found
exit=127
だめな理由: シェルは名前だけのコマンドを、環境変数 PATH に並んだディレクトリの中だけで探す。 今いるディレクトリ（カレントディレクトリ）は、PATH に書かれていなければ探さない。 終了コード 127 は「見つからなかった」という意味である。
$ echo "$PATH"
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

PATH はコロン区切りのディレクトリの並びで、シェルは前から順に探し、最初に見つかったものを実行する。ls は /usr/bin にあるので見つかる。/home/lab/text はこの並びに無い。

では場所を書いて打つ。名前に / が入っていると、シェルは PATH を使わず、その場所を直接開く。

$ ./hello.sh; echo "exit=$?"
bash: ./hello.sh: Permission denied
exit=126
$ bash hello.sh
hello from hello.sh
$ chmod +x hello.sh
$ ./hello.sh
hello from ./hello.sh

今度は見つかったが、終了コード 126（見つかったが実行できない）になった。ls -l で見たとおり、hello.sh には実行権（x）が無い。bash hello.sh が動くのは、実行しているのが bash で、hello.sh は bash が読むだけのファイルだからである。chmod +x で実行権を付けると、./hello.sh でも動く。

スクリプトが出した $0（自分がどう呼ばれたか）が、打ち方ごとに違うことにも注目する。シェルが組み立てて渡した名前が、そのまま届いている。

打ち方PATH を探すか実行権どこで動くか
hello.sh探す（カレントは探さない）要る子プロセス
./hello.sh探さない（/ を含むので、その場所を開く）要る子プロセス
bash hello.shbash を探す要らない（読むだけ）子プロセス（新しい bash）
. hello.sh / source hello.sh—要らない今のシェル（次の節）
たとえ: 電話の短縮ダイヤルに近い。名前だけで掛けられるのは、登録簿（PATH）に載っている相手だけで、 目の前の机に名刺が置いてあっても、登録していなければ掛からない。番号を全部押せば（./hello.sh や絶対パス）、登録簿は使われない。
ただし崩れる点: 短縮ダイヤルは同じ名前が2つあれば迷うが、PATH は前から順に探して最初の1つで止まる。 後ろのディレクトリに同じ名前があっても、黙って隠れる。

絶対パスと相対パス

この節で分かること: 同じファイルを3通りの書き方で指せる理由。
$ ~/text/hello.sh
hello from /home/lab/text/hello.sh
$ /home/lab/text/hello.sh
hello from /home/lab/text/hello.sh
$ cd /tmp
$ ../home/lab/text/hello.sh
hello from ../home/lab/text/hello.sh
$ cd ~/text

/ から始まるのが絶対パスで、どこにいても同じ場所を指す。~ はシェルがホームディレクトリ（/home/lab）に置き換える。.. から始まるのは相対パスで、pwd が示す今いる場所から数える。/tmp にいたので、..（ひとつ上）が / になり、そこから home/lab/text/hello.sh をたどった。

. と .. は記号ではなく、どのディレクトリにも実際に入っている名前である。

$ ls -ld . ..
drwxr-xr-x 1 lab lab 4096 Oct 13 09:00 .
drwxr-x--- 1 lab lab 4096 Oct 13 09:00 ..
$ cd ..; pwd
/home/lab
$ cd text; pwd
/home/lab/text
$ cd /usr/share; pwd
/usr/share
$ cd -
/home/lab/text

cd - は直前にいたディレクトリへ戻り、戻った先を表示する。

たとえ: 絶対パスは住所、相対パスは道案内（「ここから1つ上の階に上がって、右の部屋」）に近い。 住所はどこから読んでも同じ建物を指すが、道案内は出発点が変わると別の場所に着く。
ただし崩れる点: 道案内は出発点を口で確認できるが、相対パスの出発点はそのプロセスのカレントディレクトリで、画面には出ていない。 迷ったら pwd で確かめるしかない。

シェルが先に答えるものと、. で読み込むもの

この節で分かること: PATH を探す前にシェルが自分で処理するものと、.（ドット）コマンドの意味。
$ type ls
ls is aliased to `ls --color=auto'
$ type cd
cd is a shell builtin
$ type pwd
pwd is a shell builtin
$ type -a pwd
pwd is a shell builtin
pwd is /usr/bin/pwd
pwd is /bin/pwd
$ type hello.sh
bash: type: hello.sh: not found
$ which ls
/usr/bin/ls

type は「この名前を打ったら、シェルが何を実行するか」を答える。ls は ~/.bashrc が定義したエイリアス（色付きで出す ls --color=auto に置き換える）、cd と pwd はシェル自身が持つ組み込みコマンドである。pwd は /usr/bin/pwd という外部コマンドもあるが、組み込みが先に使われる。シェルの順番は「エイリアス → 関数 → 組み込みコマンド → PATH の順に探す」だ。

cd が組み込みなのには理由がある。カレントディレクトリはプロセスごとに持つもので、子プロセスが移動しても親は動かない。

$ cat cdtest.sh
cd /tmp
echo "スクリプトの中では $PWD"
$ bash cdtest.sh
スクリプトの中では /tmp
$ pwd
/home/lab/text
$ . cdtest.sh
スクリプトの中では /tmp
$ pwd
/tmp

bash cdtest.sh は子の bash の中で /tmp に移ったが、終わって戻ってくると親は ~/text のままだった。.（ドット。source と同じ）は、ファイルを今のシェルで読み込んで実行する。だから cd が今のシェルに効いた。~/.bashrc を書き換えた後に . ~/.bashrc と打つのは、この性質を使っている。

最後に、PATH にディレクトリを足すと、名前だけで動くようになることを確かめる。

$ cd ~/text
$ PATH="$PATH:$HOME/text"
$ hello.sh
hello from /home/lab/text/hello.sh
$ type hello.sh
hello.sh is hashed (/home/lab/text/hello.sh)
$ cd /; hello.sh; cd ~/text
hello from /home/lab/text/hello.sh

PATH はもともと環境変数なので、書き換えた値は子プロセスにも渡る（第1章）。hashed は「一度見つけた場所を覚えておいた」という意味で、次からは探し直さない。引用符の中で ~ は展開されないので、$HOME と書いている。

確認

カレントディレクトリにある実行権付きのスクリプト run.sh を実行する打ち方として正しいものを、すべて選べ（カレントディレクトリは PATH に含まれていない）。

A. run.sh　B. ./run.sh　C. bash run.sh　D. $PWD/run.sh

答え

B・C・D。A は PATH の中だけを探すので command not found（終了コード 127）になる。 D の $PWD はシェルがカレントディレクトリの絶対パスに置き換える。

確認

/home/lab/text にいるとき、cd ../../../tmp を実行すると、どこへ移るか。

答え

/tmp。.. を3回たどると /home/lab → /home → / になり、そこから tmp へ入る。 相対パスは、いる場所（pwd）から数える。

履歴は、打ったものを全部は残さない

この節で分かること: history の使い方と、.bash_history にいつ何が書かれるか。

打ったコマンドは、シェルが番号を付けて覚えている。設定は ~/.bashrc にある。

$ grep -n HIST ~/.bashrc
13:HISTCONTROL=ignoreboth
18:# for setting history length see HISTSIZE and HISTFILESIZE in bash(1)
19:HISTSIZE=1000
20:HISTFILESIZE=2000
$ echo "HISTFILE=$HISTFILE HISTSIZE=$HISTSIZE HISTFILESIZE=$HISTFILESIZE HISTCONTROL=$HISTCONTROL"
HISTFILE=/home/lab/.bash_history HISTSIZE=1000 HISTFILESIZE=2000 HISTCONTROL=ignoreboth
$ ls -l ~/.bash_history; echo "exit=$?"
ls: cannot access '/home/lab/.bash_history': No such file or directory
exit=2

覚えておく件数が HISTSIZE（メモリの中）、保存するファイルが HISTFILE、ファイルに残す行数が HISTFILESIZE である。そして起動したばかりの檻には、.bash_history がまだ無い。

ここからは、端末の上で対話的に打った記録である（プロンプトは $ にそろえてある）。子の bash を1つ起動して、その中で打ち、抜けた後でファイルを見る。

$ bash
$ history -c
$ echo 一行目
一行目
$ echo 二行目
二行目
$ history
    1  echo 一行目
    2  echo 二行目
    3  history
$ !1
echo 一行目
一行目
$ !ec
echo 一行目
一行目
$ !!
echo 一行目
一行目

history -c で一度空にしてから打ったので、番号が 1 から振られている。!1（1番を再実行）、!ec（ec で始まる最新のものを再実行）、!!（直前を再実行）は、どれも展開した結果を1行表示してから実行した。これをヒストリ展開という。! を書き換えたのはシェルで、echo に届いたのは展開後の echo 一行目 である。

$  echo 先頭に空白を置いた
先頭に空白を置いた
$ echo 二行目
二行目
$ echo 二行目
二行目
$ history
    1  echo 一行目
    2  echo 二行目
    3  history
    4  echo 一行目
    5  echo 二行目
    6  history
$ history 2
    6  history
    7  history 2

打ったのは11回なのに、履歴は7件しかない。

  • 先頭に空白を置いた echo 先頭に空白を置いた が無い
  • !1 !ec !! で同じ echo 一行目 を続けて打った分は、1件にまとまっている
  • 続けて2回打った echo 二行目 も1件

Ubuntu の ~/.bashrc にある HISTCONTROL=ignoreboth が、「空白で始まる行（ignorespace）」と「直前と同じ行（ignoredups）」の両方を記録しない設定だからである。

$ tail -3 ~/.bash_history
tail: cannot open '/home/lab/.bash_history' for reading: No such file or directory
$ exit
exit
$ tail -5 ~/.bash_history
echo 二行目
history
history 2
tail -3 ~/.bash_history
exit

子の bash の中から見たとき、.bash_history はまだ存在しなかった。exit で抜けた後に初めて、子の履歴がファイルに書かれている。履歴は打った瞬間ではなく、シェルが終わるときにまとめてファイルへ書かれる。

操作意味
history / history 5履歴を番号付きで表示する / 最後の5件だけ
!!直前のコマンドを再実行
!番号その番号のコマンドを再実行
!文字列その文字列で始まる最新のコマンドを再実行
history -cメモリ上の履歴を消す（ファイルはそのまま）
history -w / history -a今すぐファイルに書く（全部 / 増えた分だけ）
↑ ↓ / Ctrl+R履歴をたどる / 文字列で後ろ向きに検索する
たとえ: 会議の議事録係に近い。発言はその場でメモされる（history で見える）が、 清書して共有フォルダ（.bash_history）に置くのは会議が終わってから。 しかもこの係は「前置きの雑談（空白で始まる行）」と「同じことの繰り返し」をメモしない方針になっている。
ただし崩れる点: 議事録係は1人だが、bash は端末ごとに別の係がいる。 2つの端末を開いていると、それぞれが自分のメモを閉じるときに書き足すので、ファイルの中で順番が入り混じる。
確認

bash で、直前に実行したコマンドをもう一度実行する入力はどれか。

A. !!　B. !-0　C. history -r　D. $$

答え

A。!! は直前のコマンドに展開され、展開結果を表示してから実行される。 $$ はシェル自身のプロセス ID である。

確認

bash のコマンド履歴が既定で保存されるファイルはどれか。また、それはいつ書き込まれるか。

答え

~/.bash_history（変数 HISTFILE で変えられる）。既定ではシェルの終了時にまとめて書き込まれる。 実測では、子の bash の中から見たときは存在せず、exit した後には子で打った行が入っていた（末尾の5行を表示した）。

手を動かす: 実践編の演習02は、自分で用意したコマンドをどこからでも名前だけで動かす課題である。 判定は /tmp に移ってから探すので、PATH に相対パスを足すと必ず鳴る。

この章で分かったこと

持ち帰ってほしいこと

  • 名前だけのコマンドは、シェルが PATH の並びの中だけを前から探す。カレントディレクトリは探さない
  • / を含む名前は PATH を使わない。だから ./hello.sh。127 は見つからない、126 は実行できない
  • bash file は実行権が要らず子で動く。. file（source）は今のシェルで動くので cd や変数が残る
  • 絶対パスは / から、相対パスは pwd から数える。. と .. は実在する名前
  • !! !番号 !文字列 はシェルが展開してから実行する。HISTCONTROL=ignoreboth で空白始まりと連続した重複は残らない
  • .bash_history に書かれるのはシェルの終了時
