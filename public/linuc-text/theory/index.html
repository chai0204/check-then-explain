理論編 — GNU と Unix のコマンド

この10章を貫いている1つの事実

コマンドが受け取るのは、シェルが組み立て終えた後の文字列だけである。引用符・変数・ワイルドカード・リダイレクト・パイプは、コマンドが動き出す前にシェルが片づけている。

echo '$HOME' が $HOME と出るのも、sort f > f が空になるのも、grep a* file が何も出さないのも、 xargs に渡した名前が空白で割れるのも、同じ理由です。出力が予想と違ったら、 「このコマンドは何を受け取ったか」と問えば説明がつきます。出題範囲に記号（>> 2>&1 |）が並ぶのは、それがシェルの仕事だからです。

ここで覚えなくていいこと: シェルスクリプトの書き方（if for 関数。主題1.06）、awk、Perl 互換の正規表現、 vim の設定とプラグイン、emacs のキー操作の細部。どれも主題1.03 の出題範囲の外です。

章

  1. 引用符と変数は、コマンドに届く前に片づく — echo '$HOME' と "$HOME" の差を作ったのはシェル。export しない変数は子に届かない（15分）
  2. コマンドを探すのはシェルで、カレントは探さない — 目の前の hello.sh が command not found。履歴は11回打って7件、ファイルに書かれるのは終了時（20分）
  3. man が説明しているのは、打ったものと別物のことがある — echo --version が --version と出る。セクション番号と man -k / -f（14分）
  4. 1行とは、改行で終わっている範囲のこと — 2行見えるのに wc -l は 1。見た目が同じで2バイト違うファイル（16分）
  5. uniq は隣どうししか比べない — apple が3行あるのに2回残る。cut -d' ' が空の欄を数える（20分）
  6. sed は書き換えた結果を見せるだけ — 画面に出た 9090 はファイルに無い。-i は i ノードを変える（22分）
  7. リダイレクトは、左から順に配線する — 2>&1 > f ではエラーが画面に残る。sort f > f は0バイト（18分）
  8. xargs は空白で区切って引数にする — 3つのファイルを渡して「見つからない」が5つ。-print0 と -0（20分）
  9. . は何にでも当たる1文字 — grep 10.0.0.5 が4行全部に当たる。grep a* はシェルに先に食べられる（22分）
  10. :w! は、読み取り専用のファイルにも書く — 444 のファイルが書き換わり、権限は 444 のまま。EDITOR は export しないと届かない。ここで10章が1本になる（25分）

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの4つに集まります。

場面ここで効く理由見落としやすい点関連する章
ログを集計する cut | sort | uniq -c | sort -rn で、件数の多い順が1行で出る uniq の前の sort。Windows から来たログは行末に \r が残り、$ で当たらない4・5・9
設定ファイルを一括で書き換える sed -i.bak で、エディタを開かずに同じ変更を何台にも当てられる ^ で位置を決めないと別の行も変わる。-i はファイルを作り直すので、ハードリンクは古いまま残る6・9
スクリプトの出力を残す > log 2>&1 で、成功も失敗も1つのファイルに、書かれた順に残る 2>&1 を先に書くとエラーだけ画面に残る。> は毎回空にする。標準出力をためてから書くプログラムでは、エラーの行が先に入ることがある7
大量のファイルをまとめて処理する find ... | xargs で、何千ものファイルに1つのコマンドを当てられる 名前の空白で割れる。-print0 と -0 を常に付ける習慣にする8

この主題の道具を使わない方がよい場面も1つあります。 JSON や、欄の中にカンマや改行を含む CSV を、cut や sed で切り刻むことです。 この章の道具はどれも「区切り文字はちょうど1文字で、行は改行で終わる」という前提で動くので、 引用符で囲まれた欄の中のカンマも区切りとして扱ってしまいます。構造のあるデータには、その形式を読める専用の道具（jq など）を使います。
