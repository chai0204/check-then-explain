6. sed は書き換えた結果を見せるだけ

sed 's/8080/9090/' app.conf と打つと、画面には port=9090 が出る。そのあと app.conf を見ると 8080 のままだ。sed は読んだものを加工して標準出力に流すフィルタで、ファイルを書き換えるのは -i を付けたときだけ。しかも -i でさえ、同じファイルを書き換えてはいなかった。

前提: 第5章前提: 檻が起動している所要 22分影響度 B出題範囲 1.03.2（重要度3）出題範囲 1.03.4（重要度2）最終検証 2026-10-13

この章のゴール

  • sed の s（置換）・d（削除）・-n と p（表示）を、行番号やパターンで行を選んで使える
  • s///g の g と、^ で行頭に限る意味を言える
  • -i と -i.bak の違いと、-i がファイルを作り直していることを説明できる
  • expand unexpand fmt pr split の役割と主なオプションを言える
ここで覚えなくていいこと: ホールドスペース（h g x）、複数行をまたぐ処理（N）、a i c コマンドの細かい書き方、pr のヘッダの書式指定、split の接尾辞の長さ。正規表現そのものは第9章で扱う。

sed はファイルを書き換えない

この節で分かること: sed が何を読んで、どこへ出しているか。

ふつうこう考える

sed は「ストリームエディタ」で、エディタなのだから、置換すればファイルが書き換わるはずだ。 画面に新しい中身が出たのは、書き換えた結果を見せてくれているのだろう。

$ cd ~/text
$ cat app.conf
# app.conf - 練習用の設定ファイル
host=localhost
port=8080
port_admin=8081
# debug=true
log_level=info
url=http://localhost:8080/?lang=ja
$ sed "s/8080/9090/" app.conf
# app.conf - 練習用の設定ファイル
host=localhost
port=9090
port_admin=8081
# debug=true
log_level=info
url=http://localhost:9090/?lang=ja
$ grep -c 9090 app.conf
0
だめな理由: 画面には 9090 が2行出たのに、ファイルの中の 9090 は 0 行だった。 sed はファイルを読むだけで、1行ずつコマンドを当てた結果を標準出力に流す。 cat や tr と同じフィルタである。書き換えたファイルが欲しいなら、 -i を付けるか、出力を別のファイルにリダイレクトする（同じファイルへのリダイレクトは空になる。第7章）。
たとえ: 原稿を読みながら赤を入れた清書を別の紙に書いていく校正者に近い。元の原稿には一切書き込まない。
ただし崩れる点: 校正者は清書を机に残してくれるが、sed の清書は画面に流れて消える。 残したければ、受け取る先（ファイル）を自分で用意する必要がある。

置換 s の細部

この節で分かること: g の有無と、パターンがどこに当たるか。
$ sed "s/=/ = /" app.conf
# app.conf - 練習用の設定ファイル
host = localhost
port = 8080
port_admin = 8081
# debug = true
log_level = info
url = http://localhost:8080/?lang=ja
$ sed "s/=/ = /g" app.conf
# app.conf - 練習用の設定ファイル
host = localhost
port = 8080
port_admin = 8081
# debug = true
log_level = info
url = http://localhost:8080/?lang = ja

s/探す/置き換える/ は、各行で最初に見つかった1か所だけを置き換える。url=...?lang=ja の2つ目の = は、g（global）を付けたときだけ変わった。コメント行の # debug=true も、= を含むので変わっている。

$ sed "s/port/PORT/" app.conf
# app.conf - 練習用の設定ファイル
host=localhost
PORT=8080
PORT_admin=8081
# debug=true
log_level=info
url=http://localhost:8080/?lang=ja
$ sed "s/^port=/PORT=/" app.conf
# app.conf - 練習用の設定ファイル
host=localhost
PORT=8080
port_admin=8081
# debug=true
log_level=info
url=http://localhost:8080/?lang=ja

port とだけ書くと port_admin にも当たる。^（行頭）を付けて ^port= と書けば、port= で始まる行だけに当たる。/ を含む文字列を置き換えるときは、区切りを別の文字にしてよい。-E（拡張正規表現。第9章）を付けると、(...) で囲んだ部分を \1 \2 で置き換え側に持ち込める。

$ sed "s|http://localhost|https://example.com|" app.conf | tail -1
url=https://example.com:8080/?lang=ja
$ sed -E "s/^([a-z_]+)=(.*)$/\1: \2/" app.conf
# app.conf - 練習用の設定ファイル
host: localhost
port: 8080
port_admin: 8081
# debug=true
log_level: info
url: http://localhost:8080/?lang=ja
$ sed "y/abc/ABC/" fruits.txt
BAnAnA
Apple
Cherry
Apple
Apple
BAnAnA
DuriAn

y/abc/ABC/ は1文字ずつの置き換えで、tr abc ABC と同じことをする。

-E を付けない既定の基本正規表現では、( ) はただの文字で、まとめるには \( \) と書く。( ) のまま \1 を使うと、sed は「参照する組が無い」と拒否する。

$ sed "s/^(port)=/\1: /" app.conf; echo "exit=$?"
sed: -e expression #1, char 16: invalid reference \1 on `s' command's RHS
exit=1
$ sed "s/^\(port\)=/\1: /" app.conf | grep "^port:"
port: 8080
$ sed -E "s/^(port)=/\1: /" app.conf | grep "^port:"
port: 8080

行を選ぶ — 行番号とパターン

この節で分かること: どの行にコマンドを当てるかの指定と、-n の意味。
$ sed -n "2,4p" app.conf
host=localhost
port=8080
port_admin=8081
$ sed -n "/port/p" app.conf
port=8080
port_admin=8081
$ sed "/^#/d" app.conf
host=localhost
port=8080
port_admin=8081
log_level=info
url=http://localhost:8080/?lang=ja
$ sed "1d" app.conf
host=localhost
port=8080
port_admin=8081
# debug=true
log_level=info
url=http://localhost:8080/?lang=ja
$ sed "\$d" app.conf
# app.conf - 練習用の設定ファイル
host=localhost
port=8080
port_admin=8081
# debug=true
log_level=info
$ sed -n "\$p" app.conf
url=http://localhost:8080/?lang=ja
$ sed "3q" app.conf
# app.conf - 練習用の設定ファイル
host=localhost
port=8080
$ sed -e "/^#/d" -e "s/8080/9090/g" app.conf
host=localhost
port=9090
port_admin=8081
log_level=info
url=http://localhost:9090/?lang=ja
$ sed "2i\\# ここに挿入" app.conf | head -4
# app.conf - 練習用の設定ファイル
# ここに挿入
host=localhost
port=8080

sed は何も指定しなければ全行を出す。-n はその自動の出力を止め、p を当てた行だけを出させる。d は当てた行を出さない。コマンドの前に書く行の指定（アドレス）は次のとおり。

書き方意味
3 / 2,4 / $3行目 / 2〜4行目 / 最後の行（二重引用符の中では \$ と書く）
/^#/パターンに当たる行（ここでは # で始まる行）
s/A/B/ / s/A/B/g最初の1か所を置換 / 全部置換
dその行を出さない（削除）
-n と p自動の出力を止め、p した行だけ出す
qその行を出したら終わる（3q は head -3 と同じ）
-e を複数コマンドを順に全部当てる
-i / -i.bak結果でファイルを置き換える / 元を .bak 付きで残す（次の節）

-i は、同じファイルを書き換えていない

この節で分かること: -i の裏で何が起きているか。
$ cp app.conf my.conf
$ ls -i my.conf
18371087 my.conf
$ sed -i "s/^port=8080/port=9090/" my.conf
$ ls -i my.conf
18371088 my.conf
$ grep ^port= my.conf
port=9090

書き換わった。ところが ls -i が出す番号（i ノード番号。ファイルの実体の番号）が変わっている。-i は結果を新しいファイルに書いてから、元の名前に付け替えている。番号そのものは環境ごとに違うので、見るのは「変わったかどうか」だけでよい。

$ sed -i.bak "/^#/d" my.conf
$ ls -1 my.conf*
my.conf
my.conf.bak
$ cat my.conf
host=localhost
port=9090
port_admin=8081
log_level=info
url=http://localhost:8080/?lang=ja
$ diff my.conf.bak my.conf
1d0
< # app.conf - 練習用の設定ファイル
5d3
< # debug=true

-i.bak は、作り直す前の中身を my.conf.bak として残す（-i と .bak の間に空白は入れない）。付け替える前の実体に、別の名前を残しておく仕組みだ。

「作り直している」ことは、同じ実体に2つ目の名前（ハードリンク。主題1.02）を付けておくと、はっきり見える。

$ ln my.conf hard.conf
$ ls -i my.conf hard.conf
18371087 hard.conf
18371087 my.conf
$ sed -i "s/^port=9090/port=7070/" my.conf
$ ls -i my.conf hard.conf
18371087 hard.conf
18371089 my.conf
$ grep ^port= my.conf hard.conf
my.conf:port=7070
hard.conf:port=9090

sed -i の後、my.conf だけが新しい実体に付け替えられ、hard.conf は古い実体（port=9090）を指したまま残った。

たとえ: 掲示板の紙に直接書き込むのではなく、清書した新しい紙に貼り替えるのに近い。 -i.bak は、はがした古い紙を「.bak」と書いた封筒に入れて残しておくことだ。
ただし崩れる点: 掲示板なら古い紙を見ていた人も、貼り替えに気づいて新しい紙を見に来る。 ハードリンクで同じ実体を指していた名前は気づかない。古い紙を持ったまま、黙って取り残される。

TAB を広げる・行を折り返す

この節で分かること: expand unexpand fmt が、空白と改行をどう作り直すか。
$ cat -A tabs.txt
name^Iage^Icity$
alice^I23^Itokyo$
bob^I7^Iosaka$
$ expand tabs.txt | cat -A
name    age     city$
alice   23      tokyo$
bob     7       osaka$
$ expand -t 4 tabs.txt | cat -A
name    age city$
alice   23  tokyo$
bob 7   osaka$

TAB は「次のタブ位置まで進める」という1文字で、タブ位置は既定で8桁ごとにある。expand は TAB を、そこまでの空白に置き換える。-t 4 は4桁ごとにする。unexpand は逆に、空白を TAB に戻す。

$ cat -A indent.txt
list:$
^Iapple   red$
^Ibanana  yellow$
$ expand indent.txt | cat -A
list:$
        apple   red$
        banana  yellow$
$ expand indent.txt | unexpand | cat -A
list:$
^Iapple   red$
^Ibanana  yellow$
$ expand indent.txt | unexpand -a | cat -A
list:$
^Iapple^Ired$
^Ibanana^Iyellow$

unexpand が TAB に戻したのは行頭の空白だけだった。apple と red の間の空白は、-a（all）を付けたときだけ TAB になった。

$ cat poem.txt
Text streams flow from one command to the next. Each filter reads its input, changes it a little, and writes the result for the next command.
$ fmt -w 40 poem.txt
Text streams flow from one command to
the next. Each filter reads its input,
changes it a little, and writes the
result for the next command.
$ fmt -w 40 poem.txt | wc -L
38
$ fmt -w 20 jp.txt
日本語の文には単語の間に空白が無いので、どこで折り返せばよいかを
fmt
は知らない。

fmt は段落の行を詰め直し、指定した幅（-w。既定は75桁）に収まるよう空白の位置で折り返す。wc -L（いちばん長い行の桁数）は 38 で、40 に収まっている。日本語の文は空白が無いので折り返せず、空白のあった fmt の前後でだけ切れた。

たとえ: TAB はタイプライターのタブストップ（あらかじめ決めた目盛りまで一気に送るキー）に近い。 何文字分進むかは、押した位置によって変わる。
ただし崩れる点: タイプライターの目盛りは機械ごとに自分で決めるが、ファイルの中の TAB は「どこまで進むか」を持っていない。 表示する道具の設定（既定は8桁）で見た目が変わるので、TAB でそろえた表は別の環境で崩れることがある。

ページを付ける・分割する — pr と split

この節で分かること: pr が付けるヘッダと、split の分け方と名前。
$ pr fruits.txt | head -5


2026-10-13 09:00                    fruits.txt                    Page 1
$ pr -3 -t fruits.txt
banana			apple			banana
apple			apple			Durian
cherry
$ pr -l 12 fruits.txt | grep -c "Page"
4

pr は印刷向けにページを組む。各ページの先頭に、ファイルの更新日時・名前・ページ番号のヘッダを付ける（日時は檻の中の fruits.txt が作られた時刻）。-3 は3段組み、-t はヘッダを付けない、-l 12 は1ページを12行にする（ヘッダと余白で10行使うので、本文は2行ずつになり4ページになった）。

$ seq 2500 > big.txt
$ split big.txt
$ wc -l xa*
 1000 xaa
 1000 xab
  500 xac
 2500 total
$ split -l 1000 -d big.txt part_
$ wc -l part_*
 1000 part_00
 1000 part_01
  500 part_02
 2500 total
$ cat xa* | cmp - big.txt; echo "exit=$?"
exit=0

split は既定で1000行ずつに分け、xaa xab … という名前を付ける。-l で行数、-d で接尾辞を数字に、最後の引数で名前の頭を変えられる。cat でつなげば元と1バイトも違わない（cmp の終了コード 0）。

$ split -n 2 fruits.txt half_; wc -c half_*
23 half_aa
23 half_ab
46 total
$ cat half_aa; echo "<-- ここまでが half_aa"
banana
apple
cherry
app<-- ここまでが half_aa
$ split -n l/2 fruits.txt line_; wc -l line_*
 4 line_aa
 3 line_ab
 7 total

-n 2 はバイト数で2等分するので、apple の途中で切れた。行の途中で切りたくなければ -n l/2（line）を使う。-b 100k のようにバイト数で分ける指定もある。

確認

sed でファイル a.txt のすべての foo を bar に置き換えて表示したい（1行に複数ある場合も全部）。正しいものはどれか。

A. sed 's/foo/bar/' a.txt　B. sed 's/foo/bar/g' a.txt　C. sed -n 's/foo/bar/' a.txt　D. sed 'y/foo/bar/' a.txt

答え

B。A は各行の最初の1か所だけ（実測の s/=/ = / と同じ）。C は -n で自動の出力が止まり何も出ない。 D は1文字ずつの置き換え（tr と同じ）で、foo という並びを探すものではない。

確認

config.txt を直接書き換え、書き換える前の内容を config.txt.orig として残したい。sed のオプションはどれか。

答え

sed -i.orig 's/.../.../' config.txt。-i の直後に、空白を入れずに拡張子を書く。 sed 's/.../.../' config.txt > config.txt はシェルが先にファイルを空にするので、空のファイルが残る（第7章）。

確認

ファイルの3行目から5行目だけを表示する sed の書き方を答えよ。

答え

sed -n '3,5p' ファイル。-n を付けないと、全行の自動の出力に加えて3〜5行目がもう一度出る。 head -5 ファイル | tail -3 でも同じ結果になる。

確認

2500行のファイル log.txt に、オプションを付けずに split log.txt を実行した。できるファイルの名前と行数を答えよ。

答え

xaa（1000行）、xab（1000行）、xac（500行）。実測の big.txt と同じ。

手を動かす: 実践編の演習04は、設定ファイルの1つの値だけを sed で書き換え、元を .bak で残す課題である。 ^ で行頭を決めないと、変えてはいけない行も変わったと観測される。

この章で分かったこと

持ち帰ってほしいこと

  • sed はファイルを読んで、結果を標準出力に流すだけ。ファイルを変えるのは -i
  • s/A/B/ は各行の最初の1か所、g で全部。^ で行頭に限る。-n と p で選んだ行だけ出す。d で消す
  • 行の指定は 3 2,4 $ /パターン/
  • -i は新しいファイルに書いて付け替える（i ノード番号が変わる）。-i.bak で元を残す
  • expand は TAB を空白に、unexpand は行頭の空白を TAB に（-a で全部）。fmt -w は空白の位置で折り返す
  • pr はヘッダ付きのページを組む。split は既定で1000行ずつ xaa xab …
