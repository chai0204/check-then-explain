9. . は何にでも当たる1文字

grep 10.0.0.5 ips.txt は、4行のうち4行すべてに当たる。. はピリオドではなく「任意の1文字」で、しかも grep は行のどこかに当たればその行を出す。grep に渡したのは IP アドレスではなく正規表現という小さな言語だった。そしてその言語は、grep に届く前にシェルに書き換えられることがある。

前提: 第8章まで前提: 檻が起動している所要 22分影響度 A出題範囲 1.03.4（重要度2）最終検証 2026-10-13

この章のゴール

  • 正規表現の部品（. * ^ $ [ ] [^ ] \、拡張の + ? { } | ( )）を読める
  • grep の -E -F -v -i -n -c -l -w -x -r を使い分けられる
  • 基本正規表現と拡張正規表現の違いと、egrep fgrep が何者かを言える
  • パターンを引用符で囲む理由を、シェルのワイルドカード展開から説明できる
ここで覚えなくていいこと: Perl 互換の正規表現（grep -P）、後方参照を使った検索、POSIX 文字クラス（[[:digit:]]）の全種類、最長一致の細かい規則。regex(7) の中身を全部読む必要もない。

. は、ピリオドではない

この節で分かること: grep がパターンをどう解釈し、行のどこに当てているか。

ふつうこう考える

grep 10.0.0.5 は「10.0.0.5 という文字列を含む行」を探す。だから 10.0.0.5 の行が1つだけ出るはずだ。

$ cd ~/text
$ cat ips.txt
10.0.0.5
10.0.0.50
110.0.0.5
ip-10-0-0-5
$ grep 10.0.0.5 ips.txt
10.0.0.5
10.0.0.50
110.0.0.5
ip-10-0-0-5
だめな理由: 4行全部が出た。理由は2つある。 1つは、grep のパターンが正規表現で、. が「任意の1文字」を表すこと。ip-10-0-0-5 は - が . に当たった。 もう1つは、grep が行のどこかに当たればその行を出すこと。10.0.0.50 と 110.0.0.5 は、行の一部が当たった。
$ grep -F 10.0.0.5 ips.txt
10.0.0.5
10.0.0.50
110.0.0.5
$ grep "10\.0\.0\.5" ips.txt
10.0.0.5
10.0.0.50
110.0.0.5
$ grep -x "10\.0\.0\.5" ips.txt
10.0.0.5
$ grep -w 10.0.0.5 ips.txt
10.0.0.5
ip-10-0-0-5
$ grep -Fx 10.0.0.5 ips.txt
10.0.0.5

-F（fixed strings）は正規表現として読まず、文字どおりに探す。\. は「. の特別な意味を消す」書き方で、-F と同じ3行になった。それでも部分一致は残る。-x は行全体が一致するものだけ、-w は前後が単語の区切りになっているものだけを出す。-w は - を単語の区切りと見るので、ip-10-0-0-5 がまた当たった。

部品意味例
.任意の1文字a.c は abc, a-c, a.c
*直前の1文字（か部品）の0回以上の繰り返しan*a は aa, ana, anna
^ / $行頭 / 行末^# は # で始まる行
[abc] / [a-z]括弧の中のどれか1文字 / 範囲^[A-Z] は大文字で始まる行
[^ ]括弧の中以外の1文字[^ ] は空白以外の1文字
\直後の記号の特別な意味を消す\. はピリオドそのもの
たとえ: 新聞の伏せ字（○）に近い。「1○.○.○.5」と書けば、○にはどんな文字でも入れられる。
ただし崩れる点: 伏せ字は「元の文字が何かは決まっているが隠している」印だが、. は「どの1文字でもよい」という指定で、 - でも . でも同じように当たる。しかも grep は文の途中に伏せ字の並びが現れても当たりにする。

grep のオプション

ERROR とだけ書くと、本文に ERROR を含む INFO の行も当たる。レベルが ERROR の行だけにしたいなら、^ から「日付・空白・時刻・空白」と位置を決めてから ERROR と書く（-E の + は次の節）。

$ grep WARN server.log

2026-10-13 09:05:00 WARNING deprecated option -x
$ grep -w WARN server.log

$ grep -l ERROR access.log server.log app.conf

$ grep -c 8080 access.log server.log app.conf

オプション意味
-v当たらない行を出す
-i大文字と小文字を区別しない
-n行番号を付ける
-c当たった行の数だけを出す（ファイルが複数ならファイルごと）
-l当たる行があったファイルの名前だけを出す
-w / -x単語として一致 / 行全体が一致
-rディレクトリの下を再帰的に探す
-E / -F拡張正規表現として読む / 文字どおりに読む
-o行全体ではなく、当たった部分だけを出す

基本正規表現と拡張正規表現

この節で分かること: + や | が効かない理由と、egrep fgrep の正体。
$ grep -E "ERROR|WARN" server.log
2026-10-13 09:00:05 WARN  disk usage 85%
2026-10-13 09:01:10 ERROR connection refused from 10.0.0.5
2026-10-13 09:02:30 INFO  retry finished after ERROR in job 42
2026-10-13 09:03:00 ERROR timeout after 30s
2026-10-13 09:05:00 WARNING deprecated option -x
$ grep "ERROR|WARN" server.log; echo "exit=$?"
exit=1
$ grep "ERROR\|WARN" server.log
2026-10-13 09:00:05 WARN  disk usage 85%
2026-10-13 09:01:10 ERROR connection refused from 10.0.0.5
2026-10-13 09:02:30 INFO  retry finished after ERROR in job 42
2026-10-13 09:03:00 ERROR timeout after 30s
2026-10-13 09:05:00 WARNING deprecated option -x

-E を付けない grep は基本正規表現（BRE）で読む。基本正規表現では | はただの文字なので、「ERROR|WARN という11文字」を探して見つからなかった（終了コード 1 は「見つからない」）。-E は拡張正規表現（ERE）で読み、| が「どちらか」になる。GNU の grep は基本正規表現でも \| と書けば同じ意味に読む。

$ grep "ap+le" fruits.txt; echo "exit=$?"
exit=1
$ grep -E "ap+le" fruits.txt
apple
apple
apple
$ grep "ap\+le" fruits.txt
apple
apple
apple
$ grep -E "[0-9]{3}" server.log | head -3
2026-10-13 09:00:01 INFO  server started on port 8080
2026-10-13 09:00:05 WARN  disk usage 85%
2026-10-13 09:01:10 ERROR connection refused from 10.0.0.5
$ grep "[0-9]\{3\}" server.log | head -3
2026-10-13 09:00:01 INFO  server started on port 8080
2026-10-13 09:00:05 WARN  disk usage 85%
2026-10-13 09:01:10 ERROR connection refused from 10.0.0.5
意味拡張（grep -E / egrep）基本（grep）
直前の1回以上+\+（GNU の拡張）
直前の0回か1回?\?（GNU の拡張）
回数の指定{3} {1,}\{3\} \{1,\}
どちらかA|BA\|B（GNU の拡張）
まとめる(A|B)\(A\|B\)
. * ^ $ [ ]どちらも同じ意味

egrep は grep -E、fgrep は grep -F と同じものである。中身を見ると、どちらも1行の小さなスクリプトだった。

$ egrep "ERROR|WARN" server.log
2026-10-13 09:00:05 WARN  disk usage 85%
2026-10-13 09:01:10 ERROR connection refused from 10.0.0.5
2026-10-13 09:02:30 INFO  retry finished after ERROR in job 42
2026-10-13 09:03:00 ERROR timeout after 30s
2026-10-13 09:05:00 WARNING deprecated option -x
$ cat /usr/bin/egrep
#!/bin/sh
cmd=${0##*/}
exec grep -E "$@"
$ cat /usr/bin/fgrep
#!/bin/sh
cmd=${0##*/}
exec grep -F "$@"
$ fgrep 10.0.0.5 ips.txt
10.0.0.5
10.0.0.50
110.0.0.5

本家の GNU grep 3.8 以降の egrep は、実行するたびに「egrep: warning: egrep is obsolescent; using grep -E」と警告を出す。この檻（Ubuntu 24.04 の grep 3.11）では警告が出なかった。cat で見た2行目の cmd=${0##*/} は、警告文を作るための行の名残で、警告を出す行は Debian が取り除いている（パッケージの変更履歴に記録がある）。試験の答えは「egrep = grep -E、fgrep = grep -F」で変わらないが、新しく書くなら grep -E / grep -F を使う。

$ zcat /usr/share/doc/grep/changelog.Debian.gz | grep -m1 disable-egrep
  * Add 01-disable-egrep-fgrep-warnings.patch (Closes: #1019335)
たとえ: 同じ記号を使う2つの方言に近い。拡張正規表現では + や | がそのまま命令として通じるが、 基本正規表現では「\ を前に付けたときだけ命令」で、付けなければただの文字として読まれる。
ただし崩れる点: 方言なら聞き手が文脈で察してくれるが、grep は察しない。 -E を付け忘れた ap+le は、エラーも出さずに「+ という文字を含む行」を探し、見つからないと黙って終わる。

位置と繰り返し

この節で分かること: ^ $ と * の実際の当たり方。
$ grep "^b" fruits.txt
banana
banana
$ grep "a$" fruits.txt
banana
banana
$ grep "^[A-Z]" fruits.txt
Durian
$ grep -E "^(apple|cherry)$" fruits.txt
apple
cherry
apple
apple
$ grep -E "^.{6,}$" fruits.txt
banana
cherry
banana
Durian
$ grep "an*a" fruits.txt
banana
banana
$ grep -o "an*a" fruits.txt
ana
ana

* は「直前の1文字の0回以上」なので、an*a は aa にも ana にも anna にも当たる。banana の中では -o で見ると ana が当たっている。

「0回以上」には、0回も含まれる。

$ grep -c "" fruits.txt
7
$ grep -c "x*" fruits.txt
7
$ grep -v "^$" blank.txt
first
third
$ grep "line1$" unix.txt win.txt
unix.txt:line1

x* は「x が0個以上」で、x を1つも含まない行にも（長さ0の部分で）当たるので、7行すべてが数えられた。^$ は「行頭の直後が行末」＝空行で、-v と組み合わせると空行を除ける。最後の行は第4章の CRLF のファイルで、line1 の後ろに見えない \r があるので、line1$（行末が line1）に当たらなかった。

シェルが先に * を使ってしまう

この節で分かること: パターンを引用符で囲む理由。
$ echo grep a* fruits.txt
grep access.log app.conf fruits.txt
$ grep a* fruits.txt; echo "exit=$?"
exit=1
$ grep "a*" fruits.txt | head -3
banana
apple
cherry

引用符の無い a* は、grep に届く前にシェルがワイルドカードとして展開する（第1章の echo *.csv と同じ）。~/text に a で始まるファイルが2つあったので、grep が受け取ったのは「パターン access.log、ファイル app.conf と fruits.txt」だった。どちらにも access.log という文字は無いので、何も出ずに終わった。引用符で囲めば、a* はそのまま grep に届く。

記号シェルのワイルドカード（ファイル名）正規表現（grep / sed の中身）
*任意の長さの任意の文字列直前の1文字の0回以上
?任意の1文字直前の0回か1回（拡張）
.ただの文字任意の1文字
[abc]どれか1文字どれか1文字
たとえ: 同じ「*」が、トランプのジョーカー（何にでもなれる1枚。シェルのワイルドカード）と、 「直前の札を何枚でも」という特別ルール（正規表現）の2つの意味で使われているのに近い。
ただし崩れる点: トランプなら今どちらのゲームをしているか全員が知っているが、コマンド行では先にシェルがジョーカーとして使ってしまい、 grep の番が来たときには札がもう別の物に置き換わっている。どちらのルールで読ませるかは、引用符で決めるしかない。

sed の中の正規表現と regex(7)

この節で分かること: 同じ正規表現が sed でも使えることと、規則の一次資料のありか。
$ sed -n "/^b/p" fruits.txt
banana
banana
$ sed -E "s/^([0-9-]+) ([0-9:]+) /\2 /" server.log | head -2
09:00:01 INFO  server started on port 8080
09:00:05 WARN  disk usage 85%
$ sed "s/[0-9]\{1,\}/N/g" ips.txt
N.N.N.N
N.N.N.N
N.N.N.N
ip-N-N-N-N

sed も既定は基本正規表現で、-E で拡張正規表現になる。( ) で囲んだ部分は \1 \2 で置き換え側に使える（2行目は日付の欄を落とした）。正規表現の規則の正式な説明は regex(7)、つまり man 7 regex にある（第3章）。

$ man 7 regex | grep -A1 "^NAME"
NAME
       regex - POSIX.2 regular expressions
$ man grep | grep -E "^ +-[EFGP], --"
       -E, --extended-regexp
       -F, --fixed-strings
       -G, --basic-regexp
       -P, --perl-regexp
確認

設定ファイル app.conf から、# で始まるコメント行と空行を除いて表示したい。正しいものはどれか。

A. grep -v '#' app.conf　B. grep -v '^#' app.conf | grep -v '^$'　C. grep '^[^#]' app.conf | grep -v '$'　D. grep -x '#' app.conf

答え

B。A は行の途中に # がある行（URL の # など）も消してしまう。 C の後半 grep -v '$' は全行に当たる $ を除くので何も残らない。grep -Ev '^(#|$)' と1回で書いてもよい。

確認

拡張正規表現を使うための grep のオプションと、同じ働きをする古いコマンド名を答えよ。正規表現を使わず文字どおりに探す場合はどうか。

答え

拡張正規表現は grep -E で、古い名前は egrep。文字どおりに探すのは grep -F で、古い名前は fgrep。 この檻の /usr/bin/egrep は exec grep -E "$@" の1行を実行するだけのスクリプトだった。

確認

拡張正規表現 ^[0-9]{3}-[0-9]{4}$ に一致するものをすべて選べ。

A. 123-4567　B. 1234-567　C. 〒123-4567　D. 123-45678

答え

A だけ。^ と $ で行全体を「数字3桁・ハイフン・数字4桁」に固定している。 C は先頭に別の文字があり、D は末尾が5桁なので外れる。

確認

ディレクトリ /etc の下で、ssh という文字列を含むファイルの名前だけを一覧したい。grep のオプションの組み合わせはどれか。

答え

grep -rl ssh /etc。-r で再帰的に探し、-l でファイル名だけを出す（一般ユーザでは読めないファイルのエラーが混ざるので、2> /dev/null を足すとよい。第7章）。

手を動かす: 実践編の演習07は、ログからレベルが ERROR か WARN の行だけを抜き出す課題である。 判定は各行を元のログと突き合わせ、本文に ERROR を含むだけの行や WARNING の行が混ざると、その行番号を観測として出す。

この章で分かったこと

持ち帰ってほしいこと

  • grep のパターンは正規表現。. は任意の1文字で、行のどこかに当たれば出る。文字どおりなら -F か \.、行全体なら -x、単語なら -w
  • ^ 行頭、$ 行末、* 直前の0回以上（だから x* は全行に当たる）、[ ] どれか1文字、[^ ] それ以外の1文字
  • 基本正規表現（grep）では + ? { } | ( ) に \ が要る。拡張（grep -E = egrep）では要らない。grep -F = fgrep
  • -v -i -n -c -l -r -o の意味
  • パターンは引用符で囲む。囲まないと * がシェルのワイルドカードとして先に展開される
  • 規則の一次資料は regex(7)（man 7 regex）。sed も同じ正規表現を使う
