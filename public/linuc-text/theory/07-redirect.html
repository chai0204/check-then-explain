7. リダイレクトは、左から順に配線する

> out.txt を付けても、エラーは画面に出る。> が付け替えるのは出力の口のうち1本だけだからだ。そして 2>&1 は「エラーもまとめる」という呪文ではなく、「2番の口を、いま1番が向いている先へつなぐ」という1回きりの配線である。配線はコマンドが動き出す前に、シェルが左から順に済ませている。

前提: 第6章まで前提: 檻が起動している所要 18分影響度 B出題範囲 1.03.3（重要度4）最終検証 2026-10-13

この章のゴール

  • 標準入力（0番）・標準出力（1番）・標準エラー出力（2番）と、> >> < 2> 2>&1 &> の意味を言える
  • cmd > f 2>&1 と cmd 2>&1 > f の結果の違いを、左から順に処理される規則で説明できる
  • sort f > f が空になる理由と、noclobber >| /dev/null ヒアドキュメントの使いどころを言える
ここで覚えなくていいこと: 3番以降の口を開く exec 3>、プロセス置換 <(...)、読み書き両用の <>、名前付きパイプ。パイプ（|）は第8章で扱う。

出力の口は2本ある

この節で分かること: 標準出力と標準エラー出力が別の口であること。
$ cd ~/text
$ ls fruits.txt nosuch.txt
ls: cannot access 'nosuch.txt': No such file or directory
fruits.txt
$ ls fruits.txt nosuch.txt > out.txt
ls: cannot access 'nosuch.txt': No such file or directory
$ cat out.txt
fruits.txt
$ ls fruits.txt nosuch.txt 2> err.txt
fruits.txt
$ cat err.txt
ls: cannot access 'nosuch.txt': No such file or directory

どのプロセスも、生まれたときから3本の口を持っている。番号で呼ぶ。

  0番 標準入力        どこから読むか（既定は端末のキーボード）
  1番 標準出力        結果をどこへ書くか（既定は端末の画面）
  2番 標準エラー出力  エラーや警告をどこへ書くか（既定も端末の画面）

1番と2番はどちらも画面につながっているので、ふだんは混ざって見える。> out.txt（1> の略）は1番だけを付け替えたので、ls のエラーは2番を通って画面に残った。2> err.txt は2番だけを付け替えた。書く先（画面かファイルか）を選んだのはシェルで、ls はどちらの場合も同じように「1番に結果、2番にエラー」を書いただけである。ただしコマンドは、1番の先が端末かどうかを調べることはできる。ls は端末なら名前を横に並べ、ファイルやパイプなら1行に1つずつ出す（第4章の less がパイプの途中で画面を開かなかったのも同じ仕組み）。

たとえ: 郵便受けが2つある家に近い。ふつうの郵便（1番）と督促状（2番）は別の箱に届き、 どちらも初めは同じ玄関先（画面）に置いてある。> は「ふつうの郵便だけ別の住所へ転送して」という届けで、督促状は玄関に届き続ける。
ただし崩れる点: 郵便は差出人が宛先を書くが、ここでは差出人（コマンド）は「1番の箱」「2番の箱」に入れるだけで、 転送の届けを出す（行き先を決める）のはシェルである。それでも差出人は、箱が玄関（端末）に置かれたままかどうかだけはのぞいて確かめられ、 ls のようにそれで出し方を変えるコマンドもある。

2>&1 は、書く順番で結果が変わる

この節で分かること: 2>&1 の正確な意味と、リダイレクトが処理される順番。

ふつうこう考える

2>&1 は「エラーも標準出力にまとめる」という意味だから、> ファイル の前に書いても後に書いても、両方がファイルに入るはずだ。

$ ls fruits.txt nosuch.txt > both.txt 2>&1
$ cat both.txt
ls: cannot access 'nosuch.txt': No such file or directory
fruits.txt
$ ls fruits.txt nosuch.txt 2>&1 > only.txt
ls: cannot access 'nosuch.txt': No such file or directory
$ cat only.txt
fruits.txt
だめな理由: 後ろに書いた1つ目は両方がファイルに入ったが、前に書いた2つ目はエラーが画面に出て、ファイルには1行しか入らなかった。 2>&1 は「2番を、この時点で1番がつながっている先へつなぐ」という操作で、 その後に1番を付け替えても、2番はついていかない。シェルはリダイレクトを左から順に処理する。
書き方1つ目の処理2つ目の処理結果
> both.txt 2>&11番 → both.txt2番 → 1番の今の先（both.txt）両方 both.txt
2>&1 > only.txt2番 → 1番の今の先（画面）1番 → only.txt結果は only.txt、エラーは画面

bash には、両方を1つのファイルへ送る短い書き方 &> もある。

1つのファイルにまとめたときの行の順番は「書かれた順」である。ls はエラーを先に出すので、端末でもファイルでもエラーが上に来た。標準出力をためておいてまとめて書くプログラム（出力先が端末でないときの C のプログラムの多く）では、画面で見た順と違い、エラーの行が先に入ることがある。

$ ls fruits.txt nosuch.txt &> amp.txt
$ cat amp.txt
ls: cannot access 'nosuch.txt': No such file or directory
fruits.txt
たとえ: 2>&1 は「督促状は、ふつうの郵便と同じ転送先へ」という転送届に近い。 窓口はこの届けを受け取ると、ふつうの郵便のその時点の転送先を書き写して処理する。
ただし崩れる点: 人の窓口なら「同じ先へ」を覚えておいて、後から変わった転送先にも合わせてくれそうに思えるが、 シェルは書き写したら終わりで、後の変更を追いかけない。だから届けを出す順番がすべてになる。

上書きと追記、捨て場所

この節で分かること: > と >> の違いと、/dev/null。
$ echo first > note.txt
$ echo second > note.txt
$ cat note.txt
second
$ echo third >> note.txt
$ cat note.txt
second
third
$ ls nosuch.txt 2>> note.txt
$ cat note.txt
second
third
ls: cannot access 'nosuch.txt': No such file or directory

> はファイルを開くときに中身を空にしてから書く。>> は末尾に足す。2>> のように番号と組み合わせられる。

$ ls fruits.txt nosuch.txt 2> /dev/null
fruits.txt
$ ls fruits.txt nosuch.txt > /dev/null
ls: cannot access 'nosuch.txt': No such file or directory
$ stat -c "%A %F" /dev/null
crw-rw-rw- character special file

/dev/null は書いたものを全部捨て、読むと何も返さない特殊なファイル（キャラクタデバイス）である。エラーだけ見たくないなら 2> /dev/null、結果を捨ててエラーだけ見たいなら > /dev/null と書く。

標準入力を付け替える

この節で分かること: < とヒアドキュメント。
$ wc -l < fruits.txt
7
$ tr a-z A-Z < fruits.txt > upper.txt
$ cat upper.txt
BANANA
APPLE
CHERRY
APPLE
APPLE
BANANA
DURIAN

< は0番（標準入力）をファイルにつなぐ。第4章で見たとおり、wc にはファイル名が届かないので、数だけが出る。入力と出力を同時に付け替えることもできる。

短い文章をその場で標準入力に渡すには、ヒアドキュメント << 終わりの印 を使う。端末では2行目から > という続きのプロンプトが出る。

$ cat << EOF > greet.txt
> hello, $HOME
> EOF
$ cat greet.txt
hello, /home/lab
$ cat << 'EOF'
> hello, $HOME
> EOF
hello, $HOME
$ tr a-z A-Z <<< "here string"
HERE STRING

終わりの印を引用符で囲むと（'EOF'）、中の $HOME は展開されない。第1章の引用符の規則が、ここでもそのまま効いている。<<<（ヒアストリング）は、続く1つの文字列を（展開した後で）末尾に改行を1つ足して標準入力に渡す bash の書き方である。文字列が改行を含んでいれば、渡る行も複数になる。

読みながら同じファイルに書くと、空になる

この節で分かること: リダイレクトの処理がコマンドより先に起きることの、いちばん痛い結果。
$ cp fruits.txt copy.txt
$ sort copy.txt > copy.txt
$ wc -c copy.txt
0 copy.txt

並べ替えたかったファイルが、0バイトになった。シェルは sort を動かす前に > copy.txt を処理し、ファイルを空にして開く。sort が読み始めたときには、もう何も残っていない。sort には -o という自分で書き出すオプションがあり、全部読んでから書くので同じファイルを指定できる（第6章の sed -i も同じ問題を避けるための仕組み）。

$ cp fruits.txt copy.txt
$ sort copy.txt -o copy.txt
$ head -2 copy.txt
Durian
apple

うっかり上書きを防ぐには、シェルのオプション noclobber を入れる（第1章の set -o）。入れていても、>| と書けば上書きできる。

$ set -o noclobber
$ echo again > note.txt
bash: note.txt: cannot overwrite existing file
$ echo again >| note.txt
$ cat note.txt
again
$ set +o noclobber
たとえ: 原本を書き写そうとして、書き写す先の紙を用意する作業で原本を消しゴムで消してしまうのに近い。 写す係（sort）が来る前に、紙の準備係（シェル）が同じ紙をまっさらにしている。
ただし崩れる点: 人なら「それは原本です」と止めるが、シェルは名前が同じかどうかを確かめない。 noclobber を入れたときだけ、既にあるファイルへの > を拒む。

最後に、コマンドの成否はどの口にも出ない終了コード（$?）で受け取る。0 が成功で、それ以外が失敗である。

$ ls nosuch.txt; echo "exit=$?"
ls: cannot access 'nosuch.txt': No such file or directory
exit=2
$ ls fruits.txt; echo "exit=$?"
fruits.txt
exit=0
確認

コマンド backup.sh の標準出力と標準エラー出力の両方を result.log に書きたい。正しいものを2つ選べ。

A. backup.sh 2>&1 > result.log　B. backup.sh > result.log 2>&1　C. backup.sh &> result.log　D. backup.sh 2> result.log

答え

B と C。A は2番が画面につながったまま残る（実測の only.txt と同じ）。D はエラーだけがファイルに入る。

確認

find / -name passwd を一般ユーザで実行すると、Permission denied が大量に出る。見つかった結果だけを画面に出すには、どう書くか。

答え

find / -name passwd 2> /dev/null。エラーは2番に出るので、2番だけを /dev/null へ捨てる。

確認

> と >> の違いを説明せよ。また、sort data.txt > data.txt を実行すると data.txt はどうなるか。

答え

> はファイルを空にしてから書き、>> は末尾に追記する。 sort data.txt > data.txt は、sort が読む前にシェルが data.txt を空にするので、空のファイルになる（実測 0 バイト）。 同じファイルに書き戻すなら sort data.txt -o data.txt。

手を動かす: 実践編の演習05は、1つのスクリプトの出力を「標準出力だけ」「標準エラー出力だけ」「両方を順番どおり」の3つのファイルに分ける課題である。 2>&1 を先に書くと、判定は「all.log に NG の行が入っていない」と観測する。

この章で分かったこと

持ち帰ってほしいこと

  • 出力の口は2本ある。1番が標準出力、2番が標準エラー出力。0番が標準入力
  • >（1>）は1番だけ、2> は2番だけを付け替える。>> は追記、< は0番
  • 2>&1 は「2番を、いま1番が向いている先へ」。リダイレクトは左から順に処理されるので、> f 2>&1 と 2>&1 > f は違う。&> f は前者と同じ
  • リダイレクトはコマンドより先に処理される。だから sort f > f は空になる（sort -o を使う）
  • 捨てるなら /dev/null。上書きを防ぐ set -o noclobber と、それを越える >|
