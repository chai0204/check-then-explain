8. xargs は空白で区切って引数にする

find が見つけた3つのファイルを xargs ls -l に渡すと、「見つからない」というエラーが5つ出る。xargs は受け取った文字を空白と改行で区切って引数に並べるので、ファイル名の中の空白も区切りになる。パイプは文字の流れをつなぐだけで、どこが1つの名前なのかという情報は運ばない。

前提: 第7章前提: 檻が起動している所要 20分影響度 B出題範囲 1.03.3（重要度4）最終検証 2026-10-13

この章のゴール

  • パイプ | がつなぐのは1番（標準出力）だけで、2番もつなぐには 2>&1 | か |& を使うと言える
  • xargs の区切り方と、-n -I{} -0（と find -print0）の使いどころを言える
  • tee（-a）と、コマンド置換 $(...) / `...` を使える
ここで覚えなくていいこと: xargs -P（並列実行）、名前付きパイプ（mkfifo）、プロセス置換 <(...)、set -o pipefail の細部。find の条件の書き方は主題1.02 の側で扱う。

パイプがつなぐのは1番だけ

この節で分かること: | が何をどこへつないでいるか。
$ cd ~/text
$ cut -d" " -f9 access.log | sort | uniq -c | sort -rn
      4 200
      3 404
      1 500
      1 403
      1 302

第5章の集計を、アクセスログのステータスコードに当てた。|（パイプ）は、左のコマンドの1番（標準出力）を、右のコマンドの0番（標準入力）につなぐ。シェルはつなぎ終えてから4つのコマンドを同時に起動し、各コマンドは届いた分から処理していく。

$ ls nosuch.txt | wc -l
ls: cannot access 'nosuch.txt': No such file or directory
0
$ ls nosuch.txt 2>&1 | wc -l
1
$ ls nosuch.txt |& wc -l
1

1つ目は、エラーが画面に出て、wc は 0 行と数えた。エラーは2番に出たので、パイプを通らなかった。2>&1 |（2番を、パイプにつながった1番の先へ）か、bash の短い書き方 |& で、両方をパイプに流せる。

$ false | true; echo "exit=$? PIPESTATUS=${PIPESTATUS[*]}"
exit=0 PIPESTATUS=1 0

パイプ全体の終了コード（$?）は最後のコマンドのもので、途中の false の失敗は隠れる。各段の終了コードは bash の配列 PIPESTATUS に残っている。

たとえ: バケツリレーに近い。各人は前の人から受け取った水（1番の出力）を、手を加えて次の人に渡す。 文句（2番のエラー）は列に流さず、観客席（画面）に向かって叫ぶ。
ただし崩れる点: バケツリレーは前の人が渡すまで次の人は待っているだけだが、パイプの各コマンドは最初から全員が同時に動いていて、 流れてきた分から少しずつ処理する。だから tail -f のように終わらないコマンドも、パイプの左に置ける。

標準入力を、引数に組み替える

この節で分かること: xargs が何をしているか。

ls や rm は、操作する相手を引数で受け取り、標準入力は読まない。パイプで名前を流しても、受け取る口が無い。xargs は標準入力から読んだ文字を区切り、それを引数に並べてコマンドを起動する。

$ echo a b c | xargs echo
a b c
$ echo a b c | xargs -n 1 echo
a
b
c
$ echo a b c | xargs -n 2 echo
a b
c
$ printf "%s\n" apple banana | xargs -I{} echo "果物: {}"
果物: apple
果物: banana

既定では、受け取ったものをできるだけまとめて、1回のコマンドの引数に並べる。-n 1 は「1回に1つずつ」で、echo が3回起動した。-I{} は1行ずつ、{} の位置に差し込んで起動する。

「まとめて」には上限がある。1回のコマンド行の長さには限りがあり、xargs は超える分を何回かに分けて起動する。30万個の数を渡すと、echo は16回起動して16行を出した。

$ seq 1 300000 | xargs echo | wc -l
16

何を実行したかを見るには -t を付ける。組み立てたコマンド行を標準エラー出力に出してから実行する。試験の例題にならって、/tmp にディレクトリを作って試す。

$ cd /tmp
$ mkdir -p dir/d1 dir/d2 dir/d3; touch dir/d1/file1.txt dir/d2/file2.txt dir/d3/file3.txt
$ find dir -type f | sort | xargs -t rm -f
rm -f dir/d1/file1.txt dir/d2/file2.txt dir/d3/file3.txt
$ find dir | sort
dir
dir/d1
dir/d2
dir/d3
$ echo a b c | xargs -t -n 1 echo
echo a
a
echo b
b
echo c
c

rm -f dir/d1/file1.txt … の行は -t が出したもので、rm 自身は何も出していない。find dir | sort で、ファイルだけが消えてディレクトリが残ったことが分かる。-p は、1回ずつ確かめてから実行する（y で実行、それ以外で飛ばす）。端末の上で打った記録で見る。

$ echo a b | xargs -p -n 1 echo
echo a?...y
a
echo b?...n

y と答えた a だけが実行された。ほかの似た名前のオプションも確かめておく。

$ find dir -type f | xargs -c 'rm -f $0'
xargs: invalid option -- 'c'
Try 'xargs --help' for more information.
$ find dir -type f | xargs -P rm -f
xargs: invalid number "rm" for -P option
Try 'xargs --help' for more information.
$ cd ~/text

-c というオプションは無い。-P は同時に動かすプロセスの数を数で受け取るオプションで、rm を数として読めずに止まった。最後の cd ~/text で、この章の作業場所に戻る。

名前の中の空白も、区切りになる

この節で分かること: xargs が名前を壊す仕組みと、壊さない渡し方。

ふつうこう考える

find が見つけたファイルの一覧を xargs に渡せば、1行に1つずつのファイル名が、そのまま1つずつの引数になるはずだ。 find は名前を1行に1つずつ出しているのだから。

$ find files -type f | sort
files/cache.tmp
files/memo.txt
files/old data.tmp
files/report 2026.txt
files/sub/a b c.tmp
files/sub/keep.txt
$ find files -name "*.tmp" | sort
files/cache.tmp
files/old data.tmp
files/sub/a b c.tmp
$ find files -name "*.tmp" | sort | xargs ls -l
ls: cannot access 'files/old': No such file or directory
ls: cannot access 'data.tmp': No such file or directory
ls: cannot access 'files/sub/a': No such file or directory
ls: cannot access 'b': No such file or directory
ls: cannot access 'c.tmp': No such file or directory
-rw-r--r-- 1 lab lab 0 Oct 13 09:00 files/cache.tmp
だめな理由: 3つのファイルを渡したのに、ls は「見つからない」を5回出し、見つけたのは空白の無い cache.tmp だけだった。 xargs は改行だけでなく空白でも区切る。files/old data.tmp は files/old と data.tmp の2つの引数になり、 どちらもそんなファイルは無い。パイプに流れているのはただの文字の並びで、「ここからここまでが1つの名前」という印は付いていない。

区切られ方は、xargs に1つずつ echo させると見える。

$ find files -name "*.tmp" | sort | xargs -n 1 echo
files/cache.tmp
files/old
data.tmp
files/sub/a
b
c.tmp
$ find files -name "*.tmp" -print0 | sort -z | xargs -0 -n 1 echo
files/cache.tmp
files/old data.tmp
files/sub/a b c.tmp

find -print0 は名前の区切りに改行ではなく NUL 文字（値が 0 のバイト）を使い、xargs -0 は NUL だけを区切りとして扱う。ファイル名には NUL を入れられないので、どんな名前も1つの引数のまま届く（sort -z は NUL 区切りのまま並べる）。

$ find files -name "*.tmp" -print0 | sort -z | xargs -0 ls -l
-rw-r--r-- 1 lab lab 0 Oct 13 09:00  files/cache.tmp
-rw-r--r-- 1 lab lab 0 Oct 13 09:00 'files/old data.tmp'
-rw-r--r-- 1 lab lab 0 Oct 13 09:00 'files/sub/a b c.tmp'
$ find files -name "*.tmp" -exec ls -l {} +
-rw-r--r-- 1 lab lab 0 Oct 13 09:00  files/cache.tmp
-rw-r--r-- 1 lab lab 0 Oct 13 09:00 'files/old data.tmp'
-rw-r--r-- 1 lab lab 0 Oct 13 09:00 'files/sub/a b c.tmp'
$ printf "%s\n" "files/old data.tmp" | xargs -d "\n" ls -l
-rw-r--r-- 1 lab lab 0 Oct 13 09:00 'files/old data.tmp'

find -exec コマンド {} + は xargs を通さず、find が名前を直接引数に並べる。xargs -d "\n" は「改行だけで区切る」という GNU の書き方である（改行を含む名前には効かない）。

名前を囲む ' は ls が付けた飾りで、名前の一部ではない。ls は出力先が端末のときだけ、空白などを含む名前を引用符で囲み、囲まない名前の前に空白を1つ足して桁をそろえる（パイプやファイルに出すときは囲まない）。

xargs は既定で引用符（' と "）も特別な文字として読む。名前にアポストロフィが1つあるだけで、対になる引用符が無いと言って止まる。-0 か -d を付けると、引用符もただの文字として扱う。

$ printf "%s\n" "it's.txt" | xargs echo; echo "exit=$?"
xargs: unmatched single quote; by default quotes are special to xargs unless you use the -0 option
exit=1
$ printf "%s\n" "it's.txt" | xargs -d "\n" echo
it's.txt

消すときにこれを間違えると、消したつもりのファイルが残る。

$ find files -name "*.tmp" | sort | xargs rm; echo "exit=$?"
rm: cannot remove 'files/old': No such file or directory
rm: cannot remove 'data.tmp': No such file or directory
rm: cannot remove 'files/sub/a': No such file or directory
rm: cannot remove 'b': No such file or directory
rm: cannot remove 'c.tmp': No such file or directory
exit=123
$ find files -name "*.tmp" | sort
files/old data.tmp
files/sub/a b c.tmp
$ find files -name "*.tmp" -print0 | xargs -0 rm
$ find files -name "*.tmp" | wc -l
0

xargs は、起動したコマンドが1つでも失敗すると終了コード 123 を返す。空白の無い cache.tmp だけが消え、2つが残った。-print0 と -0 で渡し直すと、残りも消えた。

たとえ: 名簿を読み上げて宛名ラベルを1枚ずつ作る係に近い。この係は「空白が来たら次のラベル」と決めているので、 「old data」さんのラベルは「old」と「data」の2枚になる。-0 は「区切りは空白ではなく、名簿の線（NUL）で」と頼むことだ。
ただし崩れる点: 人の係なら「old data」が1人の名前だと文脈で分かるが、xargs は文字しか見ない。 区切りを決めるのは、渡す側（-print0）と受け取る側（-0）の約束だけである。

途中を保存する — tee

この節で分かること: パイプの途中の流れを、ファイルにも残す方法。
$ cut -d" " -f1 access.log | sort | uniq -c | sort -rn | tee ip-count.txt | head -2
      4 192.168.1.10
      2 192.168.1.12
$ cat ip-count.txt
      4 192.168.1.10
      2 192.168.1.12
      2 192.168.1.11
      1 192.168.1.14
      1 192.168.1.13
$ echo "追記" | tee -a ip-count.txt
追記
$ tail -2 ip-count.txt
      1 192.168.1.13
追記

tee は標準入力から読んだものを、標準出力とファイルの両方に書く。画面には head -2 の2行しか出なかったが、ip-count.txt には全部が残っている。-a は上書きせずに追記する（>> と同じ）。

たとえ: 水道管の T 字の継ぎ手（名前の由来）に近い。流れの途中に挟むと、同じ流れが2方向へ出ていく。
ただし崩れる点: 水道の T 字管は流れが2つに分かれる（片方の量が減る）が、tee は同じ内容を丸ごと2つ作る。 画面側にもファイル側にも、全部が流れる。

出力を、コマンドの引数に埋め込む

この節で分かること: コマンド置換と、そこでも起きる空白での区切り。
$ echo "ここは $(pwd)"
ここは /home/lab/text
$ echo "ここは `pwd`"
ここは /home/lab/text
$ echo "果物は $(wc -l < fruits.txt) 行"
果物は 7 行

$(コマンド) と `コマンド`（バッククォート）は、中のコマンドを先に実行し、その出力（末尾の改行はすべて除く）で置き換える。コマンド置換と呼ぶ。$(...) は入れ子にでき、読みやすいので、新しく書くならこちらを使う。

$ wc -l $(find files -name "*.txt" | sort)
0 files/memo.txt
wc: files/report: No such file or directory
wc: 2026.txt: No such file or directory
0 files/sub/keep.txt
0 total

引用符で囲まないコマンド置換は、第1章の変数と同じように、展開した後で空白で区切られる。files/report 2026.txt が2つの引数になった。xargs と同じ壊れ方である。

確認

カレントディレクトリ以下の .log ファイルを、名前に空白が含まれていても安全にすべて gzip したい。正しいものはどれか。

A. find . -name '*.log' | xargs gzip　B. find . -name '*.log' -print0 | xargs -0 gzip　C. find . -name '*.log' | xargs -n 1 gzip　D. gzip $(find . -name '*.log')

答え

B。A・C・D はどれも空白で名前が割れる（実測の xargs ls -l と wc -l $(...) と同じ）。 -n 1 は1回に渡す数を決めるだけで、区切り方は変えない。

確認

コマンド make の出力を画面に表示しながら、同時に build.log にも保存したい。エラー出力も含めたい。どう書くか。

答え

make 2>&1 | tee build.log（bash なら make |& tee build.log も同じ）。 パイプは1番しかつながないので、2番を先に1番へ合流させる。追記なら tee -a。

確認

echo a b c d e | xargs -n 2 echo の出力は何行になるか。

答え

3行（a b / c d / e）。-n 2 は「1回に2つずつ」なので echo が3回起動する。 実測の echo a b c | xargs -n 2 echo は a b と c の2行だった。

手を動かす: 実践編の演習06は、名前に空白を含むものも含めて .tmp だけを find と xargs で消す課題である。 判定は残っているファイルを数えるので、-print0 / -0 を付け忘れると「空白入りの名前だけが残っている」と観測される。
確認

dir の下のファイルだけを xargs で消し、実行したコマンドも表示したい。適切なものはどれか。

A. find dir -type f | xargs rm -f　B. find dir -type f | xargs -c 'rm -f $0'　C. find dir -type f | xargs -t rm -f　D. find dir -type f | xargs -P rm -f

答え

C。-t は組み立てたコマンド行を標準エラー出力に出してから実行する。A は消すが表示しない。 実測では B は invalid option -- 'c'、D は invalid number "rm" for -P option で止まった。

この章で分かったこと

持ち帰ってほしいこと

  • | は左の1番を右の0番につなぐ。2番は通らない（2>&1 | か |&）。パイプの終了コードは最後のコマンドのもの
  • xargs は標準入力を区切って引数に並べる。区切りは空白と改行なので、名前の空白でも割れる
  • 名前を壊さずに渡すには find -print0 | xargs -0（区切りを NUL にする）か find -exec ... {} +
  • -n 数 は1回に渡す数、-I{} は1行ずつ差し込み
  • tee は画面とファイルの両方へ（-a で追記）。$(...) と `...` はコマンド置換で、引用符が無いと空白で区切られる
