確かめて説明する Docker — 実践編

練習機（仮想マシン）の中に入れた本物の docker で、コンテナのプロセス・イメージの指紋・overlay・ポートの公開・ビルドのキャッシュ・特権を、自分の手で確かめます。 あなたの PC の docker の上で起動しますが、あなたの PC の docker の設定やファイルには触れません（練習機の中の docker を使います）。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントの Get started のほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: docker run は打てる。写経すれば動く。 でも「その1行が何をしているのか」を人に説明できない人。

端末には2つの場所があります。プロンプトで、いまどちらにいるかが分かります。

あなたの PC（docker がある）
└─ 外側のコンテナ          lab@host       … 外。lab check と、練習機への ssh を打つ場所
   └─ 練習機（QEMU）        student@linuc  … 仮想マシン。この中の docker で、本文のコマンドを打つ
      └─ 練習機の中の docker のコンテナ   … 本文で起動するもの（alpine・busybox）

影響度 B（変更は練習機とコンテナの中だけ。あなたの PC の設定もファイルも書き換えません）。 練習機の中では sudo が使え、docker の設定や iptables を変える章もあります。壊したら外で vm reset --yes を打てば、練習機が最初の状態に戻ります。 演習を始めるときの lab の案内にも、この戻し方が出ます（起動し直すだけでは練習機は戻りません。ディスクはボリュームに残ります）。

はじめる

Docker の場合。起動して、入ります。

docker run -d --name lab-docker --hostname host --stop-timeout 30 \
  -v lab-docker-vm:/home/lab/vm \
  -v lab-docker-state:/home/lab/.lab \
  ghcr.io/chai0204/lab:docker-1.0.2@sha256:__DIGEST__

docker exec -it lab-docker bash -l
  • --stop-timeout 30 は特権ではなく、docker stop のときに待つ秒数です。練習機を正常に止めるのにかかる時間は、練習機の中で動いているもの次第です（著者の記録では、何も動いていなければ 4.4 秒、TERM を受け取らないコンテナを3つ残していると 16.0 秒）。 docker の既定の10秒を超えると電源を抜くのと同じ止まり方になるので、30秒にしています（理由は第2章で確かめます）。 付けずに作った場合は docker stop -t 30 lab-docker で止めてください。
  • --privileged も --cap-add も要りません。練習機の中の docker を動かすのに要る特権は、練習機の中の話で、あなたの PC からは何も借りません（第7章）。
  • podman でも、同じオプションのまま動きます（docker を podman に読み替える）。rootless の podman 5.8.6 で、名前付きボリュームも同じにして起動を確かめてあります（著者の記録 logs/docker-rootless.log: 起動から ssh まで35秒。仕組みは Podman の記事の第7章）。

入ると、練習機の状態と現在地が出ます。起動の直後は練習機がまだ立ち上がっていないことがあります（1行目が running（エージェント 応答あり / ssh 待ち受け中） になるまで、KVM なしで 1分前後）。

練習機 linuc: running（エージェント 応答あり / ssh 待ち受け中）
  vm start / vm ssh / vm console / vm stop   練習機の操作（中身は virsh と ssh）


── lab-docker 1.0.2 ────────────────────────────────────────
lab-docker  進捗 0/7
  次 → 01 「メモリの上限を付けたコンテナを動かす」 (目安 8分 / 影響度 B)
  lab start 01 で課題を開く
  進捗の保存先: /home/lab/.lab/progress.json（消すには docker volume rm lab-docker-state）
  lab ls      演習一覧 / lab start NN  課題を開く / lab check  答え合わせ
────────────────────────────────────────────────────────────

まだ running でなければ、外で vm start と打つと、起動が終わるまで待ってくれます。いるのは外側のコンテナ（lab@host）です。練習機には ssh linuc で入ります。

$ ssh linuc

  練習機（Ubuntu 24.04 / 仮想マシン）— Docker と Podman の記事
  - 採点は外のコンテナが持っています。この中でも lab check NN で答え合わせできます
  - 管理用の NIC（enp0s16）を止めると ssh が切れます。そのときは外で vm console

プロンプトが student@linuc に変わります。本文の端末は、ほとんどがこの練習機の中で打つものです（見出しが「練習機の中（student@linuc）」）。 student は docker グループに入っているので、docker を sudo なしで打てます（それが何を意味するかは第7章）。 sudo もパスワード無しで使えます。抜けるのは exit です。

本文の出力のうち、コンテナの ID・PID・時刻と経過時間（Up 5 seconds など）・time の秒数・MAC アドレスなど、打つたびに変わる値は、あなたの画面では本文と違います。それ以外の行は同じになります（同じ手順で通しに2回打ち、変わる値だけを伏せて突き合わせてあります）。

本文は、第1章から順に、同じ1つのシェルで打った記録です。章の途中で抜けたり、本文に無いコマンドを足したりすると、後ろの章の画面（ID の番号、残っているコンテナやボリューム）が本文と変わることがあります。

この檻について

練習機は Docker Hub に届きません（わざとです。ほかのレジストリには届きますが、本文と演習では使いません）。使うイメージ（alpine:3.24.2 と busybox:1.38.0。ダイジェストで照合済み）は練習機のディスクに入れてあり、 Docker Hub へ取りに行く操作は、読者のネットワークに関係なく全員に同じ失敗（connection refused）を出します。練習機の /etc/hosts の最後の行で、Docker Hub の名前（registry-1.docker.io など）を 0.0.0.0 に向けてあります。

外（lab@host）の 127.0.0.1:8080 は、練習機の 8080 番へ転送しています。第5章と演習05で、公開したポートに「練習機の外から」届くかを確かめるためです。 この転送は外側のコンテナの中で閉じていて、あなたの PC の 8080 番には何も出ていません。

この檻の練習機は KVM を使いません。起動コマンドに --device /dev/kvm を足しても、練習機の定義が完全エミュレーション（type='qemu'）に固定されているので、QEMU は -accel tcg のまま動きます（著者の環境で実測: 足して起動しても、起動から ssh まで 35 秒。KVM を使わない理由は KVM の記事の6章）。何も足さずに起動してください。本文の出力はすべて KVM なしで取ったものです。

1.0.1 で始めた人は、「終わったら」の手順で檻を止めてから（ボリュームは消さずに）、上の起動コマンドで起動し直すだけで構いません。1.0.2 で変わったのは lab コマンドだけなので、進み具合と作業ファイルはそのまま使えます。

演習

7本あります。判定は観測できる結果だけで行い、コマンドの打ち方は見ません。 判定は外の端末でも、練習機の中でも lab check NN で打てます。課題は lab start NN で出て、lab show でいつでももう一度出せます。 詰まったら lab hint NN を何度でも。使い切ったら lab solve NN で模範解答に必ず届きます （見ても構いません。進捗には「solve を見た」として残ります）。

Noやること章目安
01メモリの上限を付けたコンテナを動かす18分
02docker stop が TERM で終わるコンテナを動かす210分
03付け替えられた名前を、中身に戻す38分
04コンテナを消しても残るデータを置く410分
05練習機の外から届くように、ポートを公開する512分
06キャッシュが効く順に Dockerfile を並べ替える615分
07必要な特権だけを渡して起動する710分

先に読む場合は 理論編（7章）へ。章と演習は対応しているので、どちらから始めても構いません。 ただし本文の画面は「第1章から順に打った」ものなので、演習を先にやると、本文の docker ps -a などに演習のコンテナが混ざります。

lab は sudo を付けずに打ちます。付けると root として動き、作業ディレクトリと進み具合が /root の下にできて檻を抜けると消えてしまうので、理由を出して何もせずに止まります。~/work や ~/.lab の持ち主が自分でなくなっていたら、lab が見つけて戻し、そのことを画面に出します。

終わったら

docker stop lab-docker                # 練習機を正常に止めてから止まる
docker rm lab-docker
docker volume rm lab-docker-vm lab-docker-state   # 練習機のディスクと進捗も消す場合だけ

イメージは docker rmi で消せます。 あなたの PC には何も残りません（名前付きボリューム以外のファイルを作っていないため）。 続きをやる日は docker start lab-docker で再開できます（練習機のディスクも、進捗も、そのまま残っています）。
