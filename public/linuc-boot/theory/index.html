理論編 — 起動・仮想マシン・プロセス

LinuC レベル1 101 試験・主題1.01（インストールと仮想マシン・コンテナ／ブートと systemd／プロセス／デスクトップ）を、 コンテナの中で動く本物の仮想マシン（練習機）で確かめる10章。 電源を入れるところから、GRUB でカーネルに引数を渡し、プロセスにシグナルを送るところまで、全部あなたの手で打てます。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この10章を貫いている1つの事実

停止の頼みも、シグナルも、ログインも、相手に送る「合図」でしかない。どう振る舞うかは、受け取った側が決める。

virsh shutdown は中の OS に止まるよう頼むだけで（ゲストエージェントがいればエージェント経由、いなければ ACPI の電源ボタンで）、止まるかどうかは中の OS が決める。 kill は番号の付いた合図を送るだけで、受け取ったプロセスは無視できる。 ssh の鍵は見せるだけで、通すかどうかは相手の authorized_keys が決める。 出題範囲に shutdown halt poweroff reboot、kill pkill killall、nohup screen tmux と 似たコマンドがいくつも並ぶのは、送る合図と、受け取る相手が違うからです。 受け手に決めさせずに終わらせられるのは、電源を抜く virsh destroy と kill -9 だけです。

ここで覚えなくていいこと: libvirt の XML の全項目、仮想ネットワークやストレージプール（virsh net-* pool-*）、 GRUB の設定ファイルの文法（grub.cfg を手で書く）、Secure Boot の署名の仕組み、 systemd のユニットファイルの書き方、Wayland の詳細。どれもこの主題の出題範囲の外で、本文では名前が出るだけです。

章

  1. virsh は電源を入れ、止まるよう頼むだけ — virsh start は一瞬で返るが、OS はまだいない。virsh shutdown は頼むだけ（25分）
  2. 入れるかどうかは、受け取る側のファイルが決める — ssh-keygen が作るのは id_rsa ではなかった。権限が緩い authorized_keys は無視される（20分）
  3. コンテナの中のカーネルは、ホストのもの — Ubuntu 24.04 のコンテナで uname -r が 7.2.6 を出す。練習機の CPU は AMD-V を名乗る（15分）
  4. GUI が無くても、既定は graphical.target — X の無い練習機で runlevel が 5 を返す。インストールの選択はファイルに残る（12分）
  5. ファームウェアが必ず読めるのは、FAT の中のファイルだけ — UEFI → GRUB → カーネル → initramfs → systemd のリレー。書き換えたブート順が戻される（20分）
  6. Ubuntu では、root にパスワードが無いとシングルユーザモードは何も聞かずに root を渡す — root がロックされた Ubuntu では、Enter 1回で root のシェル。本家の sulogin は止まる（18分）
  7. halt では電源は切れない — System halted と出た後も、外から見ると running。電源を抜くと、直前に書いたファイルが消えた（16分）
  8. kill は止めない。合図を送るだけ — TERM を無視するプロセスに kill を打っても消えない。pgrep が見る名前は 15 文字で切られる（16分）
  9. exit では消えず、切断で消える — & のジョブは exit では生き残り、回線が切れると消える（16分）
  10. X では、画面の側がサーバー — ssh -X は手元の X サーバーと相手の xauth が揃うまで何もしない。ここで10章が1本になる（14分）

檻で再現できないもの

出題範囲の語なぜ再現できないか代わりにしたこと
GUI 一式（startx・X サーバー・ディスプレイマネージャ・ウィンドウマネージャ・統合デスクトップ環境） 練習機には画面が無く（シリアルコンソールだけ）、X を入れても読者の手元に絵を出す経路が無い。読者ごとに見える絵も違う 第10章で、X が無いことと ssh -X の失敗のしかたを記録で見せ、役割の向きは理論で説明した
DVD・ISO イメージからのインストール（パッケージグループの選択など） インストーラは画面と数十分の対話を要し、毎回の画面を揃えられない。練習機は配布用のクラウドイメージから作った 第4章で、インストーラが決めるものが「どのファイルに残るか」を練習機の中から読んだ
レガシー BIOS からの起動 練習機のファームウェア（OVMF）は UEFI 専用 第5章で、同じディスクに BIOS 用の区画（BIOS boot）があることを見せ、違いは表にした
実機のブートメディア（USB・DVD）の抜き差し 練習機に物理の媒体は無い 第5章で、ファームウェアの設定画面の Boot Manager と efibootmgr で、本物の NVRAM のブート順を書き換えた
X の情報を出すコマンド（xdpyinfo・xwininfo・xlsclients・xwd・showrgb） 尋ねる先の X サーバーが無い（上の GUI と同じ理由） 第10章で、何を出すコマンドかを表にした（記録は無い）
virt-viewer（仮想マシンの画面を GUI で見る） 練習機には画面が無く（シリアルコンソールだけ）、読者の手元に GUI の窓を出す経路も無い 第1章で、同じ役目をシリアルコンソール（virsh console）で果たした
docker pull・docker images・docker create、build・commit・tag・export・import・save、restart・pause・kill・attach 外側のコンテナの中に docker は無い。docker は読者の PC で打つもので、イメージの取得はネットワークと読者の環境に左右される 第3章で、run との関係を表にした（記録は無い）

実務のどこで効くか

場面ここで効く理由見落としやすい点関連する章
リモートのサーバが応答しない 「電源は入っている（running）」と「OS が応答する」は別に確かめる必要がある クラウドのコンソールで「起動中」と出ていても、ssh が入れるとは限らない1・5
鍵で入れなくなった 受け取る側が鍵を断る理由は、相手のログにしか出ない authorized_keys や ~/.ssh の権限が緩いと、黙ってパスワードに戻る2
root のパスワードを忘れた／起動しなくなった GRUB でカーネル引数を足せば、ディスクの上の設定を変えずに入り方を変えられる それは攻撃者にもできる。コンソールに触れる人は root になれる5・6
長い処理を ssh 越しに走らせる 回線が切れたときに SIGHUP が届く exit で抜ける試験では気づけない。nohup か tmux を最初から使う9
