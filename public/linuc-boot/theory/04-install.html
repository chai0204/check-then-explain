4. GUI が無くても、既定は graphical.target

この練習機には X も、GUI のログイン画面も入っていない。それでも systemctl get-default は graphical.target と答え、runlevel は 5 と答える。 インストールのときに選ぶ「GUI か CUI か」は、入れるパッケージと、1本のシンボリックリンクの2か所で、別々に決まっている。

前提: 第3章まで読了所要 12分影響度 B出題範囲 1.01.1（重要度4）最終検証 2026-10-13

この章のゴール

  • インストーラが聞くこと（ブートメディア・タイムゾーン・パスワード・パッケージグループ・GUI/CUI）が、インストール後にどこに残るかを言える
  • GUI / CUI の既定がブートターゲットで決まることを、出力で示せる
  • root がロックされた Ubuntu の流儀を、passwd -S で確かめられる
ここで覚えなくていいこと: インストーラの画面ごとの操作（ディストリビューションと版ごとに違う）、 インストールを自動で進める仕組み（kickstart・autoinstall・cloud-init の書き方）、ロケールやキーボード配列の細かい選択肢。

インストーラが聞くことと、その行き先

この節で分かること: 「仕様書に従ってインストールする」とき、決めたことが後でどこに見えるか。

DVD や ISO イメージ（ブートメディア）から起動すると、インストーラが順に聞いてくる。答えはインストールが終わった後、決まった場所に残る。

聞かれること例インストール後に残る場所確かめるコマンド
どこから起動するか（ブートメディア）DVD・USB・ISO・ネットワークUEFI / BIOS の設定（ブート順）efibootmgr（第5章）
ディスクの割り当て/ と /boot と ESP、スワップパーティションと /etc/fstablsblk
タイムゾーンAsia/Tokyo/etc/localtime のリンク先timedatectl
パスワードroot のパスワード、最初のユーザ/etc/shadowpasswd -S
パッケージグループ（ソフトウェアの選択）Server with GUI / Minimal Install入っているパッケージdpkg-query / rpm -qa
GUI か CUI かグラフィカルログイン / テキストdefault.target のリンク先systemctl get-default

この練習機はインストーラではなく、Ubuntu が配っているクラウド用のイメージから作った（インストール済みのディスクを複製し、初回起動で名前やユーザを設定する方式）。 それでも、決めたことの置き場所は同じである。練習機の中で1つずつ読む。

たとえ: インストーラの質問は、新しい家に入るときの入居の申込書に近い。書いた内容（時刻の地域・合い言葉・家具のセット）は、それぞれ別の係に回されて保管される。
ただし崩れる点: 申込書は1枚の紙として手元に控えが残るが、インストールの答えは1か所にまとまって残らない。 タイムゾーンはリンクに、パスワードは /etc/shadow に、GUI か CUI かは別のリンクに散らばる。どこに回ったかを知らないと、後から読み返せない。

GUI と CUI は、パッケージとリンクで別々に決まる

この節で分かること: 既定のブートターゲットが何で決まり、GUI が入っているかとは関係なく決まること。

ふつうこう考える

この練習機には GUI を入れていない。インストールで GUI を選ばなかったのだから、既定は CUI の multi-user.target（昔のランレベル3）で起動しているはずだ。

$ systemctl get-default
graphical.target
$ runlevel
N 5
$ who -r
         run-level 5  2026-10-13 20:47
$ systemctl list-units --type=target --state=active --no-legend --no-pager | grep -E "graphical|multi-user"
  graphical.target        loaded active active Graphical Interface
  multi-user.target       loaded active active Multi-User System
だめな理由: 既定は graphical.target（GUI 用）で、ランレベルも 5 と答えた。GUI のログイン画面を出すプログラム（ディスプレイマネージャ）も X も入っていないのに、である。 「どこまで起動するか」（ターゲット）と、「GUI の部品が入っているか」（パッケージ）は別々に決まる。 Ubuntu のサーバ向けのイメージは systemd の元々の既定（graphical.target）を変えておらず、部品が無いまま graphical.target に到達している。
$ systemctl status display-manager.service
Unit display-manager.service could not be found.
$ ls /usr/share/xsessions /usr/bin/Xorg
ls: cannot access '/usr/share/xsessions': No such file or directory
ls: cannot access '/usr/bin/Xorg': No such file or directory
$ ls -l /usr/lib/systemd/system/default.target /etc/systemd/system/default.target
ls: cannot access '/etc/systemd/system/default.target': No such file or directory
lrwxrwxrwx 1 root root 16 Jul 29 00:04 /usr/lib/systemd/system/default.target -> graphical.target

graphical.target は「multi-user.target に、ディスプレイマネージャ（display-manager.service）を足したもの」である。 足すはずのものが入っていないので、graphical.target に着いても何も増えない。だから GUI の無いサーバが graphical.target で動いていても困らない。

既定の指定は /usr/lib/systemd/system/default.target というリンクで、/etc/systemd/system/default.target はまだ無い。 /etc 側にリンクを置けば、そちらが優先される。それを作るのが systemctl set-default で、第6章と演習04で使う。 RHEL 系のインストーラは、GUI を含まないパッケージグループを選ぶと、ここを multi-user.target にしておく。

たとえ: 既定のブートターゲットは、エレベーターに最初から押してある行き先の階のボタンに近い。 5階（graphical）が押してあれば、4階（multi-user）を通って5階まで上がる。5階に何も無くても（GUI が入っていなくても）、エレベーターは5階に着いて止まる。
ただし崩れる点: エレベーターは1つの階にしか止まっていないが、systemd のターゲットは重なっている。5階に着いた後も4階は「着いた」状態のままで、 上の出力でも graphical.target と multi-user.target が両方 active だった。

タイムゾーンとパスワード

この節で分かること: インストールで決めたタイムゾーンとパスワードの残り方。Ubuntu の root がどうなっているか。
$ timedatectl | grep -E "Local time|Time zone"
               Local time: Tue 2026-10-13 20:48:14 JST
                Time zone: Asia/Tokyo (JST, +0900)
$ ls -l /etc/localtime
lrwxrwxrwx 1 root root 30 Oct 13 10:06 /etc/localtime -> /usr/share/zoneinfo/Asia/Tokyo
$ localectl status
System Locale: LANG=C.UTF-8
    VC Keymap: (unset)
   X11 Layout: us
    X11 Model: pc105

タイムゾーンは /etc/localtime というリンクの行き先（Asia/Tokyo）として残っている。インストーラで選んだ地域が、このリンクになる。

$ sudo passwd -S root
root L 2026-09-05 0 99999 7 -1
$ sudo passwd -S student
student P 2026-10-13 0 99999 7 -1
$ sudo grep -E "^(root|student):" /etc/shadow | cut -d: -f1,2 | cut -c1-16
root:*
student:$y$j9T$z
$ id
uid=1000(student) gid=1000(student) groups=1000(student),4(adm),27(sudo)

passwd -S の2列目は、L がロック（パスワードでは入れない）、P が使えるパスワードあり。 root の /etc/shadow のパスワード欄は * で、どんなパスワードとも一致しない。 Ubuntu のインストーラは root にパスワードを付けず、最初のユーザを sudo グループに入れる（groups=…27(sudo)）。RHEL 系のインストーラは root のパスワードを聞く。

たとえ: Ubuntu の root は、鍵穴をふさいだ金庫に近い。合い鍵（パスワード）を作れないので、誰も鍵では開けられない。管理は sudo という別の扉から行う。
ただし崩れる点: ふさいだ金庫は誰にも開けられないが、Ubuntu の root は「鍵穴が無いなら確かめようがない」として、保守用の入口（シングルユーザモード）では逆に誰でも通してしまう。第6章で確かめる。

パッケージグループと、ディスクの割り当て

この節で分かること: 「用途を選ぶ」と何が入るか。ディスクがどう分けられたか。
$ dpkg-query -W | wc -l
418
$ dpkg-query -W -f='${db:Status-Abbrev} ${Package}\n' 'ubuntu-*'
un  ubuntu-advantage-tools
ii  ubuntu-cloud-minimal
un  ubuntu-cloudimage-keyring
un  ubuntu-core-launcher
ii  ubuntu-drivers-common
ii  ubuntu-keyring
ii  ubuntu-pro-client
un  ubuntu-pro-client-l10n
ii  ubuntu-release-upgrader-core
un  ubuntu-server
un  ubuntu-snappy
un  ubuntu-snappy-cli

練習機に入っているパッケージは 418 個。ubuntu- で始まるものの先頭の2文字が状態で、ii は入っている、un は名前だけ知っていて入っていない。 この練習機の中身を決めているのは ubuntu-cloud-minimal（クラウド向けの最小構成）で、ubuntu-server も GUI の ubuntu-desktop も入っていない。 こうした「中身を持たず、依存関係として他のパッケージをまとめて引き込むだけのパッケージ」（メタパッケージ）が、Ubuntu でのパッケージグループに当たる。

インストーラの「ソフトウェアの選択」は、個々のパッケージではなくパッケージグループ（用途ごとのまとまり）を選ばせる。

系統インストール時に選ぶもの後から見る・足す
RHEL・AlmaLinux など環境グループ（Server with GUI / Server / Minimal Install / Workstation）dnf group list / dnf groupinstall "Server with GUI"
Debian・Ubuntuタスク（デスクトップ環境・SSH サーバ など）、メタパッケージtasksel / apt install ubuntu-desktop

GUI のグループを後から足しても、既定のブートターゲットまでは変わらない場合がある。そのときは systemctl set-default graphical.target も要る（GUI とターゲットは別々、が前節の結論）。

$ lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS /dev/vda
NAME     SIZE FSTYPE MOUNTPOINTS
vda       20G
├─vda1    19G ext4   /
├─vda14    4M
├─vda15  106M vfat   /boot/efi
└─vda16  913M ext4   /boot

ディスクは4つに分けられている。/（ext4）、/boot（ext4）、/boot/efi（vfat、UEFI が読む区画）、そしてファイルシステムを持たない 4MB の区画（vda14）。 最後の2つが何のためにあるかは、次の第5章で、電源を入れてから login: が出るまでを追って確かめる。区画の作り方そのものは主題1.05 のコースで手を動かす。

手を動かす: 実践編の演習04は、この練習機の既定を CUI（multi-user.target）に変え、再起動しても CUI で起動することを確かめる課題である。 インストーラで CUI を選んだのと同じ状態を、後から作ることになる。
確認

次回の起動から GUI ではなく CUI（マルチユーザ）で起動するように設定したい。打つコマンドはどれか。

A. systemctl isolate multi-user.target　B. systemctl set-default multi-user.target　C. systemctl start multi-user.target　D. runlevel 3

答え

B。set-default は /etc/systemd/system/default.target のリンクを書き換え、次回の起動から効く。 A はいまの状態だけを切り替え、再起動すると既定に戻る。D の runlevel は今と前回のランレベルを表示するだけのコマンドである。

確認

runlevel を実行したら N 5 と表示された。それぞれの意味は何か。また systemd ではどのターゲットに当たるか。

答え

1つ目は前回のランレベルで、N は「前回が無い」（起動してから一度も切り替えていない）。2つ目がいまのランレベルで 5。 systemd では runlevel5.target が graphical.target を指している。この練習機は GUI が入っていなくても 5 と答えた。

確認

Ubuntu で sudo passwd -S root を実行すると、2列目に L と表示された。何を意味するか。

答え

root のパスワードがロックされている（パスワードでは root としてログインできない）。/etc/shadow のパスワード欄が * や ! で始まっている状態。 Ubuntu のインストーラは root にパスワードを付けず、最初のユーザに sudo を使わせる。

この章で分かったこと

持ち帰ってほしいこと

  • インストーラで決めたことは、インストール後にファイルとして残る（タイムゾーン → /etc/localtime、パスワード → /etc/shadow、GUI/CUI → default.target）
  • GUI / CUI は「どこまで起動するか（ターゲット）」と「GUI の部品が入っているか（パッケージ）」の2つで決まり、別々に変えられる
  • GUI の無い Ubuntu のサーバでも、既定は graphical.target のことがある。systemctl get-default と runlevel で確かめる
  • Ubuntu は root をロックし（passwd -S で L）、最初のユーザを sudo グループに入れる
  • パッケージグループは用途ごとのまとまり。RHEL 系は dnf group、Debian / Ubuntu は tasksel やメタパッケージ
