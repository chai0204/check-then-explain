1. virsh は電源を入れ、止まるよう頼むだけ

virsh start linuc は一瞬で Domain 'linuc' started と返る。その瞬間、練習機の中の OS はまだ1行も動いていない。 virsh shutdown は「止める」コマンドに見えるが、中の OS に「止まってほしい」と頼むだけで （練習機の中のゲストエージェントがつながっていればエージェント経由、いなければ ACPI の電源ボタンを押して）、止まるかどうかは中の OS が決める。 OS の都合に関係なく virsh ができるのは、電源を入れること、抜くこと、仮想の CPU を一時停止することである。

この章のゴールと前提所要 25分
前提: 檻が起動している前提: 端末を2つ開いている所要 25分影響度 B出題範囲 1.01.2（重要度4）最終検証 2026-10-13

この章のゴール

  • virsh で仮想マシンの一覧・起動・停止・強制停止・一時停止・自動起動を操作できる（list --all start shutdown destroy suspend resume autostart dominfo console）
  • 「定義がある」と「動いている」、「running」と「OS が応答する」が別のことだと、出力で示せる
  • virsh shutdown と virsh destroy の違いを、受け取る相手の違いとして説明できる
ここで覚えなくていいこと: libvirt の XML の各項目の意味（<memory> や <vcpu> が何を決めているかだけ分かれば足りる）、 virsh define / undefine による定義の作り直し、スナップショット（virsh snapshot-*）、仮想ネットワーク（virsh net-*）は扱わない。 仮想マシンを新しく作る virt-install も出てこない。出題範囲が求めているのは、できあがった仮想マシンの起動と停止とログインである。

定義はあるが、電源が入っていない

この節で分かること: 仮想マシンが「どこに・何として」あるか。一覧に出ない仮想マシンがあること。

檻に入ったら、外（lab@host）で一覧を出す。

$ virsh list
 Id   Name   State
--------------------

$ virsh list --all
 Id   Name    State
------------------------
 -    linuc   shut off

virsh list は動いている仮想マシンしか出さない。--all を付けて初めて、電源の入っていない linuc が見える。 試験で「停止しているものも含めて一覧する」と問われたら --all である。

ただし崩れる点: 実物の PC は電源を切っても部品がそこにあるが、仮想マシンは電源が切れている間、XML の文字とディスクのファイルでしかない。 電源を入れた瞬間にだけ、QEMU というプロセスがこの表を読んで、CPU やメモリを組み立てる。

shutdown は、止まるよう頼むだけ

この節で分かること: virsh shutdown と virsh destroy が、それぞれ誰に何を頼んでいるか。

起動し終わった練習機を止める。端末1は Ctrl+] でコンソールから抜けておき、端末2で打つ。

$ virsh shutdown linuc
Domain 'linuc' is being shutdown

$ virsh domstate linuc
running

$ virsh domstate linuc --reason
shut off (shutdown)

virsh shutdown の直後はまだ running で、十数秒たってから shut off になった。返事も「止めた」ではなく「止めている途中」（is being shutdown）である。 virsh shutdown は、仮想マシンを止めるのではなく、中の OS に「止まってほしい」と頼む。頼み方は2つあり、 練習機の中のゲストエージェント（さっき guest-ping に答えた案内役）がつながっていればエージェントに頼み、つながっていなければ ACPI の電源ボタンを押して知らせる。 どちらで頼まれたかは、受け取った OS の記録に残る。次の起動のときに読む。

ふつうこう考える

virsh shutdown は仮想マシンを止めるコマンドだ。時間がかかるのは OS の後片付けのせいで、 起動の途中（GRUB のメニューが出ている間）に打てば、片付けるものも無いのですぐ止まるはずだ。

端末1で virsh start linuc --console を打つ。GRUB のメニューが出たら、数え下げ（10 秒）が終わる前に、端末2で virsh shutdown linuc を打つ。

$ virsh start linuc --console
Domain 'linuc' started
（略）

（略）

（略）

（略）

（略）

$ virsh shutdown linuc
Domain 'linuc' is being shutdown

$ virsh domstate linuc
running
$ virsh domstate linuc --reason
running (unpaused)
だめな理由: 止まらなかった。GRUB のメニューはそのまま数え下げを終え、Ubuntu が最後まで起動して、ログインを待っている。 GRUB の間は、練習機の中にまだ OS もゲストエージェントもいない。エージェントがつながっていないので、virsh shutdown は ACPI の電源ボタンを押して頼んだ。 押されたことを受け取って「では止まろう」と決めるのは中の OS（Linux の systemd-logind）で、GRUB のメニューにはボタンを聞く者がいない。 聞く者がいない間に押されたボタンは、誰にも届かずに消えた（著者は4回試して4回とも同じだった）。 止めるかどうかを決めていたのは、virsh ではなく受け取る側だった。 （状態の理由が booted ではなく unpaused なのは、--console を付けて起動すると、virsh がいったん一時停止の状態で起動し、 コンソールをつないでから動かすため。起動の最初の表示を取りこぼさないための工夫で、ここでの話とは関係ない。）

では、最初の virsh shutdown（起動し終わってから打ったもの）は、どう頼まれたのか。端末1のコンソールでログインし、1つ前の起動の記録（journalctl -b -1）を読む（シリアルの画面は描き直しで行が欠けることがあり、下の記録では linuc login: の案内が消えて、打った student だけが残っている）。

今度は systemd-logind が「電源ボタンが短く押された」（Power key pressed short.）と受け取って、止まった。 頼み方は違っても、止めると決めたのは、どちらも中の OS（systemd-logind）である。

書き方頼み方
virsh shutdown linucゲストエージェントがつながっていればエージェント、いなければ ACPI の電源ボタン（libvirt が選ぶ）
virsh shutdown --mode agent linucゲストエージェントだけ（つながっていなければ失敗する）
virsh shutdown --mode acpi linucACPI の電源ボタンだけ

受け取る側に決めさせずに止める方法が1つだけある。電源を抜くことである。端末1は Ctrl+D と Ctrl+] で外に戻り、動いたままの練習機に対して端末2で打つ。

$ virsh destroy linuc
Domain 'linuc' destroyed

$ virsh domstate linuc --reason
shut off (destroyed)

destroy は名前に反して何も壊さない（定義もディスクも残る）。QEMU のプロセスを終わらせる、つまり電源コードを抜く。 中の OS は止まる準備をする暇が無いので、書きかけのデータは失われうる。何が起きるかは第7章で確かめる。

コマンド誰に届くか中の OS が断れるか
virsh startハイパーバイザー（QEMU のプロセスを起動する）— （まだ OS がいない）
virsh shutdown中の OS（ゲストエージェント、いなければ ACPI の電源ボタン）断れる・受け取る者がいなければ届かない
virsh reboot中の OS（同じく、ゲストエージェントか ACPI）断れる
virsh suspend / resumeハイパーバイザー（仮想の CPU を止める / 動かす。次の節）断れない（止められたことにも気づかない）
virsh destroyハイパーバイザー（QEMU のプロセスを終わらせる）断れない（電源を抜く）
virsh console仮想のシリアルポート— （画面とキーボードをつなぐだけ）
たとえ: virsh shutdown は、建物の中の人に「閉めてください」と頼むことに近い。館内電話（ゲストエージェント）がつながっていれば電話で、 つながっていなければ非常ボタン（ACPI の電源ボタン）を押して知らせる。virsh destroy は建物の電気を落とすことである。
ただし崩れる点: 実物の電源ボタンは押し続けると（4秒ほどで）強制的に電源が切れるが、virsh shutdown は何秒待っても強制には変わらない。 強制したければ、人が自分で destroy を打つ。

自動起動の印と、つなぎっぱなしのコンソール

この節で分かること: 起動のしかたを libvirt に覚えさせる方法と、コンソールが1人分しか無いこと。
$ virsh autostart linuc
Domain 'linuc' marked as autostarted

$ virsh dominfo linuc | grep Autostart
Autostart:      enable
$ ls -l ~/.config/libvirt/qemu/autostart/
total 0
lrwxrwxrwx 1 lab lab 40 Oct 13 20:44 linuc.xml -> /home/lab/.config/libvirt/qemu/linuc.xml
$ virsh start linuc
Domain 'linuc' started

自動起動の印は、定義へのシンボリックリンク1本である。libvirt は自分が起動したとき（実機ならホストの起動時、この檻ではコンテナの起動時）にこのディレクトリを見て、 印の付いた仮想マシンの電源を入れる。本当にそうなるかは第3章で、コンテナを止めて起動し直して確かめる。

電源を入れたまま、仮想の CPU だけを止めることもできる。

$ virsh suspend linuc
Domain 'linuc' suspended

$ virsh domstate linuc --reason
paused (user)

$ virsh resume linuc
Domain 'linuc' resumed

$ virsh domstate linuc --reason
running (unpaused)

virsh suspend で paused (user)（人が一時停止した）になり、virsh resume で動き出した。止めている間もメモリの中身はそのままで、 中の OS から見ると時間が飛んだだけである。止められたことを断ることも、気づくこともできない。

コンソールは1人分しか無い。試す。外の窓をもう1つ開き（docker exec -it lab-linuc-boot bash -l）、virsh console linuc でつなぐ。 つながったら Ctrl+] を押さずに、その窓を閉じる（端末のウィンドウやタブを閉じる）。それから端末1で virsh console linuc を打つ。

$ virsh console linuc
Connected to domain 'linuc'
Escape character is ^] (Ctrl + ])
error: operation failed: Active console session exists for this domain

$ virsh console --force linuc
Connected to domain 'linuc'
Escape character is ^] (Ctrl + ])

窓を閉じても、外のコンテナの中では古い virsh console が「つながっている」と言い張っている。--force で奪えば入れる（抜けるのは Ctrl+]）。 抜けるときは窓を閉じずに Ctrl+] で抜ける習慣にしておけば、こうはならない。

たとえ: コンソールは、サーバ室に1台だけある保守用の端末に近い。誰かが座っていれば、次の人は座れない。
ただし崩れる点: 実物の端末なら席を立てば空くが、virsh console は窓を閉じても「座っている」記録が残る。 空いているかどうかを決めているのは、端末を閉じた人ではなく、コンソールを持っている側（libvirt）である。
手を動かす: 実践編の演習01は、電源を入れ、自動起動の印を付ける課題である。 判定は libvirt に状態を尋ねるのとは別に、練習機の中の OS から返事が来るかを確かめる。running だけでは合格にならない。
確認

libvirt で管理している仮想マシンのうち、停止しているものも含めて一覧を表示するコマンドはどれか。

A. virsh list　B. virsh list --all　C. virsh dominfo　D. virsh domstate

答え

B。virsh list は動いているものだけを出す。実測では、電源の入っていない linuc は --all を付けたときにだけ shut off として出た。 dominfo と domstate は1台を指定して詳しく見るコマンドである。

確認

virsh shutdown vm1 を実行したが、いつまでも running のままである。ゲスト OS が応答していない。 仮想マシンを直ちに停止するコマンドはどれか。また、その副作用は何か。

答え

virsh destroy vm1。shutdown は中の OS に止まるよう頼むだけ（ゲストエージェントか ACPI の電源ボタンで）なので、受け取る OS が応答しなければ止まらない。 destroy は QEMU のプロセスを終わらせる（電源を抜く）。定義とディスクは消えないが、ゲストは後片付けをできないので、書きかけのデータを失うことがある。

確認

ホスト（この檻では外側のコンテナ）が起動したとき、仮想マシン vm1 も起動するように設定したい。打つコマンドは何か。

答え

virsh autostart vm1。virsh dominfo vm1 の Autostart が enable になる。 外すときは virsh autostart --disable vm1。

持ち帰ってほしいこと

  • virsh list は動いているものだけ。止まっているものまで見るのは virsh list --all
  • 仮想マシンのハードウェアは定義（XML）の数行で、ディスクは1つのファイル。dominfo dumpxml で読める
  • running は電源が入っているだけ。OS が起動し終わったかは、OS に尋ねないと分からない
  • virsh shutdown は中の OS に止まるよう頼むだけ。ゲストエージェントがつながっていればエージェント経由、いなければ ACPI の電源ボタンで頼み（--mode acpi で固定できる）、止めるかは中の OS が決める。受け取る者がいなければ届かない
  • virsh destroy は電源を抜く。受け手に決めさせない代わりに、後片付けもさせない。virsh suspend / resume は仮想の CPU を止める / 動かす
  • virsh console は1人分。抜けるのは Ctrl+]、奪うのは --force。自動起動は virsh autostart
