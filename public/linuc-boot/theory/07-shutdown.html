7. halt では電源は切れない

sudo halt を打つと、練習機は最後に reboot: System halted と書いて止まる。ところが外で virsh domstate を打つと running と出る。 halt が止めたのは CPU で、電源ではない。電源を切るのは poweroff で、しかもこの2つと shutdown reboot は、同じ1つのプログラムである。

この章のゴール

  • shutdown に時刻と文を渡して停止を予約し、取り消せる（-h -r -c now +分）
  • halt・poweroff・reboot の違いを、仮想マシンの状態で示せる

ここで覚えなくていいこと: systemd が止まるときのユニットの順番（shutdown.target・final.target）の細部、 ACPI の仕様、ログイン記録のファイル（wtmp）の形式、/run/systemd/shutdown/scheduled の各行の意味。

4つのコマンドは、同じプログラム

この節で分かること: shutdown halt poweroff reboot の正体。
$ ls -l /usr/sbin/shutdown /usr/sbin/halt /usr/sbin/poweroff /usr/sbin/reboot
lrwxrwxrwx 1 root root 16 Jul 29 00:04 /usr/sbin/halt -> ../bin/systemctl
lrwxrwxrwx 1 root root 16 Jul 29 00:04 /usr/sbin/poweroff -> ../bin/systemctl
lrwxrwxrwx 1 root root 16 Jul 29 00:04 /usr/sbin/reboot -> ../bin/systemctl
lrwxrwxrwx 1 root root 16 Jul 29 00:04 /usr/sbin/shutdown -> ../bin/systemctl

4つとも systemctl へのシンボリックリンクである。systemctl は「どの名前で呼ばれたか」を見て、halt なら halt、poweroff なら poweroff として振る舞う。 SysV init の時代に別々のプログラムだった名前を、互換のために残している。だから systemctl halt と halt、systemctl poweroff と poweroff は同じことをする。

たとえ: 4つのコマンドは、1人の係員が4つの窓口の名札を付け替えているのに近い。「停止」の窓口に座れば停止の受付を、「再起動」の窓口なら再起動の受付をする。
ただし崩れる点: 人は名札を替えても同じ人だと分かるが、コマンドの名前だけを見ても、それが同じプログラムかは分からない。ls -l でリンク先を見て初めて分かる。

予約して、知らせて、取り消す

この節で分かること: shutdown の時刻と文が、誰にどう届くか。

端末を2つ使う。端末2で練習機に入って待っておき、端末1で停止を予約する。

$ sudo shutdown -h +30 "メンテナンスのため停止します"
Shutdown scheduled for Tue 2026-10-13 21:28:18 JST, use 'shutdown -c' to cancel.
$ cat /run/systemd/shutdown/scheduled
USEC=1791894498606338
WARN_WALL=1
MODE=poweroff
UID=0
TTY=pts/2
WALL_MESSAGE=\xe3\x83\xa1\xe3\x83\xb3\xe3\x83\x86\xe3\x83\x8a\xe3\x83\xb3\xe3\x82\xb9\xe3\x81\xae\xe3\x81\x9f\xe3\x82\x81\xe5\x81\x9c\xe6\xad\xa2\xe3\x81\x97\xe3\x81\xbe\xe3\x81\x99
$ busctl get-property org.freedesktop.login1 /org/freedesktop/login1 org.freedesktop.login1.Manager ScheduledShutdown
(st) "poweroff" 1791894498606338
$ ls -l /run/nologin
ls: cannot access '/run/nologin': No such file or directory

shutdown は止めたのではなく、予約した。予約を持っているのは systemd-logind で、/run/systemd/shutdown/scheduled に時刻（1970年からのマイクロ秒）・種類・文が書かれている。 -h の種類は poweroff（電源を切る）になった。文は UTF-8 のバイト列を \x.. で書き並べた形で保存されている。

この時点で、端末2には何も届いていなかった。予約を取り消し、時刻の書き方を1つ確かめる。

$ sudo shutdown -c

Broadcast message from root@linuc on pts/2 (Tue 2026-10-13 20:58:27 JST):

System shutdown has been cancelled

$ sudo shutdown -r 10

Broadcast message from root@linuc on pts/2 (Tue 2026-10-13 20:58:31 JST):

The system will reboot at Tue 2026-10-13 21:08:31 JST!

Reboot scheduled for Tue 2026-10-13 21:08:31 JST, use 'shutdown -c' to cancel.
$ sudo shutdown -c

Broadcast message from root@linuc on pts/2 (Tue 2026-10-13 20:58:32 JST):

System shutdown has been cancelled

-r 10 は 20:58:31 に打って、予約は 21:08:31 だった。10 は「10 時」ではなく「10 分後」（+10 と同じ）と読まれる。10 時にしたいなら 10:00 と書く。 こちらは、予約した時点で知らせ（Broadcast message）が出た。

次の1行は、1分後に本当に電源を切る予約になる: 外の端末（lab@host）を先に開いておき、試したら 1分以内に 端末1で sudo shutdown -c を打って取り消す。 間に合わなければ練習機は止まる（外で virsh start linuc を打てば起動する）。
$ sudo shutdown

Broadcast message from root@linuc on pts/2 (Tue 2026-10-13 20:58:36 JST):

The system will power off at Tue 2026-10-13 20:59:36 JST!

Shutdown scheduled for Tue 2026-10-13 20:59:36 JST, use 'shutdown -c' to cancel.
$ cat /run/nologin
System is going down. Unprivileged users are not permitted to log in anymore. For technical details, see pam_nologin(8).

時刻を付けない shutdown は「いますぐ」ではなく「1分後」だった（20:58:36 に打って、予約は 20:59:36）。 今度はすぐに知らせ（Broadcast message）が出て、さらに /run/nologin が作られた。残り 5 分を切ると作られるファイルで、これがある間、一般ユーザは新しくログインできない。外の端末から試す。

$ ssh -v linuc hostname 2>&1 | grep -E 'Server accepts key|going down|Connection closed'

入れなかった。-v の表示を見ると、断られたのは鍵の照合の後である。練習機の sshd は鍵を受け入れ（Server accepts key）、 そのあと「このユーザをいまログインさせてよいか」を確かめる段（PAM のアカウントの確認。pam_nologin）で /run/nologin を見つけ、その文を見せて接続を閉じた。 端末1で予約を取り消し、練習機の側の記録を見る。

$ sudo shutdown -c

Broadcast message from root@linuc on pts/2 (Tue 2026-10-13 20:58:43 JST):

$ sudo journalctl -u ssh --no-pager -n 20 | grep 'Access denied'
Oct 13 20:58:41 linuc sshd[727]: fatal: Access denied for user student by PAM account configuration [preauth]
Oct 13 20:58:42 linuc sshd[729]: fatal: Access denied for user student by PAM account configuration [preauth]

sshd の記録にも「PAM のアカウントの設定で断った」（by PAM account configuration）と残っている。続けて、全員に文を送る wall と、止めないための shutdown -k を試す。

$ wall "これは wall の試験です"

Broadcast message from student@linuc (pts/0) (Tue Oct 13 20:58:48 2026):

これは wall の試験です

$ sudo shutdown -k now
$ systemctl is-system-running

-k は「止めない」ための書き方で、now を付けても何も起きず、システムは running のままだった（この版の systemd では、now のときは知らせも出なかった）。 時刻を付けた -k +5 "文" のような書き方なら、止めない予約として、知らせだけを送る（man shutdown の説明）。 入って待っていた端末2の画面には、ここまでの知らせがこう届いていた。

Broadcast message from root@linuc on pts/2 (Tue 2026-10-13 20:58:27 JST):

System shutdown has been cancelled

Broadcast message from root@linuc on pts/2 (Tue 2026-10-13 20:58:31 JST):

Broadcast message from root@linuc on pts/2 (Tue 2026-10-13 20:58:32 JST):

The system will power off at Tue 2026-10-13 20:59:36 JST!

Broadcast message from root@linuc on pts/2 (Tue 2026-10-13 20:58:43 JST):

System shutdown has been cancelled

Broadcast message from student@linuc (pts/0) (Tue Oct 13 20:58:48 2026):

これは wall の試験です

30 分後の予約（とその文）は、予約した時点では端末2に届いていない。10 分後の予約と1分後の予約は、すぐに届いた。 logind は残り時間に応じて間を置いて知らせるので、遠い予約ほど、最初の知らせは後になる。すぐ知らせたいなら wall を自分で打つ。

書き方意味
shutdown -h nowいますぐ止める（Ubuntu では電源を切る。-P と同じ）
shutdown -h +30 "文"30 分後に止める予約。文はログイン中の端末に届く
shutdown -r 23:00 / shutdown -r 1023 時に再起動 / 10 分後に再起動（数だけなら分）
shutdown -H now止めるが、電源は切らない（halt）
shutdown -k +5 "文"止めない。知らせだけを送る（now では何も起きなかった。実測）
shutdown -c予約を取り消す
shutdown（時刻なし）1 分後に電源を切る
shutdown -f / -F次の起動で fsck を飛ばす / 必ず行う（SysV init の書き方。systemd の shutdown は受け付けるが、何もしない）

halt と poweroff

この節で分かること: 「止める」と「電源を切る」が別のことだと。

halt の後に何が起きるかは、練習機の画面（コンソール）でしか見えない。外の窓で virsh console linuc をつないでおく （第6章からつないだままなら、そのままでよい）。端末2は exit で抜けておく。

ふつうこう考える

halt は「システムを止める」コマンドだ。止まったのだから、電源も切れているはずだ。外から見れば、仮想マシンは shut off になっているだろう。

$ sudo halt

Broadcast message from root@linuc on pts/1 (Tue 2026-10-13 20:58:58 JST):

The system will halt now!

$ Connection to 127.0.0.1 closed by remote host.
Connection to 127.0.0.1 closed.
[  OK  ] Reached target shutdown.target - System Shutdown.
[  OK  ] Reached target final.target - Late Shutdown Services.
[  OK  ] Finished systemd-halt.service - System Halt.
[  OK  ] Reached target halt.target - System Halt.
[  104.285935] reboot: System halted
$ virsh domstate linuc --reason
running (booted)
だめな理由: 練習機の中では systemd が後片付けを終え、カーネルが System halted と書いて止まった。それでも外から見ると running のままで、 10 秒待っても変わらない。halt は CPU を止める（何もしない状態で待たせる）だけで、電源を切る指示は出さない。 電源を切るのは別の動き（ACPI でハードウェアに「切って」と頼む）で、それをするのが poweroff である。 昔の機械では halt の後に人が電源スイッチを切った。仮想マシンでは、外から virsh destroy で切るしかない。
$ virsh destroy linuc
Domain 'linuc' destroyed

$ virsh domstate linuc --reason
shut off (destroyed)

$ virsh start linuc
Domain 'linuc' started

コンソールは destroy で切れたので（外の端末に戻っている）、起動し直したら virsh console linuc でつなぎ直す。 login: が出たら、端末1で練習機に入り直し、同じことを poweroff で行う。

$ sudo poweroff

Broadcast message from root@linuc on pts/1 (Tue 2026-10-13 21:00:19 JST):

The system will power off now!

$ Connection to 127.0.0.1 closed by remote host.
Connection to 127.0.0.1 closed.
[  OK  ] Reached target shutdown.target - System Shutdown.
[  OK  ] Reached target final.target - Late Shutdown Services.
[  OK  ] Finished systemd-poweroff.service - System Power Off.
[  OK  ] Reached target poweroff.target - System Power Off.
[   50.019723] reboot: Power down
$ virsh domstate linuc --reason
shut off (shutdown)

$ virsh start linuc
Domain 'linuc' started

最後の行が reboot: Power down に変わり、外から見た状態も shut off (shutdown)（中から止まった）になった。 halt と poweroff の違いは、止まる最後に電源を切るよう頼むかどうかだけである。前の節で見たとおり、Ubuntu の shutdown -h は poweroff として予約された（MODE=poweroff）。 止めるだけにしたいときは shutdown -H、電源まで切るなら shutdown -P と書き分けられる。

書き方（試験に出るもの）意味
halt -phalt と打ちながら電源まで切る（poweroff と同じ）
halt -f / reboot -f / poweroff -fサービスを順に止める後片付けをせずに、すぐに止める / 再起動する / 電源を切る（systemd に頼まない）
halt -w / reboot -w止めずに、ログインの記録（wtmp）に停止・再起動の印だけを書く

この表の書き方は試していない（-f は電源を抜くのに近く、-w は次の節で読む起動の記録を書き換えてしまうため）。意味は Ubuntu 24.04 の man halt による。

たとえ: halt は、店の閉店作業を終えて照明を落とした状態に近い。店は営業していないが、建物の電気（電源）は来たままである。poweroff はブレーカーまで落とす。
ただし崩れる点: 店なら照明が消えていれば外から「閉まった」と分かるが、仮想マシンは halt した後も外からは running にしか見えない。 中で何が起きたかは、コンソールの最後の1行（System halted）を見ないと分からない。

電源を抜くと、次の起動で何が起きるか

この節で分かること: 正しく止めることに、何の意味があるか。

今度は、正しく止めずに電源を抜く。起動したら端末1で練習機に入り直し、ファイルを1つ書いて、数秒のうちに外から virsh destroy する。

$ echo "抜く前に書いた" > memo.txt; ls -l memo.txt
-rw-rw-r-- 1 student student 22 Oct 13 21:01 memo.txt
$ Connection to 127.0.0.1 closed by remote host.
Connection to 127.0.0.1 closed.
$ virsh destroy linuc
Domain 'linuc' destroyed

$ virsh start linuc
Domain 'linuc' started

起動し直したら、もう一度入って、同じ場所を見る。

$ sudo cat /run/initramfs/fsck.log
Log of fsck -C -a -V -t ext4 /dev/vda1
Tue Oct 13 12:01:48 2026

fsck from util-linux 2.39.3
[/usr/sbin/fsck.ext4 (1) -- /dev/vda1] fsck.ext4 -a -C0 /dev/vda1
cloudimg-rootfs: recovering journal
cloudimg-rootfs: Clearing orphaned inode 1525 (uid=0, gid=0, mode=0100600, size=0)
cloudimg-rootfs: clean, 31930/2490368 files, 431989/4980475 blocks

Tue Oct 13 12:01:48 2026
----------------
$ ls -l memo.txt; cat memo.txt
ls: cannot access 'memo.txt': No such file or directory
cat: memo.txt: No such file or directory

2つのことが起きている。1つ目に、起動の途中（initramfs の中）で fsck がルートのファイルシステムを調べ、recovering journal（ジャーナルを再生した）と書いている。 ext4 は、書き換えの予定を先にジャーナルという控えに書いてから、本体を書き換える。途中で電源が切れても、次の起動で控えを読み直せば、ファイルシステムを壊れていない状態に戻せる。 Clearing orphaned inode の行は、使い終わる途中だったファイル（消す予定の i ノード）を、fsck が片付けた跡である。正しく止めたときは止める前に書き終えているので、この作業は要らない（第5章の起動では clean とだけ出ていた）。 なお、この記録の時刻は UTC（日本時間の 9 時間前）で書かれている。initramfs の中では、まだタイムゾーンの設定を読んでいないからである。

2つ目に、電源を抜く数秒前に書いた memo.txt は、ファイルごと残っていなかった。ファイルシステムが守ったのは「壊れていない」ことで、「書いたものが残る」ことではない。 書いた中身はすぐにはディスクに書かれず、しばらくメモリの上に置かれてから、まとめて書き出される。その前に電源が消えれば、書いたつもりのものは無かったことになる。 shutdown や poweroff が止まる前にしていたのは、この書き出しと、各サービスの後片付けである。

たとえ: 正しい停止は、閉店のあとで帳簿を締めて金庫にしまうことに近い。電源を抜くのは、営業中に停電することである。 翌朝、帳簿の控え（ジャーナル）を見れば、最後に締めたところまでは戻せる。
ただし崩れる点: 店なら、停電の直前に書いた注文のメモも、紙として机の上に残っている。コンピュータでは、書いたつもりのものはまだメモリの上にあり、紙（ディスク）に写す前だった。 「書いた」と「残った」が別の出来事であるところが、人の感覚とずれる。

reboot と、起動の記録

この節で分かること: 再起動したことを、後から確かめる方法。

最後に再起動する。/proc/sys/kernel/random/boot_id は起動のたびに作り直される乱数で、この値が変われば、間に再起動があったと分かる。

$ cat /proc/sys/kernel/random/boot_id
eb182ae3-cb67-4295-b118-7c3ee4bf1f65
$ sudo reboot

Broadcast message from root@linuc on pts/1 (Tue 2026-10-13 21:02:20 JST):

The system will reboot now!

$ Connection to 127.0.0.1 closed by remote host.
Connection to 127.0.0.1 closed.
$ cat /proc/sys/kernel/random/boot_id
9e8d6a13-e94c-49b8-be31-06601b44d025
$ last -x reboot shutdown | head -8
reboot   system boot  6.8.0-142-generi Tue Oct 13 21:03   still running
shutdown system down  6.8.0-142-generi Tue Oct 13 21:02 - 21:03  (00:00)
reboot   system boot  6.8.0-142-generi Tue Oct 13 21:01 - 21:02  (00:00)
reboot   system boot  6.8.0-142-generi Tue Oct 13 21:00 - 21:02  (00:01)
shutdown system down  6.8.0-142-generi Tue Oct 13 21:00 - 21:00  (00:00)
（略）

boot_id が変わった。last -x は、ログインの記録から起動（reboot）と停止（shutdown）の行を出す。1行が1回の起動か停止で、新しいものが上に並ぶ。 正しく止めた起動は、その上に shutdown の行が付く。電源を抜かれた起動には shutdown の行が無く、reboot の行が2つ続いている（上から3行目と4行目）。 後から「この機械は正しく止められていたか」を調べるときの手がかりになる（6行目より下は、それまでに何回起動し直したかで人ごとに変わるので略した）。

reboot も、これまでの3つと同じく systemctl へのリンクで、shutdown -r now と同じことをする。再起動の前に、ログイン中の端末へ知らせが届き、接続が閉じられた。

手を動かす: 実践編の演習05は、30 分後に電源を切る予約を、理由の文を付けて入れる課題である。 判定は予約を持っている systemd-logind に、予約の種類・時刻・文を尋ねる。確かめたら shutdown -c で取り消すこと。
確認

10 分後にシステムの電源を切り、ログイン中のユーザに「メンテナンスします」と知らせたい。正しいコマンドはどれか。

A. shutdown -c +10 "メンテナンスします"
B. shutdown -h +10 "メンテナンスします"
C. shutdown -r 10 "メンテナンスします"
D. halt +10 "メンテナンスします"

答え

B。時刻は +分（または hh:mm、now）、文は時刻の後に書く。-h は Ubuntu（systemd）では電源断（poweroff）になった（実測で MODE=poweroff）。 A の -c は予約の取り消し、C の -r は再起動で、数だけの 10 は「10 分後」（+10 と同じ）と読まれる（実測。10 時にするなら 10:00）。

確認

shutdown を時刻なしで実行したら、どうなるか。

答え

1分後の電源断が予約される（すぐには止まらない）。実測では「The system will power off at …!」がすぐに他の端末へ届き、 残り 5 分以内なので /run/nologin が作られて、一般ユーザは新しくログインできなくなった。

確認

halt と poweroff の違いは何か。

答え

どちらもシステムを止めるが、halt は CPU を止めるだけで電源は切らない。poweroff は最後にハードウェア（ACPI）に電源を切ってもらう。 実測では halt の後も仮想マシンは running のままで、poweroff の後は shut off (shutdown) になった。

確認

予約した停止を取り消すコマンドは何か。取り消すと、ログイン中のユーザには何が届くか。

答え

shutdown -c。ログイン中の端末に「System shutdown has been cancelled」という知らせ（Broadcast message）が届いた（実測）。

この章で分かったこと

持ち帰ってほしいこと

  • shutdown halt poweroff reboot はどれも systemctl へのリンク。呼ばれた名前で動きを変える
  • shutdown -h +30 "文" は予約。予約を持つのは systemd-logind で、shutdown -c で取り消す。時刻なしは1分後、数だけ（-r 10）は分。-k は知らせだけで止めない
  • 残り 5 分を切ると /run/nologin ができ、一般ユーザは新しくログインできない（鍵の照合は通り、その後の PAM の確認で断られる）。wall は全端末に文を送る
  • halt は CPU を止めるだけで、電源は切らない。電源を切るのは poweroff
  • 電源を抜くと（virsh destroy）、次の起動でファイルシステムの回復が走る。止め方の違いは、後片付けをさせるかどうか
