9. exit では消えず、切断で消える

& でバックグラウンドに回したジョブは、ログアウトすると消える——と教わることが多い。練習機で確かめると、exit で抜けたときは消えなかった。 消えたのは、回線が切れたときだった。消すのはログアウトではなく、回線が切れたときに届く SIGHUP という合図で、それをどう扱うかを決めておくのが nohup と tmux / screen である。

前提: 第8章まで読了前提: 端末を2つ開いている所要 16分影響度 B出題範囲 1.01.4（重要度3）最終検証 2026-10-13

この章のゴール

  • &・Ctrl+Z・jobs・bg・fg で、フォアグラウンドとバックグラウンドを行き来できる
  • ssh を切断したときに何が起きるかを、SIGHUP という言葉で説明できる
  • nohup と tmux / screen で、切断しても止まらない処理を残せる
ここで覚えなくていいこと: tmux と screen の画面分割・設定ファイル（~/.tmux.conf・~/.screenrc）、 disown や setsid など他の切り離し方、bash がジョブを管理する仕組み（プロセスグループ・端末の制御）の細部。

フォアグラウンドとバックグラウンド

この節で分かること: ジョブを止めて、後ろで動かして、前に戻す。

端末を2つ使う。端末1は、外（lab@host）から ssh linuc で練習機に入り、入ったり切ったりする係。端末2は、練習機に入ったまま様子を見る係にする。

端末1で練習機に入り、sleep 300（300 秒待つだけのコマンド）を打って、終わる前に Ctrl+Z を押す。

$ sleep 300
^Z
[1]+  Stopped                 sleep 300
$ jobs -l
[1]+   766 Stopped                 sleep 300
$ ps -o pid,stat,cmd -p $(pgrep -f "sleep 300")
    PID STAT CMD
    766 T    sleep 300
$ bg
[1]+ sleep 300 &
$ jobs
[1]+  Running                 sleep 300 &
$ fg
sleep 300
^C
$ jobs
$ exit
logout
Connection to 127.0.0.1 closed.

打ったコマンドが終わるまでプロンプトが戻らない状態をフォアグラウンド、プロンプトが戻って、裏で動き続けている状態をバックグラウンドと呼ぶ。シェルはそれぞれをジョブとして番号（[1]）で管理する。

操作何が起きたか（上の記録）
Ctrl+Z端末が TSTP（20番）を送り、sleep は止まった（Stopped、ps の状態は T）。終わったのではない
jobsこのシェルのジョブの一覧。-l で PID も出る。+ は今のジョブ（番号を省いたときの相手）、- はその前のもの
bg止めたジョブを、バックグラウンドで再開した（[1]+ sleep 300 &）
fgバックグラウンドのジョブを、フォアグラウンドに戻した。ここで Ctrl+C（INT、2番）を押して終わらせた
末尾の &はじめからバックグラウンドで起動する（次の節）

ジョブが複数あるときは、番号で選ぶ。端末2（練習機の中）で試す。

$ sleep 701 &
[1] 771
$ sleep 702 &
[2] 772
$ jobs
[1]-  Running                 sleep 701 &
[2]+  Running                 sleep 702 &
$ fg 2
sleep 702
^C
$ fg %1
sleep 701
^C
$ jobs
$ sleep 703 &
[1] 773
$ kill %1
$ jobs
[1]+  Terminated              sleep 703

fg 2 は2番のジョブ（sleep 702）を、fg %1 は1番のジョブを前に戻した。番号の前の % は付けても付けなくてもよい（bg も同じ）。 kill %1 のように、ジョブ番号は kill にも渡せるが、そのときは % が要る（% を付けないと PID の意味になる）。 ジョブはシェルごとの番号で、別の端末のシェルからは見えない（そちらでは PID を使う）。

たとえ: 端末は、1本しかないマイクに近い。フォアグラウンドのジョブだけがマイクを持っていて、あなたのキー入力を受け取れる。 バックグラウンドのジョブはマイクを持たずに作業を続け、Ctrl+Z はマイクを持っている者の作業を凍らせる。
ただし崩れる点: マイクを持っていなくても、バックグラウンドのジョブは端末に文字を出せる。入力は受け取れないのに出力はできるので、前で打っているコマンドの表示に割り込んで混ざることがある。 この章の nohup の案内が、プロンプトの後ろに出たのもそのためである。

exit と切断

この節で分かること: & のジョブが消えるのは、いつか。

ふつうこう考える

末尾に & を付けてバックグラウンドで動かしたジョブは、ログアウトすると一緒に消える。だから、ログアウトした後も動かし続けたいなら nohup が要る。

$ sleep 1001 &
[1] 789
$ jobs -l
[1]+   789 Running                 sleep 1001 &
$ shopt huponexit
huponexit      	off
$ exit
logout
Connection to 127.0.0.1 closed.
$ pgrep -a -f 'sleep 100'
789 sleep 1001
だめな理由: exit でログアウトしても、sleep 1001 は消えずに動いている。 bash は、自分が終わるときにジョブへ SIGHUP（1番、「端末が無くなった」という合図）を配るかどうかを huponexit という設定で決めていて、これが off だった（Ubuntu の既定）。 自分から exit したときは、ジョブに合図は届かない。

今度は、回線が切れたときを再現する。ssh は、行の先頭で ~.（チルダ、ピリオドの順）を打つと、その場で接続を切る。~. は画面に出ないので、Enter を押してから打つ。相手から見ると、回線が突然切れたのと同じである。

$ sleep 1002 &
[1] 808
$
$ Connection to 127.0.0.1 closed.
$ pgrep -a -f 'sleep 100'
789 sleep 1001

sleep 1002 は消えた（sleep 1001 だけが残っている）。回線が切れると、練習機の sshd はログインに使っていた端末（擬似端末）を閉じ、ログインしていたシェルに SIGHUP が届く。 bash は SIGHUP を受け取ると、自分のジョブにも SIGHUP を配ってから終わる。sleep は SIGHUP を無視していないので、既定の動き（終了）で終わった。 「ログアウトするとジョブが消える」と言われるのは、端末のウィンドウを閉じる・回線が切れるといった、この経路のことである。

試験との関係: 試験の例題では「ログアウトすると、& のジョブにも HUP が送られて止まる」と説明されることがある。 bash の既定（huponexit が off）では、上で見たとおり exit では送らず、回線が切れたときに送る。どちらの説明でも、 「ログアウトした後も実行を続けるには」と問われたら、答えは nohup（と、端末ごと残す screen・tmux）である。
たとえ: & のジョブは、部屋（シェル）に残した作業員に近い。exit は、あなたが静かに部屋を出ることで、作業員には何も言わないので作業は続く。 切断は、建物の回線が切れて非常放送（SIGHUP）が流れることで、作業員はふつう放送を聞いて帰る。
ただし崩れる点: 建物の停電なら作業そのものができなくなるが、練習機は止まっていない。消えたのは「つながっていた端末」だけで、作業員を帰らせたのは停電ではなく、シェルが流した放送のほうである。 放送を聞かない作業員（次の節の nohup）は、端末が消えた後も仕事を続ける。

nohup: SIGHUP を無視させてから起動する

この節で分かること: nohup が実際に何を変えているか。

nohup を付けて起動し、同じように ~. で切断する。

$ nohup sleep 1003 &
[1] 826
$ nohup: ignoring input and appending output to 'nohup.out'

$ grep SigIgn /proc/$!/status
SigIgn:	0000000000000001
$
$ Connection to 127.0.0.1 closed.
$ pgrep -a -f 'sleep 100'
789 sleep 1001
826 sleep 1003
$ cat ~/nohup.out; ls -l ~/nohup.out
-rw------- 1 student student 0 Oct 13 21:05 /home/student/nohup.out

sleep 1003 は切断の後も残った。nohup は、SIGHUP を無視する設定にしてから、指定したコマンドを起動する。 SigIgn の右端（1番、HUP）が立っているのがその印で（第8章の読み方）、無視の設定は起動したコマンドに引き継がれる。だから SIGHUP が届いても何も起きない。

nohup はもう1つ、出力の行き先も変える。端末が消えた後に端末へ書こうとすると困るので、出力を nohup.out（カレントディレクトリ。書けなければホームディレクトリ）に足していく。 sleep は何も出さないので 0 バイトのままで、ファイルは本人しか読めない形（-rw-------）で作られた。 なお、nohup の案内（nohup: ignoring input and appending output to 'nohup.out'）は、バックグラウンドのジョブが出すので、プロンプトの後ろに出ることがある。Enter を押せば新しいプロンプトが出る。

nohup は SIGHUP を無視させるだけで、ジョブを端末から切り離すわけではない。末尾の & を付けなければ、nohup を付けてもフォアグラウンドで動き、プロンプトは戻らない。

tmux と screen: 端末ごと練習機に預ける

この節で分かること: 切断しても、後から画面ごと戻れる方法。

nohup は「合図を無視させる」方法だった。もう1つの方法は、端末そのものを練習機の中に残しておくことである。 1つの端末の中で複数の端末を動かし、それを切り離して残しておけるソフトを端末多重化（ターミナルマルチプレクサ）と呼び、tmux と screen がある。

端末1で練習機に入り、tmux new -s work を打つ。画面が tmux の中に切り替わり、下端に [work] で始まる帯が出る。そこで lab-count（1秒ごとに数を数える）を打ち、数え始めたら Ctrl+B を押してから d を押す。 画面は元に戻り、[detached (from session work)] と出る。そのまま ~. で切断する。

$ tmux new -s work
[detached (from session work)]
$
$ Connection to 127.0.0.1 closed.
$ tmux ls
work: 1 windows (created Tue Oct 13 21:05:19 2026)
$ pgrep -a lab-count
861 /bin/bash /usr/local/bin/lab-count

セッション work は残っていて、lab-count も動いている。端末1でもう一度練習機に入り、tmux attach -t work で戻る。

切り離して、回線まで切っていた間も、lab-count は数え続けていた。戻った画面には、その間の表示がそのまま残っている。 tmux の中のプログラムは、あなたの ssh のシェルではなく、練習機の中で動き続ける tmux（の server）の子として動いているので、回線が切れても SIGHUP は届かない。 Ctrl+C で lab-count を止め、tmux の中のシェルを exit で終えると、セッションも終わる（[exited]）。

$ tmux attach -t work
[exited]
$ exit
logout
Connection to 127.0.0.1 closed.

たとえ: nohup は、作業員に耳栓をさせて放送が聞こえないようにすること。tmux と screen は、作業部屋ごと練習機の中に移して、あなたは窓から覗いているだけにすることに近い。窓（ssh）が割れても、部屋は無事である。
ただし崩れる点: 本物の窓なら、見ていなかった間の出来事は見えない。tmux は画面の中身ごと持っているので、戻った人は、離れていた間に画面に出たものを続きから見られる。 nohup にはこれが無く、出力は nohup.out というファイルに溜まるだけである。
手を動かす: 実践編の演習07は、lab-count を切断しても止まらない形で動かし、実際に ~. で切断してから確かめる課題である。 判定は、プロセスの親をたどり、SIGHUP を無視しているか（/proc/PID/status の SigIgn）、tmux / screen の中にいるかを見る。
確認

ログアウトした後もコマンド backup.sh を実行し続けさせたい。SIGHUP を無視させて起動するコマンドはどれか。

A. bg backup.sh　B. nohup backup.sh &　C. jobs backup.sh　D. fg backup.sh

答え

B。nohup は SIGHUP を無視する設定にしてから起動する。端末に出るはずの出力は nohup.out に書かれる。 末尾の & でバックグラウンドにすると、すぐにプロンプトが戻る。

確認

実行中のコマンドを Ctrl+Z で一時停止した。それをバックグラウンドで実行し直すコマンドと、フォアグラウンドに戻すコマンドは何か。

答え

bg でバックグラウンドで再開、fg でフォアグラウンドに戻す。ジョブが複数あるときは bg %2 のようにジョブ番号を付ける。 一覧は jobs（-l で PID も）。実測では、止めたジョブの状態は ps で T（停止）と出た。

確認

tmux のセッションから、中のプログラムを動かしたまま抜けるキー操作は何か。また、後から戻るコマンドは何か。

答え

Ctrl+B を押してから d（デタッチ）。戻るのは tmux attach -t セッション名（一覧は tmux ls）。 screen なら Ctrl+A → d で抜け、screen -r で戻る（一覧は screen -ls）。

この章で分かったこと

持ち帰ってほしいこと

  • 末尾の & でバックグラウンド、Ctrl+Z で一時停止、bg で後ろで再開、fg で前へ、jobs で一覧
  • 回線が切れると、ログインしていたシェルに SIGHUP が届き、シェルはそれを自分のジョブに配る。& だけのジョブはこれで止まる
  • exit で普通に抜けたときは、bash は（huponexit が off なので）ジョブに配らない。だから「exit では消えず、切断で消える」
  • nohup は SIGHUP を無視させてから起動する（SigIgn の 1番が立つ）。出力は nohup.out
  • tmux / screen は端末ごと相手に残す。切断しても動き続け、後から画面ごと戻れる
