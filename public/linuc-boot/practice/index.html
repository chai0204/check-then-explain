確かめて説明する LinuC 主題1.01

LinuC レベル1 101 試験・主題1.01「Linux のインストールと仮想マシン・コンテナの利用」 （起動と停止・ssh での接続 / 仮想マシンとコンテナ / ブートプロセスと systemd / プロセス / デスクトップ）を、 コンテナの中で動く本物の仮想マシンで確かめます。 電源を入れる、GRUB でカーネルに引数を渡す、シングルユーザモードで入る、halt で止める——全部あなたの手で打てます。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: コマンドは打てる。写経すれば動く。 でも「なぜ動くのか」を人に説明できない人。
LinuC を受ける人向けには: 出題範囲を読んで「そういうことができるんだな」で止まっている人。

この教材の檻

檻準備ここで触れるここでは触れない（逃がす先）
仮想マシン型（コンテナの中で QEMU が練習機を1台動かす）5分 virsh・UEFI の設定画面と efibootmgr・GRUB・カーネル引数・systemd のターゲット・shutdown halt・ssh の鍵・シグナル GUI（X）・DVD からのインストーラ・レガシー BIOS → 理論編で説明（理由）

端末には2つの場所があります。プロンプトで、いまどちらにいるかが分かります。

あなたの PC（ホスト OS）
└─ コンテナ          lab@host       … 外。virsh・ssh・lab check を打つ場所
   └─ 練習機（QEMU）  student@linuc  … 仮想マシン。Ubuntu 24.04 が自分のカーネルで動く

影響度 B（変更は練習機とコンテナの中だけ。あなたの PC の設定もファイルも書き換えません）。 練習機はシステム全体を触る演習をします。壊したら外で vm reset --yes を打てば、工場出荷時に戻ります。 演習を始めるとき lab は「元に戻すには起動し直してください」と出しますが、この檻では起動し直しても練習機は戻りません（ディスクはボリュームに残ります）。戻すのは vm reset --yes です。 あなたの PC で同じことはしないでください（GRUB や root の入り方を変える章があります）。

練習機は KVM を使わない完全エミュレーションで動きます。あなたの PC に特権を1つも求めない代わりに、 起動に 30〜90 秒かかります。本文の出力は、すべてこの条件で取ったものです。

はじめる

Docker の場合。2行です。

docker run -d --name lab-linuc-boot --hostname host --stop-timeout 30 \
  -v lab-linuc-boot-vm:/home/lab/vm \
  -v lab-linuc-boot-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:boot-1.0.1@sha256:a442381b8ff6ee27bb22dfa933605fb8b0d42426cfb547cd2e975c2fbe2cf3c1

docker exec -it lab-linuc-boot bash -l
  • --stop-timeout 30 は外さないでください。docker stop のとき、練習機を正常に止めるのに十数秒かかります（著者の環境で 12.4 秒）。 docker の既定の猶予（10 秒）では途中で打ち切られ、練習機は電源を抜かれたのと同じになります（第3章・第7章）。
  • --privileged も --cap-add も要りません。練習機は QEMU がソフトだけで動かすので、あなたの PC の特権を借りません。
  • 端末は2つ以上あると楽です（練習機の画面を見る端末と、操作する端末）。docker exec -it lab-linuc-boot bash -l を別の窓でもう一度打てば増えます。

入ると現在地が出ます。練習機の電源は、まだ入っていません（第1章で、あなたが入れます）。

練習機 linuc: shut off（エージェント — / ssh —）
  vm start / vm ssh / vm console / vm stop   練習機の操作（中身は virsh と ssh）

── lab-linuc-boot 1.0.0 ────────────────────────────────────────
lab-linuc-boot  進捗 0/7
  次 → 01 「練習機に電源を入れ、自動で起動するようにする」 (目安 10分 / 影響度 B)
  lab start 01 で課題を開く
  進捗の保存先: /home/lab/.lab/progress.json（消すには docker volume rm lab-linuc-boot-state）
  lab ls      演習一覧 / lab start NN  課題を開く / lab check  答え合わせ
────────────────────────────────────────────────────────────

1行目は練習機の状態で、vm は virsh と ssh を包んだ短縮のコマンドです（打つと中で何を実行したかを表示します）。 この教材では、仮想マシンを操作するコマンドそのもの（virsh）を覚えるために、本文では virsh を直接打ちます。

演習

7本あります。判定は観測できる結果だけで行い、コマンドの打ち方は見ません。 判定は外の端末でも、練習機の中でも lab check NN で打てます。 詰まったら lab hint NN を何度でも。使い切ったら lab solve NN で模範解答に必ず届きます （見ても構いません。進捗には「solve を見た」として残ります）。

Noやること副題目安

終わったら

docker stop lab-linuc-boot                # 練習機を正常に止めてから止まる
docker rm lab-linuc-boot
docker volume rm lab-linuc-boot-vm lab-linuc-boot-state   # 練習機のディスクと進捗も消す場合だけ

イメージは docker rmi で消せます。 あなたの PC には何も残りません（名前付きボリューム以外のファイルを作っていないため）。 続きをやる日は docker start lab-linuc-boot で再開できます（練習機のディスクも、進捗も、そのまま残っています）。
