理論編 — ネットワークの基礎

LinuC レベル1 102 試験・主題1.07（重要度の合計 14。102 の主題の中で最も重い）を、 仮想マシンの中に作った「社内 LAN」で実際に打って確かめる9章。 1章ごとに「実際に打つと何が出るか」を先に置いています。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この9章を貫いている1つの事実

ネットワークの「見え方」は、道具が読んだ表で決まる。
ifconfig と ip、ifup と nmcli、dig と ping は、同じものを別々の表から読んでいる。
つながらないときは、相手を疑う前に「どの道具が、どの表の、どの1行を読んだか」を確かめる。

ifconfig は NIC に付いた2つ目のアドレスを表示しない。ifdown は自分の作業記録に無い NIC を下げない。 dig が 172.16.20.10 と答えても、ping は /etc/hosts の古い行を先に読んで 172.16.20.99 へ行く。 どれも壊れているのではなく、読んでいる表が違う。主題1.07 の詳細欄にコマンドと設定ファイルが並んでいるのは、 試験が「どの道具が何を読むか」を問うているからです。

ここで覚えなくていいこと: IP ヘッダのフィールドの並び（TTL だけは第5章で使う）、DNS サーバ側の設定（ゾーンファイルや再帰の仕組み。レベル2の範囲）、 ルーティングプロトコル（OSPF / BGP。経路をルータ同士で自動でやり取りする仕組み。主題1.07 が扱うのは、経路表を手で読み、デフォルトルート・ネットワーク宛て・1台宛ての行を足し引きするところまで）、ファイアウォール（主題1.10）。 この9章には出てきません。

練習機の中の「社内 LAN」

この教材の檻は、コンテナの中で動く仮想マシン（練習機 linuc）です。 練習機の中に network namespace（名前空間）でルータ・撤去予定の旧ルータ・サーバを作り、スイッチでつないであります。 経路も DNS も相手のサーバも練習機の中にあるので、あなたの家のルータ、会社のプロキシ、オフラインかどうかで画面が変わりません。

練習機を受け取った時点で、次の3つが「前任者の置き土産」として壊れています。章の中で原因を突き止め、演習で直します。

  • デフォルトルートが旧ルータを向いている（/etc/network/interfaces の gateway 192.168.10.254）→ 第4章・演習04
  • 名前解決の問い合わせ先が無い（/etc/resolv.conf は 127.0.0.53。その先の DNS サーバが1つも設定されていない）→ 第8章・演習06
  • /etc/hosts に www.lab.example の古いアドレスが1行残っている → 第9章・演習07

練習機はインターネットに出ません（わざとです）。apt install もできません。この主題で使う道具は全部入っています。 外へ出られる経路を残すと、読者ごとに ping の結果や名前の引け方が変わってしまうためです（実測した理由は実践編に書いてあります）。

1.07.4 クライアント側の DNS 設定
/etc/resolv.confnameserver（問い合わせ先。1行に1つ・3つまで）と search（1行に空白で並べる。2行書くと後の行だけ効く）。Ubuntu では 127.0.0.53 へのリンク8
getentNSS を通して引く。ping と同じ引き方は getent ahosts（IPv4 だけなら ahostsv4）。getent hosts は IPv6 を先に聞くので、ping と答えが違うことがある9

章

  1. アドレスは、分けるたびに減る — /24 を2つに分けると 254 台ではなく 252 台。ネットワークアドレスとブロードキャストを ipcalc で数える（14分）
  2. ifconfig に見えないアドレスがある — ip addr add で足した2つ目が ifconfig には出ない。ifconfig で付けると全部入れ替わる（16分）
  3. ifup は、自分が付けたものしか知らない — 手で付けたアドレスがあると ifup が失敗し、ifdown は not configured と言う。nmcli と netplan の持ち物（21分）
  4. 返事をしたのは、相手ではなかった — ping の From は旧ルータ。IPv6 では届いている。経路表の1行を直し、ファイルにも残す（18分）
  5. traceroute は、断られた返事で道を知る — UDP の 33434 番へ送り、ICMP の「時間切れ」と「その番号は無い」で道順を知る。* は止まった印ではない（16分）
  6. IPv6 のアドレスは、頼まなくても付いている — MAC から作られた fd00:10:: のアドレス。%lab0 を付けないと別の NIC から出ていく（14分）
  7. LISTEN していても、外からは入れない — 127.0.0.1:8080 は自分の 192.168.10.2 宛てでも断る。TCP は RST で、UDP は ICMP で断られる（19分）
  8. resolv.conf に書いた1行は、消される — nameserver 127.0.0.53 の正体。systemd-resolved が書き直すファイルと、残す2つの方法（19分）
  9. dig と ping は、別の表を引いている — dig は .10、ping は .99。/etc/hosts と nsswitch.conf の順番、そしてホスト名の3つの置き場所（18分）

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの4つに集まります。

場面ここで効く理由見落としやすい点関連する章
「サーバにつながらない」と言われた ping の From・traceroute の !N・* を読めば、どこで止まったかが分かる 返事をしたのが相手とは限らない。IPv4 と IPv6 は経路表が別で、片方だけ壊れていることがある4・5・6
新しく立てたサービスに外からつながらない ss の Local Address で、どのアドレスで待っているかが分かる LISTEN は「誰からでも」ではない。127.0.0.1 なら、自分の LAN 側アドレス宛てでも断られる7
設定を直したのに、再起動したら戻った ip で直したものはその場限り。残すのは持ち主（ifupdown / NetworkManager / netplan）の設定ファイル 持ち主が違う NIC は、その持ち主の道具でしか直せない（nmcli は unmanaged の NIC に効かない）3・4
名前で接続すると別のサーバに行く getent ahosts が ping と同じ引き方をするので、/etc/hosts と DNS のどちらが答えたか分かる dig で正しくても ping が正しいとは限らない。getent hosts は IPv6 を先に聞くので、ping とは違う答えを出すことがある。Ubuntu の 127.0.0.53 経由だと host にも /etc/hosts が混ざる8・9

この主題の道具だけで足りない場面も1つあります。 コンテナ（Docker など）の中から外へつながらない場合です。コンテナは自分の名前空間と経路表を持ち、 その外側でホストの NAT やファイアウォールが効いています。この教材で名前空間を「別の機械」として使っているのと同じ仕組みで、 コンテナの中の ip route だけを見ても原因の半分しか見えません。
