1. アドレスは、分けるたびに減る

254 台が使えるネットワークを、マスクを1ビット長くして2つに分ける。半分ずつなら 127 台ずつのはずだが、ipcalc は 126 台ずつ・合計 252 台と答える。2台ぶんは、分けたこと自体で消えた。アドレスの数え方は、マスクという「線」の引き方で決まっている。

この章のゴールと前提所要 14分
前提: 練習機に ssh linuc で入れる（実践編の「はじめる」）所要 14分影響度 A出題範囲 1.07.1（重要度4）最終検証 2026-10-13

この章のゴール

  • アドレスとネットワークマスク（/24 と 255.255.255.0）から、ネットワークアドレス・ブロードキャストアドレス・使える台数を出せる
  • サブネットに分けると使える台数が減る理由を、ビットの図で説明できる
  • プライベートアドレスの3つの範囲を、クラス（A/B/C）と組で言え、パブリックアドレスとの違いを説明できる
ここで覚えなくていいこと: クラス D・E の中身と、クラスでアドレスを配っていた時代の経緯（A/B/C の表はこの章に置く）、NAT がアドレスを付け替える仕組みの細部、IPv4 ヘッダのフィールドの並び。IPv6 は第6章で扱う。

練習機には、ネットワークが3つある

この節で分かること: アドレスの後ろの /24 が何を言っているか。

練習機に入り（外で ssh linuc）、IPv4 のアドレスを全部出す。

$ ip -4 addr show
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
2: enp0s16: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    inet 10.0.2.15/24 metric 100 brd 10.0.2.255 scope global dynamic enp0s16
       valid_lft 86375sec preferred_lft 86375sec
5: lab0@if3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP group default qlen 1000 link-netns sw
    inet 192.168.10.2/24 brd 192.168.10.255 scope global lab0
       valid_lft forever preferred_lft forever

inet の行がアドレスで、/ の後ろの数がネットワークマスクの長さ（CIDR 表記）である。 10.0.2.15/24 は「前から24ビットがネットワークの番号、残り8ビットがその中の機械の番号」という意味になる。 brd の後ろはブロードキャストアドレス（後で出す）。enp0s16 の dynamic と valid_lft 86377sec は DHCP で借りたアドレスで、残り時間が減っていく（あなたの画面では秒数が違う）。

NICアドレス何のネットワークか
lo127.0.0.1/8ループバック。この機械の中だけで折り返す
enp0s1610.0.2.15/24管理用。外のコンテナからの ssh が通る（QEMU が作る小さなネットワーク）
lab0192.168.10.2/24社内 LAN。ルータ（192.168.10.1）と旧ルータ（192.168.10.254）がいる

3つとも、後で見るプライベートアドレスの範囲に入っている。この章では、この3つを材料に「マスクが何を決めているか」を確かめる。 enp0s17 と enp0s18 はまだアドレスを持っていないので出てこない（第2章と第3章で付ける）。

マスクは、どこまでが同じネットワークかの線

この節で分かること: マスクの読み方と、宛先が同じネットワークかどうかの判定。

ipcalc にアドレスとマスクを渡すと、2進数で並べてくれる。

$ ipcalc 192.168.10.2/24
Address:   192.168.10.2         11000000.10101000.00001010. 00000010
Netmask:   255.255.255.0 = 24   11111111.11111111.11111111. 00000000
Wildcard:  0.0.0.255            00000000.00000000.00000000. 11111111
=>
Network:   192.168.10.0/24      11000000.10101000.00001010. 00000000
HostMin:   192.168.10.1         11000000.10101000.00001010. 00000001
HostMax:   192.168.10.254       11000000.10101000.00001010. 11111110
Broadcast: 192.168.10.255       11000000.10101000.00001010. 11111111
Hosts/Net: 254                   Class C, Private Internet

2進数の中の空白が線である。空白の左（24ビット）がネットワーク部、右（8ビット）がホスト部。 ネットワークマスクは、ネットワーク部を 1、ホスト部を 0 にした数で、255.255.255.0 と /24 は同じものを2通りに書いただけである。

$ ipcalc -b 192.168.10.2 255.255.255.0
Address:   192.168.10.2
Netmask:   255.255.255.0 = 24
...
Broadcast: 192.168.10.255
Hosts/Net: 254                   Class C, Private Internet

ホスト部の8ビットで作れる番号は 256 個。そのうち2つは機械に割り当てられない。

ホスト部アドレス意味
全部 0192.168.10.0ネットワークそのものの名前（Network）
全部 1192.168.10.255そのネットワークの全員宛て（Broadcast）
それ以外192.168.10.1〜254機械に付けられる（HostMin〜HostMax）。256 − 2 = 254 個

マスクが実際に効くのは、送るときである。宛先が自分と同じネットワークなら直接送り、違えばルータ（ゲートウェイ）に渡す。 カーネルにどちらにするかを聞ける。

$ ip route get 192.168.10.200
192.168.10.200 dev lab0 src 192.168.10.2 uid 1000
    cache
$ ip route get 192.168.11.1
192.168.11.1 via 192.168.10.254 dev lab0 src 192.168.10.2 uid 1000
    cache

192.168.10.200 は /24 の線の内側なので via が無い（直接送る）。192.168.11.1 は3つ目の数が違うので線の外で、 via 192.168.10.254（ルータ）に渡される。この 192.168.10.254 が「撤去予定の旧ルータ」であることは第4章で問題になる。

たとえ: 住所の「何丁目までが同じなら、歩いて届けに行く」という線引きに近い。 線の内側なら自分で届け、外なら郵便局（ルータ）に預ける。
ただし崩れる点: 住所の区切りは丁目・番地と決まっているが、マスクは1ビット単位でどこにでも引ける。 /24 の次は /25、/26 と、線を右へずらすたびに「同じネットワーク」の範囲が半分になる。

分けると、使える台数が減る

この節で分かること: サブネットに分けたとき、何台ぶん減るかの数え方。

192.168.10.0/24 を2つのネットワーク（サブネット）に分けたい。マスクを1ビット長くして /25 にすればよい。

ふつうこう考える

254 台使えるネットワークを半分に分けるのだから、半分ずつ 127 台。2つ合わせれば 254 台のままだろう。 分けても台数は変わらないはずだ。

$ ipcalc 192.168.10.0/24 /25
...
Subnets after transition from /24 to /25

Netmask:   255.255.255.128 = 25 11111111.11111111.11111111.1 0000000
Wildcard:  0.0.0.127            00000000.00000000.00000000.0 1111111

 1.
Network:   192.168.10.0/25      11000000.10101000.00001010.0 0000000
HostMin:   192.168.10.1         11000000.10101000.00001010.0 0000001
HostMax:   192.168.10.126       11000000.10101000.00001010.0 1111110
Broadcast: 192.168.10.127       11000000.10101000.00001010.0 1111111
Hosts/Net: 126                   Class C, Private Internet

 2.
Network:   192.168.10.128/25    11000000.10101000.00001010.1 0000000
HostMin:   192.168.10.129       11000000.10101000.00001010.1 0000001
HostMax:   192.168.10.254       11000000.10101000.00001010.1 1111110
Broadcast: 192.168.10.255       11000000.10101000.00001010.1 1111111
Hosts/Net: 126                   Class C, Private Internet


Subnets:   2
Hosts:     252
だめな理由: 126 台ずつ、合計 252 台である。2台減った。 減ったのは 192.168.10.127（1つ目のブロードキャスト）と 192.168.10.128（2つ目のネットワークアドレス）。 分ける前はどちらも普通の機械に付けられる番号だったが、分けた瞬間に、それぞれのサブネットの「両端の予約席」になった。 どのネットワークにも、ホスト部が全部 0 と全部 1 の2つが要るので、N 個に分けると予約席も N 組になる。

4つに分けると、さらに減る。

$ ipcalc -b 192.168.10.0/24 /26 | tail -3

Subnets:   4
Hosts:     248
分け方マスク1つあたり合計減った数
/24 × 1255.255.255.0254254—
/25 × 2255.255.255.1281262522
/26 × 4255.255.255.192622486

1つあたりの台数は「2の（ホスト部のビット数）乗 − 2」。/25 はホスト部が7ビットなので 128 − 2 = 126、/26 は6ビットなので 64 − 2 = 62 になる。 試験では、ある機械のアドレスとマスクから「そのネットワークのブロードキャストは何か」を問われる。手で出す練習をして、ipcalc で答え合わせする。

$ ipcalc -b 192.168.10.130/25
Address:   192.168.10.130
Netmask:   255.255.255.128 = 25
Wildcard:  0.0.0.127
=>
Network:   192.168.10.128/25
HostMin:   192.168.10.129
HostMax:   192.168.10.254
Broadcast: 192.168.10.255
Hosts/Net: 126                   Class C, Private Internet

手で出すなら、最後の数 130 を2進数にする（10000010）。/25 なら先頭の1ビットだけがネットワーク部に入るので、 残り7ビットを全部 0 にすると 128（ネットワークアドレス）、全部 1 にすると 255（ブロードキャスト）。

たとえ: 1棟のアパートを2棟に建て替えるようなものだ。 どの棟にも管理人室と掲示板が1つずつ要るので、棟を増やすたびに住める部屋が2つずつ減る。
ただし崩れる点: アパートの管理人室は建物の好きな場所に置けるが、 ネットワークアドレスとブロードキャストは必ず番号の両端に来る。どこを予約するかは選べない。
確認

IP アドレス 172.16.20.70/26 の機械がある。この機械が属するネットワークのネットワークアドレスとブロードキャストアドレスの組み合わせとして正しいものはどれか。

A. 172.16.20.0 と 172.16.20.255　B. 172.16.20.64 と 172.16.20.127　C. 172.16.20.64 と 172.16.20.255　D. 172.16.20.70 と 172.16.20.127

答え

B。/26 はホスト部が6ビット（64 個ずつ）なので、最後の数は 0〜63、64〜127、128〜191、192〜255 の4つに分かれる。 70 は 64〜127 の組に入るので、ネットワークアドレスは 172.16.20.64、ブロードキャストは 172.16.20.127。 使える台数は 64 − 2 = 62。ipcalc -b 172.16.20.70/26 で確かめられる。

プライベートとパブリック

この節で分かること: 自由に使ってよいアドレスの3つの範囲と、その外側。

ipcalc の最後の行の Private Internet が、もう1つの区別である。練習機の3つのネットワークを順に見る。

$ ipcalc -b 10.0.2.15/24
...
Hosts/Net: 254                   Class A, Private Internet
$ ipcalc -b 172.16.20.10/24
...
Hosts/Net: 254                   Class B, Private Internet
$ ipcalc -b 172.32.0.1/16
...
Hosts/Net: 65534                 Class B
$ ipcalc -b 203.0.113.10/24
...
Hosts/Net: 254                   Class C

10.0.2.15 と 172.16.20.10 は Private Internet、172.32.0.1 と 203.0.113.10 には付かない。 プライベートアドレスは、組織の中で自由に使ってよいと RFC 1918 が決めた3つの範囲である。

範囲CIDRこの練習機での例
10.0.0.0 〜 10.255.255.25510.0.0.0/810.0.2.15（管理用）、10.0.3.0/24・10.0.4.0/24（練習用）
172.16.0.0 〜 172.31.255.255172.16.0.0/12172.16.20.10（サーバ）
192.168.0.0 〜 192.168.255.255192.168.0.0/16192.168.10.2（社内 LAN）

172 で始まっても、プライベートなのは 172.16〜172.31 だけである（/12 は2つ目の数の上位4ビットまでを固定する）。 172.32.0.1 はその外なので、ipcalc は Private と書かない。これは試験でよく狙われる。

試験では、この3つの範囲がクラスと組で問われる（「クラス C のプライベートアドレスの範囲はどれか」）。 クラスは、アドレスの先頭の数だけでネットワークの大きさ（マスク）を決めていた昔の区分で、上の記録で ipcalc が出した Class A などがそれである。

クラス先頭の数（第1オクテット）既定のマスクプライベートの範囲
A0 〜 127255.0.0.0（/8）10.0.0.0 〜 10.255.255.255
B128 〜 191255.255.0.0（/16）172.16.0.0 〜 172.31.255.255
C192 〜 223255.255.255.0（/24）192.168.0.0 〜 192.168.255.255

クラスは先頭の数だけで決まり、実際に付けたマスクとは関係ない。10.0.2.15 は /24 で使っていてもクラス A、172.32.0.1 はクラス B だがプライベートではない。 今はクラスに縛られずにマスクの長さを決める（これが CIDR）。それでも「/8・/16・/24 がクラス A・B・C の既定のマスク」という呼び方は残っている。 0 と 127 で始まるものは特別な用途（127 は後で出すループバック）で、224 〜 239 はクラス D（マルチキャスト）、240 〜 255 はクラス E（実験用）として、ふつうの機械には付けない。

プライベートアドレスはどの家・どの会社でも同じものを使うので、インターネットの上では通用しない。 インターネットで使うのは世界で1つしかないパブリックアドレス（グローバルアドレスとも言う）で、プライベートアドレスの機械が外へ出るときは、ルータが送り元をパブリックアドレスに付け替える（NAT）。 「プライベート以外は全部パブリック」ではない。ループバック（127.0.0.0/8、この後で出す）やリンクローカル（169.254.0.0/16）、マルチキャスト（224.0.0.0/4）のような特別な範囲は、どちらでもない。 203.0.113.10 もパブリックアドレスの形をしているが、実は説明書のために予約された範囲（203.0.113.0/24）で、どこにもつながっていない。 この教材はインターネットに出ないので、パブリックアドレスの代わりの例にはこれを使う。

最後に、どれとも違うのが ループバックである。

$ ipcalc -b 127.0.0.1/8
...
Network:   127.0.0.0/8
HostMin:   127.0.0.1
HostMax:   127.255.255.254
Broadcast: 127.255.255.255
Hosts/Net: 16777214              Class A, Loopback

127.0.0.0/8 は1600万個以上の番号を持つが、どれもその機械自身を指し、NIC から外へ出ない。第7章で、ここで待ち受けるサービスに外から入れないことを確かめる。

たとえ: 会社の内線番号に近い。社内では「101番」で通じるが、 外からかけるには代表番号（パブリックアドレス）を通すしかない。どの会社にも101番があるので、内線番号だけでは相手を特定できない。
ただし崩れる点: 内線番号の範囲は会社が自由に決めるが、プライベートアドレスの範囲は RFC で決まっていて、 172.32.0.1 のように「それらしい」番号でも、範囲の外ならプライベートではない（172.32.0.1 はパブリックアドレス）。
確認

次の IPv4 アドレスのうち、プライベートアドレスでないものを1つ選べ。

A. 10.200.1.1　B. 172.20.0.5　C. 172.40.0.5　D. 192.168.255.1

答え

C。172 で始まるプライベートアドレスは 172.16.0.0/12、つまり 172.16〜172.31 だけ。 172.40 はその外である。B の 172.20 は範囲内。ipcalc -b 172.40.0.5/16 と打つと、172.32.0.1 と同じく Private Internet が付かない。

手を動かす: 実践編の演習01で、練習用の NIC に 10.0.3.50/24 を付け、同じネットワークの 10.0.3.2 と直接話す。 付けたあと ip route get 10.0.3.2 を打つと、via の無い（直接届ける）行が選ばれていることが分かる。

この章で分かったこと

持ち帰ってほしいこと

  • /24 と 255.255.255.0 は同じもの。マスクは「どこまでがネットワーク部か」の線（CIDR は線の位置をビット数で書く）
  • ホスト部が全部 0 がネットワークアドレス、全部 1 がブロードキャストアドレス。この2つは機械に付けられない
  • N 個に分けると、使える台数は (N − 1) × 2 減る（/24 → /25 × 2 で 254 → 252、/26 × 4 で 248）
  • 宛先が線の内側なら直接、外ならゲートウェイへ。ip route get でカーネルの判断を聞ける
  • プライベートは 10/8（クラス A）・172.16/12（クラス B）・192.168/16（クラス C）の3つ。172.32 はパブリック。127/8 はループバック
  • クラスは先頭の数で決まる昔の区分（A 0〜127 /8・B 128〜191 /16・C 192〜223 /24）。付けたマスクとは関係ない
