2. ifconfig に見えないアドレスがある

NIC にアドレスを2つ付ける。ip addr には2つ並ぶのに、ifconfig には1つしか出ない。どちらかが壊れているのではない。ifconfig は「1つの名前に1つのアドレス」という古い表を読んでいて、その表には2つ目の欄が無い。

前提: 第1章まで読了所要 14分影響度 B出題範囲 1.07.2（重要度4）出題範囲 1.07.3（重要度4）最終検証 2026-10-13

この章のゴール

  • ip link・ip addr・ifconfig の出力から、NIC が上がっているか、どのアドレスが付いているかを読める
  • NIC を手で上げ下げし、アドレスを付け外しできる（ip link set / ip addr add・del・flush / ifconfig）
  • ifconfig と ip が違う答えを返す理由を、見ている表の違いとして説明できる
ここで覚えなくていいこと: ip のトンネルやブリッジを作るサブコマンド、ip neigh の状態の語（REACHABLE / STALE など）の細かい意味、ifconfig で MAC アドレスを変える操作。ここで付けた設定は再起動で消える。残す方法（ifupdown と NetworkManager）は第3章で扱う。

NIC の一覧は、道具によって数が違う

この節で分かること: ip link と ifconfig が出す一覧の違い。

練習機の NIC を全部出す。ip link はリンク（ケーブルの口）の状態だけを出す。

$ ip link show
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN mode DEFAULT group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
2: enp0s16: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT group default qlen 1000
    link/ether 52:54:00:12:34:56 brd ff:ff:ff:ff:ff:ff
3: enp0s17: <BROADCAST,MULTICAST> mtu 1500 qdisc noop state DOWN mode DEFAULT group default qlen 1000
    link/ether 52:54:00:12:34:57 brd ff:ff:ff:ff:ff:ff
4: enp0s18: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT group default qlen 1000
    link/ether 52:54:00:12:34:58 brd ff:ff:ff:ff:ff:ff
5: lab0@if3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP mode DEFAULT group default qlen 1000
    link/ether 52:54:00:0a:00:02 brd ff:ff:ff:ff:ff:ff link-netns sw

山かっこの中の UP は「上げてある（使う設定になっている）」、LOWER_UP は「ケーブルの先がつながっている」。 enp0s17 にはどちらも無く、state DOWN である。誰もまだ上げていない。 link/ether の後ろが MAC アドレス。lab0@if3 … link-netns sw は、lab0 がケーブル（veth）の片端で、 もう片端がスイッチ（名前空間 sw）の3番の口にささっていることを示している。

同じことを ifconfig で見る。行の先頭が NIC 名なので、その行だけ抜き出す。

$ ifconfig | grep '^[a-z]'
enp0s16: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
enp0s18: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
lab0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
lo: flags=73<UP,LOOPBACK,RUNNING>  mtu 65536
$ ifconfig -a | grep '^[a-z]'
enp0s16: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
enp0s17: flags=4098<BROADCAST,MULTICAST>  mtu 1500
enp0s18: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
lab0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
lo: flags=73<UP,LOOPBACK,RUNNING>  mtu 65536

ifconfig は上がっている NIC だけを出す。上がっていない enp0s17 を見るには -a（all）が要る。 「ifconfig に出てこない＝NIC が無い」ではない。名前を指定すれば、上がっていなくても出る。

$ ip addr show enp0s17
3: enp0s17: <BROADCAST,MULTICAST> mtu 1500 qdisc noop state DOWN group default qlen 1000
    link/ether 52:54:00:12:34:57 brd ff:ff:ff:ff:ff:ff
$ ifconfig enp0s17
enp0s17: flags=4098<BROADCAST,MULTICAST>  mtu 1500
        ether 52:54:00:12:34:57  txqueuelen 1000  (Ethernet)
        RX packets 0  bytes 0 (0.0 B)
        RX errors 0  dropped 0  overruns 0  frame 0
        TX packets 0  bytes 0 (0.0 B)
        TX errors 0  dropped 0 overruns 0  carrier 0  collisions 0

アドレスの行（inet）が1つも無い。ifconfig は送受信したパケットの数（RX / TX）も出す。まだ0である。

上げて、付ける

この節で分かること: 「リンクが上がっている」と「アドレスが付いている」が別々の状態であること。
$ sudo ip link set enp0s17 up
$ ip addr show enp0s17
3: enp0s17: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    link/ether 52:54:00:12:34:57 brd ff:ff:ff:ff:ff:ff
    inet6 fe80::5054:ff:fe12:3457/64 scope link
       valid_lft forever preferred_lft forever

上げただけで state UP になり、IPv6 のアドレス（fe80::…）が勝手に付いた。これは第6章の主題なので、ここでは「IPv4 のアドレスはまだ無い」ことだけ見ておく。 IPv4 のアドレスを足す。

$ sudo ip addr add 10.0.3.50/24 dev enp0s17
$ ip -4 addr show enp0s17
3: enp0s17: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    inet 10.0.3.50/24 scope global enp0s17
       valid_lft forever preferred_lft forever
$ ping -c 2 10.0.3.2
PING 10.0.3.2 (10.0.3.2) 56(84) bytes of data.
64 bytes from 10.0.3.2: icmp_seq=1 ttl=255 time=5.37 ms
64 bytes from 10.0.3.2: icmp_seq=2 ttl=255 time=0.898 ms

--- 10.0.3.2 ping statistics ---
2 packets transmitted, 2 received, 0% packet loss, time 1003ms
rtt min/avg/max/mdev = 0.898/3.133/5.369/2.235 ms

10.0.3.2 は、この練習用ネットワークで待っている相手（QEMU が作る仮想のゲートウェイ）である。 同じ /24 の中にいるので、付けた直後から直接話せる（時間の ms はあなたの画面では違う）。 直接話す相手の MAC アドレスは ARP で調べ、表に残っている。

$ ip neigh show dev enp0s17
10.0.3.2 lladdr 52:55:0a:00:03:02 REACHABLE
たとえ: 新しい電話機の設置に近い。電源を入れて回線につなぐ（ip link set up）のと、 番号を割り当てる（ip addr add）のは別の作業で、どちらが欠けても話せない。
ただし崩れる点: 電話機は番号が無ければ何も名乗らないが、IPv6 の NIC は上げた瞬間に自分で番号（fe80::）を作って名乗る。 「上げただけ」の状態は、IPv4 と IPv6 で同じではない。

ifconfig に見えないアドレス

この節で分かること: ifconfig と ip addr が別の表を読んでいること。

同じ NIC に、同じネットワークのアドレスをもう1つ足す（1台の機械に2つの名前を持たせたいときに使う）。

ふつうこう考える

ifconfig と ip addr は、同じ NIC の同じ設定を、別の見た目で出しているだけだ。 片方に出るアドレスは、もう片方にも出るはずだ。

$ sudo ip addr add 10.0.3.51/24 dev enp0s17
$ ip -4 addr show enp0s17
3: enp0s17: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    inet 10.0.3.50/24 scope global enp0s17
       valid_lft forever preferred_lft forever
    inet 10.0.3.51/24 scope global secondary enp0s17
       valid_lft forever preferred_lft forever
$ ifconfig enp0s17
enp0s17: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 10.0.3.50  netmask 255.255.255.0  broadcast 0.0.0.0
        inet6 fe80::5054:ff:fe12:3457  prefixlen 64  scopeid 0x20<link>
        ether 52:54:00:12:34:57  txqueuelen 1000  (Ethernet)
        RX packets 3  bytes 260 (260.0 B)
        RX errors 0  dropped 0  overruns 0  frame 0
        TX packets 11  bytes 894 (894.0 B)
        TX errors 0  dropped 0 overruns 0  carrier 0  collisions 0
だめな理由: ip には2つ、ifconfig には 10.0.3.50 の1つしか出ない。 ifconfig（net-tools）は、カーネルに「この名前の NIC のアドレスは？」と聞く古い窓口（ioctl）を使う。 その窓口は1つの名前に1つのアドレスしか返さない。ip（iproute2）は、NIC に付いたアドレスを全部並べて返す新しい窓口（netlink）を使う。 2つ目のアドレスには secondary の印が付いていて、ifconfig の表にはその欄が無い。 もう1つ、broadcast 0.0.0.0 にも注意する。ip addr add は brd を指定しないとブロードキャストアドレスを付けない。

名前（ラベル）を付けて足すと、ifconfig にも見えるようになる。

$ sudo ip addr add 10.0.3.52/24 dev enp0s17 label enp0s17:1
$ ifconfig | grep '^[a-z]'
enp0s16: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
enp0s17: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
enp0s17:1: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
enp0s18: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
lab0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
lo: flags=73<UP,LOOPBACK,RUNNING>  mtu 65536
$ ifconfig enp0s17:1
enp0s17:1: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 10.0.3.52  netmask 255.255.255.0  broadcast 0.0.0.0
        ether 52:54:00:12:34:57  txqueuelen 1000  (Ethernet)

enp0s17:1 という「別の NIC のような名前」（エイリアス）で出てきた。MAC アドレスは enp0s17 と同じで、実体は同じ NIC である。 ifconfig の時代は、2つ目のアドレスをこの形（ifconfig enp0s17:1 10.0.3.52）で付けていた。 ifconfig から見えるのはラベルの付いたものだけで、10.0.3.51 はまだ見えないままである。

たとえ: 社員名簿の「内線番号」の欄に近い。欄が1つしか無い名簿（ifconfig）には、2つ目の内線を書く場所が無い。 別の名前（enp0s17:1）で1行増やせば、名簿にも載る。
ただし崩れる点: 名簿なら書き漏れに気づけるが、ifconfig は「書いていない」ことを表示しない。 見えないアドレスは、無いのと区別がつかない。

ifconfig で付けると、置き換わる

この節で分かること: ip addr add と ifconfig の、付け方の違い。

いま enp0s17 には 10.0.3.50・10.0.3.51・10.0.3.52 の3つが付いている。ここで ifconfig でアドレスを付ける。

$ sudo ifconfig enp0s17 10.0.3.60 netmask 255.255.255.0
$ ip -4 addr show enp0s17
3: enp0s17: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    inet 10.0.3.60/24 brd 10.0.3.255 scope global enp0s17
       valid_lft forever preferred_lft forever

3つとも消えて、10.0.3.60 だけになった。ifconfig 名前 アドレス は「この名前のアドレスをこれにする」という命令で、足すのではなく置き換える。 1つ目（primary）のアドレスが消えると、同じネットワークの2つ目以降（secondary）も一緒に消える （この練習機の既定。sysctl net.ipv4.conf.enp0s17.promote_secondaries が 1 の機械では、2つ目が1つ目に繰り上がって残る）。 ifconfig で付けると、ブロードキャスト（brd 10.0.3.255）はマスクから自動で計算される。元に戻しておく。

$ sudo ifconfig enp0s17 10.0.3.50 netmask 255.255.255.0
$ ip -4 addr show enp0s17
3: enp0s17: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    inet 10.0.3.50/24 brd 10.0.3.255 scope global enp0s17
       valid_lft forever preferred_lft forever
やりたいことip（iproute2）ifconfig（net-tools）
一覧（上がっていないものも）ip link show / ip addr showifconfig -a
上げる / 下げるip link set enp0s17 up / downifconfig enp0s17 up / down
アドレスを付けるip addr add 10.0.3.50/24 dev enp0s17（足す）ifconfig enp0s17 10.0.3.50 netmask 255.255.255.0（置き換える）
2つ目を付けるもう一度 ip addr addifconfig enp0s17:1 10.0.3.52 netmask …（エイリアス）
1つ外す / 全部外すip addr del 10.0.3.51/24 dev enp0s17 / ip addr flush dev enp0s17—（この章では ip を使う）
見えるアドレス全部（secondary も）名前ごとに1つ

Ubuntu 24.04 や RHEL 9 の最小構成には ifconfig が入っていないこともある（net-tools は古い道具として別パッケージ）。試験では両方の形が問われる。

確認

eth0 に IPv4 アドレス 192.168.1.10/24 を追加するコマンドとして正しいものはどれか。

A. ip link add 192.168.1.10/24 dev eth0　B. ip addr add 192.168.1.10/24 dev eth0　C. ip route add 192.168.1.10/24 dev eth0　D. ifconfig eth0 add 192.168.1.10/24

答え

B。ip addr（address）がアドレス、ip link がリンク、ip route が経路を扱う。 ifconfig eth0 192.168.1.10 netmask 255.255.255.0 でも付くが、それは「追加」ではなく、元のアドレスとの置き換えになる。

下げても、アドレスは消えない

この節で分かること: リンクを下げたときに消えるものと残るもの。
$ sudo ip link set enp0s17 down
$ ip -4 addr show enp0s17
3: enp0s17: <BROADCAST,MULTICAST> mtu 1500 qdisc fq_codel state DOWN group default qlen 1000
    inet 10.0.3.50/24 brd 10.0.3.255 scope global enp0s17
       valid_lft forever preferred_lft forever
$ ip route
default via 192.168.10.254 dev lab0 onlink
10.0.2.0/24 dev enp0s16 proto kernel scope link src 10.0.2.15 metric 100
192.168.10.0/24 dev lab0 proto kernel scope link src 192.168.10.2

下げてもアドレスは残る（state DOWN のまま inet の行がある）。消えたのは経路表の 10.0.3.0/24 の行である。 アドレスとマスクを付けると「そのネットワークへは、この NIC から直接」という行（直結の経路、proto kernel scope link）がカーネルに自動で足され、 リンクが下がっている間は使えないので外される。上げ直すと戻る。

$ sudo ip link set enp0s17 up
$ ip route
default via 192.168.10.254 dev lab0 onlink
10.0.2.0/24 dev enp0s16 proto kernel scope link src 10.0.2.15 metric 100
10.0.3.0/24 dev enp0s17 proto kernel scope link src 10.0.3.50
192.168.10.0/24 dev lab0 proto kernel scope link src 192.168.10.2
$ ping -c 1 10.0.3.2
PING 10.0.3.2 (10.0.3.2) 56(84) bytes of data.
64 bytes from 10.0.3.2: icmp_seq=1 ttl=255 time=3.32 ms

--- 10.0.3.2 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 3.322/3.322/3.322/0.000 ms

この表の1行目（default via 192.168.10.254）は、第4章で直すことになる。

たとえ: 店のシャッターに近い。シャッターを下ろしても（down）看板（アドレス）は掛かったままだが、 地図アプリの「営業中の店」の一覧（経路表）からは外れる。
ただし崩れる点: 店ならシャッターを上げれば客は自分で戻ってくるが、経路表の行はカーネルが付け直さないと戻らない。 付け直すのは「アドレスとマスクから」なので、アドレスを外して上げても行は戻らない。
確認

ip addr show eth0 には 192.168.1.10/24 と 192.168.1.11/24 の2つが表示されるが、ifconfig eth0 には 192.168.1.10 しか表示されない。正しい説明はどれか。

A. 192.168.1.11 は設定ファイルにしか無く、まだ有効になっていない　B. ifconfig はラベルの無い2つ目（secondary）のアドレスを表示しない　C. eth0 が down になっている　D. 192.168.1.11 は IPv6 のアドレスである

答え

B。ip addr show に出ているのでカーネルには付いている（A は誤り）。ifconfig は1つの名前に1つのアドレスしか表示しない。 ip addr add … label eth0:1 のようにラベルを付けると ifconfig にも eth0:1 として出る。

手を動かす: 実践編の演習01が、この章の操作そのもの（enp0s17 を上げて 10.0.3.50/24 を付け、10.0.3.2 と話す）である。 判定は enp0s17 の状態を読み、判定の中で 10.0.3.2 に ping を1回打って確かめる。ここで付けた設定は再起動で消えるので、第3章と演習02 で残し方を扱う。

この章で分かったこと

持ち帰ってほしいこと

  • ifconfig は上がっている NIC しか一覧に出さない。全部見るなら ifconfig -a か ip link show
  • リンクを上げる（ip link set … up）とアドレスを付ける（ip addr add）は別の操作。下げてもアドレスは残り、直結の経路だけ消える
  • ip addr add は足す。ifconfig 名前 アドレス は置き換える（2つ目以降も消える）
  • ifconfig はラベルの無い2つ目（secondary）のアドレスを表示しない。ip addr は全部出す
  • ip addr add で brd を省くとブロードキャストが付かない（ifconfig に broadcast 0.0.0.0）
