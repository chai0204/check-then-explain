6. IPv6 のアドレスは、頼まなくても付いている

lab0 の IPv6 について、設定ファイルには inet6 auto としか書いていない。アドレスはどこにも無い。それでも lab0 には fd00:10::5054:ff:fe0a:2 が付いている。後半の 5054:ff:fe0a:2 は、lab0 の MAC アドレス 52:54:00:0a:00:02 から作られた番号である。IPv6 の機械は、ルータの広告を聞いて自分でアドレスを名乗る。

前提: 第4章まで読了所要 14分影響度 A出題範囲 1.07.1（重要度4）出題範囲 1.07.3（重要度4）最終検証 2026-10-13

この章のゴール

  • IPv6 アドレスを送り方でユニキャスト・エニーキャスト・マルチキャストの3種類に分けられ（ブロードキャストは無い）、ユニキャストのうちループバック・リンクローカル・ユニークローカル・グローバルと、マルチキャストを先頭の数で見分けられる
  • アドレスが SLAAC と EUI-64 でどう作られたかを、MAC アドレスから説明できる
  • ping6・traceroute6・tracepath -6 で IPv6 の到達を確かめられる（リンクローカル宛ての %NIC を含めて）
ここで覚えなくていいこと: IPv4 と IPv6 を共存させる仕組み（トンネルや変換）の細部、IPv6 ヘッダの拡張ヘッダの種類、プライバシー拡張（一時アドレス）の設定値。違いと基本の機能は、この章の表に挙げたものを押さえれば足りる。

設定していないのに、付いている

この節で分かること: IPv6 のアドレスがどこから来たか。

ふつうこう考える

IPv4 と同じで、IPv6 のアドレスも設定ファイルに書くか、DHCP で配られない限り付かないはずだ。 lab0 の設定には IPv6 のアドレスを書いていないのだから、IPv6 では話せないだろう。

$ ifquery lab0
address: 192.168.10.2
gateway: 192.168.10.1
broadcast: 192.168.10.255
netmask: 255.255.255.0
privext: 0
accept_ra: 2
request_prefix: 0
ll-attempts: 60
ll-interval: 0.1
$ ip -6 addr show lab0
5: lab0@if3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP group default qlen 1000 link-netns sw
    inet6 fd00:10::5054:ff:fe0a:2/64 scope global dynamic mngtmpaddr
       valid_lft forever preferred_lft forever
    inet6 fe80::5054:ff:fe0a:2/64 scope link
       valid_lft forever preferred_lft forever
だめな理由: 設定に書いたのは IPv4 のアドレスと、IPv6 の「ルータの広告を受け取る（accept_ra）」「一時アドレスを作らない（privext 0）」だけなのに、IPv6 のアドレスが2つ付いている。 fe80:: で始まる方（リンクローカルアドレス）は、NIC を上げた瞬間にカーネルが自分で作る（第2章の enp0s17 でも見た）。 fd00:10:: で始まる方は、社内 LAN のルータ（router）が流しているルータ広告（RA）から前半の fd00:10::/64 を受け取り、 後半を自分で付けて名乗ったものである。これを SLAAC（ステートレスアドレス自動設定）と呼ぶ。DHCP サーバは要らない（dynamic がルータ広告から作った印）。

後半はどこから来たか。lab0 の MAC アドレスと並べる。

$ ip link show lab0
5: lab0@if3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP mode DEFAULT group default qlen 1000
    link/ether 52:54:00:0a:00:02 brd ff:ff:ff:ff:ff:ff link-netns sw
MAC アドレス       52:54:00  :  0a:00:02         （48ビット）
真ん中に ff:fe     52:54:00:ff:fe:0a:00:02       （64ビットに伸ばす）
先頭の 7 ビット目を反転   0x52 = 0101 0010 → 0101 0000 = 0x50
インタフェース ID  5054:00ff:fe0a:0002  →  省略して 5054:ff:fe0a:2

この作り方を EUI-64 と呼ぶ。アドレスを見れば MAC が分かってしまうので、パソコンの OS は乱数の後半（一時アドレス・stable-privacy）を使うことが多い。 この練習機は、画面を読者ごとに揃えるために EUI-64 にしてある。

IPv6 のアドレスは 128 ビットを 16 ビットずつ 8 つに区切って 16 進数で書く。省略の規則は2つある。

$ python3 -c 'import ipaddress; print(ipaddress.ip_address("fd00:10::5054:ff:fe0a:2").exploded)'
fd00:0010:0000:0000:5054:00ff:fe0a:0002
  • 各区切りの先頭の 0 は省ける（0010 → 10、00ff → ff）
  • 0 だけの区切りが続くところは、1か所だけ :: にまとめられる（:0000:0000: → ::）

（python3 は省略を戻す電卓として使っただけで、出題範囲ではない。）

ルータ広告が無いネットワークではどうなるか。enp0s17 の先にはルータ広告を出す機械がいない。

$ ip -6 addr show enp0s17
3: enp0s17: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    inet6 fe80::5054:ff:fe12:3457/64 scope link
       valid_lft forever preferred_lft forever
$ ip -6 route
fd00:10::/64 dev lab0 proto kernel metric 256 pref medium
fe80::/64 dev enp0s16 proto kernel metric 256 pref medium
fe80::/64 dev enp0s17 proto kernel metric 256 pref medium
fe80::/64 dev lab0 proto kernel metric 256 pref medium
fe80::/64 dev enp0s18 proto kernel metric 1024 pref medium
default via fe80::5054:ff:fe0a:1 dev lab0 proto ra metric 1024 expires 1743sec hoplimit 64 pref medium

enp0s17 にはリンクローカルしか無い。経路表を見ると、IPv6 のデフォルトルートもルータ広告から来ている（proto ra。行き先は router のリンクローカル fe80::5054:ff:fe0a:1。expires の秒数は見るたびに減る）。 第4章で IPv4 が壊れていた間も IPv6 で届いたのは、IPv6 の経路はルータ自身が教えてくれていたからである。

先頭種類送り方この練習機の例IPv4 で近いもの
::1ループバックユニキャスト::1（lo）127.0.0.1
fe80::/10リンクローカル（同じリンクの中だけ。必ず付く）ユニキャストfe80::5054:ff:fe0a:2169.254.0.0/16
fc00::/7（実際は fd）ユニークローカル（ULA。組織の中だけ）ユニキャストfd00:10::5054:ff:fe0a:2プライベートアドレス
2000::/3グローバルユニキャスト（インターネットで一意）ユニキャスト—（この練習機はインターネットに出ない）パブリックアドレス
ff00::/8マルチキャスト（グループ宛て）マルチキャストff02::1（リンク上の全員）ブロードキャスト（IPv6 には無い）

送り方で分けると、IPv6 のアドレスは3種類である。ユニキャスト（1台宛て）、エニーキャスト（同じアドレスを持つ複数の機械のうち、いちばん近い1台宛て）、 マルチキャスト（グループの全員宛て）。ブロードキャストは無い。ループバックもリンクローカルも、1台を指すのでユニキャストに入る。 エニーキャストには専用の範囲が無く、ユニキャストの範囲から割り当てるので、アドレスの形だけでは見分けられない（この練習機には無い）。

たとえ: 町内の掲示板に貼られた「この町は○○町です」を見て、自分の番地を誕生日から作って名乗るようなものだ。 町名（前半 64 ビット）はルータが掲示し、番地（後半 64 ビット）は自分で作る。役所（DHCP サーバ）に届け出る必要がない。
ただし崩れる点: 人の番地なら役所が重複を防ぐが、SLAAC では本人が近所に「この番地の人はいますか」と聞いて確かめる（DAD）。 そして EUI-64 の番地は MAC から作るので、引っ越しても後半が変わらず、どこにいても同じ機械だと分かってしまう。

リンクローカルには、NIC の名前を付けて呼ぶ

この節で分かること: %lab0 が要る理由。

router のリンクローカルアドレスに ping6 を打つ。

$ ping6 -c 1 fe80::5054:ff:fe0a:1
PING fe80::5054:ff:fe0a:1 (fe80::5054:ff:fe0a:1) 56 data bytes
From fe80::5054:ff:fe12:3456%enp0s16 icmp_seq=1 Destination unreachable: Address unreachable

--- fe80::5054:ff:fe0a:1 ping statistics ---
1 packets transmitted, 0 received, +1 errors, 100% packet loss, time 0ms
$ ping6 -c 1 fe80::5054:ff:fe0a:1%lab0
PING fe80::5054:ff:fe0a:1%lab0 (fe80::5054:ff:fe0a:1%lab0) 56 data bytes
64 bytes from fe80::5054:ff:fe0a:1%lab0: icmp_seq=1 ttl=64 time=0.953 ms

--- fe80::5054:ff:fe0a:1%lab0 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 0.953/0.953/0.953/0.000 ms

NIC の名前を付けないと、管理用の enp0s16 から送られて Address unreachable になった（From の %enp0s16）。 経路表には fe80::/64 の行が NIC の数だけあり、どれも同じ長さで一致する。宛先だけではどのリンクか区別できないので、カーネルは表の最初の行（enp0s16）を選んだ。 リンクローカルは「どのリンクの fe80 か」まで言わないと相手が決まらない。%lab0 の部分をゾーン（スコープ ID）と呼ぶ。 ping6 は ping への別名で、ping に IPv6 アドレスを渡しても同じように動く。

$ ping -c 1 fe80::5054:ff:fe0a:1%lab0
PING fe80::5054:ff:fe0a:1%lab0 (fe80::5054:ff:fe0a:1%lab0) 56 data bytes
64 bytes from fe80::5054:ff:fe0a:1%lab0: icmp_seq=1 ttl=64 time=0.351 ms

--- fe80::5054:ff:fe0a:1%lab0 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 0.351/0.351/0.351/0.000 ms
たとえ: どのフロアにも「101号室」がある建物で、「101号室へ」とだけ言われた配達員に近い。どのフロアの101号室か分からないので、最初に見たフロアへ行ってしまう。
ただし崩れる点: 配達員なら着いてから「違うフロアだった」と気づいて戻れるが、カーネルは別の NIC へ送って「届かない」と言うだけで、別のフロアを試さない。

ブロードキャストの代わりに、マルチキャスト

この節で分かること: IPv6 で「全員」に送る方法と、ARP の代わりのもの。
$ ping6 -c 2 -w 3 ff02::1%lab0
PING ff02::1%lab0 (ff02::1%lab0) 56 data bytes
64 bytes from fe80::5054:ff:fe0a:2%lab0: icmp_seq=1 ttl=64 time=1.06 ms
64 bytes from fe80::5054:ff:fe0a:1%lab0: icmp_seq=1 ttl=64 time=1.70 ms
64 bytes from fe80::5054:ff:fe0a:2%lab0: icmp_seq=2 ttl=64 time=0.425 ms

--- ff02::1%lab0 ping statistics ---
2 packets transmitted, 2 received, +1 duplicates, 0% packet loss, time 1003ms
rtt min/avg/max/mdev = 0.425/1.062/1.704/0.522 ms
$ ip -6 neigh show dev lab0
fe80::5054:ff:fe0a:1 lladdr 52:54:00:0a:00:01 router DELAY

ff02::1 は「このリンクの IPv6 の全ノード」というマルチキャストアドレスで、自分（…:2）と router（…:1）が答えた。 同じ LAN にいる旧ルータは IPv6 を話さないので答えない。IPv6 にはブロードキャストが無く、「全員」はマルチキャストのグループとして表す （返事の順番や回数は毎回変わる。+1 duplicates は1回の問いに2つ返事が来たという意味）。

隣の機械の MAC アドレスを調べる仕組みも、IPv4 の ARP ではなく、マルチキャストを使う NDP（近隣探索）になる。表は ip -6 neigh で見る（router の印は、ルータ広告を出している相手。DELAY などの状態の語は時間で変わる）。 /etc/hosts にも、マルチキャストのアドレスに名前が付いている。

$ grep ip6 /etc/hosts
::1 ip6-localhost ip6-loopback
fe00::0 ip6-localnet
ff00::0 ip6-mcastprefix
ff02::1 ip6-allnodes
ff02::2 ip6-allrouters
ff02::3 ip6-allhosts
$ ping6 -c 1 ip6-localhost
PING ip6-localhost (::1) 56 data bytes
64 bytes from ip6-localhost (::1): icmp_seq=1 ttl=64 time=15.8 ms

--- ip6-localhost ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 1ms
rtt min/avg/max/mdev = 15.804/15.804/15.804/0.000 ms
たとえ: 校内放送（ブロードキャスト）をやめて、部活ごとの連絡網（マルチキャスト）だけにした学校に近い。 「全校生徒」という連絡網（ff02::1）を作れば、校内放送と同じことができる。
ただし崩れる点: 部活は自分で入部するが、ff02::1 には IPv6 を話す機械が自動で入っている。 入っていない機械（ここでは旧ルータ）には、何を送っても届かない。

確認

IPv6 アドレス 2001:0db8:0000:0000:0000:ff00:0042:8329 の省略表記として正しいものはどれか。

A. 2001:db8::ff00:42:8329　B. 2001:db8::ff:42:8329　C. 2001:db8:0:0:0:ff00:42:8329::　D. 2001:db8:::ff00:42:8329

答え

A。区切りの先頭の 0 は省けるが、後ろの 0 は省けない（ff00 を ff にはできない。B は誤り）。 0 だけの区切りの連続は1か所だけ :: にできる（C は形が誤り、D はコロンが3つで誤り）。

確認

IPv6 の説明として誤っているものはどれか。

A. IPv6 アドレスは 128 ビットである　B. fe80::/10 はリンクローカルアドレスで、ルータを越えない　C. IPv6 では全ノード宛てにブロードキャストアドレスを使う　D. ルータ広告からアドレスを自動で作る仕組みがある

答え

C。IPv6 にブロードキャストは無い。全ノード宛ては ff02::1 などのマルチキャストで表す。D は SLAAC。 この練習機では ping6 ff02::1%lab0 に、同じリンクで IPv6 を話す自分と router が答えた。

手を動かす: この章の演習は無いが、実践編の演習04の前に ping -c 2 172.16.20.10 と ping6 -c 2 fd00:20::10 を並べて打つと、 同じサーバに IPv4 では届かず IPv6 では届く。IPv4 と IPv6 が別々の経路表を持つことを、壊れた状態で確かめられるのは演習04 を解く前だけである。

この章で分かったこと

持ち帰ってほしいこと

  • NIC を上げるとリンクローカル（fe80::/10）が必ず付く。ルータ広告があれば SLAAC でもう1つ（ここでは ULA の fd00:10::/64）が付く
  • EUI-64 は MAC の真ん中に ff:fe を挟み、先頭の 7 ビット目を反転して後半 64 ビットを作る
  • リンクローカル宛てには %NIC名 が要る。付けないと別の NIC から出て Address unreachable になる
  • 送り方はユニキャスト・エニーキャスト・マルチキャストの3種類。ループバックとリンクローカルもユニキャスト
  • IPv6 にブロードキャストは無い。全員宛ては ff02::1（マルチキャスト）、ARP の代わりは NDP
  • ping6 / traceroute6 / tracepath -6。Ubuntu 24.04 には tracepath6 が無い
