8. resolv.conf に書いた1行は、消される

/etc/resolv.conf に nameserver 172.16.20.10 を1行足すと、名前が引けるようになる。ところが systemd-resolved を再起動すると、その行は跡形もなく消えている。書き込んだ先は /etc ではなく、systemd-resolved が起動のたびに作り直す /run の中のファイルだった。

前提: 第4章を終えている（172.16.20.10 に届く）所要 19分影響度 B出題範囲 1.07.4（重要度2）出題範囲 1.07.3（重要度4）最終検証 2026-10-13

この章のゴール

  • /etc/resolv.conf の書き方（nameserver / search）と、Ubuntu での実体（127.0.0.53 の systemd-resolved）を説明できる
  • host と dig で決まった DNS サーバに問い合わせ、答えの種類（NOERROR / NXDOMAIN / SERVFAIL / REFUSED）を読める
  • 問い合わせ先の DNS サーバと検索ドメインを、再起動しても消えない形で設定できる
ここで覚えなくていいこと: DNS サーバ側の設定（ゾーンファイル・再帰の仕組み。LinuC レベル2の範囲）、DNSSEC や DNS over TLS、resolved.conf の細かい項目（DNS= と Domains= だけで足りる）。クライアントとして「どこに聞くか」を決めるところまでを扱う。

nameserver 127.0.0.53 は、DNS サーバではない

この節で分かること: Ubuntu の /etc/resolv.conf の正体。
$ ls -l /etc/resolv.conf
lrwxrwxrwx 1 root root 39 Sep  5 20:21 /etc/resolv.conf -> ../run/systemd/resolve/stub-resolv.conf
$ cat /etc/resolv.conf
# This is /run/systemd/resolve/stub-resolv.conf managed by man:systemd-resolved(8).
# Do not edit.
...
# Third party programs should typically not access this file directly, but only
# through the symlink at /etc/resolv.conf. To manage man:resolv.conf(5) in a
# different way, replace this symlink by a static file or a different symlink.
...
nameserver 127.0.0.53
options edns0 trust-ad
search .

/etc/resolv.conf はシンボリックリンクで、実体は /run/systemd/resolve/stub-resolv.conf。先頭に Do not edit.（編集するな）とある。 nameserver 127.0.0.53 はこの練習機の中のループバックで、そこにいるのは DNS サーバではなく、名前解決を中継する systemd-resolved である（第7章の ss にも 127.0.0.53%lo:53 が出ていた）。 本当の問い合わせ先は systemd-resolved に聞く。

$ resolvectl status
Global
         Protocols: -LLMNR -mDNS -DNSOverTLS DNSSEC=no/unsupported
  resolv.conf mode: stub

Link 2 (enp0s16)
    Current Scopes: none
         Protocols: -DefaultRoute -LLMNR -mDNS -DNSOverTLS DNSSEC=no/unsupported
...
Link 5 (lab0)
    Current Scopes: none
         Protocols: -DefaultRoute -LLMNR -mDNS -DNSOverTLS DNSSEC=no/unsupported
$ host server.lab.example
Host server.lab.example not found: 2(SERVFAIL)
$ getent hosts server.lab.example; echo $?
2

どの NIC にも DNS サーバ（DNS Servers: の行）が無い。この練習機は、読者のネットワークの DNS を使わないように、中継の先を空にしてある。 中継役は聞く相手がいないので SERVFAIL（サーバ側の失敗）を返し、getent（第9章）も見つからない（終了コード 2）。名前は「無い」のではなく「聞けない」。

DNS サーバに、直接聞く

この節で分かること: dig と host で決まったサーバに聞く方法と、答えの読み方。

社内の DNS サーバは 172.16.20.10 である。dig は @サーバ で、resolv.conf を通さずに直接聞ける。

$ dig @172.16.20.10 server.lab.example

; <<>> DiG 9.18.39-0ubuntu0.24.04.7-Ubuntu <<>> @172.16.20.10 server.lab.example
; (1 server found)
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 48758
;; flags: qr aa rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 1232
;; QUESTION SECTION:
;server.lab.example.		IN	A

;; ANSWER SECTION:
server.lab.example.	300	IN	A	172.16.20.10

;; Query time: 15 msec
;; SERVER: 172.16.20.10#53(172.16.20.10) (UDP)
;; WHEN: Tue Oct 13 19:27:29 JST 2026
;; MSG SIZE  rcvd: 63
部分読み方
status: NOERROR答えの種類（応答コード）。名前があった
flags: qr aa rd raqr = 応答、aa = 自分の持ち物として答えた、rd / ra = 再帰を頼んだ / できる
QUESTION SECTION聞いたもの（server.lab.example の A レコード＝IPv4 アドレス）
ANSWER SECTION答え。300 はキャッシュしてよい秒数（TTL）、A はレコードの種類
SERVER:答えたサーバ。resolv.conf に従ったときは、ここが 127.0.0.53 になる

（id と WHEN と Query time はあなたの画面では違う。）host は同じことを1行の文で答える。2つ目の引数がサーバである。

$ host server.lab.example 172.16.20.10
Using domain server:
Name: 172.16.20.10
Address: 172.16.20.10#53
Aliases:

server.lab.example has address 172.16.20.10
server.lab.example has IPv6 address fd00:20::10

host は種類を指定しないと IPv4（A）・IPv6（AAAA）・メールの受け先（MX）をまとめて聞き、あったものだけを表示する。dig は何も指定しなければ A だけを聞く。 （古い解説には「host も種類を省くと A だけ」と書かれていることがある。この練習機の host（bind9-dnsutils 9.18）は、上の記録のとおり IPv6（AAAA）の答えも出している。）

1行足すと引けるようになり、そして消える

この節で分かること: /etc/resolv.conf に書き込んだ先が、どこだったか。

ふつうこう考える

問い合わせ先の DNS サーバは /etc/resolv.conf の nameserver 行で決まる。ここに1行足せば、以後はずっとそのサーバに聞きに行くはずだ。

$ echo 'nameserver 172.16.20.10' | sudo tee -a /etc/resolv.conf
nameserver 172.16.20.10
$ host server.lab.example
server.lab.example has address 172.16.20.10
server.lab.example has IPv6 address fd00:20::10
$ sudo systemctl restart systemd-resolved
$ grep -v '^#' /etc/resolv.conf

nameserver 127.0.0.53
options edns0 trust-ad
search .
$ host server.lab.example
Host server.lab.example not found: 2(SERVFAIL)
だめな理由: 足した直後は引けた（host は1行目の 127.0.0.53 で SERVFAIL を受けると、2行目の 172.16.20.10 にも聞く）。 ところが systemd-resolved を再起動すると、足した行が消えていた。tee -a /etc/resolv.conf が書き込んだのはリンクの先の /run/systemd/resolve/stub-resolv.conf で、これは systemd-resolved が起動のたびに（設定が変わるたびにも）作り直すファイルである。 /run は再起動で空になる場所でもある。「Do not edit.」の通り、ここに書いたものは残らない。

残す方法は2つある

この節で分かること: systemd-resolved に教える方法と、resolv.conf をふつうのファイルにする方法。

1つ目は、中継役の systemd-resolved に「lab0 の先の DNS サーバは 172.16.20.10、検索ドメインは lab.example」と教える方法である。

$ sudo resolvectl dns lab0 172.16.20.10
$ sudo resolvectl domain lab0 lab.example
$ resolvectl status lab0
Link 5 (lab0)
    Current Scopes: DNS
         Protocols: +DefaultRoute -LLMNR -mDNS -DNSOverTLS DNSSEC=no/unsupported
       DNS Servers: 172.16.20.10
        DNS Domain: lab.example
$ grep -v '^#' /etc/resolv.conf

nameserver 127.0.0.53
options edns0 trust-ad
search lab.example
$ host server
server.lab.example has address 172.16.20.10
server.lab.example has IPv6 address fd00:20::10

systemd-resolved が自分の作るファイルに search lab.example を書き足した。host server のように短い名前で聞くと、後ろに lab.example を付けて引いてくれる（検索ドメイン）。 この方法は systemd-resolved の再起動では消えないが、練習機を再起動すると消える（残すなら /etc/systemd/resolved.conf の [Resolve] に DNS= と Domains= を書く）。 1つ寄り道をする。この状態で www.lab.example を引く。

$ host www.lab.example
www.lab.example has address 172.16.20.99

DNS サーバ（172.16.20.10）に聞けば 172.16.20.10 と答える名前なのに、172.16.20.99 が返った。systemd-resolved は DNS サーバに聞く前に /etc/hosts も読んで答える。 その /etc/hosts に古い行が残っている。これは第9章の主題なので、ここでは「中継役を通すと、DNS の道具（host）にも /etc/hosts が混ざる」とだけ覚えておく。元に戻す。

$ sudo resolvectl revert lab0
$ host server
Host server not found: 2(SERVFAIL)

2つ目は、リンクをやめて /etc/resolv.conf をふつうのファイルにする方法である。ファイルの先頭のコメント（replace this symlink by a static file）が勧めているやり方で、 LinuC の試験が想定している「resolv.conf に書く」はこちらの形になる。

$ sudo unlink /etc/resolv.conf
$ printf 'nameserver 172.16.20.10\nsearch lab.example\n' | sudo tee /etc/resolv.conf
nameserver 172.16.20.10
search lab.example
$ ls -l /etc/resolv.conf
-rw-r--r-- 1 root root 43 Oct 13 19:27 /etc/resolv.conf
書き方意味
nameserver 172.16.20.10問い合わせ先の DNS サーバ。1行に1つ書き、3行まで書ける。上から順に試す
search lab.example短い名前に付け足して試すドメイン（検索ドメイン）。複数なら1行に空白で区切って並べる（2行に分けると後の行だけが効く。次の節で確かめる）
domain lab.examplesearch の古い形（1つだけ）。search と両方書くと後に書いた方が効く
options …待ち時間や試す回数などの細かい指定（timeout: attempts: など）

こんどはリンクではないので、systemd-resolved を再起動しても書き換えられない。

$ sudo systemctl restart systemd-resolved
$ cat /etc/resolv.conf
nameserver 172.16.20.10
search lab.example
$ getent hosts ns.lab.example
172.16.20.10    ns.lab.example
たとえ: 会社の代表電話の「取り次ぎ表」に近い。ふだんは受付（systemd-resolved）が取り次ぎ表を持っていて、 社員が見る掲示（/run の stub-resolv.conf）は受付が毎朝貼り替える。掲示に手で書き足しても、翌朝には消えている。
ただし崩れる点: 会社なら掲示を剥がして自分の表を貼れば受付は口を出さないが、Linux でも同じことができる。 リンクをやめてふつうのファイルにすれば、systemd-resolved はそのファイルに触らない（そのかわり、中継役の便利な機能は使われなくなる）。

dig は、search を使わない

この節で分かること: host と dig の、短い名前の扱いの違い。
$ dig +short server.lab.example
172.16.20.10
$ host server
server.lab.example has address 172.16.20.10
server.lab.example has IPv6 address fd00:20::10
$ dig +short server
$ dig +short +search server
172.16.20.10

host は resolv.conf の search を使って server を server.lab.example として引く。dig は何も付け足さずに「server.」という名前を聞くので何も返らない（+short は答えだけを出す指定）。 +search を付けると search を使う。「dig で引けないから DNS に無い」とは限らない。

たとえ: 社内で「鈴木さん」と言えば同じ部の鈴木さんと分かる（host）が、外線の交換手（dig）は「鈴木さんという方は何社の？」と聞き返さず、そのまま「該当なし」と答える。
ただし崩れる点: 人は聞き返してくれることもあるが、dig は +search を付けない限り決して付け足さない。道具の決まりで、文脈は関係ない。

search に複数のドメインを書くときは、1行に空白で区切って並べる。行を分けて2行にすると、後の行だけが効く（domain の行と同じ決まりで、resolv.conf(5) に書いてある）。 わざと2行に分けて確かめ、最後に元に戻す。

$ printf 'nameserver 172.16.20.10\nsearch lab.example\nsearch nosuch.lab.example\n' | sudo tee /etc/resolv.conf
nameserver 172.16.20.10
search lab.example
search nosuch.lab.example
$ host server
Host server not found: 5(REFUSED)
$ printf 'nameserver 172.16.20.10\nsearch nosuch.lab.example lab.example\n' | sudo tee /etc/resolv.conf
nameserver 172.16.20.10
search nosuch.lab.example lab.example
$ host server
server.lab.example has address 172.16.20.10
server.lab.example has IPv6 address fd00:20::10
$ printf 'nameserver 172.16.20.10\nsearch lab.example\n' | sudo tee /etc/resolv.conf
nameserver 172.16.20.10
search lab.example

2行のときは、2行目の nosuch.lab.example だけが使われ、1行目の lab.example は試されずに見つからなかった（REFUSED の意味は次の節で扱う。ここでは「引けなかった」と読めばよい）。 1行に並べると前から順に試し、2つ目の lab.example で見つかった。nameserver はこれと違い、1行に1つずつ書く（3行まで。上から順に聞く）。

DNS の答えを読む

この節で分かること: 逆引き・MX・AAAA・CNAME と、答えが無いときの種類。
$ dig +short -x 172.16.20.10
server.lab.example.
$ host 172.16.20.10
10.20.16.172.in-addr.arpa domain name pointer server.lab.example.
$ dig +short MX lab.example
10 mail.lab.example.
$ host -t MX lab.example
lab.example mail is handled by 10 mail.lab.example.
$ dig +short AAAA server.lab.example
fd00:20::10
$ dig +noall +answer web.lab.example
web.lab.example.	300	IN	CNAME	www.lab.example.
www.lab.example.	300	IN	A	172.16.20.10
$ host nosuch.lab.example
Host nosuch.lab.example not found: 3(NXDOMAIN)
$ host example.com
Host example.com not found: 5(REFUSED)
聞き方意味
dig -x アドレス / host アドレス逆引き（アドレスから名前。in-addr.arpa の PTR レコード）
dig MX / host -t MXそのドメイン宛てのメールを受ける機械（数が小さいほど優先）
dig AAAAIPv6 アドレス（A は IPv4）
dig -t 種類種類を -t で指定する形（dig -t MX は dig MX と同じ）
dig +tcp（+vc）TCP で聞く（既定は UDP）。-p 番号 は問い合わせ先のポート番号
CNAME別名。web.lab.example は www.lab.example の別名で、dig は行き先の A まで一緒に返した
3(NXDOMAIN)その名前は存在しない（確かな答え）
2(SERVFAIL)サーバが答えを用意できなかった（この練習機では中継の先が無かった）
5(REFUSED)答えるのを断った。この社内 DNS は lab.example しか知らず、外の名前は聞きに行かない
たとえ: 問い合わせ窓口の3つの返事に近い。「該当者はおりません」（NXDOMAIN）、「担当者が不在で調べられません」（SERVFAIL）、 「こちらではお答えできません」（REFUSED）。名前が無いと言っているのは1つ目だけである。
ただし崩れる点: 人の窓口は理由を添えて話してくれるが、DNS は番号1つしか返さない。 SERVFAIL の理由（この練習機では中継の先が空だったこと）は、resolvectl status のように別の道具で調べるしかない。

dig のオプションには2つの系統がある。+ で始まるもの（聞き方の指定: +short・+search・+tcp など）と、 - で始まるもの（-t 種類、-p ポート番号、-x 逆引き）である。DNS は既定で UDP を使い、+tcp（古い書き方は +vc）で TCP にできる。 どちらで聞いたかは、答えの最後の SERVER: の行に出る。

$ dig server.lab.example | grep SERVER
;; SERVER: 172.16.20.10#53(172.16.20.10) (UDP)
$ dig +tcp server.lab.example | grep SERVER
;; SERVER: 172.16.20.10#53(172.16.20.10) (TCP)
$ dig +vc server.lab.example | grep SERVER
;; SERVER: 172.16.20.10#53(172.16.20.10) (TCP)
$ dig --tcp server.lab.example
Invalid option: --tcp
...
$ dig +t server.lab.example
Invalid option: +t
...
$ dig -t MX +short lab.example
10 mail.lab.example.
$ dig -p 53 +short @172.16.20.10 server.lab.example
172.16.20.10

--tcp や +t という形は無く、Invalid option で断られた。-t MX は MX と書くのと同じ、-p 53 は問い合わせ先のポート番号（既定の 53）を指定している。

名前が引けるようになったので、第5章の traceroute の表示も変わる。名前はアドレスの逆引きで、DNS サーバが答えている。

$ traceroute 172.16.20.10
traceroute to 172.16.20.10 (172.16.20.10), 30 hops max, 60 byte packets
 1  router.lab.example (192.168.10.1)  2.152 ms  0.148 ms  0.093 ms
 2  server.lab.example (172.16.20.10)  0.242 ms  0.073 ms  0.058 ms

第5章では1番目が _gateway（systemd-resolved が付けた名前）、2番目は名前が付かなかった。答えている表が変わると、同じ道具の表示が変わる。

確認

/etc/resolv.conf が次の内容のとき、ping web を打つと最初に問い合わせる名前はどれか（/etc/hosts には web の行が無いものとする）。

nameserver 192.168.1.53
search example.co.jp example.com

A. web　B. web.example.co.jp　C. web.example.com　D. 192.168.1.53.web

答え

B。ドットを含まない短い名前は、search に書いた順に付け足して試す（見つからなければ web.example.com、最後に web そのもの）。 問い合わせ先は nameserver の 192.168.1.53。dig web なら search を使わず web だけを聞く。

確認

DNS サーバ 192.168.1.53 に、www.example.com の IPv4 アドレスだけを直接問い合わせるコマンドとして正しいものはどれか。

A. dig www.example.com 192.168.1.53　B. dig @192.168.1.53 www.example.com　C. host -s 192.168.1.53 www.example.com　D. dig -x www.example.com @192.168.1.53

答え

B。dig はサーバを @ で指定する（A の形は、2つ目の引数を名前として聞いてしまう）。種類を書かなければ A レコード（IPv4）を聞く。 host なら host www.example.com 192.168.1.53（サーバは2つ目の引数）。-x は逆引き。

手を動かす: 実践編の演習06が、lab.example の名前を引けるようにする課題である。 判定は判定の中で systemd-resolved を再起動してから名前を引くので、リンクの先に1行足しただけでは ✗ になる（この章の「消える」をそのまま踏む）。

この章で分かったこと

持ち帰ってほしいこと

  • /etc/resolv.conf の nameserver は問い合わせ先（3つまで）、search は短い名前に付け足すドメイン
  • Ubuntu の既定では resolv.conf は /run へのリンクで、127.0.0.53 は中継役の systemd-resolved。本当の問い合わせ先は resolvectl status
  • リンクの先に書いた行は systemd-resolved が消す。残すなら resolv.conf をふつうのファイルにするか、resolved.conf に書く（resolvectl は再起動で消える）
  • dig @サーバ 名前（+short / -x / MX / AAAA）と host 名前 サーバ（-t MX）。dig は search を使わない
  • NXDOMAIN は「無い」、SERVFAIL は「答えられない」、REFUSED は「断る」。引けないことと名前が無いことは別
