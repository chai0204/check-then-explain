確かめて説明する LinuC 主題1.07

LinuC レベル1 102 試験・主題1.07「ネットワークの基礎」 （プロトコルの基礎 / ネットワーク構成 / 問題解決 / クライアント側の DNS 設定。重要度の合計 14）を、 仮想マシンの中に作った社内 LAN で実際に打って確かめます。 ip も ifup も nmcli も traceroute も、本物のカーネルの上で動きます。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: コマンドは打てる。写経すれば動く。 でも「なぜ動くのか」を人に説明できない人。
LinuC を受ける人向けには: ip と ifconfig、ifup と nmcli、dig と ping を「同じことをする別の道具」として覚えていて、 どれを打てば何が分かるのかで止まっている人。

docker exec -it lab-linuc-network bash -l

最初の起動では、練習機の起動（KVM なしで 40〜90 秒）と、このコースの準備（社内 LAN を作る）が続けて走ります。 著者の環境では、docker run から準備が終わるまで約 65 秒でした。 1行目が running（エージェント 応答あり / ssh 待ち受け中） になると練習機に入れますが、初回はその後 20 秒ほど準備が続きます。 準備が終わったかは、外で次のコマンドがファイル名を表示することで分かります（まだなら No such file or directory）。

ls ~/vm/.provisioned
ssh linuc

プロンプトが student@linuc に変わります。本文の端末の見出しが「練習機の中（student@linuc）」なら練習機で、 「外（lab@host）」なら外のコンテナで打ってください。抜けるのは exit です。

起動コマンドの --stop-timeout 30 について（権限ではありません）

docker stop は既定で 10 秒待って強制終了します。練習機の正常な停止には、KVM なしで 7〜11 秒かかりました（PC が混んでいるほど長くなります）。 10 秒を超えると電源を抜いたのと同じになり、次の起動でディスクの回復が走ります。30 秒待たせれば正常に止まります。 付けずに作ったコンテナは docker stop -t 30 lab-linuc-network で止めてください。

podman（5.8.6・rootless）でも、同じ起動オプションのまま docker を podman に読み替えて動きます （仮想マシン型の檻に共通の土台で確かめてあります。本文の出力は docker で取ったものです）。

読者に渡してもらう権限は1つもありません（--cap-add も --privileged も無し）。 練習機は QEMU の完全エミュレーション（TCG）で動き、ホストの特権を借りずに本物のカーネルを動かします。 --device /dev/kvm を足しても速くはなりません。練習機の定義が type='qemu'（KVM を使わない完全エミュレーション）に固定されているためです（KVM の記事の6章で測っています）。

練習機はインターネットに出ません（わざとです）

練習機の管理用 NIC（enp0s16）は、外のコンテナを通って読者のネットワークにつながっています。 そのままにすると、練習機の通信の一部が読者の家や会社のネットワークへ出ていき、読者ごとに画面が変わります。 著者の環境で実測した例: 管理用 NIC が受け取った IPv6 のデフォルトルート（default via fe80::2 metric 100）が 社内 LAN のルータの経路（metric 1024）より優先され、練習機の IPv6 の通信が全部外へ出て、社内のサーバに ping6 が届きませんでした。

そこで管理用 NIC からはデフォルトルート・DNS サーバ・IPv6 の自動設定を受け取らないようにしてあります （ssh と lab check は 10.0.2.2 と直接つながっているので、デフォルトルートが無くても通ります）。 練習用の2枚の NIC も外へは転送しない設定です。apt install はできませんが、この主題で使う道具は全部入っています。

1.0.2 で始めた人は、「終わったら」の手順で檻を止めてから（ボリュームは消さずに）、上の起動コマンドで起動し直すだけで構いません。1.0.3 で変わったのは lab コマンドだけなので、進み具合と作業ファイルはそのまま使えます。

演習

Issue を立てる（フォームが3種類あります）。 カーネル の行はあなたの母艦のカーネルなので、違っていて正常です。練習機の版は 練習機 OS の行です。 練習機 の行が running 以外のときは、外で vm start を打ってください。

ping や traceroute の時間（ms）、DHCP の残り時間、プロセス番号、nmcli が作る UUID、tcpdump のポート番号とシーケンス番号は 毎回変わります。本文では変わる値の近くにそう書いてあります。ss の列の間隔は端末の幅で変わります（本文は 80 桁の端末で取りました）。
