確かめて説明する KVM — 実践編

コンテナの中で、Ubuntu 24.04 の練習機（仮想マシン）を qemu-system-x86_64 で直接起動し、 同じ練習機を TCG（完全エミュレーション）と KVM で起動して比べます。KVM を使うには、あなたの PC の /dev/kvm を檻に渡します。 渡せない PC でも、--device なしで檻は起動し、TCG の演習はできます（Linux の PC で確かめました。macOS・Windows の Docker Desktop では試していません）。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この記事はあなたの PC の CPU と KVMを見るので、CPU の名前・/dev/kvm の権限・時間などは本文と違って正常です。そういう行には本文に注記があります。

影響度 B（変更は練習機とコンテナの中だけ。あなたの PC の設定もファイルも書き換えません）。 /dev/kvm を渡しても、あなたの PC の KVM の設定（nested など）は読むだけで、変えません。

はじめる

あなたの PC が Linux で、/dev/kvm がある場合（ls -l /dev/kvm で確かめる）。

docker run --rm -it --name lab-kvm --hostname host \
  --device /dev/kvm --group-add "$(stat -c %g /dev/kvm)" \
  -v lab-kvm-vm:/home/lab/vm -v lab-kvm-state:/home/lab/.lab \
  ghcr.io/chai0204/lab:kvm-1.0.0@sha256:__DIGEST__

/dev/kvm が無い場合（入れ子の仮想化が無効な仮想マシンの中など）は、--device と --group-add の行を外します。 TCG の演習（01・05）と、理論編の TCG の章はそのままできます。KVM が要る演習は lab check が「前提不足」と理由を出します。 macOS・Windows の Docker Desktop では、著者は試していません（/dev/kvm が渡せるかも、檻が起動するかも未確認です。この檻のイメージは amd64 用だけです）。

docker run --rm -it --name lab-kvm --hostname host \
  -v lab-kvm-vm:/home/lab/vm -v lab-kvm-state:/home/lab/.lab \
  ghcr.io/chai0204/lab:kvm-1.0.0@sha256:__DIGEST__
書いてあるものなぜ書くか
--rm -it端末をつないで起動し、抜けたらコンテナを消す。あなたの PC に残骸を残さない
--hostname host外のプロンプトを lab@host にする（練習機は student@linuc）。本文と同じ表示にするため
--device /dev/kvmあなたの PC の /dev/kvm を檻に置き、その番号（10, 232）を開くことをコンテナに許す（第2章）
--group-add "$(stat -c %g /dev/kvm)"/dev/kvm の持ち主のグループの番号を、檻の lab に足す。/dev/kvm が 0660 の PC ではこれが無いと開けない（第2章）
-v lab-kvm-vm:…練習機のディスク（土台との差分）の置き場。起動し直しても練習機の中は続きから
-v lab-kvm-state:…演習の進捗の置き場。これを省くと次回起動時に進捗が消えます
@sha256:…イメージを1つに固定する。これがあるので「本文と同じ文字が出る」を約束できる
podman で起動する場合: docker を podman に置き換えても檻は起動します。ただし rootless の podman では、 --group-add の番号は檻の中の番号として扱われ、あなたの PC の kvm グループにはなりません（檻の中の /dev/kvm は nobody nogroup と表示されます）。 /dev/kvm が 0660 の PC（Ubuntu 24.04・podman 4.9.3）では、この起動コマンドのままでは Permission denied で開けませんでした。 あなたが kvm グループに入ったうえで --group-add keep-groups を使うと開けました（podman の OCI ランタイムが crun のときだけ効きます。--runtime runc では効きませんでした）。 0666 の PC（著者の PC・podman 5.8.6・crun）では、どちらでも開けました。演習の判定（lab check）を podman で通しては試していません。

--privileged も --cap-add も要りません。--device と --group-add で増えるのは、デバイスのファイル1つと補助グループ1つで、 特権は増えません（持てる特権の上限 CapBnd が docker の既定のままです）。第2章と演習02で、実際に測って確かめます。

入ると、現在地が出ます。著者の PC（--device と --group-add を付けて起動）では、こう出ました。

groups: cannot find name for group ID 302

lab-kvm  進捗 0/5

────────────────────────────────────────────────────────────
  • 1行目の groups: cannot find name for group ID 302 は害がありません。302 はあなたの PC の /dev/kvm のグループの番号で、檻の中にはその番号の名前が無い、という知らせです（番号は PC で違う。第2章）。 --group-add を付けなかったときは出ません。
  • 2行目は、練習機が動いているか（動いていれば TCG か KVM か）と、この檻の lab が /dev/kvm を開けるかです。 /dev/kvm: なし なら --device なしで起動しています。あり（開けない: Permission denied） なら --group-add が要ります。

練習機の動かし方

練習機は qemu-linuc で起動します。後ろに書いたものがそのまま QEMU のオプションになり、実際に打ったコマンド行を ▶ で表示します。 固定の部分（メモリ・CPU の数・UEFI・ディスク・NIC）は、このサイトの他の練習機と同じです。

コマンド何をするか
qemu-linuc -accel tcgTCG で起動し、練習機が起動し終わるまで待つ（著者の PC で 30 秒前後）
qemu-linuc -accel kvmKVM で起動する（同じく 7 秒前後。/dev/kvm が要る）
qemu-linuc -accel kvm -cpu host練習機にあなたの PC の CPU をそのまま見せて起動する
ssh linuc / exit練習機に入る / 外に戻る
qemu-linuc stop練習機の中で poweroff を頼み、止まるまで待つ。檻を抜ける前に打ってください
qemu-linuc status動いているか・どのアクセラレータか・/dev/kvm を開けるか
qemu-linuc reset --yes練習機のディスクを最初の状態に戻す（中の変更と起動の記録はすべて消える）

練習機を止めずに檻を exit すると、練習機は電源を抜かれたのと同じになります（次の起動でディスクの回復が走ることがあります）。

演習

5本あります。判定は観測できる結果だけで行い、コマンドの打ち方は見ません（QEMU のプロセスが開いているファイルと、練習機の中の OS の答えを見ます）。 詰まったら lab hint NN を何度でも。使い切ったら lab solve NN で模範解答に必ず届きます （見ても構いません。進捗には「solve を見た」として残ります）。

NoやることKVM章目安
01練習機を TCG で起動し、中から見える CPU を確かめる不要110分
02この檻の lab が /dev/kvm を開けるようにする要る210分
03同じ練習機を KVM で起動し直し、起動の速さを比べる要る3・412分
04練習機に、あなたの PC の CPU をそのまま見せる要る510分
05練習機の CPU から、仮想化支援の印を消す不要512分

課題は lab start NN で開きます。lab は「元に戻すには起動し直してください」と出しますが、この檻では起動し直しても練習機のディスクは戻りません（ボリュームに残ります）。 練習機を最初の状態に戻すのは qemu-linuc stop の後の qemu-linuc reset --yes です（演習03 が見る起動の記録も消えます）。

判定は外の端末でも、練習機の中でも lab check NN で打てます。演習03・04 を /dev/kvm の無い（開けない）檻で打つと、 ⚠ この環境では判定できません と、理由（/dev/kvm が無い・開けない）が出ます。読者の失敗ではありません。 演習02 は /dev/kvm を用意すること自体が課題なので、KVM のある PC では ✗ 未達 になり、docker が動いているカーネルに KVM が無いときだけ ⚠ になります。 演習05 は、KVM（-cpu host）で確かめようとして、あなたの PC の KVM が入れ子の仮想化を許していない（nested が N / 0）ときも ⚠ になります（TCG でやってください）。

先に読む場合は 理論編（6章）へ。章と演習は対応しているので、どちらから始めても構いません。

終わったら

qemu-linuc stop                                  # 檻の中で。練習機を正常に止める
exit                                             # 檻を抜ける（--rm なのでコンテナは消える）
docker volume rm lab-kvm-vm lab-kvm-state        # あなたの PC で。練習機のディスクと進捗も消す場合だけ

イメージは docker rmi で消せます。あなたの PC には何も残りません（名前付きボリューム以外のファイルを作っていないため）。 続きをやる日は、同じ docker run をもう一度打てば、練習機のディスクも進捗もそのまま残っています。
