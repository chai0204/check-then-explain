確かめて説明する QEMU — 実践編

コンテナの中に QEMU と練習機のディスクが入っています。あなたは libvirt（virsh）を使わず、 qemu-system-x86_64 と qemu-img を自分で打って、仮想マシンを組み立て、起動し、止めます。 理論編の7章と演習6本は、全部この檻の中で打てます。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま仮想マシンを作りたいだけの人 → virt-manager や公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: このサイトの実践編で docker run を打ち、練習機を起動したことはある。 でも、そのとき裏で何が動いていて、--stop-timeout 30 や ssh linuc が何をしているのかを人に説明できない人。

はじめる

Docker の場合。1行です。

docker run --rm -it --name lab-qemu --hostname host \
  -v lab-qemu-work:/home/lab/work \
  -v lab-qemu-state:/home/lab/.lab \
  ghcr.io/chai0204/lab:qemu-1.0.2@sha256:d9dfe1cb9112ebddb41b322fd9df5ab479cf53515085e47014368f9baf8bae55
書いてあるものなぜ書くか
--rm -it端末つきで入り、exit でコンテナごと消える。中で動かした QEMU も一緒に消える
--hostname hostプロンプトを lab@host にする。練習機（student@linuc）と見分けるため。他の仮想マシン型の檻と同じ
-v lab-qemu-work:/home/lab/work本文と演習で作るディスク（qcow2）の置き場所。名前付きボリュームなので、exit しても次の起動で続きから使える
-v lab-qemu-state:/home/lab/.lab演習の進捗。省くと次の起動で進捗が消える
@sha256:…イメージを1つに固定する。中の QEMU・ファームウェア・練習機のディスクが本文と同じ版になる

podman でも同じオプションで動きます（docker を podman に置き換える。著者が podman 5.8.6 の rootless で、第5章と演習 05 の流れが docker と同じに動くことを確かめた）。

入ると現在地が出ます。

── lab-qemu 1.0.2 ────────────────────────────────────────
lab-qemu  進捗 0/6
  次 → 01 「画面の無い PC を後ろで動かし、QMP で尋ねられるようにする」 (目安 12分 / 影響度 B)
  lab start 01 で課題を開く
  進捗の保存先: /home/lab/.lab/progress.json（消すには docker volume rm lab-qemu-state）
  lab ls      演習一覧 / lab start NN  課題を開く / lab check  答え合わせ
────────────────────────────────────────────────────────────

シェルは章をまたいで同じまま使う前提です。理論編は、檻に入ったときのシェルで第1章から順に打っていく書き方にしてあります。 前の章で作ったディスク（~/work/linuc.qcow2）を後の章でも使い、第1章で QEMU を抜けた端末の状態が第2章の最初の画面になります。 本文の記録は、第1章から第7章までを1つのシェルで通して打ったものです。

  • 練習機にログインするときのユーザとパスワードは student / student です（パスワードは打っても表示されません）。
  • 練習機の中に表示される「この中でも lab check NN で答え合わせできます」は、他の仮想マシン型の檻の案内で、この檻では使えません（中から外の lab に頼む中継を動かしていないため）。lab check は外（lab@host）で打ってください。
  • QEMU を前で動かしている間（-nographic や -serial mon:stdio）は、その端末は練習機の画面になります。抜けるのは Ctrl-a x です（Ctrl-C は練習機に届く）。演習で練習機を動かしたまま lab check を打ちたいときは、-daemonize で後ろに回すか、別の窓で docker exec -it lab-qemu bash -l と打って入ります。
  • 本文と演習の練習機には、1.5GB のメモリを割り当てます（-m 1536）。Docker Desktop のように docker が仮想マシンの中で動く環境では、その仮想マシンに割り当てたメモリから使われます。

1.0.1 で始めた人は、「終わったら」の手順で檻を止めてから（ボリュームは消さずに）、上の起動コマンドで起動し直すだけで構いません。1.0.2 で変わったのは lab コマンドだけなので、進み具合と作業ファイルはそのまま使えます。

演習

6本あります。判定は観測できる結果だけで行い、コマンドの打ち方は見ません。 判定は、あなたの QEMU に QMP で尋ねたり、ディスクのファイルを qemu-img で読んだり、ssh linuc で練習機に入ったりして確かめます。 課題文は lab start NN で開き、作業の途中でも lab show でもう一度出せます。 詰まったら lab hint NN を何度でも。使い切ったら lab solve NN で模範解答に必ず届きます （見ても構いません。進捗には「solve を見た」として残ります）。作業場所は lab start NN が作る ~/work/NN です。

Noやること章判定が見るもの目安

先に読む場合は 理論編（7章）へ。 演習は章の順に並んでいますが、どれも単体で始められます（どの演習も、自分のディスクを ~/work/NN に作るところから始めます）。

演習 05 と 06 は、どちらも練習機の ssh を 127.0.0.1:2222 で受けます。片方を動かしたままもう片方を起動すると、 Could not set up host forwarding rule で断られます。先に動いている方を止めてください（止め方は各演習の解答にあります）。

lab は sudo を付けずに打ちます。付けると root として動き、作業ディレクトリと進み具合が /root の下にできて檻を抜けると消えてしまうので、理由を出して何もせずに止まります。~/work や ~/.lab の持ち主が自分でなくなっていたら、lab が見つけて戻し、そのことを画面に出します。

Issue を立てる（フォームが3種類あります）。 カーネル の行は、あなたの PC のカーネルなので本文と違って正常です。 /dev/kvm の行が「あり」なら、起動のときに --device /dev/kvm を付けています。本文は /dev/kvm の無い檻で取った記録で、付けたままだと第4章の -accel kvm の行の結果が本文と変わります。外して起動し直してください。 本文の時間を測る行（time の結果や info jit の数）は、あなたの CPU の速さで変わります。

終わったら

exit                                              # --rm なのでコンテナは消える。中で動かしていた QEMU も止まる
docker volume rm lab-qemu-work lab-qemu-state     # 作ったディスクと進捗も消す場合だけ

イメージは docker rmi で消せます。 あなたの PC には何も残りません（名前付きボリューム以外のファイルを作っていないため）。 続きをやる日は、同じ docker run を打てば、~/work のディスクと進捗はそのまま残っています。
