1. 何も渡さなくても、PC が1台組み上がる

qemu-system-x86_64 とだけ打つ。ディスクも何も渡していないのに、QEMU は使い方もエラーも出さず、1行を出したまま戻ってこない。 画面を端末に出してみると、BIOS が起動し、ハードディスク・フロッピー・CD を順に探し、最後にはネットワークから起動しようとして、 DHCP で 10.0.2.15 という IP アドレスまでもらっていた。QEMU は「渡されたディスクを動かす」プログラムではなく、 コマンド行に書かれなかった部品を既定値で補って、PC を1台組み立てて電源を入れるプログラムである。

前提: 檻が起動している所要 15分影響度 B最終検証 2026-10-14

この章のゴール

  • qemu-system-x86_64 が、PC を1台ソフトウェアで組み立てて動かすプログラムだと、何も渡さずに起動した画面で示せる
  • マシン型（pc / q35）・CPU の型（qemu64 / max / host）・デバイスの一覧を、-machine help・-cpu help・-device help で調べられる
  • 何も指定しないときに付いてくる部品（フロッピー・CD-ROM・NIC と、その先のネットワーク）を、QEMU のモニタで確かめられる
  • virtio と昔ながらのデバイス（e1000・IDE）の違いを、「実在する部品の真似か、仮想マシンのための取り決めか」で説明できる
ここで覚えなくていいこと: マシン型の版ごとの違い（pc-i440fx-noble と pc-i440fx-8.2）、iPXE の使い方、 VNC で画面を見る方法、-device に渡せる細かい設定。この章のモニタ（(qemu)）は「QEMU に尋ねる窓がある」ことだけ分かれば足り、使い方は第2章で見る。

何も渡さずに起動する

この節で分かること: QEMU が、部品を何も指定されなくても止まらずに動き続けること。

檻に入ったら、作業の場所（ボリュームの ~/work）に移り、QEMU の版を見る。この記事は、ここから第7章まで同じシェルで続けて打つ。

$ cd ~/work
$ qemu-system-x86_64 --version
QEMU emulator version 8.2.2 (Debian 1:8.2.2+ds-0ubuntu1.18)
Copyright (c) 2003-2023 Fabrice Bellard and the QEMU Project developers

qemu-system-x86_64 は「x86_64 の計算機（system）を丸ごと作る QEMU」という名前である。ARM の計算機を作る qemu-system-aarch64 のように、作る計算機の種類ごとに別のプログラムがある（この檻には x86_64 のものだけが入っている）。

ふつうこう考える

QEMU は、仮想マシンのディスクのイメージを渡して起動するものだ。何も渡さずに打てば、使い方を表示するか、「ディスクが無い」というエラーで終わるはずだ。

$ qemu-system-x86_64
VNC server running on ::1:5900
（打鍵: Ctrl-C）
^Cqemu-system-x86_64: terminating on signal 2
だめな理由: エラーで終わらず、プロンプトも戻ってこなかった（著者は数秒待って Ctrl-C で止めた。待ち続けても何も起きない）。 QEMU は仮想の PC を1台組み立てて電源を入れ、その画面を VNC（画面を遠くから見るための仕組み）で出していた。 この檻の QEMU には、窓を開いて画面を描く部品が入っていないので、画面の出し先に VNC を選び、このコンテナの中の ::1（自分自身）の 5900 番で待ち受けた。誰も見ていない画面の中で、PC は動き続けていた。 QEMU の仕事は「渡されたディスクを動かす」ではなく「PC を組み立てて動かす」で、ディスクは部品の1つにすぎない。部品を指定しなければ、既定の部品で組み立てる。
たとえ: QEMU は、部品表を渡されると、その場で PC を組み立てて電源を入れる組み立て屋に近い。 部品表に書いていない部品は、店の標準品で埋める。
ただし崩れる点: 実物の組み立て屋は部品が無ければ組めないが、QEMU は部品を全部ソフトウェアで作るので、部品表が空でも1台組める。 そして電源を切る（プロセスが終わる）と、PC は跡形もなく消える。残るのは、ディスクとして渡したファイルだけである。

部品の選び方を QEMU に尋ねる

この節で分かること: 「PC」を決める3つの選択（マシン型・CPU の型・デバイス）と、その一覧の出し方。virtio と昔ながらのデバイスの違い。

何を組み立てるかは、3つのオプションで選ぶ。まずマシン型（-machine）。マザーボードとチップセットの型に当たる。

$ qemu-system-x86_64 -machine help | grep -E '^(pc|q35) '
pc                   Ubuntu 24.04 PC (i440FX + PIIX, 1996) (alias of pc-i440fx-noble)
pc                   Standard PC (i440FX + PIIX, 1996) (alias of pc-i440fx-8.2)
q35                  Ubuntu 24.04 PC (Q35 + ICH9, 2009) (alias of pc-q35-noble)
q35                  Standard PC (Q35 + ICH9, 2009) (alias of pc-q35-8.2)
$ qemu-system-x86_64 -machine help | grep default
pc-i440fx-noble-v2   Ubuntu 24.04 PC v2 (i440FX + PIIX, arch_caps fix, 1996) (default)

大きく2種類ある。pc は 1996 年の Intel のチップセット（i440FX と PIIX）を、q35 は 2007 年のもの（Q35 と ICH9。一覧の説明文には 2009 とある）を真似る。 何も指定しないときに使われるのは pc-i440fx-noble-v2（(default) の行）で、1996 年型の PC だった。 名前の後ろの noble や 8.2 は版である。QEMU を新しくしても、同じ版を指定すれば同じ部品の並びが組み上がる（中の OS から見たハードウェアが、QEMU の更新で勝手に変わらない）。 同じ pc が2行あるのは、Ubuntu が自分の版（noble）の別名と、QEMU 本来の版（8.2）の別名を両方載せているためである。 どちらが使われるかは、一覧からは分からない。この QEMU で -machine pc と打つと、QEMU 本来の版（pc-i440fx-8.2）のほうが組み上がる（q35 も同じで、第5章で確かめる）。

次に CPU の型（-cpu）。

$ qemu-system-x86_64 -cpu help | grep -E '^x86 (qemu64|qemu64-v1|max|host) '
x86 qemu64                (alias configured by machine type)
x86 qemu64-v1             QEMU Virtual CPU version 2.5+
x86 host                  processor with all supported host features
x86 max                   Enables all features supported by the accelerator in the current host
$ qemu-system-x86_64 -cpu help | grep -c '^x86 '
145

何も指定しないと qemu64 になる。その中身は「QEMU Virtual CPU version 2.5+」という、どこの会社も売っていない CPU で、 どの PC の上でも同じに見えるよう、機能を少なめにしてある。max は使える機能を全部持たせた CPU、host はホストの CPU をそのまま見せる CPU で、host は KVM を使うときにしか選べない（第4章）。 一覧には別名を含めて 145 の型が並び（最後の行）、ほとんどは実在する CPU（Broadwell や EPYC など）の機能を真似たものである。

最後にデバイス（-device）。種類ごとに分かれている。

$ qemu-system-x86_64 -device help | grep -E '^[A-Z].*:$'
Controller/Bridge/Hub devices:
USB devices:
Storage devices:
Network devices:
Input devices:
Display devices:
Sound devices:
Misc devices:
CPU devices:
Watchdog devices:
Uncategorized devices:
$ qemu-system-x86_64 -device help | grep -E '"(e1000|virtio-net-pci|ide-hd|virtio-blk-pci)"'
name "ide-hd", bus IDE, desc "virtual IDE disk"
name "virtio-blk-pci", bus PCI, alias "virtio-blk"
name "e1000", bus PCI, alias "e1000-82540em", desc "Intel Gigabit Ethernet"
name "virtio-net-pci", bus PCI, alias "virtio-net"

ディスクにも NIC にも、2つの系統がある。ide-hd と e1000 は実在する部品の真似で、 e1000 は Intel の 82540EM という実際の NIC の振る舞いを、レジスタ1つ1つまで再現する。中の OS は、本物の 82540EM のためのドライバをそのまま使う。 virtio-blk-pci と virtio-net-pci は、仮想マシンのために決めた取り決め（virtio）に沿った部品で、手本にした実物の製品は無い（取り決めのほうに合わせて、後から実物の装置を作った製品はある）。 中の OS は「相手は仮想の部品だ」と分かったうえで、少ないやりとりでまとめてデータを渡すので、本物の部品を真似る手間が要らない。そのかわり、中の OS に virtio のドライバが要る（Linux には入っている）。

昔ながらのデバイス（e1000・IDE）virtio（virtio-net・virtio-blk）
何の真似か実在する部品（Intel 82540EM・IDE のディスク）何の真似でもない。仮想マシン用の取り決め
中の OS に要るものその部品の、昔からあるドライバvirtio のドライバ
QEMU の仕事本物のレジスタの読み書きを1つずつ再現する決まった形の受け渡しの場所（キュー）を読み書きする
中から見える名前（Linux）ディスクは /dev/sda、NIC は e1000 のドライバディスクは /dev/vda、NIC は virtio_net のドライバ
たとえ: 昔ながらのデバイスは、本物そっくりに作った模型の電話である。受話器を上げ、ダイヤルを回す手順まで本物と同じなので、使い方を知っている人なら誰でも使える。 virtio は社内の連絡箱で、決まった用紙を入れれば相手に届く。手順が少ない分、速い。
ただし崩れる点: 連絡箱は社内の約束を知らない人には使えない。virtio のドライバを持たない古い OS は、virtio のディスクを見つけられずに起動できない。 だから QEMU は、何も指定されなければ、誰でも使える模型の電話（e1000 や IDE）を付ける。

画面を端末に出して、PC の起動を見る

この節で分かること: 何も渡さない PC が、電源を入れてから何をしていたか。QEMU 自身に部品を尋ねる窓（モニタ）があること。

VNC の代わりに、PC の画面を端末に出す -nographic を付けて、もう一度起動する。今度は Ctrl-C では止まらない（第2章で理由を見る）。 止めるときは QEMU のモニタに切り替えて quit と打つ。モニタへの切り替えは、Ctrl を押しながら a、離してから c（以下 Ctrl-a c と書く）。

起動すると、画面が一度消えてから PC の画面になる。No bootable device. が出たら（10 秒ほど）、Ctrl-a c でモニタに切り替え、(qemu) の後に打つ。

太字（info block など）があなたが打つ文字。#net の後ろの数字は起動のたびに変わる。 Configuring (net0 …) の点の数（DHCP の返事を待った時間）も毎回違うので、その前後と一緒に（略）とした。

上から順に読む。電源が入った PC で最初に動くのはファームウェア（BIOS）で、QEMU の既定は SeaBIOS である。

画面の行出したものしていたこと

iPXE (https://ipxe.org) 00:03.0 …NIC（PCI の 00:03.0）に載ったプログラムネットワークから起動するための部品が見つかった

何も指定しなかったのに、この PC にはフロッピーと CD-ROM の装置と NIC が付いていて、NIC の先にはネットワークまであり、DHCP でアドレスを配る誰かがいた。 配ったのは、外のどこかではなく QEMU のプロセス自身である（第5章）。

Ctrl-a c で切り替えた (qemu) は、QEMU のモニタ（QEMU 自身への窓口）で、ここに打つものは仮想の PC にではなく QEMU のプロセスに届く。 中の PC からは、モニタがあることも、そこで何を打たれたかも見えない。 info block は、ディスクをつなげる口の一覧である。CD-ROM（ide1-cd0）とフロッピー（floppy0）の口があり、どちらも [not inserted]（媒体が入っていない）。sd0 は QEMU が既定で用意した SD カード用のドライブだが、Attached to: の行が無い。この PC には、それを受ける装置（SD カードの差し込み口）が無いからである。 装置はあるが中身が空なので、SeaBIOS は「Boot failed」と言った。 info network は、NIC（e1000.0、MAC アドレス 52:54:00:12:34:56）と、その先のネットワーク（type=user、net=10.0.2.0）が、ハブ（hub 0）でつながっていることを示す。 最後の quit は QEMU のプロセスを終わらせる。中の PC から見れば、電源コードを抜かれたのと同じである（第2章）。

たとえ: 何も言わずに頼んだ定食に近い。主菜（ディスク）を選ばなくても、ご飯・味噌汁・漬物（フロッピー・CD-ROM・NIC と、その先のネットワーク）が付いてくる。
ただし崩れる点: 定食の付け合わせは食べなければ済むが、QEMU の既定の部品は中の OS から見え、使われる。 NIC があるから iPXE はネットワークから起動しようとし、DHCP のやりとりまで起きた。断りたいときは -nodefaults で、既定の部品を全部外せる（第7章で、libvirt がそうしているのを見る）。
この章はここまで: quit の後、プロンプト（$）は戻ってくるが、この端末はもう元のとおりではない。 次の第2章は、この端末のまま始める（第2章を別の日に始めるなら、もう一度 qemu-system-x86_64 -nographic を打ち、Ctrl-a x で抜けてから始めると、同じ画面になる）。
手を動かす: 実践編の演習01は、この章の「何も渡さない PC」を、画面をシリアル経由でファイルに書かせ、モニタを UNIX ソケットで受け付ける形で、端末から切り離して動かす課題である。 判定は、あなたの QEMU にモニタ（QMP）で状態を尋ねて確かめる。
確認

qemu-system-x86_64 だけを打ったら VNC server running on ::1:5900 と出て、プロンプトが戻らなかった。このとき QEMU は何をしているか。

答え

既定の部品で PC を1台組み立てて電源を入れ、その画面を VNC で出している（SeaBIOS が起動し、起動できる媒体を探している）。 「ディスクが無いから何もしない」のではなく、ディスクの無い PC として動き続けている。-nographic を付けると、その様子が端末に出る。

確認

iPXE の画面に net0: 10.0.2.15/255.255.255.0 gw 10.0.2.2 と出た。この PC にアドレスを配ったのは誰か。そう言える根拠は何か。

答え

QEMU 自身。モニタの info network で、NIC（e1000）の先が type=user,net=10.0.2.0 のネットワークにつながっていた。 これは QEMU のプロセスの中にあるネットワーク（ユーザモードネットワーク）で、DHCP で 10.0.2.15 を配り、10.0.2.2 をゲートウェイとして演じる（第5章）。外の LAN の DHCP サーバではない。

確認

モニタの info block に floppy0: [not inserted] と出た。この PC にフロッピーの装置はあるか。

答え

ある。floppy0 という口（装置）はあり、媒体が入っていない（not inserted）。 だから SeaBIOS は Booting from Floppy... と試して Boot failed になった。装置ごと無くすには -nodefaults などで外す。

確認

同じ Ubuntu のディスクを、-device ide-hd でつないだときと -device virtio-blk-pci でつないだときとで、中の Linux から見えるディスクの名前はどう違うか。違う理由は何か。

答え

IDE なら /dev/sda、virtio なら /dev/vda（第3章で lsblk を打つと vda が見える）。 中の OS は、つながっている部品の種類を見て、その部品のドライバで扱う。IDE は実在する部品の真似なので昔からのドライバ（sd）が、virtio は仮想マシン用の取り決めなので virtio のドライバ（vd）が受け持つ。ディスクのファイルの中身は同じでも、名前は部品の種類で決まる。

この章で分かったこと

持ち帰ってほしいこと

  • QEMU は、渡されたディスクを動かすのではなく、PC を1台組み立てて電源を入れる。部品を指定しなければ既定の部品で組む
  • 既定の PC（pc-i440fx-noble-v2）には、SeaBIOS・IDE の CD-ROM・フロッピー・NIC（e1000）と、その先のネットワーク（10.0.2.0/24）が付く
  • 何を組むかは -machine（マシン型）・-cpu（CPU の型）・-device（部品）で選び、一覧は help で出る
  • e1000 や IDE は実在する部品の真似、virtio は仮想マシンのための取り決め。中の OS には、それぞれのドライバが要る
  • (qemu) は QEMU 自身への窓口（モニタ）で、中の PC からは見えない。Ctrl-a c で切り替え、quit で QEMU を終わらせる
