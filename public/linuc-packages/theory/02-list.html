2. いま何が入っているかを調べる

前の章までにやったこと: labhello を apt install で入れて、使って、apt remove で消した。この章でやること: いまこの檻にどんなパッケージが入っているかを、一覧と、1つずつの詳しい情報で調べる。そして、その答えがどこから来ているかを確かめる。

前提: 第1章まで読了前提: Debian 系の檻を起動し直した直後所要 15分影響度 B出題範囲 1.04.1（重要度3）出題範囲 1.04.2（重要度1）最終検証 2026-10-21

この章のゴール

  • 入っているパッケージの一覧を dpkg -l と apt list で出し、行頭の ii が何を表すかを確かめる
  • 1つのパッケージの版・分類・依存関係などを、dpkg -s と apt show で調べる
  • 「入っているか」の答えが、いつ書かれ、いつ消えるのかを確かめる
ここで覚えなくていいこと: dpkg -l の行頭に出る ii 以外の記号、dpkg -s の全部の欄、台帳のファイルの中身の形。この章では「一覧で探して、1つを詳しく見る」ができれば足りる。

入っているものの一覧 — dpkg -l

この節で分かること: 入っているパッケージを全部並べる方法と、その行の読み方。

dpkg は、パッケージのファイルを実際に置いたり外したりして、何を入れたかを覚えておく道具である（第1章の apt は、中でこれを呼んでいる）。dpkg -l（list）は、覚えているものを一覧にする。

$ dpkg -l
（打鍵: q）
Desired=Unknown/Install/Remove/Purge/Hold
| Status=Not/Inst/Conf-files/Unpacked/halF-conf/Half-inst/trig-aWait/Trig-pend
|/ Err?=(none)/Reinst-required (Status,Err: uppercase=bad)
||/ Name                        Version                           Architecture >
+++-===========================-=================================-============->
ii  apt                         2.8.3                             amd64        >
ii  apt-file                    3.3                               all          >
ii  apt-utils                   2.8.3                             amd64        >
...

dpkg は、一覧を端末に出すとき、いつも less（長い出力を1画面ずつ見せる道具）に渡す。less は、全部が1画面に収まればそのまま閉じるが、この一覧は行が端末の幅（80 桁）に収まらず、行の数も画面の高さを超えるので、右端を > で切り、画面の一番下で止まる。矢印キーやスペースで先を見られ、q で抜ける（抜けると上の画面がそのまま残る）。

上の5行は見出しで、6行目から1行に1つのパッケージが並ぶ。

欄何を表すか
1文字目（Desired）そのパッケージを「どうしたいか」。i は入れたい（Install）
2文字目（Status）いま「どうなっているか」。i は入っていて使える（Installed）
Nameパッケージの名前
Version入っている版
Architectureどの CPU 向けか（第1章の amd64・all）
Description短い説明

行頭の ii は「入れたい・入っている」で、ふつうに入っているものは全部これになる。見出しの3行は、1文字目・2文字目・3文字目に出うる文字の凡例である（大文字は異常の印）。いくつ入っているかを数える。

$ dpkg -l | grep -c '^ii'
168

grep -c は当てはまった行の数を出す。'^ii' は「行頭が ii」。この檻には、それだけのパッケージが入っている。名前を渡すと、その名前のものだけを出す。* は「何文字でもよい」の印で、シェルに先に解釈させないように ' で囲む。

$ dpkg -l 'lab*'
（打鍵: q）
Desired=Unknown/Install/Remove/Purge/Hold
| Status=Not/Inst/Conf-files/Unpacked/halF-conf/Half-inst/trig-aWait/Trig-pend
|/ Err?=(none)/Reinst-required (Status,Err: uppercase=bad)
||/ Name           Version      Architecture Description
+++-==============-============-============-==================================>
ii  labbackup      1.0          all          practice backup command
ii  labfortune     1.0          all          prints a fortune for the day
ii  labsvc         1.0          all          sample service tool with a config >
ii  labsvc-common  1.0          all          data files for labsvc
ii  labweb         1.0          all          sample web board with a config file
ii  labweb-data    1.0          all          data files for labweb

練習用のパッケージが並んだ。行の数は画面に収まるが、1行が端末の幅を超えるので、less が右端を切って止まった。出力をパイプ（|）でほかのコマンドに渡すと、dpkg は less を使わず、右端も切らない。cat は受け取ったものをそのまま出すだけのコマンドで、ここではパイプの受け手としてだけ使う。

$ dpkg -l 'lab*' | cat
Desired=Unknown/Install/Remove/Purge/Hold
| Status=Not/Inst/Conf-files/Unpacked/halF-conf/Half-inst/trig-aWait/Trig-pend
|/ Err?=(none)/Reinst-required (Status,Err: uppercase=bad)
||/ Name           Version      Architecture Description
+++-==============-============-============-======================================
ii  labbackup      1.0          all          practice backup command
ii  labfortune     1.0          all          prints a fortune for the day
ii  labsvc         1.0          all          sample service tool with a config file
ii  labsvc-common  1.0          all          data files for labsvc
ii  labweb         1.0          all          sample web board with a config file
ii  labweb-data    1.0          all          data files for labweb

第1章で入れて消した labhello は、起動し直したこの檻にも入っていないので、並んでいない。名前を指定して聞くと、こう答える（dpkg-query は dpkg の中で問い合わせを受け持つ部分の名前）。

$ dpkg -l labhello
dpkg-query: no packages found matching labhello
たとえ: 家の持ち物リストに近い。物を買うたびに1行書き足し、捨てるたびに線を引いて消す。「家に何があるか」を聞かれたら、家じゅうを見て回らずに、このリストを読み上げる。
ただし崩れる点: 家のリストに載るのは自分で買った物だけだが、この一覧には、あなたが入れていないもの（檻を作ったときから入っていたもの）も全部並ぶ。

apt で一覧を出す — apt list

この節で分かること: apt list の出力の読み方。

apt にも一覧を出すサブコマンド list がある。

ふつうこう考える

apt list labhello と打って名前が出てくれば、labhello は入っているはずだ。

$ apt list labhello
Listing... Done
labhello/lab 1.0 all
$ labhello
bash: labhello: command not found
だめな理由: 名前は出たのに、labhello は入っていない。 apt list は、入っているものだけでなく、入れられるもの（リポジトリにあるもの）も全部並べる。 第1章で apt が名前だけで labhello を見つけられたのは、入れられるパッケージの一覧を持っているからで、apt list はその一覧から探している。 入っているかどうかは、行末の印で見分ける。入っていれば [installed] が付く。上の行には付いていない。

入っているものだけを出すのが --installed である。

$ apt list --installed 'lab*'
Listing... Done
labbackup/lab,now 1.0 all [installed]
labfortune/lab,now 1.0 all [installed]
labsvc-common/lab,now 1.0 all [installed,automatic]
labsvc/lab,now 1.0 all [installed]
labweb-data/lab,now 1.0 all [installed,automatic]
labweb/lab,now 1.0 all [installed]

1行目の Listing... Done は「一覧を作り終えた」という知らせで、2行目からがパッケージである。labsvc/lab,now 1.0 all [installed] は、名前 labsvc・どこから来た版か（lab はリポジトリの中の区分の名前で、第1章の Get: の行にも lab/main と出ていた）・いま入っている（now）・版 1.0・アーキテクチャ all・印 [installed] と読む。

labsvc-common と labweb-data には、automatic も付いている。これは「利用者が名前を指定したのではなく、ほかのパッケージに必要なので一緒に入った」という印である（labsvc-common は labsvc と、labweb-data は labweb と一緒に入った）。

たとえ: 店のカタログのうち、もう持っている品物に「購入済み」の印が付いているものに近い。カタログには持っていない品物も載っているので、載っていることと持っていることは別である。
ただし崩れる点: 店のカタログは1冊だが、apt はリポジトリの区分ごとに一覧を持っていて、それをまとめて1つに見せている。apt list の / の後ろ（lab）が、どの一覧から来た行かの印である。

1つを詳しく調べる — dpkg -s と apt show

この節で分かること: 1つのパッケージについて、版・分類・依存関係などを調べる方法。

dpkg -s（status）に名前を渡すと、そのパッケージについて覚えていることを全部出す。

$ dpkg -s labsvc
Package: labsvc
Status: install ok installed
Priority: optional
Section: admin
Installed-Size: 40
Maintainer: check-then-explain <lab@example.invalid>
Architecture: all
Version: 1.0
Depends: labsvc-common (>= 1.0)
Conffiles:
 /etc/labsvc.conf b80eac61a4576d1a58b32b4df52a77dd
Description: sample service tool with a config file
 Used to practice remove, purge and autoremove.

欄は「名前: 値」の形で並ぶ。主な欄の意味と、何のためにあるかはこうである。

欄値の意味何のためにあるか
Statusinstall ok installed ＝ 入れたい・問題なし・入っているいま入っているかを確かめる
Priorityoptional ＝ 無くてもシステムは動くシステムに欠かせないもの（required など）と見分ける
Sectionadmin ＝ 管理用の道具の分類パッケージを種類で分ける（utils 便利な道具・games 遊び・libs ほかから使われる部品 など）
Installed-Size入れたときに使うディスクの量（KiB。1 KiB は 1024 バイト）入れる前に、どれだけ場所を取るかを知る
Maintainerパッケージを作って面倒を見ている人不具合を誰に知らせるかを知る
Version入っている版新しい版があるか・どの版の説明書を読むかを決める
Dependslabsvc-common (>= 1.0) ＝ labsvc-common の 1.0 以上が要るこのパッケージが動くのに、先に入っていなければならない別のパッケージ（依存関係）を示す
Conffiles/etc/labsvc.conf と、その中身の要約利用者が書き換える設定ファイルに印を付ける（消すときの扱いが、ほかのファイルと変わる）
Description1行目が短い説明、2行目から長い説明何をするパッケージかを知る

apt にも、1つを詳しく見る show がある。

$ apt show labsvc
Package: labsvc
Version: 1.0
Priority: optional
Section: admin
Maintainer: check-then-explain <lab@example.invalid>
Installed-Size: 41.0 kB
Depends: labsvc-common (>= 1.0)
Download-Size: 932 B
APT-Manual-Installed: yes
APT-Sources: file:/srv/lab-repo lab/main amd64 Packages
Description: sample service tool with a config file
 Used to practice remove, purge and autoremove.

ほとんど同じだが、dpkg に無い欄が3つある。Download-Size は取ってくるパッケージのファイルの大きさ、APT-Manual-Installed: yes は「利用者が名前を指定して入れた」（automatic の反対）、APT-Sources は「どのリポジトリから入ったか」である。Installed-Size が 41.0 kB と、dpkg の 40（KiB）と違うのは、単位を 1000 バイトの kB に直して見せているからである。

入っていないパッケージに聞くと、2つの答え方が分かれる。

$ dpkg -s labhello
dpkg-query: package 'labhello' is not installed and no information is available
Use dpkg --info (= dpkg-deb --info) to examine archive files.
$ apt show labhello
Package: labhello
Version: 1.0
Priority: optional
Section: utils
Maintainer: check-then-explain <lab@example.invalid>
Installed-Size: 77.8 kB
Download-Size: 1120 B
APT-Sources: file:/srv/lab-repo lab/main amd64 Packages
Description: prints its own version
 A tiny package used to practice upgrades.

dpkg -s は「入っていないので、情報が無い」と答えた（2行目は「.deb ファイルを調べるなら --info を使え」という案内）。.deb ファイルは、第1章で apt が取ってきた labhello_1.0_all.deb のような、パッケージのファイルである。apt show は、入っていない labhello についても答えた。前の節の apt list と同じく、入れられるパッケージの一覧を持っているからである。APT-Manual-Installed の欄が無いのは、入っていないからである。

たとえ: 家電の裏に貼ってある銘板に近い。型番・製造元・必要な電源（ここでは依存関係）が書いてあり、本体を分解しなくても読める。
ただし崩れる点: 銘板は品物が手元にあれば読めるが、dpkg -s が答えるのは、dpkg -l の一覧に行のあるパッケージだけである。一度も入れたことのない labhello には「情報が無い」と答えた。

答えはどこから来るか

この節で分かること: dpkg -l や dpkg -s の答えが、いつ書かれ、いつ消えるか。

dpkg -l も dpkg -s も apt list --installed も、ディスクを探し回って答えているのではない。パッケージを入れたときに dpkg が書いておいた記録を読んでいる。この記録を、この教材では台帳と呼ぶ。入れると台帳に行が増え、消すと減ることを確かめる。

$ sudo apt install labhello
...
Setting up labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...
$ dpkg -l labhello | tail -1
ii  labhello       1.0          all          prints its own version
$ sudo apt remove labhello
...
Do you want to continue? [Y/n] y
...
Removing labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...
$ dpkg -l labhello
dpkg-query: no packages found matching labhello

| tail -1 は最後の1行だけを見るため（パイプに渡すので less も開かない）。入れたら台帳に ii の行ができ、消したら行ごと無くなって「見つからない」に戻った。台帳は /var/lib/dpkg/ の下にあるファイルで、書き換えるのは dpkg だけである。

知りたいことコマンド入っていないパッケージには
入っているものの一覧dpkg -l（名前で絞るなら dpkg -l '名前'）・apt list --installed—
入れられるものも含めた一覧apt list 名前（入っていれば [installed]）答える
1つの詳しい情報dpkg -s 名前・apt show 名前dpkg -s は答えない。apt show は答える
手を動かす: 実践編の演習02は、入っているパッケージを並べ、1つずつ分類（Section）を確かめて、仕事に要らない遊びのパッケージだけを消す課題である。 判定は dpkg の台帳を見て、分類が games のものが無くなり、ほかが入ったままかを確かめる。
確認

dpkg -l の行頭が ii のパッケージは、どういう状態か。

答え

1文字目の i が「入れたい（Install）」、2文字目の i が「入っていて使える（Installed）」。ふつうに入っているパッケージは全部これになる。

確認

apt list labhello と打つと labhello/lab 1.0 all と出た。labhello は入っているか。確かめるにはどうするか。

答え

入っているとは限らない（実測では入っていなかった）。apt list は入れられるものも並べ、入っているものにだけ [installed] を付ける。 入っているものだけを出すなら apt list --installed、または dpkg -l labhello で台帳に ii の行があるかを見る。

確認

パッケージ foo が動くのに、先に入っていなければならない別のパッケージを調べたい。入っている foo について、dpkg -s foo のどの欄を見ればよいか。

答え

Depends の欄（依存関係）。labsvc では Depends: labsvc-common (>= 1.0) と出て、labsvc-common の 1.0 以上が要ると分かった。apt show foo にも同じ欄が出る。

この章で分かったこと

持ち帰ってほしいこと

  • 入っているものの一覧は dpkg -l（行頭 ii が入っているもの）と apt list --installed。apt list だけだと入れられるものも並ぶ
  • 1つを詳しく見るのは dpkg -s と apt show。Version（版）・Section（分類）・Depends（依存関係）が読める。入っていないものに答えられるのは apt show だけ
  • これらの答えは、入れたときに dpkg が書く記録（台帳）から来ている。入れると行が書かれ、消すと消える
  • dpkg -l は 80 桁の端末では less で開く（q で抜ける）。パイプに渡すと開かない
