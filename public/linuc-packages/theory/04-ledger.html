4. 台帳とファイルを見比べる

前の章までにやったこと: パッケージを入れて・使って・消し（第1章）、入っているものを調べ（第2章）、置かれたファイルとパッケージを dpkg -L・dpkg -S で両方向に引いた（第3章）。どの答えも、入れたときに dpkg が書く台帳から来ていた。この章でやること: 台帳の実物のファイルを開く。そして、パッケージ管理を通さずにファイルだけを消したり置いたりして、台帳とファイルを見比べる。

前提: 第3章まで読了前提: Debian 系の檻を起動し直した直後所要 18分影響度 B出題範囲 1.04.2（重要度1）最終検証 2026-10-21

この章のゴール

  • 台帳が /var/lib/dpkg/ の下のどのファイルで、dpkg -s・dpkg -L がどれを読んでいるかを確かめる
  • パッケージ管理を通さずにファイルだけを消すと、台帳がどう答えるかを確かめ、dpkg -V で台帳とファイルを照らし合わせる
  • 台帳どおりに戻す方法（apt reinstall）を確かめる
  • 中身だけを置くと（dpkg-deb -x）、台帳がどう答えるかを確かめる
ここで覚えなくていいこと: /var/lib/dpkg/ のほかのファイル（available・triggers など）、台帳を手で書き換える方法（書き換えてはいけない）、ファイルの中身から計算する値（ダイジェスト）の計算のしくみ、dpkg -V が行の頭に並べる記号のうち 5 以外の意味。この章では、台帳とファイルを見比べることが1回できれば足りる。

台帳の実物

この節で分かること: 台帳がどのファイルで、何が書いてあるか。

第2章で、台帳は /var/lib/dpkg/ の下にあるファイルだと書いた。中を見る。

$ ls /var/lib/dpkg/
alternatives  diversions      lock           status      updates
available     diversions-old  lock-frontend  status-old
cmethopt      info            parts          triggers

使うのは status と info の2つである。labhello を入れてから、labhello について何が書かれたかを見る（入れる出力は略す）。

$ sudo apt install labhello
...
Setting up labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...
$ grep -A9 '^Package: labhello$' /var/lib/dpkg/status
Package: labhello
Status: install ok installed
Priority: optional
Section: utils
Installed-Size: 76
Maintainer: check-then-explain <lab@example.invalid>
Architecture: all
Version: 1.0
Description: prints its own version
 A tiny package used to practice upgrades.

grep -A9 は、当たった行と、その後ろ9行を出す。/var/lib/dpkg/status は、入っているパッケージごとに、この形の段落が並ぶテキストのファイルである。第2章で dpkg -s labsvc が出したのも、この中の labsvc の段落である（dpkg -s は、この段落をそのまま出す）。

$ cat /var/lib/dpkg/info/labhello.list
/.
/usr
/usr/bin
/usr/bin/labhello
/usr/share
/usr/share/doc
/usr/share/doc/labhello
/usr/share/doc/labhello/README
/usr/share/man
/usr/share/man/man1
/usr/share/man/man1/labhello.1.gz
$ cat /var/lib/dpkg/info/labhello.md5sums
6be84e0d8606ca3736aa91842490e59b  usr/bin/labhello
8e9bcd880a99bacdc323fd47fd5d93ec  usr/share/doc/labhello/README
b05396f6cf7828a35df2ccec28d866ec  usr/share/man/man1/labhello.1.gz

info/labhello.list は、第3章で dpkg -L labhello が出したのと同じ一覧である。dpkg -L はこのファイルを読み、dpkg -S は全部のパッケージの .list から探している。

info/labhello.md5sums には、ファイルごとに32桁の値が書いてある。これは、入れたときのファイルの中身から計算したダイジェスト（中身の要約。中身が1文字でも違えば、まったく別の値になる短い値）である。md5sum コマンドで、いまのファイルのダイジェストを計算して比べる。

$ md5sum /usr/bin/labhello
6be84e0d8606ca3736aa91842490e59b  /usr/bin/labhello

同じ値になった。いまの /usr/bin/labhello は、入れたときと中身が同じである。

台帳のファイル書いてあること何のためにあるか読むコマンド
/var/lib/dpkg/statusパッケージごとの状態・版・依存関係など何が・どの版で・どんな状態で入っているかを答えるdpkg -l・dpkg -s
/var/lib/dpkg/info/名前.listそのパッケージが置いたファイルの一覧ファイルとパッケージを両方向に引くdpkg -L・dpkg -S
/var/lib/dpkg/info/名前.md5sums置いたときのファイルの中身のダイジェストいまのファイルが入れたときのままかを確かめるdpkg -V（次の節）
たとえ: ダイジェストは書類の指紋に近い。書類そのものを並べて読み比べなくても、指紋が同じなら同じ書類だと見なせる。
ただし崩れる点: 人の指紋は誰のものかを示すが、ダイジェストは「中身が同じか」しか示さない。誰が作ったファイルかは、ダイジェストからは分からない。

ファイルだけを消すと

この節で分かること: パッケージ管理を通さずにファイルを消したとき、台帳がどう答えるか。

ふつうこう考える

パッケージは、結局はファイルである。要らなくなったら、ファイルを消してしまえば「入っていない」ことになるはずだ。

$ sudo rm /usr/bin/labhello
$ labhello
bash: labhello: command not found
$ dpkg -l labhello | tail -1
ii  labhello       1.0          all          prints its own version
$ dpkg -L labhello
/.
/usr
/usr/bin
/usr/bin/labhello
/usr/share
/usr/share/doc
/usr/share/doc/labhello
/usr/share/doc/labhello/README
/usr/share/man
/usr/share/man/man1
/usr/share/man/man1/labhello.1.gz
だめな理由: コマンドは無くなったが、台帳は ii（入っていて使える）のままで、dpkg -L も /usr/bin/labhello を並べ続けた。 rm はファイルを消しただけで、台帳（/var/lib/dpkg/）には触れていない。台帳を書き換えるのは dpkg だけで、dpkg は答えるとき台帳しか読まない。 だから、ファイルと台帳が食い違ったまま、台帳のほうの答えが返ってくる。消すなら apt remove で、ファイルと台帳を一緒に変える。
たとえ: 引っ越しと住民票に近い。荷物を運び出しても、転出届を出さなければ、役所の台帳ではまだそこに住んでいることになっている。rm は届けを出さない引っ越しで、apt remove は届けを出す引っ越しである。
ただし崩れる点: 住民票は本人が窓口へ行って直すが、dpkg の台帳を書き換えるのは dpkg だけである（apt も、中で dpkg を呼んで書かせている）。台帳を直すにも、パッケージを入れる・消す操作を通す。

台帳と照らし合わせる — dpkg -V

この節で分かること: 台帳とファイルの食い違いを見つける方法と、台帳どおりに戻す方法。

dpkg -V（verify）は、台帳に書いてあるファイルの一覧とダイジェストを、いまのディスクと照らし合わせる。

$ dpkg -V labhello
missing     /usr/bin/labhello
$ echo $?
0

missing は「台帳には載っているのに、ファイルが無い」という意味である。違いのあるファイルだけが1行ずつ出て、全部台帳どおりなら何も出ない。echo $? は直前のコマンドの終了コード（うまくいったかを表す数。0 が成功）を出す。違いが見つかっても、終了コードは 0 だった。違いがあるかは、出力が空かどうかで見る。

台帳どおりに戻すには、同じ版を入れ直す。apt reinstall である。

$ sudo apt reinstall labhello
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
0 upgraded, 0 newly installed, 1 reinstalled, 0 to remove and 0 not upgraded.
Need to get 0 B/1120 B of archives.
After this operation, 0 B of additional disk space will be used.
Get:1 file:/srv/lab-repo lab/main amd64 labhello all 1.0 [1120 B]
(Reading database ... 12837 files and directories currently installed.)
Preparing to unpack .../labhello/labhello_1.0_all.deb ...
Unpacking labhello (1.0) over (1.0) ...
Setting up labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...
$ dpkg -V labhello
$ labhello
labhello 1.0

1 reinstalled（入れ直し 1）、Unpacking labhello (1.0) over (1.0)（1.0 の上に 1.0 を置いた）と出て、ファイルが戻った。dpkg -V は何も出さなくなり、labhello も動いた。

ファイルが無いのではなく、中身が書き換わった場合も見つける。tee -a はファイルの末尾に書き足す（sudo を付けて root として書くため、echo … | sudo tee の形にする）。

$ echo '# 書き足した' | sudo tee -a /usr/bin/labhello
# 書き足した
$ dpkg -V labhello
??5??????   /usr/bin/labhello

左の9文字は、台帳と比べた項目の結果を並べたものである。3文字目の 5 が「ダイジェスト（MD5）が違う」で、? は「確かめていない」である。dpkg の台帳にはダイジェストしか書いていないので、ほかの項目は確かめようがない。

たとえ: 納品書の控えと、倉庫の現物を突き合わせる棚卸しに近い。控え（.md5sums）に書いてある要約と、いまの現物の要約が違うものだけを報告する。
ただし崩れる点: 棚卸しなら数も色も傷も見るが、dpkg の控えには中身の要約しか無い。ファイルの権限や持ち主が変わっても、中身が同じで読めるなら、dpkg -V は何も言わない。権限を変えたせいで一般ユーザが読めなくなったときだけ、要約を作れないので、9文字が全部 ? の行を出す（終了コードは 0 のまま）。

中身だけを置くと

この節で分かること: ファイルがあることと、パッケージが入っていることの違い。

逆の向きも確かめる。第3章の apt download で liblab の .deb ファイルを取ってきて、dpkg-deb -x で中身を / に広げる。dpkg-deb は .deb ファイルを扱う道具で、-x（extract）は中身のファイルの木だけを、指定した場所に取り出す。

$ apt download liblab
Get:1 file:/srv/lab-repo lab/main amd64 liblab all 1.0 [746 B]
$ sudo dpkg-deb -x liblab_1.0_all.deb /
$ ls -l /usr/lib/liblab/liblab.sh
-rw-r--r-- 1 root root 106 Oct  1 09:00 /usr/lib/liblab/liblab.sh
$ dpkg -S /usr/lib/liblab/liblab.sh
dpkg-query: no path found matching pattern /usr/lib/liblab/liblab.sh
$ dpkg -l liblab
dpkg-query: no packages found matching liblab

ファイルは置かれたのに、dpkg -S は「そのパスを持つパッケージは無い」、dpkg -l は「そんなパッケージは無い」と答えた。dpkg-deb -x は箱を開けて中身を並べただけで、台帳には1行も書いていない。apt で入れ直すと、台帳に載る。

$ sudo apt install liblab
...
The following NEW packages will be installed:
  liblab
...
Unpacking liblab (1.0) ...
Setting up liblab (1.0) ...
$ dpkg -S /usr/lib/liblab/liblab.sh
liblab: /usr/lib/liblab/liblab.sh

置かれているファイルは同じなのに、答えが変わった。変わったのは台帳のほうである。この章で見たことをまとめる。

apt install / apt remove   … ファイルを置く・外す ＋ 台帳を書く（いつも両方）
rm                          … ファイルだけを消す（台帳は「入っている」のまま）
dpkg-deb -x                 … ファイルだけを置く（台帳には書かない）
dpkg -l / -s / -L / -S      … 台帳だけを読む
dpkg -V                     … 台帳とファイルを見比べる（違うものだけを出す）

パッケージが「入っている」とは、ファイルがそこにあることではなく、台帳に書かれていることである。ファイルと台帳は別々にあるので、片方だけを変えると食い違う。食い違いを見つけるのが dpkg -V、台帳どおりに戻すのが apt reinstall である。

手を動かす: 実践編の演習04は、コマンドが見つからないのに台帳は「入っている」と言っている labbackup を、台帳と照らし合わせて、パッケージから入れたときの状態に戻す課題である。 判定は labbackup を実際に動かし、dpkg -V labbackup が何も出さないかを見る。
確認

入っているパッケージ foo のファイル /usr/bin/foo を sudo rm で消した。このあと dpkg -l foo はどう答えるか。そうなる理由は何か。

答え

行頭 ii（入っていて使える）のまま答える（実測では labhello がそうだった）。dpkg -l が読むのは台帳（/var/lib/dpkg/status）で、rm は台帳を書き換えないから。 食い違いは dpkg -V foo で missing として見つかる。

確認

dpkg -V foo の出力に ??5?????? /usr/bin/foo とあった。何を意味するか。終了コードで違いの有無を判断できるか。

答え

/usr/bin/foo の中身のダイジェストが、入れたときと違う（中身が書き換わっている）。? は確かめていない項目。 終了コードは違いがあっても 0 なので、判断できない（実測）。出力が空かどうかで見る。台帳どおりに戻すなら sudo apt reinstall foo。

確認

パッケージ bar の .deb ファイルを sudo dpkg-deb -x bar_1.0_all.deb / で展開した。このあと dpkg -S に bar のファイルのパスを渡すと、何が返るか。

答え

「そのパスを持つパッケージは無い」（dpkg-query: no path found matching pattern …）。dpkg-deb -x は中身を置くだけで、dpkg -S が読む台帳（info/*.list）には何も書かないから（実測）。

この章で分かったこと

持ち帰ってほしいこと

  • 台帳は /var/lib/dpkg/ の status（状態・版・依存関係）と info/名前.list（置いたファイル）・info/名前.md5sums（ダイジェスト）。dpkg -s・-l・-L・-S はこれを読む
  • ファイルと台帳は別々にある。rm でファイルを消しても台帳は ii のまま、dpkg-deb -x で置いても台帳には載らない
  • dpkg -V は台帳とファイルを見比べ、違うものだけを出す（missing は無い、5 は中身が違う）。違いがあっても終了コードは 0
  • 台帳どおりに戻すのは sudo apt reinstall 名前
