2. apt は目録を読んで、台帳に書く

apt install は名前を1つ渡すだけで、必要なものまで全部入れる。ところが apt remove で消したはずのパッケージは、台帳に rc という印を付けて残り、設定ファイルも、一緒に入ってきたものも消えない。apt の「消す」には段階がある。

前提: 第1章まで読了前提: Debian 系の檻を起動し直した直後所要 20分影響度 B出題範囲 1.04.1（重要度3）最終検証 2026-10-13

この章のゴール

  • apt-cache の search / show / depends / rdepends / showpkg / policy を、目録を読むコマンドとして使い分けられる
  • apt install が依存関係をたどって何を入れたかを、出力と apt-mark で説明できる
  • remove / purge / autoremove の違いを、台帳の状態（ii / rc）と設定ファイルの有無で言える
  • apt と apt-get と apt-cache の関係を言える
ここで覚えなくていいこと: 優先度の書き換え（/etc/apt/preferences.d/ の pinning）、apt-mark hold、aptitude、full-upgrade が何を消すかの細かい判断。apt-cache policy に出る 500 や 100 という数字は、この章では「どの帳簿から来た版か」の印として読めれば足りる。

目録を読む — apt-cache

この節で分かること: 入れる前に、目録から何を引き出せるか。

第1章で見た目録（/var/lib/apt/lists/）を読むのが apt-cache である。名前と説明文から探す。

$ apt-cache search liblab
labapp - sample application that needs liblab
liblab - small shell library for lab programs
liblab-gamut1 - rich set of graph drawing tools - liblab_gamut library
liblablgl-ocaml - Runtime libraries for lablgl
liblablgl-ocaml-dev - OpenGL interface for Objective Caml
...
liblabltk-ocaml-dev - OCaml bindings to Tcl/Tk (dev. libraries)

14件出た。上の2つは檻の中の練習用パッケージで、残りは本物の Ubuntu のパッケージである。search は名前と説明文の部分一致なので、liblablgl-ocaml も liblab を含むとして引っかかる。そして、この檻の目録には Ubuntu の目録の写しも入っているので、まだ入れていない本物のパッケージまで出てくる。

1つに絞って詳しく見る。

$ apt-cache show labapp
Package: labapp
Architecture: all
Version: 1.0
Priority: optional
Section: utils
Maintainer: check-then-explain <lab@example.invalid>
Installed-Size: 68
Depends: liblab (>= 1.0)
Filename: pool/main/l/labapp/labapp_1.0_all.deb
Size: 1076
...
Description: sample application that needs liblab
 Prints a greeting. The greeting is read from /etc/labapp.conf.
$ apt-cache depends labapp
labapp
  Depends: liblab
$ apt-cache rdepends liblab
liblab
Reverse Depends:
  labapp

depends は「これが必要とするもの」、rdepends（reverse depends）は「これを必要としているもの」である。どちらも目録に書かれたパッケージどうしの関係を、前から読むか後ろから読むかの違いである。練習用のパッケージには Depends: しか書いていないので1行だけだが、本物のパッケージでは関係の種類がもっと出る。

$ apt-cache depends apt
apt
 |Depends: base-passwd
  Depends: adduser
...
  Conflicts: <apt-verify>
...
  Breaks: apt-transport-https
...
  Recommends: ca-certificates
  Suggests: apt-doc
...
  Replaces: apt-transport-https
  Replaces: apt-utils
関係意味
Depends:無いと動かない（apt が必ず一緒に入れる）。行頭の | は「次の行とどちらか一方でよい」
Recommends:ふつうは一緒に入れる（apt は既定で入れる。--no-install-recommends で外せる）
Suggests:あると便利（apt は既定では入れない）
Conflicts: / Breaks:一緒には入れられない（入れるなら片方を消す）
Replaces:相手のファイルを上書きしてよい（置き換える）

依存を出すサブコマンドはもう1つある。showpkg は、目録にある版・逆向きの依存・版ごとの依存を、1つの出力にまとめて出す（別の檻で記録した）。

$ apt-cache showpkg labapp
Package: labapp
Versions:
1.0 (/var/lib/apt/lists/_srv_lab-repo_dists_lab_main_binary-amd64_Packages.lz4)
...
Reverse Depends:
Dependencies:
1.0 - liblab (2 1.0)
Provides:
1.0 -
Reverse Provides:
$ apt-cache showpkg liblab
Package: liblab
...
Reverse Depends:
  labapp,liblab 1.0
Dependencies:
1.0 -
...

Dependencies: は depends と同じ向き（labapp は liblab を必要とする）、Reverse Depends: は rdepends と同じ向き（liblab は labapp に必要とされている）である。liblab (2 1.0) の括弧の中は版の条件を番号で書いたもので、上の show の Depends: liblab (>= 1.0) にあたる（2 が >=）。man にも「並べたパッケージの版と逆向きの依存を出し、版ごとの依存も出す」とある。依存しているパッケージを出せるのは depends と showpkg で、rdepends は逆向き（これに依存しているもの）を出す。

いちばん情報が多いのは policy である。檻には labhello の 1.0 が最初から入っている。

$ apt-cache policy labhello
labhello:
  Installed: 1.0
  Candidate: 1.1
  Version table:
     1.1 500
        500 file:/srv/lab-repo lab/main amd64 Packages
 *** 1.0 500
        500 file:/srv/lab-repo lab/main amd64 Packages
        100 /var/lib/dpkg/status

ここに2冊の帳簿が両方出ている。500 file:/srv/lab-repo … は目録に載っている版で、100 /var/lib/dpkg/status は台帳に載っている版（第1章で読んだファイル）である。*** が付いた版がいま入っている版、Candidate は「入れるならこれ」で、目録のいちばん新しい版になる。

本物のパッケージでも同じ形で出る。

$ apt-cache policy tree
tree:
  Installed: 2.1.1-2ubuntu3.24.04.2
  Candidate: 2.1.1-2ubuntu3.24.04.2
  Version table:
 *** 2.1.1-2ubuntu3.24.04.2 500
        500 https://snapshot.ubuntu.com/ubuntu/20260929T000000Z noble-updates/universe amd64 Packages
        100 /var/lib/dpkg/status
     2.1.1-2ubuntu3 500
        500 https://snapshot.ubuntu.com/ubuntu/20260929T000000Z noble/universe amd64 Packages

tree は Ubuntu 24.04 の発売時の版（noble）と、その後の修正版（noble-updates）の2つが目録にあり、新しいほうが入っている。

この節で使った apt-cache のサブコマンドをまとめる。どれも帳簿を読むだけで、何も入れない。

サブコマンド答えること
search 語名前と説明文に語を含むパッケージ
show 名前目録の記載そのまま（Depends: もここに出る）
depends 名前これが必要とするもの（依存）
rdepends 名前これを必要としているもの（逆向きの依存）
showpkg 名前目録にある版・逆向きの依存・版ごとの依存をまとめて
policy 名前目録の版と台帳の版、入れるならどの版か（Candidate）
たとえ: 通販のカタログで商品を調べる作業に近い。 品番・値段・「別売りの部品が要る」は、注文する前にカタログで分かる。apt-cache はカタログを引くだけで、何も注文しない。
ただし崩れる点: 通販カタログは「自分が何を持っているか」を知らないが、 apt-cache policy は手元の台帳（/var/lib/dpkg/status）も一緒に読んで、持っている版に印を付けてくる。

頼んだのは labapp だけだが、目録の Depends: liblab (>= 1.0) を読んで liblab も足した（additional packages）。そして liblab を先に設定している。-y は「よろしいですか（Do you want to continue? [Y/n]）」に自動で yes と答えるオプションで、付けなければここで1回止まって尋ねられる。

画面で打つと、最初に Reading package lists... Done の3行と進み具合の表示が出る。本文の記録はパイプで取ったので、その部分を「...」で略している。

apt は、どちらを利用者が名指ししたかも覚えている。

$ apt-mark showauto | grep lab
labsvc-common
liblab
$ apt-mark showmanual | grep lab
labapp
labhello
labsvc

liblab には「自動で入った（auto）」の印が付いた。labsvc-common は、檻を作ったときに labsvc の依存として入ったものである。この印は dpkg の台帳ではなく、apt が別に持っている帳簿（/var/lib/apt/extended_states）に書かれる。次の節でこの印が効いてくる。

消す — 3段ある

この節で分かること: remove / purge / autoremove が、それぞれ何を残すか。

ふつうこう考える

apt remove で消せば、パッケージは跡形なく消える。 設定ファイルも、一緒に入ってきた liblab も、まとめて片付くはずだ。

$ sudo apt remove -y labapp
...
The following package was automatically installed and is no longer required:
  liblab
Use 'sudo apt autoremove' to remove it.
The following packages will be REMOVED:
  labapp
0 upgraded, 0 newly installed, 1 to remove and 3 not upgraded.
After this operation, 69.6 kB disk space will be freed.
Removing labapp (1.0) ...
$ dpkg -l labapp
Desired=Unknown/Install/Remove/Purge/Hold
| Status=Not/Inst/Conf-files/Unpacked/halF-conf/Half-inst/trig-aWait/Trig-pend
|/ Err?=(none)/Reinst-required (Status,Err: uppercase=bad)
||/ Name           Version      Architecture Description
+++-==============-============-============-====================================
rc  labapp         1.0          all          sample application that needs liblab
$ ls -l /etc/labapp.conf
-rw-r--r-- 1 root root 93 Oct  1 09:00 /etc/labapp.conf
$ dpkg -s labapp | head -2
Package: labapp
Status: deinstall ok config-files
だめな理由: 3つ残っている。台帳の labapp の行（rc）、 設定ファイル /etc/labapp.conf、そして liblab である。 rc の1文字目 r は「消したい（Remove）」、2文字目 c は 「設定ファイルだけ残っている（Conf-files）」。dpkg -s の deinstall ok config-files も同じ意味である。 /etc/labapp.conf はパッケージの中で conffile（利用者が書き換える設定ファイル）として印が付いているので、 remove は中身だけ消して、設定を残す。入れ直したときに、書き換えた設定が戻ってくるようにするためだ。 liblab については、apt 自身が「もう要らないので apt autoremove で消せる」と出力の中で教えている。

残ったものを順に消す。設定ファイルごと消すのが purge である。

$ sudo apt purge -y labapp
...
The following packages will be REMOVED:
  labapp*
0 upgraded, 0 newly installed, 1 to remove and 3 not upgraded.
After this operation, 0 B of additional disk space will be used.
Purging configuration files for labapp (1.0) ...
$ dpkg -l labapp; echo "exit=$?"
dpkg-query: no packages found matching labapp
exit=1
$ ls -l /etc/labapp.conf; echo "exit=$?"
ls: cannot access '/etc/labapp.conf': No such file or directory
exit=2

labapp* の * が「設定ファイルも消す」印である。台帳の行も消えた。次に、自動で入って、もう誰にも必要とされていないものを消す。

$ dpkg -l liblab
...
ii  liblab         1.0          all          small shell library for lab programs
$ sudo apt autoremove -y
...
The following packages will be REMOVED:
  liblab
0 upgraded, 0 newly installed, 1 to remove and 3 not upgraded.
After this operation, 36.9 kB disk space will be freed.
Removing liblab (1.0) ...
$ dpkg -l liblab; echo "exit=$?"
dpkg-query: no packages found matching liblab
exit=1

名前を渡さない autoremove は、「auto の印があり、もう誰も依存していないもの」を apt が自分で探して消す。前の節の apt-mark showauto の印がここで使われた。liblab には設定ファイル（conffile）が無いので、rc も残さず台帳から行ごと消えている（no packages found）。remove が rc を残すのは、conffile を持つパッケージだけである。

autoremove には名前を渡すこともできる。渡したパッケージを remove し、それで要らなくなった自動の依存も一緒に消す。檻を起動し直して labapp をもう一度 sudo apt install -y labapp で入れてから打った記録である。

$ sudo apt autoremove -y labapp
...
The following packages will be REMOVED:
  labapp liblab
0 upgraded, 0 newly installed, 2 to remove and 3 not upgraded.
After this operation, 106 kB disk space will be freed.
Removing labapp (1.0) ...
Removing liblab (1.0) ...
$ dpkg -l labapp
...
rc  labapp         1.0          all          sample application that needs liblab
$ ls -l /etc/labapp.conf
-rw-r--r-- 1 root root 93 Oct  1 09:00 /etc/labapp.conf

labapp も liblab も消えたが、labapp は remove と同じ消し方なので、設定ファイルが残って rc になった。設定ファイルまで消したいなら purge を使う。

コマンド中身設定ファイル（conffile）台帳の行自動で入った依存
apt remove 名前消える残るrc で残る（conffile が無ければ行ごと消える）残る
apt purge 名前（= apt remove --purge）消える消える消える残る
apt autoremoveauto の印があって、誰も依存していないものを消す
apt autoremove 名前その名前を remove し（設定ファイルは残って rc）、それで要らなくなった自動の依存も消す
apt purge --autoremove 名前purge と autoremove を1回で

すでに rc になったものにも purge は効く。apt-get でも同じ名前のサブコマンドがある（apt-get remove / purge / autoremove）。

たとえ: 賃貸の部屋を引き払うときに近い。remove は家具を運び出すだけで、 自分で替えたカーテンと、管理会社の名簿の名前は残る。purge はカーテンも外して名簿からも消す。 autoremove は、引っ越しのときに一緒に借りたトランクルームを、使う人がいなくなったので返す作業である。
ただし崩れる点: 実際の退去は原状回復が決まりだが、apt は残すのが既定である。 設定を消すには、利用者が purge と言わなければならない。

更新する — 目録の版と、台帳の版を比べる

この節で分かること: 「更新できる」が何と何の比較で決まっているか。
$ apt list --upgradable

WARNING: apt does not have a stable CLI interface. Use with caution in scripts.

Listing...
labhello/lab 1.1 all [upgradable from: 1.0]
libaudit-common/noble-updates 1:3.1.2-2.1ubuntu0.1 all [upgradable from: 1:3.1.2-2.1build1.1]
libaudit1/noble-updates 1:3.1.2-2.1ubuntu0.1 amd64 [upgradable from: 1:3.1.2-2.1build1.1]

3つ出た。どれも「目録の版（1.1）」と「台帳の版（upgradable from: 1.0）」が違うものである。下の2つは本物の Ubuntu のパッケージで、檻の土台が作られた時点より目録のほうが新しい。

apt upgrade はこれを全部上げるが、下の2つはネットから取ってくる必要がある。-s（simulate）を付けると、何をするかだけ表示して実際には何もしない。

$ sudo apt-get -s upgrade
Reading package lists...
Building dependency tree...
Reading state information...
Calculating upgrade...
The following packages will be upgraded:
  labhello libaudit-common libaudit1
3 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.
Inst libaudit-common [1:3.1.2-2.1build1.1] (1:3.1.2-2.1ubuntu0.1 Ubuntu:24.04/noble-updates [all])
Conf libaudit-common (1:3.1.2-2.1ubuntu0.1 Ubuntu:24.04/noble-updates [all])
Inst libaudit1 [1:3.1.2-2.1build1.1] (1:3.1.2-2.1ubuntu0.1 Ubuntu:24.04/noble-updates [amd64])
Conf libaudit1 (1:3.1.2-2.1ubuntu0.1 Ubuntu:24.04/noble-updates [amd64])
Inst labhello [1.0] (1.1 lab lab:lab [all])
Conf labhello (1.1 lab lab:lab [all])

[1.0] が台帳の版、(1.1 …) が目録の版である。1つだけ上げたいときは、名前を指定して install する（入っているものに install すると、新しい版があれば上がる）。

$ labhello
labhello 1.0
$ sudo apt install -y labhello
...
The following packages will be upgraded:
  labhello
1 upgraded, 0 newly installed, 0 to remove and 2 not upgraded.
Need to get 0 B/620 B of archives.
After this operation, 0 B of additional disk space will be used.
Get:1 file:/srv/lab-repo lab/main amd64 labhello all 1.1 [620 B]
Preparing to unpack .../labhello/labhello_1.1_all.deb ...
Unpacking labhello (1.1) over (1.0) ...
Setting up labhello (1.1) ...
$ labhello
labhello 1.1
$ apt-cache policy labhello
labhello:
  Installed: 1.1
  Candidate: 1.1
  Version table:
 *** 1.1 500
        500 file:/srv/lab-repo lab/main amd64 Packages
        100 /var/lib/dpkg/status
     1.0 500
        500 file:/srv/lab-repo lab/main amd64 Packages

*** と 100 /var/lib/dpkg/status が 1.1 のほうへ移った。台帳が書き換わったのである。

コマンドすること
apt update（= apt-get update）目録を取り直す（第3章）。パッケージは1つも入れない
apt upgrade入っているものを、目録の新しい版に上げる。上げるのに新しい依存が要れば新しく入れるが、消しはしない（消さないと上げられないものは上げずに残す）
apt-get upgrade入っているものを上げる。新しく入れも消しもしない（それが要るものは上げずに残す。出力では kept back と出る）
apt full-upgrade（= apt-get dist-upgrade）上げるために必要なら、新しく入れることも消すこともする
apt install 名前入っていなければ入れ、入っていて新しい版があれば上げる

apt upgrade と apt-get upgrade は同じではない。この檻の練習用リポジトリには「上げるのに新しい依存が要る版」が無いので、違いは man の記述で確かめる（別の檻で記録した。MANWIDTH=80 は折り返しの幅を本文と揃えるため）。

$ MANWIDTH=80 man apt | sed -n "/^ *upgrade (apt-get(8))/,/^ *full-upgrade/p"
       upgrade (apt-get(8))
           upgrade is used to install available upgrades of all packages
           currently installed on the system from the sources configured via
           sources.list(5). New packages will be installed if required to
           satisfy dependencies, but existing packages will never be removed.
           If an upgrade for a package requires the removal of an installed
           package the upgrade for this package isn't performed.
...
$ MANWIDTH=80 man apt-get | sed -n "/^ *upgrade$/,/^ *dist-upgrade/p"
       upgrade
...
           versions available are retrieved and upgraded; under no
           circumstances are currently installed packages removed, or packages
           not already installed retrieved and installed. New versions of
           currently installed packages that cannot be upgraded without
           changing the install status of another package will be left at
           their current version. An update must be performed first so that
...
$ MANWIDTH=80 man apt | sed -n "/^ *full-upgrade (apt-get(8))/,/^ *install, reinstall/p"
       full-upgrade (apt-get(8))
           full-upgrade performs the function of upgrade but will remove
           currently installed packages if this is needed to upgrade the
           system as a whole.
...

apt の upgrade は「新しいパッケージは依存のためなら入れる（New packages will be installed if required）、入っているものは決して消さない」、apt-get の upgrade は「入っているものを消すことも、入っていないものを入れることも、どんな場合もしない（under no circumstances）」、full-upgrade は「全体を上げるのに必要なら消す（will remove）」と書いてある。

「パッケージ一覧を新しくする」が update、「入っているパッケージを新しくする」が upgrade である。名前が似ていて試験でよく入れ替えられる。

試験の例題には、dist-upgrade を「ディストリビューションの更新（Debian 8 から 9 へ）」、upgrade を「インストールされているパッケージを全部更新する」と言い切ったものがあり、この形で出うる。man に書いてある違いは上のとおりで、upgrade も全部を上げようとはするが、消さないと上げられないものは上げずに残す。特定のパッケージだけを上げるのは install 名前 である。

たとえ: 新しいカタログと、自宅の持ち物の記録を並べて「型が古いもの」に印を付ける作業に近い。 印を付けるだけなら何も買わなくてよい（-s）。
ただし崩れる点: 人ならカタログが古いと気づけるが、apt は手元のカタログを疑わない。 カタログを取り直す（apt update）まで、どれだけ古くても「これが最新」として比べる。

apt・apt-get・apt-cache の関係

この節で分かること: 似た名前の3つのコマンドが、何を分担しているか。

同じ質問をしても、答え方が違うことがある。

$ apt-cache show labhello | grep -E "^(Package|Version):"
Package: labhello
Version: 1.1
Package: labhello
Version: 1.0
$ apt show labhello 2>/dev/null | grep -E "^(Package|Version):"
Package: labhello
Version: 1.1

apt-cache show は目録にある版を全部出し、apt show は Candidate の1つだけを出す。そして apt は、画面以外に出力すると警告を出す。

$ apt show labapp

WARNING: apt does not have a stable CLI interface. Use with caution in scripts.

Package: labapp
Version: 1.0
...

「apt のコマンドの形は変わりうるので、スクリプトでは注意して使え」という意味である。apt は人が画面で打つための入口で、出力を見やすく整えるかわりに形を保証しない。スクリプトに書くなら、形を変えない apt-get と apt-cache を使う。

apt（人向け）apt-get / apt-cache（スクリプト向け）読む・書く帳簿
apt updateapt-get update目録を書き直す
apt install / remove / purge / autoremoveapt-get install / remove / purge / autoremove目録を読み、台帳を書く（実際に書くのは apt が呼ぶ dpkg）
apt upgrade / full-upgradeapt-get upgrade / dist-upgrade同上
apt search / apt showapt-cache search / apt-cache show目録を読むだけ
apt list --installed / --upgradable（dpkg -l が近い）台帳と目録を読む
apt depends / rdepends / policyapt-cache depends / rdepends / policy目録を読むだけ
apt download 名前apt-get download 名前目録を読んで .deb を取ってくるだけ（入れない）
apt cleanapt-get clean/var/cache/apt/archives/ の取ってきた .deb を消す

下の3行は、apt の man では「apt-cache と apt-get の説明に任せる」とまとめて1行ずつ書かれているだけだが、apt でもそのまま打てる（別の檻で記録した）。

$ apt depends labapp
...
labapp
  Depends: liblab (>= 1.0)
$ apt policy labhello

  Candidate: 1.1

       source, build-dep, download, changelog, clean, distclean, autoclean
       (summarised in apt-get(8))

apt depends は版の条件（(>= 1.0)）まで出し、apt-cache depends labapp は名前だけだった。同じ目録を読んでいて、見せ方だけが違う。

最後の2つの行を確かめる。apt-get download は root でなくてよい。台帳も目録の写しも書き換えず、カレントディレクトリにファイルを置くだけだからである。

$ apt-get download liblab
Get:1 file:/srv/lab-repo lab/main amd64 liblab all 1.0 [746 B]
$ ls -l *.deb
-rw-r--r-- 1 lab lab 746 Oct 13 11:40 liblab_1.0_all.deb
$ dpkg -l liblab; echo "exit=$?"
dpkg-query: no packages found matching liblab
exit=1
$ ls /var/cache/apt/archives/
lock
partial

ファイルは取れたが、台帳には載っていない。/var/cache/apt/archives/ は、apt install がネットから取ってきた .deb を置いておく場所で、apt-get clean がここを空にする。この檻の練習用リポジトリは file: なので、apt はそこから直接読み、ここにはコピーしない。

手を動かす: 実践編の演習01は、最初から入っている labsvc を「跡形なく」消す課題である。 判定は dpkg の台帳の状態（rc が残っていないか）と、/etc/labsvc.conf の有無と、一緒に入った labsvc-common が消えたかを実際に見る。
確認

インストール済みのパッケージを、設定ファイルも含めて削除するコマンドとして正しいものを2つ選べ。
(a) apt-get remove pkg　(b) apt-get purge pkg　(c) apt-get autoremove pkg　(d) apt-get remove --purge pkg　(e) apt-get clean pkg

答え

(b) と (d)。(a) は設定ファイルを残し、台帳に rc が残る（実測）。 (c) の autoremove pkg は pkg を remove し、それで不要になった自動の依存も消すが、pkg の設定ファイルは残す（rc。実測）。 (e) の clean は /var/cache/apt/archives/ の .deb を消すもので、入っているパッケージには触らない。

確認

apt-cache policy foo の出力に 100 /var/lib/dpkg/status という行があった。何を表すか。

答え

その版が、いま入っている版として dpkg の台帳（/var/lib/dpkg/status）に載っていることを表す。 500 の行は目録（リポジトリ）に載っている版である。 *** の付いた版が入っている版、Candidate が「入れるならこれ」になる。

確認

パッケージ foo が依存しているパッケージの一覧と、foo に依存しているパッケージの一覧を表示するコマンドをそれぞれ答えよ。

答え

apt-cache depends foo と apt-cache rdepends foo。 どちらも目録を読むだけなので、foo が入っていなくても答えられる。 依存の一覧は apt-cache showpkg foo の Dependencies: にも出る（逆向きは Reverse Depends:）。

確認

apt-get update と apt-get upgrade の違いを説明せよ。

答え

update は目録（パッケージの一覧）を取り直すだけで、パッケージは1つも入れ替えない。 upgrade は、手元の目録の新しい版と台帳の版を比べて、入っているパッケージを上げる。 apt-get upgrade は新しく入れることも消すこともしない（それが要るものは上げずに残す）。 apt upgrade は依存のために新しく入れることはあるが、消さない。消すことまでするのは apt-get dist-upgrade（apt full-upgrade）である。

この章で分かったこと

持ち帰ってほしいこと

  • apt-cache（search / show / depends / rdepends / showpkg / policy）は目録を読むだけ。入っていないパッケージにも答えられる。依存を出すのは depends と showpkg（rdepends は逆向き）
  • apt-cache policy には目録の版（500）と台帳の版（100 /var/lib/dpkg/status）が並ぶ
  • apt install は目録の Depends: をたどって足りないものも入れ、それに auto の印を付ける（apt-mark showauto）
  • remove は設定ファイル（conffile）を残して rc（conffile の無いパッケージは台帳から消える）、purge は設定ファイルも台帳の行も消す、autoremove は auto の印で不要になったものを消す（名前を渡すとそのパッケージも remove）
  • upgrade は目録の版と台帳の版の比較。update（目録を取り直す）とは別物。apt-get upgrade は入れも消しもせず、apt upgrade は依存のためなら入れ、full-upgrade（dist-upgrade）は消すこともある
  • apt は人向けの入口。スクリプトには apt-get と apt-cache
