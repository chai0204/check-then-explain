11. .rpm ファイルを rpm で直接入れて、確かめる

前の章までにやったこと: RPM 系で、yum で入れて消し、rpm に台帳を聞き（第9章）、yum のリポジトリを足して上げ、署名を rpm -K で確かめた（第10章）。Debian 系では、.deb ファイルを dpkg で直接入れ（第7章）、台帳とファイルを dpkg -V で見比べた（第4章）。この章でやること: RPM 系で同じことをする。.rpm ファイルを入れずに取ってきて中を見て、rpm で直接入れ、上げて、消す。台帳と照らし合わせる rpm -V と、入れずに中身を取り出す rpm2cpio も使う。最後に、この11章を1つにまとめる。

前提: 第10章まで読了前提: RPM 系の檻を起動し直した直後所要 28分影響度 B出題範囲 1.04.4（重要度1）出題範囲 1.04.3（重要度3）最終検証 2026-10-21

この章のゴール

  • yumdownloader で .rpm ファイルを取り、rpm -qp… で入れる前に中を見る
  • rpm -ivh で入れ、依存関係が足りないとどうなるかを確かめる。-U・-F・-e の違いを確かめる
  • rpm -V の出力の9文字を読み、何が変わったかを確かめる
  • rpm2cpio で、入れずに中身を取り出す
ここで覚えなくていいこと: rpm のこの章に出てこないオプション（--force など）、rpm -V の文字のうち、この章で実際には出てこないもの（表の D・L・P）が出る場面、設定ファイルを書き換えたまま消したときの扱い（.rpmsave）、台帳の作り直し。この章は「ファイルから入れる・上げる・照らし合わせる・取り出す」が1回できれば足りる。

入れずに取ってくる — yumdownloader

この節で分かること: .rpm ファイルを手に入れて、入れる前に中を見る方法。

Debian 系の apt download（第3章）にあたるのが yumdownloader である。目録を見て .rpm ファイルを取ってくるだけで、入れない。

$ yumdownloader labtool
Last metadata expiration check: 4:50:59 ago on Tue Oct 20 19:34:06 2026.
$ ls -l
total 12
-rw-r--r-- 1 lab lab 6859 Oct 21 00:25 labtool-1.0-1.noarch.rpm
drwxr-xr-x 2 lab lab 4096 Oct 20 19:34 work
$ rpm -q labtool
package labtool is not installed

1行目は第10章の、目録を最後に確かめた時刻の知らせで、取ってきたファイルが labtool-1.0-1.noarch.rpm である（日時は、あなたが打った時刻になる）。台帳には何も書いていない。だから root でなくても打てる。このファイルに、rpm で中を聞く。台帳ではなくファイルに聞くときは、-q に p（package file）を足す。

$ rpm -qpi labtool-1.0-1.noarch.rpm
Name        : labtool
Version     : 1.0
Release     : 1
Architecture: noarch
Install Date: (not installed)
Group       : Unspecified
Size        : 98
License     : MIT
Signature   : RSA/SHA256, Tue Oct 20 19:33:57 2026, Key ID ed81483d5236f3f6
Source RPM  : labtool-1.0-1.src.rpm
Build Date  : Thu Oct  1 09:00:00 2026
Build Host  : linuc-build
Packager    : check-then-explain <lab@example.invalid>
Vendor      : check-then-explain
URL         : https://github.com/chai0204/check-then-explain
Summary     : tool that needs labtool-data
Description :
Prints a line shipped in labtool-data.
$ rpm -qpl labtool-1.0-1.noarch.rpm
/usr/bin/labtool
$ rpm -qpR labtool-1.0-1.noarch.rpm
/usr/bin/sh
labtool-data >= 1.0
rpmlib(CompressedFileNames) <= 3.0.4-1
rpmlib(FileDigests) <= 4.6.0-1
rpmlib(PayloadFilesHavePrefix) <= 4.0-1
rpmlib(PayloadIsZstd) <= 5.4.18-1

-qpi は情報（欄の読み方は第9章の rpm -qi と同じ）、-qpl は中のファイル、-qpR は依存関係である（第3章の dpkg -I・dpkg -c にあたる）。Install Date: (not installed) は、ファイルの中には入れた日時が書かれていないので、いつもこう出る。labtool は labtool-data >= 1.0 が要ると分かる。

聞く相手書き方答えられること
台帳（入っているもの）rpm -q□ 名前（-qi・-ql・-qR など）入っているパッケージだけ
.rpm ファイルrpm -qp□ ファイル（-qpi・-qpl・-qpR など）入れる前のファイルの中身

rpm で入れる — rpm -ivh

この節で分かること: rpm で入れるとき、依存関係がどう扱われるか。

.rpm ファイルを入れるのは rpm -i（install）である。v は経過を表示し、h は進み具合を # で表示する。たいてい -ivh と3つ並べて使う。

ふつうこう考える

第7章の dpkg -i と同じで、依存関係が足りなくても、中身を置くところまでは進めて止まるはずだ。

$ sudo rpm -ivh labtool-1.0-1.noarch.rpm
error: Failed dependencies:
        labtool-data >= 1.0 is needed by labtool-1.0-1.noarch
$ echo $?
1
$ rpm -q labtool
package labtool is not installed
$ ls /usr/bin/labtool
ls: cannot access '/usr/bin/labtool': No such file or directory
だめな理由: Failed dependencies（依存関係が満たされない）で止まり、labtool は台帳にも無く、ファイルも置かれていない。 rpm も dpkg と同じく、依存関係を読めるが、取りに行かない。違うのは止まり方で、足りないと分かった時点で、1つも入れずに止まる。dpkg は展開まで進めて iU を残したが、rpm は台帳にもディスクにも何も残さない。

足りない labtool-data も取ってきて、2つ並べて渡す。yumdownloader の --resolve は、依存関係のパッケージも一緒に取ってくる。

$ yumdownloader --resolve labtool
Last metadata expiration check: 4:51:04 ago on Tue Oct 20 19:34:06 2026.
$ ls -l
total 20
-rw-r--r-- 1 lab lab 6859 Oct 21 00:25 labtool-1.0-1.noarch.rpm
-rw-r--r-- 1 lab lab 6729 Oct 21 00:25 labtool-data-1.0-1.noarch.rpm
drwxr-xr-x 2 lab lab 4096 Oct 20 19:34 work
$ sudo rpm -ivh labtool-1.0-1.noarch.rpm labtool-data-1.0-1.noarch.rpm
Verifying...                          ################################# [100%]
Preparing...                          ################################# [100%]
Updating / installing...
   1:labtool-data-1.0-1               ################################# [ 50%]
   2:labtool-1.0-1                    ################################# [100%]
$ labtool
labtool: labtool-data から読んだ1行です

Verifying（署名とダイジェストを確かめる）・Preparing（準備）のあと、Updating / installing の下に入れた順が出る。渡した順は labtool が先だったが、rpm は依存関係を見て labtool-data を先に入れた。yum からはどう見えるか。

$ yum list installed labtool labtool-data
Installed Packages
labtool.noarch                             1.0-1                         @System
labtool-data.noarch                        1.0-1                         @System

右端が @System になった。rpm で直接入れたものは、どのリポジトリから来たかの記録が無いからである（yum で入れれば、第9章のように @lab になる）。ただし、同じ版を前に yum で入れたことがあると、消して rpm で入れ直しても @@System や @lab のように、yum がその版について最後に残した記録が出続ける。

たとえ: 部品表を見て「この部品が無いと組めない」と言う検品係に近い。足りなければ、作業台に何も載せずに、作業票ごと突き返す。部品を取りに倉庫へ行くのは別の係（yum）の仕事である。
ただし崩れる点: 人の検品係なら「急ぎだから部品なしで組んで」と言われても事情を聞き返すが、rpm に依存関係を確かめさせない指示（--nodeps）を付けると、聞き返さずに組めないものを組む。それを「台帳と照らし合わせる」の節で確かめる。

rpm で消す — rpm -e

この節で分かること: rpm で消すときの打ち方。
$ sudo rpm -e labtool-data
error: Failed dependencies:
        labtool-data >= 1.0 is needed by (installed) labtool-1.0-1.noarch
$ sudo rpm -e labtool labtool-data
$ rpm -q labtool labtool-data
package labtool is not installed
package labtool-data is not installed

-e（erase）は消す。入っている labtool が必要としている labtool-data は、先に消すことを断られた（needed by (installed)）。2つ並べて渡せば、順番は rpm が決めて消す。rpm -e は、うまくいくと何も出さない。

上げる — -i・-U・-F の違い

この節で分かること: 新しい版のファイルを入れるときの3つのオプションの違い。

labhello の 1.0 を yumdownloader で取り、1.1 は第10章で足したリポジトリの置き場から写す（この檻では、まだそのリポジトリを足していない）。

$ yumdownloader labhello
Last metadata expiration check: 4:51:09 ago on Tue Oct 20 19:34:06 2026.
$ cp /srv/lab-updates-rpm/labhello-1.1-1.noarch.rpm .
$ ls
labhello-1.0-1.noarch.rpm  labtool-1.0-1.noarch.rpm       work
labhello-1.1-1.noarch.rpm  labtool-data-1.0-1.noarch.rpm

まず、labhello が入っていない状態で -F（freshen）を使う。

$ sudo rpm -Fvh labhello-1.0-1.noarch.rpm
$ echo $?
0
$ rpm -q labhello
package labhello is not installed

何も出ず、終了コード 0 で、何も入らなかった。-F は「入っているものだけを新しくする」オプションで、入っていないものには何もしない。次に 1.0 を -i で入れてから、1.1 を -i で入れようとする。

$ sudo rpm -ivh labhello-1.0-1.noarch.rpm
Verifying...                          ################################# [100%]
Preparing...                          ################################# [100%]
Updating / installing...
   1:labhello-1.0-1                   ################################# [100%]
$ sudo rpm -ivh labhello-1.1-1.noarch.rpm
warning: labhello-1.1-1.noarch.rpm: Header V4 RSA/SHA256 Signature, key ID a5824b40: NOKEY
Verifying...                          ################################# [100%]
Preparing...                          ################################# [100%]
        file /usr/bin/labhello from install of labhello-1.1-1.noarch conflicts with file from package labhello-1.0-1.noarch
        file /usr/share/doc/labhello/README from install of labhello-1.1-1.noarch conflicts with file from package labhello-1.0-1.noarch
        file /usr/share/man/man1/labhello.1.gz from install of labhello-1.1-1.noarch conflicts with file from package labhello-1.0-1.noarch

1行目の warning … NOKEY は、1.1 の署名を確かめる鍵（lab updates）をこの檻ではまだ取り込んでいない、という警告である（第10章）。rpm は警告を出すだけで先へ進む。止まったのはその後で、conflicts with file from package labhello-1.0-1（1.0 のファイルとぶつかる）と言われた。-i は「新しく入れる」で、古い版を消さずに並べて入れようとするので、同じファイルがぶつかる。上げるのは -U（upgrade）である。

$ sudo rpm -Uvh labhello-1.1-1.noarch.rpm
warning: labhello-1.1-1.noarch.rpm: Header V4 RSA/SHA256 Signature, key ID a5824b40: NOKEY
Verifying...                          ################################# [100%]
Preparing...                          ################################# [100%]
Updating / installing...
   1:labhello-1.1-1                   ################################# [ 50%]
Cleaning up / removing...
   2:labhello-1.0-1                   ################################# [100%]
$ labhello
labhello 1.1

1.1 を入れ（Updating / installing）、1.0 を片付けた（Cleaning up / removing）。

オプション入っていないとき古い版が入っているとき何のためにあるか
-i（install）入れる止まる（ファイルがぶつかる）新しく入れる。カーネルのように、古い版を残して並べて入れたいものにも使う
-U（upgrade）入れる上げる（古い版を消す）入っていてもいなくても、この版にする。ただし、入っているのと同じ版や、それより古い版を渡すと is already installed と断る（終了コード 2。同じ版を入れ直すのは、次の節の --replacepkgs）
-F（freshen）何もしない上げる（古い版を消す）入っているものだけを新しくする（入っていないものを増やさない）
たとえ: 名簿を更新するときの3通りの指示に近い。-i は「新しく名前を書け」、-U は「名前があれば書き換え、無ければ足せ」、-F は「名前があるときだけ書き換えよ」である。
ただし崩れる点: 名簿なら同じ人の名前を2行書いても困るだけだが、rpm の -i は、同じファイルを持つ2つの版を見つけると、書く前に止まる。

台帳と照らし合わせる — rpm -V

この節で分かること: rpm -V が何を比べ、どう答えるか。

第4章の dpkg -V にあたるのが rpm -V（verify）である。いまの labhello を照らし合わせる。

$ rpm -V labhello
$ echo $?
0

何も出ず、終了コードは 0 だった。dpkg -V と同じく、違うファイルだけを出すので、何も出ないのは「全部台帳どおり」という答えである。2か所変える。実行の許可を外し（chmod 644）、中身に1行書き足す。

$ sudo chmod 644 /usr/bin/labhello
$ echo '# 書き足した' | sudo tee -a /usr/bin/labhello
# 書き足した
$ rpm -V labhello
SM5....T.    /usr/bin/labhello
$ echo $?
1
$ labhello
bash: /usr/bin/labhello: Permission denied

labhello は Permission denied（実行の許可が無い）で動かなくなった。rpm -V の左の9文字は、台帳と比べた項目ごとに、違った項目だけ文字が入り、同じなら . になる。

文字比べたもの何のために見るか
S大きさ（Size）書き足し・切り詰めを見つける
M権限と種類（Mode）実行の許可や書き込みの許可の変化を見つける（いまの chmod 644）
5中身の要約（ダイジェスト）中身が1バイトでも変わったかを見つける
Dデバイスの番号装置ファイル（ディスクや端末などの装置を、ファイルとして扱えるようにしたもの）のすり替えを見つける
Lシンボリックリンクの行き先リンクの付け替えを見つける
U / G持ち主 / グループ持ち主の変化を見つける
T更新時刻（mTime）いつか書き換えられたことを見つける
Pケーパビリティ（root の力の一部を分けて与える印）与えられた力の変化を見つける
?（どの欄にも出る）確かめられなかった読む許可の無いファイルなど。一般ユーザでは読めないファイルの中身（5）は、sudo を付けて打つと確かめられる

SM5....T. は「大きさ・権限・中身・時刻が違う」と読む。ファイル名の前に c があれば設定ファイル、d なら説明書である（ここは空白なのでふつうのファイル）。dpkg -V と違い、台帳に大きさや権限も記録されているので欄が埋まり、違いがあれば終了コードも 0 以外（ここでは 1）になる。台帳どおりに戻すには、同じ版をもう一度入れる。--replacepkgs は「同じ版が入っていても入れ直す」の印である。

$ sudo rpm -Uvh --replacepkgs labhello-1.1-1.noarch.rpm
warning: labhello-1.1-1.noarch.rpm: Header V4 RSA/SHA256 Signature, key ID a5824b40: NOKEY
Verifying...                          ################################# [100%]
Preparing...                          ################################# [100%]
Updating / installing...
   1:labhello-1.1-1                   ################################# [ 50%]
Cleaning up / removing...
   2:labhello-1.1-1                   ################################# [100%]
$ rpm -V labhello
$ labhello
labhello 1.1

黙った。権限も中身も台帳どおりに戻り、labhello が動いた。リポジトリにある版なら、sudo yum reinstall 名前 でも入れ直せる。rpm -V は依存関係も照らし合わせる。第9章の labapp を入れ、依存関係を確かめずに消す --nodeps で liblab だけを消してみる。

$ sudo yum install labapp
...
Installing:
 labapp             noarch             1.0-1              lab             7.3 k
Installing dependencies:
 liblab             noarch             1.0-1              lab             6.7 k

...
Is this ok [y/N]: y
...
Complete!
$ sudo rpm -e --nodeps liblab
$ labapp
/usr/bin/labapp: line 3: /usr/lib/liblab/liblab.sh: No such file or directory
$ rpm -V labapp
Unsatisfied dependencies for labapp-1.0-1.noarch:
        liblab >= 1.0 is needed by (installed) labapp-1.0-1.noarch

--nodeps を付けると、rpm は labapp が liblab を必要としていることを確かめずに、黙って消した。labapp は動かなくなり、rpm -V は「満たされていない依存関係がある（Unsatisfied dependencies）」と報告した。--nodeps は台帳の整合を自分で崩すオプションで、使ったら後始末も自分でする。yum reinstall で入れ直すと、足りない liblab も一緒に入る。

$ sudo yum reinstall labapp
...
Reinstalling:
 labapp             noarch             1.0-1              lab             7.3 k
Installing dependencies:
 liblab             noarch             1.0-1              lab             6.7 k

...
Is this ok [y/N]: y
...
Installed:
  liblab-1.0-1.noarch
Reinstalled:
  labapp-1.0-1.noarch

Complete!
$ labapp
liblab: hello from labapp 1.0

全部のパッケージをまとめて照らし合わせるのは rpm -Va（all）である。

$ rpm -Va | wc -l
31

31 は、出てきた行の数である（wc -l は第9章で使った、行を数えるコマンド）。このように何十行も出ることがあり、全部が異常ではない。一般ユーザのまま打ったので、読む許可の無いもの（/etc/sudoers など）は確かめられず、? の付いた行や Permission denied の付いた行になって数に入っている（この檻では10行。sudo rpm -Va と打てば確かめられるので、21行になる）。設定ファイル（c）は書き換えて使うものであり（この檻では、AlmaLinux のリポジトリの向き先を書き換えてある）、コンテナには省かれたディレクトリもある（missing の行）。この檻では、yum の目録の写しの置き場を付け替えてある分（/var/cache/dnf の2行）と、演習11 のために書き換えてある labmotd の2行も出る。読むときは、設定ファイルでないのに 5 や M が付いた行から先に疑う。

たとえ: 賃貸の退去点検で、入居したときの写真と、いまの部屋を比べる作業に近い。点検表には違う項目だけが書かれ、何も書かれていなければ元どおりということである。
ただし崩れる点: 写真で比べられるのは見た目だけだが、rpm -V は中身の要約（5）まで比べる。見た目（大きさや時刻）をそろえても、中身が1文字違えば見つかる。

入れずに中身を取り出す — rpm2cpio

この節で分かること: .rpm の中のファイルを、台帳に触らずに取り出す方法。

rpm2cpio は、.rpm ファイルの中身を cpio という形式のひとかたまりにして出す。受け取った cpio の -t は一覧を出し、-i は取り出す（-d は途中のディレクトリを作る、-m は時刻を保つ、-v は取り出したものを表示する）。取り出すときは、mkdir で作ったディレクトリ ext に cd で移ってから打つ。../labtool-… の .. は「1つ上のディレクトリ」で、移る前の場所にある .rpm を指す。最後の cd は、行き先を書かないとホーム（~）に戻る。

$ rpm2cpio labtool-1.0-1.noarch.rpm | cpio -t
./usr/bin/labtool
1 block
$ mkdir ext
$ cd ext
$ rpm2cpio ../labtool-1.0-1.noarch.rpm | cpio -idmv
./usr/bin/labtool
1 block
$ ls -l usr/bin/labtool
-rwxr-xr-x 1 lab lab 98 Oct  1 09:00 usr/bin/labtool
$ rpm -qf usr/bin/labtool
file /home/lab/ext/usr/bin/labtool is not owned by any package
$ cd

1 block は cpio が読んだ量の知らせである。いまいるディレクトリの下に usr/bin/labtool として取り出されたので、root も要らない。rpm -qf は「どのパッケージのものでもない（not owned by any package）」と答えた。台帳は何も知らない。第4章の dpkg-deb -x と同じで、壊れた設定ファイルの元の姿を1つだけ見たいときなどに使う。

たとえ: 届いた箱から説明書だけを抜き出して読み、品物は棚に入れない使い方に近い。
ただし崩れる点: 箱から抜いた説明書は箱の付属品だと分かるが、取り出したファイルには「どのパッケージから出たか」の記録が残らない。rpm -qf に聞いても、誰のものでもないと答える。

11章を1つにまとめる

この節で分かること: 2つの系統のパッケージ管理が、同じ形をしていること。

Debian 系と RPM 系で、道具の名前は違うが、形は同じだった。

                     Debian 系                      RPM 系
パッケージのファイル   .deb（中身＋情報）              .rpm（中身＋情報）
リポジトリの表         /etc/apt/sources.list(.d)       /etc/yum.repos.d/*.repo
目録の写し             /var/lib/apt/lists/             /var/cache/dnf/
目録を取り直す         apt update（言われたときだけ）  yum が自分で（makecache でも）
取ってきて入れる       apt                             yum（= dnf）
ファイルを置いて書く   dpkg                            rpm
台帳                   /var/lib/dpkg/（テキスト）       /var/lib/rpm/（データベース）
台帳とファイルを比べる dpkg -V                         rpm -V

どちらも、パッケージを入れると、ファイルが置かれ、入れたという記録（台帳）が書かれる。ファイルと台帳は別々にあるので、片方だけが変わることがある（ファイルだけ消す・中身だけ広げる）。apt と yum は、リポジトリの目録を読んで取ってきて、dpkg と rpm がファイルを置き、台帳に書く。コマンドの答えが食い違ったり、思ったのと違ったりしたら、いま見ているのが「ファイル」「台帳」「目録」のどれかを確かめる。

手を動かす: 実践編の演習11は、入れたあとで2か所いじられた labmotd を、台帳と照らし合わせて突き止め、入れた直後の状態に戻す課題である。 演習12は、yumdownloader で取ってきた .rpm ファイルを、yum を使わずに rpm だけで入れる。判定は台帳と、rpm で入れたか（台帳の「入れた時刻」を、yum の取引の記録と比べる）を見る。
確認

入っているパッケージだけを新しい版に更新し、入っていなければ何もしない rpm のオプションはどれか。
(a) -i　(b) -U　(c) -F　(d) -e

答え

(c) -F（freshen）。実測では、入っていない labhello には何もせず終了コード 0 だった。 (b) の -U は入っていなければ新しく入れる。(a) の -i は古い版が入っているとファイルがぶつかって止まる。

確認

rpm -V httpd の出力に S.5....T. c /etc/httpd/conf/httpd.conf とあった。何を意味するか。

答え

設定ファイル（c）の大きさ（S）・中身の要約（5）・更新時刻（T）が、入れたときと違う。つまり書き換えられている。 設定ファイルなら、意図して書き換えたことが多い。権限（M）・持ち主（U）・グループ（G）は入れたときのままである。

確認

依存関係を確かめずにパッケージを消す rpm のコマンドを答えよ。また、そのあと何が起きうるか。

答え

rpm -e --nodeps パッケージ名。それを必要としていたパッケージが動かなくなる （実測: liblab を消すと labapp が動かなくなり、rpm -V labapp が Unsatisfied dependencies を報告した）。

確認

.rpm ファイルを入れずに、中のファイルをいまいるディレクトリに取り出すコマンドを答えよ。

答え

rpm2cpio foo.rpm | cpio -idmv。rpm2cpio が中身を cpio の形式で出し、cpio -i が取り出す。 一覧だけなら rpm2cpio foo.rpm | cpio -t、または rpm -qpl foo.rpm。

この章で分かったこと

持ち帰ってほしいこと

  • yumdownloader（--resolve で依存関係も）で .rpm を取り、rpm -qpi・-qpl・-qpR で入れる前に中を見る
  • rpm -ivh は依存関係が足りないと1つも入れずに止まる（dpkg は iU を残した）。必要なファイルを並べて渡せば、順番は rpm が決める。rpm で入れたものは yum から見ると @System
  • -i は新しく入れる（古い版があればぶつかる）、-U は上げるか入れる、-F は入っているものだけ上げる、-e は消す（依存されていれば断る。--nodeps は確かめない）
  • rpm -V は違うファイルだけを出す。9文字は SM5DLUGTP（違った項目だけ文字が入る）で、違いがあれば終了コードも 0 以外
  • rpm2cpio | cpio -idmv は入れずに中身を取り出す。台帳には載らない
