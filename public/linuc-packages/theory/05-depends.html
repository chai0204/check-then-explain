5. 依存関係のあるパッケージを入れて、消す

前の章までにやったこと: 1つだけで動くパッケージ labhello を入れて・使って・消し（第1章）、入っているものとその置き場所を調べ（第2・3章）、台帳とファイルが別々にあることを確かめた（第4章）。この章でやること: ほかのパッケージが無いと動かないパッケージ labapp を入れて、一緒に何が入るかを見る。それから消して、台帳と /etc に何が起きるかを確かめる。

前提: 第4章まで読了前提: Debian 系の檻を起動し直した直後所要 18分影響度 B出題範囲 1.04.1（重要度3）最終検証 2026-10-21

この章のゴール

  • 依存関係のあるパッケージを apt install で入れると、何が入るかを出力から確かめる
  • 依存関係を apt-cache depends（必要とするもの）と apt-cache rdepends（必要とされているもの）で調べる
  • remove・purge・autoremove で、それぞれ何が消えて何が残るかを、台帳の記号と /etc の設定ファイルで確かめる
ここで覚えなくていいこと: Depends 以外の関係（Recommends・Conflicts など）、このあと見る apt の印を、手で付け替える方法（apt-mark auto / manual）、設定ファイルが書き換えられていたときの細かい扱い。この章は、入れて、消して、片付けるところまでが1回できれば足りる。

依存関係のあるパッケージを入れる — apt install

この節で分かること: 依存関係のあるパッケージを入れると、apt が何をするか。

第3章で .deb ファイルの情報を見たとき、labapp には Depends: liblab (>= 1.0) と書いてあった。labapp は liblab が無いと動かない、という依存関係である。labapp を入れる。

$ sudo apt install labapp
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
The following additional packages will be installed:
  liblab
The following NEW packages will be installed:
  labapp liblab
0 upgraded, 2 newly installed, 0 to remove and 0 not upgraded.
Need to get 0 B/1822 B of archives.
After this operation, 106 kB of additional disk space will be used.
Do you want to continue? [Y/n] y
Get:1 file:/srv/lab-repo lab/main amd64 liblab all 1.0 [746 B]
Get:2 file:/srv/lab-repo lab/main amd64 labapp all 1.0 [1076 B]
Selecting previously unselected package liblab.
(Reading database ... 12833 files and directories currently installed.)
Preparing to unpack .../libl/liblab/liblab_1.0_all.deb ...
Unpacking liblab (1.0) ...
Selecting previously unselected package labapp.
Preparing to unpack .../l/labapp/labapp_1.0_all.deb ...
Unpacking labapp (1.0) ...
Setting up liblab (1.0) ...
Setting up labapp (1.0) ...

頼んだのは labapp だけだが、The following additional packages will be installed: liblab（次のものも追加で入れる）と出て、2つ入った。apt は labapp の依存関係を読んで、足りない liblab をリポジトリから一緒に取ってきた。頼んでいないものを入れるときは、第1章と違って Do you want to continue? [Y/n] と尋ねてくる。Setting up の順番も見てほしい。labapp を使える状態にする前に、先に liblab を整えている。

$ labapp
liblab: hello from labapp 1.0

行の頭の liblab: は、labapp が liblab の中の部品を使って挨拶を出している印である。

依存関係は、入れる前にも調べられる。apt-cache は apt の兄弟のコマンドで、入れられるパッケージの一覧から情報を引くだけで、何も入れない（root も要らない）。

$ apt-cache depends labapp
labapp
  Depends: liblab
$ apt-cache rdepends liblab
liblab
Reverse Depends:
  labapp

depends は「これが必要とするもの」、rdepends（reverse depends）は「これを必要としているもの」で、同じ関係を前から読むか後ろから読むかの違いである。もう1つ、版ごとの依存関係と逆向きの依存関係をまとめて出す showpkg がある。

$ apt-cache showpkg labapp
Package: labapp
Versions:
1.0 (/var/lib/apt/lists/_srv_lab-repo_dists_lab_main_binary-amd64_Packages.lz4) (/var/lib/dpkg/status)
 Description Language:
                 File: /var/lib/apt/lists/_srv_lab-repo_dists_lab_main_binary-amd64_Packages.lz4
                  MD5:


Reverse Depends:
Dependencies:
1.0 - liblab (2 1.0)
Provides:
1.0 -
Reverse Provides:

行が多いが、見るのは2か所である。Dependencies: の 1.0 - liblab (2 1.0) が「版 1.0 は liblab を必要とする」で、括弧の中の 2 1.0 は「1.0 以上」を番号で書いたもの（2 が「以上」）。Reverse Depends: の下が空なのは、labapp を必要としているパッケージが無いからである。Versions: の行の括弧の中は、この版が載っている一覧のファイルである。/var/lib/apt/lists/ の下のものは、リポジトリの「入れられるパッケージの一覧」のファイル（.lz4 は縮めた形）、/var/lib/dpkg/status は台帳（第4章）である。

たとえ: テレビを注文したら、配達の人がアンテナ線も一緒に持ってきて、先に線をつないでからテレビを置いてくれるのに近い。頼んだのはテレビだけでも、使うのに要るものは一緒に来る。
ただし崩れる点: 人の配達なら、要りそうな物を配達の人が見て判断するが、apt が見るのは、パッケージに書かれた関係だけである（Depends: のほか、既定では「一緒に入れるとよい」という Recommends: に書かれたものも入れる。練習用のパッケージには Depends: しか書いていない）。書かれていない物は、要りそうでも持ってこない。

自動で入った印

この節で分かること: apt が、どれを利用者が頼み、どれを自分が足したかを覚えていること。

第2章の apt list --installed で、labsvc-common に automatic の印が付いていた。liblab にも付いたかを、apt-mark（apt の「自動で入った・利用者が頼んだ」の印を見るコマンド）で見る。

$ apt-mark showauto | grep lab
labsvc-common
labweb-data
liblab
$ apt-mark showmanual | grep lab
labapp
labbackup
labfortune
labsvc
labweb

showauto は自動で入ったもの、showmanual は利用者が名前を指定して入れたものを出す（どちらもほかのパッケージがたくさん並ぶので、grep で練習用だけにしぼった）。liblab は自動、labapp は手動である。この印は、dpkg の台帳ではなく、apt が別に持っている記録 /var/lib/apt/extended_states に書かれている。

$ grep -A2 '^Package: liblab$' /var/lib/apt/extended_states
Package: liblab
Architecture: amd64
Auto-Installed: 1

Auto-Installed: 1 が「自動で入った」の印である。次の節で、この印が効いてくる。

たとえ: 薬局が、医者の出した薬と、その薬のために一緒に出した胃薬を、分けて控えておくのに近い。控えがあれば、元の薬をやめたときに「この胃薬ももう要らない」と後で判断できる。
ただし崩れる点: 薬なら、どちらが付き添いかは処方箋そのものに書いてあるが、この印はパッケージにも dpkg の台帳にも書かれていない。apt が別に持っている記録（/var/lib/apt/extended_states）にだけある。

消す — apt remove

この節で分かること: apt remove で消したあと、台帳と /etc がどうなるか。

ふつうこう考える

第1章のとおり apt remove で消せば、labapp は跡形なく消える。設定ファイルも、一緒に入ってきた liblab も、まとめて片付くはずだ。

$ sudo apt remove labapp
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
The following package was automatically installed and is no longer required:
  liblab
Use 'sudo apt autoremove' to remove it.
The following packages will be REMOVED:
  labapp
0 upgraded, 0 newly installed, 1 to remove and 0 not upgraded.
After this operation, 69.6 kB disk space will be freed.
Do you want to continue? [Y/n] y
(Reading database ... 12839 files and directories currently installed.)
Removing labapp (1.0) ...
$ dpkg -l labapp | tail -1
rc  labapp         1.0          all          sample application that needs liblab
$ ls -l /etc/labapp.conf
-rw-r--r-- 1 root root 93 Oct  1 09:00 /etc/labapp.conf
$ dpkg -l liblab | tail -1
ii  liblab         1.0          all          small shell library for lab programs
だめな理由: 3つ残っている。台帳の labapp の行（rc）、設定ファイル /etc/labapp.conf、そして liblab（ii）である。 rc の1文字目 r は「消したい（Remove）」、2文字目 c は「設定ファイルだけ残っている（Conf-files）」。 /etc/labapp.conf は、パッケージを作った人が「利用者が書き換える設定ファイル」として印を付けたファイル（conffile。第2章の dpkg -s の Conffiles: 欄）なので、remove は残す。入れ直したときに、書き換えた設定が戻ってくるようにするためである。 liblab については、apt 自身が出力の中で「自動で入ったもので、もう要らない。sudo apt autoremove で消せる」と教えている。

台帳の行が残っているので、dpkg -s にも答えがある（head -2 は、受け取った行の先頭の2行だけを出す）。

$ dpkg -s labapp | head -2
Package: labapp
Status: deinstall ok config-files

deinstall ok config-files は「消したい・問題なし・設定ファイルだけ」で、rc と同じ意味である。

設定ファイルごと消す — purge

この節で分かること: 残った設定ファイルと台帳の行を消す方法。

設定ファイルまで消すのが purge である。すでに rc になったものにも使える。

$ sudo apt purge labapp
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
The following package was automatically installed and is no longer required:
  liblab
Use 'sudo apt autoremove' to remove it.
The following packages will be REMOVED:
  labapp*
0 upgraded, 0 newly installed, 1 to remove and 0 not upgraded.
After this operation, 0 B of additional disk space will be used.
Do you want to continue? [Y/n] y
(Reading database ... 12836 files and directories currently installed.)
Purging configuration files for labapp (1.0) ...
$ dpkg -l labapp
dpkg-query: no packages found matching labapp
$ ls -l /etc/labapp.conf
ls: cannot access '/etc/labapp.conf': No such file or directory

labapp* の * が「設定ファイルも消す」の印で、Purging configuration files（設定ファイルを消している）と出た。台帳の行も、設定ファイルも無くなった。

自動で入ったものを片付ける — autoremove

この節で分かること: もう誰にも必要とされていない依存を消す方法。
$ sudo apt autoremove
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
The following packages will be REMOVED:
  liblab
0 upgraded, 0 newly installed, 1 to remove and 0 not upgraded.
After this operation, 36.9 kB disk space will be freed.
Do you want to continue? [Y/n] y
(Reading database ... 12835 files and directories currently installed.)
Removing liblab (1.0) ...
$ dpkg -l liblab
dpkg-query: no packages found matching liblab

名前を渡さない autoremove は、「自動で入った印があり、もう誰にも必要とされていないもの」を apt が自分で探して消す。前の節の印が、ここで使われた。liblab には設定ファイルが無いので、rc も残さず台帳から行ごと消えた。remove で rc が残るのは、purge のときにまだすることが残っているパッケージである。練習用のパッケージでは、設定ファイル（conffile）を持つもの（labapp など）がそれにあたる。練習用でないパッケージには、消すときに動かす手順（postrm というスクリプト。スクリプトは、コマンドを並べて自動で動かすファイル）を持つものも多く、それらは conffile が無くても、purge でその手順をもう一度動かすために rc で残る（この檻に入っている計算のコマンド bc のパッケージがそうである）。

コマンド何のためにあるか中身設定ファイル（conffile）台帳の行自動で入った依存
apt remove 名前設定は残して、また入れたときに戻したい消える残るrc で残る（conffile も、消すときの手順 postrm も無ければ、行ごと消える）残る
apt purge 名前（= apt remove --purge 名前）設定も含めて、跡形なく消したい消える消える消える残る
apt autoremoveもう誰にも要らなくなった依存を片付けたい自動で入った印があって、誰にも必要とされていないものを消す

apt-get（apt より前からある、ほぼ同じ働きのコマンド）にも、同じ名前の remove・purge・autoremove がある。

たとえ: 賃貸の部屋を引き払うときに近い。remove は家具を運び出すだけで、自分で替えたカーテン（設定ファイル）と、管理会社の名簿の名前（rc の行）は残る。purge はカーテンも外して名簿からも消す。autoremove は、引っ越しのときに一緒に借りたトランクルームを、使う人がいなくなったので返す作業である。
ただし崩れる点: 実際の退去は元に戻して返すのが決まりだが、apt は残すのが既定である。設定まで消すには、利用者が purge と言わなければならない。
手を動かす: 実践編の演習05は、最初から入っている labweb を、設定ファイルも、一緒に入った labweb-data も残さずに消す課題である。 labweb-data は名前を打たずに消す。判定は dpkg の台帳（rc が残っていないか）と、/etc/labweb.conf の有無を見る。
確認

入っているパッケージを、設定ファイルも含めて削除するコマンドとして正しいものを2つ選べ。
(a) apt-get remove pkg　(b) apt-get purge pkg　(c) apt-get autoremove　(d) apt-get remove --purge pkg

答え

(b) と (d)。(a) は設定ファイルを残し、台帳に rc が残る（実測）。 (c) は自動で入って要らなくなった依存を消すもので、pkg 自身の設定ファイルは消さない。

確認

dpkg -l の結果で、行頭が rc のパッケージがあった。どういう状態で、完全に消すにはどうするか。

答え

削除されたが、設定ファイルだけが残っている状態（Remove / Conf-files）。sudo apt purge パッケージ名 で設定ファイルごと消すと、台帳の行も消える（実測）。

確認

labapp を apt remove したあと、liblab が残っていた。なぜ残ったのか。名前を指定せずに片付けるにはどうするか。

答え

liblab は labapp の依存関係で自動で入ったものだが、remove は名指しされた labapp しか消さないから。 sudo apt autoremove で、自動で入った印があって誰にも必要とされていないものを、apt が探して消す（実測で liblab が消えた）。

この章で分かったこと

持ち帰ってほしいこと

  • apt install は依存関係（Depends）を読んで、足りないものも一緒に入れる（additional packages）。そのときは [Y/n] と尋ねる
  • 依存関係は apt-cache depends（必要とするもの）・rdepends（必要とされているもの）・showpkg（版ごとの依存と逆向きをまとめて）で、入れる前にも調べられる
  • apt は自動で入れたものに印を付ける（apt-mark showauto。記録は /var/lib/apt/extended_states）
  • remove は設定ファイル（conffile）を残して台帳に rc、purge は設定ファイルも台帳の行も消す、autoremove は誰にも要らなくなった自動の依存を消す
