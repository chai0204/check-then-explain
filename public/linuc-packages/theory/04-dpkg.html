4. dpkg は依存を読めるが、取りに行かない

dpkg -i で .deb を入れると、足りない依存関係を見つけた時点で止まる。止まるのに、中身は展開したまま残る。台帳には iU（展開済み・設定前）と書かれ、そのあいだ apt は関係ないパッケージの操作まで断る。

前提: 第3章まで読了前提: Debian 系の檻を起動し直した直後所要 20分影響度 B出題範囲 1.04.2（重要度1）最終検証 2026-10-13

この章のゴール

  • dpkg の主なオプション（-i -r -P -l -L -S -s -c -I -V）を、台帳を書くもの・台帳を読むもの・ファイルを読むものに分けて言える
  • dpkg -i が依存関係で止まったときの台帳の状態と、続きのやり方を言える
  • dpkg -l の行頭の記号（ii rc iU un）を読める
  • dpkg-reconfigure が何をやり直すのかを説明できる
ここで覚えなくていいこと: dpkg --set-selections、dpkg-divert、トリガ、パッケージの中のスクリプト（preinst / postinst など）の書き方、debconf のデータベースの形式。dpkg-reconfigure は「入れたときの質問をもう一度してもらう」とだけ分かれば足りる。

dpkg -i は、足りないものを取りに行かない

この節で分かること: 依存関係が足りないとき、dpkg がどこまで進めて、何を残すか。

第2章では apt install labapp が liblab を足して入れた。同じ labapp を、今度は .deb のファイルを指定して dpkg で入れる。

ふつうこう考える

dpkg -i もパッケージを入れるコマンドなのだから、足りない liblab も一緒に入れてくれるはずだ。 少なくとも、入れられないなら何もせずに終わるだろう。

(Reading database ... 12824 files and directories currently installed.)

  Package liblab is not installed.

 labapp
exit=1
$ dpkg -l labapp liblab

| Status=Not/Inst/Conf-files/Unpacked/halF-conf/Half-inst/trig-aWait/Trig-pend

$ labapp; echo "exit=$?"
/usr/bin/labapp: 3: .: cannot open /usr/lib/liblab/liblab.sh: No such file
exit=2
だめな理由: どちらの予想も外れた。dpkg は liblab を取りに行かず、 かといって何もせずに終わってもいない。展開（Unpacking）までは進めて、設定の手前で止まっている。 台帳には labapp が iU（入れたい／展開済み）と書かれた（liblab の un は、すぐ下で確かめるとおり台帳の行ではない）。 /usr/bin/labapp は置かれているので、打つと動きかけて、liblab のファイルが無いところで失敗する。 dpkg は control の Depends: を読めるので「足りない」とは分かる。 しかしどこへ取りに行けばいいかを知らない。リポジトリの目録を持っているのは apt のほうである。

liblab の un（知らない／入っていない）は、台帳に liblab の行ができたという意味ではない。同じ状態を作って台帳を直接見ると、liblab の行は1つも無い（別の檻で記録した）。

$ grep -c '^Package: liblab$' /var/lib/dpkg/status
0
$ dpkg -s labapp | grep -E '^(Status|Depends):'
Status: install ok unpacked
Depends: liblab (>= 1.0)

台帳にあるのは labapp の行だけで、その Depends: に liblab の名前が出てくる。dpkg -l は名前を指定されたので、台帳に行の無い liblab を un として表示しただけである。

しかもこの状態は、関係ないパッケージの操作も止める。labhello を上げようとする。

$ sudo apt install -y labhello; echo "exit=$?"
...
You might want to run 'apt --fix-broken install' to correct these.
The following packages have unmet dependencies:
 labapp : Depends: liblab (>= 1.0) but it is not going to be installed
E: Unmet dependencies. Try 'apt --fix-broken install' with no packages (or specify a solution).
exit=100

apt は「台帳の全体で依存関係が満たされた状態」しか作らない。依存関係が満たされないもの（ここでは liblab の無い labapp）が残っていると、それを直す以外の操作を受け付けない。直し方は出力の中に書いてある。

$ sudo apt --fix-broken install -y
...
Correcting dependencies... Done
The following additional packages will be installed:
  liblab
The following NEW packages will be installed:
  liblab
0 upgraded, 1 newly installed, 0 to remove and 3 not upgraded.
1 not fully installed or removed.
Need to get 0 B/746 B of archives.
After this operation, 36.9 kB of additional disk space will be used.
Get:1 file:/srv/lab-repo lab/main amd64 liblab all 1.0 [746 B]
...
Setting up liblab (1.0) ...
Setting up labapp (1.0) ...
$ dpkg -l labapp liblab
...
ii  labapp         1.0          all          sample application that needs liblab
ii  liblab         1.0          all          small shell library for lab programs
$ labapp
liblab: hello from labapp 1.0

1 not fully installed or removed. が labapp の iU のことで、apt が目録から liblab を取ってきて入れ、続けて labapp の設定（Setting up）を済ませた。apt --fix-broken install は apt-get -f install とも書く（-f = fix-broken）。

断られた原因は iU そのものではなく、満たされない依存関係のほうである。依存関係が満たされている iU なら、apt は断らずに、次の操作のついでに設定を済ませる。dpkg --unpack（展開だけして設定しない）で依存の無い labhello を iU にしてから、別のパッケージを入れた記録である（別の檻）。

$ sudo dpkg --unpack /srv/lab-repo/pool/main/l/labhello/labhello_1.1_all.deb
...
Unpacking labhello (1.1) over (1.0) ...
$ dpkg -l labhello | tail -1
iU  labhello       1.1          all          prints its own version
$ sudo apt install -y liblab
...
1 not fully installed or removed.
...
Setting up labhello (1.1) ...
Setting up liblab (1.0) ...
$ dpkg -l labhello | tail -1
ii  labhello       1.1          all          prints its own version
やり方依存関係結果
dpkg -i ファイル.deb読んで確かめるだけ。足りなければ止まる展開済み・設定前（iU）で残る
続けて apt --fix-broken install目録から足りないものを取ってくる全部 ii になる
apt install ./ファイル.deb最初から目録で解決する1回で ii になる（./ を付けないとパッケージ名として探される）
依存を先に入れてから dpkg --configure -a自分で揃える止まっていた設定を全部やり直す
たとえ: 組み立て家具の箱を開けたら「別売りの部品 B が要る」と書いてあった場面に近い。 dpkg は箱を開けて部品を床に並べたところで手を止める店員で、 apt は倉庫の在庫表を見て部品 B を取ってくる店員である。
ただし崩れる点: 人の店員なら「部品が無いので、いったん箱に戻します」とできるが、 dpkg は並べたまま止まり、台帳に iU と書く。片付けるか続けるかは、利用者が決める。

この節で分かること: 入っているパッケージについて、dpkg に何を聞けるか。

dpkg -l は台帳の一覧（--list）で、名前を渡すとワイルドカードで絞れる。行頭の2文字（3文字目はエラーの印）は、見出しの3行に書いてある凡例の頭文字である。

unUnknown（知らない）Not（入っていない）台帳に行は無いが、labapp の Depends: に名前が出てくる liblab（dpkg -l が表示だけする）

オプション長い名前相手すること
-i--install.deb ファイル展開して設定し、台帳に書く
-r--removeパッケージ名中身を消す。conffile は残す（rc）。conffile の無いパッケージは台帳の行も消える
-P--purgeパッケージ名設定ファイルも消し、台帳の行も消す
-l--list台帳一覧と状態
-s--status台帳1つのパッケージの詳しい状態
-L--listfiles台帳パッケージが置いたファイルの一覧
-S--search台帳ファイルを置いたパッケージを探す
-V--verify台帳とディスク入れたときと違うファイルを出す（次の節）
-c--contents.deb ファイル中のファイルの一覧
-I--info.deb ファイル中の control（名前・版・依存）
—--configure -a台帳設定前で止まっているものを全部設定する

台帳と照らし合わせる — dpkg -V

この節で分かること: パッケージの「整合性」を、台帳の何と比べて確かめているか。

第1章で見た .md5sums（入れたときの中身の要約）と、いまのファイルを比べるのが dpkg -V（--verify）である。2か所書き換えて比べる。

$ dpkg -V labapp; echo "exit=$?"
exit=0
$ echo 'greeting="こんにちは"' | sudo tee -a /etc/labapp.conf
greeting="こんにちは"
$ echo '# 書き足した' | sudo tee -a /usr/bin/labapp
# 書き足した
$ dpkg -V labapp; echo "exit=$?"
??5?????? c /etc/labapp.conf
??5??????   /usr/bin/labapp
exit=0

違うファイルだけが出る。何も違わなければ何も出ない。9文字の欄のうち3つ目の 5 が「中身の要約（MD5）が違う」で、? は「確かめていない」である（dpkg の台帳には MD5 しか無いので、他の欄は確かめようがない）。c は設定ファイル（conffile）の印。そして違いが見つかっても終了コードは 0 だった。スクリプトで $? だけを見ると見逃す。出力が空かどうかを見ること。

入れ直すと、中身は台帳どおりに戻る。ただし設定ファイルは戻らない。

$ sudo apt install -y --reinstall labapp
...
0 upgraded, 0 newly installed, 1 reinstalled, 0 to remove and 3 not upgraded.
...
Unpacking labapp (1.0) over (1.0) ...
Setting up labapp (1.0) ...
$ dpkg -V labapp; echo "exit=$?"
??5?????? c /etc/labapp.conf
exit=0

/usr/bin/labapp の行は消え、/etc/labapp.conf の行だけが残った。利用者が書き換えた設定を、入れ直しで勝手に元へ戻さないためである（第2章の remove が設定を残すのと同じ考え方）。同じ照らし合わせは RPM 系では rpm -V で、第6章でもう一度出てくる。

たとえ: 納品書の控えと、倉庫の現物を突き合わせる棚卸しに近い。 控え（.md5sums）に書いてある要約と、いまの現物の要約が違うものだけを報告する。
ただし崩れる点: 棚卸しなら数・色・傷も見るが、dpkg の控えには中身の要約しか無い。 権限や持ち主が変わっていても、dpkg -V は ? のまま何も言わない。

消す — -r と -P

この節で分かること: dpkg で消すときに、何が拒まれ、何が残るか。
$ sudo dpkg -r liblab; echo "exit=$?"
dpkg: dependency problems prevent removal of liblab:
 labapp depends on liblab (>= 1.0).

dpkg: error processing package liblab (--remove):
 dependency problems - not removing
Errors were encountered while processing:
 liblab
exit=1

labapp が依存している liblab は、先に消すことを拒まれた。台帳の Depends: を見て、壊れる組み合わせを作らない。入れるときに依存を取りに行かないのに、消すときは依存を守る。どちらも台帳だけでできる判断だからである。

$ sudo dpkg -r labapp
(Reading database ... 12830 files and directories currently installed.)
Removing labapp (1.0) ...
$ dpkg -l labapp | tail -1
rc  labapp         1.0          all          sample application that needs liblab
$ ls -l /etc/labapp.conf
-rw-r--r-- 1 root root 120 Oct 13 11:40 /etc/labapp.conf
$ sudo dpkg -P labapp
(Reading database ... 12827 files and directories currently installed.)
Purging configuration files for labapp (1.0) ...
$ dpkg -l labapp; echo "exit=$?"
dpkg-query: no packages found matching labapp
exit=1
$ sudo dpkg -P liblab
(Reading database ... 12826 files and directories currently installed.)
Removing liblab (1.0) ...

-r は rc を残し（書き換えた 120 バイトの設定ファイルも残っている）、-P がそれを消した。apt の remove / purge は、この2つを呼んでいる。入っているパッケージにいきなり -P を使うと、中身と設定ファイルが一度に消える（最後の liblab）。dpkg に autoremove にあたるものは無い。「自動で入った」という印は apt だけが持っているからだ。

設定をやり直す — dpkg-reconfigure

この節で分かること: 入れたあとで、パッケージの設定をもう一度やる方法。

パッケージの中には、入れるときに質問をするものがある。代表がタイムゾーンを決める tzdata で、答えは debconf というしくみが覚えている。いまの答えは UTC である。

$ cat /etc/timezone; ls -l /etc/localtime
Etc/UTC
lrwxrwxrwx 1 root root 27 Sep 30 19:32 /etc/localtime -> /usr/share/zoneinfo/Etc/UTC
$ env -u TZ date -d @1790812800
Thu Oct  1 00:00:00 UTC 2026
$ sudo debconf-show tzdata | sort
  tzdata/Areas: Etc
...
  tzdata/Zones/Etc: UTC
...

（env -u TZ は、この檻が環境変数 TZ=Asia/Tokyo を持っているので、それを外して /etc/localtime の効き目だけを見るためである。debconf-show の行の順番は打つたびに変わるので、sort で並べている。）

質問をもう一度してもらうのが dpkg-reconfigure である。画面で sudo dpkg-reconfigure tzdata と打つと、地域の一覧が出るので矢印キーで Asia を選んで Enter、次の一覧で Tokyo を選んで Enter を押す。ここでは同じ質問を文字だけの形（-f teletype）で出させ、番号を流し込んで記録した。

Configuring tzdata
------------------
...

  2. America     5. Asia      8. Europe     11. Etc
  3. Antarctica  6. Atlantic  9. Indian     12. Legacy
Geographic area:
Please select the city or region corresponding to your time zone.

$ cat /etc/timezone; ls -l /etc/localtime

dpkg-reconfigure は、パッケージを入れたときの「質問して設定する」手順を、入れ直さずにもう一度走らせる。答えは debconf の記録に残り（* は「その質問がもう出された」印。下の man の記述を参照）、tzdata の設定の手順がその答えで /etc/timezone と /etc/localtime を書き直した。設定ファイルを手で直す代わりに、パッケージ自身に直させる方法である。

$ MANWIDTH=80 man debconf-show | sed -n "/The most common use/,/with an/p"
       The most common use is "debconf-show packagename", which displays all
       items in the debconf database owned by a given package, and their
       current values.  Questions that have been asked already are prefixed
       with an '*'.

* は「今回答えたもの」ではなく「すでに尋ねられた質問」の印である（別の檻で記録した）。tzdata は Areas と Zones/Asia の2問を尋ねたので、その2行に付いた。

たとえ: 家電の「初期設定をやり直す」メニューに近い。 買ったときに答えた質問（地域・言語）にもう一度答えると、本体の設定が書き換わる。
ただし崩れる点: 家電は設定画面を出し直すだけだが、dpkg-reconfigure はパッケージの設定の手順を丸ごと走らせ直す。 答えと違う値を設定ファイルに手で書いていた場合、それを上書きすることがある。
手を動かす: 実践編の演習03は、リポジトリに無い単体の .deb（labnote）を、動く状態まで入れる課題である。 dpkg -i で止まったところから続ける。判定は dpkg の台帳で labnote と依存先の両方が ii になり、labnote が実際に動くかを見る。
確認

インストール済みの Debian パッケージの一覧を表示するコマンドとして正しいものはどれか。
(a) dpkg -L　(b) dpkg -l　(c) dpkg -c　(d) dpkg -S

答え

(b)。-l（--list）が台帳の一覧。(a) の -L は1つのパッケージが置いたファイルの一覧、 (c) の -c は .deb ファイルの中身の一覧、(d) の -S はファイルからパッケージを探す。大文字と小文字で意味が違う。

確認

dpkg -l の結果で、行頭が rc のパッケージがあった。どういう状態で、完全に消すにはどうするか。

答え

削除されたが設定ファイルだけが残っている状態（Remove / Conf-files）。dpkg -P パッケージ名 （または apt purge パッケージ名）で設定ファイルごと消すと、台帳の行も消える。

確認

インストール済みのパッケージを再設定するコマンドはどれか。
(a) dpkg --configure　(b) dpkg-reconfigure　(c) apt-get install --reinstall　(d) debconf-show

答え

(b)。入れたときの質問をもう一度出して、その答えで設定し直す（例: dpkg-reconfigure tzdata）。 (a) は展開済み・設定前（iU）で止まっているものを設定するもので、設定済みのものの質問はしない。 (c) は中身を入れ直すが、書き換えた設定ファイルは戻さない（dpkg -V で実測）。(d) は記録された答えを見るだけ。

確認

dpkg -i foo.deb を実行したところ、依存関係のエラーで foo が設定されずに残った。 依存するパッケージをリポジトリから取ってきて、foo の設定まで済ませるコマンドを答えよ。

答え

apt --fix-broken install（apt-get -f install）。dpkg は依存を取りに行けないので、目録を持つ apt に続きをさせる。 最初から apt install ./foo.deb と打てば、依存も解決して1回で入る。

この章で分かったこと

持ち帰ってほしいこと

  • dpkg -i は依存関係を読めるが取りに行かない。足りなければ展開済み・設定前（iU）で止まり、ファイルは置かれたまま残る
  • 依存関係が満たされないまま iU が残っていると、apt は別の操作も断る。apt --fix-broken install（apt-get -f install）が目録から足りないものを取って続きをする（依存が満たされた iU なら、apt は次の操作のついでに設定する）
  • 台帳を読む: -l 一覧・-s 状態・-L パッケージ→ファイル・-S ファイル→パッケージ。ファイルを読む: -c 中身・-I 情報
  • -r は conffile を残して rc（conffile の無いパッケージは台帳から消える）、-P は全部消す。依存されているものは -r を拒まれる
  • dpkg -V は違うファイルだけを出し、違いがあっても終了コードは 0。入れ直しても書き換えた設定ファイルは戻らない
  • dpkg-reconfigure は入れたときの質問をやり直し、その答えで設定を書き直す
