6. パッケージはどこから来るか

前の章までにやったこと: パッケージを入れる・調べる・消すを一通りやり、台帳とファイルの関係（第4章）と、依存関係で一緒に入るもの・消しても残るもの（第5章）を確かめた。そのたびに apt は file:/srv/lab-repo というリポジトリから取ってきていた（Get: の行）。この章でやること: apt がどのリポジトリへ、何を見て取りに行くのかを確かめる。新しい版の置き場を足して、labhello を新しい版に上げる。最後に、名前やファイルからパッケージを探す。

前提: 第5章まで読了前提: Debian 系の檻を起動し直した直後所要 25分影響度 B出題範囲 1.04.1（重要度3）最終検証 2026-10-20

この章のゴール

  • /etc/apt/sources.list の1行（種類・URI・ディストリビューション・コンポーネント）を読み、行を足す
  • リポジトリの区分を足してから、新しい版に上がるまでに何が要るかを、実際に上げて確かめる
  • 入っていないパッケージを、名前と説明（apt search）やファイル名（apt-file search）から探す
  • apt と apt-get・apt-cache の使い分けを確かめる
ここで覚えなくていいこと: リポジトリに署名する手順と鍵の配り方、署名を確かめるしくみの細部、ミラー（同じ中身を配る別のサーバ）の選び方、ソースパッケージ（deb-src）、優先度の数字（500・100）の決め方の細部。apt-cache policy の数字は「どこから来た版か」の印として読めれば足りる。

どこから来た版か — apt-cache policy

この節で分かること: 入っている版と、入れられる版が、それぞれどこに載っているか。

labhello を入れて（出力は略す）、apt-cache policy で版の出どころを聞く。apt-cache は第5章で使った、パッケージの情報を引くだけのコマンドである。

$ sudo apt install labhello
...
Setting up labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...
$ apt-cache policy labhello
labhello:
  Installed: 1.0
  Candidate: 1.0
  Version table:
 *** 1.0 500
        500 file:/srv/lab-repo lab/main amd64 Packages
        100 /var/lib/dpkg/status
行意味
Installed: 1.0いま入っている版（台帳に書いてある版）
Candidate: 1.0入れるならこの版（入れられる版のうち、いちばん新しいもの）
*** 1.0 500*** はいま入っている版の印。500 は優先度（同じ名前の版が何か所かにあるとき、どれを選ぶかの数）
500 file:/srv/lab-repo lab/main amd64 Packagesこの版が、リポジトリ file:/srv/lab-repo の区分 lab の一覧に載っている
100 /var/lib/dpkg/statusこの版が、台帳（第4章で開いたファイル）に載っている

apt は、リポジトリの一覧と台帳の両方を見比べて答えている。いまは入っている版と入れられる版が同じ 1.0 なので、上げるものは無い。

リポジトリの中 — 中身と目録

この節で分かること: リポジトリが、何と何でできているか。

この檻のリポジトリは、ただのディレクトリである。中のファイルを全部並べる。find は、指定したディレクトリの下を順にたどってファイルを探すコマンドで、-type f は「ふつうのファイルだけ」という指定である。sort は受け取った行を並べ替える（find はたどった順に出すので、読みやすいように並べた）。

2つに分かれている。pool/ の下が中身（.deb ファイル）で、dists/ の下が目録（リポジトリにあるパッケージの名前・版・依存関係・置き場所を並べた一覧）である。dists/lab/ と dists/lab-updates/ の2つの区分があり、pool/ には labhello の 1.0 と 1.1 が両方置いてある。区分ごとの Release は、その区分にある目録のファイルの一覧（大きさとダイジェストつき）、Packages がパッケージの一覧、Contents-amd64 が「どのファイルがどのパッケージに入っているか」の一覧で、.gz の付いたものは gzip で縮めたものである。目録の中身を見る。zcat は gzip で縮めたファイルを広げながら表示するコマンドである。

第3章の dpkg -I で見た情報に、Filename:（中身の置き場所）と、Size:・MD5sum:・SHA256: などの値が足されている。値は、取ってきた .deb ファイルが壊れていないかを確かめるためのダイジェストである。区分 lab の目録には、labhello は 1.0 しか載っていない。1.1 は lab-updates の目録に載っている。

たとえ: 倉庫と、その在庫の一覧表に近い。品物（.deb）は棚（pool/）に並び、一覧表（目録）に「どの棚に・何の何版が・どんな大きさで」と書いてある。apt は一覧表を見て、棚から取ってくる。
ただし崩れる点: 人なら倉庫に行けば棚を直接見られるが、apt は一覧表しか見ない。棚に品物を置いても、一覧表に載っていなければ「無い」ことになる（pool/ に 1.1 があるのに、Candidate は 1.0 だった）。

apt が見に行く場所の表 — sources.list

この節で分かること: どのリポジトリのどの区分を使うかを、どこに書くか。

apt がどのリポジトリを使うかは、/etc/apt/sources.list に書いてある。

$ cat /etc/apt/sources.list
# Ubuntu sources have moved to the /etc/apt/sources.list.d/ubuntu.sources
# file, which uses the deb822 format. Use deb822-formatted .sources files
# to manage package sources in the /etc/apt/sources.list.d/ directory.
# See the sources.list(5) manual page for details.

# 檻の中の練習用リポジトリ（確かめて説明する LinuC 主題1.04）。
# 署名していないので [trusted=yes] で署名の確認を外している。本物のリポジトリでは外さない。
deb [trusted=yes] file:/srv/lab-repo lab main

# で始まる行は説明書き（コメント）で、最後の1行が設定である。空白で区切って読む（[ ] は書かなくてもよい）。

deb  [trusted=yes]  file:/srv/lab-repo  lab                     main
^^^  ^^^^^^^^^^^^^  ^^^^^^^^^^^^^^^^^^  ^^^                     ^^^^
種類  オプション      URI（どこ）          ディストリビューション   コンポーネント（複数並べられる）
欄この行では何のためにあるか
種類deb取ってくるものの種類。deb はそのまま入れられるパッケージ（deb-src ならプログラムの元のソース）
オプション[trusted=yes]この行だけの特別な扱い。ここでは「署名を確かめない」。署名は、リポジトリの作り手が目録に付ける印で、誰が作ったか・途中で書き換えられていないかを確かめるのに使う。作り手だけが持つ鍵で付け、対になる公開鍵（誰に配ってもよい鍵）で確かめる（この練習用リポジトリには署名を付けていないので、確かめないことにしている。本物のリポジトリには、この指定を付けない）
URIfile:/srv/lab-repoリポジトリの場所。ふつうは http:// や https:// で始まるサーバ
ディストリビューションlabリポジトリの中の区分（スイートとも呼ぶ）。dists/ の下のディレクトリの名前
コンポーネントmain区分の中をさらに分けたもの。dists/lab/ の下のディレクトリの名前

Ubuntu 本体の分は、1行目のコメントのとおり、別のファイルに別の書き方で書いてある。

$ cat /etc/apt/sources.list.d/ubuntu.sources
Types: deb
URIs: https://snapshot.ubuntu.com/ubuntu/20260929T000000Z
Suites: noble noble-updates noble-security
Components: main universe
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg

これは deb822 形式という書き方で、Ubuntu 24.04 からの既定である。URIs の snapshot.ubuntu.com/…/20260929T000000Z は、Ubuntu のリポジトリを 2026-09-29 の時点のまま残した写しで、この檻は、いつ起動しても同じ版を見るように、そこを指している。中身は同じで、欄に名前が付いている（Types が種類、URIs が URI、Suites がディストリビューション、Components がコンポーネント、Signed-By は署名を確かめる鍵の場所）。Suites: の noble は Ubuntu 24.04 が出たときの版の区分、noble-updates はその後に出た修正版、noble-security は安全のための修正版の区分である。練習用のリポジトリの lab と lab-updates も、同じ分け方にしてある。/etc/apt/sources.list.d/ には、名前が .list（1行の形式）か .sources（deb822 形式）で終わるファイルをいくつでも置け、どれも /etc/apt/sources.list と同じように読まれる。

新しい版の置き場を足して、上げる

この節で分かること: リポジトリの区分を足したあと、新しい版を入れるまでに要ること。

labhello 1.1 が載っている区分 lab-updates を、apt の表に足す。/etc/apt/sources.list.d/ に1行のファイルを置く。

$ apt-cache policy labhello

2つのコマンドは名前が似ているが、することが違う。

コマンド何のためにあるかパッケージを入れ替えるか
apt updateリポジトリの目録を取り直して、写しを新しくする1つも入れ替えない
apt upgrade入っているパッケージを、写しに載っている新しい版に上げる上げる（上げるのに要るなら新しく入れることもあるが、消しはしない）
apt full-upgrade全体を上げるために、必要なら消すこともする上げる・入れる・消す
apt install 名前入っていなければ入れ、入っていて新しい版があれば上げるその1つだけ
たとえ: apt update は新しいカタログを取り寄せること、apt upgrade はカタログを見て、持っている古い型の品物を新しい型に買い替えることに近い。カタログを取り寄せただけでは、家の中の品物は1つも変わらない。
ただし崩れる点: 人なら、手元のカタログが古いと気づけるが、apt は手元の写しを疑わない。apt update で取り直すまで、どれだけ古くても「これが最新」として比べる。

apt と apt-get・apt-cache

この節で分かること: 似た名前のコマンドを、どう使い分けるか。

第5章で apt-get（apt より前からある、ほぼ同じ働きのコマンド）と apt-cache の名前を出した。apt は、この2つのよく使う働きを、人が画面で打ちやすいようにまとめた入口である。出力の行き先が画面ではなくパイプだと、注意を出す。

$ apt show labhello | head -3
WARNING: apt does not have a stable CLI interface. Use with caution in scripts.

Package: labhello
Version: 1.1
Priority: optional

WARNING: apt does not have a stable CLI interface. Use with caution in scripts. は「apt のコマンドの形は今後変わりうるので、スクリプト（コマンドを並べて自動で動かすファイル）では注意して使え」という意味である。パイプの先はスクリプトかもしれないので出している（画面に直接出すときは出ない）。スクリプトには、形を変えない apt-get と apt-cache を使う。

apt（人が画面で打つ）apt-get / apt-cache（スクリプトに書く）何をするか
apt updateapt-get update目録を取り直す
apt install / remove / purge / autoremoveapt-get install / remove / purge / autoremove入れる・消す
apt upgrade / full-upgradeapt-get upgrade / dist-upgrade上げる（apt-get upgrade は、上げるのに新しいパッケージを入れる必要があるものを、上げずに残す）
apt search / apt showapt-cache search / apt-cache show目録を読む
apt downloadapt-get download入れずに .deb ファイルを取ってくる（第3章）

名前とファイルから探す — apt search と apt-file

この節で分かること: 入っていないパッケージを、名前や説明、ファイル名から探す方法。

apt search は、目録の名前と説明から語を探す。

$ apt search labhello
Sorting... Done
Full Text Search... Done
labhello/lab-updates,now 1.1 all [installed]
  prints its own version

見つかったパッケージが「名前/区分,now 版 アーキテクチャ [印]」と、その下の説明の2行で出る（now と [installed] は入っているものだけに付く）。名前も説明も分からず、「このファイルを入れるパッケージ」だけが分かっていることもある。第3章の dpkg -S は台帳を引くので、入っていないパッケージのファイルは知らない。

$ dpkg -S liblab.sh
dpkg-query: no path found matching pattern *liblab.sh*
$ apt-file search liblab.sh
liblab: /usr/lib/liblab/liblab.sh
$ apt-file list labapp
labapp: /etc/labapp.conf
labapp: /usr/bin/labapp
labapp: /usr/share/doc/labapp/README

apt-file は、目録のうち Contents（どのファイルがどのパッケージに入っているかの一覧）を引く道具である。search はファイル名からパッケージを、list はパッケージから中のファイルを、入っていなくても答える（dpkg -S に渡した liblab.sh のように、パスの一部だけでよい）。Contents は、さっきの apt update で Contents (deb) として一緒に取ってきた。

$ ls /var/lib/apt/lists/ | grep Contents
_srv_lab-repo_dists_lab-updates_main_Contents-amd64.lz4
_srv_lab-repo_dists_lab_main_Contents-amd64.lz4
$ apt-file search bin/dig

bin/dig（dig は、DNS ＝ ホスト名から IP アドレスなどを引くしくみ、を調べるコマンド）では何も出なかった。この檻では、apt-file が引く Contents を練習用のリポジトリの分だけに絞ってある。Ubuntu 本体の Contents は3つの区分で合わせて約 195MB あり、apt update のたびに取りに行くと重すぎるからである（設定は /etc/apt/apt.conf.d/60lab-apt-file。消して apt update すれば Ubuntu の分も引ける）。ふつうの Ubuntu で apt-file search bin/dig と打てば、dig を入れるパッケージの名前が出る。

聞きたいこと入っているものだけ（台帳）入っていなくてよい（目録）
名前や説明に語を含むパッケージ—apt search 語（apt-cache search）
このファイルはどのパッケージにあるかdpkg -S パスapt-file search パス
このパッケージにはどのファイルがあるかdpkg -L 名前apt-file list 名前
たとえ: 本の目次と巻末の索引に近い。目次（目録の Packages）では章の題名（パッケージの名前と説明）しか分からないが、巻末の索引（Contents）を引けば、ある言葉（ファイル名）がどの章にあるかが分かる。
ただし崩れる点: 本の索引は本と一緒に手元に来るが、Contents は別に取りに行く目録で、しかも目次よりずっと大きい。取らない設定にもでき、取っていなければ引けない。
手を動かす: 実践編の演習06は、まだ apt の表に入っていないリポジトリから、名前の分からないパッケージに入っている labcalc コマンドを使えるようにする課題である。 1行書く・目録を取りに行く・Contents を引く、の3つが要る。判定は labcalc を実際に動かし、dpkg の台帳と apt の目録を見る。
確認

/etc/apt/sources.list の次の1行について、各欄の意味を答えよ。
deb http://jp.archive.ubuntu.com/ubuntu noble main restricted

答え

deb がそのまま入れられるパッケージの取得先であること（ソースなら deb-src）、 http://jp.archive.ubuntu.com/ubuntu がリポジトリの URI、 noble がディストリビューション（区分）、main restricted がコンポーネント（2つ並べてある）。

確認

/etc/apt/sources.list.d/ に新しいリポジトリの行を足した。続けて apt install したところ E: Unable to locate package（パッケージが見つからない）になった。まず実行すべきコマンドは何か。

答え

sudo apt update（または sudo apt-get update）。apt が引くのは /var/lib/apt/lists/ の目録の写しで、行を足しただけでは写しは作られない（実測では、行を足したあとも Candidate が変わらなかった）。

確認

apt update と apt upgrade の違いを説明せよ。

答え

update は目録（パッケージの一覧）を取り直すだけで、パッケージは1つも入れ替えない。 upgrade は、手元の目録の新しい版と台帳の版を比べて、入っているパッケージを上げる。 実測では、update のあとに初めて labhello 1.1 が見え、upgrade で 1.0 から 1.1 に上がった。

確認

入っていないパッケージも含めて、/usr/bin/xyz というファイルを入れるパッケージを探すコマンドはどれか。
(a) dpkg -S /usr/bin/xyz　(b) dpkg -L xyz　(c) apt-file search /usr/bin/xyz　(d) apt-cache search xyz

答え

(c)。(a) は台帳を引くので入っているものしか答えない（実測）。(b) はパッケージからファイルを引くもので向きが逆。 (d) は名前と説明を探すもので、ファイル名は見ない。

この章で分かったこと

持ち帰ってほしいこと

  • リポジトリは、中身（pool/ の .deb）と目録（dists/ の一覧）でできている。apt は目録を見て、中身を取ってくる
  • どのリポジトリを使うかは /etc/apt/sources.list と /etc/apt/sources.list.d/ に「種類・URI・ディストリビューション・コンポーネント」で書く
  • apt が読むのは手元の目録の写し（/var/lib/apt/lists/）。表に書いただけでは変わらず、apt update で取り直す。apt upgrade は、その写しと台帳の版を比べて上げる
  • 入っていないパッケージは、名前と説明なら apt search、ファイル名なら apt-file search（Contents を引く）で探す
  • apt は人が画面で打つ入口、apt-get・apt-cache はスクリプトに書くもの
