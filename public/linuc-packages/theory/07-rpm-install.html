7. OK は、確かめられた範囲の OK

rpm -K で署名を確かめると、誰も署名していないパッケージが「OK」と出て、正しく署名されたパッケージが「NOT OK」と出る。OK は「確かめられたものは正しかった」という意味で、「署名が確かめられた」という意味ではない。確かめるには鍵が要り、鍵もまた台帳に載っていなければならない。

前提: 第6章まで読了前提: RPM 系の檻を起動し直した直後所要 22分影響度 B出題範囲 1.04.4（重要度1）最終検証 2026-10-13

この章のゴール

  • rpm -i / -U / -F / -e の違いを、入っている・いないの組み合わせで言える
  • rpm が依存関係で何を拒み、--nodeps で何が壊れるかを示せる
  • rpm -K の出力（digests / signatures / NOKEY）を読み、署名が確かめられたかを判断できる
  • 公開鍵を台帳に取り込む（rpm --import）と何が変わるかを言える
  • 7章で使ったコマンドを、どの帳簿を読むかで分けられる
ここで覚えなくていいこと: パッケージに署名する手順（rpm --addsign、gpg での鍵の作り方）、鍵の失効と差し替え、--force の細かい挙動、署名をどこまで強制するかの設定（%_pkgverify_level）。

rpm も依存を取りに行かない。ただし1つも入れずに止まる

この節で分かること: rpm が依存関係をどこまで扱うか。dpkg との違い。
$ sudo rpm -ivh /srv/lab-rpm/labapp-1.0-1.noarch.rpm; echo "exit=$?"
error: Failed dependencies:
	liblab >= 1.0 is needed by labapp-1.0-1.noarch
exit=1
$ sudo rpm -ivh /srv/lab-rpm/liblab-1.0-1.noarch.rpm /srv/lab-rpm/labapp-1.0-1.noarch.rpm
Verifying...                          ########################################
Preparing...                          ########################################
Updating / installing...
liblab-1.0-1                          ########################################
labapp-1.0-1                          ########################################

-i は install、v は経過を表示、h は進み具合を # で表示する。rpm も依存関係を読めるが、取りに行かない。第4章の dpkg -i と違うのは、足りないと分かった時点で1つも入れずに止まることである（dpkg は展開まで進めて iU を残した）。必要なファイルを全部並べて渡せば、rpm が順番（liblab が先）を決めて1回で入れる。

消すときも依存関係を守る。

$ sudo rpm -e liblab; echo "exit=$?"
error: Failed dependencies:
	liblab >= 1.0 is needed by (installed) labapp-1.0-1.noarch
exit=1
$ sudo rpm -e --nodeps liblab
$ labapp; echo "exit=$?"
/usr/bin/labapp: line 3: /usr/lib/liblab/liblab.sh: No such file or directory
exit=1
$ rpm -V labapp; echo "exit=$?"
Unsatisfied dependencies for labapp-1.0-1.noarch:
	liblab >= 1.0 is needed by (installed) labapp-1.0-1.noarch
exit=1

-e（erase）は、ほかのパッケージが必要としているものを消すのを拒む。--nodeps を付けると依存関係を確かめずに消し、黙って成功する。そして labapp は動かなくなった。rpm -V は、ファイルだけでなく依存関係が台帳の上で満たされているかも確かめていて、壊れた組み合わせを報告した。--nodeps は台帳の整合を自分で崩すオプションで、使ったら後始末も自分でする。

$ sudo rpm -ivh /srv/lab-rpm/liblab-1.0-1.noarch.rpm
Verifying...                          ########################################
Preparing...                          ########################################
Updating / installing...
liblab-1.0-1                          ########################################
$ sudo rpm -e labapp liblab
$ rpm -q labapp liblab; echo "exit=$?"
package labapp is not installed
package liblab is not installed
exit=2

並べて渡せば、消すときも順番を rpm が決める。rpm -e は成功すると何も出さない。

たとえ: 部品表を見て「この部品が無いと組めない」と言う検品係に近い。 足りなければ、作業台に何も載せずに作業票ごと突き返す。部品を取りに倉庫へ行くのは別の係（yum）の仕事である。
ただし崩れる点: 人の検品係なら「急ぎなので部品なしで組んで」と言われても事情を聞き返すが、 --nodeps を付けられた rpm は聞き返さない。組めないものを組んだまま、台帳の上は「入っている」にする。

-i・-U・-F は、入っているかどうかで動きが変わる

この節で分かること: 入れる・上げるの3つのオプションの違い。

いま labhello は 1.0 が入っていて、labtool-data は入っていない。

$ rpm -q labhello labtool-data; echo "exit=$?"
labhello-1.0-1.noarch
package labtool-data is not installed
exit=1
$ sudo rpm -ivh /srv/lab-rpm/labhello-1.1-1.noarch.rpm; echo "exit=$?"
Verifying...                          ########################################
Preparing...                          ########################################
	file /usr/bin/labhello from install of labhello-1.1-1.noarch conflicts with file from package labhello-1.0-1.noarch
exit=1
$ sudo rpm -Fvh /srv/lab-rpm/labtool-data-1.0-1.noarch.rpm; echo "exit=$?"
exit=0
$ rpm -q labtool-data; echo "exit=$?"
package labtool-data is not installed
exit=1
$ sudo rpm -Fvh /srv/lab-rpm/labhello-1.1-1.noarch.rpm
Verifying...                          ########################################
Preparing...                          ########################################
Updating / installing...
labhello-1.1-1                        ########################################
Cleaning up / removing...
labhello-1.0-1                        ########################################
$ sudo rpm -Uvh /srv/lab-rpm/labtool-data-1.0-1.noarch.rpm
Verifying...                          ########################################
Preparing...                          ########################################
Updating / installing...
labtool-data-1.0-1                    ########################################
$ rpm -q labhello labtool-data
labhello-1.1-1.noarch
labtool-data-1.0-1.noarch

-i は「新しく入れる」で、古い版が入っていても上書きしない。同じファイルを2つの版が持つことになるので、衝突（conflicts）で止まった。-F（freshen）は「入っているものだけを新しくする」で、入っていない labtool-data には何もせず、終了コード 0 で黙って終わった。入っていた labhello は 1.1 に上がり、1.0 は片付けられた。-U（upgrade）は「入っていれば上げ、無ければ入れる」で、labtool-data を新しく入れた。

オプション入っていない古い版が入っている
-i（install）入れる止まる（衝突。古い版を残したまま並べて入れようとする）
-U（upgrade）入れる上げる（古い版を消す）
-F（freshen）何もしない（終了コード 0）上げる（古い版を消す）

カーネルのように複数の版を並べて残すものは、あえて -i で入れる（第5章の installonly_limit はその世代数だった）。

$ yum list installed labhello labtool-data
Installed Packages
labhello.noarch                            1.1-1                         @System
labtool-data.noarch                        1.0-1                         @System

rpm で直接入れたものは、yum から見ると @System になる。どのリポジトリから来たかの記録が無いからである（yum で入れれば @lab だった）。

たとえ: 名簿の更新の指示に近い。-i は「新しく名前を書け」、 -U は「名前があれば書き換え、無ければ足せ」、-F は「名前があるときだけ書き換えよ」である。
ただし崩れる点: 名簿なら同じ人の名前を2行書いても困るだけだが、rpm の -i は 同じファイルを持つ2つの版を見つけると、書く前に止まる。

rpm -K の OK は、何を確かめた OK か

この節で分かること: 署名を確かめる出力の読み方と、確かめるのに要るもの。

檻の /srv/lab-files/ には、リポジトリに属さない .rpm が2つ置いてある。labnosig は誰も署名していないもの、tree は AlmaLinux が署名した本物のパッケージである。もう1つ、演習04 で使う /srv/lab-tools-rpm のパッケージには「lab tools」という鍵で署名がしてある。3つを rpm -K（--checksig）で確かめる。

ふつうこう考える

rpm -K で OK と出れば、署名は確かめられた。NOT OK と出たら、壊れているか偽物だ。 署名の無いパッケージなら、少なくとも OK にはならないはずだ。

$ ls -l /srv/lab-files/
total 64
-rw-r--r-- 1 root root  6879 Oct 13 10:08 labnosig-1.0-1.noarch.rpm
-rw-r--r-- 1 root root 55988 Oct 13 10:08 tree-1.8.0-10.el9.x86_64.rpm
$ rpm -K /srv/lab-files/labnosig-1.0-1.noarch.rpm; echo "exit=$?"
/srv/lab-files/labnosig-1.0-1.noarch.rpm: digests OK
exit=0
$ rpm -K /srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm; echo "exit=$?"
/srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm: digests SIGNATURES NOT OK
exit=1
$ rpm -K /srv/lab-files/tree-1.8.0-10.el9.x86_64.rpm; echo "exit=$?"
/srv/lab-files/tree-1.8.0-10.el9.x86_64.rpm: digests signatures OK
exit=0
だめな理由: 署名の無い labnosig が OK で、署名のある lab-mathtools が NOT OK だった。 行の中の語を読むと理由が分かる。digests は「中身の要約（ダイジェスト）が一致した＝壊れていない」、 signatures は「署名を鍵で確かめた」である。labnosig には署名が無いので signatures という語自体が出ず、 確かめられた digests だけが OK になった。lab-mathtools は署名を持っているが、 それを確かめる鍵が手元に無いので、SIGNATURES が大文字（だめだったもの）で出た。 OK は「確かめられたものは全部正しかった」であって、「作った人が確かめられた」ではない。

-v を足すと、何をどう確かめたかが1行ずつ出る。

$ rpm -Kv /srv/lab-files/labnosig-1.0-1.noarch.rpm
/srv/lab-files/labnosig-1.0-1.noarch.rpm:
    Header SHA256 digest: OK
    Header SHA1 digest: OK
    Payload SHA256 digest: OK
    MD5 digest: OK
$ rpm -Kv /srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm
/srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm:
    Header V4 RSA/SHA256 Signature, key ID 484bd981: NOKEY
    Header SHA256 digest: OK
    Header SHA1 digest: OK
    Payload SHA256 digest: OK
    MD5 digest: OK
$ rpm -Kv /srv/lab-files/tree-1.8.0-10.el9.x86_64.rpm
/srv/lab-files/tree-1.8.0-10.el9.x86_64.rpm:
    Header V4 RSA/SHA256 Signature, key ID b86b3716: OK
    Header SHA256 digest: OK
    Header SHA1 digest: OK
    Payload SHA256 digest: OK
    V4 RSA/SHA256 Signature, key ID b86b3716: OK
    MD5 digest: OK

labnosig には Signature の行が1つも無い。lab-mathtools の NOKEY は「鍵 484bd981 の署名があるが、その鍵を持っていない」で、改ざんを見つけたという意味ではない（改ざんなら BAD と出る。すぐ後で確かめる）。tree は AlmaLinux の鍵 b86b3716 で確かめられた。

rpm が「持っている鍵」は、台帳に入っている。鍵は gpg-pubkey という名前の、ファイルを持たないパッケージとして記録される。

$ rpm -q gpg-pubkey --qf '%{NAME}-%{VERSION}-%{RELEASE}\t%{SUMMARY}\n'
gpg-pubkey-b86b3716-61e69f29	AlmaLinux OS 9 <packager@almalinux.org> public key
gpg-pubkey-93f77b82-6acd849f	lab packages <lab@example.invalid> public key
$ head -3 /srv/lab-tools-rpm/RPM-GPG-KEY-lab-tools
-----BEGIN PGP PUBLIC KEY BLOCK-----

mQGNBGrNhJ8BDACs4CZvLuZBw9OXnQ8OZ7QlK2pVIlW1nNDyBJD8XBlDHAEU6M7G
$ sudo rpm --import /srv/lab-tools-rpm/RPM-GPG-KEY-lab-tools
$ rpm -q gpg-pubkey --qf '%{NAME}-%{VERSION}-%{RELEASE}\t%{SUMMARY}\n'
gpg-pubkey-b86b3716-61e69f29	AlmaLinux OS 9 <packager@almalinux.org> public key
gpg-pubkey-93f77b82-6acd849f	lab packages <lab@example.invalid> public key
gpg-pubkey-484bd981-6acd849f	lab tools <tools@example.invalid> public key
$ rpm -K /srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm; echo "exit=$?"
/srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm: digests signatures OK
exit=0

gpg-pubkey- の後ろの8桁が鍵の ID で、NOKEY に出た 484bd981 と同じである。rpm --import で公開鍵のファイルを台帳に取り込むと、同じパッケージが signatures OK になった。パッケージは1バイトも変わっていない。変わったのは台帳のほうである。

逆に、パッケージのほうを1バイト変えるとどうなるか。tree を写して、末尾近くの1バイトを書き換える。

今度は DIGESTS まで大文字になった。中身（Payload）の要約が合わず BAD、中身にかかる署名も BAD である。鍵が無いときの NOKEY とは別の答えで、こちらが「壊れている・書き換えられている」の印になる。

rpm -K の出力（この檻・RHEL 8 以降）RHEL 7（rpm 4.11）での出方意味入れてよいか
digests signatures OKrsa sha1 md5 OK壊れておらず、持っている鍵で署名を確かめられた鍵を信じるなら、よい
digests OKsha1 md5 OK壊れていない。署名は無い（誰が作ったかは分からない）出どころを別の手段で確かめてから
digests SIGNATURES NOT OKRSA sha1 ((MD5) PGP) md5 NOT OK (MISSING KEYS: …)署名はあるが確かめられなかった（-Kv で NOKEY なら鍵が無い）正しい鍵を --import してから確かめ直す
DIGESTS SIGNATURES NOT OK—中身が壊れているか、書き換えられている（-Kv に BAD）入れない

表記は rpm の版で違う。この教材の記録は RHEL 8 以降（rpm 4.14 以降）の表記で、RHEL 7 の rpm 4.11 は digests / signatures という語を出さない（RHEL 7 の列は、別の環境で確かめられた出方である）。読み方は共通している。署名の語（RHEL 8 以降は signatures、RHEL 7 は rsa・pgp）が小文字で、最後が OK のときだけ、署名が確かめられている。大文字の語は、その確かめが失敗したことを表す。署名の無いものは、署名の語がそもそも出ずに OK になる。

そして rpm は、署名が無くても入れる。

$ sudo rpm -ivh /srv/lab-files/labnosig-1.0-1.noarch.rpm
Verifying...                          ########################################
Preparing...                          ########################################
Updating / installing...
labnosig-1.0-1                        ########################################
$ rpm -q --qf '%{NAME}: %{RSAHEADER:pgpsig}\n' labnosig labhello
labnosig: (none)
labhello: RSA/SHA256, Tue Oct 13 10:08:48 2026, Key ID 0ba6fe4393f77b82

入ったあとでも、どのパッケージに署名があったかは台帳で分かる（rpm -qi の Signature 欄も同じもの）。署名の確認を強制しているのは rpm ではなく yum のほうで、/etc/yum.conf と .repo の gpgcheck=1 がそれだった（第5章）。リポジトリから入れるとき、yum は鍵が台帳に無い署名を「確かめられない」として、入れるのを断る。.repo の gpgkey= に鍵の場所を書いておくと、yum は入れる前に「この鍵を取り込んでよいか」を尋ね、取り込んでから確かめる（演習04 で確かめる）。

たとえ: 書類の印鑑を、登録済みの印影の帳簿と照合する窓口に近い。 印鑑の無い書類は照合のしようが無いので、「照合で問題は見つからなかった」と言われる。 登録の無い印鑑の書類は「照合できない」と言われる。照合できるようになるには、印影を帳簿に登録する（--import）。
ただし崩れる点: 役所なら印鑑の無い書類はそもそも受け付けないが、rpm は受け付けて入れてしまう。 「印鑑の無いものは断る」は、窓口の規則（yum の gpgcheck=1）として別に決めてある。

7章が1つの事実から出ていた

この節で分かること: 主題1.04 のコマンドが多いのに覚えられる理由。

この教材で驚いた結果を並べる。

章驚いたこと読んでいた帳簿
1中身を置いても、dpkg も rpm も「入っていない」と言う台帳（/var/lib/dpkg・/var/lib/rpm）
2apt remove しても台帳に rc が残り、設定ファイルも残る台帳（と、apt の「自動で入った」の記録）
3ソースを書いても Unable to locate。dpkg -S は入っていないものを知らない目録の写し（/var/lib/apt/lists）／ Contents
4dpkg -i は依存を読めるのに取りに行かず、iU で止まるdpkg は台帳しか持たない。目録は apt のもの
5yum はリポジトリを足すと、そのまま入れられる目録の写し（/var/cache/dnf）を自分で取り直す
6rpm -V が黙るのは、台帳どおりだから台帳（入れたときの大きさ・権限・要約）
7署名の無いものが OK、鍵の無いものが NOT OK鍵の台帳（gpg-pubkey）

7つとも同じ形をしている。

パッケージのコマンドは、どれも帳簿を読んでいるだけである。
手元に入ったものの「台帳」（dpkg・rpm）か、リポジトリにあるものの「目録」（apt・yum）か。
答えが食い違ったら、どちらの帳簿を読んだかを先に疑う。

だから試験に並ぶ大量のオプションは、「どの帳簿を、どちら向きに引くか」で整理できる。

聞きたいこと台帳を引く（入っているものだけ）目録を引く（入っていなくてよい）
あるか・どの版かdpkg -l ／ rpm -q rpm -qaapt-cache policy ／ yum list
詳しい情報dpkg -s ／ rpm -qiapt-cache show ／ yum info
ファイル → パッケージdpkg -S ／ rpm -qfapt-file search ／ yum provides
パッケージ → ファイルdpkg -L ／ rpm -qlapt-file list ／ yum repoquery -l 名前（yum-utils の repoquery -l）
依存関係rpm -qR ／ rpm -q --whatrequiresapt-cache depends rdepends ／ yum deplist
台帳とディスクを比べるdpkg -V ／ rpm -V—
目録を取り直す—apt update ／ yum makecache（yum は自動でも取る）

ファイルそのもの（.deb / .rpm）に聞くのが3つ目の向きで、dpkg -I -c と rpm -qp… がそれにあたる。迷ったら、そのコマンドが「台帳・目録・ファイルのどれを開いているか」を先に考える。それが分かれば、入っていないパッケージに答えられるかどうか、root が要るかどうかまで決まる。root が要るのは、台帳・目録の写し・設定ファイルを書き換えるとき（入れる・消す・上げるのほか、目録の写しを書き換える apt update・apt-get update・apt-file update も。一般ユーザで打つと lock の Permission denied で止まる。第3章）。読むだけ（apt-cache・dpkg -l・rpm -q・yum info）と、手元に取るだけ（apt-get download・yumdownloader）は要らない。

手を動かす: 実践編の演習06は、yumdownloader で取ってきた .rpm を rpm だけで入れる課題で、この章の「rpm は依存を取りに行かない」をそのまま踏む。 演習04は、署名の確認（gpgcheck=1）を切らずに、別の鍵で署名されたリポジトリから入れる。判定は鍵が台帳に入ったかまで見る。
確認

インストールされているパッケージだけを新しい版に更新し、インストールされていなければ何もしない rpm のオプションはどれか。
(a) -i　(b) -U　(c) -F　(d) -e

答え

(c) -F（freshen）。実測では、入っていない labtool-data には何もせず終了コード 0、入っていた labhello は 1.1 に上げた。 (b) の -U は入っていなければ新しく入れる。(a) の -i は古い版が入っているとファイルの衝突で止まる。

確認

rpm -K foo.rpm の結果が digests SIGNATURES NOT OK だった。考えられる原因と、確かめ方を答えよ。

答え

署名はあるが、確かめられなかった（digests は小文字なので、中身の要約は合っている）。 rpm -Kv foo.rpm で NOKEY と出れば、その鍵が rpm の台帳に無いだけで、 正しい公開鍵を rpm --import で取り込めば確かめられる。取り込んである鍵の一覧は rpm -q gpg-pubkey で見られる。 （この表記は RHEL 8 以降のもので、RHEL 7 では同じ状態が RSA sha1 ((MD5) PGP) md5 NOT OK (MISSING KEYS: …) と出る。署名の語が大文字なのは同じ。） 中身が書き換えられていれば、実測のように DIGESTS まで大文字になり、-Kv に BAD が出る。

確認

依存関係を無視してパッケージを削除する rpm のコマンドを答えよ。また、そのあと何が起きうるか。

答え

rpm -e --nodeps パッケージ名。それを必要としていたパッケージが動かなくなる （実測: liblab を消すと labapp が No such file or directory で失敗し、rpm -V labapp が Unsatisfied dependencies を報告した）。

確認

署名の無い RPM パッケージを rpm -ivh で入れようとした。どうなるか。また、署名を確かめてから入れる仕組みはどこで有効にするか。

答え

入る（実測で labnosig が入った）。rpm 自身は署名の無いパッケージを拒まない。 署名の確認を強制するのは yum（dnf）で、/etc/yum.conf や .repo の gpgcheck=1 と、 鍵の場所を示す gpgkey= で設定する。

この章で分かったこと

持ち帰ってほしいこと

  • rpm -ivh は依存関係が足りないと1つも入れずに止まる。必要なファイルを並べて渡せば順番は rpm が決める
  • rpm -e は依存されているものを消さない。--nodeps は台帳の整合を崩し、rpm -V が Unsatisfied dependencies を報告する
  • -i は新しく入れる（古い版があれば衝突）、-U は上げるか入れる、-F は入っているものだけ上げる
  • rpm -K の digests OK は「署名が無い」。署名の語（RHEL 8 以降は signatures、RHEL 7 は rsa・pgp）が小文字で OK のときだけ、署名が確かめられている。大文字は失敗
  • 確かめる鍵は台帳（gpg-pubkey）に入っている。rpm --import で取り込む
  • 署名の確認を強制するのは yum の gpgcheck=1。rpm は署名が無くても入れる
  • 主題1.04 のコマンドは「台帳・目録・ファイルのどれを、どちら向きに引くか」で整理できる
