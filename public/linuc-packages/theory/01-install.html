1. パッケージを入れて、使って、消す

このコースでやること: Linux にソフトウェアを入れる・調べる・消す方法を、2つの系統の Linux で、実際に打って確かめる。Linux には、ソフトウェアの配り方と、それを扱う道具が違う系統がいくつかあり、ここでは代表の2つを使う。Debian 系（Debian と、それをもとに作られた Ubuntu など）と、RPM 系（Red Hat Enterprise Linux と、それと同じ作りの AlmaLinux など）である。第1〜8章は Debian 系で、第9〜11章は RPM 系で同じことをする。この章でやること: いちばん普通の使い方を1回やる。まだ入っていないコマンドを1つ入れて、使って、消す。始める前に要るもの: docker が動く PC と、端末（80 桁 × 24 行の大きさで確かめてある）。

前提: docker が動く前提: 端末でコマンドを打てる前提: sudo の意味が分かる所要 15分影響度 B出題範囲 1.04.1（重要度3）最終検証 2026-10-20

この章のゴール

  • まだ入っていないコマンドを、パッケージとして sudo apt install で入れて使える
  • 入れたパッケージを sudo apt remove で消せる
  • apt install の出力から、何を・どこから取ってきて・何をしたかを読める
  • パッケージを入れたり消したりするのに sudo が要る理由を言える
ここで覚えなくていいこと: apt のほかのサブコマンドとオプション、出力のうち意味をまだ説明していない行（Building dependency tree など）、パッケージのファイルの中身の形、Debian 系と RPM 系の違い。この章は「入れて、使って、消す」が1回できれば足りる。

檻を起動する

この節で分かること: この教材のコマンドを、どこで、どう打つか。

この教材のコマンドは、あなたの PC の上では打たない。コンテナ（1台の PC の中に、ほかと切り離した小さな Linux の部屋を作るしくみ。docker はそれを作る道具）の中で打つ。この教材では、このコンテナを檻と呼ぶ。パッケージを入れたり消したりすると、その Linux 全体が書き換わる。壊しても困らない部屋でやるためである。

あなたの PC の端末で、次の1行（4行に折ってある）をそのまま打つ。この章から第8章までは、この Debian 系の檻を使う。

docker run --rm -it --name lab-linuc-packages-deb --hostname linuc \
  -v lab-linuc-packages-deb-work:/home/lab/work \
  -v lab-linuc-packages-deb-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:packages-deb-1.1.0@sha256:__DIGEST__

初めて打つときは、檻の元になるイメージ（檻の中身をまとめたファイル。約 800MB）を取ってくるので、少し待つ。起動すると案内が数行出て、lab@linuc:~$ というプロンプトが出る。ここからが檻の中で、あなたは一般ユーザ lab として動いている。この教材では、檻の中のプロンプトを $ と短く書く。

起動の1行の部品何のためにあるか
--rm檻を抜けたら、檻を消す。次に起動すると最初の状態から始まる
-itあなたの端末を檻につなぐ。これが無いと、打ったものが檻に届かない
--name / --hostname檻の名前と、檻の中の機械の名前（プロンプトの linuc）
-v …-work:/home/lab/work / -v …-state:/home/lab/.lab檻を消しても残る置き場（ボリューム）を2つつなぐ。演習の作業ファイルと、演習の進み具合を残すため
ghcr.io/…@sha256:…使うイメージ。@sha256: の後ろで中身を1つに決めてあるので、誰が起動しても同じ檻になる

章ごとに起動し直す。この教材に載せた出力は、章ごとに檻を起動し直した直後から、本文の順に打った記録である。前の章で入れたものが残っていると出力が変わるので、章が変わったら exit で檻を抜け、もう一度上の1行を打つ。檻の中で打つコマンドの枠には「Debian 系の檻」と書いてある。

たとえ: ホテルの部屋に近い。チェックアウト（exit）すると部屋は片付けられ、次に泊まると最初の状態に戻っている。ただ、フロントに預けた荷物（ボリュームの中身）だけは、次に泊まったときも受け取れる。
ただし崩れる点: ホテルの部屋は1つの建物に並んでいるが、檻はあなたの PC の中に作られ、PC の力（CPU やメモリ）をそのまま分けて使う。檻の中で重い作業をすると、PC 全体が重くなる。

まだ入っていないコマンド

この節で分かること: パッケージ・パッケージ管理・apt が、それぞれ何か。

labhello というコマンドを打ってみる。この教材のために作った、自分の版（バージョン）を1行出すだけのコマンドである。

$ labhello
bash: labhello: command not found

command not found（コマンドが見つからない）と言われた。この檻には、まだ入っていないからである。

Linux では、コマンドやアプリはパッケージの形で配られる。パッケージは、プログラムと、それが使うファイル（説明書や設定ファイル）を1つにまとめて、名前と版を付けたものである。パッケージを入れる・消す・何を入れたかを覚えておく、という仕事をパッケージ管理と呼び、それをするコマンドがある。Ubuntu のような Debian 系の Linux では apt を使う。

たとえ: スマートフォンのアプリストアに近い。名前を指定して「入手」すれば、どこから取ってくるかを自分で探さなくても入り、要らなくなれば消せる。
ただし崩れる点: スマートフォンのアプリはあなた専用だが、apt で入れたものは、その機械を使う全員が使う場所に置かれる。だから、次の節で見るとおり、入れるには特別な権限が要る。

入れる — apt install

この節で分かること: apt install の打ち方と、出力の読み方。

入れるコマンドは apt install パッケージの名前 である。このパッケージの名前は、コマンドと同じ labhello である。パッケージを入れると、/usr/bin のような、その機械の全員が使う場所にファイルが置かれ、何を入れたかの記録も書き換わる。どちらも root（その機械の管理者）しか書けない場所にあるので、前に sudo を付けて、root の権限で打つ。この檻の lab は、パスワードを聞かれずに sudo を使えるようにしてある。

$ sudo apt install labhello
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
The following NEW packages will be installed:
  labhello
0 upgraded, 1 newly installed, 0 to remove and 0 not upgraded.
Need to get 0 B/1120 B of archives.
After this operation, 77.8 kB of additional disk space will be used.
Get:1 file:/srv/lab-repo lab/main amd64 labhello all 1.0 [1120 B]
Selecting previously unselected package labhello.
(Reading database ... 12833 files and directories currently installed.)
Preparing to unpack .../labhello/labhello_1.0_all.deb ...
Unpacking labhello (1.0) ...
Setting up labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...

入った。出力の1行ずつの意味はこうである。

行意味
Reading package lists... Done入れられるパッケージの一覧を読み込んだ
Building dependency tree... Done頼まれたものを入れるのに、一緒に要るものが無いかを調べた（今回は無かった）
Reading state information... Doneいま入っているものの記録を読み込んだ
The following NEW packages will be installed:これから新しく入れるもの（次の行の labhello）
0 upgraded, 1 newly installed, 0 to remove …新しい版に上げるもの 0・新しく入れるもの 1・消すもの 0
Need to get 0 B/1120 B of archives.パッケージのファイルは 1120 バイトで、ネットから取ってくる量は 0 バイト（この檻では置き場が同じ機械の中にあるので）
After this operation, … kB of additional disk space will be used.入れると、ディスクをこれだけ使う
Get:1 file:/srv/lab-repo lab/main amd64 labhello all 1.0 [1120 B]パッケージを取ってきた。どこから（file:/srv/lab-repo）・何を（labhello）・どの版を（1.0）
Selecting previously unselected package labhello.これまで入っていなかったパッケージとして、入れる側に選んだ
(Reading database ... 12833 files and directories currently installed.)入っているものの記録を読み込んだ。数は、パッケージから入ったファイルとディレクトリの数
Preparing to unpack .../labhello/labhello_1.0_all.deb ...取ってきたファイル labhello_1.0_all.deb を広げる用意をした
Unpacking labhello (1.0) ...中身のファイルを置いた
Setting up labhello (1.0) ...使える状態に整えた
Processing triggers for man-db …labhello が説明書（man のページ）も一緒に置いたので、man の索引を作り直した

Get:1 の行の file:/srv/lab-repo が、パッケージを取ってきた場所である。パッケージを配っている置き場をリポジトリと呼ぶ。この檻では、練習用のリポジトリを檻の中の /srv/lab-repo に置いてある。本物の Ubuntu では、インターネットの向こうのサーバがリポジトリになる。同じ行の amd64 はこの機械の CPU の種類（アーキテクチャ）、all は「どの種類の CPU でも動くパッケージ」という印である。

途中で Do you want to continue? [Y/n] と尋ねられることはなかった。頼んだ1つだけを入れるときは、apt は尋ねずに進める。使ってみる。

$ labhello
labhello 1.0
たとえ: 引っ越しの荷物の搬入に近い。荷物を部屋に運び込む（Unpacking）だけでは暮らせず、電気やガスをつないで初めて使える（Setting up）。apt は両方をまとめてやる。
ただし崩れる点: 引っ越しは何日もかかるが、ここでは一瞬で終わり、途中で止まることはめったにない。止まるのは、運び込んだあとで「つなぐ」ための別のものが足りないときで、そのときは2つ目の手順の手前で止まる。

消す — apt remove

この節で分かること: apt remove の打ち方と、消したあとの bash の言い方。

消すコマンドは apt remove パッケージの名前 である。これも root の権限が要る。

$ sudo apt remove labhello
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
The following packages will be REMOVED:
  labhello
0 upgraded, 0 newly installed, 1 to remove and 0 not upgraded.
After this operation, 77.8 kB disk space will be freed.
Do you want to continue? [Y/n] y
(Reading database ... 12837 files and directories currently installed.)
Removing labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...

The following packages will be REMOVED: が「これから消すもの」で、消す前に Do you want to continue? [Y/n]（続けますか？）と尋ねてきた。y と打って Enter を押す。Y だけが大文字なのは、何も打たずに Enter だけを押しても Y（はい）になるという印である。Removing labhello (1.0) ... がファイルを外した行で、Processing triggers for man-db は、説明書が無くなったので man の索引をまた作り直した行である。

ふつうこう考える

消したのだから、もう一度 labhello と打てば、入れる前と同じ command not found に戻るはずだ。

$ labhello
bash: /usr/bin/labhello: No such file or directory
だめな理由: 入れる前の command not found とは違う言い方になった。No such file or directory は「そのファイルが無い」という意味である。 bash（このプロンプトを出しているシェル）は、一度見つけたコマンドの場所（/usr/bin/labhello）を覚えていて、2回目からは探さずにその場所を直接開く。 ファイルは消えたので、その場所を開けなかった、と言っている。パッケージは消えている。違うのは bash の覚え方のほうである。

覚えている場所を忘れさせるのが hash -r である。

$ hash -r
$ labhello
bash: labhello: command not found

hash -r は何も出さずに終わる。そのあとは、最初と同じ command not found に戻った。入れる前の状態に戻ったということである。

たとえ: よく行く店の場所を覚えていて、地図を見ずに直接行くのに近い。店が閉まっていても、行ってみるまで気づかない（No such file or directory）。hash -r は覚えた場所を全部忘れて、次からまた地図を見るようにする。
ただし崩れる点: 人なら、店が無ければその場で別の店を探すが、bash は覚えた場所が無いと、そこで止まって探し直さない。だから2回目に打っても同じ言い方になる。
手を動かす: 実践編の演習01は、この章のとおりに labhello を入れて使えるようにする課題である。 判定は、labhello を実際に動かして版を出すかと、パッケージとして入ったことになっているかを見る。
確認

sudo を付けずに apt install labhello と打つと、どうなるか。そうなるのはなぜか。

答え

Permission denied と are you root? が出て、何も入らない（実測）。 パッケージを入れると /usr/bin のようなその機械の全員が使う場所にファイルが置かれ、何を入れたかの記録も書き換わる。 どちらも root しか書けないので、sudo を付けて root の権限で打つ。

確認

apt install の出力にあった次の1行から、何が読み取れるか。
Get:1 file:/srv/lab-repo lab/main amd64 labhello all 1.0 [1120 B]

答え

パッケージ labhello の版 1.0 を、リポジトリ（パッケージの配り場所）file:/srv/lab-repo から取ってきたこと。 all はどの種類の CPU でも動くパッケージだという印で、amd64 はこの機械の CPU の種類である。

確認

sudo apt remove labhello のあと、同じシェルで labhello と打つと bash: /usr/bin/labhello: No such file or directory と出た。command not found と出ないのはなぜか。

答え

bash が、前に見つけた labhello の場所（/usr/bin/labhello）を覚えていて、探し直さずにそこを開いたから。 ファイルは消えているので「そのファイルが無い」と言う。hash -r で覚えた場所を忘れさせると、command not found に戻る（実測）。

この章で分かったこと

持ち帰ってほしいこと

  • Linux のコマンドやアプリは、パッケージ（プログラムと関係するファイルに名前と版を付けたもの）の形で配られる
  • Debian 系では sudo apt install 名前 で入れ、sudo apt remove 名前 で消す。sudo が要るのは、全員が使う場所と、入れたものの記録を書き換えるから
  • apt install は、リポジトリ（配り場所）から取ってきて（Get）、中身を置き（Unpacking）、使える状態に整える（Setting up）
  • 消したあとに No such file or directory と出るのは、bash が前の場所を覚えているから。hash -r で忘れさせる
