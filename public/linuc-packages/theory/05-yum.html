5. yum は、目録を自分で取りに行く

いまの RHEL 系で yum と打つと、動いているのは dnf である。/etc/yum.conf も dnf の設定ファイルを指すリンクにすぎない。そして apt と違い、リポジトリを足したら更新のコマンドを打たずにそのまま入れられる。目録が無い・古いと気づくと、自分で取りに行くからだ。

前提: 第4章まで読了前提: RPM 系の檻を起動し直した直後所要 22分影響度 B出題範囲 1.04.3（重要度3）最終検証 2026-10-13

この章のゴール

  • yum と dnf、/etc/yum.conf と /etc/dnf/dnf.conf の関係を ls -l で示せる
  • /etc/yum.repos.d/ の .repo ファイルの主な項目（[repo id] name baseurl enabled gpgcheck gpgkey）を読み書きできる
  • yum の list / info（installed / available / updates）/ search / provides / repoquery -l / deplist / install / remove / update / check-update を使い分けられる
  • yumdownloader でパッケージを入れずに取ってこられる
ここで覚えなくていいこと: モジュール（dnf module）、グループ（yum groupinstall）の中身、yum history undo、次の世代の dnf5、RHEL のサブスクリプション登録。Last metadata expiration check の行は「目録を最後に確かめた時刻」とだけ読めれば足りる（時刻は読者ごとに違う）。

この章からは RPM 系の檻を使う。出力は、RPM 系の檻を起動し直した直後から打ったものである（起動のしかたは実践編）。

yum と打つと、dnf が動く

この節で分かること: 試験に出る yum と、いまの RHEL 系の実物との関係。
$ ls -l /usr/bin/yum /usr/bin/dnf
lrwxrwxrwx 1 root root 5 Sep 22  2025 /usr/bin/dnf -> dnf-3
lrwxrwxrwx 1 root root 5 Sep 22  2025 /usr/bin/yum -> dnf-3
$ ls -l /etc/yum.conf
lrwxrwxrwx 1 root root 12 Sep 22  2025 /etc/yum.conf -> dnf/dnf.conf
$ cat /etc/yum.conf
[main]
gpgcheck=1
installonly_limit=3
clean_requirements_on_remove=True
best=True
skip_if_unavailable=False
$ rpm -qf /etc/yum.conf /etc/dnf/dnf.conf /usr/bin/yum
yum-4.14.0-31.el9.alma.1.noarch
dnf-data-4.14.0-31.el9.alma.1.noarch
yum-4.14.0-31.el9.alma.1.noarch
$ yum --version | head -1
4.14.0

yum も dnf も、同じ dnf-3 を指すシンボリックリンクである。yum --version が返す 4.14.0 は dnf の版だ。RHEL 8 から、yum の中身は dnf に置き換わった。yum という名前は、古い手順や試験問題がそのまま使えるように、yum というパッケージがリンクとして残している（rpm -qf で持ち主が分かる）。コマンドの形（サブコマンドとオプション）はそのまま試せるが、既定値と出力は RHEL 7 の yum と違うところがある。この章では、違うところにそのつど印を付ける。

/etc/yum.conf も dnf/dnf.conf へのリンクで、どちらを編集しても同じファイルが変わる。[main] の5行の意味を押さえる。

項目意味
gpgcheck=1入れるパッケージの署名を確かめる（第7章）
installonly_limit=3カーネルのように「上書きせず並べて入れる」ものを、3世代まで残す
clean_requirements_on_remove=True消すとき、依存のために入ったもので不要になったものも消す（この章で実測）。dnf（RHEL 8 以降）は既定でこうなる。RHEL 7 の yum は既定が False で、依存を残す
best=Trueいちばん新しい版を入れられないなら、失敗にする
skip_if_unavailable=False目録を取れないリポジトリがあれば、止まる

CentOS 7 までの /etc/yum.conf には cachedir=（目録の置き場）や keepcache=（取ってきた .rpm を残すか）も書かれていた。どちらも dnf でも使える項目で、書いていなければ既定値になる。

たとえ: 屋号を変えずに店主が代わった店に近い。看板（yum）も、注文の仕方（install / remove / list）も前のままで、奥で働いているのは新しい店主（dnf）である。
ただし崩れる点: 看板が同じでも、細かい道具は入れ替わっている。たとえば yumdownloader は dnf の download へのリンクになっている（この章の最後）。古い資料のオプションが、そのまま通らないこともある。

リポジトリの表 — /etc/yum.repos.d/

この節で分かること: yum が「どこへ取りに行くか」を書いたファイルの形。
$ ls -1 /etc/yum.repos.d/
almalinux-appstream.repo
almalinux-baseos.repo
...
almalinux-saphana.repo
lab.repo
$ cat /etc/yum.repos.d/lab.repo
# 檻の中の練習用リポジトリ（確かめて説明する LinuC 主題1.04）。
# 中身はイメージを作ったときから変わらないので、目録を期限切れにしない（metadata_expire=-1）。
[lab]
name=lab packages (LinuC 1.04)
baseurl=file:///srv/lab-rpm
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-lab
metadata_expire=-1
$ grep -A10 '^\[baseos\]' /etc/yum.repos.d/almalinux-baseos.repo
[baseos]
name=AlmaLinux $releasever - BaseOS
#mirrorlist=https://mirrors.almalinux.org/mirrorlist/$releasever/baseos
baseurl=https://vault.almalinux.org/9.7/BaseOS/$basearch/os/
enabled=1
gpgcheck=1
countme=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-AlmaLinux-9
metadata_expire=-1
enabled_metadata=1

1つのリポジトリは [ ] で始まる1節で、[ ] の中が repo id（そのリポジトリを指す名前）である。1つのファイルに何節でも書け、ファイル名は .repo で終わっていれば自由である。

項目意味
[lab]repo id。yum repolist に出て、--enablerepo=lab のように指定するときにも使う
name=人が読むための説明
baseurl=リポジトリの場所（http:// https:// file://）。$basearch は CPU（x86_64）、$releasever は版に置き換わる
mirrorlist=「場所の候補の一覧」を返す URL。baseurl の代わりに使う
enabled=1使う（0 なら書いてあっても使わない）
gpgcheck=1パッケージの署名を確かめる
gpgkey=署名を確かめる公開鍵の場所
metadata_expire=目録の有効期限（秒）。過ぎると次のコマンドで取り直す。-1 は期限なし

この檻だけの書き換えが2つある。AlmaLinux の本来の設定は mirrorlist= で、その日いちばん近いミラーから最新の目録を取る。それでは読者ごと・日ごとに出力が変わるので、baseurl= を、更新が止まっている 9.7 の保存庫（vault）に向け、目録の期限も -1（無期限。本来は 86400 秒 = 1日）にした。

$ yum repolist
repo id                         repo name
appstream                       AlmaLinux 9 - AppStream
baseos                          AlmaLinux 9 - BaseOS
extras                          AlmaLinux 9 - Extras
lab                             lab packages (LinuC 1.04)
$ yum repolist all
repo id                      repo name                                  status
appstream                    AlmaLinux 9 - AppStream                    enabled
appstream-debuginfo          AlmaLinux 9 - AppStream - Debug            disabled
appstream-source             AlmaLinux 9 - AppStream - Source           disabled
baseos                       AlmaLinux 9 - BaseOS                       enabled
...
crb                          AlmaLinux 9 - CRB                          disabled
...

repolist は有効なものだけ、repolist all は enabled=0 のものも出す。

目録を引く — list・info・search・provides

この節で分かること: 入れる前に、yum に何を聞けるか。台帳と目録のどちらから来た答えか。
$ yum list installed 'lab*'

$ yum list labhello

台帳しか読まない rpm -qf は、入っていないファイルに答えられない。yum provides は入っていないパッケージのファイルまで答える。Debian 系の apt-file にあたることを、yum は追加の道具なしでできる。dnf の目録には最初からファイルの一覧（filelists）が入っているからである。パスの一部しか分からなければ '*/liblab.sh' のようにワイルドカードを使う（シェルに展開されないよう引用符で囲む）。

逆向き（パッケージの中身の一覧）も、入れる前に目録から引ける。yum repoquery -l である（別の檻で記録した）。

$ rpm -q labtool; echo "exit=$?"
package labtool is not installed
exit=1
$ yum repoquery -l labtool
...
/usr/bin/labtool
$ ls -l /usr/bin/repoquery
lrwxrwxrwx 1 root root 22 Nov 12  2025 /usr/bin/repoquery -> /usr/libexec/dnf-utils
$ repoquery -l labtool
...
/usr/bin/labtool

台帳しか読まない rpm -ql labtool は「入っていない」で終わるが、repoquery -l は目録のファイル一覧を引くので、入れる前の labtool の中身を答えた。Debian 系の apt-file list にあたる。repoquery は yum-utils に入っている道具で、RHEL 8 以降は yum repoquery（dnf のサブコマンド）と同じものへのリンク、RHEL 7 では yum-utils の独立したコマンドである。どちらでも repoquery -l 名前 と書ける。

入れる・消す — 依存は、消すときにも片付く

この節で分かること: yum の install と remove が、依存関係をどう扱うか。
$ sudo yum install -y labapp
...
Dependencies resolved.
================================================================================
 Package            Architecture       Version            Repository       Size
================================================================================
Installing:
 labapp             noarch             1.0-1              lab             7.3 k
Installing dependencies:
 liblab             noarch             1.0-1              lab             6.7 k
...
Complete!
$ yum list installed labapp liblab
Installed Packages
labapp.noarch                             1.0-1                             @lab
liblab.noarch                             1.0-1                             @lab
$ sudo yum remove -y labapp
Dependencies resolved.
================================================================================
 Package            Architecture       Version           Repository        Size
================================================================================
Removing:
 labapp             noarch             1.0-1             @lab             409
Removing unused dependencies:
 liblab             noarch             1.0-1             @lab             106
...
Complete!
$ rpm -q labapp liblab; echo "exit=$?"
package labapp is not installed
package liblab is not installed
exit=2
$ grep clean_requirements_on_remove /etc/yum.conf
clean_requirements_on_remove=True

入れるときに依存（Installing dependencies）を足すのは apt と同じだが、消すときに依存も一緒に消した（Removing unused dependencies）。/etc/yum.conf の clean_requirements_on_remove=True がそれを指示している。apt では remove のあとに autoremove を別に打った（第2章）。dnf も「どれを依存のために入れたか」を自分の記録に持っていて、それを見て判断している。これは dnf（RHEL 8 以降）の既定で、RHEL 7 の yum は clean_requirements_on_remove の既定が False なので、yum remove は依存を残す。

名前を付けた yum autoremove 名前 も、dnf（この檻）では名前を付けたものを依存ごと消す（別の檻で、labapp を入れ直してから記録した）。ただし試験で「パッケージを削除するコマンド」を問われたら、答えは remove である。

$ sudo yum autoremove -y labapp
Dependencies resolved.
...
Removing:
 labapp             noarch             1.0-1             @lab             409
Removing unused dependencies:
 liblab             noarch             1.0-1             @lab             106
...
Complete!
$ rpm -q labapp liblab; echo "exit=$?"
package labapp is not installed
package liblab is not installed
exit=2

yum の remove は erase とも書ける。RPM 系には Debian 系の rc（設定ファイルだけ残る）にあたる状態は無く、消せば台帳から消える。書き換えた設定ファイルは .rpmsave という名前で残される。

リポジトリを足したら、そのまま入れられる

この節で分かること: yum の目録が「いつ」取り直されるか。apt との違い。

檻にはまだ使っていないリポジトリ /srv/lab-extra-rpm がある。

$ find /srv/lab-extra-rpm -type f | sort
/srv/lab-extra-rpm/labextra-1.0-1.noarch.rpm
/srv/lab-extra-rpm/repodata/5dd2854da38fd1c14d69ca9c2976e3db924c8dd2e356e9f356a6793537a199a9-filelists.xml.gz
...
/srv/lab-extra-rpm/repodata/repomd.xml
$ yum list labextra; echo "exit=$?"
...
Error: No matching Packages to list
exit=1

repodata/ が目録で、repomd.xml がその目録の目録（第3章の Release にあたる）である。まだ登録していないので、yum は labextra を知らない。

ふつうこう考える

第3章の apt と同じで、リポジトリを書き足したら、まず目録を取り直すコマンドが要るはずだ。 それを打たずに yum install すれば「見つからない」と言われるだろう。

$ printf '%s\n' '[lab-extra]' 'name=lab extra (LinuC 1.04)' 'baseurl=file:///srv/lab-extra-rpm' 'gpgcheck=1' 'gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-lab' | sudo tee /etc/yum.repos.d/lab-extra.repo
[lab-extra]
name=lab extra (LinuC 1.04)
baseurl=file:///srv/lab-extra-rpm
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-lab
$ sudo yum install -y labextra
lab extra (LinuC 1.04)                           63 kB/s | 935  B     00:00
Dependencies resolved.
...
Installing:
 labextra           noarch           1.0-1            lab-extra           6.7 k
...
Complete!
$ labextra
labextra 1.0 (/srv/lab-extra-rpm から入った)
だめな理由: 入ってしまった。yum install の出力の1行目 （lab extra (LinuC 1.04) … 935 B）が、目録を取りに行った記録である。 dnf はコマンドを打たれるたびに、有効なリポジトリの目録が手元にあるか、期限（metadata_expire）が切れていないかを確かめ、 無いか古ければその場で自分で取りに行く。新しく足したリポジトリには目録の写しが無いので、必ず取りに行く。 apt は apt update と言われるまで決して取りに行かなかった。同じ「目録の写し」を持つ道具でも、取り直す時機の決め方が違う。
$ yum repolist
repo id                         repo name
appstream                       AlmaLinux 9 - AppStream
baseos                          AlmaLinux 9 - BaseOS
extras                          AlmaLinux 9 - Extras
lab                             lab packages (LinuC 1.04)
lab-extra                       lab extra (LinuC 1.04)

手で取り直させたいときのコマンドもある。

コマンドすることapt でいえば
yum makecache目録を取ってきて写しを作るapt update
yum clean all手元の目録の写しと、取ってきた .rpm を捨てるapt-get clean と、lists を消すことを合わせたもの
yum --refresh コマンド期限に関係なく、取り直してから実行する—

写しの置き場は /var/cache/dnf/ である（RHEL 8 以降。RHEL 7 の yum は /var/cache/yum/）。この檻では、一般ユーザと root が同じ写しを読むように、そこから /var/tmp/dnf-lab-cache へリンクしてある。dnf は root 以外で動くと利用者ごとの別の置き場を使い、写しを一から取り直すためである。

$ ls -ld /var/cache/dnf
lrwxrwxrwx 1 root root 22 Oct 13 10:08 /var/cache/dnf -> /var/tmp/dnf-lab-cache
$ ls /var/cache/dnf/
appstream-69125d5665712457
...
lab-extra-87753e023cd3c28c
lab-extra-filenames.solvx
lab-extra.solv
...

さっき取りに行った lab-extra の写し（lab-extra-…）が増えている。

たとえ: 取引先の住所を住所録に書き足すと、次に注文するとき、店員が気を利かせて先にカタログを取りに行ってくれる店に近い。 カタログに「有効期限」が書いてあり、期限が過ぎていても取り直してくる。
ただし崩れる点: 気を利かせる時機は「コマンドを打ったとき」だけである。 期限の内側でリポジトリの中身が変わっても、dnf は気づかずに古い写しを使う。そのときは yum makecache か --refresh で取り直させる。

...
exit=0

check-update は「台帳の版より新しい版が目録にあるもの」を並べ、あれば終了コード 100、無ければ 0 を返す（失敗なら 1）。スクリプトで「更新があるか」を判定するのに使われる。yum update は名前を付ければそれだけ、付けなければ全部を上げる。dnf では update と upgrade は同じものである。AlmaLinux 本体のパッケージが1つも出ないのは、vault の 9.7 が凍結されていて、檻がその最終の状態で作られているからだ。

試験の例題には、update を「インストール済みのパッケージを最新版にする」、upgrade を「システム全体を最新にする」と別のものとして書いたものがあり、この形で出うる。dnf で同じものだと分かるのは使い方の表示で、update と打っても upgrade と出る（別の檻で記録した）。

$ yum update --help | head -1
usage: yum upgrade [-c CONFIG_FILE] [-q] [-v] [--version] [--installroot PATH]

入れずに取ってくる — yumdownloader

この節で分かること: .rpm ファイルだけを手に入れる方法と、その道具の正体。
$ ls -l /usr/bin/yumdownloader
lrwxrwxrwx 1 root root 22 Nov 12  2025 /usr/bin/yumdownloader -> /usr/libexec/dnf-utils
$ cd ~/work
$ yumdownloader labtool
...
$ ls -l
total 8
-rw-r--r-- 1 lab lab 6859 Oct 13 11:38 labtool-1.0-1.noarch.rpm
$ rpm -q labtool; echo "exit=$?"
package labtool is not installed
exit=1
$ rpm -qpl labtool-1.0-1.noarch.rpm
/usr/bin/labtool
$ rpm -qpR labtool-1.0-1.noarch.rpm
/usr/bin/sh
labtool-data >= 1.0
...
$ yumdownloader --resolve --destdir dl labtool
...
$ ls -l dl/
total 16
-rw-r--r-- 1 lab lab 6859 Oct 13 11:38 labtool-1.0-1.noarch.rpm
-rw-r--r-- 1 lab lab 6729 Oct 13 11:38 labtool-data-1.0-1.noarch.rpm

yumdownloader は目録を読んで .rpm を取ってくるだけで、台帳には書かない（rpm -q は「入っていない」）。だから root でなくても打てる。取ったファイルは、第1章の rpm -qpl / -qpR で中身と依存を確かめられる。--resolve は依存するものも一緒に取り、--destdir は置き場所を指定する。RHEL 8 以降の実体は yum-utils パッケージの /usr/libexec/dnf-utils で、dnf download を呼んでいる（RHEL 7 の yumdownloader は、yum-utils に入った独立した Python のプログラムである。使い方は同じ）。Debian 系なら apt-get download（第2章）がこれにあたる。

オプション意味
（なし）カレントディレクトリに取る
--destdir 場所指定した場所に取る
--resolve入っていない依存も一緒に取る
--sourceソース RPM（.src.rpm）を取る
たとえ: 通販で「取り置き」だけ頼んで、受け取った箱を開けずに置いておく使い方に近い。 箱（.rpm）は手元にあるが、家の持ち物の記録（台帳）には載っていない。
ただし崩れる点: 通販の取り置きは1点ずつだが、--resolve を付けると、 その品に要る別売りの部品まで目録で調べて一緒に取ってくる。
手を動かす: 実践編の演習04は、まだ登録されていない別のリポジトリから、名前の分からないパッケージに入っている labcalc を入れる課題である（.repo を書く・yum provides で探す・署名を確かめて入れる）。 演習06は yumdownloader で取ってきた .rpm を、yum を使わずに入れる。
確認

独自のリポジトリを yum に登録したい。どのディレクトリに、どんな名前のファイルを置き、リポジトリの場所はどの項目に書くか。

答え

/etc/yum.repos.d/ に、名前が .repo で終わるファイルを置く。中は [repo id] で始まる節にし、 場所を baseurl=（または mirrorlist=）に書く。enabled=1 で有効、 gpgcheck=1 と gpgkey= で署名の確認を指定する。

確認

インストールされていないパッケージも含めて、/usr/bin/dig を含むパッケージを調べる yum のサブコマンドはどれか。
(a) yum search　(b) yum info　(c) yum provides　(d) yum list

答え

(c)（別名 whatprovides）。実測では bind-utils などが答えとして出た。(a) は名前と要約しか見ない。 入っているファイルなら rpm -qf /usr/bin/dig でも分かるが、入っていなければ No such file or directory になる。

確認

パッケージをインストールせずに、.rpm ファイルとしてカレントディレクトリに取得するコマンドはどれか。
(a) yum install --downloadonly　(b) yumdownloader　(c) rpm -qp　(d) yum makecache

答え

(b)。依存するものも取るなら --resolve、置き場所を変えるなら --destdir。 (a) も入れずに取るが、置き場所はカレントディレクトリではなく dnf のキャッシュの中になる。 (d) は目録を取ってくるだけで、パッケージは取らない。

確認

yum check-update の終了コードが 100 だった。何を意味するか。

答え

更新できるパッケージがある（目録に、台帳の版より新しい版がある）。0 なら無い、1 ならエラー。実測でも、labhello 1.1 があるときは 100、上げた後は 0 だった。

この章で分かったこと

持ち帰ってほしいこと

  • RHEL 8 以降の yum は dnf へのリンク。/etc/yum.conf も /etc/dnf/dnf.conf へのリンク
  • リポジトリは /etc/yum.repos.d/*.repo に、[repo id]・baseurl=・enabled=・gpgcheck=・gpgkey= で書く
  • yum list の右端の @lab は台帳（そこから入った）、lab は目録（そこから入れられる）
  • 入っているもの全部を出すのは yum list installed と yum info installed（info も installed / available / updates を付けられる）
  • yum provides（ファイル → パッケージ）と yum repoquery -l（パッケージ → 中身）は、入っていないパッケージにも答える（apt-file が要らない）
  • dnf は目録が無い・期限切れだと、コマンドを打った時点で自分で取りに行く。apt は apt update まで取りに行かない
  • yum remove は依存のために入った不要なものも消す（dnf の既定 clean_requirements_on_remove=True。RHEL 7 の yum は既定 False で残す）
  • yumdownloader（RHEL 8 以降の実体は dnf download）は入れずに .rpm を取る。--resolve で依存も
