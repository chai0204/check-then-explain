8. パッケージを自分で作る

前の章までにやったこと: パッケージをリポジトリから apt で入れ（第1・5・6章）、.deb ファイルから dpkg で入れ（第7章）、入っているもの・置かれたファイル・台帳を調べた（第2〜4章）。.deb ファイルが「中身」と「情報」でできていることも見た（第3章）。この章でやること: その .deb ファイルを自分で作る。中身と情報を並べて1つのファイルに固め、これまでの章の道具で中を確かめ、入れて、台帳に載ったことを確かめ、消す。パッケージを作ることは LinuC レベル1 の出題範囲には入っていないが、第1〜7章でやったことが1本につながる。

前提: 第7章まで読了前提: Debian 系の檻を起動し直した直後所要 18分影響度 B出題範囲の外（第1〜7章のまとめ）最終検証 2026-10-20

この章のゴール

  • 中身のファイルの木と DEBIAN/control（情報）を並べて、dpkg-deb --build で .deb ファイルを作れる
  • 作った .deb ファイルを dpkg -c・dpkg -I で確かめ、apt install ./ で入れ、台帳に載ったことを dpkg -l・-L・-S で示せる
  • --root-owner-group を付ける理由を言える
ここで覚えなくていいこと: パッケージを作る正式な道具（dpkg-buildpackage など）、control のこの章で使わない欄、設定ファイルの印（conffiles）の書き方、作ったパッケージをリポジトリに載せる方法。どれも LinuC レベル1 の出題範囲の外で、この章も試験には出ない。

中身を並べる

この節で分かること: .deb ファイルの中身を、どんな形で用意するか。

自分の版を1行出すだけのコマンド myhello をパッケージにする。まず、入れたあとに置きたい場所と同じ形のディレクトリの木を作る。ディレクトリ myhello が、入れる先の / にあたる。

$ mkdir -p myhello/usr/bin

mkdir -p は、途中のディレクトリ（myhello と myhello/usr）もまとめて作る。うまくいくと何も出さない。次に、コマンドの中身のファイルを書く。

$ cat > myhello/usr/bin/myhello <<'END'
> #!/bin/sh
> echo "myhello 1.0: 自分で作ったパッケージから入りました"
> END

cat > ファイル <<'END' は、次の行から END だけの行までを、そのままファイルに書く書き方（ヒアドキュメント）である。2行目からは、続きの入力を待つ > というプロンプトが出る。書いた中身の1行目 #!/bin/sh は「このファイルは sh（シェル）に読ませて動かす」という印で、2行目が実際に動く1行である。最後に、実行できるようにする。

$ chmod 755 myhello/usr/bin/myhello

chmod 755 で、誰でも実行できるようにした（持ち主は読み書きと実行、ほかの人は読みと実行）。

ふつうこう考える

置きたいファイルを置き場所どおりに並べたのだから、あとはこの木を1つのファイルに固めれば .deb ファイルになるはずだ。固めるのは dpkg-deb（第4章で中身を取り出すのに使った、.deb ファイルを扱う道具）の --build である。

$ dpkg-deb --build myhello
dpkg-deb: error: failed to open package info file 'myhello/DEBIAN/control' for reading: No such file or directory
だめな理由: myhello/DEBIAN/control が無いので開けない、と断られた。 第3章で見たとおり、.deb ファイルは中身（ファイルの木）と情報の2つでできている。いま用意したのは中身だけで、名前も版も書いていない。 情報は、木の一番上に DEBIAN というディレクトリを作り、その中の control というファイルに書く決まりである。

情報を書く — DEBIAN/control

この節で分かること: control に最低限書くことと、.deb ファイルの固め方。
$ mkdir myhello/DEBIAN
$ cat > myhello/DEBIAN/control <<'END'
> Package: myhello
> Version: 1.0
> Architecture: all
> Maintainer: lab <lab@example.invalid>
> Description: my first package
> END
欄この例では何のためにあるか
Packagemyhelloパッケージの名前。apt install や dpkg -l で使う名前になる
Version1.0版。新しい版かどうかを比べるのに使う（第6章の upgrade）
Architectureallどの CPU 向けか。シェルのスクリプトはどの CPU でも動くので all
Maintainerlab <lab@example.invalid>作って面倒を見る人（名前 <メール>）。不具合の知らせ先になる
Descriptionmy first package説明。dpkg -l の右端や apt show に出る

依存関係があるなら Depends: の行も書く（第3章で見た labapp の control の Depends: liblab (>= 1.0) の形）。myhello は何も要らないので書かない。固める。--build の2つ目に置き場所のディレクトリ（ここでは . ＝いまいる所）を渡すと、control の名前・版・アーキテクチャから「名前_版_アーキテクチャ.deb」という名前で作る。

$ dpkg-deb --build myhello .
dpkg-deb: building package 'myhello' in './myhello_1.0_all.deb'.
$ dpkg -c myhello_1.0_all.deb
drwxr-xr-x lab/lab           0 2026-10-20 21:35 ./
drwxr-xr-x lab/lab           0 2026-10-20 21:35 ./usr/
drwxr-xr-x lab/lab           0 2026-10-20 21:35 ./usr/bin/
-rwxr-xr-x lab/lab          85 2026-10-20 21:35 ./usr/bin/myhello

できた。ただ、第3章の labapp では root/root だったファイルの持ち主が、lab/lab になっている。dpkg-deb は、ふつう、ファイルをいまの持ち主（作業した lab）のまま詰める。このまま入れると、/usr/bin/myhello の持ち主が lab になり、一般ユーザがシステムのコマンドを書き換えられてしまう。持ち主を root にして詰めるのが --root-owner-group である。作り直して確かめる。

$ dpkg-deb --build --root-owner-group myhello .
dpkg-deb: building package 'myhello' in './myhello_1.0_all.deb'.
$ dpkg -c myhello_1.0_all.deb
drwxr-xr-x root/root         0 2026-10-20 21:35 ./
drwxr-xr-x root/root         0 2026-10-20 21:35 ./usr/
drwxr-xr-x root/root         0 2026-10-20 21:35 ./usr/bin/
-rwxr-xr-x root/root        85 2026-10-20 21:35 ./usr/bin/myhello
$ dpkg -I myhello_1.0_all.deb
 new Debian package, version 2.0.
 size 610 bytes: control archive=201 bytes.
     116 bytes,     5 lines      control
 Package: myhello
 Version: 1.0
 Architecture: all
 Maintainer: lab <lab@example.invalid>
 Description: my first package

持ち主が root/root になった（dpkg -c の日時は、あなたが作った時刻になる。中に時刻が入るので、dpkg -I の先頭の大きさも、あなたの画面では数バイト違うことがある）。dpkg -I には、いま書いた control がそのまま入っている。

たとえ: 引っ越しの荷物を、新居の部屋割りどおりに自分で箱詰めし、送り状を書いて同封するのに近い。業者（dpkg）は、箱の中の並びのとおりに荷物を置き、送り状を台帳に写す。
ただし崩れる点: 人の業者なら「この荷物は台所ではなく寝室では？」と気づくことがあるが、dpkg は箱の中のパスをそのまま使う。間違った場所に詰めれば、間違った場所に置かれる。
たとえ: --root-owner-group は、荷物に付ける「持ち主」の札を、自分の名前から建物の管理人（root）の名前に書き換えて詰めることに近い。共用の棚（/usr/bin）に置くものは、管理人の物でなければならない。
ただし崩れる点: 札を書き換えても、荷物の中身や送り状は変わらない。変わるのは、置いたあとに誰が書き換えられるか（ファイルの持ち主とパーミッションの効き方）だけである。

入れて、台帳で確かめる

この節で分かること: 自分で作ったパッケージも、入れれば台帳に載ること。

第7章のとおり、apt にファイルとして渡す。

$ sudo apt install ./myhello_1.0_all.deb
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
Note, selecting 'myhello' instead of './myhello_1.0_all.deb'
The following NEW packages will be installed:
  myhello
0 upgraded, 1 newly installed, 0 to remove and 0 not upgraded.
Need to get 0 B/610 B of archives.
After this operation, 0 B of additional disk space will be used.
Get:1 /home/lab/myhello_1.0_all.deb myhello all 1.0 [610 B]
Selecting previously unselected package myhello.
(Reading database ... 12833 files and directories currently installed.)
Preparing to unpack /home/lab/myhello_1.0_all.deb ...
Unpacking myhello (1.0) ...
Setting up myhello (1.0) ...
N: Download is performed unsandboxed as root as file '/home/lab/myhello_1.0_all.deb' couldn't be accessed by user '_apt'. - pkgAcquire::Run (13: Permission denied)
$ myhello
myhello 1.0: 自分で作ったパッケージから入りました

Get:1 /home/lab/myhello_1.0_all.deb は、リポジトリではなく手元のファイルから取ったという行である。最後の N: の行は失敗ではなく知らせ（Notice）で、「apt はファイルを読む作業を、権限を絞った専用の利用者 _apt にさせる決まりがあるが、/home/lab は lab しか入れないので、root のまま読んだ」と言っている。台帳を見る。

$ dpkg -l myhello | tail -1
ii  myhello        1.0          all          my first package
$ dpkg -L myhello
/.
/usr
/usr/bin
/usr/bin/myhello
$ dpkg -S /usr/bin/myhello
myhello: /usr/bin/myhello
$ ls -l /usr/bin/myhello
-rwxr-xr-x 1 root root 85 Oct 20 21:35 /usr/bin/myhello

自分で作ったパッケージも、ほかのパッケージと同じように台帳に載り、dpkg -L・-S で引ける。/usr/bin/myhello の持ち主は root である。消すのも同じである。

$ sudo apt remove myhello
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
The following packages will be REMOVED:
  myhello
0 upgraded, 0 newly installed, 1 to remove and 0 not upgraded.
After this operation, 0 B of additional disk space will be used.
Do you want to continue? [Y/n] y
(Reading database ... 12834 files and directories currently installed.)
Removing myhello (1.0) ...
$ dpkg -l myhello
dpkg-query: no packages found matching myhello
たとえ: 自分で書いた送り状の荷物でも、配送センター（apt）は同じように受け付けて、台帳に記録してくれる。
ただし崩れる点: 本物の配送なら差出人を確かめるが、apt install ./ファイル は手元のファイルを誰が作ったかを確かめない。出どころの分からない .deb ファイルを入れると、何が置かれても受け入れてしまう。

第1〜8章が1つにつながる

この節で分かること: Debian 系のパッケージ管理の全体の形。

自分で作ってみると、これまでの章に出てきたものが、どれも同じ形の一部だったことが分かる。

.deb ファイル ＝ 中身（ファイルの木）＋ 情報（DEBIAN/control）      … 第3章・この章
リポジトリ   ＝ 中身の置き場（pool/）＋ 目録（dists/ の Packages・Contents）  … 第6章
apt          … 目録を読み、.deb を取ってきて dpkg に渡す（依存関係も解く）  … 第1・5・6章
dpkg         … .deb を展開・設定し、台帳（/var/lib/dpkg/）に書く            … 第2・4・7章
台帳とファイル … 別々にある。片方だけを変えると食い違い、dpkg -V で見つかる … 第4章

答えが食い違ったら、いま見ているのが「ファイル」「台帳」「目録」のどれかを確かめる。第9章からは、RPM 系の Linux で同じことをする。道具の名前は変わるが、この形は変わらない。

手を動かす: 実践編の演習08は、配られたスクリプトを、依存関係（liblab）つきのパッケージ labmine に作って入れる課題である。 判定は台帳で labmine の版・依存関係・ファイルの持ち主を見て、labmine を実際に動かす。
確認

ディレクトリ pkg を dpkg-deb --build pkg で .deb ファイルにしようとしたところ、pkg/DEBIAN/control が開けないと言われた。何が足りないか。

答え

パッケージの情報（DEBIAN/control）。.deb ファイルは中身（ファイルの木）と情報の2つでできていて、名前・版などを書いた control が無いと作れない（実測）。

確認

--root-owner-group を付けずに作った .deb ファイルを入れると、何が困るか。

答え

パッケージの中のファイルが、作った人（ここでは lab）の持ち物として詰められ、入れたあとも /usr/bin などのファイルの持ち主がその人になる。 一般ユーザがシステムのコマンドを書き換えられる状態になる。dpkg -c で root/root になっているかを確かめてから入れる（実測で lab/lab から root/root に変わった）。

確認

dpkg-deb --build --root-owner-group pkg . で作られるファイルの名前は、何で決まるか。

答え

pkg/DEBIAN/control の Package・Version・Architecture。「名前_版_アーキテクチャ.deb」になる（実測で myhello_1.0_all.deb）。

この章で分かったこと

持ち帰ってほしいこと

  • .deb ファイルは、置き場所どおりのファイルの木と、DEBIAN/control（Package・Version・Architecture・Maintainer・Description、要るなら Depends）を並べて dpkg-deb --build で作る
  • --root-owner-group を付けて、中のファイルの持ち主を root にする。dpkg -c で確かめる
  • 自分で作ったパッケージも、apt install ./ で入れれば台帳に載り、dpkg -l・-L・-S で引け、apt remove で消せる
  • Debian 系のパッケージ管理は「.deb（中身＋情報）・リポジトリ（置き場＋目録）・apt・dpkg・台帳」の組み合わせでできている
