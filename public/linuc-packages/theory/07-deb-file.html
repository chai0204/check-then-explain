7. .deb ファイルを直接入れる

前の章までにやったこと: apt でパッケージを入れる・調べる・消すをやり、apt がリポジトリの目録を見て取ってくること、依存関係があれば一緒に入れることを確かめた（第5・6章）。この章でやること: リポジトリを通さずに、手元にある .deb ファイルを dpkg で直接入れる。依存関係が足りないと何が起きるかを見て、そのあとの片付け方を確かめる。最後に、パッケージを入れたときの質問をやり直す dpkg-reconfigure を使う。

前提: 第6章まで読了前提: Debian 系の檻を起動し直した直後所要 22分影響度 B出題範囲 1.04.2（重要度1）出題範囲 1.04.1（重要度3）最終検証 2026-10-20

この章のゴール

  • .deb ファイルを dpkg -i で入れ、dpkg -r・dpkg -P で消す
  • 依存関係が足りない .deb ファイルを dpkg -i で入れるとどうなるかを確かめ、続きを済ませる方法を確かめる
  • dpkg -i がしている「展開」と「設定」を、dpkg --unpack と dpkg --configure で分けて打つ
  • dpkg-reconfigure で、入れたときの質問をもう一度出し、設定し直す
ここで覚えなくていいこと: dpkg のそのほかのオプション（--set-selections・--force-… など）、パッケージの中で動く設定の手順（スクリプト）の書き方、debconf（質問と答えを覚えるしくみ）の記録の形、dpkg-reconfigure の画面の種類の違い。この章は、ファイルから入れる・消す・設定をやり直す、が1回できれば足りる。

.deb ファイルを入れる — dpkg -i

この節で分かること: 手元の .deb ファイルを、dpkg で入れて消す方法。

リポジトリに無いパッケージを、.deb ファイルの形で配られることがある（ソフトウェアの会社が自分のサイトで配る場合など）。ここでは第3章の apt download で labhello の .deb ファイルを取ってきて、それを手元のファイルとして入れる。

$ apt download labhello
Get:1 file:/srv/lab-repo lab/main amd64 labhello all 1.0 [1120 B]
$ sudo dpkg -i labhello_1.0_all.deb
Selecting previously unselected package labhello.
(Reading database ... 12833 files and directories currently installed.)
Preparing to unpack labhello_1.0_all.deb ...
Unpacking labhello (1.0) ...
Setting up labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...
$ labhello
labhello 1.0
$ dpkg -l labhello | tail -1
ii  labhello       1.0          all          prints its own version

dpkg -i（install）は、渡された .deb ファイルを展開して（Unpacking）、使える状態に整える（Setting up）。第1章の apt install の出力の後半と同じ行が並んでいる。apt は、目録を見てリポジトリから .deb ファイルを取ってきて、それを dpkg に渡しているのである。消すのは dpkg -r（remove）である。

$ sudo dpkg -r labhello
(Reading database ... 12837 files and directories currently installed.)
Removing labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...
$ dpkg -l labhello
dpkg-query: no packages found matching labhello

dpkg は、消してよいかを尋ねない。

依存関係が足りない .deb ファイル

この節で分かること: 依存関係が足りない .deb ファイルを dpkg で入れると、どうなるか。

第5章で apt install labapp は liblab を一緒に入れた。同じ labapp を、今度は .deb ファイルから dpkg で入れる。

ふつうこう考える

dpkg -i もパッケージを入れるコマンドなのだから、足りない liblab も一緒に入れてくれるはずだ。少なくとも、入れられないなら何もせずに終わるだろう。

$ apt download labapp
Get:1 file:/srv/lab-repo lab/main amd64 labapp all 1.0 [1076 B]
$ sudo dpkg -i labapp_1.0_all.deb
Selecting previously unselected package labapp.
(Reading database ... 12833 files and directories currently installed.)
Preparing to unpack labapp_1.0_all.deb ...
Unpacking labapp (1.0) ...
dpkg: dependency problems prevent configuration of labapp:
 labapp depends on liblab (>= 1.0); however:
  Package liblab is not installed.

dpkg: error processing package labapp (--install):
 dependency problems - leaving unconfigured
Errors were encountered while processing:
 labapp
$ dpkg -l labapp liblab | tail -2
iU  labapp         1.0          all          sample application that needs liblab
un  liblab         <none>       <none>       (no description available)
$ labapp
/usr/bin/labapp: 3: .: cannot open /usr/lib/liblab/liblab.sh: No such file
だめな理由: どちらの予想も外れた。dpkg は liblab を取りに行かず、かといって何もせずに終わってもいない。 展開（Unpacking）までは進めて、設定の手前で止まった（dependency problems - leaving unconfigured＝依存関係の問題があるので、設定しないままにする）。 台帳には labapp が iU と書かれた。1文字目 i は「入れたい」、2文字目 U は「展開済み（Unpacked）・設定前」である。 ファイルは置かれたので、labapp を打つと動きかけて、liblab のファイルが無いところで失敗する。 dpkg は .deb ファイルの Depends: を読めるので「足りない」とは分かる。しかし、どこへ取りに行けばいいかを知らない。リポジトリの目録を持っているのは apt のほうである。 （liblab の un は「知らない・入っていない」で、台帳に行は無いが、labapp の依存関係に名前が出てくるので表示だけしている。）

しかもこの状態は、関係ないパッケージの操作も止める。labhello を入れようとしてみる。

$ sudo apt install labhello
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
You might want to run 'apt --fix-broken install' to correct these.
The following packages have unmet dependencies:
 labapp : Depends: liblab (>= 1.0) but it is not going to be installed
E: Unmet dependencies. Try 'apt --fix-broken install' with no packages (or specify a solution).

apt は「依存関係が満たされていない（Unmet dependencies）」と言って断った。apt は、台帳全体で依存関係が満たされた状態しか作らないので、満たされていないもの（liblab の無い labapp）が残っていると、それを直す以外の操作を受け付けない。直し方は出力の中に書いてある。

$ sudo apt --fix-broken install
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
Correcting dependencies... Done
The following additional packages will be installed:
  liblab
The following NEW packages will be installed:
  liblab
0 upgraded, 1 newly installed, 0 to remove and 0 not upgraded.
1 not fully installed or removed.
Need to get 0 B/746 B of archives.
After this operation, 36.9 kB of additional disk space will be used.
Do you want to continue? [Y/n] y
Get:1 file:/srv/lab-repo lab/main amd64 liblab all 1.0 [746 B]
Selecting previously unselected package liblab.
(Reading database ... 12837 files and directories currently installed.)
Preparing to unpack .../libl/liblab/liblab_1.0_all.deb ...
Unpacking liblab (1.0) ...
Setting up liblab (1.0) ...
Setting up labapp (1.0) ...
$ dpkg -l labapp liblab | tail -2
ii  labapp         1.0          all          sample application that needs liblab
ii  liblab         1.0          all          small shell library for lab programs
$ labapp
liblab: hello from labapp 1.0

1 not fully installed or removed.（設定し終わっていないものが1つある）が labapp の iU のことで、apt が目録から liblab を取ってきて入れ、続けて labapp の設定（Setting up labapp）を済ませた。apt --fix-broken install は apt-get -f install とも書く（-f は fix-broken）。

たとえ: 組み立て家具の箱を開けたら「別売りの部品 B が要る」と書いてあった場面に近い。dpkg は、箱を開けて部品を床に並べたところで手を止める係で、apt は、倉庫の在庫表を見て部品 B を取ってくる係である。
ただし崩れる点: 家具なら、部品を床に並べたまま放っておいても困るのはその家具だけだが、依存関係が足りないまま残った iU は、apt のほかの操作まで止める。片付けるか続けるかを、先に決めなければならない。

dpkg で消す — -r と -P

この節で分かること: dpkg で消すときの打ち方と、消したあとの台帳。
$ sudo dpkg -r liblab
dpkg: dependency problems prevent removal of liblab:
 labapp depends on liblab (>= 1.0).

dpkg: error processing package liblab (--remove):
 dependency problems - not removing
Errors were encountered while processing:
 liblab

labapp が必要としている liblab は、先に消すことを断られた。入れるときは依存関係を取りに行かないのに、消すときは依存関係を守る。どちらも、台帳を読むだけでできる判断だからである。labapp のほうから消す。

$ sudo dpkg -r labapp
(Reading database ... 12839 files and directories currently installed.)
Removing labapp (1.0) ...
$ dpkg -l labapp | tail -1
rc  labapp         1.0          all          sample application that needs liblab
$ sudo dpkg -P labapp
(Reading database ... 12836 files and directories currently installed.)
Purging configuration files for labapp (1.0) ...
$ sudo dpkg -P liblab
(Reading database ... 12835 files and directories currently installed.)
Removing liblab (1.0) ...

dpkg -r は第5章の apt remove と同じく、設定ファイルを残して rc にした。dpkg -P（purge）は設定ファイルも消し、台帳の行も消す（apt purge と同じ）。入っているパッケージにいきなり -P を使うと、中身と設定ファイルが一度に消える（最後の liblab）。dpkg に autoremove にあたるものは無い。「自動で入った」という印は、apt だけが持っているからである。

たとえ: 積み木で、上に別の積み木が乗っている土台だけを抜こうとする場面に近い。上の積み木（labapp）を先に下ろせば、土台（liblab）も抜ける。
ただし崩れる点: 積み木は形のうえで抜けないが、dpkg が断るのは、台帳に「labapp は liblab に依存する」と書いてあるからである。台帳を通さずに rm でファイルを消せば、誰も止めない（第4章で /usr/bin/labhello を消したときも、台帳は ii のままだった）。

.deb ファイルを apt に渡す — apt install ./ファイル

この節で分かること: 手元の .deb ファイルを、依存関係ごと1回で入れる方法。

最初から apt に .deb ファイルを渡せば、止まらずに入る。名前ではなくファイルだと分かるように、./（いまいるディレクトリ）を付ける。

$ sudo apt install ./labapp_1.0_all.deb
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
Note, selecting 'labapp' instead of './labapp_1.0_all.deb'
The following additional packages will be installed:
  liblab
The following NEW packages will be installed:
  labapp liblab
0 upgraded, 2 newly installed, 0 to remove and 0 not upgraded.
Need to get 0 B/1822 B of archives.
After this operation, 106 kB of additional disk space will be used.
Do you want to continue? [Y/n] y
Get:1 file:/srv/lab-repo lab/main amd64 liblab all 1.0 [746 B]
Get:2 file:/srv/lab-repo lab/main amd64 labapp all 1.0 [1076 B]
Selecting previously unselected package liblab.
(Reading database ... 12833 files and directories currently installed.)
Preparing to unpack .../libl/liblab/liblab_1.0_all.deb ...
Unpacking liblab (1.0) ...
Selecting previously unselected package labapp.
Preparing to unpack .../l/labapp/labapp_1.0_all.deb ...
Unpacking labapp (1.0) ...
Setting up liblab (1.0) ...
Setting up labapp (1.0) ...

Note, selecting 'labapp' instead of './labapp_1.0_all.deb' は「ファイル ./labapp_1.0_all.deb を、中に書いてある名前の labapp として扱う」という知らせである。あとは第5章と同じで、依存関係を読んで liblab も一緒に入れた（同じ版の labapp がリポジトリにもあるので、apt はそちらから取っている。中身は同じである）。./ を付けないと、apt はファイル名をパッケージの名前として目録から探し、見つからない。リポジトリに無いファイルを渡すと（演習07 の labnote など）、最後に N: Download is performed unsandboxed as root … という行が出る。これは失敗ではなく知らせ（Notice）で、apt は取ってきたファイルを読む作業を、権限を絞った専用の利用者 _apt にさせる決まりだが、そのファイルが _apt の入れない場所（あなたのホームディレクトリの下）にあったので、root のまま読んだ、という意味である。

やり方何のためにあるか（いつ使うか）依存関係結果
sudo dpkg -i ファイル.deb手元のファイルをそのまま入れる。依存関係が無いか、もう入っているとき読んで確かめるだけ。足りなければ止まる足りないと展開済み・設定前（iU）で残る
続けて sudo apt --fix-broken installdpkg -i が依存関係で止まったあとに、続きを済ませる目録から足りないものを取ってくる全部 ii になる
sudo apt install ./ファイル.deb手元のファイルを、足りない依存関係ごと1回で入れる最初から目録で解決する1回で ii になる

展開と設定を分けて打つ — dpkg --unpack と --configure

この節で分かること: dpkg -i がしている2つの段を、分けて打つ方法。

第1章から出ている Unpacking（展開）と Setting up（設定）は、別々に打つこともできる。依存関係の無い labhello で確かめる。

$ sudo dpkg --unpack labhello_1.0_all.deb
Selecting previously unselected package labhello.
(Reading database ... 12839 files and directories currently installed.)
Preparing to unpack labhello_1.0_all.deb ...
Unpacking labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...
$ dpkg -l labhello | tail -1
iU  labhello       1.0          all          prints its own version
$ sudo dpkg --configure labhello
Setting up labhello (1.0) ...
$ dpkg -l labhello | tail -1
ii  labhello       1.0          all          prints its own version

--unpack は展開だけをして台帳を iU にし、--configure が設定を済ませて ii にした。dpkg -i は、この2つを続けてやっている。依存関係で止まったのは、2つ目の段の手前だったわけである。止まっているものを全部まとめて設定するのは dpkg --configure -a である。

設定をやり直す — dpkg-reconfigure

この節で分かること: 入れたあとで、パッケージの設定を質問からやり直す方法。

パッケージの中には、設定の段で利用者に質問をするものがある。代表が、機械のタイムゾーン（どの地域の時刻を使うか）を決める tzdata である。質問と答えは debconf（パッケージの質問と、その答えを覚えておくしくみ）が記録している。いまの設定を見る。

$ cat /etc/timezone
Etc/UTC
$ ls -l /etc/localtime
lrwxrwxrwx 1 root root 27 Sep 30 19:32 /etc/localtime -> /usr/share/zoneinfo/Etc/UTC
$ sudo debconf-show tzdata | sort
  tzdata/Areas: Etc
  tzdata/Zones/Africa:
  tzdata/Zones/America:
  tzdata/Zones/Antarctica:
  tzdata/Zones/Arctic:
  tzdata/Zones/Asia:
  tzdata/Zones/Atlantic:
  tzdata/Zones/Australia:
  tzdata/Zones/Etc: UTC
  tzdata/Zones/Europe:
  tzdata/Zones/Indian:
  tzdata/Zones/Legacy:
  tzdata/Zones/Pacific:

タイムゾーンは Etc/UTC（世界の基準の時刻）である。ls -l の行頭の l と、名前のあとの -> は、/etc/localtime が別のファイル（/usr/share/zoneinfo/Etc/UTC）を指す名札（シンボリックリンク。別の名前で同じファイルを指すもの）だという印である。debconf-show は、そのパッケージについて debconf が覚えている答えを出す（行の順番は打つたびに変わるので、sort で並べた）。質問をもう一度してもらうのが dpkg-reconfigure である。ふつうに打つと矢印キーで選ぶ画面が出るが、ここでは同じ質問を文字だけで出す形（-f teletype）にする。地域の一覧が出たら 5（Asia）と打って Enter、都市の一覧の途中で [More]（続きがある）と出たら Enter、最後に 78（Tokyo）と打って Enter を押す。

$ sudo dpkg-reconfigure -f teletype tzdata

------------------

questions will narrow this down by presenting a list of cities, representing
the time zones in which they are located.

最後の3行は、新しい設定での時刻の表示である（時刻は、あなたが打った時刻になる）。/etc/timezone が Asia/Tokyo に書き換わり、/etc/localtime の指す先が /usr/share/zoneinfo/Asia/Tokyo に付け替わった。dpkg-reconfigure は、パッケージを入れたときの「質問して設定する」手順を、入れ直さずにもう一度走らせる。答えは debconf の記録に残り（行頭の * は「その質問がもう出された」という印）、tzdata の設定の手順がその答えで設定ファイルを書き直した。設定ファイルを手で直す代わりに、パッケージ自身に直させる方法である。

たとえ: 家電の「初期設定をやり直す」メニューに近い。買ったときに答えた質問（地域・言語）にもう一度答えると、本体の設定が書き換わる。
ただし崩れる点: 家電の設定は本体の中だけで変わるが、dpkg-reconfigure の答えは2か所に残る。/etc の設定ファイル（/etc/timezone・/etc/localtime）と、debconf の記録（debconf-show の行頭の *）である。
手を動かす: 実践編の演習07は、リポジトリに無い単体の .deb ファイル（labnote）を、動く状態まで入れる課題である。 判定は dpkg の台帳で labnote と、labnote が必要とするパッケージの両方が ii になり、labnote が実際に動くかを見る。
確認

sudo dpkg -i foo.deb を実行したところ、依存関係のエラーで foo が設定されずに残った。 依存するパッケージをリポジトリから取ってきて、foo の設定まで済ませるコマンドを答えよ。

答え

sudo apt --fix-broken install（sudo apt-get -f install）。dpkg は依存関係を取りに行けないので、目録を持つ apt に続きをさせる（実測）。 最初から sudo apt install ./foo.deb と打てば、依存関係も解決して1回で入る。

確認

dpkg -l の行頭が iU のパッケージは、どういう状態か。

答え

入れたい（i）が、展開しただけで設定が済んでいない（U = Unpacked）。ファイルは置かれている。 依存関係が足りなくて dpkg -i が止まったときにこうなった（実測）。

確認

入っているパッケージを、入れたときの質問からやり直して設定し直すコマンドはどれか。
(a) dpkg --configure　(b) dpkg-reconfigure　(c) apt reinstall　(d) debconf-show

答え

(b)。例: dpkg-reconfigure tzdata。(a) は展開済み・設定前（iU）のものを設定するもので、設定済みのものの質問はしない。 (c) は中身を入れ直すもの（第4章）。(d) は記録された答えを見るだけ。

確認

dpkg -r と dpkg -P の違いを答えよ。

答え

-r は中身を消し、設定ファイル（conffile）は残して台帳を rc にする。-P は設定ファイルも消し、台帳の行も消す（実測）。 apt の remove と purge にあたる。

この章で分かったこと

持ち帰ってほしいこと

  • dpkg -i ファイル.deb は手元のファイルを入れる。apt は、リポジトリから取ってきたファイルを dpkg に渡している
  • dpkg は依存関係を読めるが取りに行かない。足りなければ展開まで進めて iU（展開済み・設定前）で止まり、apt はほかの操作も断る。apt --fix-broken install（apt-get -f install）が目録から取って続きをする。最初から apt install ./ファイル.deb でもよい
  • dpkg -r は設定ファイルを残して rc、dpkg -P は全部消す。依存されているものは消すのを断られる
  • dpkg -i は「展開（--unpack）」と「設定（--configure）」の2段
  • dpkg-reconfigure は入れたときの質問をやり直し、その答えで設定し直す。答えは debconf-show で見られる
