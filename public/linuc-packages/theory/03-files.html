3. 入れたファイルがどこに置かれたかを調べる

前の章までにやったこと: パッケージを入れて、使って、消した（第1章）。入っているものを一覧と詳しい情報で調べ、その答えが台帳（入れたときに dpkg が書く記録）から来ていることを確かめた（第2章）。この章でやること: パッケージを入れたとき、ファイルが檻のどこに置かれたかを調べる。逆に、あるファイルがどのパッケージから来たかを調べる。最後に、入れる前のパッケージのファイルの中を見る。

前提: 第2章まで読了前提: Debian 系の檻を起動し直した直後所要 18分影響度 B出題範囲 1.04.2（重要度1）出題範囲 1.04.1（重要度3）最終検証 2026-10-20

この章のゴール

  • パッケージが置いたファイルを dpkg -L で並べ、/usr/bin・/usr/share/doc・/usr/share/man・/etc がそれぞれ何の置き場所かを確かめる
  • あるファイルがどのパッケージから来たかを調べる方法を確かめる（コマンドなら、先に which で場所を出す）
  • .deb ファイルを入れずに取ってきて、dpkg -c で中身、dpkg -I で情報を見る
ここで覚えなくていいこと: この章に出てこない置き場所（/usr/lib・/var など）の役目、man の索引のしくみ、.deb ファイルの中の細かい形式（中にさらに縮めたファイルが入っていること）。この章は「ファイルとパッケージを、どちら向きにも引ける」が1回できれば足りる。

コマンドの場所 — which

この節で分かること: 入れたコマンドのファイルが、どこに置かれたか。

第1章と同じように labhello を入れる（出力は第1章と同じなので、途中を略す）。

$ sudo apt install labhello
...
Setting up labhello (1.0) ...
Processing triggers for man-db (2.12.0-4build2) ...
$ which labhello
/usr/bin/labhello

which は、コマンドの名前を受け取り、そのコマンドのファイルがどこにあるかを出す。シェルは、コマンドを探すディレクトリの並び（環境変数 PATH）を前から順に探していて、which はそれと同じ探し方をする。labhello は /usr/bin に置かれた。

パッケージが置いたファイル — dpkg -L

この節で分かること: 1つのパッケージが置いたファイルの全部と、置き場所ごとの役目。

置かれたのはコマンドのファイルだけではない。dpkg -L（listfiles）にパッケージの名前を渡すと、そのパッケージが置いたものを全部並べる。

$ dpkg -L labhello
/.
/usr
/usr/bin
/usr/bin/labhello
/usr/share
/usr/share/doc
/usr/share/doc/labhello
/usr/share/doc/labhello/README
/usr/share/man
/usr/share/man/man1
/usr/share/man/man1/labhello.1.gz

ファイルは3つで、残りの行はそれを入れておくディレクトリである（/. は一番上の / のこと）。置き場所には、それぞれ役目がある。

置き場所何のための場所かlabhello では
/usr/bin誰でも使うコマンドのファイルlabhello
/usr/share/doc/パッケージ名そのパッケージの説明書き（README など）README
/usr/share/manman コマンドで読む説明書。man1 はコマンドの説明の区分で、.gz は縮めて置いてある印labhello.1.gz
/etc設定ファイル（利用者や管理者が書き換えて、動きを変えるためのファイル）無い
$ cat /usr/share/doc/labhello/README
labhello 1.0 - 確かめて説明する LinuC 主題1.04 の練習用パッケージ
自分の版を1行表示するだけのコマンドです。

  labhello      → labhello 1.0 と表示する
$ man -w labhello
/usr/share/man/man1/labhello.1.gz

man -w は、man が読むファイルの場所だけを出す。man labhello と打てば説明書が開く（q で閉じる）のは、パッケージがここに置いたからである。

たとえ: 新しく入った同僚の荷物の置き方に近い。仕事道具は共用の道具棚（/usr/bin）、取扱説明書は資料室（/usr/share/doc）、自分の設定の書き付けは設定の棚（/etc）に、決まった場所へ置く。だから誰でも、探す場所の見当が付く。
ただし崩れる点: 人の荷物なら、置いた本人に聞けば場所が分かるだけだが、パッケージの場合は台帳に1つずつ書いてあるので、dpkg -L で本人がいなくても全部引ける。

ファイルからパッケージを引く — dpkg -S

この節で分かること: あるファイルが、どのパッケージから来たかを調べる方法。

今度は逆向きに、ふだん使っている ls がどのパッケージから来たかを調べたい。

ふつうこう考える

labhello は、パッケージの名前とコマンドの名前が同じだった。ls も ls というパッケージに入っているはずだから、dpkg -L ls で分かるだろう。

$ dpkg -L ls
dpkg-query: package 'ls' is not installed
Use dpkg --contents (= dpkg-deb --contents) to list archive files contents.
だめな理由: ls という名前のパッケージは入っていない（1行目）。パッケージの名前とコマンドの名前は、同じとは限らない。 1つのパッケージがたくさんのコマンドをまとめて入れていることも多い。 2行目は「.deb ファイルの中身を見るなら --contents を使え」という案内で、ここでは関係ない。 コマンドから出発するなら、パッケージの名前ではなく、ファイルからパッケージを引く。

まずファイルの場所を which で出し、そのファイルを dpkg -S（search）に渡す。

$ which ls
/usr/bin/ls
$ dpkg -S /usr/bin/ls
coreutils: /usr/bin/ls

ls は coreutils というパッケージに入っていた。ls・cp・mv のような基本のコマンドをまとめたパッケージである。答えは「パッケージ名: パス」の形で出る。labhello でも、設定ファイルでも同じように引ける。

$ dpkg -S /usr/bin/labhello
labhello: /usr/bin/labhello
$ dpkg -S /etc/sudoers
sudo: /etc/sudoers

/etc/sudoers は、sudo が「誰に何を許すか」を読む設定ファイルで、sudo という名前のパッケージが置いたものだった。sudo パッケージが /etc に置いたものを、dpkg -L と grep で並べる。

$ dpkg -L sudo | grep etc
/etc
/etc/pam.d
/etc/pam.d/sudo
/etc/pam.d/sudo-i
/etc/sudo.conf
/etc/sudo_logsrvd.conf
/etc/sudoers
/etc/sudoers.d
/etc/sudoers.d/README

パッケージは、コマンドと一緒に、その設定ファイルを /etc に置く。設定ファイルの場所が分からないときは、こうしてパッケージから引ける。

コマンド向き渡すもの
dpkg -L パッケージ名パッケージ → それが置いたファイルパッケージの名前
dpkg -S ファイルのパスファイル → それを置いたパッケージファイルのパス（which で出したもの など）

どちらも台帳を読んでいる。台帳には、パッケージごとに「置いたファイルの一覧」が書いてあり、-L はそれを前から、-S は後ろから引いている。

たとえ: 図書館の貸出台帳に近い。「この人が借りている本」（-L）も、「この本を借りている人」（-S）も、同じ台帳を逆向きに引くだけで答えが出る。
ただし崩れる点: 本は1冊を1人しか借りられないが、ディレクトリは多くのパッケージが一緒に使う。/usr/bin のようなディレクトリを dpkg -S に渡すと、そこにファイルを置いたパッケージが何十も並ぶ。

入れる前に中身を見る — .deb ファイル

この節で分かること: パッケージのファイル（.deb）に、何が入っているか。

apt はリポジトリからパッケージのファイルを取ってきて入れていた（第1章の Get: の行）。apt download は、入れずにそのファイルだけを取ってきて、いまいるディレクトリに置く。まだ入っていない labapp を取ってくる。

$ apt download labapp
Get:1 file:/srv/lab-repo lab/main amd64 labapp all 1.0 [1076 B]
$ ls -l
total 8
-rw-r--r-- 1 lab lab 1076 Oct 20 21:33 labapp_1.0_all.deb
drwxr-xr-x 2 lab lab 4096 Sep 30 19:32 work

labapp_1.0_all.deb が取れた（日時は、あなたが打った時刻になる。work は演習で使うディレクトリ）。ファイル名は「名前_版_アーキテクチャ.deb」の形で、.deb は Debian 系のパッケージのファイルの印である。apt download は root でなくても打てる。台帳も、ほかの誰かが使う場所も書き換えないからである。

.deb ファイルの中身の一覧は dpkg -c（contents）で見る。

$ dpkg -c labapp_1.0_all.deb
drwxr-xr-x root/root         0 2026-10-01 09:00 ./
drwxr-xr-x root/root         0 2026-10-01 09:00 ./etc/
-rw-r--r-- root/root        93 2026-10-01 09:00 ./etc/labapp.conf
drwxr-xr-x root/root         0 2026-10-01 09:00 ./usr/
drwxr-xr-x root/root         0 2026-10-01 09:00 ./usr/bin/
-rwxr-xr-x root/root       188 2026-10-01 09:00 ./usr/bin/labapp
drwxr-xr-x root/root         0 2026-10-01 09:00 ./usr/share/
drwxr-xr-x root/root         0 2026-10-01 09:00 ./usr/share/doc/
drwxr-xr-x root/root         0 2026-10-01 09:00 ./usr/share/doc/labapp/
-rw-r--r-- root/root       128 2026-10-01 09:00 ./usr/share/doc/labapp/README

ls -l と同じ形で、/ から見たファイルの木が並ぶ。入れると、この木がそのまま /etc/labapp.conf や /usr/bin/labapp として置かれる。root/root は、置いたときの持ち主とグループである。.deb ファイルには、もう1つ、パッケージの情報が入っている。それを読むのが dpkg -I（info）である。

$ dpkg -I labapp_1.0_all.deb
 new Debian package, version 2.0.
 size 1076 bytes: control archive=347 bytes.
      17 bytes,     1 lines      conffiles
     292 bytes,    10 lines      control
 Package: labapp
 Version: 1.0
 Section: utils
 Priority: optional
 Architecture: all
 Depends: liblab (>= 1.0)
 Installed-Size: 68
 Maintainer: check-then-explain <lab@example.invalid>
 Description: sample application that needs liblab
  Prints a greeting. The greeting is read from /etc/labapp.conf.

先頭の数行は情報の部分の大きさで、control が情報そのもの、conffiles が設定ファイルの印の一覧である。Package: から下が control の中身で、第2章の dpkg -s で見た欄と同じものが並ぶ。Depends: liblab (>= 1.0) は、labapp を動かすには liblab の 1.0 以上が要る、という依存関係である。

つまり .deb ファイルは、中身（ファイルの木）と情報（名前・版・依存関係など）の2つでできている。入れるときに、中身はディスクに置かれ、情報は台帳に写される。ファイルを取ってきただけなので、台帳にはまだ何も無い。

$ dpkg -l labapp
dpkg-query: no packages found matching labapp
たとえ: 送り状を同封した宅配の箱に近い。箱の中には品物（中身）と、品名・型番・「この部品と組み合わせて使うこと」と書いた紙（情報）が入っている。
ただし崩れる点: 本物の送り状は箱の外に貼ってあって開けずに読めるが、.deb の情報は箱の中にある。dpkg -I は、箱を開けて紙だけを取り出して読んでいる。
手を動かす: 実践編の演習03は、labsvc というコマンドが読んでいる設定ファイルを、場所を教えられないまま見つけて書き換える課題である。 コマンド → パッケージ → 置いたファイル、とたどる。判定は labsvc を実際に動かし、書き換わったのが設定ファイルだけかを台帳と照らし合わせて見る。
確認

/usr/bin/xyz というファイルを、どのパッケージが置いたかを調べたい。dpkg -L と dpkg -S のどちらを使うか。

答え

dpkg -S /usr/bin/xyz。-S はファイルからパッケージを引く。-L は向きが逆で、パッケージの名前を渡してファイルの一覧を出す。 dpkg -L ls のようにコマンドの名前を渡しても、同じ名前のパッケージが無ければ「入っていない」と言われる（実測）。

確認

まだ入れていない .deb ファイル foo.deb の中に、どんなファイルが入っているかを見るコマンドはどれか。
(a) dpkg -L foo.deb　(b) dpkg -c foo.deb　(c) dpkg -S foo.deb　(d) dpkg -s foo.deb

答え

(b)。-c は .deb ファイルの中身の一覧を出す。(a)・(c)・(d) は台帳を読むもので、入っているパッケージの名前やファイルのパスを渡す。 .deb ファイルの名前・版・依存関係を見るなら dpkg -I foo.deb。

確認

nginx_1.24.0-2ubuntu7_amd64.deb というファイル名から、パッケージの名前・版・アーキテクチャを読み取れ。

答え

名前 nginx・版 1.24.0-2ubuntu7・アーキテクチャ amd64。.deb のファイル名は「名前_版_アーキテクチャ.deb」を _ でつなぐ。 どの CPU でも動くものは all（labapp_1.0_all.deb のように）になる。

この章で分かったこと

持ち帰ってほしいこと

  • dpkg -L パッケージ名 で、そのパッケージが置いたファイルが全部分かる。コマンドは /usr/bin、説明書は /usr/share/doc と /usr/share/man、設定ファイルは /etc
  • dpkg -S ファイルのパス で、そのファイルを置いたパッケージが分かる。コマンドなら先に which で場所を出す。パッケージの名前はコマンドの名前と同じとは限らない（ls は coreutils）
  • .deb ファイルは中身（dpkg -c）と情報（dpkg -I）の2つでできている。apt download で、入れずに取ってこられる
  • 入れると、中身はディスクに置かれ、情報は台帳に写される。-L と -S は、その台帳を前から・後ろから引いている
