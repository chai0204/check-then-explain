10. yum のリポジトリを足して、署名を確かめる

前の章までにやったこと: RPM 系の檻で、yum で入れて消し、rpm に入っているものと置かれたファイルを聞き、yum が要らなくなった依存関係も消すことを確かめた（第9章）。Debian 系では、apt が見に行くリポジトリの表（sources.list）を読み、区分を足して apt update と apt upgrade で新しい版に上げた（第6章）。この章でやること: yum の設定とリポジトリの表を読み、新しい版の置き場を足して labhello を上げる。上げるときに出てくる問いをきっかけに、パッケージの署名と鍵を確かめる。最後に、入っていないパッケージを yum で探す。

前提: 第9章まで読了前提: RPM 系の檻を起動し直した直後所要 28分影響度 B出題範囲 1.04.3（重要度3）出題範囲 1.04.4（重要度1）最終検証 2026-10-21

この章のゴール

  • yum と dnf、/etc/yum.conf と /etc/dnf/dnf.conf の関係を ls -l で確かめる
  • /etc/yum.repos.d/ の .repo ファイル（[repo id]・name・baseurl・enabled・gpgcheck・gpgkey）を読み、リポジトリを足してから新しい版に上がるまでに何が要るかを確かめる
  • rpm -K の出力を読んで、署名が確かめられたかを判断し、鍵を台帳に取り込む方法を確かめる
  • 入っていないパッケージを yum search・info・provides・repoquery -l・deplist で調べる
ここで覚えなくていいこと: パッケージに署名する手順と鍵の作り方、鍵の失効、yum のモジュール（dnf module）とグループ（yum groupinstall）、RHEL のサブスクリプションの登録、yum.conf のこの章に出てこない項目。Last metadata expiration check の行は「目録を最後に確かめた時刻」と読めれば足りる（時刻は読者ごとに違う）。

yum と設定ファイル

この節で分かること: yum と打つと何が動き、どこに設定があるか。
$ ls -l /usr/bin/yum /usr/bin/dnf
lrwxrwxrwx 1 root root 5 Sep 22  2025 /usr/bin/dnf -> dnf-3
lrwxrwxrwx 1 root root 5 Sep 22  2025 /usr/bin/yum -> dnf-3
$ ls -l /etc/yum.conf
lrwxrwxrwx 1 root root 12 Sep 22  2025 /etc/yum.conf -> dnf/dnf.conf

yum も dnf も、同じ dnf-3 を指すシンボリックリンク（別の名前で同じファイルを指すもの）である。RHEL 8 から、yum の中身は dnf という新しい道具に置き換わった。yum という名前は、古い手順や試験の問題がそのまま使えるように残してある。打ち方（サブコマンドとオプション）はそのまま使えるが、既定の動きと出力の見た目は、RHEL 7 の yum と違うところがある（第9章の clean_requirements_on_remove のように）。設定ファイル /etc/yum.conf も、dnf/dnf.conf（つまり /etc/dnf/dnf.conf）へのリンクで、どちらを書き換えても同じファイルが変わる。

$ cat /etc/yum.conf
[main]
gpgcheck=1
installonly_limit=3
clean_requirements_on_remove=True
best=True
skip_if_unavailable=False
項目意味と、何のためにあるか
[main]この下が yum 全体の設定だという見出し
gpgcheck=1入れるパッケージの署名を確かめる。作った人が確かめられないパッケージを入れないため（この章の後半）
installonly_limit=3カーネル（Linux そのものの中心で動き、機械を直接動かすプログラム）のように、上書きせずに並べて入れるものを、3世代まで残す。新しいものが動かないとき、古いものに戻れるようにするため
clean_requirements_on_remove=True消すとき、要らなくなった依存関係も消す（第9章）
best=Trueいちばん新しい版を入れられないなら、失敗にする。古い版で黙って済ませないため
skip_if_unavailable=False目録を取れないリポジトリがあれば止まる。取れないまま古い目録で進めないため

リポジトリの表 — /etc/yum.repos.d/

この節で分かること: yum がどのリポジトリを使うかを、どこにどう書くか。

Debian 系の sources.list にあたるのが、/etc/yum.repos.d/ の .repo ファイルである。

$ ls /etc/yum.repos.d/
almalinux-appstream.repo         almalinux-plus.repo
almalinux-baseos.repo            almalinux-resilientstorage.repo
almalinux-crb.repo               almalinux-rt.repo
almalinux-extras.repo            almalinux-sap.repo
almalinux-highavailability.repo  almalinux-saphana.repo
almalinux-nfv.repo               lab.repo
$ cat /etc/yum.repos.d/lab.repo
# 檻の中の練習用リポジトリ（確かめて説明する LinuC 主題1.04）。
# 中身はイメージを作ったときから変わらないので、目録を期限切れにしない（metadata_expire=-1）。
[lab]
name=lab packages (LinuC 1.04)
baseurl=file:///srv/lab-rpm
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-lab
metadata_expire=-1

almalinux-… は AlmaLinux 本体のリポジトリで、lab.repo が練習用のリポジトリである。1つのリポジトリは [ ] で始まる1つのまとまりで、[ ] の中が repo id（そのリポジトリを指す名前）である。1つのファイルにいくつ書いてもよく、ファイルの名前は .repo で終わっていれば自由である。

項目この例では何のためにあるか
[lab]labrepo id。yum list の @lab や、yum repolist に出る名前
name=lab packages (LinuC 1.04)人が読むための説明
baseurl=file:///srv/lab-rpmリポジトリの場所。ふつうは https:// で始まるサーバ。file:// のあとに /srv/lab-rpm を続けると、檻の中のディレクトリになる（/ が3つ並ぶ。第6章の apt の file:/srv/lab-repo と同じ場所の書き方で、yum も file:/srv/… の形を読める）
enabled=1使う（0 なら書いてあっても使わない。必要なときだけ使うリポジトリのため）
gpgcheck=1このリポジトリのパッケージの署名を確かめる
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-lab署名を確かめる鍵のファイルの場所
metadata_expire=-1目録の期限。目録の写しを何秒で古いとみなすか。-1 は「古くならない」（この練習用リポジトリは中身が変わらないので、そうしてある）
$ yum repolist
repo id                         repo name
appstream                       AlmaLinux 9 - AppStream
baseos                          AlmaLinux 9 - BaseOS
extras                          AlmaLinux 9 - Extras
lab                             lab packages (LinuC 1.04)
$ yum repolist all
repo id                      repo name                                  status
appstream                    AlmaLinux 9 - AppStream                    enabled
appstream-debuginfo          AlmaLinux 9 - AppStream - Debug            disabled
appstream-source             AlmaLinux 9 - AppStream - Source           disabled
baseos                       AlmaLinux 9 - BaseOS                       enabled
...
lab                          lab packages (LinuC 1.04)                  enabled
...

repolist は使っている（enabled=1）リポジトリだけ、repolist all は enabled=0 のものも含めて全部を、status の欄つきで出す。この檻の AlmaLinux 本体のリポジトリは、更新の止まった 9.7 の保存庫に向けてある（日ごとに中身が変わる本来の配り先に向けると、読者ごと・日ごとに出力が変わるため）。

たとえ: 取引先ごとに1枚ずつ作った連絡先カードに近い。カードには、呼び名（repo id）・住所（baseurl）・取引中か（enabled）・印鑑を確かめるか（gpgcheck）・照合用の印影の場所（gpgkey）が書いてあり、カードを足せば取引先が増える。
ただし崩れる点: 連絡先カードは手元にあれば誰にでも連絡できるが、yum は enabled=0 と書いたカードを、読みはするが使わない。yum repolist all で disabled と出たリポジトリがそれである。

新しい版の置き場を足す

この節で分かること: リポジトリを足したあと、新しい版が見えるまでに要ること。

labhello を入れて（出力は略す）、新しい版 1.1 が置いてあるリポジトリ /srv/lab-updates-rpm の中を見る。

$ sudo yum install labhello
...
Installing:
 labhello            noarch            1.0-1               lab            7.4 k

...
Is this ok [y/N]: y
...
Installed:
  labhello-1.0-1.noarch

Complete!
$ ls /srv/lab-updates-rpm
labhello-1.1-1.noarch.rpm  repodata

.rpm ファイルと、repodata（RPM 系のリポジトリの目録の置き場）がある。これを .repo ファイルに書く。sudo tee ファイル は、受け取ったものを root の権限でファイルに書き、画面にも出す。ヒアドキュメント（第8章）で中身を渡す。

ふつうこう考える

第6章の apt と同じで、リポジトリを書き足したら、まず目録を取り直すコマンドが要るはずだ。それを打たずに更新できるものを聞いても、新しい版は出てこないだろう。

$ sudo tee /etc/yum.repos.d/lab-updates.repo <<'END'
> [lab-updates]
> name=lab updates (LinuC 1.04)
> baseurl=file:///srv/lab-updates-rpm
> gpgcheck=1
> gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-lab-updates
> END
[lab-updates]
name=lab updates (LinuC 1.04)
baseurl=file:///srv/lab-updates-rpm
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-lab-updates
$ yum check-update
lab updates (LinuC 1.04)                         64 kB/s | 960  B     00:00

labhello.noarch                        1.1-1                         lab-updates
$ echo $?
100
だめな理由: 出てきた。yum check-update（更新できるものを並べる）の1行目 lab updates (LinuC 1.04) … B/s | … B 00:00 は、目録を取りに行った記録である（速さと大きさは打つたびに違う）。この行の下に、第9章で見た Last metadata expiration check（目録を最後に確かめた時刻の知らせ）の行が出ることもある（取ってきてから1秒たったかどうかで、出たり出なかったりする）。 yum は、コマンドを打たれるたびに、使うリポジトリの目録の写しが手元にあるか、目録の期限（metadata_expire）が切れていないかを確かめ、無いか古ければ、その場で自分で取りに行く。足したばかりのリポジトリには写しが無いので、必ず取りに行く。 apt は apt update と言われるまで決して取りに行かなかった。同じ「目録の写し」を持つ道具でも、取り直す時機の決め方が違う。

check-update は、更新できるものがあれば終了コード 100、無ければ 0 を返す（失敗なら 1）。スクリプトで「更新があるか」を決めるのに使える。目録の写しは、ふつうは root が打てば /var/cache/dnf/ に、一般ユーザが打てば /var/tmp/dnf-ユーザ名-…/ に置かれる。この檻では2つを1か所にまとめてあり（/var/cache/dnf は /var/tmp/dnf-lab-cache を指す名札）、いま取ってきた lab-updates の分が増えている。

$ ls /var/cache/dnf/

appstream-filenames.solvx   extras.solv
appstream-updateinfo.solvx  hawkey.log
appstream.solv              lab-f54269022358d74c
baseos-a0068bac1404caa3     lab-filenames.solvx
baseos-filenames.solvx      lab-updates-562a72ee6b8fd388
baseos-updateinfo.solvx     lab-updates-filenames.solvx

dnf.librepo.log             lab.solv
dnf.log                     locks

expired_repos.json          tempfiles.json
extras-6ca639b91115fc97

lab-updates-… のディレクトリと、lab-updates.solv・lab-updates-filenames.solvx が、いま取ってきた分である。ディレクトリには取ってきた目録がそのまま入り、.solv は yum が速く読めるように作り直した形の目録、-filenames の付いたものは中のファイルの一覧である。ほかは AlmaLinux 本体と lab の分と、yum の作業の記録（.log など）である。

手で取り直させるコマンドもある。

コマンド何のためにあるかapt でいえば
yum makecache全部のリポジトリの目録を取ってきて、写しを作る（期限の内側でも中身が変わったと分かっているとき）。この檻では AlmaLinux 本体の分をネットの向こう（vault.almalinux.org）へ確かめに行くので、ネットが無いと失敗するapt update
yum clean all手元の目録の写しと、取ってきた .rpm を捨てる（写しが壊れたと疑わしいとき）。この檻で打つと、次の yum が AlmaLinux 本体の目録（約 53MB）を取り直す。ネットが無いと、目録の要る操作（lab から入れるのも含めた install や provides など）が Failed to download metadata for repo 'appstream' で止まり、檻を起動し直すまで直らない（入っているものを並べる・消す操作は動く）apt-get clean（取ってきた .deb を捨てる）と apt-get distclean（目録の写しを捨てる）を合わせたもの

署名と鍵 — rpm -K

この節で分かること: 署名が何を保証し、rpm -K の出力をどう読むか。

署名は、パッケージを作った人が、自分だけが持つ鍵（秘密鍵）で付ける印である。受け取った側は、それと対になる鍵（公開鍵。配ってよい鍵）で確かめると、「その人が作ったもので、あとから1バイトも書き換えられていない」ことが分かる。yum が取り込んだのは、この公開鍵である。rpm は、取り込んだ公開鍵を台帳に gpg-pubkey という名前で記録している。--qf は、出す形を自分で決めるオプションで、%{NAME} のように %{ } で囲んだ所に台帳のその欄（NAME は名前、VERSION は版、RELEASE はリリース、SUMMARY は一行の説明）が入り、\n は改行になる。

$ rpm -q gpg-pubkey --qf '%{NAME}-%{VERSION}-%{RELEASE}  %{SUMMARY}\n'
gpg-pubkey-b86b3716-61e69f29  AlmaLinux OS 9 <packager@almalinux.org> public key
gpg-pubkey-5236f3f6-6ad74395  lab packages <lab@example.invalid> public key
gpg-pubkey-a5824b40-6ad74395  lab updates <updates@example.invalid> public key

3つある。AlmaLinux の鍵、最初から入れてあった練習用リポジトリ lab の鍵、そしていま取り込んだ lab updates の鍵である。gpg-pubkey- の後ろの8桁が鍵の ID で、yum の問いに出た A5824B40 と同じ（小文字で書いている）。.rpm ファイルの署名を、取り込んである鍵で確かめるのが rpm -K（checksig）である。

$ rpm -K /srv/lab-updates-rpm/labhello-1.1-1.noarch.rpm
/srv/lab-updates-rpm/labhello-1.1-1.noarch.rpm: digests signatures OK

digests は「中身の要約（ダイジェスト）が合った＝壊れていない」、signatures は「署名を鍵で確かめた」、OK は「確かめたものが全部正しかった」である。次の2つは、檻の中の別の .rpm ファイルである。

$ rpm -K /srv/lab-files/labnosig-1.0-1.noarch.rpm
/srv/lab-files/labnosig-1.0-1.noarch.rpm: digests OK
$ rpm -K /srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm
/srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm: digests SIGNATURES NOT OK
$ rpm -Kv /srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm
/srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm:
    Header V4 RSA/SHA256 Signature, key ID b0f3d614: NOKEY
    Header SHA256 digest: OK
    Header SHA1 digest: OK
    Payload SHA256 digest: OK
    MD5 digest: OK

labnosig は誰も署名していないパッケージで、signatures という語自体が出ずに digests OK になった。署名が無くても OK と出る。OK は「確かめられたものは正しかった」という意味で、「作った人が確かめられた」という意味ではない。lab-mathtools は「lab tools」という別の鍵で署名してあり、その鍵は取り込んでいないので、SIGNATURES が大文字（確かめられなかったもの）で出て NOT OK になった。-v を足すと1行ずつ出て、NOKEY（その鍵 b0f3d614 を持っていない）が理由だと分かる。鍵は、yum を使わずに rpm --import で取り込むこともできる。

$ sudo rpm --import /srv/lab-tools-rpm/RPM-GPG-KEY-lab-tools
$ rpm -K /srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm
/srv/lab-tools-rpm/lab-mathtools-1.0-1.noarch.rpm: digests signatures OK

パッケージは1バイトも変えていないのに、signatures OK になった。変わったのは台帳（取り込んだ鍵）のほうである。最後に、中身を書き換えたらどう出るかを見る。AlmaLinux が署名した本物のパッケージ（tree）を写し、dd で末尾近くの1バイトを書き換える。dd は、決めた位置のバイトをそのまま書くコマンドである。bs=1 は1バイトずつ、seek=55888 は先頭から 55888 バイト進んだ所、conv=notrunc は残りを切り捨てない、status=none は経過を出さない、という指定で、壊れたファイルを作るためだけの操作なので、覚えなくてよい。printf 'A' は A の1文字だけを出す（echo と違って、最後に改行を付けない）。$HOME は、ホーム（~）の場所 /home/lab が入った環境変数で、~ と同じ所を指す。

$ rpm -K /srv/lab-files/tree-1.8.0-10.el9.x86_64.rpm
/srv/lab-files/tree-1.8.0-10.el9.x86_64.rpm: digests signatures OK
$ cp /srv/lab-files/tree-1.8.0-10.el9.x86_64.rpm ~/tree-copy.rpm
$ printf 'A' | dd of=$HOME/tree-copy.rpm bs=1 seek=55888 conv=notrunc status=none
$ rpm -K ~/tree-copy.rpm
/home/lab/tree-copy.rpm: DIGESTS SIGNATURES NOT OK

今度は DIGESTS まで大文字になった。中身の要約が合わず、署名も合わない。鍵が無いだけの NOKEY とは別で、こちらが「壊れている・書き換えられている」の印である。

rpm -K の出力意味入れてよいか
digests signatures OK壊れておらず、取り込んである鍵で署名を確かめられたその鍵の持ち主を信じるなら、よい
digests OK壊れていない。署名は無い（誰が作ったかは分からない）出どころを別の手段で確かめてから
digests SIGNATURES NOT OK署名はあるが、確かめられなかった（-Kv で NOKEY なら鍵が無いだけ）正しい鍵を取り込んでから確かめ直す
DIGESTS SIGNATURES NOT OK
DIGESTS signatures NOT OK		中身が壊れているか、書き換えられている（DIGESTS が大文字）。2つ目は、署名がファイルの見出しの部分（名前・版・中身の要約などを書いた所）だけに付いた .rpm の形で、見出しの署名は合ったが、中身がその要約と合わなかった。練習用のパッケージはこの付け方なので、中身を書き換えるとこう出る入れない

読み方は1つにまとめられる。署名の語（signatures）が小文字で、最後が OK のときだけ、署名が確かめられている。大文字の語は、その確かめが失敗したことを表す（DIGESTS が大文字なら、署名の語が小文字でも、中身が壊れている）。yum の gpgcheck=1 は、リポジトリから入れるときに、この確かめが通らないパッケージを入れないようにする設定である。

たとえ: 書類の印鑑を、登録してある印影の帳簿と照らし合わせる窓口に近い。印鑑の無い書類は照らし合わせようが無いので「照合で問題は見つからなかった」と言われ、登録の無い印鑑の書類は「照合できない」と言われる。照合できるようにするには、印影を帳簿に登録する（rpm --import）。
ただし崩れる点: 役所なら印鑑の無い書類はそもそも受け付けないが、rpm -K は「印鑑が無い」を失敗として扱わない。印鑑の無いものを断るのは、窓口の規則（yum の gpgcheck=1）のほうである。

入っていないパッケージを探す — yum の目録を引く

この節で分かること: 入れる前に、yum に何を聞けるか。

yum は目録を持っているので、入っていないパッケージについても答える。名前と説明から探すのが search、1つを詳しく見るのが info である。

$ yum search liblab
Last metadata expiration check: 0:00:09 ago on Tue Oct 20 23:09:15 2026.
========================= Name Exactly Matched: liblab =========================
liblab.noarch : small shell library for lab programs
=========================== Summary Matched: liblab ============================
labapp.noarch : sample application that needs liblab

search は、名前が一致したもの（Name Exactly Matched）と、説明（Summary）に語を含むもの（Summary Matched）を分けて出す。1行目は第9章で見た、目録を最後に確かめた時刻の知らせである。

$ yum info labtool
Last metadata expiration check: 0:00:10 ago on Tue Oct 20 23:09:15 2026.
Available Packages
Name         : labtool
Version      : 1.0
Release      : 1
Architecture : noarch
Size         : 6.7 k
Source       : labtool-1.0-1.src.rpm
Repository   : lab
Summary      : tool that needs labtool-data
URL          : https://github.com/chai0204/check-then-explain
License      : MIT
Description  : Prints a line shipped in labtool-data.

info の Available Packages は「入れられるもの」の印で、入っていれば Installed Packages になる。欄は第9章の rpm -qi と同じで、Repository がどのリポジトリの目録に載っているかである。

ファイル名からパッケージを探すのが provides である。入れる前でも答える。

$ yum provides /usr/bin/labtool
Last metadata expiration check: 0:00:11 ago on Tue Oct 20 23:09:15 2026.
labtool-1.0-1.noarch : tool that needs labtool-data
Repo        : lab
Matched from:
Filename    : /usr/bin/labtool
$ yum provides '*/liblab.sh'
Last metadata expiration check: 0:00:11 ago on Tue Oct 20 23:09:15 2026.
liblab-1.0-1.noarch : small shell library for lab programs
Repo        : lab
Matched from:
Filename    : /usr/lib/liblab/liblab.sh

答えは「パッケージ名-版-リリース.アーキテクチャ : 説明」の行と、どのリポジトリか（Repo）、どの名前で当たったか（Filename）である。パスの一部しか分からないときは、'*/liblab.sh' のように * を使う（シェルに先に解釈させないよう ' で囲む）。逆向きに、パッケージの中のファイルの一覧を出すのが repoquery -l である。

$ yum repoquery -l labtool
Last metadata expiration check: 0:00:12 ago on Tue Oct 20 23:09:15 2026.
/usr/bin/labtool

labtool が置くファイルは /usr/bin/labtool の1つである。repoquery は、もとは yum-utils という別の道具の中のコマンドで、いまの yum では yum repoquery とも repoquery とも打てる。依存関係を出すのが deplist である。

$ yum deplist labtool
Last metadata expiration check: 0:00:13 ago on Tue Oct 20 23:09:15 2026.
package: labtool-1.0-1.noarch
  dependency: /usr/bin/sh
   provider: bash-5.1.8-9.el9.x86_64
  dependency: labtool-data >= 1.0
   provider: labtool-data-1.0-1.noarch

deplist は、依存関係（dependency）と、それを満たすパッケージ（provider）の組を出す。labtool は、シェル（/usr/bin/sh。bash が満たす）と labtool-data を必要としている。

Debian 系では、ファイル名から探すのに apt-file と、その分の目録（Contents）が別に要った（第6章）。yum は追加の道具なしでできる。dnf の目録には、最初からファイルの一覧も入っているからである。入っていない本物のパッケージでも同じである。

$ rpm -qf /usr/bin/dig
error: file /usr/bin/dig: No such file or directory
$ yum provides /usr/bin/dig
Last metadata expiration check: 0:00:14 ago on Tue Oct 20 23:09:15 2026.
bind-utils-32:9.16.23-34.el9_7.1.x86_64 : Utilities for querying DNS name
                                        : servers
Repo        : appstream
Matched from:
Filename    : /usr/bin/dig

...

台帳しか読まない rpm -qf は、無いファイルには答えられない。yum provides は、dig（第6章で名前が出た、DNS を調べるコマンド）を入れるパッケージを、版ごとに全部並べた（長いので最初の1つの後を略した）。名前のあとの 32: はエポックという番号で、版の付け方を変えたときなどに足し、版の番号より先に比べる（ふだんの表示では省かれる）。

聞きたいこと入っているものだけ（rpm・台帳）入っていなくてよい（yum・目録）Debian 系（目録）
名前や説明で探す—yum search 語apt search
1つの詳しい情報rpm -qi 名前yum info 名前apt show
ファイル → パッケージrpm -qf パスyum provides パスapt-file search
パッケージ → ファイルrpm -ql 名前yum repoquery -l 名前apt-file list
依存関係rpm -qR 名前yum deplist 名前apt-cache depends
たとえ: 品物ごとの部品表まで載っている通販カタログに近い。部品の名前（ファイル名）から、それを使っている品物（パッケージ）を引ける。
ただし崩れる点: 紙のカタログは届いたときのままだが、yum のカタログ（目録の写し）は、期限が切れたり、リポジトリを足したりすると、次に引くときに yum が自分で取り直す。
手を動かす: 実践編の演習10は、まだ登録されていない別のリポジトリから、名前の分からないパッケージに入っている labcalc を入れる課題である（.repo を書く・yum provides で探す・署名の確認を切らずに入れる）。 判定は labcalc を動かし、そのリポジトリから yum で入ったか、その .repo が gpgcheck=1 のままか、鍵がパッケージより先に台帳に入ったかを見る。この章を打った檻のままではなく、檻を起動し直してから開く。この章の「署名と鍵」の節で取り込んだ lab tools の鍵が台帳に残っていると、演習の要の問い（鍵を取り込んでよいか）が出ないからである。
確認

独自のリポジトリを yum に登録したい。どのディレクトリに、どんな名前のファイルを置き、リポジトリの場所はどの項目に書くか。

答え

/etc/yum.repos.d/ に、名前が .repo で終わるファイルを置く。中は [repo id] で始まるまとまりにし、場所を baseurl= に書く。enabled=1 で使い、gpgcheck=1 と gpgkey= で署名の確かめ方を指定する（実測では、置いただけで yum が目録を取りに行った）。

確認

yum check-update の終了コードが 100 だった。何を意味するか。

答え

更新できるパッケージがある（目録に、入っている版より新しい版がある）。0 なら無い、1 ならエラー（実測で、labhello 1.1 が見えたときに 100）。

確認

rpm -K foo.rpm の結果が digests OK だった。foo.rpm の作り手は確かめられたか。

答え

確かめられていない。digests OK は中身が壊れていないことだけで、signatures の語が無いのは署名が無いから（実測で、誰も署名していない labnosig がこう出た）。 署名が確かめられたときは digests signatures OK と出る。

確認

インストールされていないパッケージも含めて、/usr/bin/dig を入れるパッケージを調べる yum のサブコマンドはどれか。
(a) yum search　(b) yum info　(c) yum provides　(d) yum list

答え

(c)（whatprovides とも書ける）。(a) は名前と説明しか見ない。入っているファイルなら rpm -qf でも分かるが、入っていなければ答えられない（実測）。

この章で分かったこと

持ち帰ってほしいこと

  • RHEL 8 以降の yum は dnf へのリンク。/etc/yum.conf も /etc/dnf/dnf.conf へのリンク
  • リポジトリは /etc/yum.repos.d/*.repo に [repo id]・name=・baseurl=・enabled=・gpgcheck=・gpgkey= で書く。yum repolist（all）で一覧
  • yum は目録が無い・古いと、コマンドを打った時点で自分で取りに行く（apt は apt update まで取りに行かない）。yum check-update は更新があれば終了コード 100
  • 署名は作った人と無改ざんを確かめる印。rpm -K は signatures が小文字で OK のときだけ確かめられている（署名が無いと digests OK、鍵が無いと SIGNATURES NOT OK、書き換えは DIGESTS）。鍵は yum の問いか rpm --import で台帳に取り込む
  • 入っていなくても、yum search・info・provides・repoquery -l・deplist で目録から調べられる
