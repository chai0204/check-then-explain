理論編 — リポジトリとパッケージ管理

LinuC レベル1 101 試験・主題1.04（apt・dpkg・yum・rpm）を、 練習用のコンテナ（檻）の中で実際に打って確かめる11章。 第1章で、まだ入っていないコマンドを1つ入れて、使って、消すところから始めます。 第1〜8章は Debian 系（Ubuntu）の檻で、第9〜11章は RPM 系（AlmaLinux）の檻で、同じことを順にやります。

出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

読む順番と、前提

第1章から順に読みます。各章の出力は、檻を起動し直した直後から本文の順に打ったものなので、章が変わるたびに檻を起動し直してください（exit して、もう一度 docker run）。 各章の冒頭に「前の章までにやったこと」と「この章でやること」を書いてあります。 前提として要るのは、主題1.01〜1.03 のコースで扱った範囲（端末でコマンドを打つ・ファイルとディレクトリ・パーミッション・sudo・パイプと grep・vi か sed）です。このコースが説明なしで使うものと、それが出たコースの章は、第1章の冒頭に一覧にしてあります。 それ以外の語は、使う前にその場で一言で説明しています。

前の版（1.0.x）でこの教材の演習を進めたことがある人は、章と演習の番号が変わったので、先に実践編の「はじめる」の「前の版（1.0.x）で進めた人へ」の箱を読んでください。

このコースの流れ

前の章でやったことだけを使って、次の章へ進みます。

章やること檻
1コマンドを1つ、パッケージとして入れて、使って、消すDebian 系
2・3いま何が入っているか、入れたファイルがどこに置かれたかを調べるDebian 系
4調べた答えの出どころ（台帳）を開き、ファイルと見比べるDebian 系
5ほかのパッケージが要るパッケージ（依存関係）を入れて、消すDebian 系
6パッケージを取ってくる場所（リポジトリ）を読み、足して、新しい版に上げるDebian 系
7・8.deb ファイルを直接入れ、最後に自分で作るDebian 系
9〜11同じことを RPM 系の yum と rpm でやり、署名も確かめるRPM 系

読み終えると、次のことができるようになります。

  • apt と yum でパッケージを入れる・上げる・消すことができ、出力を1行ずつ読める
  • 入っているもの・置かれたファイル・依存関係を、dpkg と rpm に聞いて調べられる
  • リポジトリを足し、署名を確かめ、.deb / .rpm ファイルから直接入れられる
ここで覚えなくていいこと: パッケージに署名する手順、優先度の書き換え（pinning）、yum のモジュールとグループ（dnf module・yum groupinstall）、aptitude、dnf5。 どれもレベル1の範囲の外で、この11章には出てきません（第8章のパッケージ作りも範囲の外ですが、それまでの章を1つにつなぐために入れてあります）。

檻が2つある理由

主題1.04 は Debian 系（apt・dpkg）と RPM 系（yum・rpm）の両方を問います。1つの Linux には片方しか無いので、 Debian 系の檻（Ubuntu 24.04）で第1〜8章を、RPM 系の檻（AlmaLinux 9.7）で第9〜11章を確かめます（起動のしかたは第1章と第9章の最初にあります）。 どちらの檻にも、練習用の小さなパッケージと、その配り元が入っていて、ネットにつながっていなくても本文と同じ結果になります （違って出るのは、Ubuntu と AlmaLinux 本体の配り元に取りに行くところだけで、どう違って出るかは、その章に書いてあります）。

試験の直前に見る表

出題範囲の「詳細」欄に並ぶ語を、一行の意味と、説明している章に並べました。章を読み終えてから使う表なので、各章で確かめる答えも書いてあります。

出題範囲の語一行の意味章
apt人が画面で打つための入口。install remove purge autoremove update upgrade search show list をまとめて持つ（スクリプトには apt-get・apt-cache）1・6
apt-getapt より前からある、入れる・消す・上げる道具。update は目録を取り直すだけ、upgrade は入っているものを上げる（新しく入れることが要るものは上げずに残す）、dist-upgrade は消すこともある、-f install は依存関係の足りないものを直す6・7
apt-cache目録を読むだけ。search 名前と説明、show 詳細、depends / rdepends 依存関係とその逆向き、showpkg 版ごとの依存関係と逆向きをまとめて、policy 目録の版と台帳の版5・6
apt-fileContents の目録を引き、入っていないパッケージも含めて「このファイルはどのパッケージか」（search）・「中身は何か」（list）に答える6
/etc/apt/sources.listどこから取るかの表。deb URI ディストリビューション コンポーネント の1行の形式。/etc/apt/sources.list.d/ の *.list と *.sources（deb822）も同じ扱い。書いたら apt update6
依存関係先に入っていなければならない別のパッケージ（.deb の Depends:、.rpm の Requires）。apt と yum は一緒に入れ、dpkg と rpm は読むが取りに行かない5・7・9・11
dpkgDebian 系の、ファイルを置いて台帳に書く道具。-l 一覧・-s 状態・-L パッケージ→ファイル・-S ファイル→パッケージ・-c / -I .deb の中身と情報・-V 台帳と照らし合わせ・-i 入れる・-r 消す（設定ファイルは残す）・-P 全部消す2〜4・7
dpkg-reconfigure入れたときの質問（debconf）をもう一度出し、その答えで設定し直す。例: dpkg-reconfigure tzdata7
リポジトリ中身（.deb / .rpm）の置き場と、目録（dists/…/Packages / repodata/）をまとめた配り場所6・10
yumRPM 系の、目録を読んで入れる道具。RHEL 8 以降は dnf へのリンク。入っているもの全部は list installed。provides でファイルからパッケージを、repoquery -l でパッケージの中身を、入っていなくても引ける。目録が無い・古いと自分で取り直す9・10
/etc/yum.repos.d/リポジトリを1つずつ書く .repo ファイルの置き場。[repo id] name= baseurl= enabled= gpgcheck= gpgkey=10
/etc/yum.confyum 全体の設定（[main]）。RHEL 8 以降は /etc/dnf/dnf.conf へのリンク。gpgcheck=1 installonly_limit clean_requirements_on_remove10
yumdownloader入れずに .rpm を取ってくる（--resolve で依存関係も）。RHEL 8 以降の実体は dnf の働きを呼ぶ道具へのリンク11
repoquery目録に聞く道具。repoquery -l 名前（yum repoquery -l）で、入っていないパッケージの中のファイルを出す10
rpmRPM 系の、ファイルを置いて台帳に書く道具。-q の仲間で台帳を引き（-p を付けると .rpm ファイルに聞く）、-V で照らし合わせ、-i / -U / -F / -e で入れて消す9・11
署名作った人が鍵で付ける印。rpm -K で確かめ、signatures が小文字で OK のときだけ確かめられている（署名が無いと digests OK）。大文字は失敗。鍵は yum の問いか rpm --import で台帳へ10

取り違えやすい組み合わせも並べておきます。どれも本文で両方を実際に打っています。

組み合わせ違い章
apt remove と apt purgeremove は設定ファイル（conffile）を残して台帳に rc（conffile も、消すときの手順 postrm も無いパッケージは行ごと消える）、purge は全部消す5
apt update と apt upgradeupdate は目録を取り直すだけ、upgrade は入っているものを上げる6
dpkg -S と apt-file searchどちらもファイル→パッケージ。-S は入っているものだけ、apt-file は入っていなくてよい6
dpkg -l と dpkg -L小文字は台帳の一覧、大文字は1つのパッケージのファイルの一覧2・3
dpkg -i と apt install ./ファイルdpkg は依存関係が足りないと iU で止まる。apt はファイルを渡されても目録から依存関係を入れる7
rpm -qf と rpm -ql-qf はファイル→パッケージ、-ql はパッケージ→ファイル9
rpm -qf と yum providesrpm は入っているものだけ、yum は入っていなくてよい10
rpm -i と -U と -F-i は新しく入れる（古い版があるとぶつかる）、-U は上げるか入れる（入っているのと同じ版・古い版は断る）、-F は入っているものだけ上げる11
dpkg -V と rpm -Vどちらも違うファイルだけを出す。dpkg は中身の要約しか持たず、違っても終了コード 0。rpm は欄が埋まり、終了コードも 0 以外4・11
dpkg -i と rpm -iどちらも依存関係を取りに行かない。dpkg は展開まで進めて止まり、rpm は1つも入れずに止まる7・11

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの4つに集まります。

場面ここで効く理由見落としやすい点関連する章
「コマンドが無い」と言われた どのパッケージに入っているかは、入っていない以上、台帳ではなく目録に聞く Debian 系は apt-file と Contents の目録が別に要る。RPM 系は yum provides だけで足りる6・10
配られた単体の .deb / .rpm を入れる 依存関係を取ってこられるのは目録を持つ apt / yum だけ dpkg -i は依存関係が足りないと iU で止まり、ほかの操作まで止める。apt install ./x.deb や yum install ./x.rpm なら1回で済む7・11
サーバのファイルが勝手に変わっていないか確かめる 台帳は入れたときのファイルの姿を持っている rpm -Va は何十行も出ることがある（この檻でも、一般ユーザで31行、sudo を付けて21行）。設定ファイル（c）以外の 5 と M から見る。dpkg -V は終了コードで判定できない4・11
新しいリポジトリを足す 足しただけでは目録は変わらない（apt）／自分で取りに行く（yum） 署名の確認を外す（[trusted=yes]・gpgcheck=0）のは最後の手段。鍵の出どころを確かめて Signed-By / gpgkey= で指定する6・10

この主題を使わない方がよい場面も1つあります。動いているコンテナに apt install や yum install で後から足していくことです。 コンテナは作り直すと元に戻るので、足したものはイメージの作り方（Dockerfile）に書いて作り直します （この教材の檻が起動し直すたびに初めの状態へ戻るのも、そのためです）。

読み終えたら

11章を通すと、パッケージ管理のコマンドが多いのに整理できる理由が見えてきます。パッケージを入れると、ファイルが置かれ、入れたという記録（台帳）が書かれる。apt と yum はリポジトリの目録を読んで取ってきて、dpkg と rpm がファイルを置き、台帳に書く。答えが食い違ったら、いま見ているのが「ファイル」「台帳」「目録」のどれかを確かめる、という1つの見方で、どの章のコマンドも並べられます（第8章と第11章の最後にまとめてあります）。

檻でそのままでは再現できないものが3つあり、本文にその理由ごと書いてあります。 (1) 本物の Ubuntu のパッケージに対する apt-file search: Ubuntu の Contents の目録は3つの区分で約 195MB あり、 apt update のたびに読者に取らせるのは重すぎるので、この檻では取らない設定にした（設定を消せば同じように引ける。第6章）。 (2) dpkg-reconfigure の矢印キーで選ぶ画面: 画面いっぱいに描く画面は、本文に写せる文字の並びにならないので、同じ質問を文字だけの形（-f teletype）で出して打った（第7章）。矢印キーの画面そのものは、探る記録に画面ごと残してある。 (3) 本物のリポジトリの「今の最新」: 出力が日ごとに変わるので、Ubuntu は snapshot（2026-09-29 で固定）、AlmaLinux は更新の止まった 9.7 の保存庫（vault）に向けた。 打てないことを黙って飛ばしてはいません。

手を動かす

読んだあと、同じ操作を自分でやる演習が12本あります（Debian 系の檻で8本、RPM 系の檻で4本）。1本目は第1章をなぞれば通り、後ろほど前の章の操作を組み合わせます。判定は観測できる結果だけで行い、コマンドの打ち方は見ません。
