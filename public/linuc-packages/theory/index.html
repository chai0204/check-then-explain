理論編 — リポジトリとパッケージ管理

LinuC レベル1 101 試験・主題1.04（apt・dpkg・yum・rpm）を、 Debian 系と RPM 系の2つの檻の中で実際に打って確かめる7章。 1章ごとに「ふつうはこう考える」を先に置き、実際に打った結果がそれを裏切るところから説明しています。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この7章を貫いている1つの事実

パッケージのコマンドは、どれも帳簿を読んでいるだけである。 手元に入ったものの「台帳」（dpkg・rpm）か、リポジトリにあるものの「目録」（apt・yum）か。 答えが食い違ったら、どちらの帳簿を読んだかを先に疑う。

中身を手で置いても dpkg -l は「入っていない」と言う（台帳に無いから）。 リポジトリを書き足しても apt install は「見つからない」と言う（目録の写しを取り直していないから）。 dpkg -S は入っていないパッケージのファイルを知らず、apt-file と yum provides は知っている（読む帳簿が違うから）。 主題1.04 のオプションが多いのに整理できるのは、どの帳簿を、どちら向きに引くかで全部が分けられるからです。

ここで覚えなくていいこと: パッケージの作り方（dpkg-deb --build・rpmbuild）、リポジトリや パッケージへの署名のしかた、 pinning（優先度の書き換え）、モジュールとグループ（dnf module・yum groupinstall）、aptitude、dnf5。 どれもレベル1の範囲の外で、この7章には手順としては出てきません。

檻でそのままでは再現できないものが3つあり、本文にその理由ごと書いてあります。 (1) 本物の Ubuntu のパッケージに対する apt-file search: Ubuntu の Contents 目録は3スイートで約 195MB あり、 apt update のたびに読者に取らせるのは重すぎるので、この檻では取らない設定にした（設定を消せば同じように引ける）。 (2) dpkg-reconfigure の質問の画面: 矢印キーで選ぶ画面は記録に残せないので、同じ質問を文字だけの形（-f teletype）で出させて記録した。 (3) 本物のリポジトリの「今の最新」: 出力が日ごとに変わるので、Ubuntu は snapshot（2026-09-29 で固定）、AlmaLinux は更新の止まった 9.7 の保存庫（vault）に向けた。 打てないことを黙って飛ばしてはいません。

apt人が画面で打つための入口。install remove purge update upgrade search show list をまとめて持つ（スクリプトには向かない）2
apt-get目録を読んで入れる・消す・上げる道具。update は目録を取り直すだけ（root が要る）、upgrade は入っているものを上げる（新しく入れも消しもしない。apt upgrade は依存のためなら新しく入れる）、dist-upgrade は消すこともある、clean は取ってきた .deb を消す2

/etc/apt/sources.listどこから取るかの表。deb URI ディストリビューション コンポーネント の1行形式。/etc/apt/sources.list.d/ の *.list と *.sources（deb822）も同じ扱い。書いたら apt update3

dpkg-reconfigure入れたときの質問（debconf）をもう一度出し、その答えで設定し直す。例: dpkg-reconfigure tzdata4

yumRPM 系の、目録を読んで入れる道具。RHEL 8 以降は dnf へのリンク（形はそのまま使えるが、既定値と出力は RHEL 7 と違うところがある）。provides でファイルからパッケージを、repoquery -l でパッケージの中身を、入っていなくても引ける。目録は期限切れなら自分で取り直す5
/etc/yum.repos.d/リポジトリを1つずつ書く .repo ファイルの置き場。[repo id] name= baseurl= enabled= gpgcheck= gpgkey=5

yumdownloader入れずに .rpm を取ってくる（--resolve で依存も、--destdir で置き場所を指定）。yum-utils に入っていて、RHEL 8 以降の実体は dnf download（RHEL 7 は独立した Python のプログラム）5
rpmRPM 系の台帳を読み書きする道具。-q 系で引き、-V で照らし合わせ、-i / -U / -F / -e で入れて消す。-p を付けると .rpm ファイルに聞く6・7
署名作った人が鍵で付ける印。rpm -K で確かめ、署名の語（RHEL 8 以降は signatures、RHEL 7 は rsa・pgp）が小文字で OK のときだけ確かめられている（RHEL 8 以降で署名が無いと digests OK、RHEL 7 なら sha1 md5 OK）。大文字は失敗。鍵は rpm --import で台帳へ7

檻が2つある理由

主題1.04 は Debian 系（apt・dpkg）と RPM 系（yum・rpm）の両方を問います。1つのディストリビューションには片方しか無いので、 Debian 系の檻（Ubuntu 24.04）で第1〜4章を、RPM 系の檻（AlmaLinux 9.7）で第5〜7章を確かめます（第1章の後半だけ RPM 系の檻も使います）。 どちらの檻にも、練習用の小さなパッケージ（依存関係つき・署名つき・署名なし）とリポジトリが入っていて、ネットにつながっていなくても本文と同じ結果になります。 本物の Ubuntu / AlmaLinux のパッケージを入れる操作だけは、ネットが要ります。

各章の出力は、檻を起動し直した直後から打ったものです。前の章で入れたものが残っていると出力が変わるので、章が変わるたびに檻を起動し直してください（exit して、もう一度 docker run）。

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの4つに集まります。

場面ここで効く理由見落としやすい点関連する章
「コマンドが無い」と言われた どのパッケージに入っているかは、入っていない以上、台帳ではなく目録に聞く Debian 系は apt-file を別に入れて Contents を取る必要がある。RPM 系は yum provides だけで足りる3・5
ベンダーが配る単体の .deb / .rpm を入れる 依存関係を解決できるのは目録を持つ apt / yum だけ dpkg -i は iU で止まり、ほかの操作まで止める。apt install ./x.deb や yum install ./x.rpm なら1回で済む4・7
サーバの設定が勝手に変わっていないか確かめる 台帳は入れたときのファイルの姿を持っている rpm -Va は実機でも何十行も出る。設定ファイル（c）以外の 5 と M から見る。dpkg -V は終了コードで判定できない4・6
新しいリポジトリを足す 足しただけでは目録は変わらない（apt）／勝手に取りに行く（yum） 署名の確認を外す（[trusted=yes]・gpgcheck=0）のは最後の手段。鍵の出どころを確かめて Signed-By / gpgkey= で指定する3・5・7

この主題を使わない方がよい場面も1つあります。コンテナのイメージの中で、動いているコンテナに apt install や yum install で後から足していくことです。 コンテナは作り直すと元に戻るので、足したものは Dockerfile に書いてイメージを作り直します （この教材の檻が起動し直すたびに初期状態へ戻るのも、そのためです）。
