6. rpm -V が黙っているのは、台帳どおりだから

rpm -V でパッケージを台帳と照らし合わせても、何も出ないことがある。確かめられなかったのではない。違うところが1つも無かったのである。rpm の台帳は、入れたときの各ファイルの大きさ・権限・中身の要約・時刻まで持っていて、いまの姿と違う欄だけを報告する。

前提: 第5章まで読了前提: RPM 系の檻を起動し直した直後所要 20分影響度 B出題範囲 1.04.4（重要度1）最終検証 2026-10-13

この章のゴール

  • rpm -q の主なオプション（-qa -qi -ql -qf -qc -qd -qR --provides --whatrequires）と、ファイルに聞く -qp を使い分けられる
  • rpm -V の出力の9文字の欄を読んで、何が変わったかを言える
  • 設定ファイル（%config）が、入れ直しと削除でどう扱われるかを言える
  • rpm2cpio で、入れずに中身を取り出せる
ここで覚えなくていいこと: --queryformat の書き方、rpm -V の D・L・P の欄が出る場面、--setugids、台帳の作り直し（rpm --rebuilddb）、spec ファイルの %config(noreplace) の書き方。

台帳を引く — rpm -q

この節で分かること: 入っているパッケージについて、rpm の台帳に何を聞けるか。
$ rpm -qa | wc -l
182
$ rpm -qa 'lab*'
labmotd-1.0-1.noarch
labhello-1.0-1.noarch
$ rpm -q labhello
labhello-1.0-1.noarch
$ rpm -q labapp; echo "exit=$?"
package labapp is not installed
exit=1
$ rpm -qi labhello
Name        : labhello
Version     : 1.0
Release     : 1
Architecture: noarch
Install Date: Tue Oct 13 10:08:56 2026
Group       : Unspecified
Size        : 34
License     : MIT
Signature   : RSA/SHA256, Tue Oct 13 10:08:48 2026, Key ID 0ba6fe4393f77b82
Source RPM  : labhello-1.0-1.src.rpm
Build Date  : Thu Oct  1 09:00:00 2026
...
Summary     : prints its own version
$ rpm -ql labhello
/usr/bin/labhello
$ rpm -qf /usr/bin/labhello
labhello-1.0-1.noarch

-q（query）がつくものは全部「台帳に聞く」である。-qa は全部（all）、-qi は情報（info）、-ql はファイルの一覧（list）、-qf はファイルからパッケージ（file）。入っていなければ is not installed と終了コード 1 が返る。-qi の Install Date は台帳に書かれた日時で、第1章で見た「まだ入っていないファイル」では (not installed) だった。

依存関係を持つ labapp を入れて、もう少し聞く。

$ sudo yum install -y labapp
...
Installing:
 labapp             noarch             1.0-1              lab             7.3 k
Installing dependencies:
 liblab             noarch             1.0-1              lab             6.7 k
...
Complete!
$ rpm -ql labapp
/etc/labapp.conf
/usr/bin/labapp
/usr/share/doc/labapp/README
$ rpm -qc labapp
/etc/labapp.conf
$ rpm -qd labapp
/usr/share/doc/labapp/README
$ rpm -qR labapp
/usr/bin/sh
config(labapp) = 1.0-1
liblab >= 1.0
rpmlib(CompressedFileNames) <= 3.0.4-1
rpmlib(FileDigests) <= 4.6.0-1
rpmlib(PayloadFilesHavePrefix) <= 4.0-1
rpmlib(PayloadIsZstd) <= 5.4.18-1
$ rpm -q --provides liblab
liblab = 1.0-1
$ rpm -q --whatrequires liblab
labapp-1.0-1.noarch

-qc は設定ファイル（config）、-qd は文書（doc）だけを出す。どちらも、パッケージを作るときに付けられた印で分けている。-qR（requires）には liblab >= 1.0 のほかに、/usr/bin/sh（中のスクリプトを動かすシェル）や rpmlib(…)（rpm 自身が対応していなければならない機能）も並ぶ。--provides は「これが満たすもの」、--whatrequires は「これを必要としている、入っているもの」で、Debian の apt-cache rdepends にあたる。

入っていないパッケージに -ql を使っても答えは無い。ファイルに聞くときは p を足す（第1章）。

$ rpm -ql labtool; echo "exit=$?"
package labtool is not installed
exit=1
$ rpm -qpl /srv/lab-rpm/labtool-1.0-1.noarch.rpm
/usr/bin/labtool
$ rpm -qpi /srv/lab-rpm/labtool-1.0-1.noarch.rpm | head -4
Name        : labtool
Version     : 1.0
Release     : 1
Architecture: noarch
オプション聞く相手答えDebian 系
rpm -qa台帳入っている全パッケージdpkg -l
rpm -q 名前台帳入っている版（無ければ not installed）dpkg -l 名前
rpm -qi 名前台帳詳しい情報dpkg -s 名前
rpm -ql 名前台帳ファイルの一覧dpkg -L 名前
rpm -qf パス台帳そのファイルを入れたパッケージdpkg -S パス
rpm -qc 名前 / -qd 名前台帳設定ファイル / 文書だけ（dpkg -s の Conffiles）
rpm -qR 名前台帳必要とするものapt-cache depends
rpm -q --whatrequires 名前台帳これを必要としているものapt-cache rdepends
rpm -qp□ ファイル.rpm ファイル□ に i / l / R などを付けて同じことをファイルに聞くdpkg -I / -c
たとえ: 図書館の貸出台帳に近い。「この人は何を借りているか」（-ql）と 「この本は誰が借りているか」（-qf）は、同じ台帳を逆向きに引いているだけである。
ただし崩れる点: 貸出台帳は本の題名しか記録しないが、rpm の台帳はファイルごとに大きさ・権限・中身の要約まで記録している。 だから次の節のように、いまの姿と「入れたときの姿」を比べることまでできる。

台帳と照らし合わせる — rpm -V

この節で分かること: rpm -V が何を比べ、何も出ないときに何を意味するか。

ふつうこう考える

照らし合わせたのだから、何か結果が出るはずだ。「OK」でも「一致」でもよい。 何も出ないのは、照らし合わせられなかった（何かがおかしい）からだろう。

$ rpm -V labhello
$ rpm -V labhello; echo "exit=$?"
exit=0
$ rpm -V nosuchpkg; echo "exit=$?"
package nosuchpkg is not installed
exit=1
だめな理由: 何も出ず、終了コードは 0 だった。照らし合わせられないときは、 nosuchpkg のように理由が出て、終了コードも 0 以外になる。 何も出ないのは「台帳と違うファイルが1つも無い」という答えである。 rpm -V は違う欄のあるファイルだけを1行ずつ出す。 UNIX のコマンドの多くと同じく、うまくいったときは黙っている。

2か所変えてみる。設定ファイルに1行書き足し、コマンドの実行の許可を外す。

$ echo 'greeting="こんにちは"' | sudo tee -a /etc/labapp.conf
greeting="こんにちは"
$ labapp
liblab: こんにちは from labapp 1.0
$ sudo chmod 0644 /usr/bin/labhello
$ labhello; echo "exit=$?"
...
exit=126
$ rpm -V labapp labhello; echo "exit=$?"
S.5....T.  c /etc/labapp.conf
.M.......    /usr/bin/labhello
exit=2

labhello は Permission denied（実行の許可が無い）で動かなくなった。rpm -V は変えた2つのファイルだけを出した（終了コードは、違いのあったパッケージの数になっていた）。左の9文字は、台帳と比べた結果を欄ごとに並べたものである。

S.5....T.  c /etc/labapp.conf
^^^^^^^^^  ^
|||||||||  ファイルの種類（c = 設定ファイル、d = 文書。空白はふつうのファイル）
SM5DLUGTP の順に、違った欄だけ文字が入り、同じなら「.」
文字比べたものこの章で出た場面
S大きさ（Size）設定ファイルに1行足した
M権限と種類（Mode）chmod 0644 で実行の許可を外した
5中身の要約（MD5 などのダイジェスト）中身を変えた
Dデバイス番号—
Lシンボリックリンクの行き先—
U / G所有者 / グループ—
T更新時刻（mTime）書き足して時刻が変わった
Pケーパビリティ—
?確かめられなかった（読む権限が無い など）一般ユーザで、root しか読めないファイルを比べたとき

Debian の dpkg -V（第4章）は同じ形で出すが、台帳に中身の要約しか無いので 5 以外の欄が ? になり、終了コードも 0 のままだった。rpm -V は欄が埋まり、終了コードでも違いを知らせる。

台帳どおりに戻すには、同じ版を入れ直す。

$ sudo yum reinstall -y labhello
...
Reinstalling:
 labhello            noarch            1.0-1               lab            6.6 k
...
Complete!
$ rpm -V labhello; echo "exit=$?"
exit=0
$ labhello
labhello 1.0

黙った。権限も中身も台帳どおりに戻り、labhello が動いた。ところが設定ファイルは戻らない。

$ sudo yum reinstall -y labapp
...
Reinstalling:
 labapp             noarch             1.0-1              lab             7.3 k
...
Complete!
$ rpm -V labapp; echo "exit=$?"
S.5....T.  c /etc/labapp.conf
exit=1
$ ls -l /etc/labapp.conf*
-rw-r--r-- 1 root root 118 Oct 13 10:47 /etc/labapp.conf
$ sudo rpm -e labapp
warning: /etc/labapp.conf saved as /etc/labapp.conf.rpmsave
$ ls -l /etc/labapp.conf*
-rw-r--r-- 1 root root 118 Oct 13 10:47 /etc/labapp.conf.rpmsave

labapp の設定ファイルは、作るときに「利用者が書き換えたら上書きしない」という印（%config(noreplace)）が付いている。だから入れ直しても、書き足した 118 バイトのまま残った。そして消したとき（rpm -e）には捨てずに .rpmsave という名前で取っておいた。書き換えた設定を勝手に捨てないという考え方は、Debian の rc（第2章）と同じで、残し方が違う。

書き換えた設定ファイルDebian 系RPM 系
入れ直したときそのまま残る（dpkg -V に出続ける）そのまま残る（rpm -V に出続ける）
消したときそのまま残り、台帳に rc.rpmsave に名前を変えて残り、台帳からは消える
完全に消すにはdpkg -P / apt purge残った .rpmsave を自分で消す

全部のパッケージをまとめて照らし合わせるのが rpm -Va である。

$ rpm -Va | wc -l
31
$ rpm -Va
S.5....T.  c /etc/yum.repos.d/almalinux-appstream.repo
S.5....T.  c /etc/yum.repos.d/almalinux-baseos.repo
...
.M.......    /
missing     /boot
missing     /usr/share/i18n/charmaps
missing     /usr/share/i18n/locales
..?......  c /etc/libaudit.conf
...
.M.......  c /etc/machine-id
...
.M...UG..    /var/cache/dnf
...
..?......  c /etc/sudoers
...

31行出た。実機でも何十行も出るのがふつうで、全部が異常ではない。c の付いた設定ファイルは書き換えて使うものであり（この檻では第5章のリポジトリの向き先を書き換えた）、missing はコンテナのイメージで省かれたディレクトリ、? は一般ユーザでは読めないファイルである。/var/cache/dnf は、この檻で目録を共有するためにリンクに置き換えた跡だ。読み方は、設定ファイルでないのに 5 や M が付いた行から先に疑うことである。

たとえ: 賃貸の退去点検で、入居したときの写真と部屋の今を比べる作業に近い。 点検表には「傷がある」「色が違う」項目だけが書かれ、何も書かれていなければ元どおりということである。
ただし崩れる点: 写真で比べられるのは見た目だけだが、rpm は中身の要約（5）まで比べる。 見た目（大きさや時刻）を同じにしても、中身が1文字違えば見つかる。

入れずに中身を取り出す — rpm2cpio

この節で分かること: .rpm の中のファイルを、台帳に触らずに取り出す方法。
$ rpm2cpio /srv/lab-rpm/labtool-1.0-1.noarch.rpm | cpio -t
1 block
./usr/bin/labtool
$ cd ~/work && rpm2cpio /srv/lab-rpm/labtool-1.0-1.noarch.rpm | cpio -idmv
./usr/bin/labtool
1 block
$ ls -l ~/work/usr/bin/labtool
-rwxr-xr-x 1 lab lab 98 Oct  1 09:00 /home/lab/work/usr/bin/labtool
$ rpm -qf ~/work/usr/bin/labtool; echo "exit=$?"
file /home/lab/work/usr/bin/labtool is not owned by any package
exit=1
$ rpm -q labtool; echo "exit=$?"
package labtool is not installed
exit=1

rpm2cpio は .rpm の中身を cpio という形式の固まりにして標準出力へ出す。受け取った cpio の -t は一覧、-i は取り出し、-d は途中のディレクトリを作る、-m は時刻を保つ、-v は取り出したものを表示する。カレントディレクトリの下に ./usr/bin/labtool として取り出されたので、root も要らない。台帳は何も知らない（第1章と同じ）。壊れた設定ファイルの元の姿を1つだけ見たいときなどに使う。

たとえ: 届いた箱から説明書だけ抜き出して読み、品物は棚に入れない使い方に近い。
ただし崩れる点: 箱から抜いた説明書は箱の付属品だと分かるが、取り出したファイルには「どのパッケージから出たか」の記録が残らない。 rpm -qf に聞いても「誰のものでもない」と答える。
手を動かす: 実践編の演習05は、入れたあとで2か所いじられた labmotd を、台帳と照らし合わせて突き止め、入れた直後の状態に戻す課題である。 判定は rpm -V labmotd が黙ること（終了コード 0）と、labmotd が実際に動くことを見る。
確認

/usr/bin/ssh がどの RPM パッケージに含まれるかを調べるコマンドはどれか（インストール済みの場合）。
(a) rpm -ql /usr/bin/ssh　(b) rpm -qf /usr/bin/ssh　(c) rpm -qi /usr/bin/ssh　(d) rpm -V /usr/bin/ssh

答え

(b)。-qf はファイルからパッケージを引く。逆にパッケージからファイルの一覧を出すのが -ql。 入っていないパッケージのファイルなら、台帳には無いので yum provides /usr/bin/ssh（第5章）を使う。

確認

rpm -V httpd の出力に S.5....T. c /etc/httpd/conf/httpd.conf とあった。何を意味するか。

答え

設定ファイル（c）の大きさ（S）・中身の要約（5）・更新時刻（T）が、入れたときと違う。つまり書き換えられている。 設定ファイルなら意図して書き換えたことが多い。権限（M）・所有者（U）・グループ（G）は入れたときのままである。 何も出なければ、全ファイルが台帳どおりということになる。

確認

インストール済みのパッケージ foo について、(1) 設定ファイルだけ、(2) foo が必要とするもの、を表示するコマンドをそれぞれ答えよ。

答え

(1) rpm -qc foo、(2) rpm -qR foo（--requires）。 文書だけなら rpm -qd foo、foo を必要としている側を知りたいなら rpm -q --whatrequires foo。

確認

RPM ファイルをインストールせずに、中のファイルをカレントディレクトリに取り出すコマンドを答えよ。

答え

rpm2cpio foo.rpm | cpio -idmv。rpm2cpio が中身を cpio 形式で出し、cpio -i が取り出す。 一覧だけなら rpm2cpio foo.rpm | cpio -t、または rpm -qpl foo.rpm。

この章で分かったこと

持ち帰ってほしいこと

  • rpm -q は台帳に聞く: -qa 全部・-qi 情報・-ql ファイル・-qf ファイル→パッケージ・-qc 設定ファイル・-qd 文書・-qR 依存・--whatrequires 逆依存。ファイルに聞くなら -qp
  • rpm -V は台帳と違うファイルだけを出す。何も出ず終了コード 0 なら、全部台帳どおり
  • 9文字の欄は SM5DLUGTP（大きさ・権限・中身の要約・…・時刻）。違った欄だけ文字が入り、c は設定ファイル
  • 入れ直す（yum reinstall）と台帳どおりに戻るが、書き換えた設定ファイル（%config(noreplace)）は戻らず、消すと .rpmsave で残る
  • rpm -Va は実機でも多くの行を出す。設定ファイルでないのに 5 や M が付いた行から疑う
  • rpm2cpio | cpio -idmv は入れずに中身を取り出す。台帳には載らない
