確かめて説明する LinuC 主題1.04

LinuC レベル1 101 試験・主題1.04「リポジトリとパッケージ管理」 （apt / Debian パッケージ / yum / RPM パッケージ）を、 Debian 系と RPM 系の2つの檻の中で実際に打って確かめます。 演習は理論編の章の順に並んでいて、1本目は第1章をなぞれば通ります。後ろの演習ほど、前の章の操作を組み合わせます。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: コマンドは打てる。写経すれば動く。 でも「なぜ動くのか」を人に説明できない人。
LinuC を受ける人向けには: パッケージを入れたことがほとんど無く、dpkg -S と apt-file search、rpm -qf と yum provides の違いも、問題文の言い回しで迷う人。

影響度 B（変更はコンテナの中だけ。母艦の設定もファイルも書き換えません）。 演習は sudo でパッケージを入れたり消したりするので、母艦では実行しないでください。 檻は exit すると消え、次に起動すると最初の状態に戻ります（演習の作業ファイルと進み具合だけはボリュームに残ります）。

どちらの檻にも、練習用の小さなパッケージとリポジトリが入っています。演習はネットにつながっていなくても同じ結果になります。

はじめる

前の版（1.0.x）でこの教材の演習を進めたことがある人は、先に下の「前の版（1.0.x）で進めた人へ」の箱を読んでください。前の版の記録が残ったまま起動すると、新しい演習の進み具合が正しく出ません。

Debian 系の檻（理論編の第1〜8章・演習01〜08）:

docker run --rm -it --name lab-linuc-packages-deb --hostname linuc \
  -v lab-linuc-packages-deb-work:/home/lab/work \
  -v lab-linuc-packages-deb-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:packages-deb-1.1.1@sha256:__DIGEST__

RPM 系の檻（理論編の第9〜11章・演習09〜12）:

docker run --rm -it --name lab-linuc-packages-rpm --hostname linuc \
  -v lab-linuc-packages-rpm-work:/home/lab/work \
  -v lab-linuc-packages-rpm-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:packages-rpm-1.1.1@sha256:__DIGEST__

1.1.0 で始めた人は、檻を exit で抜けて、上の起動コマンドで入り直すだけで構いません。1.1.1 で変わったのは lab コマンドだけなので、進み具合と作業ファイルはそのまま使えます（ボリュームは消しません）。

前の版（1.0.x）で進めた人へ: 1.1.0 で、演習の番号と中身が変わりました。前の版のボリュームが残っていると、次の3つが新しい演習に混ざります。
  • 進み具合（~/.lab/progress.json）。前の版で済ませた番号に、新しい演習の ✔ が付きます（前の版の 01〜03 を済ませていると、新しい 01〜03 が ✔ の状態で始まります）。
  • 全問を終えた印（~/.lab/finale）。残っていると、新しい版で全問を終えたときの締めくくりの表示が出ません。
  • ~/work/ の下の作業ファイル。lab start は、すでにあるファイルを上書きしないで配るので、古いファイルが残ります。
先に、動いている2つの檻を exit で抜けます。檻が使っているボリュームは消せないからです。そのあとで4つのボリュームを消し、上の起動コマンドで始めます。 
docker volume rm lab-linuc-packages-deb-work lab-linuc-packages-deb-state lab-linuc-packages-rpm-work lab-linuc-packages-rpm-state
podman で起動していた人は、docker を podman に替えて打ちます（podman volume rm …。この檻を podman で動かすことは、まだ確かめていません）。 ボリュームが無いときは、無いという趣旨のエラーが出るだけで、何も消えません。

起動の1行の部品の意味は、理論編の第1章にあります。 特別な権限は1つも渡しません（--privileged も --cap-add もありません）。 中では一般ユーザ lab として動き、パッケージを入れるときだけ sudo を付けます（パスワードは聞かれません）。 2つの檻は名前もボリュームも別なので、同時に動かしても構いません。

入ると、案内が出ます（Debian 系の檻の場合）。

── lab-linuc-packages-deb 1.1.1 ────────────────────────────────────────
lab-linuc-packages-deb  進捗 0/8
  次 → 01 「labhello を入れて、使えるようにする」 (目安 5分 / 影響度 B)
  lab start 01 で課題を開く
  進捗の保存先: /home/lab/.lab/progress.json（消すには docker volume rm lab-linuc-packages-deb-state）
  lab ls      演習一覧 / lab start NN  課題を開く / lab check  答え合わせ
────────────────────────────────────────────────────────────

lab コマンド

演習は、檻の中の lab コマンドで進めます。

打つもの何のためにあるか
labいまどこまで進んだかと、次に打つものを見る
lab lsその檻の演習の一覧と、どれが済んだかを見る
lab start NN演習 NN の課題文を開く。作業ファイルがある演習は ~/work/NN に配る
lab show（lab show NN）課題文をもう一度出す。作業を進めると課題文は画面の上へ流れて見えなくなるので、見返すときに使う。番号を省くと、最後に開いた演習を出す（配り直しも記録もしない）
lab check NN答え合わせ。観測した事実だけを出す（番号を省くと全部）
lab hint NNヒントを1段ずつ出す（3段。打つたびに深くなる）
lab solve NN模範解答を見る。見たことは進み具合に記録される
lab reset NN~/work/NN を配られたときの状態に戻す（システム全体を触る演習は、檻を起動し直すと戻る）
lab env検証環境を表示する（本文と違う出力が出たときに貼る）

lab は sudo を付けずに打ちます。付けて打つと、何もせずに理由を出して止まります。付けると root として動くので、作業ディレクトリと進み具合が root のホーム（/root）の下にでき、~/work には現れず、檻を抜けると消えてしまうからです。判定に root が要るところは、判定が自分で sudo を使います。 ~/work や ~/.lab（進み具合の置き場）の持ち主が lab でなくなっていたら、lab がそれを見つけて lab に戻し、何を戻したかを画面に出します。

lab start の課題文は、太い罫線の見出し（演習の番号・題・影響度・目安）で始まり、細い罫線で終わります。課題文はいつも「いまの状態（打つコマンドと、そのとき出る画面）→ やること → 判定のしかた → できたら」の順です。いまの状態でエラーが出る演習は、そのエラーを全文載せ、それが正しい始まりの状態だと書いてあります。

演習

12本あります。番号の順に進めてください（後ろの演習は、前の演習で入れたものを前提にしていません。ただ、前の章を読んでいることを前提にしています）。 判定は観測できる結果だけ（パッケージの台帳の状態・ファイルの有無・コマンドを実際に動かした結果）で行い、 コマンドの打ち方は見ません。詰まったら lab hint NN を何度でも。使い切ったら lab solve NN で模範解答に必ず届きます （見ても構いません。進み具合には「solve を見た」として残ります）。

各檻の lab ls には、その檻の演習だけが出ます。対応する章を読んでから演習を開けば、その章までに出たものだけで解けます（設定ファイルを書き換える演習03・09 は、主題1.03 で使った vi か sed も使います）。

理論編の各章は「檻を起動し直した直後」から打つ前提で書いてあります。演習を解いた檻のまま章を読み進めると、入れたものが残っていて出力が本文と変わることがあるので、章を読むときは起動し直してください。逆に、章を読んだ檻のまま演習を開くと、課題文の「いまの状態」と少し違う画面になることがあります（演習01 の課題文に、その場合の出方も書いてあります）。

lab reset NN で演習を配られたときの状態に戻すと、~/work/NN はディレクトリごと作り直されます。 そのディレクトリの中にいたなら、続けて cd ~/work/NN と打ち直してください（打たないと、消えた古いディレクトリに残ったままになり、ls は何も出さず、cat などは No such file or directory になります）。

dpkg -l は、出力をいつも less に渡します。行が端末の幅か、行の数が画面の高さに収まらないと、右端を > で切って止まります（80 桁の端末では、名前を渡さない dpkg -l と dpkg -l 'lab*' のほか、説明の長い labsvc・labapp・liblab を名前で渡したときに止まります）。q で抜けてください。| tail -1 のようにパイプに渡せば止まりません（理論編の第2章）。

docker volume rm lab-linuc-packages-rpm-work lab-linuc-packages-rpm-state
