確かめて説明する Podman — 実践編

練習機（仮想マシン）の中に入れた本物の podman（rootless）で、デーモンの無い作り・ユーザ名前空間・ユーザごとの置き場所・rootless の網・pod・systemd との統合を、自分の手で確かめます。 起動するのはあなたの PC の docker（または podman）ですが、あなたの PC の podman やファイルには触れません（練習機の中の podman を使います）。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントの Getting Started のほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: docker の代わりに podman を打てる。でも「rootless だと何が違うのか」「なぜログアウトで止まるのか」を人に説明できない人。

この教材の檻

檻準備ここで触れるここでは触れない（逃がす先）
仮想マシン型（コンテナの中で QEMU が Ubuntu 24.04 の練習機を1台動かし、その中に podman 4.9.3 が入っている）イメージの取得と、練習機の起動と初回の準備（KVM なしで 1分前後） podman run unshare save/load pod、/etc/subuid、slirp4netns と pasta、loginctl、quadlet、docker 互換の API podman 5 の既定、podman machine、レジストリからの pull、Kubernetes → 理論編で説明（理由）

端末には2つの場所があります。プロンプトで、いまどちらにいるかが分かります。

あなたの PC（docker か podman がある）
└─ 外側のコンテナ          lab@host       … 外。lab check と、練習機への ssh を打つ場所
   └─ 練習機（QEMU）        student@linuc  … 仮想マシン。この中の podman（rootless）で、本文のコマンドを打つ
      └─ 練習機の中の podman のコンテナ  … 本文で起動するもの（alpine・busybox）

影響度 B（変更は練習機とコンテナの中だけ。あなたの PC の設定もファイルも書き換えません）。 壊したら外で vm reset --yes を打てば、練習機が最初の状態に戻ります。 演習を始めるとき lab は「元に戻すには起動し直してください」と出しますが、この檻では起動し直しても練習機は戻りません（ディスクはボリュームに残ります）。戻すのは vm reset --yes です。

はじめる

Docker の場合。起動して、入ります。

docker run -d --name lab-podman --hostname host --stop-timeout 30 \
  -v lab-podman-vm:/home/lab/vm \
  -v lab-podman-state:/home/lab/.lab \
  ghcr.io/chai0204/lab:podman-1.0.0@sha256:__DIGEST__

docker exec -it lab-podman bash -l

podman で起動するなら、同じオプションのまま docker を podman に読み替えます（rootless でも動きます。理由は第7章）。

podman run -d --name lab-podman --hostname host --stop-timeout 30 \
  -v lab-podman-vm:/home/lab/vm \
  -v lab-podman-state:/home/lab/.lab \
  ghcr.io/chai0204/lab:podman-1.0.0@sha256:__DIGEST__

podman exec -it lab-podman bash -l
  • --stop-timeout 30 は特権ではなく、止めるときに待つ秒数です。練習機を正常に止めるのに KVM なしで十数秒かかり、既定の10秒では電源を抜くのと同じ止まり方になります。
  • --privileged も --cap-add も要りません。
  • rootless の podman で起動した場合、あなたがログアウトすると、この檻も止まることがあります（第6章で、その理由を練習機の中で確かめます）。

入ると、練習機の状態と現在地が出ます。初回は、練習機の起動に続けてこの記事の準備（練習機の docker のデーモンを止める）が走ります。

練習機 linuc: running（エージェント 応答あり / ssh 待ち受け中）
  vm start / vm ssh / vm console / vm stop   練習機の操作（中身は virsh と ssh）


── lab-podman 1.0.0 ────────────────────────────────────────
lab-podman  進捗 0/7
  次 → 01 「コンテナの親の conmon を突き止める」 (目安 8分 / 影響度 B)
  lab start 01 で課題を開く
  進捗の保存先: /home/lab/.lab/progress.json（消すには docker volume rm lab-podman-state）
  lab ls      演習一覧 / lab start NN  課題を開く / lab check  答え合わせ
────────────────────────────────────────────────────────────

まだ running でなければ、外で vm start と打つと、起動と準備が終わるまで待ってくれます。練習機には ssh linuc で入ります。

$ ssh linuc

  練習機（Ubuntu 24.04 / 仮想マシン）— Docker と Podman の記事
  - 採点は外のコンテナが持っています。この中でも lab check NN で答え合わせできます
  - 管理用の NIC（enp0s16）を止めると ssh が切れます。そのときは外で vm console

プロンプトが student@linuc に変わります。本文の端末は、ほとんどがこの練習機の中で打つものです（見出しが「練習機の中（student@linuc）」）。 podman は student のまま（rootless で）打ちます。sudo はパスワード無しで使えます。抜けるのは exit です。

本文の出力のうち、コンテナの ID・PID・時刻と経過時間（Up 5 seconds など）・time の秒数・MAC アドレスなど、打つたびに変わる値は、あなたの画面では本文と違います。それ以外の行は同じになります（同じ手順で通しに2回打ち、変わる値だけを伏せて突き合わせてあります）。

本文は、第1章から順に、同じ1つのシェルで打った記録です（第6章だけは、本文の指示どおりに一度抜けて入り直します）。 章の途中で抜けたり、本文に無いコマンドを足したりすると、後ろの章の画面が本文と変わることがあります。

この檻について

練習機のディスクは Docker の記事と同じで、docker も入っています。この記事では、初回の準備で docker のデーモン（dockerd・containerd）を止めてあります。

練習機は Docker Hub に届きません（わざとです。ほかのレジストリには届きますが、本文と演習では使いません）。使うイメージ（alpine:3.24.2 と busybox:1.38.0。ダイジェストで照合済み）は student の置き場所に入れてあり、 Docker Hub へ取りに行く操作は全員に同じ失敗を出します。

この檻の練習機は KVM を使いません。起動コマンドに --device /dev/kvm を足しても、練習機の定義が完全エミュレーション（type='qemu'）に固定されているので、QEMU は -accel tcg のまま動きます（著者の環境で実測: 足して起動しても、起動から ssh まで 35 秒。KVM を使わない理由は KVM の記事の6章）。何も足さずに起動してください。本文の出力はすべて KVM なしで取ったものです。

演習

7本あります。判定は観測できる結果だけで行い、コマンドの打ち方は見ません。 判定は外の端末でも、練習機の中でも lab check NN で打てます。課題は lab start NN で出ます。 詰まったら lab hint NN を何度でも。使い切ったら lab solve NN で模範解答に必ず届きます （見ても構いません。進捗には「solve を見た」として残ります）。

Issue を立てる（フォームが3種類あります）。 カーネル の行は、あなたの PC のカーネルなので本文と違って正常です（練習機の中のカーネルは 練習機の中 の行）。 仮想化 の行が TCG 以外なら、時間の出る行が本文と違います。ランタイム と 特権 の行は、外側のコンテナをどちらで起動したかで変わります（podman の rootless なら ランタイム: podman・CapBnd=00000000800405fb）。

終わったら

docker stop lab-podman                # 練習機を正常に止めてから止まる
docker rm lab-podman
docker volume rm lab-podman-vm lab-podman-state   # 練習機のディスクと進捗も消す場合だけ

イメージは docker rmi で消せます（podman で起動した場合は docker を podman に読み替え）。 あなたの PC には何も残りません（名前付きボリューム以外のファイルを作っていないため）。 続きをやる日は docker start lab-podman で再開できます。
