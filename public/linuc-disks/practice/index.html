確かめて説明する LinuC 主題1.05

LinuC レベル1 101 試験・主題1.05「ハードウェア、ディスク、パーティション、ファイルシステム」 （ハードウェアの基礎知識と設定 / ハードディスクのレイアウトとパーティション / ファイルシステムの作成と管理、マウント）を、 コンテナの中で動く仮想マシン（練習機）で確かめます。 空のディスクを区切り、ファイルシステムを作り、マウントし、USB メモリを抜き差しし、ドライバを外します。 練習機は本物の Linux カーネルで動くので、あなたの PC のディスクには何も起きません。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この教材が向かない人

  • いま動かしたいだけの人 → 公式ドキュメントのほうが速い
  • 答えだけ欲しい人 → AI に聞いたほうが速く、あなたの語彙に合う

向く人: コマンドは打てる。写経すれば動く。 でも「なぜ動くのか」を人に説明できない人。
LinuC を受ける人向けには: fdisk も mount も、本物のディスクで試したことが無い人。 試そうにも、自分の PC のディスクを分割するのは怖い人。

はじめる

前の版（1.0.x）を使ったことがある人は、先に下の「前の版（1.0.x）で進めた人へ」の箱を読んでください（前の版の檻が残っていると、1行目の docker run は名前がぶつかって止まり（Conflict）、2行目の docker exec は前の版の檻の中に入ってしまいます）。

Docker の場合。2行です。

docker run -d --name lab-linuc-disks --hostname host --stop-timeout 30 \
  -v lab-linuc-disks-vm:/home/lab/vm \
  -v lab-linuc-disks-state:/home/lab/.lab \
  ghcr.io/chai0204/lab-linuc:disks-1.1.1@sha256:b930f7c2d1cc9a9198dfdb97bb8b2de0dbf4dc16d2ec5636b031b75eba3e20a8

docker exec -it lab-linuc-disks bash -l
前の版（1.0.x）で進めた人へ: 1.1.0 で章と演習の順番と中身が変わりました（演習の番号も変わっています）。 前の版の練習機のディスクと進捗がボリュームに残っていると、新しい章・演習と混ざって本文と違う画面になります。 前の版の檻とボリュームを消してから、上の2行で始めてください（練習機のディスクと進捗が消えます）。 
docker rm -f lab-linuc-disks
docker volume rm lab-linuc-disks-vm lab-linuc-disks-state
ボリュームを消さずに続けるなら、前の版の檻だけを消して（docker rm -f lab-linuc-disks）上の2行で始め、入ったら外で次の3行を打ちます（練習機を最初の状態に戻し、前の版の進捗を消して、起動し直す）。 新しい版の檻にボリュームだけを付け替えても、練習機のディスクは前の版のままで、演習05 のファイルも作られないので、この3行は省けません。 
vm reset --yes
rm -f ~/.lab/progress.json ~/.lab/current ~/.lab/finale
vm start
（~/.lab/finale は「全問を終えた」印です。前の版で全問を終えた人は、これを消さないと、新しい版の全問を終えたときの締めくくりの表示が出ません。）
  • コンテナを起動すると、中で練習機も起動します。KVM（Linux が CPU の仮想化の機能を使って、仮想マシンを速く動かす仕組み）を使わない完全エミュレーション（練習機の CPU の命令をひと塊ずつ読んで、手元の CPU の命令に翻訳してから実行する。QEMU では TCG と呼ぶ。QEMU の記事の第4章）なので、起動に 40〜90 秒かかります（第1章の最初の vm start で、起動し終わるのを待てます）。
  • --stop-timeout 30 は必須です（権限ではありません）。docker stop したとき、練習機を正常に止める（中で shutdown する）のを待つ猶予です。docker の既定の猶予は 10 秒で、過ぎると練習機は電源を抜かれたのと同じ止まり方になります。記録では止まるまで 4〜7 秒で（logs/linuc-machine-stop-autostart.log）、既定の 10 秒との差が小さいので、余裕を持たせて 30 秒にしています。
  • --device /dev/kvm を足しても速くはなりません。練習機の定義が type='qemu'（KVM を使わない完全エミュレーション）に固定されているので、/dev/kvm を渡しても TCG のまま動きます（KVM の記事の6章で測っています）。
  • podman でも、同じオプションのまま docker を podman に替えて起動できるはずです。同じ土台（仮想マシン型の檻の共通部分）を使う別のコースの檻は、podman 5.8.6（rootless）で起動・練習機への ssh・podman stop まで確かめてあります（logs/linuc-machine-podman.log）。このコースの檻そのものは、podman ではまだ確かめていません。

入ると、外のコンテナ（プロンプト lab@host）にいます。練習機の状態と現在地が出ます。

練習機 linuc: running（エージェント 応答なし / ssh まだ）
  vm start / vm ssh / vm console / vm stop   練習機の操作（中身は virsh と ssh）


── lab-linuc-disks 1.1.1 ────────────────────────────────────────
lab-linuc-disks  進捗 0/10
  次 → 01 「空のディスク vde を使えるようにする」 (目安 10分 / 影響度 B)
  lab start 01 で課題を開く
  進捗の保存先: /home/lab/.lab/progress.json（消すには docker volume rm lab-linuc-disks-state）
  lab ls      演習一覧 / lab start NN  課題を開く / lab check  答え合わせ

1行目は練習機の状態です。起動してすぐに入ると「エージェント 応答なし / ssh まだ」（まだ起動の途中）と出ます。起動し終わっていれば「応答あり / ssh 待ち受け中」です。 vm は、練習機を操作する virsh と ssh を包んだ短縮のコマンドです。

練習機（プロンプト student@linuc）には ssh linuc で入り、exit で外へ戻ります（第1章でやります）。 第6章からは外で打つコマンド（USB メモリの抜き差し）も出てくるので、そこで端末をもう1つ開きます（docker exec -it lab-linuc-disks bash -l をもう一度）。

外（コンテナ）lab@hostvm（練習機の電源）・virsh（USB メモリや CD の抜き差し）・lab（演習）
練習機の中student@linucfdisk・mkfs・mount など、本文のほとんど。root の操作は sudo（パスワードは聞かれない）。lab もここで打てる（外の lab に頼んで答えを出す）

練習機の操作（外で打つ）:

コマンドすること何のためにあるか
vm start起動して、入れるようになるまで待つ（動いていれば待つだけ）練習機に入る前・再起動したあと
vm stop正常に止めるコンテナを止める前に、練習機だけを止めたいとき
vm status状態を見る入れないときに、どこまで起動しているかを見る
vm consoleシリアルコンソールにつなぐ（抜けるのは Ctrl+]）ssh が切れて入れないとき
vm reset --yes練習機を工場出荷時に戻す（ディスクの変更はすべて消える。演習の進捗は消えない）壊したとき・最初からやり直したいとき

止めるのは docker stop lab-linuc-disks、再開は docker start lab-linuc-disks。ディスクの中身はボリュームに残ります （ただし、USB メモリは練習機を止めると抜けた状態になります。第6章・第7章・第11章の途中で止めたら、本文の virsh attach-device から挿し直してください）。

1.1.0 で始めた人は、「終わったら」の手順で檻を止めてから（ボリュームは消さずに）、上の起動コマンドで起動し直すだけで構いません。1.1.1 で変わったのは lab コマンドだけなので、進み具合と作業ファイルはそのまま使えます。

演習

10本あります。判定は観測できる結果だけで行い、コマンドの打ち方は見ません （判定は外のコンテナが qemu-guest-agent 経由で練習機の中を見るので、ssh を壊しても採点は止まりません）。 課題文は lab start NN で開き、作業の途中でも lab show でもう一度出せます（練習機の中でも外でも打てます）。 答え合わせは lab check NN（これも練習機の中でも外でも打てます）。 詰まったら lab hint NN を何度でも。使い切ったら lab solve NN で模範解答に必ず届きます （見ても構いません。進捗には「solve を見た」として残ります）。

演習は章の順に並んでいます。1本目（01）は第2章の流れを別のディスクでなぞるだけの易しいもので、後ろの演習ほど前の章の操作を組み合わせます。 理論編の章のとおりに打ってきた人は、演習03・04・06〜10 はもう達成した状態になっています（lab check で確かめられます）。 01・02・05 は、章では使わないディスクやファイルを使うので、章を読んだあとに自分で手を動かします。 演習を先にやる人のために、各課題文には「いまの状態」として、演習だけを 01 から順にやってきた練習機での画面を載せてあります。

やり直したいときは、外で vm reset --yes（練習機ごと最初の状態に戻ります。演習の進捗は消えません）。 演習を先にやった練習機で理論編を打つと、ディスクの状態が本文と違います（第2章で区切る vdb に、演習03 の GPT が残っている など）。 理論編を第1章から本文どおりに打つときは、その前に外で vm reset --yes を打って、vm start で起動し直してください。 章の途中で演習01・02・05 をやるのは構いません（使うのは章で使わない vde・vdd・old-usb.img なので、本文の画面は変わりません。第10章の /proc/partitions にだけ、作った区画の行が増えます）。 先に読む場合は 理論編（11章）へ。

lab は sudo を付けずに打ちます。付けると root として動き、作業ディレクトリと進み具合が /root の下にできて檻を抜けると消えてしまうので、理由を出して何もせずに止まります。~/work や ~/.lab の持ち主が自分でなくなっていたら、lab が見つけて戻し、そのことを画面に出します。
