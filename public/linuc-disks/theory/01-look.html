1. 練習機に入り、つながっているディスクを眺める

このコースでは、練習機（このコースの檻の中で動く、練習用の Linux の機械）につながった空のディスクを、区切って・ファイルシステムを作って・マウントして使えるようにするところから始め、表の形式、ファイルシステムの種類、起動のたびのマウント、スワップ、LVM（複数のディスクを1つにまとめる仕組み。第9章）、部品の情報と、部品を動かすプログラム（ドライバ。第11章）へと順に進む。始める前に要るのは、実践編の「はじめる」で起動した檻と、そこに入った端末1つ（docker exec -it lab-linuc-disks bash -l で開いたもの）と、下の表の「前のコースで出たもの」である。この章では、練習機に入り、つながっているディスクを lsblk と df の2つのコマンドで眺める。まだ何も変えない。

前提: 実践編の「はじめる」で檻を起動した所要 17分影響度 A出題範囲 1.05.2（重要度4）出題範囲 1.05.3（重要度4）最終検証 2026-10-20

この章のゴール

  • プロンプトを見て、いま外のコンテナ（lab@host）と練習機の中（student@linuc）のどちらにいるかを言え、ssh linuc と exit で行き来できる
  • lsblk の出力から、ディスク・パーティション・光学ドライブと、その大きさ・マウント先を読める
  • df -h の出力から、マウントされているファイルシステムの大きさと空きを読め、lsblk との違いを言える
ここで覚えなくていいこと: 仮想マシンを作るしくみ（QEMU と libvirt。主題1.01 のコース）は扱わない。lsblk の MAJ:MIN 列と、df のディスクではない行（tmpfs・efivarfs）は、この章では読まない。ディスクの名前の付き方の細かい規則（この練習機に無い種類のディスクの名前）も扱わない。

外と練習機の中 — 2つの場所

この節で分かること: いま打っている端末が外のコンテナか練習機の中かを見分け、行き来する方法。

実践編の「はじめる」で開いた端末は、プロンプトが lab@host:~$ になっている。この場所を外と呼ぶ。このコースのディスクの操作は、外ではなく練習機（ディスクを自由に区切ってよい、練習用の Linux の機械）の中で打つ。まず、練習機が起動し終わるのを待つ。vm start は練習機を起動し、中に入れるようになるまで待つコマンドである（この檻のために用意したもの）。

$ vm start
練習機はもう動いています
  起動中… 10秒（KVM なしの完全エミュレーションなので 40〜90 秒かかります）
練習機が起動しました（27秒）
  入るには:  ssh linuc   （抜けるときは exit）

「練習機はもう動いています」は、檻を起動したときに練習機の電源も入っていた、という意味である。そのあと起動し終わるまで待ち、かかった秒数を出す（秒数と「起動中…」の行の数は、あなたの PC の速さと、檻を起動してからの時間で変わる。初めての起動では「初回の準備」の行が出ることもある）。最後の行のとおりに入る。ssh は別のコンピュータにログインするコマンドで、linuc は練習機の名前である。

$ ssh linuc
  LinuC 練習機（Ubuntu 24.04 / 仮想マシン）
  - 採点は外のコンテナが持っています。この中でも lab check NN で答え合わせできます
  - 管理用の NIC（enp0s16）を止めると ssh が切れます。そのときは外で vm console

練習機の案内が出て、プロンプトが student@linuc:~$ に変わる。これが練習機の中である（このコースの端末のブロックは、プロンプトを $ だけにして載せる。どこで打つかは、ブロックの上の小さな見出しで示す）。案内の2行は、演習の答え合わせ（lab check）が練習機の中でも打てることと、練習機のネットワークの装置（NIC）を止めると ssh が切れるので、そのときは外で vm console（練習機の画面に外から直接つなぐコマンド）を使え、という注意である（このコースではネットワークは触らない）。exit で外に戻り、もう一度入ってみる。

$ exit
logout
Connection to 127.0.0.1 closed.
$ ssh linuc
  LinuC 練習機（Ubuntu 24.04 / 仮想マシン）
  - 採点は外のコンテナが持っています。この中でも lab check NN で答え合わせできます
  - 管理用の NIC（enp0s16）を止めると ssh が切れます。そのときは外で vm console

Last login: Tue Oct 20 20:55:10 2026 from 10.0.2.2

exit で logout と出てプロンプトが lab@host に戻り、ssh linuc でまた入った。2回目には、前に入った日時（Last login:）の行が出る。ここから先は、ことわりの無い限り練習機の中で打つ。

場所が2つあるのには理由がある。ディスクを区切る操作は、ディスクという装置を、カーネル（OS の中心の部分。OS はコンピュータを動かす土台のソフトウェアで、ここでは Linux。カーネルは装置と、メモリ（動いているプログラムとデータを置く場所）と、プロセス（動いているプログラム）を管理する）を通して直接いじる。ところがコンテナは PC のカーネルを借りて動くので、ディスクの装置を渡してもらえない。そこで檻は、コンテナの中で仮想マシン（ソフトウェアで作った1台のコンピュータ。自分のカーネルを持つ）を1台動かしている。それが練習機である。

あなたの PC
 └─ 檻（コンテナ）           プロンプト lab@host       … 外。vm・virsh・lab を打つ
     └─ 練習機（仮想マシン）  プロンプト student@linuc  … 中。ディスクを区切る・つなぐ
たとえ: 練習機は、作業場（コンテナ）の中に置いた練習用のパソコンに近い。ディスクを区切って失敗しても、壊れるのは練習用のパソコンのディスクだけで、作業場の外（あなたの PC）には何も起きない。
ただし崩れる点: 本物のパソコンのディスクは部品だが、練習機のディスクは外のコンテナに置いたファイルである。だから全員の練習機に同じディスクがつながっていて、本文と同じ画面が出る。また、本物より遅い（KVM という速くする仕組みを使わず、CPU（命令を実行する部品）の命令をソフトウェアで真似しているため）。

つながっているディスクを一覧する — lsblk

この節で分かること: lsblk の1行が何を表し、各列をどう読むか。

lsblk は、カーネルが知っているディスクと、その中の区画を木の形で一覧にする。

$ lsblk
NAME    MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda       8:0    0    1G  0 disk
sr0      11:0    1  368K  1 rom
vda     253:0    0   20G  0 disk
├─vda1  253:1    0   19G  0 part /
├─vda14 253:14   0    4M  0 part
├─vda15 253:15   0  106M  0 part /boot/efi
└─vda16 259:0    0  913M  0 part /boot
vdb     253:16   0    2G  0 disk
vdc     253:32   0    1G  0 disk
vdd     253:48   0  256M  0 disk
└─vdd2  253:50   0  100M  0 part
vde     253:64   0  512M  0 disk

1行が1つの装置（ディスクか、その中の区画）である。列は次のとおり。

列意味何のためにあるか
NAME装置の名前。/dev/ を付けると装置のファイルの名前になる（vdb → /dev/vdb）コマンドに渡すときの名前。├─・└─ は「上の行のディスクの中にある」という意味
MAJ:MIN装置の番号（主題1.02 で見たメジャー番号とマイナー番号）カーネルが装置を見分ける番号。この章では読まない
RM取り外せる装置なら 1（removable）USB メモリや CD のように、抜き差しする装置を見分ける
SIZE大きさ（K は KiB = 1024 バイト、M は MiB = 1024KiB、G は GiB = 1024MiB）どのディスクかを見分ける一番の手がかり
RO読み取り専用なら 1（read only）書き込めない装置（CD-ROM など）を見分ける
TYPEdisk（ディスク）・part（パーティション）・rom（光学ドライブ。CD・DVD を読む装置）その行が装置全体か、その中の区画かを見分ける
MOUNTPOINTSマウント先（その区画を、どのディレクトリから使えるようにしてあるか）空欄なら、まだどこからも使えない

ディスクはデータを書いておく記憶装置で、パーティションはディスクを区切った区画である。名前の頭の2文字は、ディスクのつながり方の種類を表す。

名前つながり方この練習機では
vda・vdb …virtio（仮想マシンのために作られた、速く単純なディスクのつなぎ方）vda（システムの入ったディスク）・vdb・vdc・vdd・vde
sda・sdb …SATA（PC の中でディスクをつなぐ線の規格）・USB（外から抜き差しする機器をつなぐ規格）・SCSI（主にサーバのディスクのつなぎ方）。Linux はこの3つのディスクを同じ仕組みで扱うので、名前がどれも sd になる。実機の PC のディスクや USB メモリはふつうこれsda
sr0光学ドライブ（CD・DVD を読む装置）sr0（CD が1枚入っている）

3文字目の a・b・c… は何台目か、後ろの数字はパーティションの番号である。vda1 は「vda の1番目のパーティション」と読む。

この表から読めることを並べる。vda（20G）は4つに区切られていて、3つがマウントされている（/・/boot/efi・/boot）。練習機の Linux そのものが、このディスクに入っている。vdb（2G）・vdc（1G）・vde（512M）・sda（1G）には区画が1つも無く、どこにもマウントされていない。このコースで区切って使うのは、これらの空のディスクである。vdd（256M）には vdd2 が1つだけあり、演習で使うので触らない。

たとえ: ディスクは土地、パーティションはそれを区切った区画に近い。区画に倉庫を建てると物（ファイル）を置けるようになり、倉庫の入口を町の道につなぐと、町の人が行けるようになる。この「倉庫」がファイルシステム、「道につなぐ」がマウントである（どちらも次の節で df の出力と一緒に見る）。
ただし崩れる点: 土地は区画に分けてから建てるのがふつうだが、ディスクは区切らずに、ディスク全体に倉庫を建てることもできる。区画を作るかどうかは、使い方で決める。

マウントされているファイルシステムを見る — df

この節で分かること: df -h が何を数えていて、lsblk と何が違うか。

ファイルシステムは、区画の中にファイルを名前で整理して置くための決まりと、そのための管理情報である。マウントは、ファイルシステムをディレクトリの木の1か所（マウントポイント）につなぎ、そのディレクトリから中のファイルを読み書きできるようにすることである。df -h は、マウントされているファイルシステムごとに、大きさと空きを出す（-h は大きさを G・M のような読みやすい単位で出すオプション）。

$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/root        19G  863M   18G   5% /
tmpfs           713M     0  713M   0% /dev/shm
tmpfs           285M  776K  285M   1% /run
tmpfs           5.0M     0  5.0M   0% /run/lock
efivarfs        256K   53K  199K  21% /sys/firmware/efi/efivars
/dev/vda16      881M  181M  639M  23% /boot
/dev/vda15      105M  6.2M   99M   6% /boot/efi
tmpfs           143M  8.0K  143M   1% /run/user/1000
列意味
Filesystemどの装置のファイルシステムか。/dev/root は、起動のときに / にした区画（ここでは vda1）をカーネルが呼ぶ名前
Size・Used・Avail大きさ・使っている量・あと使える量
Use%使っている割合
Mounted onマウントポイント

ディスクの区画は、/dev/ で始まる3行（/dev/root・/dev/vda16・/dev/vda15）だけである。tmpfs と efivarfs の行は、ディスクではなく、メモリや、ファームウェア（電源を入れたときに最初に動く、機械に組み込まれたプログラム）の設定を見せるものなので、ここでは読まない（tmpfs の行の Used は、人と時刻によって少し違う）。lsblk の MOUNTPOINTS に出ていた3つと同じものが、ここにも並んでいる（vda16 の Size が lsblk の 913M より小さい 881M なのは、ファイルシステムが自分の管理情報に使う分を除いているからで、第5章で確かめる）。

ふつうこう考える

lsblk には vdb（2G）が出ていた。df にその装置の名前を渡せば、vdb の大きさと空きが分かるはずだ。

$ df -h /dev/vdb
Filesystem      Size  Used Avail Use% Mounted on
devtmpfs        689M     0  689M   0% /dev
だめな理由: 出てきたのは vdb ではなく、/dev にマウントされている devtmpfs（カーネルが装置のファイルを置くために、メモリの上に作るファイルシステム。第10章）の行だった。df にファイルの名前を渡すと、「そのファイルが置いてあるファイルシステム」について答える。/dev/vdb は /dev の中のファイルなので、/dev の答えが返ってきた。vdb にはまだファイルシステムが無く、どこにもマウントされていない。df が数えられるのは、マウントされているファイルシステムだけで、vdb の大きさを知りたいなら lsblk を見る。

その /dev/vdb を ls -l で見る。

$ ls -l /dev/vdb
brw-rw---- 1 root disk 253, 16 Oct 20 20:54 /dev/vdb

先頭の b はブロックデバイス（決まった大きさの塊の単位で、好きな位置を読み書きする装置。ディスクがこれ）で、大きさの欄の 253, 16 は装置の番号である。中身を持つファイルではなく、カーネルの中のドライバ（装置の動かし方を知っている、カーネルの部品）への入口になっている（主題1.02 のコースの第1章で見た /dev/null の仲間）。ディスクを区切るコマンドもマウントするコマンドも、この名前で相手のディスクを指す。日時の欄は、あなたの画面では違う（このあとの章の ls -l の日時も同じ）。

最後に、4つの言葉の関係を1つの表示で確かめる。lsblk の -o は、出す列を選ぶオプションで、FSTYPE はファイルシステムの種類を出す列である。装置の名前を並べると、その装置だけを出す。

$ lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS /dev/vda /dev/vdb
NAME     SIZE TYPE FSTYPE MOUNTPOINTS
vda       20G disk
├─vda1    19G part ext4   /
├─vda14    4M part
├─vda15  106M part vfat   /boot/efi
└─vda16  913M part ext4   /boot
vdb        2G disk
vda（ディスク）
 └─ vda1（パーティション）── ext4（ファイルシステム）── /（マウントポイント）
vdb（ディスク）
 └─ （まだ何も無い）

vda1 には ext4 というファイルシステムがあり、/ にマウントされている。vda15 の vfat は、FAT（Windows などでも読める単純なファイルシステム）の Linux での呼び名で、この区画は起動に使う（第4章）。vda14 は区画だが、ファイルシステムが無い（BIOS（電源を入れたときに最初に動くファームウェアの、古い形）で起動するときのために取ってある 4M の区画で、この練習機の起動には使われていない）。vdb には区画もファイルシステムも無い。使えるようにするには、区切る → ファイルシステムを作る → マウントする、の3段が要る。次の章で、この vdb を一通り使えるようにする。

たとえ: lsblk は町の土地台帳、df は道につながった倉庫の在庫表に近い。台帳には空き地も載るが、在庫表には開いている倉庫しか載らない。
ただし崩れる点: 在庫表に無い場所を聞かれたら、ふつうは「載っていない」と答えるが、df はその場所を含む別の倉庫の在庫を答えてしまう（df -h /dev/vdb が /dev の行を返した）。答えの Mounted on の列を見て、聞いたものと合っているかを確かめる。
手を動かす: 実践編の「はじめる」で檻を起動すれば、この章の表示をそのまま自分の練習機で出せる。演習01 は、次の第2章の流れを、この章で見た空のディスク vde（512M）でなぞる課題である。
確認

lsblk には vdb（2G）が出ているのに、df -h の一覧には出てこない。なぜか。

答え

df はマウントされているファイルシステムしか数えないから。vdb にはまだ区画もファイルシステムも無く、どこにもマウントされていない。lsblk はカーネルが知っている装置を全部出すので、空のディスクも出る。

確認

lsblk の ├─vda15 253:15 0 106M 0 part /boot/efi という行は、何を表しているか。

答え

vda というディスクの15番目のパーティション（TYPE が part）で、大きさは 106M。取り外せる装置ではなく（RM 0）、読み書きできて（RO 0）、/boot/efi にマウントされている。

確認

端末のプロンプトが lab@host:~$ になっている。練習機の中で打つコマンドを打つ前に、何をするか。

答え

ssh linuc で練習機に入る（プロンプトが student@linuc:~$ に変わる）。外に戻るときは exit。

この章で分かったこと

持ち帰ってほしいこと

  • この檻は2重になっている。外のコンテナ（lab@host）の中で、練習機（仮想マシン。student@linuc）が動いている。ssh linuc で入り、exit で出る
  • ディスク = 記憶装置、パーティション = それを区切った区画、ファイルシステム = 区画の中にファイルを置くための決まりと管理情報、マウント = ファイルシステムをディレクトリ（マウントポイント）につなぐこと
  • lsblk はカーネルが知っている装置を全部出す（空のディスクも）。TYPE で disk・part・rom を、MOUNTPOINTS でマウント先を読む
  • df -h はマウントされているファイルシステムの大きさと空きだけを出す。マウントされていない装置の名前を渡すと、/dev の答えが返る
  • ディスクは /dev/vdb のようなブロックデバイス（b）のファイルとして見え、コマンドはこの名前で相手を指す
