10. 部品の情報を読む

第9章までは、ディスクを区切り、ファイルシステムを作り、マウントし、LVM でまとめる、という「使う側」の話だった。この章では、練習機にどんな部品がつながっているかを CPU・メモリ・バス（装置をつなぐ通り道）・ディスクの順に読み、カーネルがその情報をどこに見せているか（/proc・/sys・/dev）を確かめる。最後に、HDD か SSD かの扱いを、起動のたびに変える設定をする。

前提: 第9章まで読了前提: 練習機の中にいる・外の端末もある所要 25分影響度 B出題範囲 1.05.1（重要度3）最終検証 2026-10-20

この章のゴール

  • CPU・メモリ・バスにつながる装置の情報を、lscpu・/proc・lspci・lsusb で読める。/proc・/sys・/dev がそれぞれ何を見せる窓かを言い分けられる
  • 割り込み（IRQ）・I/O ポート・DMA が何のためのものかを言え、/proc のどこで見られるかを知っている
  • HDD・SSD・光学ドライブの違いを、lsblk の ROTA・RM・RO 列で説明でき、HDD か SSD かの扱いを udev の規則で変えられる
ここで覚えなくていいこと: PCI の装置の番号の細かい意味と、ベンダ・製品の ID の一覧は扱わない。lscpu の CPU の機能の旗（Flags）の1つ1つの意味も扱わない。udev の規則の書き方の全体は扱わず、この章で書く1行だけを読めればよい。

CPU とメモリ

この節で分かること: CPU とメモリの情報の読み方と、その出どころ。

lscpu は CPU の情報を表にするコマンドである。長いので、最初の8行だけを出す。

$ lscpu | head -8
Architecture:                            x86_64
CPU op-mode(s):                          32-bit, 64-bit
Address sizes:                           40 bits physical, 57 bits virtual
Byte Order:                              Little Endian
CPU(s):                                  2
On-line CPU(s) list:                     0,1
Vendor ID:                               AuthenticAMD
Model name:                              QEMU TCG CPU version 2.5+

CPU(s) の 2 は、練習機が使える CPU の数（正確には、命令を同時に実行できる部分の数）である。Model name の QEMU TCG CPU は、QEMU（仮想マシンを動かすプログラム）が CPU の命令をソフトウェアで真似している（TCG。完全エミュレーション）という意味で、この檻は KVM を使わないので、どの PC で動かしてもここは同じ表示になる（Vendor ID が AuthenticAMD なのも、QEMU が真似している CPU の種類で、あなたの PC の CPU とは関係ない）。lscpu は、カーネルが /proc/cpuinfo（と、この章で見る /sys）に出している情報を読んで整えている。

$ grep -m1 "model name" /proc/cpuinfo
model name	: QEMU TCG CPU version 2.5+
$ ls -l /proc/cpuinfo
-r--r--r-- 1 root root 0 Oct 20 22:36 /proc/cpuinfo
$ head -3 /proc/meminfo
MemTotal:        1459128 kB
MemFree:         1134508 kB
MemAvailable:    1188384 kB

grep の -m1 は、最初に見つかった1行だけを出すオプションである（CPU が2つあるので、同じ行が2回ある）。/proc/cpuinfo は、中身があるのに大きさが 0 である。ディスクの上のファイルではなく、読んだ瞬間にカーネルが答えを作るからである。/proc/meminfo も同じで、free（第8章）はここを読んでいる。MemTotal 以外の数は、人と時刻によって違う。

カーネルが情報を見せる3つの窓

この節で分かること: /proc・/sys・/dev が何で、それぞれ何を見せるか。

カーネルは、自分が知っている装置やプロセスの情報を、ファイルの形で3つの場所に出している。どれもディスクの上には無い。マウントの一覧で、種類を見る（findmnt の -t は第8章と同じく、種類で絞る）。

$ findmnt -t proc,sysfs,devtmpfs -o TARGET,SOURCE,FSTYPE
TARGET
      SOURCE   FSTYPE
/dev  devtmpfs devtmpfs
/proc proc     proc
/sys  sysfs    sysfs

見出しの TARGET だけが1行目に出て、残りが2行目に回っているのは、第3章の lsblk と同じ癖である（findmnt では、TARGET の列の中身がすべて見出しより短いと、その後ろの見出しを次の行に回す）。proc（procfs とも呼ぶ）・sysfs・devtmpfs は、どれもカーネルがメモリの上に作るファイルシステムである。

窓見せ方何のためにあるか
/proc（proc）カーネルとプロセスの状態を表にしたファイル（cpuinfo・meminfo・partitions・swaps など）状態を人やコマンドが読む。lscpu・free・swapon -s はここを読む
/sys（sysfs）装置ごとのディレクトリと、属性ごとのファイル装置1つ1つの性質を読む。いくつかは root が書き換えられ、書くとその場で扱いが変わる
/dev（devtmpfs）装置への入口になるデバイスファイルプログラムが装置を開いて読み書きする（第1章の /dev/vdb）
たとえ: 工場の計器盤に近い。/proc は全体の表示板、/sys は機械ごとの計器、/dev は機械を動かすレバーである。計器は読めばいまの値を示すが、紙に記録されているわけではない。
ただし崩れる点: 計器は読むだけのものだが、/sys のいくつかのファイルは root が書き込める。書くとカーネルの扱いがその場で変わり、電源を切ると元に戻る（この章の後半）。

割り込み・I/O ポート・DMA

この節で分かること: 装置と CPU のやりとりに使う3つの資源と、その見方。

装置と CPU がやりとりするために、装置ごとに3つの資源が割り当てられる。

資源何のためにあるか見る場所
割り込み（IRQ）装置が CPU に「用がある」と知らせる（キーが押された・読み込みが終わった など）。番号で装置を見分ける/proc/interrupts
I/O ポートCPU が装置に命令を出したり、装置の状態を読んだりするための番地/proc/ioports
DMA装置が CPU を通さずに、メモリへ直接読み書きする通り道（CPU の手間を減らす）/proc/dma
$ head -4 /proc/interrupts
           CPU0       CPU1
  0:        302          0   IO-APIC   2-edge      timer
  1:          9          0   IO-APIC   1-edge      i8042
  4:        565          0   IO-APIC   4-edge      ttyS0
$ head -5 /proc/ioports
0000-0000 : PCI Bus 0000:00
  0000-0000 : dma1
  0000-0000 : pic1
  0000-0000 : timer0
  0000-0000 : timer1
$ sudo head -5 /proc/ioports
0000-0cf7 : PCI Bus 0000:00
  0000-001f : dma1
  0020-0021 : pic1
  0040-0043 : timer0
  0050-0053 : timer1
$ cat /proc/dma
 4: cascade

割り込みは、番号ごとに各 CPU が何回受けたか（数は人と時刻によって違う）と、誰の割り込みか（timer・キーボードのコントローラ（キーボードとのやりとりを受け持つ部品）i8042・シリアルポート（古い形式の通信の口）ttyS0）が並ぶ。I/O ポートは、一般ユーザが読むと番地が全部 0000-0000 に伏せられ、sudo で読むと本当の番地が出た。同じファイルでも、読む人によってカーネルが答えを変えている。DMA の 4 番（cascade）は、2つの DMA の部品をつなぐための予約で、いまの PC ではほぼこれしか出ない。

$ virsh domblklist linuc

------------------------------------------------

練習機の中の名前（Target）と、外のファイル（Source）の対応が出る。練習機のディスクは、どれも外のコンテナの中にある qcow2（QEMU のディスクのファイルの形式）のファイルで、光学ドライブ（sdb の名前で定義されたもの。練習機の中では sr0）だけが ISO イメージを指している。

たとえ: lspci は建物の入居者名簿に近い。何階の何号室（番地）に誰（装置）が入っていて、担当の管理人（ドライバ）が誰かが分かる。
ただし崩れる点: 本物の建物なら名簿と部屋が食い違うことはあるが、仮想マシンでは名簿（外の定義）がそのまま建物になる。だから全員の練習機で同じ lspci が出る。実機では、マザーボードと挿したカードの数だけ違う。

HDD か SSD か

この節で分かること: カーネルが「回転するディスクかどうか」を何で決めているか。

HDD は円盤を回して磁気ヘッドを動かすので、離れた場所を続けて読むと遅い。SSD は半導体のメモリなので、どこを読んでも速さがほぼ同じである。カーネルは装置ごとに「回転するかどうか」の印を持っていて、読み書きの順番の工夫などに使う。その印が lsblk の ROTA（rotational = 回転する）列に出る。

ふつうこう考える

練習機のディスクは、どれも外のコンテナの中の、同じ種類（qcow2）のファイルである（さっきの virsh domblklist）。カーネルが実際の速さを測って判断するのなら、全部同じ答えになるはずだ。

$ lsblk -d -o NAME,TRAN,ROTA,RM,RO,SIZE,MODEL
NAME
    TRAN   ROTA RM RO  SIZE MODEL
sda sata      0  0  0    1G QEMU HARDDISK   ← ROTA 0（回転しない = SSD 扱い）。型番は HARDDISK
sr0 sata      1  1  1  368K QEMU DVD-ROM
vda virtio    1  0  0   20G   ← ROTA 1（回転する = HDD 扱い）。virtio の5本とも
vdb virtio    1  0  0    2G
vdc virtio    1  0  0    1G
vdd virtio    1  0  0  256M
vde virtio    1  0  0  512M
だめな理由: 答えが割れた。SATA の sda だけが回転しない装置（SSD）で、virtio の5本は回転する装置（HDD）として扱われている。 しかも sda の型番は QEMU HARDDISK のままである。カーネルは測っていない。 SATA の装置は、自分の回転数を答える欄を持っていて、カーネルはその答えをそのまま信じる。 virtio のディスクにはその欄が無いので、既定の「回転する」になる。

外の定義で確かめる。違いは、定義の中の1語だけである。

$ virsh dumpxml linuc | grep rotation_rate
      <target dev='sda' bus='sata' rotation_rate='1'/>

rotation_rate='1' は「回転数 1」という特別な値で、SATA の決まりでは「回転しない装置」を意味する。QEMU はそう答え、カーネルはそれを /sys に書いた。lsblk はそのファイルを読んでいるだけである。

$ cat /sys/block/sda/queue/rotational /sys/block/vdb/queue/rotational
0
1

このファイルは root が書き換えられ、書けばその場で扱いが変わる。

$ echo 0 | sudo tee /sys/block/vdb/queue/rotational
0
$ lsblk -d -o NAME,ROTA /dev/vdb
NAME
    ROTA
vdb    0

ただし /sys はメモリの上の窓なので、再起動すると装置が名乗った値（1）に戻る。起動のたびに書き直す仕組みが要る。それが udev である。udev は、装置が見つかるたびに（起動のときは全部の装置について）カーネルから知らせを受け、規則（rules）のファイルに従って処理をするプログラムで、第6章の /dev/disk/by-label/ の別名もこれが作っている。規則の置き場所は2つある。

場所何のためにあるか
/usr/lib/udev/rules.d/パッケージが置く規則。書き換えない（更新で上書きされる）
/etc/udev/rules.d/管理者が置く規則。同じ名前のファイルがあれば、こちらが優先される

1行の規則を書く。== は「一致したら」（条件）、= は「こう書く」（動作）で、ATTR{queue/rotational} は /sys/block/vdb/ の下のファイルを指す。「装置が加わった（add）か変わった（change）とき、ブロックの装置で、名前が vdb なら、queue/rotational に 0 を書け」と読む。

$ echo 'ACTION=="add|change", SUBSYSTEM=="block", KERNEL=="vdb", ATTR{queue/rotational}="0"' | sudo tee /etc/udev/rules.d/60-lab-ssd.rules
ACTION=="add|change", SUBSYSTEM=="block", KERNEL=="vdb", ATTR{queue/rotational}="0"

再起動したのと同じ状況で確かめる。値を装置が名乗った 1 に戻してから、起動のときと同じ知らせ（add）を udev に1回だけ送る。udevadm trigger は udev に知らせを送るコマンドで、--sysname-match=vdb で vdb だけに絞り、--settle で udev が処理し終えるまで待つ。

$ echo 1 | sudo tee /sys/block/vdb/queue/rotational
1
$ sudo udevadm trigger --action=add --subsystem-match=block --sysname-match=vdb --settle
$ cat /sys/block/vdb/queue/rotational
0

知らせを受けた udev が、規則どおりに 0 を書いた。起動のときも、すべての装置についてこの知らせが出るので、再起動しても vdb は SSD として扱われる。

たとえ: 入館証の自己申告の欄に近い。受付は「技術職」と書かれていれば技術職として案内し、本当かどうかは確かめない。
ただし崩れる点: 入館証は本人しか書けないが、rotational は後から root が書き換えられ、udev の規則にしておけば来館のたびに書き換えてくれる。申告を上書きする手段が、受け取る側に用意されている。
HDDSSD光学ドライブ
しくみ回る磁気ディスクとヘッドフラッシュメモリ（半導体）回る CD・DVD・BD をレーザーで読む
ROTA101
得意・苦手離れた場所を続けて読むと遅い。容量あたりが安いどこを読んでも速い。書き換えの回数に寿命がある読み取り専用か、書けても遅い。メディアを抜き差しできる
Linux での名前（例）/dev/sda/dev/sda（SATA）・/dev/nvme0n1（NVMe。SSD を PCI に直接つなぐ方式）/dev/sr0
この練習機vda〜vde（virtio）。vdb はいま SSD 扱いsda（SATA）sr0（SATA）

光学ドライブからメディアを抜く

この節で分かること: 光学ドライブの RM・RO と、メディアを抜いたときに何が残るか。

さっきの表で sr0 は RM（取り外せる）が 1、RO（読み取り専用）が 1 だった。外の端末で、光学ドライブからメディアを抜く（change-media … --eject は、ドライブの蓋を開けて CD を取り出すことに当たる）。

$ virsh change-media linuc sdb --eject
Successfully ejected media.
$ lsblk -d -o NAME,TYPE,RM,RO,SIZE /dev/sr0
NAME
    TYPE RM RO  SIZE
sr0 rom   1  1  368K
$ sudo mount /dev/sr0 /mnt
mount: /mnt: no medium found on /dev/sr0.
       dmesg(1) may have more information after failed mount system call.

装置（sr0）は消えない。抜けたのはメディアだけである。しかも lsblk はまだ 368K と言っている。表示は前に読んだ大きさのままで、実際に読みに行った mount だけが本当の状態（no medium found、メディアが無い）を知った。戻しておく。

$ virsh change-media linuc sdb /usr/share/lab-disks/linuc-media.iso --insert
Successfully inserted media.
$ lsblk -d -o NAME,TYPE,RM,RO,SIZE /dev/sr0
NAME
    TYPE RM RO  SIZE
sr0 rom   1  1  368K
たとえ: レコードプレーヤーに近い。台（ドライブ）は置いたまま、盤（メディア）だけを入れ替える。盤が無くても台はそこにある。
ただし崩れる点: プレーヤーなら盤が無いことは見れば分かるが、Linux の表示（lsblk の SIZE）は前の盤の大きさを出し続けることがある。確かめるには、実際に読んでみる。
確認

lsblk -d -o NAME,ROTA で sda の ROTA が 0 だった。この値はどのファイルを読んだもので、何によって決まったか。

答え

/sys/block/sda/queue/rotational を読んだもの。値は装置の申告で決まる（SATA の装置が回転数の欄に「回転しない」と答えた）。カーネルが速さを測った結果ではない。root は書き換えられるが、再起動すると申告の値に戻る。起動のたびに変えるには、udev の規則を /etc/udev/rules.d/ に置く。

確認

PCI につながっている装置の一覧と、それぞれを動かしているドライバを表示したい。打つコマンドは何か。USB の装置を、つながり方の木とドライバ付きで表示するコマンドは何か。

答え

PCI は lspci -k（1台に絞るなら -s 00:1f.2 のように番地を付ける）。USB は lsusb -t。

確認

装置が CPU に「用がある」と知らせるための番号の割り当ては、どのファイルで見られるか。

答え

/proc/interrupts（割り込み、IRQ）。I/O ポートは /proc/ioports、DMA は /proc/dma。

この章で分かったこと

持ち帰ってほしいこと

  • CPU は lscpu（元は /proc/cpuinfo）、メモリは free（元は /proc/meminfo）で読む。/proc のファイルは大きさ 0 で、読んだ瞬間に作られる
  • /proc（カーネルとプロセスの状態）・/sys（sysfs。装置ごとの属性）・/dev（装置の入口）は、どれもカーネルがメモリの上に作る窓
  • 割り込み（IRQ）は /proc/interrupts、I/O ポートは /proc/ioports、DMA は /proc/dma
  • lspci -k で PCI の装置と動かしているドライバ、lsusb -t で USB のつながりとドライバが分かる
  • HDD か SSD か（ROTA）は、カーネルが測ったのではなく装置の申告。/sys/block/<装置>/queue/rotational にあり、root が書き換えられ、udev の規則（/etc/udev/rules.d/）で起動のたびに書き換えられる
  • 光学ドライブは RM=1・RO=1（書き込めないドライブの場合）。メディアを抜いても装置は残る
