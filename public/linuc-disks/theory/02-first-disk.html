2. 空のディスクを使えるようにする

第1章では、練習機に入り、lsblk と df で、vdb（2G）が区画もファイルシステムも持たない空のディスクだと確かめた。この章では、その vdb を区切る → ファイルシステムを作る → マウントする → ファイルを書く → 外す、と一通り使ってみる。

前提: 第1章まで読了前提: 練習機の中にいる所要 20分影響度 B出題範囲 1.05.2（重要度4）出題範囲 1.05.3（重要度4）最終検証 2026-10-20

この章のゴール

  • fdisk で、空のディスクにパーティションを1つ作れる（n で作り、p で確かめ、w で書く）
  • mkfs.ext4 でファイルシステムを作り、mount でつないで読み書きし、umount で外せる
  • マウントしたディスクに student のままファイルを書いてみて、どうなるかを確かめ、書けるようにできる
ここで覚えなくていいこと: fdisk が出す表の形式の名前（DOS・MBR）と Disk identifier は、この章では読まない。mkfs.ext4 の出力の途中の行（Allocating group tables など）の意味も、この章では読まない。区画の大きさの決め方（何 MB にするか）は扱わず、ここでは 200M にする。

区切る — fdisk でパーティションを1つ作る

この節で分かること: fdisk の問いに順に答えて、区画を1つ作るまでの流れ。

ディスクを書き換えるコマンドには、root（管理者）の権限が要る。練習機の root は直接ログインできないようにしてあり、student が sudo を付けて打つ（パスワードは聞かれない）。

fdisk は、ディスクのパーティションの表（どこからどこまでを区画にするかを書いた表。ディスクの先頭に置かれる）を作るコマンドである。ディスクの名前を渡すと、1文字のコマンドを受け付ける対話の画面になる。n（新しい区画）で作り、p（表示）で確かめ、w（書き込み）で終える。

$ sudo fdisk /dev/vdb
Welcome to fdisk (util-linux 2.39.3).
Changes will remain in memory only, until you decide to write them.
Be careful before using the write command.

Device does not contain a recognized partition table.
Created a new DOS (MBR) disklabel with disk identifier 0xc9184d2b.   ← 表が無かったので、空の表をメモリの上に作った

Command (m for help): n   ← n: 新しいパーティション
Partition type
   p   primary (0 primary, 0 extended, 4 free)
   e   extended (container for logical partitions)
Select (default p): p   ← p: 基本パーティション
Partition number (1-4, default 1): 1   ← 1 番にする
First sector (2048-4194303, default 2048):   ← Enter だけ: 始まりは 2048 番目のセクタ
Last sector, +/-sectors or +/-size{K,M,G,T,P} (2048-4194303, default 4194303): +200M   ← +200M: 大きさで答える

Created a new partition 1 of type 'Linux' and of size 200 MiB.

Command (m for help): p   ← p: いまの表を見る（まだ書いていない）
Disk /dev/vdb: 2 GiB, 2147483648 bytes, 4194304 sectors
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes
I/O size (minimum/optimal): 512 bytes / 512 bytes
Disklabel type: dos
Disk identifier: 0xc9184d2b

Device     Boot Start    End Sectors  Size Id Type
/dev/vdb1        2048 411647  409600  200M 83 Linux

Command (m for help): w   ← w: ここで初めてディスクに書く
The partition table has been altered.
Calling ioctl() to re-read partition table.
Syncing disks.

上から順に読む。

  • 最初の3行は「変更は、書き込みを指示するまでメモリの上だけにある」という注意である。
  • Device does not contain a recognized partition table. は「このディスクには表が無い」。fdisk は空の表をメモリの上に作った（0x で始まる番号は表ごとに違い、あなたの画面では別の値になる。0x は16進数（0〜9 と a〜f の16文字で書く数）の印）。
  • n の後、区画の種類を聞かれる。p（primary、基本パーティション）を選ぶ。もう1つの e は、区画を5つ以上に分けたいときに使う種類である。番号は 1 にした。
  • First sector は区画の始まりの位置である。セクタはディスクを読み書きする最小の単位で、ここでは 512 バイト。Enter だけを押すと、括弧の中の default（2048）になる。表そのものはディスクの先頭の1セクタに入り、残りの 2047 セクタは、区画の始まりを 1MiB（1024×1024 バイト = 2048 セクタ）の切れ目にそろえるために空けておく（いまの道具の決まりごと）。
  • Last sector は終わりの位置で、+200M のように大きさで答えられる。大きさの単位は 1024 倍ずつで、1KiB = 1024 バイト、1MiB = 1024KiB、1GiB = 1024MiB、1TiB = 1024GiB である。fdisk や lsblk の K・M・G・T はこの意味（1000 倍ずつの KB・MB とは少し違い、第4章の parted は MB で表示する）。
  • p で、メモリの上の表を出した。/dev/vdb1 が 2048 番目のセクタから 411647 番目まで、200M ある。
  • w で表をディスクに書き、カーネルに読み直させて（Calling ioctl() to re-read partition table.）終わった。
$ lsblk /dev/vdb
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
vdb    253:16   0    2G  0 disk
└─vdb1 253:17   0  200M  0 part

vdb の中に vdb1（200M、TYPE は part）ができた。

キーすること何のためにあるか
mキーの一覧を出す（menu）キーを忘れたとき
n区画を作る（new）区画を足す
pいまの表を出す（print）書く前に確かめる
wディスクに書いて終わる（write）変更を本物にする
q書かずに終わる（quit）間違えたときに、何も変えずに抜ける
たとえ: fdisk は下書きしてから清書する書き方に近い。n で下書きし、p で見直し、w で清書する。気に入らなければ q で下書きを捨てる。
ただし崩れる点: p の表示は、まだ書いていない下書きも、書き終えた表と同じ形で見せる。p で vdb1 が見えても、w を打つまではディスクに何も書かれておらず、その時点で別の端末から lsblk を打っても vdb1 は出ない。

作る — ファイルシステムを作る

この節で分かること: 区画にファイルシステムを作ると何ができるか。

区画ができただけでは、まだファイルを置けない。区画の中に、ファイルを名前で整理するための管理情報（ファイルシステム）を書く。mkfs.ext4 は ext4（Linux でいちばんよく使われるファイルシステムの種類）を作るコマンドである。

$ sudo mkfs.ext4 /dev/vdb1
mke2fs 1.47.0 (5-Feb-2023)
Discarding device blocks: done
Creating filesystem with 51200 4k blocks and 51200 inodes
Filesystem UUID: fbf1c74f-06aa-4438-8760-faea24f1a144   ← このファイルシステムの番号。作るたびに変わる
Superblock backups stored on blocks:
	32768

Allocating group tables: done
Writing inode tables: done
Creating journal (4096 blocks): done
Writing superblocks and filesystem accounting information: done

Creating filesystem with 51200 4k blocks は「4KiB の塊を 51200 個並べた ext4 を作る」（4KiB × 51200 = 200MiB）。Filesystem UUID は、作ったときに決まるこのファイルシステムの番号（UUID）で、作るたびに違う値になる（あなたの画面では別の値）。最後の done まで出れば、管理情報が書けている。mkfs は区画の中に管理情報を書いて、ファイルシステムを新しく作る。前にファイルシステムがあれば、それを上書きして消す操作だと覚えておく（前のファイルシステムに気づいて確かめてくる道具もあるが、何も言わずに上書きする道具もある。第5章で比べる）。

lsblk に、ファイルシステムの種類（FSTYPE）とマウント先の列を足して見る。

$ lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS /dev/vdb
NAME    SIZE FSTYPE MOUNTPOINTS
vdb       2G
└─vdb1  200M ext4

vdb1 の FSTYPE が ext4 になった。MOUNTPOINTS はまだ空で、どこからも使えない。

たとえ: 第1章の土地と倉庫で言えば、fdisk で区画を切り、mkfs でそこに倉庫を建てた。倉庫には棚の配置図（管理情報）と、倉庫ごとの番号（UUID）がある。
ただし崩れる点: 本物の倉庫を建て直せば、中の物が壊れることは見れば分かる。mkfs は作り終えても、前に何があって何が消えたかを教えない。打つ前に、相手の区画の名前を確かめる。

つなぐ — マウントして読み書きする

この節で分かること: マウントすると、どのディレクトリから何が見えるようになるか。

mount は、ファイルシステムをディレクトリにつなぐコマンドである。つなぐ相手の装置と、つなぐ先のディレクトリ（マウントポイント）を順に渡す。/mnt は、一時的に何かをつなぐために最初から用意されている空のディレクトリである。

$ sudo mount /dev/vdb1 /mnt
$ df -h /mnt
Filesystem      Size  Used Avail Use% Mounted on
/dev/vdb1       172M   24K  158M   1% /mnt
$ ls -l /mnt
total 16
drwx------ 2 root root 16384 Oct 20 23:39 lost+found
$ lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS /dev/vdb
NAME    SIZE FSTYPE MOUNTPOINTS
vdb       2G
└─vdb1  200M ext4   /mnt

mount はうまくいくと何も出さない。df -h /mnt の Filesystem が /dev/vdb1 になり、/mnt が vdb1 の ext4 につながったと分かる（Size が 200M より小さいのは、ext4 が自分の管理情報などに使う分を除いて数えているから）。中には lost+found というディレクトリが1つある。これは ext4 が作るときに用意する、壊れたファイルの断片を置くための場所である。lsblk の MOUNTPOINTS にも /mnt が出た。

ふつうこう考える

/mnt に新しいディスクがつながった。ここにファイルを書けば、vdb1 に保存されるはずだ。

$ echo "はじめてのファイル" > /mnt/memo.txt
-bash: /mnt/memo.txt: Permission denied
だめな理由: Permission denied（書き込みの許可が無い）で断られた。マウントすると、/mnt は vdb1 の ext4 のいちばん上のディレクトリを見せるようになる。その持ち主と権限は ext4 の中に書かれていて、mkfs が作ったときに root のもの（rwxr-xr-x）になった。student は「その他」なので書けない。
$ ls -ld /mnt
drwxr-xr-x 3 root root 4096 Oct 20 23:39 /mnt

ls の -d は、ディレクトリの中身ではなく、ディレクトリそのものを1行で出すオプションである。持ち主が root で、その他の人は r-x（読む・中に入るだけ）である。このディスクを student のデータ置き場にするなら、いちばん上のディレクトリの持ち主を student に変える。chown は、ファイルやディレクトリの持ち主を変えるコマンドである（student:student は「持ち主を student、グループを student に」）。

$ sudo chown student:student /mnt
$ ls -ld /mnt
drwxr-xr-x 3 student student 4096 Oct 20 23:39 /mnt
$ echo "はじめてのファイル" > /mnt/memo.txt
$ cat /mnt/memo.txt
はじめてのファイル
$ ls -l /mnt
total 20
drwx------ 2 root    root    16384 Oct 20 23:39 lost+found
-rw-rw-r-- 1 student student    28 Oct 20 23:39 memo.txt

持ち主が student になり、書けた。変わったのは vdb1 の ext4 の中に書かれた持ち主で、練習機の / にある /mnt というディレクトリそのものではない（次の節で外したときに確かめる）。

たとえ: マウントは、引き出しを机の決まった穴に差し込むことに近い。差し込むと、その穴（マウントポイント）から引き出し（ファイルシステム）の中が見え、物を出し入れできる。
ただし崩れる点: 引き出しの鍵（持ち主と権限）は、穴ではなく引き出しの側に付いている。/mnt の持ち主を変えたつもりでも、変わったのは差し込んだ引き出しの鍵である。だから引き出しを抜くと、穴は元の持ち主（root）に戻る。

外す — umount

この節で分かること: 外したあと、ディレクトリとディスクがそれぞれどうなるか。

使い終わったら外す。外すコマンドは umount である（unmount ではなく、u の後に n が無い）。マウントポイントか装置の名前を渡す。

$ sudo umount /mnt
$ ls /mnt
$ ls -ld /mnt
drwxr-xr-x 2 root root 4096 Sep  5 20:14 /mnt
$ lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS /dev/vdb
NAME    SIZE FSTYPE MOUNTPOINTS
vdb       2G
└─vdb1  200M ext4

/mnt は空に戻り（ls が何も出さない）、持ち主も root に戻った（日付も、練習機の Ubuntu が作られた日のまま）。vdb1 の MOUNTPOINTS は空になったが、FSTYPE は ext4 のままである。memo.txt は vdb1 の ext4 の中に残っていて、もう一度 /dev/vdb1 をマウントすれば読める（次の章の最初で使う）。

区切る         作る            つなぐ                   使う             外す
fdisk    →   mkfs.ext4   →   mount /dev/vdb1 /mnt  →  /mnt に書く  →  umount /mnt
（表に1行）  （管理情報を書く）（/mnt から中が見える）                    （中身は vdb1 に残る）
たとえ: 外すのは、引き出しを机から抜いて棚にしまうことに近い。抜いても中の物は引き出しに入ったままで、次に差し込めばまた取り出せる。
ただし崩れる点: 机なら引き出しを抜いても机の穴はそこにあるが、マウントポイントを消してしまう（/mnt を rmdir する）と、次にマウントするときに穴が無くて断られる。マウントポイントは、前もって用意しておくただのディレクトリである。
手を動かす: 実践編の演習01は、この章の流れを、空のディスク vde（512M）で自分でなぞる課題である。 判定は vde の表と、その中のファイルシステムを直接読んで確かめる。
確認

sudo fdisk /dev/vdb で n を打って区画を作り、p で表示を確かめてから q で抜けた。lsblk /dev/vdb に新しい区画は出るか。

答え

出ない。fdisk の変更は w を打つまでメモリの上にしかなく、q は書かずに終わる。p はまだ書いていない表も同じ形で見せる。

確認

新しい ext4 を /srv/data にマウントしたら、一般ユーザでファイルを作れなかった（Permission denied）。何を確かめ、どう直すか。

答え

ls -ld /srv/data で、マウントしているファイルシステムのいちばん上のディレクトリの持ち主と権限を確かめる。mkfs で作ったばかりなら root のもので、その他の人は書けない。使う人を持ち主にする（sudo chown ユーザ:グループ /srv/data）。この変更はファイルシステムの中に書かれるので、外してもう一度マウントしても残る。

確認

空のディスク /dev/sdb を使えるようにして /mnt から使い、最後に外したい。打つコマンドを順に並べよ（区画は1つでよい）。

答え

sudo fdisk /dev/sdb（n・p・w で sdb1 を作る）→ sudo mkfs.ext4 /dev/sdb1 → sudo mount /dev/sdb1 /mnt → （使う）→ sudo umount /mnt。

この章で分かったこと

持ち帰ってほしいこと

  • 空のディスクを使えるようにするのは、区切る（fdisk）→ 作る（mkfs.ext4）→ つなぐ（mount）の3段。使い終わったら umount で外す
  • fdisk は w を打つまでディスクに書かない。q で抜ければ何も変わらない
  • +200M のように大きさで区画の終わりを指定できる。セクタは読み書きの最小の単位（ここでは 512 バイト）
  • mkfs は区画の中にファイルシステムを作り直す（前の中身は消える）。作るたびに UUID が決まる
  • マウントすると、マウントポイントはファイルシステムのいちばん上のディレクトリを見せる。その持ち主と権限はファイルシステムの中にあり、作ったばかりなら root のもの。外すと元のディレクトリに戻る
