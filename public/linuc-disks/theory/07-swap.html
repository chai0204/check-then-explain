7. tmpfs は、メモリを先に取らない

メモリが 1.4GiB しかない練習機に、size=4G の tmpfs をマウントできる。マウントしても free の数字は1つも変わらない。tmpfs の size は上限で、メモリは書いた分だけ使われる。スワップも同じで、mkswap しただけではスワップは1バイトも増えない。

前提: 第6章まで読了前提: 演習04 の切り方になっている所要 16分影響度 B出題範囲 1.05.3（重要度4）最終検証 2026-10-13

この章のゴール

  • mkswap・swapon・swapoff の役割を言い分けられ、スワップをパーティションでもファイルでも作れる
  • 起動時に使うスワップを /etc/fstab に書き、再起動せずに確かめられる
  • tmpfs がメモリの上のファイルシステムで、size が上限であることを説明できる
ここで覚えなくていいこと: スワップの使われやすさの調整（vm.swappiness）、zram・zswap、休止（ハイバネート）の設定は扱わない。スワップを「どれくらいの大きさにするか」の目安は、本文の表だけでよい。

スワップは、作る・使い始める・外すが別のコマンド

この節で分かること: スワップ領域を使えるようになるまでの3段階。

スワップは、メモリが足りないときにしばらく使われていないページを書き出しておくディスクの領域である。第4章で見たとおり、練習機にはまだ無い。第4章で切った vdb3（種類 Linux swap）をスワップにする。

$ free -h
               total        used        free      shared  buff/cache   available
Mem:           1.4Gi       254Mi       1.1Gi       804Ki       202Mi       1.1Gi
Swap:             0B          0B          0B
$ sudo mkswap -L SWAP /dev/vdb3
Setting up swapspace version 1, size = 256 MiB (268431360 bytes)
LABEL=SWAP, UUID=0c9279db-9da9-402f-afe7-2fcb3eeef276
$ free -h
               total        used        free      shared  buff/cache   available
Mem:           1.4Gi       256Mi       1.1Gi       804Ki       202Mi       1.1Gi
Swap:             0B          0B          0B   ← mkswap しても 0B のまま

mkswap はスワップ領域の形を作るだけで（ファイルシステムの mkfs に当たる）、使い始めるのは swapon である。

$ sudo swapon /dev/vdb3
$ swapon --show
NAME      TYPE      SIZE USED PRIO
/dev/vdb3 partition 256M   0B   -2
$ cat /proc/swaps
Filename				Type		Size		Used		Priority
/dev/vdb3                               partition	262140		0		-2
$ swapon -s
Filename				Type		Size		Used		Priority
/dev/vdb3                               partition	262140		0		-2
$ free -h
               total        used        free      shared  buff/cache   available
Mem:           1.4Gi       252Mi       1.1Gi       804Ki       202Mi       1.1Gi
Swap:          255Mi          0B       255Mi

使われているスワップは swapon --show・/proc/swaps・swapon -s（/proc/swaps と同じ形）で見られる。PRIO は優先度で、何も指定しないと -2 のような負の数が順に付く。

スワップはファイルでも作れる。

$ sudo dd if=/dev/zero of=/swapfile bs=1M count=128 status=none
$ ls -l /swapfile
-rw-r--r-- 1 root root 134217728 Oct 13 11:46 /swapfile
$ sudo mkswap /swapfile
mkswap: /swapfile: insecure permissions 0644, fix with: chmod 0600 /swapfile
Setting up swapspace version 1, size = 128 MiB (134213632 bytes)
no label, UUID=205fce88-8104-48d8-af8c-a43bd76ae187
$ sudo chmod 600 /swapfile
$ sudo swapon -p 10 /swapfile
$ swapon --show
NAME      TYPE      SIZE USED PRIO
/dev/vdb3 partition 256M   0B   -2
/swapfile file      128M   0B   10
$ sudo swapoff /swapfile
$ sudo rm /swapfile

mkswap が insecure permissions 0644 と注意した。スワップにはメモリの中身（パスワードを含むかもしれない）が書き出されるので、root 以外に読めてはいけない。-p 10 で優先度を付けると、数の大きいほうから使われる。swapoff で外す。

たとえ: 書類を逃がす段ボール箱が2つあるとき、手の届く近い箱（優先度の高いほう）から詰めていくのに近い。近い箱がいっぱいになってから、遠い箱を使う。
ただし崩れる点: 人なら同じ距離の箱が2つあればどちらか一方から詰めるが、カーネルは優先度が同じスワップには交互に書く（swapon の man に書かれている）。速さの同じディスクを同じ優先度にすると、両方へ分けて書ける。

起動するたびに使うスワップは /etc/fstab に書く。マウントポイントの欄は none、種類は swap。デバイス名ではなく、mkswap が書き込んだ UUID で指す（理由は第8章）。

$ echo "UUID=$(sudo blkid -s UUID -o value /dev/vdb3)  none  swap  sw  0  0" | sudo tee -a /etc/fstab
UUID=0c9279db-9da9-402f-afe7-2fcb3eeef276  none  swap  sw  0  0
$ sudo systemctl daemon-reload
$ sudo swapoff /dev/vdb3
$ swapon --show
$ sudo swapon -a
$ swapon --show
NAME      TYPE      SIZE USED PRIO
/dev/vdb3 partition 256M   0B   -2

/etc/fstab を書き換えたら、起動時にそれを読む systemd に daemon-reload で読み直させる（理由は第8章）。swapon -a は「/etc/fstab のスワップを全部有効にする」で、起動のときにも同じことが起きる。外してから -a で戻ってくれば、書いた行が効いていると再起動せずに確かめられる（第8章の最後で再起動して確かめる）。

コマンドすること
mkswap 区画かファイルスワップの形を作る。UUID を表示する（-L でラベル）
swapon 区画かファイル使い始める（-p で優先度）
swapon -a/etc/fstab のスワップを全部使い始める
swapon --show / swapon -s使っているスワップの一覧（/proc/swaps）
swapoff 区画かファイルやめる（-a で全部）。使っていた中身はメモリに戻される
たとえ: 机の横に置く段ボール箱に近い。机（メモリ）に載り切らない書類を、しばらく使わないものから箱に移す。
ただし崩れる点: 段ボール箱は置いた時点で使えるが、スワップは mkswap（箱を組み立てる）だけでは使われない。swapon（机の横に置く）して初めて机の延長になる。
手を動かす: 実践編の演習07は、vdb3 をスワップにして、起動時にも使われるように /etc/fstab に UUID で書く課題である。 判定は vdb3 をいったん外し、起動時と同じ swapon -a で戻るかを見る。

tmpfs は、メモリを先に取らない

この節で分かること: tmpfs の size が何を意味するか。

tmpfs は、メモリの上に置くファイルシステムである。練習機でもすでにいくつか使われている。

$ findmnt -t tmpfs -o TARGET,FSTYPE,SIZE
TARGET           FSTYPE   SIZE
/dev/shm         tmpfs  712.5M
/run             tmpfs    285M
├─/run/lock      tmpfs      5M
└─/run/user/1000 tmpfs  142.5M
$ free -m
               total        used        free      shared  buff/cache   available
Mem:            1424         252        1118           0         202        1172
Swap:            255           0         255

メモリは全部で 1424MiB しかない。そこに 4GiB の tmpfs を作る。

ふつうこう考える

tmpfs はメモリの上に置くのだから、size=4G と書けばメモリを 4GiB 取るはずだ。 メモリが 1.4GiB しかないこの練習機では、マウントできないか、できてもメモリが足りなくなるだろう。

$ sudo mkdir -p /mnt/ram
$ sudo mount -t tmpfs -o size=4G tmpfs /mnt/ram
$ df -h /mnt/ram
Filesystem      Size  Used Avail Use% Mounted on
tmpfs           4.0G     0  4.0G   0% /mnt/ram
$ free -m
               total        used        free      shared  buff/cache   available
Mem:            1424         252        1118           0         202        1172
Swap:            255           0         255
だめな理由: マウントでき、df には 4.0G と出て、free の数字は変わらない。 tmpfs の size は上限で、作った時点ではメモリを1バイトも取らない。書いた分だけ、その場でメモリ（ページキャッシュ）を使う。 だから実際のメモリより大きな size も書けてしまう。

300MiB 書いてみる。

$ sudo dd if=/dev/zero of=/mnt/ram/fill bs=1M count=300 status=none
$ free -m
               total        used        free      shared  buff/cache   available
Mem:            1424         552         817         300         503         872   ← shared が 300 増え、available が減った
Swap:            255           0         255
$ df -h /mnt/ram
Filesystem      Size  Used Avail Use% Mounted on
tmpfs           4.0G  300M  3.8G   8% /mnt/ram
$ sudo umount /mnt/ram
$ free -m
               total        used        free      shared  buff/cache   available
Mem:            1424         254        1116           0         203        1170
Swap:            255           0         255

書いた 300MiB は free の shared（tmpfs などの共有メモリ）に出て、available（使える量）がそのぶん減った。外すと、中身ごと消えてメモリが戻る。tmpfs の中身は、外すか再起動すると消える。メモリが足りなくなれば、tmpfs の中身もスワップに追い出される。

tmpfsスワップ
置き場所メモリ（足りなければスワップへ）ディスク
作り方mount -t tmpfs -o size=… tmpfs 場所mkswap → swapon
大きさの意味上限。書いた分だけメモリを使うディスクの上に確保した大きさ
再起動すると中身は消える中身は意味を持たない（/etc/fstab にあれば、また使い始める）
この練習機の例/run・/dev/shm・/run/lockvdb3（この章で作った）
たとえ: ホワイトボードに近い。広さの上限は決まっているが、インク（メモリ）は書いた分しか減らず、消せば跡形も無い。
ただし崩れる点: ホワイトボードは部屋の壁より大きくできないが、tmpfs の size は実際のメモリより大きく書けてしまう。そのまま書き続けると、メモリとスワップを使い切る。size は「確保」ではなく「ここまで」という約束でしかない。
確認

mkswap /dev/sdb2 を実行したが、free の Swap が 0B のまま。何が足りないか。起動時にも使うにはどうするか。

答え

swapon /dev/sdb2 で使い始める（mkswap は形を作るだけ）。起動時にも使うには、/etc/fstab に UUID=… none swap sw 0 0 の行を書く。swapon -a で、その行が効くかを再起動せずに確かめられる。

確認

スワップが2つあり、swapon --show の PRIO が 10 と -2 だった。どちらから使われるか。

答え

数の大きい 10 のほうから使われる。優先度は swapon -p か、/etc/fstab のオプション pri=10 で付ける。付けなければ、有効にした順に -2・-3… と負の数が付く。

確認

メモリが 2GiB のマシンで mount -t tmpfs -o size=8G tmpfs /mnt/t を実行した。マウントできるか。マウントした直後のメモリの使用量はどうなるか。

答え

マウントできる。size は上限なので、直後のメモリの使用量は変わらない。書き込んだ分だけメモリを使い、外すか再起動すると中身は消える。

この章で分かったこと

持ち帰ってほしいこと

  • スワップは mkswap（形を作る）→ swapon（使い始める）→ swapoff（やめる）。mkswap だけでは使われない
  • 使っているスワップは swapon --show・swapon -s・/proc/swaps・free で見る。優先度は数の大きいほうから
  • スワップはファイルでも作れる。権限は 600 にする（mkswap が注意する）
  • 起動時に使うものは /etc/fstab に UUID=… none swap sw 0 0。swapon -a で再起動せずに確かめられる
  • tmpfs はメモリの上のファイルシステム。size は上限で、書いた分だけメモリを使い、外すか再起動すると消える
