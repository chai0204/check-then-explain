8. マウントは、名前ではなく中身の印で指す

USB メモリ A を /dev/sdb としてフォーマットした。抜いて B を挿し、A を挿し直すと、/dev/sdb は B になっていた。/dev/sdb は「何番目に見つかったか」で付く名前で、ディスクの持ち物ではない。持ち物は中身に書いた UUID とラベルだけである。そしてそのラベルが、練習機自身の /boot を危うくしていた。

前提: 第7章まで読了前提: 練習機が起動している所要 30分影響度 B出題範囲 1.05.3（重要度4）最終検証 2026-10-13

この章のゴール

  • mount・umount とマウントポイントの関係を説明でき、umount が断る理由を言える
  • /etc/fstab の6列を書け、UUID とラベルで指せる。nofail・noauto・user の意味を言える
  • 一般ユーザが取り外せるメディアを /media の下にマウントできるように設定できる
ここで覚えなくていいこと: systemd の .mount ユニットの書き方、autofs、NFS などネットワーク越しのファイルシステム、マウントの名前空間は扱わない。/etc/fstab を書いたあと、いま動いている systemd に読み直させる1行（daemon-reload）だけ覚えればよい。

マウントポイントは、ただのディレクトリ

この節で分かること: マウントの前後で、ディレクトリに何が起きるか。

第6章で作った XFS（vdb4）を /mnt/newroot につなぐ。

$ sudo mount /dev/vdb4 /mnt/newroot
mount: /mnt/newroot: mount point does not exist.
       dmesg(1) may have more information after failed mount system call.
$ sudo mkdir -p /mnt/newroot
$ sudo touch /mnt/newroot/HIDDEN
$ ls /mnt/newroot
HIDDEN
$ sudo mount /dev/vdb4 /mnt/newroot
$ ls -a /mnt/newroot
.  ..
$ findmnt -o TARGET,SOURCE,FSTYPE /mnt/newroot
TARGET       SOURCE    FSTYPE
/mnt/newroot /dev/vdb4 xfs

マウントポイントは、前もって作っておくただのディレクトリである。マウントすると、そのディレクトリにもともとあった HIDDEN は見えなくなった。消えたのではなく、上にかぶさっただけである。

$ cd /mnt/newroot
$ sudo umount /mnt/newroot
umount: /mnt/newroot: target is busy.
$ cd
$ sudo umount /mnt/newroot
$ ls /mnt/newroot
HIDDEN
$ sudo rm /mnt/newroot/HIDDEN

中で作業しているプロセス（カレントディレクトリがその中にあるシェルも含む）があると、umount は target is busy で断る。ここでは自分のシェルが中にいたので、cd（引数なしでホームへ戻る）で外に出てから外した。外すと HIDDEN がまた見えた。

たとえ: 壁の釘に掛ける額縁に近い。額縁（ファイルシステム）を掛けると、後ろの壁（もとのディレクトリの中身）は見えなくなるが、壁が消えたわけではない。
ただし崩れる点: 額縁は誰かが見ていても外せるが、マウントは誰かが中にいると外せない。

/dev/sdb は、いつも同じ USB メモリ？

この節で分かること: /dev/sdb のような名前が、何で決まっているか。

USB メモリを2本使う。第2章で /etc/modprobe.d/ に置いた2つのファイルを消して、usb_storage が読み込まれるように戻す。ファイルを消したことには udev が自分で気づくので、再起動は要らない（第2章。置いていない人の rm は失敗するだけで害は無い）。

$ sudo rm /etc/modprobe.d/lab-usb.conf /etc/modprobe.d/lab-usb-install.conf

A を挿して FAT にし、目印のファイルを書く。

$ virsh attach-device linuc ~/vm/extra/usb-a.xml
Device attached successfully
$ lsblk -d -o NAME,TRAN,SIZE,SERIAL /dev/sdb
NAME
    TRAN SIZE SERIAL
sdb usb   64M LAB-USB-A
$ sudo mkfs.vfat -n STICK_A /dev/sdb
mkfs.fat 4.2 (2021-01-31)
$ sudo mkdir -p /media/stick
$ sudo mount /dev/sdb /media/stick
$ echo "これは A" | sudo tee /media/stick/who.txt
これは A
$ sudo umount /media/stick

A を抜いて B を挿し、B は ext4 にする。

$ virsh detach-device linuc ~/vm/extra/usb-a.xml
Device detached successfully
$ virsh attach-device linuc ~/vm/extra/usb-b.xml
Device attached successfully
$ lsblk -d -o NAME,TRAN,SIZE,SERIAL /dev/sdb
NAME
    TRAN SIZE SERIAL
sdb usb   64M LAB-USB-B
$ sudo mkfs.ext4 -q -L STICK_B /dev/sdb

A を挿し直す。B は挿したまま。

$ virsh attach-device linuc ~/vm/extra/usb-a.xml
Device attached successfully
$ lsblk -o NAME,TRAN,FSTYPE,LABEL,SERIAL /dev/sdb /dev/sdc
NAME
    TRAN FSTYPE LABEL   SERIAL
sdb usb  ext4   STICK_B LAB-USB-B
sdc usb  vfat   STICK_A LAB-USB-A

ふつうこう考える

A をフォーマットしたときの名前は /dev/sdb だった。/dev/sdb は A の名前なのだから、 mount /dev/sdb と打てば A が出てきて、who.txt が読めるはずだ。

$ sudo mount /dev/sdb /media/stick
$ cat /media/stick/who.txt
cat: /media/stick/who.txt: No such file or directory
$ findmnt -o TARGET,SOURCE,FSTYPE /media/stick
TARGET       SOURCE   FSTYPE
/media/stick /dev/sdb ext4
$ sudo umount /media/stick
だめな理由: /dev/sdb にいたのは B（ext4）だった。sdb という名前は、カーネルが見つけた順に空いている番号から付ける。 A を抜いたあいだに B が sdb を取り、あとから来た A は sdc になった。 しかも mount は種類を自分で判別するので、別のディスクを何も言わずにマウントした。 /etc/fstab に /dev/sdb と書いておくと、挿す順番しだいで別のディスクがマウントされる。

ディスクの持ち物は、中に書いた印だけである。blkid で読み、udev がそこから作った別名で確かめる。

$ sudo blkid /dev/sdb /dev/sdc
/dev/sdb: LABEL="STICK_B" UUID="57709cda-d84d-4899-9a7a-680061bd0758" BLOCK_SIZE="4096" TYPE="ext4"
/dev/sdc: SEC_TYPE="msdos" LABEL_FATBOOT="STICK_A" LABEL="STICK_A" UUID="9636-FC6C" BLOCK_SIZE="512" TYPE="vfat"
$ sudo findfs LABEL=STICK_A
/dev/sdc
$ ls -l /dev/disk/by-label/
total 0
lrwxrwxrwx 1 root root 10 Oct 13 19:33 BOOT -> ../../vdb2   ← BOOT は vdb2 を指している（次の節で見る）
lrwxrwxrwx 1 root root 10 Oct 13 19:33 ESP -> ../../vdb1
lrwxrwxrwx 1 root root 10 Oct 13 19:33 HOME -> ../../vdb6
lrwxrwxrwx 1 root root 10 Oct 13 19:30 KEEP -> ../../vdd2
lrwxrwxrwx 1 root root  9 Oct 13 19:30 LINUC_MEDIA -> ../../sr0
lrwxrwxrwx 1 root root 10 Oct 13 19:33 ROOT -> ../../vdb4
lrwxrwxrwx 1 root root  9 Oct 13 19:35 STICK_A -> ../../sdc
lrwxrwxrwx 1 root root  9 Oct 13 19:35 STICK_B -> ../../sdb
lrwxrwxrwx 1 root root 10 Oct 13 19:33 SWAP -> ../../vdb3
lrwxrwxrwx 1 root root 11 Oct 13 19:30 UEFI -> ../../vda15
lrwxrwxrwx 1 root root 10 Oct 13 19:33 VAR -> ../../vdb5
lrwxrwxrwx 1 root root 10 Oct 13 19:30 cloudimg-rootfs -> ../../vda1
$ sudo mount LABEL=STICK_A /media/stick
$ cat /media/stick/who.txt
これは A
$ sudo umount /media/stick

findfs は、ラベルや UUID から「いまどの装置か」を引く（findfs UUID=… も使える）。LABEL=STICK_A と書けば、何番目に挿しても A を指せる。UUID（VFAT では作った時刻から作る短い番号）も同じように使える。

たとえ: 駐車場の何番目に停めたかと、車のナンバープレートに近い。「3番目の車」は来た順で変わるが、ナンバーは車に付いている。
ただし崩れる点: ナンバーは役所が重ならないように配るが、ラベルは人が付ける名前なので重なりうる。次の節で、この練習機に実際に重なったラベルがあった。

ラベルは重なる。UUID は重ならない（ふつうは）

この節で分かること: ラベルで指すときの落とし穴と、ラベルの付け替え方。

さっきの /dev/disk/by-label/ に BOOT -> ../../vdb2 とあった。第6章で、新しいサーバの /boot のつもりで vdb2 に BOOT と付けたものである。ところが練習機自身の /etc/fstab も、/boot を LABEL=BOOT で探している（第4章）。/etc/fstab を検査する findmnt --verify を打ち、ラベルの持ち主を blkid で探す。

$ sudo findmnt --verify
/boot
   [W] ext4 does not match with on-disk ext3

0 parse errors, 0 errors, 1 warning
$ sudo blkid -t LABEL=BOOT
/dev/vda16: LABEL="BOOT" UUID="a5eecc38-8587-4601-9295-c92dabc20612" BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="ce13a6f1-b3f2-4c7a-b3db-6d75505ad739"
/dev/vdb2: LABEL="BOOT" UUID="22d4f1ec-1bd3-4377-90e8-ffb5f3da688b" SEC_TYPE="ext2" BLOCK_SIZE="4096" TYPE="ext3" PARTLABEL="Linux filesystem" PARTUUID="8992bca9-9950-4342-bea4-d4f42e92998f"
$ sudo blkid -L BOOT
/dev/vdb2

findmnt --verify が注意したのは「/boot の行は ext4 と書いてあるのに、指した先のディスクの上は ext3」という種類の食い違いで、ラベルが重なっていることそのものは言っていない（たまたま種類が違ったので気づけた）。重なりを確かめるのは blkid -t LABEL=… か /dev/disk/by-label/ である。BOOT というラベルが2つあり、LABEL=BOOT は新しい vdb2（ext3）のほうを指していた。いまの /boot は起動のときにマウントしたものなので無事だが、次に再起動したら、練習機の /boot に空の ext3 がマウントされたかもしれない。著者は第8章を書くまで気づかなかった。ラベルを付け替える。ext 系は e2label（tune2fs -L でも同じ）、XFS は xfs_admin -L（-l で読む）である。

$ sudo e2label /dev/vdb2 NEWBOOT
$ sudo e2label /dev/vdb2
NEWBOOT
$ sudo xfs_admin -l /dev/vdb4
label = "ROOT"
$ sudo findmnt --verify
Success, no errors or warnings detected
指し方例変わるときこの章の記録
デバイス名/dev/sdb挿す順番・ディスクの増減で変わるA のつもりが B だった
ラベルLABEL=STICK_A人が付け替えたとき。重なりうるBOOT が2つ重なった
UUIDUUID=…mkfs し直したとき。ディスクを丸ごと複製すると重なるmkfs のたびに違う値
たとえ: 手書きの名札とマイナンバーに近い。名札は読みやすく付け替えも簡単だが、同じ名前の人がいれば取り違える。番号は覚えにくいが重ならない。
ただし崩れる点: マイナンバーは役所が重ならないように管理するが、UUID は mkfs が乱数（VFAT では作った時刻）で決めるだけである。ディスクを dd で丸ごと写すと、同じ UUID が2つになる。そのときは tune2fs -U などで振り直す。

/etc/fstab の6列

この節で分かること: 起動時のマウントの書き方と、書いたあとの確かめ方。
$ cat /etc/fstab
LABEL=cloudimg-rootfs	/	 ext4	discard,commit=30,errors=remount-ro	0 1
LABEL=BOOT	/boot	ext4	defaults	0 2
LABEL=UEFI	/boot/efi	vfat	umask=0077	0 1
UUID=d6988a49-5d82-4426-978f-377b5dce03f2  none  swap  sw  0  0

何を           どこに  種類   オプション  │   └ 起動時に fsck する順番（勧めは / が 1、ほかは 2。調べないなら 0）
（デバイス・                              └ dump でバックアップするか（0 = しない）

fsck の順番は、fstab(5) が「/ は 1、ほかは 2」を勧めているが、決まりではない。練習機の /boot/efi の行は 0 1 になっていて、これは Ubuntu の雛形がこう書いているものである。第7章のスワップの行も入っている。vdb6（HOME）を /srv/home に、UUID で書き足す。nofail は「見つからなくても起動を止めない」。付けないと、ディスクが無いときに起動が止まる。

$ echo "UUID=$(sudo blkid -s UUID -o value /dev/vdb6)  /srv/home  ext4  defaults,nofail  0  2" | sudo tee -a /etc/fstab
UUID=76a62184-3385-4cff-ad77-c76946332553  /srv/home  ext4  defaults,nofail  0  2
$ sudo mkdir -p /srv/home
$ sudo mount -a
mount: (hint) your fstab has been modified, but systemd still uses
       the old version; use 'systemctl daemon-reload' to reload.
$ findmnt -o TARGET,SOURCE,FSTYPE /srv/home
TARGET    SOURCE    FSTYPE
/srv/home /dev/vdb6 ext4
$ sudo systemctl daemon-reload

mount -a は「/etc/fstab のうち、まだマウントされていない行を全部マウントする」（noauto の行は除く）で、起動のときにも同じことが起きる。書いたら再起動の前に mount -a と findmnt --verify で確かめる。

そして mount が (hint) を出した。「/etc/fstab は書き換えられたが、systemd はまだ古い版を使っている」。起動時のマウントは、/etc/fstab そのものではなく、systemd がそこから作ったマウントの設定（ユニット）で行われる。systemd は起動のたびに /etc/fstab からこの設定を作り直すので、次の起動には書いただけで効く。困るのは、いま動いている systemd が古い表のままでいることで、systemd を通した操作（systemctl でのマウントなど）が書き換える前の表で動く。いま動いている systemd に作り直させるのが systemctl daemon-reload である。mount コマンド自身は毎回 /etc/fstab を読むので、いまのマウントには困らない。

マウントしたまま、オプションを変えることもできる（remount）。

$ sudo mount -o remount,ro /srv/home
$ sudo touch /srv/home/test
touch: cannot touch '/srv/home/test': Read-only file system
$ sudo mount -o remount,rw /srv/home
$ sudo touch /srv/home/test

一般ユーザが、取り外せるメディアをマウントする

この節で分かること: /media と、user・noauto の役目。

/media は、取り外せるメディア（CD・USB メモリ）をマウントする場所として決められたディレクトリである（/mnt は一時的に手でつなぐ場所）。デスクトップの Linux では、挿すと udisks2 が自動でマウントする（第2章の D-Bus の話。マウント先は Ubuntu・Debian では /media/<ユーザ>/<ラベル>、RHEL 系と udisks2 の既定では /run/media/<ユーザ>/<ラベル>）。練習機には udisks2 が無いので、/etc/fstab で許す。まず一般ユーザのまま打つ。

$ mount /media/cdrom
mount: /media/cdrom: can't find in /etc/fstab.

一般ユーザの mount は、/etc/fstab に書かれた行のうち、許された行しか通らない。光学ドライブの行を書く。

$ sudo mkdir -p /media/cdrom
$ echo "/dev/sr0  /media/cdrom  iso9660  ro,user,noauto  0  0" | sudo tee -a /etc/fstab
/dev/sr0  /media/cdrom  iso9660  ro,user,noauto  0  0
$ sudo systemctl daemon-reload
$ mount /media/cdrom
$ mount | grep /media/cdrom
/dev/sr0 on /media/cdrom type iso9660 (ro,nosuid,nodev,noexec,relatime,nojoliet,check=s,map=n,blocksize=2048,iocharset=utf8,user=student)
$ lsmod | grep isofs
isofs                  61440  1
$ ls -l /media/cdrom
total 1
-r--r--r-- 1 root root 227 Oct 13 09:00 README.TXT
$ umount /media/cdrom

student のまま、マウントも外すこともできた。mount の表示に、書いていない nosuid,nodev,noexec と、誰がマウントしたか（user=student）が出ている。user を付けると、他人のメディアで権限を奪われないよう、この3つが自動で付く。noauto は「起動時と mount -a ではマウントしない」で、メディアが入っていないかもしれない装置に付ける。

光学メディアの中身をファイル（ISO イメージ）に写したものも、そのままマウントできる。ファイルを装置に見せかけるループデバイス（第1章で見た loop0〜）を使うので、オプションは -o loop である。

$ sudo dd if=/dev/sr0 of=media.iso
736+0 records in
736+0 records out
376832 bytes (377 kB, 368 KiB) copied, 0.0204182 s, 18.5 MB/s
$ sudo mount -o loop media.iso /mnt
mount: /mnt: WARNING: source write-protected, mounted read-only.
$ findmnt -o TARGET,SOURCE,FSTYPE /mnt
TARGET
     SOURCE     FSTYPE
/mnt /dev/loop0 iso9660
$ losetup -l
NAME       SIZELIMIT OFFSET AUTOCLEAR RO BACK-FILE               DIO LOG-SEC
/dev/loop0         0      0         1  0 /home/student/media.iso   0     512
$ ls /mnt
README.TXT
$ sudo umount /mnt
$ sudo mount media.iso /mnt
mount: /mnt: WARNING: source write-protected, mounted read-only.
$ findmnt -o TARGET,SOURCE,FSTYPE /mnt
TARGET
     SOURCE     FSTYPE
/mnt /dev/loop0 iso9660
$ sudo umount /mnt
$ losetup -l
$ sudo rm media.iso

SOURCE が /dev/loop0 になっている。losetup -l で、どのファイルがどのループデバイスにつながっているかが見える。いまの mount は、ふつうのファイルを渡されると自分でループデバイスを用意するので、-o loop を省いてもマウントできた。外すと、ループデバイスも一緒に片づく（AUTOCLEAR が 1。外したあとの losetup -l は空）。どちらも WARNING が出たのは、ループデバイスは書き込める（RO が 0）のに、中の iso9660 が書き込みのマウントを受け付けず、mount が読み取り専用でやり直したからである。

FAT の USB メモリでも同じことをする。VFAT はファイルに所有者を持たないので、誰がマウントしたかで見え方が変わる。

$ echo "LABEL=STICK_A  /media/stick  vfat  user,noauto  0  0" | sudo tee -a /etc/fstab
LABEL=STICK_A  /media/stick  vfat  user,noauto  0  0
$ sudo systemctl daemon-reload
$ mount /media/stick
$ ls -l /media/stick
total 2
-rwxrwxr-x 1 student student 12 Oct 13 19:35 who.txt
$ touch /media/stick/mine.txt
$ umount /media/stick
$ sudo mount /media/stick
$ ls -l /media/stick
total 2
-rwxr-xr-x 1 root root  0 Oct 13 19:37 mine.txt
-rwxr-xr-x 1 root root 12 Oct 13 19:35 who.txt
$ sudo umount /media/stick
$ sudo findmnt --verify
Success, no errors or warnings detected

student がマウントすると、ファイルはすべて student のものに見え、書き込めた。root がマウントすると root のものに見える。VFAT の所有者とパーミッションは、ディスクには無く、マウントしたときに決まる（uid=・umask= などのオプションでも決められる。練習機の /boot/efi の umask=0077 がそれで、第4章で student が中を読めなかった理由である）。

オプション意味
defaultsrw・suid・dev・exec・auto・nouser・async をまとめた既定
noauto起動時と mount -a ではマウントしない
user一般ユーザがマウントできる。外せるのはマウントした本人（と root）。nosuid・nodev・noexec が付く（後ろに exec などを書けば打ち消せる）
users一般ユーザがマウントでき、誰でも外せる。user と同じく nosuid・nodev・noexec が付く
noexecその中のプログラムを実行させない（exec で許す）
nosuid / nodevその中の set-user-ID を効かせない / その中のデバイスファイルを使わせない
nofail見つからなくても起動を止めない
ro / rw読み取り専用 / 読み書き
swスワップの行に書く慣習の値
手を動かす: 実践編の演習08は、student が /media/cdrom を自分でマウント・アンマウントできるようにする課題である。 判定は student として実際に mount と umount を打って確かめる。

8章を貫いている1つの事実

この節で分かること: 8つの「予想が外れたこと」が、同じ1つのことから出ていたこと。

このコースで外れた予想を並べる。どれも、ディスクの上に重なった層のうち1つだけを見て、隣の層も一緒に動くと思ったところで外れている。

章外れた予想実際に読んでいた印動かなかった隣の層
1HDD か SSD かはカーネルが測る装置の申告（rotational）中身のファイルは同じ種類
2ドライバを外せば装置は使えない装置の種類（modalias）と udev の表次に挿せば、表どおりに読み込まれる
3パーティションを消せば中身も消える表の1行（開始位置と大きさ）ext4 の中身はそのまま
4ESP はマウントしないと起動に使えないNVRAM の候補（PARTUUID とファイルのパス）マウント（/etc/fstab）も、種類の印も、起動には関わらなかった
5LV を広げれば使える量も増えるext4 が自分で書いた大きさ箱が広がっても中身はそのまま
6Size − Used が使える量ext4 の予約ブロック（と自分用の取り置き）区画の大きさ ≠ 使える量
7tmpfs の size だけメモリを取る書いた量size は上限で、確保ではない
8/dev/sdb はいつも同じディスク中に書いた UUID・ラベル名前は見つかった順で付く

ディスクは、装置・パーティション表・LVM・ファイルシステム・マウントの層が重なってできている。各層は自分の印（装置の申告・表の行・UUID）だけを読み、隣の層を勝手には書き換えない。だから1つの層を変えたら、隣の層は自分で合わせる。名前や見かけの大きさは、どの層から見たかで変わる。

試験の問題も、この層のどこを尋ねているかで解ける。「パーティションを広げたのにファイルシステムが…」なら層をまたいでいないか、「起動時にマウントされない」なら /etc/fstab の層か、を先に考える。

確認

次の /etc/fstab の行の、各列の意味を答えよ。
UUID=1b2c3d4e-… /srv/home ext4 defaults,nofail 0 2

答え

UUID がこの値のファイルシステムを、/srv/home に、ext4 として、既定のオプションで（見つからなくても起動を止めずに）マウントする。dump はしない（0）。起動時の fsck は 2 番目のグループ（/ の後）で行う。

確認

一般ユーザが CD-ROM を読み取り専用でマウントでき、マウントしたユーザ以外も外せるようにしたい。起動時にはマウントしない。オプションの欄に何を書くか。

答え

ro,users,noauto（読み取り専用・誰でもマウントと取り外しができる・起動時にマウントしない）。users は nosuid・nodev・noexec も一緒に付ける。user なら、外せるのはマウントした本人と root だけになる。

確認

umount /data が target is busy で失敗した。何が考えられるか。

答え

そのファイルシステムの中で、ファイルを開いているプロセスか、カレントディレクトリがその中にあるプロセス（自分のシェルを含む）がいる。cd で外に出るか、fuser -m /data・lsof /data で使っているプロセスを探す。

確認

/etc/fstab にディスクの行を書き足した。再起動の前にしておくとよいことを2つ挙げよ。

答え

findmnt --verify で書き間違い（見つからない UUID やラベル・種類の食い違いなど）を調べることと、mount -a で実際にマウントできるかを試すこと。ラベルの重なりは findmnt --verify では出ないので、blkid -t LABEL=… で確かめる。いま動いている systemd には systemctl daemon-reload で読み直させる（次の起動では、書いただけで効く）。消えるかもしれないディスクの行には nofail を付ける。

この章で分かったこと

持ち帰ってほしいこと

  • マウントポイントは前もって作るただのディレクトリで、もとの中身は隠れるだけ。中にプロセスがいると umount は断る
  • /dev/sdb は見つかった順に付く名前で、挿す順番で別のディスクを指す。/etc/fstab では UUID かラベルで指す（blkid・/dev/disk/by-uuid/・by-label/）
  • ラベルは重なりうる。重なると LABEL= の行が別のディスクを指す。findmnt --verify は重なりそのものは言わない（今回は種類の食い違いで気づいた）。重なりは blkid -t LABEL=…・/dev/disk/by-label/ で確かめ、e2label・xfs_admin -L で付け替える。findfs はラベルや UUID から装置の名前を引く
  • /etc/fstab は6列（何を・どこに・種類・オプション・dump・fsck の順番）。書いたら mount -a と findmnt --verify で確かめる。次の起動には書いただけで効き、いま動いている systemd には daemon-reload で読み直させる
  • 一般ユーザに許すのは user（本人が外せる）・users（誰でも外せる）で、どちらも nosuid・nodev・noexec を付ける。取り外せるメディアには noauto（起動時と mount -a で飛ばす）。マウント先は /media の下。ISO のファイルは -o loop（いまの mount は省いても自分で使う）
