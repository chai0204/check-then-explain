6. ファイルシステムは、作った大きさより小さく見える

390MiB の区画に ext4 を作ると、df の Size は 350M になる。さらに Size から Used を引いても、Avail（使える量）と合わない。ext4 は root のために 5% を取っておき、一般ユーザにはそのぶんを見せないからだ。ファイルシステムは、区画の中にさらに自分の管理情報と取り置きを置く。

前提: 第5章まで読了前提: 演習04 の切り方になっている所要 22分影響度 B出題範囲 1.05.3（重要度4）最終検証 2026-10-13

この章のゴール

  • mkfs で ext3・ext4・XFS・VFAT・Btrfs を作り分けられる（mkfs -t 種類 と mkfs.種類 の関係も）
  • df の Size・Used・Avail の関係を説明でき、ext4 の予約ブロックを tune2fs で読んで変えられる
  • ext3 と ext4 の違い、XFS・VFAT・Btrfs の特徴を言える。fsck がファイルシステムの種類ごとに別物であることを知っている
ここで覚えなくていいこと: ジャーナルや inode の内部の形、mkfs の細かいオプション（ブロックの大きさ -b、inode の数 -N など）、Btrfs のサブボリュームを操作するコマンドは扱わない。tmpfs とスワップは第7章で扱う。

mkfs は、種類ごとの道具を呼ぶ入口

この節で分かること: 5種類のファイルシステムの作り方と、作ったときに何が書かれるか。

第4章で切った vdb の区画に、ファイルシステムを作っていく。mkfs は入口で、実際の仕事は種類ごとの道具（mkfs.ext4 など）がする。mkfs -t ext4 と mkfs.ext4 は同じものを呼ぶ。

$ ls /sbin/mkfs*
/sbin/mkfs        /sbin/mkfs.cramfs  /sbin/mkfs.ext4   /sbin/mkfs.msdos
/sbin/mkfs.bfs    /sbin/mkfs.ext2    /sbin/mkfs.fat    /sbin/mkfs.vfat
/sbin/mkfs.btrfs  /sbin/mkfs.ext3    /sbin/mkfs.minix  /sbin/mkfs.xfs

ESP（vdb1）から始める。第4章で見たとおり、ここには第3章の ext4 の印が残っている。wipefs（引数だけなら消さずに一覧を出す）で見てから、FAT32 を作る。

$ sudo wipefs /dev/vdb1

vdb1   0x438  ext4 a8de5231-01ff-4280-9c3c-ee8a1fc7c48f   ← 第3章の ext4 の印（場所 0x438 = 1080 バイト目）
$ sudo mkfs.vfat -F 32 -n ESP /dev/vdb1
mkfs.fat 4.2 (2021-01-31)
$ sudo wipefs /dev/vdb1

vdb1   0x52   vfat B4B6-B341 ESP
vdb1   0x0    vfat B4B6-B341 ESP
vdb1   0x1fe  vfat B4B6-B341 ESP

どれも、作ったときに UUID（乱数の番号）を決めて中に書き込んでいる。UUID は作るたびに変わるので、あなたの画面では違う値になる。ext3 と ext4 の出力の Superblock backups stored on blocks は、管理情報（スーパーブロック）の写しをディスクの途中にも置いたという意味で、先頭が壊れたときに e2fsck -b で使う。mkfs.btrfs の SSD detected: no は、第1章の rotational を読んだ結果である（演習01 で vdb を SSD 扱いにした練習機では、同じ行が yes になった）。

たとえ: 区画が空き地なら、mkfs は倉庫を建てる作業に近い。棚の配置図（管理情報）と番地（UUID）と看板（ラベル）を書いた時点で、空き地は「倉庫の形式」を持つ。建て方（ext4・XFS・…）で棚の並べ方が違う。
ただし崩れる点: 倉庫を建て替えれば古い荷物は壊れるとすぐ分かるが、mkfs は前に何があったかを聞かずに上書きすることがある（mkfs.vfat は何も聞かなかった）。mkfs は「中身を消す」操作だと覚えておく。

大きさを比べる

この節で分かること: df の3つの数の関係と、ext4 の予約。

ふつうこう考える

vdb6 は 390MiB の区画である。そこに作った ext4 なら、使える量はほぼ 390MiB だろう。 少なくとも、df の Size から Used を引いた残りが、Avail（使える量）になるはずだ。

$ sudo mount /dev/vdb6 /mnt
$ df -h /mnt
Filesystem      Size  Used Avail Use% Mounted on
/dev/vdb6       350M   24K  323M   1% /mnt
$ df -m /mnt
Filesystem     1M-blocks  Used Available Use% Mounted on
/dev/vdb6            350     1       323   1% /mnt   ← 350 − 1 = 349 のはずが 323
だめな理由: Size が 390 より小さく、さらに Size − Used と Avail が 26MiB 合わない。 Size が小さいのは、ext4 が区画の中に管理情報（inode の表やジャーナル）を置いているから。 26MiB 合わないのは、ext4 がroot のために 5% を取っておく（予約ブロック）からである。 ディスクがいっぱいになっても root とデーモンが書けるように、一般ユーザにはそのぶんを Avail に見せない。

予約の量は ext4 の管理情報に書いてあり、tune2fs -l で読める。tune2fs -m で割合を変えられる（作り直す必要は無く、マウントしたままでよい）。

$ sudo tune2fs -l /dev/vdb6 | grep -E "^(Block count|Reserved block count|Block size|Reserved blocks uid)"
Block count:              99840
Reserved block count:     4909
Block size:               4096
Reserved blocks uid:      0 (user root)
$ sudo tune2fs -m 1 /dev/vdb6
tune2fs 1.47.0 (5-Feb-2023)
Setting reserved blocks percentage to 1% (998 blocks)
$ df -m /mnt
Filesystem     1M-blocks  Used Available Use% Mounted on
/dev/vdb6            350     1       338   1% /mnt
$ sudo umount /mnt

4909 ブロック × 4KiB ≈ 19MiB が予約されていた。1% にすると Avail が 15MiB 増えた。データだけを置く区画なら予約を減らしてよいが、/ や /var では残しておく。

5つのファイルシステムを、1つずつマウントして比べる（区画の大きさは 100・300・600・400・390MiB）。

$ for p in 1 2 4 5 6; do sudo mount /dev/vdb$p /mnt && df -h --output=source,fstype,size,used,avail /mnt | tail -1; sudo umount /mnt; done
/dev/vdb1      vfat   99M   512   99M
/dev/vdb2      ext3  266M   44K  251M
/dev/vdb4      xfs   536M   41M  496M
/dev/vdb5      btrfs  400M  5.8M  319M
/dev/vdb6      ext4  350M   24K  338M

VFAT は管理情報が小さく、ほぼ区画の大きさのまま使える。XFS は作った直後から 41M を Used に数える（ジャーナルなどの管理情報を Used として見せる）。Btrfs は管理情報を2重に持つ（Metadata: DUP）ぶん、Avail が少ない。同じ大きさの区画でも、使える量はファイルシステムの種類で変わる。

たとえ: 満員電車の乗務員用の扉に近い。乗客で埋まっても、乗務員が通る隙間だけは空けておく。乗客から見れば、その隙間は「無い」のと同じである。
ただし崩れる点: 扉は目に見えるが、予約ブロックは df の Size にも Used にも出ない。Avail が減っていることでしか見えない。
手を動かす: 実践編の演習06は、5種類のファイルシステムを作り、vdb6 の予約を 1% にする課題である。 判定は各区画の先頭の印と、ext4 の管理情報を直接読んで確かめる。

ext3 と ext4 の違いは、機能の旗

この節で分かること: 試験に出る5種類のファイルシステムの特徴。

ext2・ext3・ext4 は同じ系統で、違いは使える機能である。dumpe2fs -h（管理情報の見出し）で比べる。

$ sudo dumpe2fs -h /dev/vdb2 2>/dev/null | grep -i features
Filesystem features:      has_journal ext_attr resize_inode dir_index filetype sparse_super large_file
Journal features:         (none)
$ sudo dumpe2fs -h /dev/vdb6 2>/dev/null | grep -i features
Filesystem features:      has_journal ext_attr resize_inode dir_index filetype extent 64bit flex_bg sparse_super large_file huge_file dir_nlink extra_isize metadata_csum
Journal features:         journal_64bit journal_checksum_v3

どちらも has_journal（ジャーナル）を持つ。ext2 にジャーナルを足したものが ext3 で、ext4 はさらに extent（大きなファイルを連続した範囲で管理する）・64bit・flex_bg・metadata_csum（管理情報の検査値）などを足している。

種類作るコマンド特徴この章の記録で見えたこと
ext3mkfs -t ext3（mke2fs -j）ext2 ＋ ジャーナル。古い /boot などで使われたfeatures に extent が無い
ext4mkfs.ext4ext3 の後継。extent・大きな容量。縮小もできる（外してから）。Ubuntu の既定root 用の予約 5%（tune2fs -m で変更）
XFSmkfs.xfs大きなファイル・並列の書き込みに強い。RHEL の既定。縮小できない。調べるのは xfs_repair作った直後から 41M を Used に数える
VFATmkfs.vfat（-F 32 で FAT32）Windows・カメラ・ESP と共通。所有者とパーミッションを持たない（第8章）。FAT32 は 1ファイル 4GiB まで管理情報が小さく、ほぼ区画の大きさで使える
Btrfsmkfs.btrfs書き込みのたびに別の場所へ書く（コピーオンライト）。スナップショット・サブボリューム・検査値を持つ管理情報を2重（DUP）に持つ

fsck は、種類ごとに別のもの

この節で分かること: ファイルシステムの検査の道具と、その注意。

fsck も入口で、種類ごとの道具（fsck.ext4 = e2fsck など）を呼ぶ。検査はマウントを外した状態で行う。

$ sudo fsck /dev/vdb6
fsck from util-linux 2.39.3
e2fsck 1.47.0 (5-Feb-2023)
HOME: clean, 11/99840 files, 10500/99840 blocks
$ sudo fsck -f /dev/vdb6
fsck from util-linux 2.39.3
e2fsck 1.47.0 (5-Feb-2023)
Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
HOME: 11/99840 files (0.0% non-contiguous), 10500/99840 blocks

ext4 は「きれいに外された」印を持っているので、ふつうは clean とだけ答えて中を見ない。-f で強制すると、5段階（Pass 1〜5）の検査が走る。XFS と Btrfs で同じことをする。

$ sudo fsck /dev/vdb4
fsck from util-linux 2.39.3
If you wish to check the consistency of an XFS filesystem or
repair a damaged filesystem, see xfs_repair(8).
$ sudo xfs_repair -n /dev/vdb4 2>&1 | tail -3
        - moving disconnected inodes to lost+found ...
Phase 7 - verify link counts...
No modify flag set, skipping filesystem flush and exiting.
$ sudo fsck /dev/vdb5
fsck from util-linux 2.39.3
If you wish to check the consistency of a BTRFS filesystem or
repair a damaged filesystem, see btrfs(8) subcommand 'check'.

XFS と Btrfs の fsck は、何もしないで成功を返す。案内を1行出すだけである。調べるには、それぞれの道具（xfs_repair、btrfs check）を使う。xfs_repair -n の -n は「直さずに調べるだけ」。

種類fsck を打つと実際に調べる道具
ext2/3/4e2fsck が走るe2fsck（fsck.ext4）。-f で強制、-b で写しのスーパーブロックから
XFS案内を出して終わるxfs_repair（-n で調べるだけ）
Btrfs案内を出して終わるbtrfs check
VFATfsck.fat が走るfsck.fat（dosfstools）
たとえ: 病院の総合受付に近い。fsck は受付で、症状（ファイルシステムの種類）を見て診療科（e2fsck など）に回す。
ただし崩れる点: 病院の受付は回せる科が無ければ断るが、fsck は XFS や Btrfs を「どうぞお帰りください」と案内して、成功を返してしまう。終了コードだけを見るスクリプトは、検査したと思い込む。
確認

mkfs -t ext4 /dev/sdb1 と同じ意味になるコマンドを2つ挙げよ。

答え

mkfs.ext4 /dev/sdb1 と mke2fs -t ext4 /dev/sdb1。mkfs は入口で、-t で指定した種類の道具（/sbin/mkfs.ext4）を呼ぶ。ext3 なら mkfs -t ext3・mkfs.ext3・mke2fs -j。

確認

ext4 の df で、Size − Used より Avail が小さい。何が原因か。データ専用の区画で、その差を無くすコマンドは何か。

答え

root のための予約ブロック（既定で 5%）。一般ユーザに見せる Avail からは除かれる。tune2fs -m 0 /dev/… で無くせる（実測では -m 1 で 1% にした）。数は tune2fs -l の Reserved block count で読める。

確認

XFS の区画に fsck を打ったら、案内が出て終了コード 0 で終わった。この区画を検査するにはどうするか。

答え

xfs_repair を使う（マウントを外して。直さずに調べるだけなら -n）。fsck.xfs は何もしない道具で、XFS は自分の検査をマウントのときのジャーナルで済ませる設計になっている。

この章で分かったこと

持ち帰ってほしいこと

  • mkfs は入口で、mkfs -t 種類 = mkfs.種類。作ると UUID が決まり、ラベルは -L（VFAT は -n）で付ける
  • ファイルシステムは区画の中に管理情報を置くので、df の Size は区画より小さい。どれだけ小さいかは種類で違う
  • ext4 は root 用に 5% を予約する。Avail はそのぶん小さい。tune2fs -l で読み、tune2fs -m で変える
  • ext3 = ext2 ＋ ジャーナル、ext4 は extent などを足した後継。XFS は縮小できず、Btrfs はコピーオンライトでスナップショットを持ち、VFAT は所有者とパーミッションを持たない
  • fsck も入口。ext 系は e2fsck が走るが、XFS と Btrfs は何もせずに成功を返す。調べるのは xfs_repair・btrfs check
