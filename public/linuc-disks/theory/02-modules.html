2. ドライバは、外しても戻ってくる

USB メモリのドライバを外すと、ディスクは消える。ところが抜いて挿し直すと、誰も modprobe していないのにドライバが戻ってくる。読み込んでいるのは udev で、止めるには udev が読む表を書き換える。しかも、書いただけでは効かなかった。

前提: 第1章まで読了前提: 練習機が起動している所要 22分影響度 B出題範囲 1.05.1（重要度3）最終検証 2026-10-13

この章のゴール

  • lsmod・modinfo・modprobe・insmod・rmmod の役割を言い分けられる
  • 組み込みの周辺機器を、ドライバを外して使えなくし、また使えるようにできる
  • USB メモリを挿したとき、カーネル・udev・modprobe の誰が何をするかを順に言える
ここで覚えなくていいこと: モジュールに渡すパラメータ（options 行）、udev の規則の文法の全体、D-Bus のメッセージの形、depmod が作る索引ファイルの中身は扱わない。udev の規則は演習01 で1行だけ書く。

読み込まれているドライバを数える

この節で分かること: カーネルの部品のうち、後から読み込まれたものと、最初から組み込まれているもの。

Linux のドライバの多くはカーネルモジュールという部品の形で配られていて、必要になったときに読み込まれる。いま読み込まれているものは lsmod で見る（中身は /proc/modules を整えて表示したもの）。

$ lsmod | head -5
Module                  Size  Used by
isofs                  61440  0   ← 第1章で CD をマウントしたときに読み込まれた
kvm_amd               212992  0
ccp                   147456  1 kvm_amd
kvm                  1404928  1 kvm_amd
$ lsmod | wc -l
33

見出しを除いて 32 個しかない。第1章で使った ext4 も vfat も光学ドライブのドライバも見当たらない。それらは最初からカーネルに組み込まれているからで、組み込みの一覧は別のファイルにある。

$ grep -E "/(vfat|ext4|sr_mod)\.ko" /lib/modules/$(uname -r)/modules.builtin
kernel/fs/ext4/ext4.ko
kernel/fs/fat/vfat.ko
kernel/drivers/scsi/sr_mod.ko

組み込みの部品は lsmod に出ず、外すこともできない。逆に isofs（CD のファイルシステム）は、第1章で mount /dev/sr0 を打った瞬間にカーネルが自分で読み込んだ。誰も modprobe していない。

組み込みの周辺機器を、ドライバで止める

この節で分かること: 「装置がある」と「使える」が別の層であること。

SATA のコントローラ（第1章の 00:1f.2）には ahci というドライバが付いている。外してみる。

$ lspci -k -s 00:1f.2
00:1f.2 SATA controller: Intel Corporation 82801IR/IO/IH (ICH9R/DO/DH) 6 port SATA Controller [AHCI mode] (rev 02)
	Subsystem: Red Hat, Inc. QEMU Virtual Machine
	Kernel driver in use: ahci
	Kernel modules: ahci
$ lsmod | grep ahci
ahci                   49152  0
libahci                53248  1 ahci
$ sudo modprobe -r ahci
$ lsblk -d -o NAME,TRAN,SIZE
NAME
    TRAN    SIZE
vda virtio   20G
vdb virtio    2G
vdc virtio    1G
vdd virtio  256M
$ lspci -k -s 00:1f.2
00:1f.2 SATA controller: Intel Corporation 82801IR/IO/IH (ICH9R/DO/DH) 6 port SATA Controller [AHCI mode] (rev 02)
	Subsystem: Red Hat, Inc. QEMU Virtual Machine
	Kernel modules: ahci

SATA につながっていた sda と sr0 が消えた。ところが lspci にはコントローラが残っていて、消えたのは Kernel driver in use: ahci の1行だけである。装置は PCI バスの上にいる。使う人（ドライバ）がいなくなっただけ。読み込み直せば戻る。

$ sudo modprobe ahci
$ lsblk -d -o NAME,TRAN,SIZE
NAME
    TRAN    SIZE
sda sata      1G
sr0 sata    368K
vda virtio   20G
vdb virtio    2G
vdc virtio    1G
vdd virtio  256M
止め方lspci に出るか戻し方
ドライバを外す（modprobe -r / rmmod）出る（ドライバの行だけ消える）modprobe で読み込む。再起動しても戻る
読み込ませない設定（/etc/modprobe.d/。この章の後半）出る設定を消す
BIOS / UEFI の設定で止める出ない（ファームウェアがバスから隠す）ファームウェアの設定画面で戻す
たとえ: 部屋に置かれた機械と、その担当者に近い。担当者が帰っても機械は部屋に残っている。機械の名簿（lspci）には載ったままで、動かせる人がいないだけである。
ただし崩れる点: 人なら呼べば戻ってくるとは限らないが、ドライバは modprobe ですぐ戻る。しかも、呼ばなくても戻ってくることがある（次の節）。

insmod は、依存を解決しない

この節で分かること: 同じ「読み込む」でも insmod と modprobe で何が違うか。

btrfs（第6章で使うファイルシステム）のモジュールは、ほかのモジュールに依存している。modinfo で見る。

$ modinfo -F depends btrfs
raid6_pq,xor,libcrc32c
$ sudo insmod /lib/modules/$(uname -r)/kernel/fs/btrfs/btrfs.ko.zst
insmod: ERROR: could not insert module /lib/modules/6.8.0-142-generic/kernel/fs/btrfs/btrfs.ko.zst: Unknown symbol in module
$ sudo dmesg | tail -4
[  113.758486] btrfs: Unknown symbol xor_blocks (err -2)
[  113.759027] btrfs: Unknown symbol raid6_2data_recov (err -2)
[  113.760922] btrfs: Unknown symbol crc32c (err -2)
[  113.760989] btrfs: Unknown symbol raid6_call (err -2)

insmod は、渡されたファイルを1つ読み込むだけである。btrfs が使う関数（xor_blocks など）を持つモジュールがまだ無いので、Unknown symbol in module で失敗した。modprobe は依存を先に読み込む。-v で何をしたかが出る。

$ sudo modprobe -v btrfs
insmod /lib/modules/6.8.0-142-generic/kernel/lib/libcrc32c.ko.zst 
insmod /lib/modules/6.8.0-142-generic/kernel/lib/raid6/raid6_pq.ko.zst 
insmod /lib/modules/6.8.0-142-generic/kernel/crypto/xor.ko.zst 
insmod /lib/modules/6.8.0-142-generic/kernel/crypto/blake2b_generic.ko.zst 
insmod /lib/modules/6.8.0-142-generic/kernel/fs/btrfs/btrfs.ko.zst 
$ lsmod | grep -E "^(btrfs|xor|raid6_pq|libcrc32c|blake2b_generic) "
btrfs                2060288  0
blake2b_generic        24576  0
xor                    20480  1 btrfs
raid6_pq              126976  1 btrfs
libcrc32c              12288  1 btrfs
$ sudo modprobe -rv btrfs
rmmod btrfs
rmmod libcrc32c
rmmod raid6_pq
rmmod xor
rmmod blake2b_generic

modprobe の中身は「依存の順に insmod を並べたもの」だった。lsmod の Used by 列には、そのモジュールを使っているモジュールが出る（xor は btrfs に使われている）。modprobe -r は、外したあとで使われなくなった依存もまとめて外す。依存の表は /lib/modules/<版>/modules.dep にあり、depmod が作る。

コマンドすること依存
lsmod読み込まれているモジュールの一覧（/proc/modules）Used by 列で見える
modinfo 名前説明・ファイルの場所・依存・別名（alias）を表示-F depends で依存だけ
modprobe 名前名前で探して読み込む解決する
modprobe -r 名前外す使われなくなった依存も外す
insmod ファイルファイルを1つ読み込む（パスで渡す）解決しない
rmmod 名前1つ外す使われていれば断る

外したドライバは、戻ってくる

この節で分かること: 「ドライバを外す」が「装置を無効にする」にならない理由。

USB メモリのドライバを外す。

$ sudo modprobe -r usb_storage
modprobe: FATAL: Module usb_storage is in use.
$ sudo rmmod usb_storage
rmmod: ERROR: Module usb_storage is in use by: uas
$ sudo modprobe -r uas
$ lsmod | grep -E "usb_storage|uas"
$ lsblk -d -o NAME,TRAN,SIZE,SERIAL
NAME
    TRAN    SIZE SERIAL
sda sata      1G LAB-SSD
sr0 sata    368K QM00003
vda virtio   20G 
vdb virtio    2G LAB-VDB
vdc virtio    1G LAB-VDC
vdd virtio  256M LAB-VDD
$ lsusb
Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub
Bus 002 Device 002: ID 46f4:0001 QEMU QEMU USB HARDDRIVE
$ lsusb -t
/:  Bus 001.Port 001: Dev 001, Class=root_hub, Driver=xhci_hcd/8p, 480M
/:  Bus 002.Port 001: Dev 001, Class=root_hub, Driver=xhci_hcd/8p, 5000M
    |__ Port 001: Dev 002, If 0, Class=Mass Storage, Driver=[none], 5000M

usb_storage は uas に使われているので、単独では外せない（in use by: uas）。uas を外すと、使われなくなった usb_storage も一緒に外れた。ディスク sdb は消え、USB の装置は lsusb に残り、Driver=[none] になった。

ふつうこう考える

ドライバを外したのだから、この USB メモリはもう使えない。 抜いて挿し直しても、誰かがもう一度 modprobe しない限りディスクにはならないはずだ。

$ virsh detach-device linuc ~/vm/extra/usb-a.xml
Device detached successfully
$ virsh attach-device linuc ~/vm/extra/usb-a.xml
Device attached successfully
$ lsmod | grep -E "usb_storage|uas"
uas                    28672  0
usb_storage            86016  1 uas
$ lsblk -d -o NAME,TRAN,SIZE,SERIAL
NAME
    TRAN    SIZE SERIAL
sda sata      1G LAB-SSD
sdb usb      64M LAB-USB-A   ← 戻ってきた
だめな理由: 2つとも戻り、sdb もできている。読み込んだのは udev である。 挿した瞬間にカーネルが知らせを出し、udev はその知らせに書かれた装置の種類（modalias）を見て、 当てはまるドライバを modprobe と同じしくみで読み込む。rmmod が止めたのは「いま」だけで、 次に装置が来たときに読み込む流れには触れていない。

その流れを確かめる。装置は自分の種類を、/sys の modalias というファイルに出している。

$ cat /sys/bus/usb/devices/2-1:1.0/modalias
usb:v46F4p0001d0000dc00dsc00dp00ic08isc06ip50in00
$ modprobe --resolve-alias $(cat /sys/bus/usb/devices/2-1:1.0/modalias)
uas
usb_storage
$ modinfo usb_storage | grep -m3 alias
alias:          usb:v*p*d*dc*dsc*dp*ic08isc06ip50in*
alias:          usb:v*p*d*dc*dsc*dp*ic08isc05ip50in*
alias:          usb:v*p*d*dc*dsc*dp*ic08isc04ip50in*
$ grep -n "kmod load" /usr/lib/udev/rules.d/80-drivers.rules | head -1
5:ENV{MODALIAS}=="?*", RUN{builtin}+="kmod load"

ic08isc06ip50 は「種類 08（大容量記憶）・サブクラス 06（SCSI 命令）・プロトコル 50（Bulk-Only）」という意味で、usb_storage の別名（alias）の1つと一致する。この別名は uas にも当てはまるので、2つとも読み込まれた。udev の規則の5行目は「MODALIAS がある装置なら、それでドライバを読み込め」と書いてある。

たとえ: 荷物の受付係に近い。届いた荷物の伝票（modalias）を読み、規則表どおりの担当（ドライバ）を呼ぶ。担当を一度帰らせても、次の荷物が来れば受付係がまた呼ぶ。
ただし崩れる点: 受付係は伝票に合う担当を1人選ぶが、udev は当てはまる担当を全員呼ぶ。だから USB メモリ1本で uas と usb_storage の2つが来た。

止めるには、読み込む側の表に書く。しかも書いただけでは効かない

この節で分かること: /etc/modprobe.d/ の書き方と、それが効く範囲。

モジュールを読み込むときの設定は /etc/modprobe.d/*.conf に置く。Ubuntu には最初からいくつかある。起動時に読み込むものを書く /etc/modules は、いまは /etc/modules-load.d/ に置き換わっている。

$ ls /etc/modprobe.d/
amd64-microcode-blacklist.conf  blacklist.conf
blacklist-ath_pci.conf          disable-algif_aead.conf
blacklist-firewire.conf         intel-microcode-blacklist.conf
blacklist-framebuffer.conf      iwlwifi.conf
blacklist-rare-network.conf
$ cat /etc/modules
# /etc/modules is obsolete and has been replaced by /etc/modules-load.d/.
# Please see modules-load.d(5) and modprobe.d(5) for details.
#
# Updating this file still works, but it is undocumented and unsupported.

教科書どおり blacklist を書いて、挿し直す。

$ echo "blacklist usb_storage" | sudo tee /etc/modprobe.d/lab-usb.conf
blacklist usb_storage
$ sudo modprobe -r uas
$ virsh detach-device linuc ~/vm/extra/usb-a.xml
Device detached successfully
$ virsh attach-device linuc ~/vm/extra/usb-a.xml
Device attached successfully
$ lsmod | grep -E "usb_storage|uas"
uas                    28672  0
usb_storage            86016  1 uas

止まらない。udev は起動したときに読んだ設定を使い続けているからである。読み直させる（練習機ごと再起動しても同じ）。

$ sudo systemctl restart systemd-udevd
$ sudo modprobe -r uas
$ virsh detach-device linuc ~/vm/extra/usb-a.xml
Device detached successfully
$ virsh attach-device linuc ~/vm/extra/usb-a.xml
Device attached successfully
$ lsmod | grep -E "usb_storage|uas"
uas                    28672  0
usb_storage            86016  1 uas
$ modprobe --show-depends uas
insmod /lib/modules/6.8.0-142-generic/kernel/drivers/usb/storage/usb-storage.ko.zst 
insmod /lib/modules/6.8.0-142-generic/kernel/drivers/usb/storage/uas.ko.zst

まだ止まらない。blacklist は「別名で探したとき、この名前を候補から外す」という意味で、外れたのは usb_storage だけである。uas は候補に残って読み込まれ、uas は usb_storage に依存しているので、依存として読み込まれた。依存には blacklist が効かない。

$ sudo systemctl restart systemd-udevd
$ sudo modprobe -r uas
$ virsh detach-device linuc ~/vm/extra/usb-a.xml

$ lsusb -t

    |__ Port 001: Dev 006, If 0, Class=Mass Storage, Driver=[none], 5000M

    TRAN    SIZE SERIAL

modprobe: ERROR: ../libkmod/libkmod-module.c:1084 command_do() Error running install command '/bin/false' for module usb_storage: retcode 1

/etc/modprobe.d に書くもの止まる範囲この記録で
（何も書かず rmmod / modprobe -r だけ）いま読み込まれている分だけ挿し直すと戻った
blacklist usb_storage別名（modalias）で探したときの候補から外す。手の modprobe と、依存としての読み込みは止まらないudev を読み直させても、uas の依存で戻った
blacklist usb_storage と blacklist uas両方を候補から外すので、依存の入口も閉じる演習02 で試せる
install usb_storage /bin/falseどの経路で読み込もうとしても失敗する止まった。手の modprobe も失敗

どれも、書いたあとで 読む側（udev）に読み直させるまで効かない。止まっているのは装置ではなく、装置が来たときにドライバを読み込む側の表である。

たとえ: 受付係の呼び出し禁止リストに近い。「usb_storage さんは呼ばない」と書いても、受付係が朝に読んだリストを使い続けていれば効かない。読み直させても、「uas さんを呼んだら、uas さんが usb_storage さんを連れてきた」なら止まらない。
ただし崩れる点: 人なら事情を話せば連れてこないが、カーネルの依存は機械的で、例外が無い。止めるなら「誰が呼んでも来られない」（install … /bin/false）にする。
手を動かす: 実践編の演習02は、ここまでの状態（挿し直しても使えない）を作る課題である。 判定は外から判定専用の USB メモリを1本挿し、ディスクになるかを見てから抜く。設定ファイルの中身は読まない。 この章のとおりに打った人は、もう達成している。第8章で USB メモリを使う前に元に戻す。

udev・sysfs・D-Bus の関係

この節で分かること: 出題範囲の「sysfs・udev・dbus の概念」を1枚にまとめる。

ここまでに出てきた登場人物を並べる。デスクトップの Linux で USB メモリを挿すと勝手にアイコンが出てマウントされるのは、この列の右端にもう2人いるからである。

カーネル ──uevent──▶ udev ──────────────▶ udisks2 ──D-Bus──▶ デスクトップの画面
  │                    │  規則を当てる          （この練習機には無い）   「開く」を押す
  │                    │  /dev/disk/by-* を作る       ▲                  │
  └─ /sys に装置を出す  └─ modprobe でドライバ        └──D-Bus でマウントを頼む┘
      （sysfs）             を読み込ませる               → /media/<ユーザ>/<ラベル>

D-Bus は、同じマシンの上のプログラム同士が問い合わせと知らせをやりとりする通り道である。udev 自身は D-Bus を使わないが、デスクトップの部品はみなここで話す。練習機でも、systemd やログインの管理が D-Bus の上で待ち受けている。

$ busctl list --no-pager | grep -E "^org\.freedesktop\.(systemd1|login1|hostname1|timedate1|network1)"
org.freedesktop.hostname1         - -               -               (activatable) -                           -       -
org.freedesktop.login1          448 systemd-logind  root            :1.3          systemd-logind.service      -       -
org.freedesktop.network1        210 systemd-network systemd-network :1.0          systemd-networkd.service    -       -
org.freedesktop.systemd1          1 systemd         root            :1.2          init.scope                  -       -
org.freedesktop.timedate1         - -               -               (activatable) -                           -       -

(activatable) は「いまは動いていないが、問い合わせが来たら起動される」という意味である。この練習機には udisks2 が無いので、USB メモリを挿しても誰もマウントしない。マウントは第8章で手でやる。

たとえ: 会社の館内放送と内線電話に近い。udev が「荷物が届いた」と知らせ、udisks2 がそれを館内放送（D-Bus）で流し、画面のプログラムが内線で「開けて」と頼む。
ただし崩れる点: 館内放送は誰でも流せるが、D-Bus は誰がどの相手に何を頼めるかが設定で決まっている。一般ユーザの画面が「マウントして」と頼めるのも、その設定が許しているからである。
確認

依存するモジュールも含めて、モジュールを読み込むコマンドは何か。insmod では何が足りないか。

答え

modprobe。insmod はファイルのパスを渡されて1つ読み込むだけで、依存を解決しない（実測では Unknown symbol in module で失敗した）。modprobe は modules.dep を見て、依存を先に読み込む。

確認

rmmod usb_storage が Module usb_storage is in use by: uas で失敗した。どこを見れば事前に分かったか。どう外せばよいか。

答え

lsmod の Used by 列（usb_storage … 1 uas）。使っている側の uas を modprobe -r uas で外すと、使われなくなった usb_storage も一緒に外れる。

確認

/etc/modprobe.d/ に blacklist usb_storage と書いたのに、USB メモリを挿すと使えた。考えられる理由を2つ挙げよ。

答え

1つ目: 設定を読む udev が、起動したときの設定を使い続けている（systemctl restart systemd-udevd か再起動が要る）。2つ目: blacklist は別名で探すときの候補から外すだけで、別のモジュール（uas）の依存として読み込まれるのは止めない。止めるなら uas も書くか、install usb_storage /bin/false にする。

確認

起動するたびに読み込みたいモジュールがある。どこに書くか。

答え

/etc/modules-load.d/ の下に .conf のファイルを置き、モジュールの名前を1行ずつ書く。古い /etc/modules もまだ読まれるが、練習機のファイル自身が「obsolete（廃止）」と書いている。

この章で分かったこと

持ち帰ってほしいこと

  • ドライバの多くはカーネルモジュールで、lsmod に出る。最初から組み込まれているもの（ext4・vfat・sr_mod）は出ず、外せない
  • ドライバを外しても装置は lspci / lsusb に残る。消えるのは「使える」ほう（ディスク sdb など）
  • insmod は依存を解決せず、modprobe は依存の順に読み込む。modprobe -r は使われなくなった依存も外す
  • 装置が来ると、カーネルの知らせ（uevent）を受けた udev が、装置の種類（modalias）に合うドライバを読み込む。だから外しても挿し直せば戻る
  • 止めるのは /etc/modprobe.d/。blacklist は別名からの読み込みだけを止め、依存は止めない。install 名前 /bin/false は全部止める。どちらも udev に読み直させるまで効かない
