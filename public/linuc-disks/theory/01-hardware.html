1. HDD か SSD かは、装置の申告で決まる

練習機には、外から見ればまったく同じ種類のファイルを5本、ディスクとしてつないである。それなのに lsblk は1本を SSD、4本を HDD として扱う。カーネルは速さを測っていない。装置が名乗ったことを、ファイルの形にして見せているだけだ。

前提: 練習機が起動している（実践編の「はじめる」）所要 18分影響度 B出題範囲 1.05.1（重要度3）最終検証 2026-10-13

この章のゴール

  • /proc・/sys・/dev がそれぞれ何を見せる窓かを言い分けられる
  • lspci と lsusb の出力から、どの装置がどのバスにつながり、どのドライバが付いているかを読める
  • HDD・SSD・光学ドライブの違いを、lsblk の ROTA・RM・RO 列で説明できる
ここで覚えなくていいこと: PCI の構成空間の中身、ベンダ ID と製品 ID の一覧、ATA や SCSI の命令の中身は扱わない。ID は lspci -nn で出せると分かれば足りる。NVMe の SSD は /dev/nvme0n1 という別の名前の列になる（この練習機には無い）。

この章から、練習機の中で打つ

この節で分かること: 端末が2つの場所のどちらにいるか。

このコースの檻は2重になっている。外側はコンテナ（lab@host）で、その中で仮想マシンの練習機（student@linuc）が1台動いている。ディスクを分割したりマウントしたりするのは練習機の中で、ディスクを抜き差しするのは外側である。端末のブロックには、どちらで打つかを見出しで書いてある。

外（lab@host）                    練習機の中（student@linuc）
  virsh  … 練習機の定義と電源       fdisk / mount / lsblk …
  ssh linuc → 中へ入る              exit → 外へ戻る

練習機の root はロックしてある。root の権限が要るものは sudo を付けて打つ（パスワードは聞かれない）。

ハードウェアは、3つの窓から読む

この節で分かること: /proc・/sys・/dev が、ディスクの上のファイルではないこと。

カーネルは、自分が知っている装置の情報を3つの場所に出している。どれもディスクの上には無い。マウントの一覧で種類を見ると分かる。

$ findmnt -t proc,sysfs,devtmpfs -o TARGET,SOURCE,FSTYPE
TARGET
      SOURCE   FSTYPE
/dev  devtmpfs devtmpfs
/proc proc     proc
/sys  sysfs    sysfs

見出しの TARGET だけが1行目に出て、残りが2行目に回っている。これは util-linux 2.39 の findmnt や lsblk が端末に表を出すときの癖で、いちばん左の列の中身がすべて見出しより短いと、その見出しだけを折り返す（パイプに流すと1行に収まる）。このコースの記録は、読者と同じ端末の条件で取ってあるので、この折り返しもそのまま載せている。

proc・sysfs・devtmpfs は、どれもカーネルがメモリの上に作るファイルシステムである。たとえば CPU の情報のファイルは、大きさが 0 なのに中身がある。

$ ls -l /proc/cpuinfo
-r--r--r-- 1 root root 0 Oct 13 11:35 /proc/cpuinfo
$ grep -m1 "model name" /proc/cpuinfo
model name	: QEMU TCG CPU version 2.5+
$ grep -c ^processor /proc/cpuinfo
2
$ head -3 /proc/meminfo
MemTotal:        1459128 kB
MemFree:         1177460 kB
MemAvailable:    1217252 kB

読んだ瞬間にカーネルが答えを作るので、大きさを持たない。CPU は QEMU TCG CPU で、これは QEMU が CPU の命令をソフトウェアで翻訳しながら動かしている（完全エミュレーション）という意味である。KVM を使う読者は、ここに自分の CPU の名前が出る。

出題範囲の「ハードウェアの情報の取得」には、装置ごとの割り当ても入る。割り込み（IRQ。装置が CPU に「用がある」と知らせる番号）、I/O ポート（CPU が装置とやりとりする番地）、DMA（装置が CPU を通さずメモリに読み書きする通り道）である。どれも /proc で読める。

$ head -4 /proc/interrupts
           CPU0       CPU1       
  0:        302          0   IO-APIC   2-edge      timer
  1:          9          0   IO-APIC   1-edge      i8042
  4:        492          0   IO-APIC   4-edge      ttyS0
$ head -5 /proc/ioports
0000-0000 : PCI Bus 0000:00
  0000-0000 : dma1
  0000-0000 : pic1
  0000-0000 : timer0
  0000-0000 : timer1
$ sudo head -5 /proc/ioports
0000-0cf7 : PCI Bus 0000:00
  0000-001f : dma1
  0020-0021 : pic1
  0040-0043 : timer0
  0050-0053 : timer1
$ cat /proc/dma
 4: cascade

割り込みは、番号ごとにどの CPU が何回受けたか（数は人によって違う）と、誰の割り込みか（timer・キーボードのコントローラ i8042・シリアルの ttyS0）が並ぶ。I/O ポートは、一般ユーザが読むと番地が全部 0000-0000 に伏せられ、sudo で読むと本当の番地が出た。同じファイルでも、読む人によってカーネルが答えを変えている。DMA の 4 番（cascade）は2つの DMA コントローラをつなぐための予約で、いまの PC ではほぼこれしか出ない。

ディスクとパーティションについては、3つの窓がそれぞれ違う形で答える。

$ cat /proc/partitions
major minor  #blocks  name

 253        0   20971520 vda
 253        1   19921903 vda1
 253       14       4096 vda14
 253       15     108544 vda15
 259        0     934912 vda16
 253       16    2097152 vdb
 253       32    1048576 vdc
 253       48     262144 vdd
 253       50     102400 vdd2
   8        0    1048576 sda
  11        0        368 sr0
$ ls /sys/block
loop0  loop2  loop4  loop6  sda  vda  vdc
loop1  loop3  loop5  loop7  sr0  vdb  vdd
$ cat /sys/block/vdb/size
4194304
$ ls -l /dev/vda /dev/sda /dev/sr0
brw-rw---- 1 root disk    8, 0 Oct 13 11:36 /dev/sda
brw-rw---- 1 root cdrom  11, 0 Oct 13 11:36 /dev/sr0
brw-rw---- 1 root disk  253, 0 Oct 13 11:36 /dev/vda
窓見せ方この記録で読めたこと
/proc（procfs）カーネルの状態を表にしたファイル/proc/partitions にカーネルが知っているディスクとパーティションの一覧（大きさは 1KiB 単位）
/sys（sysfs）装置ごとのディレクトリと、属性ごとのファイル/sys/block/vdb/size は 4194304（512 バイトのセクタの数。つまり 2GiB）
/dev（devtmpfs）装置への入り口になるデバイスファイル先頭の b がブロックデバイス、8, 0 がメジャー番号とマイナー番号

/dev/sda の 8, 0 は「SCSI ディスクのドライバ（8）の0番目」、/dev/vda の 253, 0 は virtio のディスクのドライバ、/dev/sr0 の 11, 0 は光学ドライブのドライバを指す。デバイスファイルは中身を持たず、この番号で「どのドライバの何番目か」を指しているだけである。/sys/block の loop0〜loop7 は、ファイルをディスクとして見せるための仮の装置で、ここでは使わない。

たとえ: 工場の計器盤に近い。/proc は全体の表示板、/sys は機械ごとの計器、/dev は機械を動かすレバーである。計器は読めば今の値を示すが、紙に記録されているわけではない。
ただし崩れる点: 計器は読むだけのものだが、/sys のいくつかのファイルは root が書き込める。書くとカーネルの扱いがその場で変わる（この章の後半でやる）。

lspci と lsusb は、バスに並んだ装置の名簿

この節で分かること: 練習機にどんな装置がつながっているかの調べ方と、それが全員同じになる理由。

lspci は PCI バス（マザーボードの拡張の通り道）に並んだ装置を、/sys/bus/pci から読んで一覧にする。

$ lspci

00:01.0 PCI bridge: Red Hat, Inc. QEMU PCIe Root port
...
00:02.0 PCI bridge: Red Hat, Inc. QEMU PCIe Root port
00:10.0 Ethernet controller: Red Hat, Inc. Virtio network device

00:1f.2 SATA controller: Intel Corporation 82801IR/IO/IH (ICH9R/DO/DH) 6 port SATA Controller [AHCI mode] (rev 02)   ← SATA のコントローラ（sda と sr0 がつながる）
00:1f.3 SMBus: Intel Corporation 82801I (ICH9 Family) SMBus Controller (rev 02)
01:00.0 USB controller: Red Hat, Inc. QEMU XHCI Host Controller (rev 01)   ← USB のコントローラ
02:00.0 Communication controller: Red Hat, Inc. Virtio 1.0 console (rev 01)
03:00.0 SCSI storage controller: Red Hat, Inc. Virtio 1.0 block device (rev 01)   ← virtio のディスク（03〜06 の4つが vda〜vdd）

05:00.0 SCSI storage controller: Red Hat, Inc. Virtio 1.0 block device (rev 01)
06:00.0 SCSI storage controller: Red Hat, Inc. Virtio 1.0 block device (rev 01)

行の頭の 00:1f.2 は「バス番号:装置番号.機能番号」で、-s で1つに絞れる。-k を付けると、その装置にいま付いているドライバと、付けられるドライバが出る。-nn はベンダと製品の番号を足す。

$ lspci -k -s 00:1f.2
00:1f.2 SATA controller: Intel Corporation 82801IR/IO/IH (ICH9R/DO/DH) 6 port SATA Controller [AHCI mode] (rev 02)
	Subsystem: Red Hat, Inc. QEMU Virtual Machine
	Kernel driver in use: ahci
	Kernel modules: ahci
$ lspci -nn -s 03:00.0
03:00.0 SCSI storage controller [0100]: Red Hat, Inc. Virtio 1.0 block device [1af4:1042] (rev 01)

USB は別のバスなので、別のコマンドで見る。

$ lsusb
Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub
$ lsusb -t
/:  Bus 001.Port 001: Dev 001, Class=root_hub, Driver=xhci_hcd/8p, 480M
/:  Bus 002.Port 001: Dev 001, Class=root_hub, Driver=xhci_hcd/8p, 5000M

いまは USB のコントローラの「根」（root hub）が2つあるだけで、何も挿さっていない。USB 2.0 の口（480M）と USB 3.0 の口（5000M）である。第2章でここに USB メモリを挿す。

この名簿は、読者全員で同じになる。仮想マシンのハードウェアは、外側にある定義（libvirt の XML）で決まっているからである。外に出てディスクの一覧を見ると、練習機の中の名前と、外のファイルの対応が出る。

$ virsh domblklist linuc
 Target   Source
------------------------------------------------
 vda      /home/lab/vm/linuc.qcow2
 vdb      /home/lab/vm/extra/vdb.qcow2
 vdc      /home/lab/vm/extra/vdc.qcow2
 vdd      /home/lab/vm/extra/vdd.qcow2
 sda      /home/lab/vm/extra/sda.qcow2
 sdb      /usr/share/lab-disks/linuc-media.iso
たとえ: 建物の入居者名簿に近い。何階の何号室（バス番号.装置番号）に誰（装置）が入っていて、担当の管理人（ドライバ）が誰かが分かる。
ただし崩れる点: 本物の建物なら名簿と部屋が食い違うことはあるが、仮想マシンでは名簿（定義）がそのまま建物になる。だから全員の練習機で同じ lspci が出る。実機では、マザーボードと挿したカードの数だけ違う。

HDD か SSD か

この節で分かること: カーネルが「回転するディスクかどうか」を何で決めているか。

HDD は円盤を回して磁気ヘッドを動かすので、離れた場所を続けて読むと遅い。SSD は半導体なので、どこを読んでも速さがほぼ同じである。カーネルは、どちらかによって読み書きの並べ方（I/O スケジューラ）を変える。その区別が lsblk の ROTA（rotational = 回転する）列に出る。

ふつうこう考える

練習機のディスクは、どれも外側の同じ種類のファイルで、置き場所も同じ（著者の PC の SSD）である。 カーネルが実際の速さを測って判断するのなら、全部同じ答えになるはずだ。少なくとも、同じ種類のファイルに違う答えは出ないだろう。

$ lsblk -d -o NAME,TRAN,ROTA,RM,RO,SIZE,MODEL
NAME
    TRAN   ROTA RM RO  SIZE MODEL
sda sata      0  0  0    1G QEMU HARDDISK   ← ROTA 0（回転しない = SSD 扱い）。型番は HARDDISK
sr0 sata      1  1  1  368K QEMU DVD-ROM
vda virtio    1  0  0   20G   ← ROTA 1（回転する = HDD 扱い）。vda〜vdd の4本とも
vdb virtio    1  0  0    2G 
vdc virtio    1  0  0    1G 
vdd virtio    1  0  0  256M
だめな理由: 答えが割れた。SATA の sda だけが回転しない装置（SSD）で、virtio の4本は回転する装置（HDD）として扱われている。 しかも sda の型番は QEMU HARDDISK のままである。カーネルは測っていない。 SATA の装置は、自分の回転数を答える欄を持っていて（ATA の IDENTIFY という問い合わせの中の1語）、カーネルはその答えをそのまま信じる。 virtio のディスクにはその欄が無いので、既定の「回転する」になる。

外側で確かめる。5本のファイルは同じ種類（qcow2）で、違いは定義の中の1語だけである。

$ ls -l ~/vm/extra/*.qcow2
-rw-r--r-- 1 lab lab  196624 Oct 13 11:35 /home/lab/vm/extra/sda.qcow2
-rw-r--r-- 1 lab lab  196616 Oct 13 11:35 /home/lab/vm/extra/usb-a.qcow2
-rw-r--r-- 1 lab lab  196616 Oct 13 11:35 /home/lab/vm/extra/usb-b.qcow2
-rw-r--r-- 1 lab lab  196616 Oct 13 11:35 /home/lab/vm/extra/usb-check.qcow2
-rw-r--r-- 1 lab lab  196640 Oct 13 11:35 /home/lab/vm/extra/vdb.qcow2
-rw-r--r-- 1 lab lab  196624 Oct 13 11:35 /home/lab/vm/extra/vdc.qcow2
-rw-r--r-- 1 lab lab 1048576 Oct 13 11:36 /home/lab/vm/extra/vdd.qcow2
$ virsh dumpxml linuc | grep rotation_rate
      <target dev='sda' bus='sata' rotation_rate='1'/>

rotation_rate='1' は「回転数 1」という特別な値で、SATA の決まりでは「回転しない装置」を意味する。QEMU はそう答え、カーネルはそれを /sys に書いた。lsblk はそのファイルを読んでいるだけである。

$ cat /sys/block/sda/queue/rotational /sys/block/vdb/queue/rotational
0
1

このファイルは root が書き換えられる。書けばその場で扱いが変わる。

$ echo 0 | sudo tee /sys/block/vdb/queue/rotational
0
$ lsblk -d -o NAME,ROTA /dev/vdb
NAME
    ROTA
vdb    0

ただし /sys はメモリの上の窓なので、再起動すると装置が名乗った値（1）に戻る。起動のたびに書き直す仕組みが要る。それが第2章の udev で、演習01 の題材でもある。

たとえ: 入館証の自己申告の欄に近い。受付は「技術職」と書かれていれば技術職として案内し、本当かどうかは確かめない。
ただし崩れる点: 入館証は本人しか書けないが、rotational は後から root が書き換えられる。申告を上書きする手段が、受け取る側に用意されている。
HDDSSD光学ドライブ
しくみ回る磁気ディスクとヘッドフラッシュメモリ（半導体）回る CD・DVD・BD をレーザーで読む
ROTA101
得意・苦手離れた場所を続けて読むと遅い（シーク）。容量あたりが安いどこを読んでも速い。書き換えの回数に寿命がある。TRIM で空きを知らせる読み取り専用か、書けても書き換えが遅い。メディアを抜き差しできる
Linux での名前（例）/dev/sda/dev/sda（SATA）・/dev/nvme0n1（NVMe）/dev/sr0

手を動かす: 実践編の演習01は、vdb を「再起動しても SSD として扱われる」状態にする課題である。 判定は再起動の代わりに、起動時と同じ知らせを udev に1回送って、値が 0 に書き換わるかを見る。

光学ドライブは、取り外せて書けない装置

この節で分かること: 光学ドライブの「読み取り専用」と「取り外せる」が、どこで決まっているか。

さっきの表で sr0 は RM（removable = 取り外せる）が 1、RO（read only = 読み取り専用）が 1 だった。中には ISO9660 という CD のファイルシステムが入っている。マウントして読む。

$ sudo mount /dev/sr0 /mnt
mount: /mnt: WARNING: source write-protected, mounted read-only.
$ cat /mnt/README.TXT
LinuC 練習用の光学メディア（CD-ROM のイメージ）

このディスクは読み取り専用です。
書き込もうとすると、ファイルシステムの権限ではなく、装置の側で断られます。
$ touch /mnt/test.txt
touch: cannot touch '/mnt/test.txt': Read-only file system
$ sudo umount /mnt

mount に読み取り専用を頼んでいないのに、WARNING: source write-protected, mounted read-only. と言って勝手にそうした。装置が書き込みを受け付けないので、mount のほうが合わせたのである。書けない理由はファイルの権限ではなく装置の性質なので、Read-only file system と出る。

メディアを抜く。外で光学ドライブを「開ける」。

$ virsh change-media linuc sdb --eject
Successfully ejected media.
$ lsblk -d -o NAME,TYPE,RM,RO,SIZE /dev/sr0
NAME
    TYPE RM RO  SIZE
sr0 rom   1  1  368K
$ sudo mount /dev/sr0 /mnt
mount: /mnt: no medium found on /dev/sr0.
       dmesg(1) may have more information after failed mount system call.

装置（sr0）は消えない。抜けたのはメディアだけである。しかも lsblk はまだ 368K と言っている。表示は前に読んだ大きさのままで、実際に読みに行った mount だけが本当の状態（no medium found）を知った。戻しておく。

$ virsh change-media linuc sdb /usr/share/lab-disks/linuc-media.iso --insert
Successfully inserted media.
$ lsblk -d -o NAME,TYPE,RM,RO,SIZE /dev/sr0
NAME
    TYPE RM RO  SIZE
sr0 rom   1  1  368K
たとえ: レコードプレーヤーに近い。台（ドライブ）は置いたまま、盤（メディア）だけを入れ替える。盤が無くても台はそこにある。
ただし崩れる点: プレーヤーなら盤が無いことは見れば分かるが、Linux の表示（lsblk の SIZE）は前の盤の大きさを出し続けることがある。確かめるには、実際に読んでみるしかない。
確認

lsblk -d -o NAME,ROTA で sda の ROTA が 0 だった。この値はどのファイルを読んだもので、何によって決まったか。

答え

/sys/block/sda/queue/rotational を読んだもの。値は装置の申告で決まる（SATA の装置が回転数の欄に「回転しない」と答えた）。カーネルが速さを測った結果ではない。root はこのファイルを書き換えられるが、再起動すると申告の値に戻る。

確認

ls -l /dev/sda の出力が brw-rw---- 1 root disk 8, 0 … だった。先頭の b と 8, 0 は何を表すか。

答え

b はブロックデバイス（ブロック単位で読み書きする装置。ディスク）。8, 0 はメジャー番号とマイナー番号で、「SCSI ディスクのドライバ（8）の0番目」を指す。デバイスファイルは中身を持たず、この番号で装置を指している。

確認

PCI バスにつながっている装置の一覧と、それぞれに使われているカーネルのドライバを表示したい。打つコマンドは何か。USB 機器を、つながり方（ツリー）とドライバ付きで表示するコマンドは何か。

答え

PCI は lspci -k（1台に絞るなら -s 00:1f.2 のように番号を付ける）。USB は lsusb -t。どちらも /sys の情報を読んで並べている。

この章で分かったこと

持ち帰ってほしいこと

  • /proc（カーネルの状態の表）・/sys（装置ごとの属性）・/dev（装置の入り口）は、どれもカーネルがメモリの上に作る窓で、ディスクの上には無い
  • /proc/cpuinfo のサイズが 0 なのは、読んだ瞬間に作られるから
  • lspci -k で PCI の装置と付いているドライバ、lsusb -t で USB のつながりとドライバが分かる
  • HDD か SSD か（lsblk の ROTA）は、カーネルが測ったのではなく装置の申告。/sys/block/<装置>/queue/rotational に出ていて、root は書き換えられる（再起動で戻る）
  • 光学ドライブは RM=1・RO=1。書けないのは装置の性質で、メディアを抜いても装置は残る
