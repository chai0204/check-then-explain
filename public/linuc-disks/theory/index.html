理論編 — ハードウェア、ディスク、パーティション、ファイルシステム

LinuC レベル1 101 試験・主題1.05を、 コンテナの中で動く仮想マシン（練習機）の本物のカーネルの上で確かめる11章。 まず空のディスクを一通り使えるようにし（第1・2章）、そのあと1段ずつ詳しく見ていきます: パーティションの表（第3・4章）→ ファイルシステム（第5章）→ マウント（第6・7章）→ スワップ（第8章）→ LVM（第9章）→ 部品とドライバ（第10・11章）。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

読む順番と、前提

章は、第1章から順に、同じ1台の練習機で打っていく前提で書いてあります（前の章で作った区画やファイルシステムを、次の章で使います）。 演習を先にやった練習機では本文と違う画面になるので、その場合は外で vm reset --yes を打ってから第1章を始めてください（実践編に詳しく書いてあります）。 各章の冒頭に「前の章までにやったこと」と「この章でやること」を書いてあります。 前提として要るのは、主題1.01〜1.04 のコースで扱った範囲（端末でコマンドを打つ・ファイルとディレクトリ・パーミッション・sudo・パイプと grep）だけです。 カーネル・ドライバ・セクタのような語も、使う前にその場で一言で説明しています。

11章を通して確かめること

ディスクは、装置・パーティションの表・（LVM）・ファイルシステム・マウントの段が重なってできています。 各段は自分の印（装置の申告・表の行・UUID）だけを読み、隣の段を勝手には書き換えません。

だから、区画を消しても中身は残り（第3章）、論理ボリュームを広げてもファイルシステムは広がらず（第9章）、 /dev/sdb という名前は挿す順番で別のディスクを指します（第6章）。 どの章でも、まず普通に使ってみて、そのあとで「1つの段だけを見て、隣の段も一緒に動くと思った」ところで予想が外れるのを確かめます。 第11章の最後で、11の外れた予想を1つの表にまとめます。

ここで覚えなくていいこと: ファイルシステムの内部の形、RAID、iSCSI や NFS のようなネットワーク越しのディスク、 ディスクの暗号化（LUKS）、systemd の .mount ユニットの書き方。どれも主題1.05 の範囲外で、この11章には出てきません。

出題範囲の語この教材での扱い理由
BIOS / UEFI の設定画面で周辺機器を無効にする第11章で説明（ドライバで止める方法は実際に打つ）ファームウェアの設定画面は対話の GUI で、記録を読者と揃えられない
HDD と SSD の物理的な違い（速さ・寿命）第10章の表で説明。Linux が両者を区別するしくみ（rotational）は実際に打つ練習機のディスクは全部同じ種類のファイルで、速さの違いは測っても意味が無い（それ自体が第10章の論点）
本物の USB メモリ・CD の抜き差し外から virsh attach-device / change-media で挿す・抜くカーネルから見れば同じ「装置が来た・去った」の知らせになる
デスクトップでの自動マウント（Ubuntu・Debian は /media/<ユーザ>/、RHEL 系は /run/media/<ユーザ>/）第11章で説明。/etc/fstab の user で一般ユーザに許す方法を第7章で実際に打つudisks2 とデスクトップ環境が要る（練習機は画面を持たない）
ファイルシステムの検査と修復（fsck・xfs_repair）第7章で /etc/fstab の6列目の意味として、第9章で lvreduce が呼ぶものとして出るVersion 10.0 では 101 ではなく 201 試験（2.02.2）の範囲

記録は、読者と同じ条件の端末（docker exec -it で開いた端末・対話のシェル・TERM=xterm）で、80 桁 × 24 行にして、 本文のコマンドを1行ずつ打って取りました（練習機の中も、同じ端末から ssh linuc で入って打っています。第6章からの外のコマンドは、本文と同じく2つ目の端末で打っています）。 ls の段組みは端末の幅で変わります。lsblk と findmnt は 80 桁に収まる列だけを指定してあるので、幅が広くても同じ表示になります。 fdisk の Last sector の問いのように 80 文字を超える行は、あなたの画面では折り返して2行に見えます（文字は同じです）。 /proc/cpuinfo などは KVM を使わない完全エミュレーションでの表示です。

他の主題（1.01〜1.04・1.06〜1.11）の対応は LinuC 出題範囲マップにまとめてあります。

章

  1. 練習機に入り、つながっているディスクを眺める — 外と練習機の中を行き来し、lsblk と df でディスク・区画・ファイルシステム・マウントの関係を見る（15分）
  2. 空のディスクを使えるようにする — 区切る → 作る → つなぐ → 書く → 外す、を一通りやる（20分）
  3. パーティションの表を読む・直す — fdisk -l の読み方、表の中身、区画を消して作り直す、5つ目からの拡張・論理パーティション（22分）
  4. 新しい形式の表（GPT）と、起動に使う区画 — 練習機自身の GPT と ESP を読み、サーバのディスクを gdisk と parted で切る（25分）
  5. ファイルシステムの種類と作り方 — 5種類を作り分け、区画の大きさと使える量を比べる（22分）
  6. USB メモリと CD をマウントする — USB メモリと CD を手でマウントし、ラベル・UUID で指す。CD の写しのファイルもマウントする（24分）
  7. 起動のたびにマウントする — /etc/fstab の6列を書いて再起動の前に確かめ、一般ユーザにマウントを許し、再起動して確かめる（25分）
  8. スワップと tmpfs — スワップを作って起動のたびに使い、メモリの上に tmpfs を作る（18分）
  9. LVM で、2台のディスクを1つにまとめる — 1台より大きな箱を作って広げ・縮め、スナップショットで消したファイルを取り戻す（24分）
  10. 部品の情報を読む — CPU・メモリ・バス・ディスクを /proc・/sys・/dev で読み、HDD か SSD かの扱いを変える（25分）
  11. ドライバと、USB メモリの抜き差し — ドライバがいつ誰に読み込まれるかを確かめ、USB メモリを挿しても使えないようにする。11章を1つの事実でまとめる（28分）

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの4つに集まります。

場面ここで効く理由見落としやすい点関連する章
ディスクを増設して /etc/fstab に足す 名前・UUID・ラベルのどれで指すかで、次の起動の結果が変わる ラベルの重なり（クラウドのイメージは BOOT・UEFI のような一般的なラベルを使う）は findmnt --verify では出ないことがある。blkid -t LABEL=… で確かめ、書いたら再起動の前に mount -a と findmnt --verify2・6・7
容量が足りなくなった LVM なら止めずに広げられる 箱（LV）と中身（ファイルシステム）の両方を広げる。XFS は縮められない。ext4 の予約 5% も効いている5・9
パーティションを消してしまった 表の行を書き戻せば中身は戻る 作り直すときに「印を消すか」で Y と答えない。sfdisk -d で表を控えておく3
USB メモリを使わせたくない（情報の持ち出し対策） ドライバの読み込みを止められる rmmod では次に挿すと戻る。blacklist は依存と名前を指定した modprobe に効かず、install … /bin/false も insmod は止めない。すでにあるファイルを書き換えたら udev を再起動する11

この主題を使わない方がよい場面も1つあります。 クラウドの仮想マシンで、ディスクの大きさを OS の中から細かく設計し直そうとすることです。 クラウドではディスク（ボリューム）を管理画面で広げ、OS の中では最後の区画を広げるだけの形に寄せたほうが、手順が少なく事故も少なくなります （練習機がディスクを4つにしか分けていないのも、そのためです。第4章）。
