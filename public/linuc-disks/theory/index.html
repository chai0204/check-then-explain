理論編 — ハードウェア、ディスク、パーティション、ファイルシステム

LinuC レベル1 101 試験・主題1.05を、 コンテナの中で動く仮想マシン（練習機）の本物のカーネルの上で確かめる8章。 ディスクを分割し、フォーマットし、マウントし、ドライバを外し、USB メモリを抜き差しします。 1章ごとに「実際に打つと何が出るか」を先に置いています。

このページのコマンドは、あなたの画面に本文と同じ文字を出します。 出なければ教材のバグとして直します。 AI の回答は毎回違い、公式ドキュメントはあなたの環境を知りません。 ここにあるのは、誰かが実際に一度通した記録です。

この8章を貫いている1つの事実

ディスクは、装置・パーティション表・LVM・ファイルシステム・マウントの層が重なってできている。 各層は自分の印（装置の申告・表の行・UUID）だけを読み、隣の層を勝手には書き換えない。

パーティションを消しても中身は残り（第3章）、論理ボリュームを広げてもファイルシステムは広がらず（第5章）、 /dev/sdb という名前は挿す順番で別のディスクを指す（第8章）。 どれも「1つの層を変えたら、隣の層も一緒に変わる」と思ったところで予想が外れます。 主題1.05 の「詳細」にコマンドが層ごとに並んでいるのは、層ごとに別の道具で確かめる必要があるからです。

ここで覚えなくていいこと: ファイルシステムの内部の形、RAID、iSCSI や NFS のようなネットワーク越しのディスク、 ディスクの暗号化（LUKS）、systemd の .mount ユニットの書き方。どれも主題1.05 の範囲外で、この8章には出てきません。

出題範囲の語この教材での扱い理由
BIOS / UEFI の設定画面で周辺機器を無効にする第2章の表で説明（ドライバで止める方法は実際に打つ）ファームウェアの設定画面は対話の GUI で、記録を読者と揃えられない
HDD と SSD の物理的な違い（速さ・寿命）第1章の表で説明。Linux が両者を区別するしくみ（rotational）は実際に打つ練習機のディスクは全部同じ種類のファイルで、速さの違いは測っても意味が無い（それ自体が第1章の論点）
本物の USB メモリ・CD の抜き差し外から virsh attach-device / change-media で挿す・抜くカーネルから見れば同じ「装置が来た・去った」の知らせになる
デスクトップでの自動マウント（Ubuntu・Debian は /media/<ユーザ>/、RHEL 系と udisks2 の既定は /run/media/<ユーザ>/）第2章・第8章で説明。/etc/fstab の user で一般ユーザに許す方法を実際に打つudisks2 とデスクトップ環境が要る（練習機は GUI を持たない）

記録は、読者と同じ条件の端末（対話のシェル・TERM=xterm）で取りました。端末の幅は 80 桁です。 ls の段組みは幅で変わります。lsblk と findmnt は 80 桁に収まる列だけを指定してあるので、幅が広くても同じ表示になります。 fdisk と gdisk の対話だけは 200 桁で取りました（fdisk の Last sector の問いは 86 文字あり、それより狭い端末では行が横にずれて表示されます）。 /proc/cpuinfo などは KVM を使わない完全エミュレーションでの表示です。

他の主題（1.01〜1.04・1.06〜1.11）の対応は LinuC 出題範囲マップにまとめてあります。

章

  1. HDD か SSD かは、装置の申告で決まる — 同じ種類のファイル5本が、SSD 1本と HDD 4本に分かれる。決めたのは定義の中の1語（18分）
  2. ドライバは、外しても戻ってくる — rmmod しても挿し直すと戻る。blacklist は依存に効かず、書き換えたファイルには udev が気づかない（26分）
  3. パーティションの表は、目次にすぎない — 消して作り直すと、中のファイルが読める。表の実体は 64 バイト（25分）
  4. 起動の入口は、マウントしなくても見つかる — /boot/efi を外しても、ESP の種類を書き換えても起動する。ファームウェアは NVRAM の候補（PARTUUID とファイルのパス）で読みに行く（24分）
  5. LV を広げても、ファイルシステムは広がらない — lvextend で 1.37GiB になっても df は 574M。XFS は縮められない（22分）
  6. ファイルシステムは、作った大きさより小さく見える — Size − Used と Avail が合わない。root 用の予約と、ext4 自身の取り置きのぶん。fsck は XFS では何もしない（24分）
  7. tmpfs は、メモリを先に取らない — メモリ 1.4GiB の機械に 4GiB の tmpfs が作れる。mkswap だけではスワップは増えない（17分）
  8. マウントは、名前ではなく中身の印で指す — /dev/sdb が別の USB メモリになる。ラベルの重なりが /boot を危うくしていた。ここで8章が1本になる（30分）

実務のどこで効くか

資格の勉強として読んでも、使う場面はこの4つに集まります。

場面ここで効く理由見落としやすい点関連する章
ディスクを増設して /etc/fstab に足す 名前・UUID・ラベルのどれで指すかで、次の起動の結果が変わる ラベルの重なり（クラウドのイメージは BOOT・UEFI のような一般的なラベルを使う）は findmnt --verify では出ない。blkid -t LABEL=… で確かめ、書いたら再起動の前に mount -a と findmnt --verify3・6・8
容量が足りなくなった LVM なら止めずに広げられる 箱（LV）と中身（ファイルシステム）の両方を広げる。XFS は縮められない。ext4 の予約 5% も効いている5・6
パーティションを消してしまった 表の行を書き戻せば中身は戻る 作り直すときに「印を消すか」で Y と答えない。sfdisk -d で表を控えておく3
USB メモリを使わせたくない（情報の持ち出し対策） ドライバの読み込みを止められる rmmod では次に挿すと戻る。blacklist は依存と名前を指定した modprobe に効かず、install … /bin/false も insmod は止めない。すでにあるファイルを書き換えたら udev を再起動する2

この主題を使わない方がよい場面も1つあります。 クラウドの仮想マシンで、ディスクの大きさを OS の中から細かく設計し直そうとすることです。 クラウドではディスク（ボリューム）を管理画面で広げ、OS の中では最後の区画を広げるだけ（growpart と resize2fs）の形に寄せたほうが、手順が少なく事故も少なくなります （練習機がディスクを4つにしか分けていないのも、そのためです。第4章）。
