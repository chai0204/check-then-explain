7. 起動のたびにマウントする

第6章では、USB メモリと CD を手でマウントし、装置の名前は挿す順番で変わるので、ラベルや UUID で指すことを確かめた。手でしたマウントは、再起動すると外れる。この章では、起動のたびに自動でマウントされるように /etc/fstab に書き、一般ユーザにマウントを許す書き方と、再起動して効いているかの確かめ方を見る。

前提: 第6章まで読了前提: 練習機の中にいる・外の端末もある所要 25分影響度 B出題範囲 1.05.3（重要度4）最終検証 2026-10-20

この章のゴール

  • /etc/fstab の6つの列を読み書きでき、UUID で指す行を書いて、再起動の前に mount -a と findmnt --verify で確かめられる
  • 2つのディスクに同じラベルを付けたら LABEL= の行がどうなるかを確かめ、重なりを見つけて付け替えられる
  • user・users・noauto・ro のオプションで、一般ユーザが取り外せるメディアをマウントできるようにできる
ここで覚えなくていいこと: 起動のときのマウントを受け持つプログラム（systemd）の、マウント用の設定ファイル（.mount ユニット）の書き方は扱わない（/etc/fstab を書いたあとの systemctl daemon-reload の1行だけ覚えればよい）。autofs や NFS のような、ネットワーク越しや必要になったときのマウントも扱わない。5列目の dump（古いバックアップの道具）の使い方も扱わない（0 を書けばよい）。

/etc/fstab の6つの列

この節で分かること: /etc/fstab の1行の読み方。

/etc/fstab は、起動のときにマウントするファイルシステムの一覧である（file system table。略して fstab と呼ぶ）。練習機のものを見る。

$ cat /etc/fstab
LABEL=cloudimg-rootfs	/	 ext4	discard,commit=30,errors=remount-ro	0 1
LABEL=BOOT	/boot	ext4	defaults	0 2
LABEL=UEFI	/boot/efi	vfat	umask=0077	0 1

3行あり、練習機の /・/boot・/boot/efi を、どれもラベル（LABEL=…）で指している（第1章の lsblk で見た vda1・vda16・vda15 である）。1行は空白で区切った6つの列でできている。5列目に出てくる dump は古いバックアップの道具、6列目の fsck はファイルシステムの壊れを調べて直す道具である（1行目の4列目の discard,commit=30,errors=remount-ro は、Ubuntu のクラウド用の設定がそのまま残ったもので、ここでは読まない）。

LABEL=BOOT    /boot   ext4   defaults   0   2
──────────    ─────   ────   ────────   ─   ─
何を           どこに  種類   オプション  │   └ 6列目: 起動のときに fsck で調べる順番
（装置の名前・                             └ 5列目: dump でバックアップするか（0 = しない）
 UUID=・LABEL=）
列書くもの何のためにあるか
1. 何を装置の名前・UUID=…・LABEL=…どのファイルシステムをマウントするか。名前は変わりうるので、ふつうは UUID かラベル（第6章）
2. どこにマウントポイント（スワップなら none）つなぐ先のディレクトリ。前もって作っておく
3. 種類ext4・xfs・vfat・iso9660・swap などファイルシステムの種類
4. オプションdefaults や、カンマで並べたオプションどうマウントするか（読み取り専用・誰がマウントできるか など。後の節の表）
5. dump0 か 1dump（古いバックアップの道具）で対象にするか。いまはふつう 0
6. fsck の順番1・2・0起動のときに fsck で調べる順番。勧めは / が 1、ほかが 2、調べないなら 0

練習機の /boot/efi の行は 0 1 になっている。fsck の順番の 1・2 は勧めで決まりではなく、これは Ubuntu の元の書き方のままである。

1行足して、再起動の前に確かめる

この節で分かること: /etc/fstab に行を足してから、効くかを確かめるまでの手順。

第5章で作った vdb6（ext4、ラベル HOME）を、起動のたびに /srv/home にマウントする。指すのは UUID にする。blkid の -s UUID -o value は、UUID の値だけを出すオプションである。

$ sudo blkid -s UUID -o value /dev/vdb6
9de5d3e5-12a9-4f35-8dec-0637e6918698

この長い値を写し間違えないように、コマンドの出力をその場に埋め込む $(コマンド) を使って行を作る。tee -a は、受け取った文字を画面に出しつつ、ファイルの末尾に足す（-a が無いと上書きして、元の3行が消える）。値はあなたの画面では違う。

$ echo "UUID=$(sudo blkid -s UUID -o value /dev/vdb6)  /srv/home  ext4  defaults,nofail  0  2" | sudo tee -a /etc/fstab
UUID=9de5d3e5-12a9-4f35-8dec-0637e6918698  /srv/home  ext4  defaults,nofail  0  2
$ sudo mkdir /srv/home

nofail は「起動のときにこのディスクが見つからなくても、起動を止めない」オプションである。付けないと、ディスクを外したまま起動したときに、起動が途中で止まる。

書いただけでは、まだマウントされていない。findmnt はマウントの一覧から表を出すコマンドで、マウントポイントを渡すとその1つだけを出す（-o で列を選ぶのは lsblk と同じ）。

$ findmnt -o TARGET,SOURCE,FSTYPE /srv/home

何も出ない。/etc/fstab は書いただけではマウントされず、読まれるのは起動のときと、mount -a を打ったときと、mount にマウント先か装置の片方だけを渡したとき（足りない分をこの表から補う。この章の後半で使う）である。mount -a は「/etc/fstab の行のうち、まだマウントされていないものを全部マウントする」で、起動のときと同じことをその場で起こせる。

$ sudo mount -a
mount: (hint) your fstab has been modified, but systemd still uses
       the old version; use 'systemctl daemon-reload' to reload.
$ findmnt -o TARGET,SOURCE,FSTYPE /srv/home
TARGET    SOURCE    FSTYPE
/srv/home /dev/vdb6 ext4

/srv/home に vdb6 がマウントされた。mount が出した (hint) は、「/etc/fstab は書き換えられたが、systemd はまだ古い版を使っている。systemctl daemon-reload で読み直させよ」という意味である。systemd（練習機の起動と常駐のプログラムを管理するプログラム）は、起動のたびに /etc/fstab から「マウントの手順」を作り直し、それに従って起動のときのマウントをする。だから次の起動には、書いただけで効く。困るのは、いま動いている systemd が古い表のままでいることで、systemd を通した操作が書き換える前の表で動く。読み直させておく。

$ sudo systemctl daemon-reload
$ sudo findmnt --verify
Success, no errors or warnings detected

findmnt --verify は /etc/fstab を読み、書き間違い（見つからない UUID やラベル、ディスクの上の種類との食い違い など）を調べる。書いたら、再起動の前に mount -a と findmnt --verify で確かめる。/etc/fstab の書き間違いは、次の起動で初めて表に出て、起動が止まることがあるからである。

たとえ: /etc/fstab は、店を開けるときに読む開店の手順書に近い。手順書に1行足しても、その日の店はもう開いているので何も起きず、次の開店から効く。mount -a は、手順書のとおりにもう一度通してみる予行である。
ただし崩れる点: 人なら手順書を読み直せば済むが、systemd は開店のときに手順書から作った自分用の写しで動いている。手順書を書き換えたら、その写しを作り直させる（daemon-reload）まで、systemd は古い手順のままである。

ラベルで指せば、いつも安全？

この節で分かること: 練習機自身が使っているラベルを、新しいディスクにも付けたらどうなるか。重なりの見つけ方・直し方。

ふつうこう考える

ラベルで指せば、挿す順番やディスクの増減に関係なく、いつも同じファイルシステムを指せる（第6章）。新しいサーバのディスクなら、/boot 用の区画（vdb2。第5章では NEWBOOT と付けた）に、用途どおり BOOT と付けても困らないはずだ。e2label は、ext 系のファイルシステムのラベルを付け替えるコマンドである。

$ sudo e2label /dev/vdb2 BOOT
$ sudo findmnt --verify
/boot
   [W] ext4 does not match with on-disk ext3

0 parse errors, 0 errors, 1 warning
$ sudo blkid -t LABEL=BOOT
/dev/vda16: LABEL="BOOT" UUID="a5eecc38-8587-4601-9295-c92dabc20612" BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="ce13a6f1-b3f2-4c7a-b3db-6d75505ad739"
/dev/vdb2: LABEL="BOOT" UUID="0912d5f8-b0f2-4a83-9b5b-15a98a92a491" SEC_TYPE="ext2" BLOCK_SIZE="4096" TYPE="ext3" PARTLABEL="Linux filesystem" PARTUUID="92ea4685-9f0d-47eb-b989-1ac92e1f5b92"
$ ls -l /dev/disk/by-label/BOOT
lrwxrwxrwx 1 root root 10 Oct 20 23:43 /dev/disk/by-label/BOOT -> ../../vdb2
だめな理由: BOOT というラベルが2つになった（blkid -t LABEL=BOOT は、そのラベルを持つものを全部出す）。練習機自身の /etc/fstab は、/boot を LABEL=BOOT で探している。その LABEL=BOOT がいま指すのは、新しい vdb2（空の ext3）のほうである（/dev/disk/by-label/BOOT が vdb2 を指している）。このまま再起動すると、練習機の /boot に空の ext3 がマウントされかねない。ラベルは人が付ける名前なので、重なりうる。しかも findmnt --verify が知らせたのは「ext4 と書いてあるのに、ディスクの上は ext3」という種類の食い違いで、重なりそのものではない（たまたま種類が違ったので気づけた）。

重なりを確かめるのは blkid -t LABEL=… か /dev/disk/by-label/ である。ラベルを元に戻す。

$ sudo e2label /dev/vdb2 NEWBOOT
$ ls -l /dev/disk/by-label/BOOT
lrwxrwxrwx 1 root root 11 Oct 20 23:43 /dev/disk/by-label/BOOT -> ../../vda16
$ sudo findmnt --verify
Success, no errors or warnings detected

LABEL=BOOT は練習機の vda16 に戻った。ラベルを付け替える道具は種類ごとに違い、ext 系は e2label（tune2fs -L でも同じ）、XFS は xfs_admin -L（-l で読む）である。

$ sudo xfs_admin -l /dev/vdb4
label = "ROOT"

UUID は mkfs がでたらめに選ぶ番号なので、ふつうは重ならない。重なるのは、ディスクを丸ごと写したとき（第6章の dd のように）で、そのときは片方の UUID を振り直す（ext 系なら tune2fs -U）。/etc/fstab で迷ったら UUID で指す。

たとえ: ラベルは手書きの名札、UUID は重ならないように配られた番号に近い。名札は読みやすく付け替えも簡単だが、同じ名前の人がいれば取り違える。番号は覚えにくいが重ならない。
ただし崩れる点: 配られた番号は役所が重ならないように管理するが、UUID は mkfs がでたらめに選ぶだけである。ディスクを丸ごと写すと、同じ UUID が2つになる。

つないだまま、オプションを変える

この節で分かること: マウントしたまま読み取り専用に切り替える方法。

-o でオプションを渡せる。remount は「外さずに、オプションだけを変えてマウントし直す」である。

$ sudo mount -o remount,ro /srv/home
$ sudo touch /srv/home/test
touch: cannot touch '/srv/home/test': Read-only file system
$ sudo mount -o remount,rw /srv/home
$ sudo touch /srv/home/test

ro（読み取り専用）にすると root でも書けず、rw（読み書き）に戻すと書けた。外さずにできるので、使っている途中のファイルシステムを一時的に守るときに使う。

一般ユーザに、マウントを許す

この節で分かること: user・noauto などのオプションの役目と、FAT の持ち主の決まり方。

ここまでの mount には、どれも sudo を付けてきた。一般ユーザのまま CD をマウントしてみる。

$ mount /media/cdrom
mount: /media/cdrom: can't find in /etc/fstab.

一般ユーザの mount は、/etc/fstab に書かれた行のうち、一般ユーザに許された行しか通さない。光学ドライブの行を書く。user は一般ユーザにマウントを許すオプション、noauto は「起動のときと mount -a ではマウントしない」オプションで、メディアが入っていないかもしれない装置に付ける。

$ sudo mkdir /media/cdrom
$ echo "/dev/sr0  /media/cdrom  iso9660  ro,user,noauto  0  0" | sudo tee -a /etc/fstab
/dev/sr0  /media/cdrom  iso9660  ro,user,noauto  0  0
$ sudo systemctl daemon-reload
$ mount /media/cdrom
$ mount | grep /media/cdrom
/dev/sr0 on /media/cdrom type iso9660 (ro,nosuid,nodev,noexec,relatime,nojoliet,check=s,map=n,blocksize=2048,iocharset=utf8,user=student)
$ ls -l /media/cdrom
total 1
-r--r--r-- 1 root root 227 Oct 13 09:00 README.TXT
$ umount /media/cdrom

student のまま、マウントも外すこともできた。mount を引数なしで打つと、マウントされているもの全部の一覧が出る（grep で1行に絞った）。オプションの欄に、書いていない nosuid,nodev,noexec と、誰がマウントしたか（user=student）が出ている。user を付けると、他人が持ち込んだメディアで権限を奪われないよう、この3つが自動で付く。

FAT の USB メモリでも同じことをする。A を挿す（第6章の A。中に who.txt がある）。

$ virsh attach-device linuc ~/vm/extra/usb-a.xml
Device attached successfully
$ echo "LABEL=STICK_A  /media/stick  vfat  user,noauto  0  0" | sudo tee -a /etc/fstab
LABEL=STICK_A  /media/stick  vfat  user,noauto  0  0
$ sudo systemctl daemon-reload
$ mount /media/stick
$ ls -l /media/stick
total 2
-rwxrwxr-x 1 student student 12 Oct 20 23:41 who.txt
$ touch /media/stick/mine.txt
$ umount /media/stick
$ sudo mount /media/stick
$ ls -l /media/stick
total 2
-rwxr-xr-x 1 root root  0 Oct 20 23:44 mine.txt
-rwxr-xr-x 1 root root 12 Oct 20 23:41 who.txt
$ sudo umount /media/stick
$ sudo findmnt --verify
Success, no errors or warnings detected

student がマウントすると、ファイルはすべて student のものに見え、書き込めた。root がマウントすると、同じファイルが root のものに見える。VFAT は、ファイルごとの持ち主とパーミッションを持たない（第5章）。持ち主はマウントしたときに決まる（マウントした人か、uid=（持ち主にするユーザの番号）・umask=（落とす権限。主題1.02 第2章）などのオプションで決める。第4章で /boot/efi が root にしか読めなかったのは、/etc/fstab の umask=0077 のためである）。

たとえ: user は、図書館の貸し出し用の個室の鍵を利用者に渡すことに近い。決められた部屋（/etc/fstab に書いた行）だけは、利用者が自分で開け閉めできる。書いていない部屋の鍵は渡らない。
ただし崩れる点: 個室なら持ち込める物は限られるが、マウントは持ち込まれたメディアの中身しだいで、危ないプログラムや装置のファイルも入ってくる。だから user を付けると、nosuid・nodev・noexec が自動で付き、中のものに root の権限や装置を渡さない。
オプション意味何のためにあるか
defaultsrw・suid・dev・exec・auto・nouser・async（書き込みをまとめて後で行う。速さのため）をまとめた既定ふつうのディスクに、特別なことをしないとき
noauto起動のときと mount -a ではマウントしないいつも入っているとは限らないメディア（CD・USB メモリ）
user一般ユーザがマウントできる。外せるのはマウントした本人と root。nosuid・nodev・noexec が付く利用者に自分のメディアを使わせる
users一般ユーザがマウントでき、誰でも外せる。nosuid・nodev・noexec が付くみんなで使う装置（共用の光学ドライブなど）
noexec中のプログラムを実行させない持ち込まれたメディアのプログラムを動かさない
nosuid・nodev中の SUID ビット（実行した人ではなく、ファイルの持ち主の権限で動かす印。主題1.02 第3章）を効かせない・中のデバイスファイルを使わせない持ち込まれたメディアで root の権限や装置を奪われない
nofail見つからなくても起動を止めない外すことのあるディスク
ro・rw読み取り専用・読み書き書き換えさせたくないもの・ふつうのもの

USB メモリは抜いておく。

$ virsh detach-device linuc ~/vm/extra/usb-a.xml
Device detached successfully
手を動かす: 実践編の演習06は、student が /media/cdrom を自分でマウント・アンマウントできるようにする課題である。 判定は student として実際に mount と umount を打って確かめる。この章のとおりに打った人は、もう達成している。

再起動して確かめる

この節で分かること: 書いた行が、起動のときに本当に効くこと。

練習機を再起動する。reboot は再起動のコマンドである。

$ sudo reboot
Broadcast message from root@linuc on pts/1 (Tue 2026-10-20 23:44:39 JST):

The system will reboot now!

Connection to 127.0.0.1 closed by remote host.
Connection to 127.0.0.1 closed.

Broadcast message は「再起動する」というお知らせで、ログインしている全員の端末に出る（日時はあなたの画面では違う）。練習機が止まるので ssh が切れ（Connection to 127.0.0.1 closed by remote host.）、その端末は外（lab@host）に戻る。実際の画面では、お知らせのあとに練習機のプロンプトが一度出て、その後ろに Connection to … が続く（上の記録では、そのプロンプトを除いてある）。20 秒ほど待ってから、同じ端末で起動し終わるのを待ち（vm start は、動いている練習機なら起動し終わるまで待つだけ）、入り直す。すぐに打つと、止まりかけの練習機に入ってしまい、また切れることがある。

$ vm start
練習機はもう動いています
  起動中… 10秒（KVM なしの完全エミュレーションなので 40〜90 秒かかります）
練習機が起動しました（16秒）
  入るには:  ssh linuc   （抜けるときは exit）
$ ssh linuc
  LinuC 練習機（Ubuntu 24.04 / 仮想マシン）
  - 採点は外のコンテナが持っています。この中でも lab check NN で答え合わせできます
  - 管理用の NIC（enp0s16）を止めると ssh が切れます。そのときは外で vm console

Last login: Tue Oct 20 23:38:57 2026 from 10.0.2.2
$ findmnt -o TARGET,SOURCE,FSTYPE /srv/home
TARGET    SOURCE    FSTYPE
/srv/home /dev/vdb6 ext4
$ ls /srv/home
lost+found  test
$ findmnt -o TARGET,SOURCE,FSTYPE /media/cdrom
$ df -h /boot
Filesystem      Size  Used Avail Use% Mounted on
/dev/vda16      881M  181M  639M  23% /boot

/srv/home は起動のときにマウントされていて、remount の節で作った test も残っている。noauto の /media/cdrom はマウントされていない（findmnt が何も出さない）。/boot は練習機自身の vda16 で、ラベルを戻しておいたので取り違えは起きなかった。

確認

次の /etc/fstab の行の、各列の意味を答えよ。
UUID=1b2c3d4e-… /srv/home ext4 defaults,nofail 0 2

答え

UUID がこの値のファイルシステムを、/srv/home に、ext4 として、既定のオプションで（見つからなくても起動を止めずに）マウントする。dump はしない（0）。起動のときの fsck は 2 番目のグループ（/ の後）で行う。

確認

一般ユーザが CD-ROM を読み取り専用でマウントでき、マウントした人以外も外せるようにしたい。起動のときにはマウントしない。オプションの欄に何を書くか。

答え

ro,users,noauto（読み取り専用・誰でもマウントと取り外しができる・起動のときにマウントしない）。users も nosuid・nodev・noexec を一緒に付ける。user なら、外せるのはマウントした本人と root だけになる。

確認

/etc/fstab にディスクの行を書き足した。再起動の前にしておくとよいことを2つ挙げよ。

答え

sudo mount -a で実際にマウントできるかを試すことと、sudo findmnt --verify で書き間違い（見つからない UUID やラベル・種類の食い違いなど）を調べること。いま動いている systemd には sudo systemctl daemon-reload で読み直させる。ラベルの重なりは findmnt --verify では出ないことがあるので、blkid -t LABEL=… で確かめる。

この章で分かったこと

持ち帰ってほしいこと

  • /etc/fstab は6列（何を・どこに・種類・オプション・dump・fsck の順番）。書いただけではマウントされず、起動のときと mount -a と、mount にマウント先か装置の片方だけを渡したときに読まれる
  • 書いたら再起動の前に mount -a と findmnt --verify で確かめ、systemctl daemon-reload で systemd に読み直させる。nofail を付けると、見つからなくても起動を止めない
  • ラベルは重なりうる。重なると LABEL= の行が別のディスクを指す。blkid -t LABEL=…・/dev/disk/by-label/ で確かめ、e2label（XFS は xfs_admin -L）で付け替える。迷ったら UUID で指す
  • mount -o remount,ro で、外さずに読み取り専用に切り替えられる
  • 一般ユーザに許すのは user（本人が外せる）・users（誰でも外せる）で、どちらも nosuid・nodev・noexec を付ける。取り外せるメディアには noauto。VFAT の持ち主は、マウントしたときに決まる
