5. ファイルシステムの種類と作り方

第4章では、vdb を GPT で6つに区切った（ESP・/boot・スワップ・/・/var・/home のつもり）。この章では、それぞれの区画に用途に合った種類のファイルシステムを作り、作ったファイルシステムが区画より小さく見える理由と、種類ごとの違いを確かめる。

前提: 第4章まで読了前提: vdb が第4章の6つの区画になっている所要 22分影響度 B出題範囲 1.05.3（重要度4）最終検証 2026-10-20

この章のゴール

  • mkfs で ext3・ext4・XFS・VFAT・Btrfs を作り分けられ、ラベルを付けられる（mkfs -t 種類 と mkfs.種類 の関係も言える）
  • df の Size・Used・Avail の関係を説明でき、ext4 の予約ブロックを tune2fs で読んで変えられる
  • 5つの種類が何に向いているかを言える
ここで覚えなくていいこと: 管理情報の内部の形は扱わない。mkfs の細かいオプション（ブロックの大きさなど）も扱わない。ファイルシステムの検査と修復（fsck・xfs_repair）は、Version 10.0 の出題範囲では 101 ではなく 201 試験に入っているので扱わない。

種類ごとに mkfs で作る

この節で分かること: 5種類のファイルシステムの作り方と、作ったときに何が決まるか。

第2章の mkfs.ext4 は ext4 を作る道具だった。種類ごとに道具がある。

$ ls /sbin/mkfs*

mkfs は入口で、-t で種類を渡すと、その種類の道具（mkfs.種類）を呼ぶ。mkfs -t ext4 と mkfs.ext4 は同じものを動かす。

種類を並べる前に、1つ言葉を足す。ジャーナルは、書き込みの予定を先に記録しておき、途中で電源が切れても、記録を見て管理情報の食い違いを直せるようにする仕組みである。ext3・ext4・XFS が持つ。この章で作る5種類を、用途と一緒に並べる。

種類作るコマンド何に向いているかこの章で置く区画
VFAT（FAT32）mkfs.vfat -F 32Windows・カメラ・USB メモリと共通に読み書きする。ESP はこれで作る決まりvdb1（ESP）
ext3mkfs -t ext3ext2（ext 系のジャーナルを持たない古い版）にジャーナルを足したもの。古いシステムとの互換のためvdb2（/boot）
XFSmkfs.xfs大きなファイルと、たくさんの同時の書き込みに強い。RHEL（Red Hat Enterprise Linux）系の既定vdb4（/）
Btrfsmkfs.btrfsスナップショット（ある瞬間の姿を残す）や、データの検査値（壊れていないかを確かめるための数）を自分で持つvdb5（/var）
ext4mkfs.ext4ext3 の後継。Ubuntu など多くのディストリビューション（Linux をまとめて配る形）の既定vdb6（/home）

ESP（vdb1）から始める。第4章で見たとおり、ここには第2章の ext4 の中身が残っている。wipefs は、区画に書かれたファイルシステムの印（signature）を探すコマンドで、装置の名前だけを渡すと、消さずに一覧を出す。

$ sudo wipefs /dev/vdb1
$ sudo mkfs.vfat -F 32 -n ESP /dev/vdb1
$ sudo wipefs /dev/vdb1

最初の wipefs の OFFSET の 0x438（1080 バイト目）は、ext4 の管理情報の中心であるスーパーブロック（大きさ・UUID・ラベル・「これは ext4 だ」という印を持つ）の中の、印の位置である。FAT を作ると、古い ext4 の印は無くなり、vfat の印に置き換わった。-F 32 は FAT32 にするオプション、-n はラベル（人が付ける、ファイルシステムの名前）を付けるオプションである。ラベルを付けるのは VFAT だけが -n で、ほかの種類は -L である。残りの4つを作る。

$ sudo mkfs -t ext3 -L NEWBOOT /dev/vdb2
$ sudo mkfs.xfs -L ROOT /dev/vdb4
$ sudo mkfs.btrfs -L VAR /dev/vdb5
$ sudo mkfs.ext4 -L HOME /dev/vdb6
$ lsblk -o NAME,FSTYPE,LABEL,UUID /dev/vdb

どの種類も、作ったときに UUID（このファイルシステムの番号）を決めて中に書き込んでいる。ext3・ext4・XFS・Btrfs の UUID は 128 ビットのでたらめな数（xxxxxxxx-xxxx-… の形）、VFAT は作った時刻から決まる 32 ビットの数（XXXX-XXXX の形）である。どちらも作るたびに変わるので、あなたの画面では違う値になる。vdb3 はスワップにする区画なので、ここでは作らない（第8章）。

出力の読み方を1つずつ。mkfs.xfs の表は XFS の管理情報の作り方で、ここで読むのは log の行の blocks=16384（ジャーナルに 4KiB × 16384 = 64MiB を使う）だけでよい。mkfs.btrfs は、作ったファイルシステムの性質を並べる。Metadata: DUP は管理情報を2重に持つという意味である。

たとえ: 第1章の倉庫で言えば、mkfs は倉庫を建てる工事、種類は建て方に近い。同じ広さの区画でも、棚の並べ方・帳簿の付け方・控えの持ち方が建て方ごとに違う。
ただし崩れる点: 本物の倉庫を建て替えれば古い荷物が壊れることは見れば分かるが、mkfs は前に何があっても聞かずに上書きする（mkfs.vfat は ext4 が残っていたのに何も言わなかった）。wipefs で先に印を見れば、何を壊すことになるかが分かる。

作ったファイルシステムの大きさを比べる

この節で分かること: df の3つの数の関係と、ext4 の予約。

ふつうこう考える

vdb6 は 390MiB の区画である。そこに作った ext4 なら、使える量はほぼ 390MiB だろう。少なくとも、df の Size から Used を引いた残りが、Avail（使える量）になるはずだ。

$ sudo mount /dev/vdb6 /mnt
$ df -h /mnt
$ df -m /mnt
だめな理由: Size が 390 より小さく、さらに Size − Used と Avail が 26MiB 合わない（df -m は MiB 単位の整数で出すオプション）。 Size が小さいのは、ext4 が区画の中に管理情報（ファイルの管理表やジャーナル）を置き、その分を除いて数えているから。 26MiB 合わない分の大半は、ext4 がroot のために 5% を取っておく（予約ブロック）からである。 ディスクがいっぱいになっても root と常駐のプログラム（デーモン）が書けるように、一般ユーザにはその分を Avail に見せない。 残りは、ext4 が自分の作業のために取り置く分である（下で確かめる）。

予約の量は ext4 の管理情報に書いてあり、tune2fs -l で読める（tune2fs は ext2・ext3・ext4 の設定を読んだり変えたりするコマンド）。ext4 自身の取り置きは、マウント中なら /sys/fs/ext4/<装置>/reserved_clusters に出ている。

$ sudo tune2fs -l /dev/vdb6 | grep -E "^(Block count|Reserved block count|Block size)"
$ cat /sys/fs/ext4/vdb6/reserved_clusters

root のための予約は 4909 ブロック × 4KiB ≈ 19MiB。ext4 自身の取り置きは 1996 ブロック × 4KiB ≈ 8MiB で、全体（99840 ブロック）の 2% に当たる（大きなファイルシステムでも 4096 ブロックまで）。2つを足すと、ほぼ 26MiB の差になる（df は MiB に丸めて出すので、1 くらいはずれる）。予約の割合は tune2fs -m で変えられる。作り直す必要は無く、マウントしたままでよい。データだけを置く区画として、1% にする。

$ sudo tune2fs -m 1 /dev/vdb6
$ df -m /mnt

Avail が 323 から 338 に増えた。予約を減らしてよいのはデータだけを置く区画で、/ や /var では残しておく（溢れたときに root が後始末をする余地になる）。

ついでに、df の別の数え方と、du を見ておく。

$ df -i /mnt
$ sudo du -sh /mnt
$ sudo umount /mnt

df -i は容量ではなく inode（ファイル1つにつき1つ要る管理情報。持ち主・権限・中身の場所を書く）の数を出す。ext4 は作ったときに inode の数が決まり（ここでは 99840 個）、使い切ると、容量が空いていてもファイルを作れなくなる。du は、見えるファイルを1つずつ足した量を出す（-s は合計だけ、-h は読みやすい単位）。作ったばかりの ext4 には lost+found しか無いので 20K である。df の Used（24K）はファイルシステムが自分で答える使用量で、数え方が違うので一致するとは限らない。

たとえ: 満員電車の乗務員用の扉に近い。乗客で埋まっても、乗務員が通る隙間だけは空けておく。乗客から見れば、その隙間は「無い」のと同じである。
ただし崩れる点: 扉は目に見えるが、ext4 の予約ブロックは df の Size にも Used にも出ず、Avail が小さいことでしか見えない。しかも乗務員（root）は、隙間が空いていれば乗客と同じ席にも座れる。

種類ごとの使える量を比べる

この節で分かること: 同じくらいの大きさの区画でも、種類によって Size・Used・Avail が違うこと。

VFAT（vdb1、100MiB）・XFS（vdb4、600MiB）・Btrfs（vdb5、400MiB）を、それぞれ別のマウントポイントにつないで、まとめて df で見る。mkdir に複数の名前を渡すと、まとめて作る。umount にも複数を渡せる。

$ sudo mkdir /mnt/esp /mnt/root /mnt/var
$ sudo mount /dev/vdb1 /mnt/esp
$ sudo mount /dev/vdb4 /mnt/root
$ sudo mount /dev/vdb5 /mnt/var
$ df -h /mnt/esp /mnt/root /mnt/var
$ sudo umount /mnt/esp /mnt/root /mnt/var
$ sudo rmdir /mnt/esp /mnt/root /mnt/var
種類区画この記録で見えたことなぜか
VFAT100MiBほぼ区画の大きさのまま使える管理情報が小さい（その代わり、持ち主や権限を持たない）
XFS600MiBSize がジャーナルの分（64MiB）小さく、作った直後から Used があるXFS は自分の作業のための予約を Used に数える
Btrfs400MiBSize は区画の大きさのままだが、Avail が少ない管理情報を2重（DUP）に持ち、その場所を先に取る
ext4390MiBSize が小さく、Avail はさらに予約の分だけ小さい管理情報を Size から除き、root の予約を Avail から除く

同じ大きさの区画でも、使える量はファイルシステムの種類で変わる。区画の大きさを決めるときは、この差の分を見込んでおく。

たとえ: 同じ広さの土地に建てた倉庫でも、壁の厚さ（管理情報）や事務所の広さ（予約）は建て方で違い、荷物を置ける床の広さが変わる。
ただし崩れる点: 倉庫なら壁の厚さは図面で前もって分かるが、ファイルシステムの差は種類と区画の大きさで変わり、作って df で見るまで正確には分からない。しかも XFS のように、使っていない予約を「使用中」と数える種類もある。

ext3 と ext4 の機能を比べる

この節で分かること: ext3 と ext4 が、同じ系統の中で何が違うか。

ext2・ext3・ext4 は同じ系統で、違いは使える機能である。dumpe2fs -h（ext 系の管理情報の見出しを出すコマンド）で、機能の一覧（features）を比べる。2>/dev/null は、エラーの出力（ここでは版の表示）を捨てる書き方である。

$ sudo dumpe2fs -h /dev/vdb2 2>/dev/null | grep -i features
$ sudo dumpe2fs -h /dev/vdb6 2>/dev/null | grep -i features

どちらも has_journal（ジャーナル）を持つ。ext2 にジャーナルを足したものが ext3 で、ext4 はさらに extent（大きなファイルを、続いた範囲でまとめて管理する）・64bit（大きなディスクを扱う）・metadata_csum（管理情報に検査値を付ける）などを足している。

種類特徴この章の記録で見えたこと
ext3ext2 ＋ ジャーナル。mke2fs -j（mke2fs は ext 系を作る本体の道具で、-j はジャーナルを付けるオプション）でも作れるfeatures に extent が無い
ext4ext3 の後継。extent・大きな容量。外してからなら縮めることもできるroot 用の予約 5%（tune2fs -m で変える）と、自分用の取り置き
XFS大きなファイル・同時の書き込みに強い。縮められないジャーナルを Size から除き、予約を Used に数える
VFATほかの OS と共通。持ち主とパーミッションを持たない。FAT32 は1ファイル 4GiB まで管理情報が小さく、ほぼ区画の大きさで使える
Btrfs書き込むたびに別の場所へ書く（コピーオンライト）。スナップショット・検査値を持つ管理情報を2重（DUP）に持つ
手を動かす: 実践編の演習04は、5種類のファイルシステムを作り、vdb6 の予約を 1% にする課題である。 判定は各区画の印と、ext4 の管理情報を直接読んで確かめる。この章のとおりに打った人は、もう達成している。
確認

mkfs -t ext4 /dev/sdb1 と同じ意味になるコマンドを1つ挙げよ。ext3 を作るコマンドはどう書くか。

答え

mkfs.ext4 /dev/sdb1。mkfs は入口で、-t で渡した種類の道具（/sbin/mkfs.ext4）を呼ぶ。ext3 なら mkfs -t ext3・mkfs.ext3・mke2fs -j。

確認

ext4 の df で、Size − Used より Avail が小さい。何が原因か。データだけを置く区画で、その差を減らすコマンドは何か。

答え

大半は root のための予約ブロック（既定で 5%）で、一般ユーザに見せる Avail から除かれている。量は tune2fs -l の Reserved block count で読め、tune2fs -m 1 /dev/… で 1% に減らせる（この章でやった）。残りは ext4 が自分の作業のために取り置く分（reserved_clusters）で、tune2fs では消せない。

確認

容量はまだ空いているのに、ext4 の区画で「No space left on device」と言われてファイルを作れない。何を確かめるか。

答え

df -i で inode の残り（IFree）を確かめる。ext4 は作ったときに inode の数が決まり、小さなファイルをたくさん作って使い切ると、容量が空いていても新しいファイルを作れない。

この章で分かったこと

持ち帰ってほしいこと

  • mkfs は入口で、mkfs -t 種類 = mkfs.種類。作ると UUID が決まり、ラベルは -L（VFAT は -n）で付ける。前の中身は聞かずに上書きされる（wipefs で先に印を見られる）
  • ファイルシステムは区画の中に管理情報を置くので、df の Size は区画より小さい。どれだけ小さいかは種類で違う
  • ext4 は root 用に 5% を予約し、さらに自分の作業用に取り置く。Avail はその分小さい。予約は tune2fs -l で読み、tune2fs -m で変える
  • df -i は inode の数、du はファイルを足した量で、df の Used とは数え方が違う
  • ext3 = ext2 ＋ ジャーナル、ext4 はその後継。XFS は縮められず、Btrfs はコピーオンライトでスナップショットを持ち、VFAT はほかの OS と共通で持ち主を持たない
