8. スワップと、メモリの上のファイルシステム（tmpfs）

第7章では、/etc/fstab に書いて起動のたびにマウントし、再起動して確かめた。この章では、第4章で切った vdb3（種類 Linux swap）をメモリの逃げ場（スワップ）にして起動のたびに使われるようにし、逆にメモリの上に置くファイルシステム（tmpfs）を作ってみる。

この章のゴールと前提所要 18分
前提: 第7章まで読了前提: 練習機の中にいる所要 18分影響度 B出題範囲 1.05.2（重要度4）出題範囲 1.05.3（重要度4）最終検証 2026-10-20

この章のゴール

  • mkswap・swapon・swapoff の役割を言い分けられ、スワップを区画でもファイルでも作れる
  • 起動のたびに使うスワップを /etc/fstab に書き、再起動せずに確かめられる
  • メモリの上に tmpfs を作り、size= に実際のメモリより大きな値を書いたらどうなるかを確かめ、size= の意味を言える
ここで覚えなくていいこと: スワップの使われやすさの調整（vm.swappiness）は扱わない。メモリを圧縮して使う仕組み（zram・zswap）と、休止（ハイバネート）の設定も扱わない。スワップをどれくらいの大きさにするかは、本文の1行の目安だけでよい。

スワップを作って使い始める

この節で分かること: スワップを使えるようになるまでの段階と、それぞれのコマンド。

メモリは、いま動いているプログラムとそのデータを置く場所で、速いが量が限られ、電源を切ると消える。スワップは、メモリが足りなくなったときに、しばらく使われていない中身をディスクに書き出しておく領域である。free はメモリとスワップの使い方を出すコマンドで、-h は読みやすい単位にする。

$ free -h
列意味
total全部の量
used・free使っている量・まったく使っていない量
shared複数のプログラムで共有している量（tmpfs の中身もここに入る。この章の後半）
buff/cacheディスクの読み書きを速くするために、メモリに置いてある写し（必要になれば手放す）
available新しいプログラムが使える量の見積もり（free に、手放せる buff/cache を足したもの）

Swap の行が 0B で、練習機にはまだスワップが無い（第4章で見たとおり、練習機のディスクにはスワップの区画が無い）。数は人によって少し違う。vdb3 をスワップにする。mkswap は、区画をスワップの形にするコマンドである（ファイルシステムの mkfs に当たる）。

$ sudo mkswap -L SWAP /dev/vdb3
$ free -h

mkswap は UUID を決めて書き（-L でラベルも付けた）、大きさを出した。それでも Swap は 0B のままである。mkswap はスワップの形を作るだけで、使い始めるのは swapon である。

$ sudo swapon /dev/vdb3
$ swapon --show
$ cat /proc/swaps
$ swapon -s
$ free -h

使っているスワップは、swapon --show・/proc/swaps（カーネルが今のスワップの一覧を見せているファイル）・swapon -s（/proc/swaps と同じ形）で見られる。free の Swap の行も 255Mi になった。PRIO は優先度で、指定しなければカーネルが負の数を付ける（後から使い始めたものほど小さい）。

スワップは区画でなくても、ファイルでも作れる。dd で 128MiB のファイルを作る（/dev/zero は読むたびに 0 を返す装置のファイル）。

$ sudo dd if=/dev/zero of=/swapfile bs=1M count=128 status=none
$ ls -l /swapfile
$ sudo mkswap /swapfile

mkswap が insecure permissions 0644, fix with: chmod 0600 /swapfile（パーミッションが危ない。600 にせよ）と注意した。スワップにはメモリの中身（パスワードを含むかもしれない）が書き出されるので、root 以外に読めてはいけない。直してから使い始める。-p 10 は優先度を 10 にするオプションである。

$ sudo chmod 600 /swapfile
$ sudo swapon -p 10 /swapfile
$ swapon --show
$ sudo swapoff /swapfile
$ sudo rm /swapfile

スワップが2つ並び、PRIO は 10 と -2 になった。カーネルは優先度の数が大きいほうから使う。swapoff は使うのをやめるコマンドで（中に書き出していたものはメモリに戻す）、やめてからファイルを消した。

コマンドすること何のためにあるか
mkswap 区画かファイルスワップの形を作る（-L でラベル）区画やファイルを、スワップとして使える形にする
swapon 区画かファイル使い始める（-p で優先度）いまからメモリの逃げ場にする
swapon -a/etc/fstab のスワップを全部使い始める起動のときと同じことを、その場で起こす
swapon --show・swapon -s使っているスワップの一覧（/proc/swaps）どれが・どれだけ使われているかを見る
swapoff 区画かファイル使うのをやめる（-a で全部）外す・消す前に、中身をメモリに戻す
たとえ: スワップは、机（メモリ）の横に置く段ボール箱に近い。机に載り切らない書類を、しばらく使わないものから箱に移す。mkswap は箱を組み立てること、swapon は箱を机の横に置くことである。
ただし崩れる点: 段ボール箱は組み立てた時点で使えるが、スワップは mkswap だけでは1バイトも使われない（free が 0B のままだった）。swapon で置いて初めて、机の延長になる。
たとえ: 箱が2つあるときは、手の届く近い箱（優先度の高いほう）から詰めていくのに近い。近い箱がいっぱいになってから、遠い箱を使う。
ただし崩れる点: 人なら同じ距離の箱が2つあればどちらか一方から詰めるが、カーネルは優先度が同じスワップには交互に書く。速さの同じディスクを同じ優先度にすると、両方へ分けて書ける。

起動のたびに使う

この節で分かること: スワップの /etc/fstab の行の書き方と、再起動せずに確かめる方法。

起動のたびに使うスワップも、/etc/fstab に書く（第7章）。マウントポイントの列は none、種類は swap、オプションは慣習で sw と書く。装置の名前ではなく、mkswap が書き込んだ UUID で指す（スワップは中身を上書きして使うので、取り違えると、そこにあったデータが壊れる）。

$ echo "UUID=$(sudo blkid -s UUID -o value /dev/vdb3)  none  swap  sw  0  0" | sudo tee -a /etc/fstab
$ sudo systemctl daemon-reload
$ sudo swapoff /dev/vdb3
$ swapon --show
$ sudo swapon -a
$ swapon --show

いったん swapoff で外すと swapon --show は何も出さず、swapon -a（/etc/fstab のスワップを全部使い始める）で戻った。起動のときにも、これと同じことが起きる。外してから -a で戻ってくれば、書いた行が効いていると、再起動せずに確かめられる。

手を動かす: 実践編の演習07は、vdb3 をスワップにして、起動のたびに使われるように /etc/fstab に UUID で書く課題である。 判定は、いま vdb3 が使われているか（swapon --show と同じもの）と、/etc/fstab の行が vdb3 を指しているかを見る（状態は変えない）。この章のとおりに打った人は、もう達成している。

tmpfs — メモリの上のファイルシステム

この節で分かること: tmpfs の size= が何を意味するか。

tmpfs は、ディスクではなくメモリの上に置くファイルシステムである。速いが、外すか再起動すると中身は消える。第1章の df -h に出ていた tmpfs の行がこれで、練習機でもすでにいくつか使われている。findmnt の -t は、種類で絞るオプションである。

$ findmnt -t tmpfs -o TARGET,FSTYPE,SIZE
$ free -m

メモリは全部で 1424MiB しかない（free -m は MiB の整数で出す）。ここに 4GiB の tmpfs を作る。mount の -t は種類を指定するオプションで、-o size=4G は大きさである。tmpfs には装置が無いので、装置の名前の欄には何を書いてもよく、ふつうは tmpfs と書く。

ふつうこう考える

tmpfs はメモリの上に置くのだから、size=4G と書けばメモリを 4GiB 取るはずだ。メモリが 1.4GiB しかないこの練習機では、マウントできないか、できてもメモリが足りなくなるだろう。

$ sudo mkdir /mnt/ram
$ sudo mount -t tmpfs -o size=4G tmpfs /mnt/ram
$ df -h /mnt/ram
$ free -m
だめな理由: マウントでき、df には 4.0G と出て、free の数字はほとんど動かない。 tmpfs の size は上限で、作った時点ではメモリを1バイトも取らない。書いた分だけ、その場でメモリを使う。 だから実際のメモリより大きな size も書けてしまう。

300MiB 書いてみる。

$ sudo dd if=/dev/zero of=/mnt/ram/fill bs=1M count=300 status=none
$ free -m
$ df -h /mnt/ram
$ sudo umount /mnt/ram
$ free -m
$ sudo rmdir /mnt/ram

書いた 300MiB は free の shared に出て、available がその分減った。外すと、中身ごと消えてメモリが戻る。メモリが足りなくなれば、tmpfs の中身もスワップに書き出される。

tmpfsスワップ
置き場所メモリ（足りなければスワップへ）ディスク
作り方mount -t tmpfs -o size=… tmpfs 場所mkswap → swapon
大きさの意味上限。書いた分だけメモリを使うディスクの上に取った大きさ
再起動すると中身は消える中身は意味を持たない（/etc/fstab にあれば、また使い始める）
何のためにあるか速く読み書きしたい一時的なファイル（/run・/dev/shm）メモリが足りないときの逃げ場
たとえ: tmpfs はホワイトボードに近い。広さの上限は決まっているが、インク（メモリ）は書いた分しか減らず、消せば跡形も無い。
ただし崩れる点: ホワイトボードは部屋の壁より大きくできないが、tmpfs の size は実際のメモリより大きく書けてしまう。そのまま書き続けると、メモリとスワップを使い切る。size は「確保」ではなく「ここまで」という約束でしかない。
確認

mkswap /dev/sdb2 を実行したが、free の Swap が 0B のまま。何が足りないか。起動のたびにも使うにはどうするか。

答え

swapon /dev/sdb2 で使い始める（mkswap は形を作るだけ）。起動のたびにも使うには、/etc/fstab に UUID=… none swap sw 0 0 の行を書く。swapon -a で、その行が効くかを再起動せずに確かめられる。

確認

スワップが2つあり、swapon --show の PRIO が 10 と -2 だった。どちらから使われるか。

答え

数の大きい 10 のほうから使われる。優先度は swapon -p で付ける（この章でやった）。付けなければカーネルが負の数を付ける。

確認

メモリが 2GiB のマシンで mount -t tmpfs -o size=8G tmpfs /mnt/t を実行した。マウントできるか。マウントした直後のメモリの使用量はどうなるか。

答え

マウントできる。size は上限なので、直後のメモリの使用量はほとんど変わらない。書き込んだ分だけメモリを使い、外すか再起動すると中身は消える。

この章で分かったこと

持ち帰ってほしいこと

  • スワップは、メモリが足りないときに中身を書き出すディスクの領域。mkswap（形を作る）→ swapon（使い始める）→ swapoff（やめる）。mkswap だけでは使われない
  • 使っているスワップは swapon --show・swapon -s・/proc/swaps・free で見る。優先度は数の大きいほうから使う
  • スワップはファイルでも作れる。パーミッションは 600 にする（mkswap が注意する）
  • 起動のたびに使うものは /etc/fstab に UUID=… none swap sw 0 0。swapoff してから swapon -a で、再起動せずに確かめられる
  • tmpfs はメモリの上のファイルシステム。size= は上限で、書いた分だけメモリを使い、外すか再起動すると消える
