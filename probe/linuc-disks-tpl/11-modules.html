11. ドライバと、USB メモリの抜き差し

第10章では、部品の情報を /proc・/sys・/dev から読み、lspci -k で装置を動かしているドライバの名前を見て、udev の規則を1行書いた。この章では、そのドライバ（カーネルモジュール）が、いつ・誰によって読み込まれるのかを、CD のマウントと USB メモリの抜き差しで確かめ、USB メモリを挿しても使えないようにする設定まで行う。最後に、全11章を1つの事実でまとめる。

前提: 第10章まで読了前提: 練習機の中にいる・外の端末もある所要 28分影響度 B出題範囲 1.05.1（重要度3）最終検証 2026-10-20

この章のゴール

  • lsmod・modinfo・modprobe・insmod・rmmod の役割を言い分けられる
  • USB メモリを挿したとき、カーネル・udev・modprobe の誰が何をするかを順に言える
  • ドライバを外すだけでは次に挿したとき戻ることを説明でき、/etc/modprobe.d/ で読み込ませないようにできる
ここで覚えなくていいこと: モジュールに渡すパラメータ（options の行）は扱わない。udev の規則の書き方の全体と、D-Bus のメッセージの形も扱わない。depmod が作る索引のファイルの中身も扱わない。

読み込まれているドライバを見る

この節で分かること: カーネルの部品のうち、後から読み込まれたものと、最初から組み込まれているもの。

Linux のドライバの多くはカーネルモジュール（カーネルに後から読み込める部品）の形で配られていて、必要になったときに読み込まれる。いま読み込まれているものは lsmod で見る（中身は /proc/modules を整えて出したもの）。

$ lsmod | grep -E "^(Module|ahci|libahci) "

全部で数十個あるので、見出しと、第10章の lspci -k で見た SATA のコントローラのドライバ ahci だけを出した。Module が名前、Size が大きさ、Used by が「いくつのものに使われているか」と、使っているモジュールの名前である（libahci は ahci に使われている。ahci の 1 は、ahci が受け持つ sda を第9章の LVM がいま使っているからで、モジュールでない使い手は数だけが出る）。では、ずっと使ってきた ext4・vfat と、光学ドライブのドライバ sr_mod はどうか。

$ lsmod | grep -E "^(ext4|vfat|sr_mod) "

lsmod には1つも無い（grep が何も出さない）。この練習機（Ubuntu のカーネル）では、それらは最初からカーネルに組み込まれているからである。組み込みの一覧は、カーネルの版ごとのディレクトリの modules.builtin というファイルにある。uname -r は、いま動いているカーネルの版を出すコマンドで、ディレクトリの名前はこの版になっている。

$ uname -r
$ grep -E "/(vfat|ext4|sr_mod)\.ko" /lib/modules/$(uname -r)/modules.builtin

$(uname -r)（第7章の、コマンドの出力をその場に埋め込む書き方）は 6.8.0-142-generic に置き換わり、3つとも組み込みの一覧に載っていた（何を組み込むかはディストリビューションしだいで、RHEL 系では ext4 もモジュールになっている）。組み込みの部品は lsmod に出ず、外すこともできない。

modprobe と insmod

この節で分かること: 同じ「読み込む」でも insmod と modprobe で何が違うか。

モジュールは、ほかのモジュールに頼っていることがある（依存）。DVD や BD のファイルシステムを読む udf で確かめる。modinfo はモジュールの説明を出すコマンドで、-F depends は依存だけを出す。

$ modinfo -F depends udf

udf は crc-itu-t に頼っている。insmod は、モジュールのファイルをパスで渡して1つ読み込むコマンドである。モジュールのファイルは /lib/modules/<カーネルの版>/ の下にある（Ubuntu は zstd という形式で圧縮した .ko.zst の形で配る）。

$ sudo insmod /lib/modules/$(uname -r)/kernel/fs/udf/udf.ko.zst
$ sudo dmesg | grep "Unknown symbol"

Unknown symbol in module（知らない名前がある）で失敗した。dmesg（カーネルが出したメッセージを読むコマンド）から、その知らせの行を探すと、udf が使う関数（プログラムの中の、名前の付いた部品）crc_itu_t を持つモジュールが、まだ読み込まれていなかったと分かる（左の数字は起動からの秒数で、人によって違う）。insmod は、渡されたファイルを1つ読み込むだけで、依存を解決しない。modprobe は、名前でモジュールを探し、依存を先に読み込む。-v で何をしたかが出る。

$ sudo modprobe -v udf
$ lsmod | grep -E "^(udf|crc_itu_t) "
$ sudo modprobe -rv udf

modprobe の中身は「依存の順に insmod を並べたもの」だった。lsmod の Used by に、crc_itu_t は udf に使われていると出ている。modprobe -r は外すオプションで、外したあとで使われなくなった依存もまとめて外す。依存の一覧は /lib/modules/<版>/modules.dep にあり、depmod というコマンドが作る。

コマンドすること依存何のためにあるか
lsmod読み込まれているモジュールの一覧（/proc/modules）Used by 列で見えるいま何が読み込まれているかを見る
modinfo 名前説明・ファイルの場所・依存・別名（alias）を出す-F depends で依存だけ読み込む前に、何者かを調べる
modprobe 名前名前で探して読み込む解決するふつうの読み込み
modprobe -r 名前外す使われなくなった依存も外すふつうの取り外し
insmod ファイルファイルを1つ読み込む（パスで渡す）解決しない自分で作ったモジュールなどを、そのファイルのまま試す
rmmod 名前1つ外す使われていれば断る1つだけを確実に外す

モジュールは、要るときに読み込まれる

この節で分かること: 誰も modprobe を打たなくても、モジュールが読み込まれる場面。

CD のファイルシステム（iso9660）を読むドライバ isofs で確かめる。第7章の再起動の後、この章まで CD はマウントしていない。ただ、第7章の後で演習06 の判定（student が CD をマウントする）を打った人は、そのときに読み込まれているので、先に外しておく（読み込まれていなければ、modprobe -r は何も言わずに終わる）。

$ sudo modprobe -r isofs
$ lsmod | grep isofs
$ sudo mount /dev/sr0 /mnt
$ lsmod | grep isofs
$ sudo umount /mnt

マウントする前は無く（grep が何も出さない）、マウントした後は読み込まれている。あなたは modprobe を打っていない。カーネルが「iso9660 を読む部品が要る」と気づいて、自分で modprobe を呼んだのである。呼ぶプログラムの場所は、ここに書いてある。

$ cat /proc/sys/kernel/modprobe

USB メモリを挿すと、誰が何をするか

この節で分かること: 挿してからディスクになるまでの、カーネルと udev の役割分担。

電源を入れたまま装置を抜き差しすることをホットプラグという。USB はそれが前提の規格である。第6章では挿すとすぐ /dev/sdb ができたが、その間に何が起きていたかを見る。練習機の中の端末で、装置の出入りの知らせを見張る。udevadm monitor は、カーネルと udev が出す知らせを流し続けるコマンドで、--subsystem-match で USB とブロック（ディスク）の知らせだけに絞る。timeout 30 を前に付けたので、30 秒たつと自分で終わる。

$ sudo timeout 30 udevadm monitor --subsystem-match=usb --subsystem-match=block

見張っているあいだに（30 秒以内に）、外の端末で A を挿す。

$ virsh attach-device linuc ~/vm/extra/usb-a.xml

練習機の中の端末に、上のように知らせが流れ、30 秒たつとプロンプトに戻る。同じ出来事が2回ずつ出ている。KERNEL はカーネルが出した知らせ（uevent）、UDEV はそれを受けた udev が規則を当て終えたあとの知らせである。カーネルが USB の装置を見つけ（add … (usb)）、ドライバが付き（bind）、その結果ディスク sdb ができた（add … block/sdb (block)）。角かっこの数字は起動からの秒数で、人によって違う。

$ lsusb
$ lsusb -t
$ lsblk -d -o NAME,TRAN,RM,SIZE,SERIAL
$ lsmod | grep -E "usb_storage|uas"
$ sudo dmesg | grep -E "usb-storage|registered new interface"

lsusb に USB メモリ（QEMU USB HARDDRIVE）が出て、lsusb -t では Driver=usb-storage が付いている（Device の番号は、それまでに挿した回数で変わる）。ディスク sdb は、USB でつながり（TRAN が usb）、取り外せる（RM が 1）。そして、あなたは何も読み込んでいないのに、usb_storage と uas の2つが読み込まれた。dmesg の usbcore: registered new interface driver usb-storage がその瞬間である（上の2行の usbfs・hub は、起動したときに組み込みの部品が名乗った行。第7章の再起動の後に lab check 10 か、引数なしの lab check を打った人は、判定が USB メモリを1本挿したので、そのときの行も出る）。

外したドライバは、戻ってくる

この節で分かること: 「ドライバを外す」が「装置を使えなくする」にならない理由。

USB メモリのドライバを外す。

$ sudo modprobe -r usb_storage
$ sudo rmmod usb_storage
$ sudo modprobe -r uas
$ lsmod | grep -E "usb_storage|uas"
$ lsblk -d -o NAME,TRAN,SIZE,SERIAL
$ lsusb -t

usb_storage は uas に使われているので、単独では外せない（modprobe は is in use、rmmod は in use by: uas）。uas を外すと、使われなくなった usb_storage も一緒に外れた。ディスク sdb は消え、USB の装置は lsusb -t に残って Driver=[none]（ドライバ無し）になった。装置はバスの上にいる。使う人（ドライバ）がいなくなっただけである。

ふつうこう考える

ドライバを外したのだから、この USB メモリはもう使えない。抜いて挿し直しても、誰かがもう一度 modprobe しない限りディスクにはならないはずだ。

$ virsh detach-device linuc ~/vm/extra/usb-a.xml
$ virsh attach-device linuc ~/vm/extra/usb-a.xml
$ lsmod | grep -E "usb_storage|uas"
$ lsblk -d -o NAME,TRAN,SIZE,SERIAL
だめな理由: 2つとも戻り、sdb もできている。読み込んだのは udev である。 挿した瞬間にカーネルが知らせを出し、udev はその知らせに書かれた装置の種類（modalias）を見て、 当てはまるドライバを modprobe と同じしくみで読み込む。rmmod や modprobe -r が止めたのは「いま」だけで、 次に装置が来たときに読み込む流れには触れていない。

その流れを確かめる。装置は自分の種類を、/sys の modalias というファイルに出している。modprobe --resolve-alias は、その種類に当てはまるモジュールの名前を出す。modinfo の出力は長いので、grep -m3（見つかった最初の3行だけ）で別名の行を3つに絞り、udev の規則のファイルは grep -n（行の番号を付けて出す）で探す。

$ cat /sys/bus/usb/devices/2-1:1.0/modalias
$ modprobe --resolve-alias $(cat /sys/bus/usb/devices/2-1:1.0/modalias)
$ modinfo usb_storage | grep -m3 alias
$ grep -n "kmod load" /usr/lib/udev/rules.d/80-drivers.rules | head -1

modalias の ic08isc06ip50 は「種類 08（大容量記憶）・サブクラス 06（SCSI の命令を使う）・プロトコル 50（Bulk-Only。USB メモリのふつうのデータの送り方）」という意味で、usb_storage の別名（alias）の1つと一致する。この別名は uas にも当てはまるので、2つとも読み込まれた。udev の規則の5行目は「MODALIAS を持つ装置なら、それでドライバを読み込め」と書いてある（第10章で規則の置き場所を見た /usr/lib/udev/rules.d/ の中のファイル）。

たとえ: 荷物の受付係に近い。届いた荷物の伝票（modalias）を読み、規則の表どおりの担当（ドライバ）を呼ぶ。担当を一度帰らせても、次の荷物が来れば受付係がまた呼ぶ。
ただし崩れる点: 受付係は伝票に合う担当を1人選ぶが、udev は当てはまる担当を全員呼ぶ。だから USB メモリ1本で uas と usb_storage の2つが来た。

止めるには、読み込む側の表に書く

この節で分かること: /etc/modprobe.d/ の書き方と、それが効く範囲・効き始めるとき。

モジュールを読み込むときの設定は、/etc/modprobe.d/ の下の .conf のファイルに書く。Ubuntu には最初からいくつかある。起動のたびに読み込むモジュールを書いていた /etc/modules は、いまは /etc/modules-load.d/ に置き換わっている。

$ ls /etc/modprobe.d/
$ cat /etc/modules

教科書どおり、blacklist（「別名で探したとき、この名前を候補から外す」）を新しいファイルに書いて、挿し直す。

$ echo "blacklist usb_storage" | sudo tee /etc/modprobe.d/lab-usb.conf
$ sudo modprobe -r uas
$ virsh detach-device linuc ~/vm/extra/usb-a.xml
$ virsh attach-device linuc ~/vm/extra/usb-a.xml
$ lsmod | grep -E "usb_storage|uas"
$ modprobe --show-depends uas

止まらない。blacklist で外れたのは usb_storage だけで、uas は候補に残って読み込まれた。modprobe --show-depends（読み込むときに何をするかを、読み込まずに出す）で分かるとおり、uas は usb_storage に依存しているので、usb_storage は依存として読み込まれた。依存には blacklist が効かない。では uas も書けばよい。同じファイルを書き換えて、挿し直す（printf の \n は改行）。

$ printf "blacklist usb_storage\nblacklist uas\n" | sudo tee /etc/modprobe.d/lab-usb.conf
$ sudo modprobe -r uas
$ virsh detach-device linuc ~/vm/extra/usb-a.xml
$ virsh attach-device linuc ~/vm/extra/usb-a.xml
$ lsmod | grep -E "usb_storage|uas"

まだ止まらない。今度の理由は書き方ではなく、読む側が書き換えに気づいていないことである。udev（systemd-udevd というプログラムとして動いている）は、/etc/modprobe.d にファイルが増えた・消えたことには自分で気づいて設定を読み直す。ところがすでにあるファイルの中身を書き換えたことには気づかず、前の中身のまま動く。読み直させる（練習機ごと再起動しても同じ）。

$ sudo systemctl restart systemd-udevd
$ sudo modprobe -r uas
$ virsh detach-device linuc ~/vm/extra/usb-a.xml
$ virsh attach-device linuc ~/vm/extra/usb-a.xml
$ lsmod | grep -E "usb_storage|uas"
$ lsusb -t
$ lsblk -d -o NAME,TRAN,SIZE,SERIAL

今度は止まった。USB の装置は見えている（Driver=[none]）が、ディスクにはならない。USB メモリは、ここで抜いておく（挿したまま次のようにドライバを読み込むと、ドライバがその USB メモリを使い始めるので、lsmod の Used by の数が記録を取るたびに 0〜2 と変わった）。

$ virsh detach-device linuc ~/vm/extra/usb-a.xml

ただし blacklist が外すのは「別名で探したとき」の候補だけで、名前を指定した modprobe は止めない。名前を指定しても止めたいなら install 名前 /bin/false（「この名前を読み込もうとしたら、代わりに /bin/false を実行せよ」。/bin/false は必ず失敗するコマンド）を使う。これは新しいファイルなので、udev は自分で気づく。

$ sudo modprobe usb_storage
$ lsmod | grep -E "usb_storage|uas"
$ sudo modprobe -r usb_storage
$ echo "install usb_storage /bin/false" | sudo tee /etc/modprobe.d/lab-usb-install.conf
$ sudo modprobe usb_storage
$ sudo insmod /lib/modules/$(uname -r)/kernel/drivers/usb/storage/usb-storage.ko.zst
$ lsmod | grep -E "usb_storage|uas"
$ sudo rmmod usb_storage

blacklist だけのときは、名前を指定した modprobe で読み込めた。install を書くと、modprobe は失敗した。ところが insmod では読み込めた。insmod はファイルを直接読み込むだけで、/etc/modprobe.d を読まないからである。最後の rmmod で外しておいた。

/etc/modprobe.d に書くもの止まる範囲何のためにあるか
（何も書かず rmmod・modprobe -r だけ）いま読み込まれている分だけ。挿し直すと戻るその場で一時的に外す
blacklist 名前別名（modalias）で探したときの候補から外す。名前を指定した modprobe と、依存としての読み込みは止まらない装置が来たときに自動で読み込まれないようにする
install 名前 /bin/falsemodprobe での読み込みは、udev からでも、手でも、依存としてでも失敗する。insmod は止まらない名前を指定した読み込みまで含めて止める

効き始めるときにも気を付ける。udev は /etc/modprobe.d にファイルを足した・消したことには気づくが、すでにあるファイルを書き換えたことには気づかない。書き換えたら systemctl restart systemd-udevd（か再起動）で読み直させる。このほか、ファームウェア（BIOS・UEFI）の設定画面で装置そのものを無効にする方法もあり、そのときは装置が lspci にも出なくなる（ファームウェアが Linux に装置を見せない）。

たとえ: 受付係の呼び出し禁止リストに近い。新しい紙を掲示板に足せば受付係は気づくが、貼ってある紙を書き直しても気づかない。しかも「usb_storage さんは呼ばない」と書いても、「uas さんを呼んだら、uas さんが usb_storage さんを連れてきた」なら止まらない。
ただし崩れる点: 人なら事情を話せば連れてこないが、カーネルの依存は機械的で、例外が無い。また、受付を通らずに裏口から入る人（insmod）は、どのリストにも止められない。
手を動かす: 実践編の演習10は、ここまでの状態（挿し直しても使えない）を作る課題である。 判定は外から判定専用の USB メモリを1本挿し、ディスクになるかを見てから抜く。設定ファイルの中身は読まない。この章のとおりに打った人は、もう達成している。

udev・sysfs・D-Bus の関係

この節で分かること: 出題範囲の「sysfs・udev・dbus」を1枚にまとめる。

ここまでに出てきた登場人物を並べる。デスクトップの Linux で USB メモリを挿すと、勝手にアイコンが出てマウントされるのは、この列の右端にもう2人いるからである（マウント先は Ubuntu・Debian では /media/<ユーザ>/、RHEL 系では /run/media/<ユーザ>/）。

カーネル ──知らせ（uevent）──▶ udev ─────────────▶ udisks2 ──D-Bus──▶ デスクトップの画面
  │                              │  規則を当てる       （この練習機には無い）   「開く」を押す
  │                              │  /dev/disk/by-* を作る      ▲                  │
  └─ /sys に装置を出す（sysfs）   └─ modprobe でドライバを       └──D-Bus でマウントを頼む┘
                                      読み込ませる       → /media/<ユーザ>/<ラベル> など

udisks2 は、ディスクの情報を集めて、マウントなどの操作をほかのプログラムから頼めるようにするプログラムである。D-Bus は、同じマシンの上のプログラムどうしが、問い合わせと知らせをやりとりする通り道である。udev 自身は D-Bus を使わないが、デスクトップの部品はみなここで話す。練習機でも、systemd やログインの管理が D-Bus の上で待ち受けている。busctl list は、D-Bus の上の名前の一覧を出すコマンドである（--no-pager は、less のような画面送りを使わずに全部を出すオプション。一覧は長いので、grep で5つに絞る）。

$ busctl list --no-pager | grep -E "^org\.freedesktop\.(systemd1|login1|hostname1|timedate1|network1)"

2列目はその名前を持つプロセスの番号（PID）、5列目は D-Bus が接続ごとに付ける番号で、どちらも人と起動のたびによって違う。(activatable) は「いまは動いていないが、問い合わせが来たら起動される」という意味である。この練習機には udisks2 が無いので、USB メモリを挿しても誰もマウントしない。だから第6章では手でマウントした。

たとえ: 会社の館内放送と内線電話に近い。udev が「荷物が届いた」と処理し、udisks2 がそれを館内放送（D-Bus）で流し、画面のプログラムが内線で「開けて」と頼む。
ただし崩れる点: 館内放送は誰でも流せるが、D-Bus は、誰がどの相手に何を頼めるかが設定で決まっている。一般ユーザの画面が「マウントして」と頼めるのも、その設定が許しているからである。

11章を貫いている1つの事実

この節で分かること: 11の「予想が外れたこと」が、同じ1つのことから出ていたこと。

このコースで外れた予想を並べる。どれも、ディスクの上に重なった段のうち1つだけを見て、隣の段も一緒に動くと思ったところで外れている。

章外れた予想実際に読んでいた印動かなかった隣の段
1df に装置の名前を渡せば、その装置の空きが分かるマウントされているファイルシステムの一覧マウントされていない装置は数えない
2マウントしたら、そのディレクトリに書けるファイルシステムの中に書かれた持ち主と権限マウントポイントの権限は関係ない
3区画を消せば、中身も消える表の1行（始まりと大きさ）ext4 の中身はそのまま
4parted も、最後に書くまでは変わらない打った瞬間に書き換えた表中身はそのまま（作り直せば戻る）
5Size − Used が使える量ext4 の予約と、自分用の取り置き区画の大きさ ≠ 使える量
6/dev/sdb はいつも同じ USB メモリ中に書いたラベルと UUID名前は見つかった順で付く
7ラベルで指せば、いつも安全人が付けた名前（重なりうる）別のディスクが同じ名前を名乗れる
8tmpfs は size だけメモリを取る書いた量size は上限で、確保ではない
9LV を広げれば、使える量も増えるext4 が自分で書いた大きさ箱が広がっても中身はそのまま
10HDD か SSD かは、カーネルが測る装置の申告（rotational）中身のファイルは同じ種類
11ドライバを外せば、その装置は使えない装置の種類（modalias）と、udev・modprobe の表次に挿せば、表どおりに読み込まれる

ディスクは、装置・パーティションの表・（LVM）・ファイルシステム・マウントの段が重なってできている。各段は自分の印（装置の申告・表の行・UUID）だけを読み、隣の段を勝手には書き換えない。だから1つの段を変えたら、隣の段は自分で合わせる。名前や見かけの大きさは、どの段から見たかで変わる。

試験の問題も、この段のどこを尋ねているかで解ける。「区画を広げたのにファイルシステムが…」なら段をまたいでいないか、「起動のときにマウントされない」なら /etc/fstab の段か、を先に考える。

確認

依存するモジュールも含めて、モジュールを読み込むコマンドは何か。insmod では何が足りないか。

答え

modprobe。insmod はファイルのパスを渡されて1つ読み込むだけで、依存を解決しない（この章では Unknown symbol in module で失敗した）。modprobe は modules.dep を見て、依存を先に読み込む。

確認

rmmod usb_storage が Module usb_storage is in use by: uas で失敗した。どこを見れば前もって分かったか。どう外せばよいか。

答え

lsmod の Used by 列（usb_storage … 1 uas）。使っている側の uas を modprobe -r uas で外すと、使われなくなった usb_storage も一緒に外れる。

確認

/etc/modprobe.d/ に blacklist usb_storage と書いたのに、USB メモリを挿すと使えた。考えられる理由を2つ挙げよ。

答え

1つ目: blacklist は別名で探すときの候補から外すだけで、別のモジュール（uas）の依存として読み込まれるのは止めない。止めるなら uas も書くか、install usb_storage /bin/false にする。2つ目: すでにあるファイルを書き換えた場合、udev は書き換えに気づかず、前の中身のまま動いている（systemctl restart systemd-udevd か再起動が要る）。新しいファイルを足した・消した場合は、udev は自分で気づく。

確認

起動するたびに読み込みたいモジュールがある。どこに書くか。

答え

/etc/modules-load.d/ の下に .conf のファイルを置き、モジュールの名前を1行ずつ書く。古い /etc/modules もまだ読まれるが、練習機のファイル自身が「obsolete（廃止）」と書いている。

この章で分かったこと

持ち帰ってほしいこと

  • ドライバの多くはカーネルモジュールで、lsmod に出る。最初から組み込まれているもの（この練習機では ext4・vfat・sr_mod）は出ず、外せない
  • モジュールは、要るときに読み込まれる（CD をマウントすると isofs、USB メモリを挿すと usb_storage と uas）。読み込んだのはカーネルと udev で、あなたではない
  • insmod は依存を解決せず、modprobe は依存の順に読み込む。modprobe -r は使われなくなった依存も外す。rmmod は使われていれば断る
  • ドライバを外しても装置は lsusb・lspci に残る。次に挿せば、udev が装置の種類（modalias）に合うドライバをまた読み込む
  • 止めるのは /etc/modprobe.d/。blacklist は別名からの読み込みだけを止め、依存と名前を指定した modprobe は止めない。install 名前 /bin/false は modprobe を止めるが insmod は止めない。すでにあるファイルを書き換えたら udev を再起動する
  • sysfs は装置の情報、udev は装置の出入りの処理、D-Bus はプログラムどうしの通り道
