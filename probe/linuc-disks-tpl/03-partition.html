3. パーティションの表を読む・直す

第2章では、vdb を fdisk で区切って vdb1（200M）を作り、ext4 を作ってマウントし、memo.txt を書いてから外した。この章では、fdisk が書いた「表」を読み、表から区画を1つ消して作り直すと中身がどうなるかを確かめ、区画を5つ以上に分ける方法を見る。

前提: 第2章まで読了前提: 練習機の中にいる所要 24分影響度 B出題範囲 1.05.2（重要度4）出題範囲 1.05.3（重要度4）最終検証 2026-10-20

この章のゴール

  • fdisk -l の表示から、表の形式と、区画の位置（始まりと終わりのセクタ）・大きさ・種類を読める
  • 消す前の表を sfdisk -d で控え、区画を表から消して同じ位置に作り直したら中身がどうなるかを、自分で確かめられる
  • MBR の基本パーティション（プライマリパーティション）が4つまでの理由を説明でき、5つ目からを拡張パーティション・論理パーティションとして作れる
ここで覚えなくていいこと: CHS（シリンダ・ヘッド・セクタ）という古い位置の書き方は扱わない。区画の種類の番号は、この章の表の5つ（83・82・8e・5・ef）のほかは覚えなくてよい。論理パーティションをつなぐ小さな表（EBR）の細かい形も扱わない。

表を読む — fdisk -l

この節で分かること: fdisk -l の各行が何を表しているか。

fdisk に -l（list）を付けると、対話の画面にならず、表を表示するだけで終わる。

$ sudo fdisk -l /dev/vdb
行読めること
Disk /dev/vdb: 2 GiB, …, 4194304 sectorsディスク全体の大きさ。セクタで数えると 4194304 個
Units: sectors of 1 * 512 = 512 bytes下の表の Start・End・Sectors は、512 バイトのセクタで数えている
Disklabel type: dos表の形式。dos は MBR（Master Boot Record）形式の別名で、昔の DOS の時代からある形式
Disk identifier: 0x…この表の番号。表を作ったときに決まる（あなたの画面では別の値）
表の行 /dev/vdb1 2048 411647 409600 200M 83 Linux区画の名前・始まり・終わり・セクタの数・大きさ・種類の番号（Id）・種類の名前

Boot の列は、起動に使う区画に付ける印（起動フラグ）で、ここでは空である。種類（Id と Type）は、その区画を何に使うつもりかを表の上に書いておく印である。主なものを並べる。

IdType何のためにあるか
83LinuxLinux のファイルシステムを置く（fdisk の n の既定）
82Linux swap / Solarisスワップ（メモリが足りないときに中身を書き出しておく領域）に使う
8eLinux LVMLVM（複数のディスクをまとめる仕組み）の材料に使う
5Extended拡張パーティション。中に区画を入れるための入れ物（この章の後半）
efEFI (FAT-12/16/32)起動用の区画（ESP。中は第1章の vda15 と同じ FAT。第4章で扱う）を MBR の表に置くときに使う

種類は「使うつもり」を書いた札にすぎず、中身を決めるわけではない。vdb1 は種類が 83 で、中身は第2章で作った ext4 である。種類を変えるのは fdisk の t（type）キーで、この章では使わない。

たとえ: パーティションの表は、本の目次に近い。「第1章は2048ページから409600ページぶん」と書いてあり、本文（中身）は別の場所にある。
ただし崩れる点: 本なら目次が無くてもページをめくれば読めるが、ディスクは表に行が無いと、Linux がその区画を装置（/dev/vdb1）として作らない。中身があっても手が届かなくなる（次の次の節で確かめる）。

表の中身をバイトで読む

この節で分かること: MBR の表がどこにあり、なぜ基本パーティションが4つまでなのか。

MBR 形式では、表はディスクの先頭のセクタ（512 バイト）に入っている。ディスクの好きな位置のバイトをそのまま読むのが dd で、読んだバイトを16進数の数字で見せるのが od である。

オプション意味
dd if=/dev/vdb読む相手（input file）。ディスクそのもの
bs=1 skip=446 count=661バイトずつ数えて、先頭の 446 バイトを飛ばし、66 バイトだけ読む
status=nonedd が最後に出す「何バイト写したか」の報告を出さない
od -A d -t x1左端の位置を10進数で、中身を1バイトずつ16進数で出す
$ sudo dd if=/dev/vdb bs=1 skip=446 count=66 status=none | od -A d -t x1

先頭のセクタの中は、3つに分かれている。最初の 446 バイトは BIOS（古い方式のファームウェア。電源を入れると最初に動くプログラム）で起動するためのプログラムの置き場所、続く 64 バイトが表、最後の 2 バイトが「ここに MBR がある」という印（55 aa）である。1行目の 16 バイトを分けて読む。

00 00 21 02  83  06 46 98  00 08 00 00  00 40 06 00
│  └──────┘  │   └──────┘  └─────────┘  └─────────┘
│   開始の   種類  終わりの    開始位置      大きさ
│   CHS     83=   CHS       0x00000800   0x00064000
起動フラグ  Linux            = 2048       = 409600 セクタ（200MiB）
                              （下位のバイトが先に並ぶ）

1行が 16 バイトで、64 バイトには4行しか入らない。だから MBR の表に直接書ける区画（基本パーティション。プライマリパーティションとも呼ぶ）は4つまでである。開始位置と大きさは 32 ビット（2進数で 32 桁。4 バイト）のセクタ数なので、扱えるのは 232 × 512 バイト = 2TiB までになる。

消すと、中身も消える？

この節で分かること: 区画を表から消して作り直すと、中身はどうなるか。

消す前に、いまの表を文字にして控えておく。sfdisk は、表を文字で読み書きする区切る道具で、-d（dump）を付けると表を文字にして書き出す。それを > でホームのファイルに残す（> でファイルに書くのは student のシェルなので、ファイルは student のものになる）。

$ sudo sfdisk -d /dev/vdb > vdb-table.txt
$ cat vdb-table.txt

label: dos は表の形式（MBR）、label-id は表の番号で、最後の行が vdb1 の行である。start= は始まりのセクタ、size= はセクタの数、type=83 は種類（Linux）。これがあれば、消したあとでも元の位置が分かる。

fdisk の d（delete）で vdb1 を消してみる。区画が1つしか無いので、番号は聞かれない。

$ sudo fdisk /dev/vdb
$ lsblk /dev/vdb
$ sudo mount /dev/vdb1 /mnt

vdb1 という装置そのものが無くなり、mount も /dev/vdb1 が無いと断った（エラーの2行目の dmesg は、カーネルが出したメッセージを見るコマンドで、第11章で使う）。なお、lsblk の見出しのうち NAME だけが1行目に出て、残りが2行目に回っている。これは util-linux 2.39 の lsblk が端末に表を出すときの癖で、いちばん左の列の中身がすべて見出しより短いと（vdb は3文字、NAME は4文字）、その見出しだけを折り返す。表の中身は同じである。

ふつうこう考える

パーティションを消したのだから、中の memo.txt も消えた。同じ大きさで作り直しても、空の区画ができるだけのはずだ。

$ sudo fdisk /dev/vdb
$ sudo mount /dev/vdb1 /mnt
$ cat /mnt/memo.txt
$ sudo umount /mnt
だめな理由: 第2章で書いた memo.txt が、そのまま読めた。fdisk の d が消したのは表の1行で、区画の中身（ext4 の管理情報とファイル）には1バイトも触れていない。控えた表と同じ位置（2048 から 409600 セクタ = 200MiB）に行を書き戻したので、カーネルはまた vdb1 を作り、その中には前のままの ext4 が残っていた。fdisk 自身もそれに気づいて「中に ext4 の印（signature）がある。消すか」と聞いてきた。ここで Y と答えると、その印（ext4 の数バイト）が消され、ファイルが残っていても ext4 として読めなくなる。

だから、消してしまった区画は、同じ始まりの位置・同じ大きさで作り直せば取り戻せる。位置が1セクタでもずれると、中身の先頭と合わなくなる。消す前に sfdisk -d で表を控えておけば、元の位置が確実に分かる（演習02 の課題文に出てくるのも、この控えである）。

たとえ: 目次から章を1行消しても、本文のページは破られていない。同じページ番号で目次に書き戻せば、その章はまた引ける。
ただし崩れる点: 本の目次は書き戻しても何も聞いてこないが、fdisk は中に残っている印に気づいて「消すか」と聞く。目次を直すつもりで、本文の表紙（印）を破り捨てる選択肢が、同じ画面に出てくる。

5つ目からは、拡張パーティションの中に作る

この節で分かること: 基本パーティションが4つまでという制限の越え方と、論理パーティションの番号。

基本パーティションを1つ足し（vdb2）、3つ目を拡張パーティション（e）にして、その中に2つ作る。区画を作る問いは第2章と同じで、拡張パーティションの大きさは Enter（残り全部）にする。

$ sudo fdisk /dev/vdb
$ sudo fdisk -l /dev/vdb

拡張パーティション（vdb3、種類 5 の Extended）は、残りの空きを全部抱える入れ物で、それ自体にはファイルシステムを作らない。拡張パーティションは1つのディスクに1つまでで、基本パーティションの4つの枠のうち1つを使う。だから MBR で区画をいちばん多く作れる形は「基本3つ＋拡張1つ（中に論理パーティションをいくつでも）」になる。

拡張パーティションの中に作った論理パーティションは、4 が空いていても 5 から番号が付く（1〜4 は基本パーティションのために取ってある）。論理パーティションの位置は、拡張パーティションの中に置かれた小さな表（EBR）を順にたどって決まる。vdb5 の始まりが vdb3 の始まり（616448）ではなく 618496 なのは、その小さな表の置き場所を空けたからである。

たとえ: 棚板が4枚しかない本棚に近い。5種類目の本を置きたければ、棚板の1枚を引き出しに替えて、その中を仕切って並べる。
ただし崩れる点: 本棚の引き出しは開ければ中が全部見えるが、論理パーティションの位置は、引き出しの中に順につないだ小さな表（EBR）を先頭からたどらないと分からない。だから途中の1つが壊れると、その先の論理パーティションも見失う。

演習02 のディスクを見ておく

この節で分かること: 演習02 で取り戻す区画が、表のどこから消えているか。
$ sudo fdisk -l /dev/vdd

vdd（256M）には vdd2 しか無く、その始まりは 206848 番目のセクタである。先頭の 2048〜206847 には、表の行が無い区画がある。以前ここに vdd1 があり、誰かが表から消してしまった、という設定である。

手を動かす: 実践編の演習02は、この vdd から消えた vdd1 を取り戻し、中のファイルを読む課題である。 判定は表の行と、vdd1 の中のファイルシステムを直接読んで確かめる。mkfs してはいけない（中身が消える）。
確認

MBR のディスクで、基本パーティションを3つ作ったあと、さらに3つ作りたい。どうするか。新しくできる区画の番号は何番になるか。

答え

4つ目を拡張パーティションにして、その中に論理パーティションを3つ作る。論理パーティションの番号は 5・6・7（4 が空いていても 5 から始まる）。MBR の表は 64 バイトで4行しか書けないので、基本パーティションは4つまでで、拡張パーティションはそのうち1つの枠を使って1つだけ作れる。

確認

パーティションを fdisk の d で消して w まで打ってしまった。中のデータは取り戻せるか。取り戻すときに気を付けることは何か。

答え

取り戻せる見込みが高い。消えたのは表の1行で、中身は残っている。同じ始まりの位置・同じ大きさで作り直す。作り直すとき fdisk が「中のファイルシステムの印を消すか」と聞いてくるので、N と答える。mkfs をすると中身は失われる。

確認

MBR の表で扱えるディスクの大きさの上限はいくつか。それはなぜか。

答え

2TiB。表の1行は、区画の開始位置と大きさを 32 ビットのセクタ数で持つので、232 × 512 バイト = 2TiB までしか指せない。

この章で分かったこと

持ち帰ってほしいこと

  • fdisk -l は表を表示するだけで終わる。Disklabel type の dos は MBR 形式。区画の位置はセクタ（512 バイト）で数える
  • 種類（Id）は使うつもりを書いた札: 83 Linux・82 Linux swap・8e Linux LVM・5 Extended・ef EFI
  • MBR の表はディスクの先頭のセクタにあり、起動のプログラム 446 バイト・表 64 バイト（16 バイト × 4行）・印 2 バイト（55 aa）。だから基本パーティションは4つまでで、2TiB まで
  • 表から行を消しても中身は残る。同じ位置・同じ大きさで作り直せば読める。fdisk が「印を消すか」と聞いたら N
  • 5つ目からは、拡張パーティション（種類 5。1つのディスクに1つまで）の中に論理パーティションとして作る。番号は 5 から
