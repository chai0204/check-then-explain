6. USB メモリと CD をマウントする

第5章では、vdb の区画に5種類のファイルシステムを作り、ラベルを付けた。この章では、抜き差しするメディア（USB メモリと CD）を手でマウントして使い、USB メモリを挿し直したときに /dev/sdb のような名前がどうなるかを確かめて、ラベルや UUID で指す方法を見る。

前提: 第5章まで読了前提: 練習機の中にいる所要 24分影響度 B出題範囲 1.05.3（重要度4）最終検証 2026-10-20

この章のゴール

  • 外で USB メモリを挿し・抜きし、練習機の中でどの名前のディスクになったかを確かめられる
  • マウントポイントを用意してマウントでき、外せないとき（target is busy）の理由と対処を言える
  • 装置の名前ではなく、ラベル・UUID で目当てのファイルシステムを指せる。CD の写しのファイル（ISO イメージ）をそのままマウントできる
ここで覚えなくていいこと: デスクトップの Linux が、挿しただけで自動でマウントするしくみは扱わない（練習機は画面を持たない）。USB の規格の違い（2.0 と 3.0 の速さなど）も扱わない。CD・DVD に書き込む方法も扱わない。

外の端末をもう1つ開く

この節で分かること: 外で打つコマンドと、練習機の中で打つコマンドを、2つの端末で打ち分ける方法。

練習機に USB メモリを挿すのは、外（lab@host）で打つコマンドである。練習機の中にいる今の端末はそのままにして、あなたの PC で端末の窓をもう1つ開き、檻に入る（実践編の「はじめる」で打った2つ目のコマンドと同じ）。

docker exec -it lab-linuc-disks bash -l

新しい端末は外（プロンプト lab@host）にいる（入ったときに、実践編の「はじめる」で見たのと同じ、練習機の状態と演習の進み具合の案内が出る）。この章から先、見出しが「外（lab@host）」のブロックはこの新しい端末で、「練習機の中（student@linuc）」のブロックは今までの端末で打つ。

USB メモリを挿して使う

この節で分かること: USB メモリを挿してからマウントするまでの流れと、マウントポイントの性質。

virsh は仮想マシンを操作するコマンドで、attach-device は動いている仮想マシンに装置をつなぐ。~/vm/extra/usb-a.xml は、64M の USB メモリ（ここでは「A」と呼ぶ）を表す設定のファイルで、檻に用意してある。これを打つのが、本物の PC で USB メモリを挿すことに当たる。

$ virsh attach-device linuc ~/vm/extra/usb-a.xml

練習機の中で、どの名前のディスクになったかを見る。lsblk の -d はディスクだけを出す（中の区画は出さない）オプションで、TRAN はつながり方（usb・sata・virtio）、SERIAL は装置の製造番号の列である。

$ lsblk -d -o NAME,SIZE,TRAN,SERIAL

USB メモリは sdb になった。sda（SATA のディスク）が先にあるので、次の名前の sdb が付いた。この USB メモリは、ここでは区切らずに、ディスク全体に FAT を作る（区画を1つ作ってから、その中に作ってもよい）。第1章のたとえで「区画を作らずにディスク全体に倉庫を建てる」と書いた使い方である。

$ sudo mkfs.vfat -n STICK_A /dev/sdb
$ sudo mount /dev/sdb /media/stick

mount point does not exist（マウントポイントが無い）で断られた（2行目は第3章と同じ、dmesg も見よという案内）。マウントポイントは、前もって作っておくただのディレクトリである。/media は、取り外せるメディアをマウントする場所として決められたディレクトリで（/mnt は一時的に手でつなぐ場所）、その下に作る。マウントポイントの中にもともとあったものがどうなるかも見たいので、目印のファイルを1つ置いてからマウントする。

$ sudo mkdir /media/stick
$ sudo touch /media/stick/HIDDEN
$ ls /media/stick
$ sudo mount /dev/sdb /media/stick
$ ls /media/stick

マウントすると、HIDDEN は見えなくなった（作ったばかりの FAT には何も無いので、ls は何も出さない）。消えたのではなく、上にかぶさっただけで、外せばまた見える（すぐ下で確かめる）。目印のファイルを書いて、外す。作ったばかりの FAT のいちばん上は root のものなので、sudo tee で書く（tee は受け取った文字をファイルに書き、画面にも出すコマンド。sudo を付けると root の権限で書く）。

$ echo "これは A" | sudo tee /media/stick/who.txt
$ cd /media/stick
$ sudo umount /media/stick

target is busy（使用中）で断られた。中でファイルを開いているプロセス（動いているプログラム）か、カレントディレクトリ（いま居るディレクトリ）がその中にあるプロセスがいると、umount は外さない。ここでは自分のシェルが cd で中に入っていた。cd を引数なしで打つとホームに戻るので、外に出てから外す。

$ cd
$ sudo umount /media/stick
$ ls /media/stick
$ sudo rm /media/stick/HIDDEN

外すと HIDDEN がまた見えた。目印は消しておく。

たとえ: マウントは、壁の釘に額縁を掛けることに近い。額縁（ファイルシステム）を掛けると、後ろの壁（もとのディレクトリの中身）は見えなくなるが、壁が消えたわけではなく、額縁を外せばまた見える。
ただし崩れる点: 額縁は誰かが見ていても外せるが、マウントは誰かが中にいる（カレントディレクトリにしている・ファイルを開いている）と外せない。

/dev/sdb は、いつも同じ USB メモリ？

この節で分かること: /dev/sdb のような名前が何で決まるか。

A を抜いて、もう1本の USB メモリ（B）を挿す。detach-device は装置を外す（USB メモリを抜くことに当たる）。

$ virsh detach-device linuc ~/vm/extra/usb-a.xml
$ virsh attach-device linuc ~/vm/extra/usb-b.xml

B は ext4 にしてラベル STICK_B を付ける。-q は途中経過を出さない（quiet）オプションである。

$ lsblk -d -o NAME,SIZE,TRAN,SERIAL
$ sudo mkfs.ext4 -q -L STICK_B /dev/sdb

B を挿したまま、A を挿し直す。

$ virsh attach-device linuc ~/vm/extra/usb-a.xml
$ lsblk -o NAME,FSTYPE,LABEL,SERIAL /dev/sdb /dev/sdc

ふつうこう考える

A に FAT を作ったときの名前は /dev/sdb だった。/dev/sdb は A の名前なのだから、mount /dev/sdb と打てば A が出てきて、who.txt が読めるはずだ。

$ sudo mount /dev/sdb /media/stick
$ cat /media/stick/who.txt
$ lsblk -o NAME,FSTYPE,LABEL,MOUNTPOINTS /dev/sdb /dev/sdc
$ sudo umount /media/stick
だめな理由: /dev/sdb にいたのは B（ext4、STICK_B）だった。sdb のような名前は、カーネルが装置を見つけた順に、空いている名前から付ける。A を抜いているあいだに B が sdb を取り、あとから来た A は sdc になった。しかも mount はファイルシステムの種類を自分で見分けるので、別のディスクを何も言わずにマウントした。

ディスクにずっと付いているのは、中に書いた印（ラベルと UUID）だけである。第4章の blkid で読む。findfs は、ラベルや UUID から「いまどの装置か」を引くコマンドである。

$ sudo blkid /dev/sdb /dev/sdc
$ sudo findfs LABEL=STICK_A

カーネルの装置の管理を手伝うプログラム udev が、ラベルや UUID から、いまの装置を指す別名（シンボリックリンク）を /dev/disk/by-label/ と /dev/disk/by-uuid/ に作っている。

$ ls -l /dev/disk/by-label/ | grep STICK

mount には、装置の名前の代わりに LABEL=…（や UUID=…）を渡せる。これなら、何番目に挿しても A を指せる。

$ sudo mount LABEL=STICK_A /media/stick
$ cat /media/stick/who.txt
$ sudo umount /media/stick
指し方例変わるとき何のためにあるか
装置の名前/dev/sdb挿す順番・ディスクの増減で変わるいまつながっている装置を、その場で操作する（fdisk・mkfs）
ラベルLABEL=STICK_A人が付け替えたとき人が覚えやすい名前で指す
UUIDUUID=…作り直した（mkfs した）とき重ならない番号で、確実に1つを指す
たとえ: 駐車場の何番目に停めたかと、車のナンバープレートに近い。「2番目の車」は来た順で変わるが、ナンバーは車に付いている。
ただし崩れる点: ナンバーは役所が重ならないように配るが、ラベルは人が自由に付ける名前である。2つのディスクに同じラベルを付けたらどうなるかは、第7章で確かめる。

USB メモリは2本とも抜いておく。

$ virsh detach-device linuc ~/vm/extra/usb-a.xml
$ virsh detach-device linuc ~/vm/extra/usb-b.xml

CD を読む

この節で分かること: 読み取り専用の装置をマウントすると何が起きるか。

練習機の光学ドライブ sr0 には、CD が1枚入っている。CD のファイルシステムは iso9660 である（DVD や BD のデータは、UDF という別のファイルシステムで書かれることが多い）。

$ sudo mount /dev/sr0 /mnt
$ cat /mnt/README.TXT
$ touch /mnt/test.txt
$ sudo umount /mnt

読み取り専用を頼んでいないのに、mount は WARNING: source write-protected, mounted read-only.（書き込みが禁止された装置なので、読み取り専用でマウントした）と言った。この光学ドライブは書き込む機能の無い DVD-ROM として練習機につながっていて、カーネルは読み取り専用の装置として扱う（第1章の lsblk で、sr0 の RO が 1 だった）。touch の Read-only file system は、ファイルの権限ではなく、読み取り専用でマウントされていることが理由である。

CD の写しを、ファイルのままマウントする

この節で分かること: ディスクの中身を写したファイル（イメージ）を、装置と同じようにマウントする方法。

CD の中身を丸ごと1つのファイルに写したものを ISO イメージと呼ぶ（Linux のインストール用の配布物も、ふつうこの形）。第3章の dd で、sr0 を最初から最後まで写す（of= は書き出す先のファイル）。最後の行の秒数と速さは、あなたの画面では違う。

$ sudo dd if=/dev/sr0 of=media.iso
$ ls -l media.iso

ファイルをマウントするときは、ループデバイス（ファイルを、ディスクのような装置に見せかける仮の装置。/dev/loop0 など）を間に置く。-o loop は「ループデバイスを用意して、それをマウントせよ」とはっきり頼むオプションである（いまの mount は、付けなくてもファイルを渡されれば自分でループデバイスを用意するが、試験は -o loop の形で問う。ここでも付けて打つ）。

$ sudo mount -o loop media.iso /mnt
$ df -h /mnt
$ losetup -l
$ ls /mnt
$ sudo umount /mnt
$ losetup -l
$ sudo rm media.iso

df の Filesystem が /dev/loop0 になっている。losetup -l は、どのループデバイスがどのファイルにつながっているかの一覧で、loop0 の後ろに media.iso があると分かる。外すと、ループデバイスも一緒に片づいた（AUTOCLEAR が 1。外したあとの losetup -l は何も出さない）。今度も WARNING が出たのは、中の iso9660 が書き込みのマウントを受け付けないからである（ループデバイスそのものは書き込める。losetup -l の RO が 0）。

たとえ: ISO イメージは CD の写しで、ループデバイスはその写しを読み取り機にかけるための台紙に近い。台紙に貼ると、読み取り機（mount）は本物の CD と区別せずに読む。
ただし崩れる点: 本物の CD は書き込めない装置だが、写しの台紙（ループデバイス）は書き込める装置になる。中のファイルシステムが書き込みを受け付ける種類（ext4 や FAT）なら、ファイルの中身を書き換えられる。
手を動かす: 実践編の演習05は、練習機のホームに置いてある、昔の USB メモリを丸ごと写したファイル（old-usb.img）をマウントし、中のファイルを取り出す課題である。 判定は、取り出したファイルの中身を読んで確かめる。
確認

umount /data が target is busy で失敗した。何が考えられるか。

答え

そのファイルシステムの中で、ファイルを開いているプロセスか、カレントディレクトリがその中にあるプロセス（自分のシェルを含む）がいる。自分のシェルなら cd で外に出てから外す。ほかのプロセスなら、そのプログラムを終わらせてから外す。

確認

USB メモリを2本挿しているとき、ラベルが BACKUP のほうをマウントしたい。装置の名前を調べずにマウントするには、どう打つか。

答え

sudo mount LABEL=BACKUP /mnt。装置の名前（/dev/sdb など）は挿した順番で変わるので、中に書いたラベルで指す。どの装置かを知りたいだけなら findfs LABEL=BACKUP か ls -l /dev/disk/by-label/。

確認

ダウンロードした install.iso の中身を、CD に焼かずに見たい。どうするか。

答え

sudo mount -o loop install.iso /mnt。mount がループデバイスを用意してファイルを装置に見せかけるので、CD に焼かずにマウントできる（いまの mount は -o loop を省いても同じことをするが、試験では -o loop の形で答える）。どのループデバイスがどのファイルにつながっているかは losetup -l で見る。

この章で分かったこと

持ち帰ってほしいこと

  • 練習機に USB メモリを挿す・抜くのは、外で virsh attach-device・detach-device。中では lsblk -d の TRAN・SERIAL でどれかを見分ける
  • マウントポイントは前もって作るただのディレクトリ。もとの中身は隠れるだけで、外せばまた見える。中にプロセスがいると umount は target is busy で断る
  • /dev/sdb は見つかった順に付く名前で、挿す順番で別のディスクを指す。ディスクに付いているのは中のラベルと UUID で、blkid・findfs・/dev/disk/by-label/ で引け、mount LABEL=… で指せる
  • /media は取り外せるメディアのマウント先。CD は iso9660 で、読み取り専用の装置なので mount は読み取り専用にする
  • ISO イメージのようなファイルは、ループデバイスを通して mount -o loop でマウントできる（losetup -l で対応を見る）
