4. ロックは、扉を1つ閉めるだけ

passwd -l alice は成功し、passwd -S は L（ロック）と答える。それでも alice は ssh の鍵で入れる。ロックが閉めたのは「パスワード」という扉1つで、鍵の扉はその列を読まないからである。アカウントを一時停止するなら、どの扉からも必ず読まれる列を変える。

前提: 第3章まで読了（alice がいる）前提: 外の端末と練習機の中の両方を開いておく所要 18分影響度 B出題範囲 1.08.1（重要度5）最終検証 2026-10-13

この章のゴール

  • passwd の -l -u -S -d -e が /etc/shadow のどこを変えるかを言える
  • アカウントを消さずに一時停止する方法（有効期限・ログインシェル）を選べる
  • ロック・期限切れ・シェルの拒否が、ログインのどの段で効くかを説明できる
ここで覚えなくていいこと: PAM の設定ファイルの書き方、sshd_config の DenyUsers、失敗回数によるロック（pam_faillock）、パスワードの強度の検査は扱わない。chage のオプション一式は主題1.10（セキュリティ）の範囲で、ここでは読むのに使うだけ。

作ったばかりのユーザは、最初からロックされている

この節で分かること: passwd -S の読み方と、パスワードを付けたときの /etc/shadow の変化。

@@ sudo passwd -S alice
@@ sudo grep '^alice:' /etc/shadow

passwd -S は /etc/shadow の行を読みやすく直して表示する。2つ目の欄が状態で、L はロック（2列目が ! で始まる）、P は使えるパスワードがある、NP はパスワードが空。3つ目以降は最終変更日・最短日数・有効日数・警告日数・猶予日数で、/etc/shadow の3〜7列目に対応する。これは Ubuntu（Debian 系）の passwd の表示で、RHEL 系は LK・PS・NP の2文字と説明文を出す（章の最後で比べる）。

パスワードを付ける。passwd は2回聞いてくる。打った文字は画面に出ない。


@@ sudo passwd alice
@@ sudo passwd -S alice
@@ sudo grep '^alice:' /etc/shadow

2列目の ! が、$y$ で始まるハッシュ（yescrypt）に置き換わった。状態は P になった。

鍵を渡すと、パスワードを使わずに入れる

この節で分かること: ssh の鍵認証が、パスワードの列を使わないこと。

外の端末（lab@host）から student で入れているのは、外の鍵が student の ~/.ssh/authorized_keys に登録してあるからである。同じものを alice にも置く。


@@ sudo install -d -m 700 -o alice -g alice /home/alice/.ssh
@@ sudo install -m 600 -o alice -g alice ~/.ssh/authorized_keys /home/alice/.ssh/

外の端末で、ユーザを alice に変えて入る（-l はログインするユーザ名）。コマンドを1つだけ実行して戻ってくる形にしておく。


@@ ssh -l alice linuc id

passwd -l でロックしても、鍵では入れる

この節で分かること: passwd -l が何を止めて、何を止めないか。

ふつうこう考える

しばらく使わせたくないユーザは passwd -l でロックすればよい。 passwd -S が L と言っていれば、そのユーザはもう入れないはずだ。


@@ sudo passwd -l alice
@@ sudo passwd -S alice
@@ sudo grep '^alice:' /etc/shadow


@@ ssh -l alice linuc id
だめな理由: 入れた。passwd -l がしたのは、/etc/shadow の2列目（ハッシュ）の頭に ! を1文字足すことだけである。 こうすると、どんなパスワードを打ってもハッシュが一致しなくなる。だから止まるのはパスワードで入る経路だけで、 鍵の照合は2列目を読まないので素通りする。man passwd にもそう書いてある （Note that this does not disable the account. The user may still be able to login using another authentication token (e.g. an SSH key).）。
たとえ: 暗証番号で開くドアと、カードキーで開くドアが並んでいる建物に近い。暗証番号を無効にしても、カードキーのドアは開く。
ただし崩れる点: 建物なら「この人は入館禁止」と警備員に伝えれば全部のドアで止まるが、passwd -l は警備員に何も伝えていない。暗証番号の台帳の1行を書き換えただけである。

止めるなら、アカウントの期限を切る

この節で分かること: どの入口でも必ず読まれる列。

/etc/shadow の8列目は「アカウント自体の有効期限」である。ここに 1（1970-01-02）を書くと、とうに期限切れになる。


@@ sudo usermod -e 1 alice
@@ sudo grep '^alice:' /etc/shadow


@@ ssh -l alice linuc id

鍵の照合は通ったうえで、そのあとの「このアカウントは使ってよいか」の検査（PAM の account 段）で断られた。この検査は ssh でもコンソールでも su でも必ず通る。root から su しても止まる。


@@ sudo su - alice -c id
@@ sudo chage -l alice

chage -l は /etc/shadow の日数を日付に直して見せる。Account expires : Jan 02, 1970 が8列目の 1 である。期限を空に戻すと、また入れる（パスワードはまだロックのままなのに、鍵なら入れることにも注意）。


@@ sudo usermod -e '' alice


@@ ssh -l alice linuc id

もう1つの方法は、ログインシェル（/etc/passwd の7列目）を、ログインを断るだけのプログラムにすることである。


@@ sudo usermod -s /usr/sbin/nologin alice


@@ ssh -l alice linuc id

ただし root だけは、su -s で別のシェルを指定すれば入れる。root はもともと何でもできるので、ここで止める相手ではない。


@@ sudo su -s /bin/bash alice -c id
@@ sudo usermod -s /bin/bash alice

ログインは「本人確認（パスワードか鍵）→ アカウントの検査（有効期限など）→ シェルの起動」の順に進む。どの段で止めるかで、止まる入口が変わる。

止め方書き換える場所効く段パスワード鍵の sshroot からの su
passwd -l / usermod -L/etc/shadow 2列目に !（RHEL 系の passwd -l は !!）本人確認止まる止まらない止まらない
usermod -e 1 / chage -E 1/etc/shadow 8列目アカウントの検査止まる止まる止まる
usermod -s /usr/sbin/nologin/etc/passwd 7列目シェルの起動止まる止まる止まる（root が su -s /bin/bash でシェルを指定すると入れる）

試験で「アカウントを一時的に無効にする」と問われたら、passwd -l・usermod -L（ロック）、usermod -e・chage -E（期限）、シェルを /usr/sbin/nologin や /bin/false にする、の3系統が答えになる。実務では、鍵で入る人がいるならロックだけでは足りない。

たとえ: 社員証の有効期限に近い。期限が切れた社員証では、暗証番号のドアでもカードキーのドアでも、受付で止められる。
ただし崩れる点: 社員証の期限は本人も見て知っているが、/etc/shadow の8列目は本人には読めず、切れたことは入ろうとして初めて分かる。だから「戻ってきたら usermod -e '' で戻す」と記録しておく。
手を動かす: 実践編の演習03は、dave を消さずに一時停止する課題である。 判定は外から dave の鍵で実際に ssh し、練習機の中で root から su - dave して、入れないことを確かめる。

passwd の残りのオプション

この節で分かること: ロック解除・期限切れの強制・パスワードの削除が、それぞれ何を書くか。

@@ sudo passwd -u alice
@@ sudo passwd -S alice
@@ sudo passwd -e alice
@@ sudo passwd -S alice

-u で ! が外れて P に戻った。-e はパスワードを「期限切れ」にする。3列目（最終変更日）が 0、つまり 1970-01-01 になり、次のログインで変更を強制される。こちらはアカウントの検査で効くので、鍵の ssh でも止まる。


@@ ssh -l alice linuc id

端末があれば、その場で新しいパスワードを聞かれる。コマンドを1つ実行するだけの ssh には端末が無いので、変更できずに断られた。最後に -d（パスワードを空にする）を見る。

たとえ: passwd -e は「次に来たら、受付で暗証番号を作り直させる」という指示に近い。カードキー（鍵）で来ても受付は通るので、そこで止められる。
ただし崩れる点: 受付なら作り直す場所があるが、コマンドを1つ実行するだけの ssh には端末が無く、作り直す手段が無いまま断られる。対話のログインなら、その場で新しいパスワードを決めて入れる。

@@ sudo passwd -d alice
@@ sudo passwd -S alice
@@ sudo passwd -l alice; sudo passwd -u alice

NP はパスワードが空の状態で、コンソールではパスワード無しで入れてしまう危険な状態である。そこからロックして解除しようとすると、passwd -u は「解除するとパスワード無しのアカウントになる」と言って断る。

passwd同じことをする別のコマンド/etc/shadow の変化
-l（ロック）usermod -L2列目の頭に !（RHEL 系の passwd -l は !!）
-u（ロック解除）usermod -U2列目の ! を外す
-d（パスワードを消す）—2列目を空にする
-e（期限切れにする）chage -d 03列目を 0 にする
-S（状態を見る）chage -l（読むだけ）
-n / -x / -w / -ichage -m / -M / -W / -I4〜7列目（最短・有効・警告・猶予の日数）

chage -E の値は日数で、usermod -e 1 と同じことは chage -E 1 である。0 は「1970-01-01」とも「期限なし」とも読まれうるので使わない（man 5 shadow）。

ここまでの表示とロックの印は Ubuntu（Debian 系）のものである。RHEL 系は passwd が別の実装で、表示も印も違う。比較のために AlmaLinux 9.7 のコンテナで打った記録を添える（この教材の練習機では打てない。root で打っているので sudo が無く、パスワードは chpasswd で入れている）。


@@rhel passwd -S alice
@@rhel echo 'alice:Alice-pass-2026' | chpasswd
@@rhel passwd -S alice  ## n=2
@@rhel passwd -l alice
@@rhel grep '^alice:' /etc/shadow | cut -c1-12
@@rhel passwd -u alice
@@rhel usermod -L alice
@@rhel grep '^alice:' /etc/shadow | cut -c1-12  ## n=2
Ubuntu（この練習機）RHEL 系（AlmaLinux 9.7）
useradd 直後の2列目!!!
passwd -l が足す印!!!
usermod -L が足す印!!
passwd -S の状態L / P / NPLK / PS / NP と説明文（(Password locked.) など）

どちらも「2列目の先頭が ! ならロック」で、意味は同じである。試験の選択肢に !! や LK が出てきても、ロックのことだと読めればよい。

確認

ユーザ taro のパスワードをロックするコマンドを2つ答えよ。また、ロックすると /etc/shadow の taro の行はどう変わるか。

答え

passwd -l taro と usermod -L taro。2列目（パスワードのハッシュ）の先頭に ! が付き、passwd -S の状態が L になる（Ubuntu の場合。RHEL 系の passwd -l は !! を付け、表示は LK）。 ただし ssh の公開鍵など、パスワードを使わない入口は止まらない。

確認

passwd -l でロックしたユーザが、ssh の公開鍵認証でログインできてしまった。アカウントを削除せずに、どの方法でもログインできないようにするコマンドとして適切なものはどれか。

A. passwd -d hanako　B. usermod -e 1 hanako　C. passwd -u hanako　D. usermod -U hanako

答え

B。アカウントの有効期限（/etc/shadow の8列目）を過去にすると、PAM のアカウント検査で鍵の ssh も su も止まる。 A はパスワードを空にしてしまい、かえって危険。C と D はロック解除である。シェルを /usr/sbin/nologin にする方法でも止まる。

確認

次のログイン時にユーザ jiro にパスワードの変更を強制したい。passwd のオプションで答えよ。また /etc/shadow のどの列が何になるか。

答え

passwd -e jiro。3列目（最後にパスワードを変えた日）が 0 になる。chage -d 0 jiro でも同じ。 この章では、これで鍵の ssh も（端末が無いと変更できずに）止まった。

この章で分かったこと

持ち帰ってほしいこと

  • useradd 直後はパスワードが無く L（2列目が !。RHEL 系は !! で LK）。passwd ユーザ名 で付けると P
  • passwd -l は2列目の頭にロックの印（Ubuntu は !、RHEL 系は !!）を足すだけ。鍵の ssh は止まらない
  • 一時停止は usermod -e 1（= chage -E 1）でアカウントの期限を切るか、シェルを /usr/sbin/nologin にする（root だけは su -s で入れる）。戻すのは usermod -e '' と usermod -s
  • passwd -e は3列目を 0 にして次のログインで変更を強制する。passwd -d はパスワードを空にする（危険）
  • どの方法がどの入口を止めるかは、ログインのどの段（本人確認・アカウントの検査・シェル）でその列が読まれるかで決まる
