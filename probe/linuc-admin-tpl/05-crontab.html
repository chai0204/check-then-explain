5. crontab には「誰が」の列が無い

/etc/crontab には、時刻の5列のあとに実行ユーザの列がある。同じつもりで自分の crontab に student と書くと、cron はそれをコマンドとして実行する。ユーザの crontab では、表が置かれた場所（ファイル名）が「誰が」を表しているからである。

この章のゴールと前提所要 20分
前提: 第4章まで読了所要 20分（うち cron を待つ時間 約3分）影響度 B出題範囲 1.08.2（重要度4）最終検証 2026-10-13

この章のゴール

  • crontab の時刻の5列（分・時・日・月・曜日）を読み書きできる
  • crontab -e -l -r と、ファイルを渡す形の違いを言える
  • ユーザの crontab（Debian 系は /var/spool/cron/crontabs、RHEL 系は /var/spool/cron）・/etc/crontab・/etc/cron.d の書式の違いを、動いた結果で説明できる
  • /etc/cron.allow と /etc/cron.deny の役割を言える
ここで覚えなくていいこと: systemd のタイマーへの置き換え、MAILTO とメールの配送は扱わない。/etc/cron.daily などの「毎日・毎週」の仕組みは第6章で扱う。RHEL 系の cron（cronie）とこの Ubuntu の cron で答えが変わるところは、本文でそのつど並べる（試験は両方の書き方で出る）。

自分の表は、crontab コマンドで渡す

この節で分かること: ユーザの crontab がどこに、どう保存されるか。

@@ crontab -l
@@ ls -l /usr/bin/crontab
@@ ls -ld /var/spool/cron/crontabs

表を置く場所 /var/spool/cron/crontabs は、一般ユーザには中身を読めない（drwx-wx--T）。代わりに crontab コマンドが setgid（-rwxr-sr-x の s。crontab グループの権限で動く）になっていて、表の出し入れは必ずこのコマンドを通す。

ふだんは crontab -e でエディタを開いて書く。初めてのときは使うエディタを聞かれる（nano が既定）。

crontab -e
  （初回だけ、使うエディタを番号で選ぶよう聞かれる。1 は nano）
  （開いたエディタに1行書いて保存し、閉じると登録される）

ここでは記録どおりの画面を出すために、表をまるごと標準入力から渡す形を使う。crontab ファイル名 や crontab - は、いまある表を置き換える。


@@ echo '* * * * * date >> /tmp/tick.txt' | crontab -
@@ crontab -l
@@ sudo ls -l /var/spool/cron/crontabs
@@ sudo cat /var/spool/cron/crontabs/student

表は /var/spool/cron/crontabs/student というユーザ名のファイルとして保存された。先頭に「直接編集するな」と書いてある。この行の意味は、5つの時刻の欄とコマンドである。

*    *    *    *    *    date >> /tmp/tick.txt
分   時   日   月   曜日  コマンド
0-59 0-23 1-31 1-12 0-7（0 と 7 が日曜。sun〜sat でも書ける）
書き方意味例
*すべて* * * * * 毎分
a-b範囲30 9 * * 1-5 平日の 9:30
a,b列挙0 0 1,15 * * 毎月1日と15日の 0:00
*/nn ごと*/10 * * * * 10分ごと
@reboot @daily など特別な指定@reboot 起動時に1回、@daily は 0 0 * * * と同じ

cron は毎分0秒に目を覚まして表を見る。1分待つ。

（次の分になるまで待つ）
@@ cat /tmp/tick.txt
@@ journalctl -u cron -n 3 --no-pager

ログに (student) CMD (…) と、誰として何を実行したかが残る（サービスの名前は Ubuntu では cron、RHEL 系では crond で、LinuC の例題は crond と書く）。student という名前は表の中のどこにも書いていない。表のファイル名から来ている。

たとえ: cron は、毎分0秒に起きて全員の予定表を見回る当番に近い。予定の時刻と一致した行があれば、その人の代わりに実行する。
ただし崩れる点: 当番は寝過ごした回を後で取り返さない。練習機が止まっていた時刻の予定は、動き出しても実行されない。それを補う仕組みが第6章の anacron である。
たとえ: 名前入りの個人ロッカーに入れた予定表に近い。誰の予定かはロッカーの名札で分かるので、予定表に「誰が」の欄は要らない。
ただし崩れる点: 人の予定表なら余計に名前を書いても害は無いが、cron は5つの時刻の欄のあとを全部コマンドとして読む。名前を書くと、その名前を実行しようとする（次の節）。

/etc/crontab の書き方を、自分の表にまねる

この節で分かること: 6列目（実行ユーザ）があるのはどの表か。

システム全体の表 /etc/crontab を読む。


@@ grep -vE '^\s*#|^\s*$' /etc/crontab

時刻の5列のあとに root という列がある。

ふつうこう考える

cron の表の書式は1つのはずだ。/etc/crontab と同じように、自分の表にも6列目に実行ユーザ（student）を書いておけば、 student として動くだろう。書いておけば読む人にも分かりやすい。


@@ echo '* * * * * student date >> /tmp/tick2.txt 2>&1' | crontab -
@@ crontab -l
（次の分になるまで待つ）
@@ cat /tmp/tick2.txt
だめな理由: ユーザの crontab には実行ユーザの列が無い。cron は5列のあとの student date >> … を丸ごと /bin/sh に渡し、 sh は student というコマンドを探して失敗した。2>&1 を付けていなければ、このエラーはメールで送られ、 この練習機には MTA が無いので捨てられて何も残らない（>> でファイルだけが空のまま作られる）。 誰として動くかは、表が /var/spool/cron/crontabs/student に置かれていることで決まっている。

もう1つ起きていることがある。最初のジョブの出力が止まっている。


@@ cat /tmp/tick.txt

crontab - は表を置き換えたので、最初の date >> /tmp/tick.txt の行はもう無い。足したいときは crontab -e で開いて書き足す。

表置き場所書式編集のしかた
ユーザの crontab/var/spool/cron/crontabs/ユーザ名（RHEL 系は /var/spool/cron/ユーザ名）時刻5列＋コマンドcrontab -e（root は crontab -u ユーザ -e）
システムの表/etc/crontab時刻5列＋実行ユーザ＋コマンドroot がエディタで直接
システムの表の部品/etc/cron.d/*/etc/crontab と同じ6列root がファイルを置く（パッケージもここに置く）

/etc/cron.d には、名前の決まりもある

この節で分かること: /etc/cron.d のファイルが読まれる条件。

@@ ls -l /etc/cron.d
@@ cat /etc/cron.d/e2scrub_all

パッケージが置いた部品で、どの行にも実行ユーザ（root）がある。3つ置いて比べる。1つは正しく、1つは名前に . を入れ、1つは実行ユーザを書かない。ついでに自分の表を、ジョブが見る環境変数を書き出す1行に置き換えておく。


@@ echo '* * * * * root id -un >> /tmp/cron-d.txt' | sudo tee /etc/cron.d/lab-demo
@@ echo '* * * * * root id -un >> /tmp/cron-dot.txt' | sudo tee /etc/cron.d/lab.demo
@@ echo '* * * * * id -un >> /tmp/cron-nouser.txt' | sudo tee /etc/cron.d/lab-nouser
@@ echo '* * * * * env > /tmp/cron-env.txt' | crontab -
（次の分になるまで待つ）
@@ cat /tmp/cron-d.txt
@@ ls -l /tmp/cron-dot.txt /tmp/cron-nouser.txt
@@ journalctl -u cron -n 30 --no-pager | grep -E 'lab|ERROR'

動いたのは lab-demo だけで、6列目どおり root として動いた。実行ユーザを書かなかった lab-nouser は、id をユーザ名として読まれてファイルごと捨てられ、ログにそう出た。名前に . を入れた lab.demo はログにも何も出ずに無視された。Debian 系の cron は、/etc/cron.d のファイル名が英数字・_・- だけでできていないと読まない（パッケージの退避ファイル foo.dpkg-old などを動かさないため）。同じ決まりが第6章の run-parts にもある。RHEL 系の cron（cronie）にはこの決まりが無く、lab.demo のような名前も読む。

手を動かす: 実践編の演習04は、自分の crontab と /etc/cron.d の両方に毎分のジョブを置く課題である。 判定は cron が実際に書いたファイルを見て、誰として動いたかまで確かめる（動くまで最大 75 秒待つ）。

cron のジョブは、ログインしたシェルとは違う環境で動く

この節で分かること: 端末で動くコマンドが cron で動かないことがある理由。

@@ cat /tmp/cron-env.txt
@@ echo $SHELL

ジョブが受け取った環境変数は6つだけで、SHELL は /bin/sh である。ログインした端末は /bin/bash なので、bash にしか無い書き方（{1..3} や [[ ]] など）は cron では動かないことがある。~/.bashrc のエイリアスも読まれない。

PATH と LANG は、Ubuntu では cron の PAM の設定が /etc/environment と /etc/default/locale から読み込んで渡している。ほかのディストリビューションでは PATH=/usr/bin:/bin だけのことも多いので、cron に書くコマンドは /usr/local/bin/… のように絶対パスで書くのが確実である。

たとえ: 留守番の代理人に頼む用事に近い。代理人はあなたの部屋（ホーム）は使えるが、あなたの手帳（エイリアス）や使い慣れた道具（bash）は持っていない。
ただし崩れる点: 代理人なら分からないことを電話で聞いてくるが、cron は聞かない。失敗した出力はメールで送るだけで、この練習機のように MTA が無ければ黙って捨てる。

片づける。crontab -r は確認なしで表を丸ごと消す（-e と打ち間違えやすい位置にあるので注意）。


@@ crontab -r
@@ crontab -l
@@ sudo rm /etc/cron.d/lab-demo /etc/cron.d/lab.demo /etc/cron.d/lab-nouser

使ってよい人は、cron.allow と cron.deny で決める

この節で分かること: crontab を使えるユーザを絞る方法。

@@ ls -l /etc/cron.allow /etc/cron.deny
@@ echo student | sudo tee /etc/cron.deny
@@ crontab -l
@@ sudo rm /etc/cron.deny
@@ crontab -l

/etc/cron.allow があれば、そこに書かれた人だけが crontab を使える。無ければ /etc/cron.deny に書かれた人が断られる。どちらも無いとき、この Ubuntu（Debian 系）の cron では全員が使え、RHEL 系の cron（cronie）では root だけが使える（ただし RHEL は空の /etc/cron.deny を最初から置いているので、既定の状態では全員が使える）。at にも同じ形の /etc/at.allow と /etc/at.deny があるが、どちらも無いときの扱いが逆になっている。第7章で確かめる。

確認

毎週月曜日から金曜日の 9時30分に /usr/local/bin/report を実行したい。ユーザの crontab に書く行として正しいものはどれか。

A. 9 30 * * 1-5 /usr/local/bin/report　B. 30 9 * * 1-5 /usr/local/bin/report　C. 30 9 1-5 * * /usr/local/bin/report　D. 30 9 * * 1-5 root /usr/local/bin/report

答え

B。並びは「分 時 日 月 曜日」で、曜日の 1-5 が月〜金。A は分と時が逆、C は「毎月1〜5日」になる。 D は /etc/crontab や /etc/cron.d の書式で、ユーザの crontab に書くと root がコマンドとして実行される（この章の student: not found がその実物）。

確認

次のうち、ユーザ自身の crontab を確認なしで削除するものはどれか。

A. crontab -e　B. crontab -l　C. crontab -r　D. crontab -u

答え

C。-e は編集、-l は表示、-u ユーザ は root が他人の表を扱うときに対象を指定するオプション。 crontab ファイル名（や crontab -）も、いまの表を確認なしで置き換える。

確認

Debian 系で、ユーザ hanako が crontab -e で登録した表はどのファイルに保存されるか。また、/etc/crontab の書式との違いを1つ答えよ。

答え

/var/spool/cron/crontabs/hanako（RHEL 系では /var/spool/cron/hanako）。 /etc/crontab（と /etc/cron.d）は時刻の5列のあとに実行ユーザの列があり、ユーザの crontab には無い。

この章で分かったこと

持ち帰ってほしいこと

  • 時刻は「分 時 日 月 曜日」の5列。* a-b a,b */n と @reboot などで書く
  • ユーザの表は crontab -e で編集し、/var/spool/cron/crontabs/ユーザ名（RHEL 系は /var/spool/cron/ユーザ名）に置かれる。-l 表示、-r 削除（確認なし）、crontab ファイル は置き換え
  • /etc/crontab と /etc/cron.d/* は6列目に実行ユーザを書く。ユーザの表に書くとコマンドとして実行される
  • Debian 系の cron は、/etc/cron.d のファイル名に . を入れるとログも出さずに無視する（RHEL 系の cronie は読む）
  • ジョブは SHELL=/bin/sh と最小限の環境で動く。出力はメールで送られ、MTA が無ければ捨てられる
  • /etc/cron.allow があればそこに書いた人だけ、無ければ /etc/cron.deny に書いた人以外が使える。どちらも無いと Debian 系は全員、RHEL 系の cronie は root だけ
