8. ロケールは、名前で指しているだけ

LANG=ja_JP.UTF-8 date は、何も言わずに英語の日付を出し、終了コード 0 で終わる。ja_JP.UTF-8 という名前のロケールが、この練習機にはまだ生成されていないからである。LANG は名前で指すだけで、その名前の実体（コンパイル済みのデータ）が無ければ、プログラムは黙って C ロケールで動く。

前提: 第7章まで読了所要 18分影響度 B出題範囲 1.08.3（重要度3）最終検証 2026-10-13

この章のゴール

  • LANG・LC_*・LC_ALL の関係（強さの順）を説明できる
  • locale と locale -a で、設定と生成済みのロケールを確かめられる
  • locale-gen・localedef でロケールを生成できる
  • スクリプトで LANG=C（LC_ALL=C）を使う理由を、出力の違いで示せる
  • 国際化（i18n）とローカライゼーション（l10n）の違いを言える
ここで覚えなくていいこと: LANGUAGE 変数、gettext の仕組み、日本語入力（IM）は扱わない。タイムゾーンは主題1.09.1 の範囲（1.09 の第2章）。

いまのロケールを見る

この節で分かること: ロケールがいくつもの分野（カテゴリ）に分かれていること。

@@ locale
@@ cat /etc/default/locale
@@ locale -a

locale は、いまのシェルのロケールを分野ごとに表示する。引用符 "…" 付きの値は「その変数そのものの値ではなく、LC_ALL（設定されていればそちら）か LANG から来た値」という意味である（LC_ALL の例は後の節で見る）。LANG の値は、ログインのときに /etc/default/locale（システムの既定）から読み込まれた。locale -a は、この練習機に生成済みのロケールの一覧で、いまは C 系の3つしか無い。

変数決めるもの影響を受ける例
LC_CTYPE文字の種類（どのバイト列が1文字か）wc -m、正規表現の [[:alpha:]]
LC_NUMERIC数の書き方（小数点・桁区切り）printf "%'d"
LC_TIME日時の書き方date、ls -l の日付
LC_COLLATE並び順sort、ls の並び
LC_MONETARY通貨の書き方—
LC_MESSAGESメッセージの言語エラーメッセージ
LANG上のどれも設定されていないときの既定—
LC_ALL設定すると、全分野をこの値で上書き—

locale に分野の名前を渡すと、その分野が持っている値が並ぶ。-k を付けるとキーワード名（abday= など）も出し、-c を付けると分野の名前も出す。-t というオプションは無い。


@@ locale LC_TIME | head -4
@@ locale -k LC_TIME | head -4
@@ locale -ck LC_TIME | head -5
@@ locale -t

生成していないロケールを指すと、黙って C になる

この節で分かること: ロケールの「名前」と「実体」が別であること。

ふつうこう考える

日本語の表示にしたければ、LANG=ja_JP.UTF-8 を付けて実行すればよい。 使えない名前を指定したなら、エラーになって教えてくれるはずだ。


@@ LANG=ja_JP.UTF-8 date; echo $?
@@ LANG=ja_JP.UTF-8 locale
だめな理由: date は英語で表示し、終了コードは 0 だった。警告も出していない。 locale に聞いて初めて「Cannot set LC_CTYPE to default locale: No such file or directory」と分かる。 LANG に書いたのは名前で、その名前のデータは生成しないと存在しない。見つからないとき、C ライブラリは黙って C ロケール（POSIX）で動き、 多くのプログラムはそれを報告しない（bash はスクリプトの起動時に警告を出すことがあるが、date は何も言わない）。locale の表示が "ja_JP.UTF-8" になっているのは、変数の値を写しているだけである。
たとえ: レストランで「日本語のメニューをください」と頼むのに近い。店に日本語版が無ければ、店員は黙っていつもの英語のメニューを持ってくる。
ただし崩れる点: 店員なら「日本語版はありません」と言ってくれることもあるが、多くのプログラムは何も言わない。頼んだ側が locale -a で、店に何があるかを先に確かめるしかない。

ロケールを生成する

この節で分かること: locale-gen と localedef がすること。

Debian 系では、生成するロケールの一覧が /etc/locale.gen にある。いまは全部コメントになっている。


@@ grep ja_JP /etc/locale.gen
@@ sudo locale-gen ja_JP.UTF-8
@@ grep ja_JP /etc/locale.gen
@@ locale -a

locale-gen は /etc/locale.gen の該当行のコメントを外し、データを生成した。一覧での名前は ja_JP.utf8（小文字・ハイフン無し）に正規化されている。もう一度同じことをする。


@@ LANG=ja_JP.UTF-8 date
@@ LANG=ja_JP.UTF-8 ls -l /etc/hostname
@@ LANG=ja_JP.UTF-8 printf "%'d\n" 1234567
@@ LANG=C printf "%'d\n" 1234567

日時（LC_TIME）と桁区切り（LC_NUMERIC）が日本の書き方になった。何が変わったのかは、最初の節で使った locale -k・-c で、ロケールのデータの中身として見られる。キーワード1つを渡すこともできる。


@@ locale -k thousands_sep
@@ LANG=ja_JP.UTF-8 locale -k LC_NUMERIC
@@ LANG=ja_JP.UTF-8 locale -ck date_fmt

C.UTF-8 の桁区切り（thousands_sep）は空で、ja_JP.UTF-8 は , を3桁ごと（grouping=3）に入れる。printf "%'d" の違いはここから来ていた。date の既定の形も LC_TIME の date_fmt に書いてある。

ところがメッセージ（LC_MESSAGES）は、プログラムによって変わったり変わらなかったりする。ところがメッセージ（LC_MESSAGES）は、プログラムによって変わったり変わらなかったりする。


@@ LANG=ja_JP.UTF-8 ls /nonexistent
@@ LANG=ja_JP.UTF-8 dpkg -s nonexistent-pkg
@@ ls -1 /usr/share/locale/ja/LC_MESSAGES/

ls は英語のまま、dpkg は日本語になった。メッセージの翻訳はロケールのデータではなく、プログラムごとの翻訳ファイル（.mo）に入っていて、この練習機には dpkg や apt の分しか無い。ここに2つの言葉の違いがある。

  • 国際化（internationalization。i と n の間が18文字なので i18n）は、プログラムが言語や地域の違いを差し替えられるように作っておくこと。ls も date もロケールに従って表示を変える作りになっている
  • ローカライゼーション（localization。l10n）は、ある言語・地域向けの中身を用意すること。ja_JP の日付の書き方のデータや、日本語の翻訳ファイルがそれにあたる

ロケールを生成すると書式の中身はそろうが、翻訳は別に入れないと届かない。Ubuntu では翻訳を言語ごとのパッケージ（言語パック）にまとめて配っていて、システムを日本語にするときは、ロケールの生成と既定の LANG の設定（この章の最後の節）に加えて、それを入れる。この練習機には入れていない。生成には、もっと低い層の localedef も使える（locale-gen は /etc/locale.gen を読んでこれを呼んでいる）。


@@ sudo localedef -i en_US -f UTF-8 en_US.UTF-8
@@ locale -a

-i はロケールの定義（入力）、-f は文字コード（charmap）、最後が作るロケールの名前である。

たとえ: 国際化は、字幕を差し替えられる映画プレーヤーを作ることに近い。ローカライゼーションは、日本語の字幕ファイルを用意することである。
ただし崩れる点: 映画の字幕は1本のファイルで全部そろうが、Linux では日付や数の書き方（ロケールのデータ）と、メッセージの翻訳（プログラムごとの .mo）が別々に配られる。片方だけそろうことがふつうに起きる。

LC_ALL は、LANG と LC_* より強い

この節で分かること: 変数が複数あるとき、どれが効くか。

@@ LANG=ja_JP.UTF-8 LC_TIME=C date
@@ LANG=C LC_ALL=ja_JP.UTF-8 date
@@ LANG=ja_JP.UTF-8 LC_TIME=C locale
@@ LANG=ja_JP.UTF-8 LC_ALL=C locale

分野ごとの LC_TIME は LANG より強く、LC_ALL はその両方より強い。locale の表示では、自分で設定した LC_TIME=C だけが引用符なしになっている。LC_ALL を設定すると、全分野が引用符付きの "C" になった。LC_ALL から来た値だからで、このとき自分で設定した LC_* があっても、表示は LC_ALL の値になる。

たとえ: LANG は会社の標準ルール、LC_TIME などは部署ごとの例外ルール、LC_ALL は社長の一斉指示に近い。一斉指示が出ていれば、部署の例外も標準ルールも見ない。
ただし崩れる点: 社長の指示は全社に届くが、LC_ALL が届くのはそれを設定したプロセスと、そこから起動した子プロセスだけである。スクリプトの中で設定すれば、そのスクリプトの中だけで効く（第7章の at は、投入したときの値を持っていく）。
LC_ALL   ＞   LC_TIME など個別の LC_*   ＞   LANG
（全部を上書き）  （その分野だけ）                （何も無いときの既定）

スクリプトで LANG=C を使う理由

この節で分かること: 同じスクリプトが、呼ぶ人のロケールで別の結果を出すこと。

コマンドの出力を切り出して使うスクリプトは、出力の形が変わると壊れる。


@@ LANG=ja_JP.UTF-8 date | awk '{print $2}'
@@ LANG=C date | awk '{print $2}'

月を取り出したつもりが、日本語の環境では 10月 になる。並び順も変わる。


@@ printf '%s\n' b A a B | LANG=C sort | paste -sd ' '
@@ printf '%s\n' b A a B | LANG=en_US.UTF-8 sort | paste -sd ' '
@@ printf '%s\n' b A a B | LANG=ja_JP.UTF-8 sort | paste -sd ' '

C ロケールの sort は文字コードの順（大文字が全部先）で、en_US.UTF-8 は辞書の順（大文字と小文字を並べる）である。ja_JP.UTF-8 はこの4文字については C と同じ順になった。並び順はロケールごとの規則（LC_COLLATE）で決まり、「日本語か英語か」では決まらない。だからスクリプトの頭でロケールを固定し、誰が呼んでも同じ形の出力にする。それが「スクリプトでは LANG=C」と言われる理由である。ただし呼ぶ側が LC_ALL を設定していると LANG は負けるので、確実に固定するなら LC_ALL=C と書く。

手を動かす: 実践編の演習07は、呼ぶ人のロケールで出力が変わってしまうスクリプトを直す課題である。 判定は LANG と LC_ALL を変えて3通りに呼び、出力が同じかを比べる。

システムの既定は localectl で変える

この節で分かること: ログインしたときの LANG がどこから来るか。

@@ localectl
@@ sudo localectl set-locale LANG=ja_JP.UTF-8
@@ cat /etc/default/locale

localectl set-locale は /etc/default/locale を書き換える（RHEL 系では /etc/locale.conf）。このファイルはログインのときに読まれるので、いまのシェルには効かない。exit して入り直す。


@@ echo $LANG; date

新しいログインでは日本語になった。この教材の出力は C.UTF-8 で取っているので、元に戻して入り直す。


@@ sudo localectl set-locale LANG=C.UTF-8
@@ echo $LANG; date  ## n=2
確認

LANG=ja_JP.UTF-8、LC_TIME=C が設定され、LC_ALL は設定されていない。date の表示と、エラーメッセージの言語はそれぞれ何で決まるか。

答え

date の日時の書き方は LC_TIME=C で決まり、英語の形になる（個別の LC_* は LANG より強い）。 メッセージは LC_MESSAGES が設定されていないので LANG の ja_JP.UTF-8 に従う（ただし翻訳ファイルがあるプログラムだけ日本語になる）。 LC_ALL を設定すると、両方ともその値で上書きされる。

確認

システムで利用できる（生成済みの）ロケールの一覧を表示するコマンドはどれか。

A. locale　B. locale -a　C. localectl status　D. echo $LANG

答え

B。A はいまの設定（変数の値）を表示するだけで、その名前が生成済みかは分からない。C はシステムの既定、D は変数の値。 この章では LANG=ja_JP.UTF-8 と設定できても、locale -a に無いあいだは C で動いていた。

確認

シェルスクリプトの先頭で LANG=C（あるいは LC_ALL=C）を設定することが多い理由を説明せよ。

答え

コマンドの出力の形（日付の書式・並び順・数の書き方・メッセージ）がロケールで変わり、出力を awk や grep で切り出す処理が、 呼ぶ人の環境によって壊れるから。C ロケールに固定すれば、誰が呼んでも同じ形になる。呼ぶ側の LC_ALL まで抑えるなら LC_ALL=C にする。

確認

「i18n」と「l10n」の違いを説明せよ。

答え

i18n（国際化）は、プログラムを言語や地域に合わせて差し替えられるように作ること。l10n（ローカライゼーション）は、特定の言語・地域向けの翻訳や書式を用意すること。 数字は先頭と末尾の文字の間の文字数（internationalization の 18、localization の 10）。

この章で分かったこと

持ち帰ってほしいこと

  • ロケールは分野ごとの変数（LC_CTYPE LC_TIME LC_COLLATE LC_MESSAGES など）でできていて、強さは LC_ALL ＞ LC_* ＞ LANG
  • LANG は名前を指すだけ。生成していないロケールを指すと、多くのプログラムは黙って C で動く。生成済みかは locale -a で見る
  • 生成は locale-gen（Debian 系。/etc/locale.gen）か localedef -i 定義 -f 文字コード 名前
  • 中身は locale LC_TIME（その分野の値）・locale -k（キーワード名付き）・locale -c（分野の名前も）で見る。-t は無い。引用符付きの値は LC_ALL か LANG から来た値
  • メッセージの翻訳はロケールとは別の翻訳ファイルで、プログラムごとにある（i18n は仕組み、l10n は中身）
  • スクリプトは LANG=C（確実には LC_ALL=C）で出力の形を固定する
  • システムの既定は localectl set-locale で /etc/default/locale に書き、次のログインから効く
