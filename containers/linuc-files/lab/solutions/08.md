見つからない理由は2つ。索引が古いことと、/tmp が索引から外されていることです。

    sudo updatedb                 # 1つ目: 索引を作り直す（root で）
    locate needle.txt
    #=> /home/lab/work/08/needle.txt

    grep PRUNEPATHS /etc/updatedb.conf
    #=> PRUNEPATHS="/tmp /var/spool /media /var/lib/os-prober …"
    sudo sed -i 's#^PRUNEPATHS="/tmp #PRUNEPATHS="#' /etc/updatedb.conf
    sudo updatedb                 # 2つ目: 外す設定を消してから作り直す
    locate needle.txt
    #=> /home/lab/work/08/needle.txt
    #=> /tmp/needle.txt

【locate はディスクを探さない】

  locate が引いているのは /var/lib/plocate/plocate.db という索引です。
  索引を作るのは updatedb で、実機では毎日1回タイマー（plocate-updatedb.timer）か
  cron（/etc/cron.daily/plocate）が呼びます。コンテナではどちらも動かないので、
  この檻の索引はイメージを作った時点のまま止まっています。

    作った直後のファイル    → 索引に無いので出ない
    消した直後のファイル    → 索引に残っているので出る（locate -e なら実在を確かめる）

【updatedb.conf の4つの設定】

    PRUNEPATHS         索引に入れないディレクトリ（/tmp はここに最初から入っている）
    PRUNEFS            索引に入れないファイルシステムの種類（proc・tmpfs・nfs など）
    PRUNENAMES         索引に入れない名前（.git など。既定はコメントアウト）
    PRUNE_BIND_MOUNTS  bind mount を入れないか

【一般ユーザには、読めないものは出ない】

  plocate は、結果を出す前に「呼んだ人が、親ディレクトリすべてに r と x を持っているか」を
  確かめます（man plocate）。索引に載っていても、他人のホームの中など、そこを満たさない場所の
  ものは出ません。
