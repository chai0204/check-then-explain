umask 027 を、シェルの起動時に読まれる場所へ書きます。

    echo 'umask 027' >> ~/.bashrc

    umask 022                       # 親から受け継がせないよう、起動時の値に戻してから
    bash -l                         # 新しいログインシェルで確かめる
    umask
    #=> 0027
    cd ~/work/02; touch new.txt; mkdir new.d; ls -ld new.txt new.d
    #=> drwxr-x--- 2 lab lab 4096 … new.d
    #=> -rw-r----- 1 lab lab    0 … new.txt
    exit

【umask は引き算ではない】

  ファイルは 666、ディレクトリは 777 から、umask に立っているビットを「落とします」。

    ファイル   666 = rw- rw- rw-
    umask      027 = --- -w- rwx
    結果       640 = rw- r-- ---    （6 から w を落として 4、6 から rwx を落として 0）

  引き算で 666 − 027 を桁ごとに計算すると、最後の桁が 6 − 7 になって意味を持ちません。
  umask 033 なら引き算は 633 を予想しますが、実際に作られるのは 644 です（第2章で実測）。

【umask は親から受け継がれる】

  umask はプロセスが持つ値で、子のプロセスにそのまま受け継がれます。いまのシェルで
  umask 027 と打ってから bash -l を起動すると、~/.bashrc に何も書いていなくても
  新しいシェルは 027 になります。著者はこれで判定を一度すり抜けさせてしまいました。

  ログインし直したときのように親の値を持たずに始まるシェルは、起動時に読む設定で
  決め直します。だから判定は umask を 0022（この檻の起動時の値）に戻してから
  新しいシェルを起動しています。起動のたびに読まれる場所に書くのは、このためです。

    ~/.bashrc       対話シェルが起動するたびに読む（この演習はこれで通る）
    ~/.profile      ログインシェルが読む（Ubuntu の ~/.profile は中で ~/.bashrc も読む）
    /etc/profile    全ユーザのログインシェルが読む
    /etc/login.defs PAM（pam_umask）がログイン時に使う UMASK の既定値

【docker exec で入ったシェルは umask 0000】

  別の端末から docker exec で同じコンテナに入ると、そのシェルの umask は 0000 で、
  ファイルが 666 で作られます（著者の実測・docker 29.8.0）。~/.bashrc に書いてあれば、
  そのシェルも起動時に読むので 027 になります。

【この後の章を本文どおりに見るには】

  ~/.bashrc に足した行が残っていると、これから開くシェルは 027 で始まり、
  本文（0022 で記録）と ls -l の表示が変わります。終わったら消しておいてください。

    sed -i '/^umask 027$/d' ~/.bashrc

  檻を抜けて入り直しても消えます（--rm で起動しているため）。
