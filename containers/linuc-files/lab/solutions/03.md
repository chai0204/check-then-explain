グループを devs にし、SGID とスティッキービットを付け、その他には何も渡しません。

    sudo mkdir /srv/share
    sudo chgrp devs /srv/share
    sudo chmod 3770 /srv/share
    ls -ld /srv/share
    #=> drwxrws--T 2 root devs 4096 … /srv/share

    sudo -u alice touch /srv/share/a.txt
    sudo ls -l /srv/share
    #=> -rw-rw-r-- 1 alice devs 0 … a.txt        ← グループが devs になっている
    sudo -u bob rm /srv/share/a.txt
    #=> rm: cannot remove '/srv/share/a.txt': Operation not permitted
    sudo -u carol ls /srv/share
    #=> ls: cannot open directory '/srv/share': Permission denied

【3770 の読み方】

    3   = 2（SGID）+ 1（スティッキービット）
    7   持ち主 root      rwx
    7   グループ devs    rwx   ← alice と bob はここが効く
    0   その他           ---   ← carol はここ。一覧も通り抜けもできない

  ls -l では、特殊なビットは x の位置に重ねて表示されます。

    drwxrws--T
          ^  ^
          |  └ その他の x の位置: t ならスティッキー＋x あり、T ならスティッキー＋x なし
          └─── グループの x の位置: s なら SGID＋x あり、S なら SGID＋x なし

【4つの条件と、受け持つ仕組み】

    1 alice のファイルが devs になる   … ディレクトリの SGID（グループを受け継ぐ）
    2 bob も作れる                     … グループに w と x（770 の真ん中の 7）
    3 bob は alice のファイルを消せない … スティッキービット（/tmp と同じ）
    4 carol は一覧できない             … その他に何も渡さない（770 の最後の 0）

【よくある誤答】

  2775 だと、SGID は効きますが、bob が alice のファイルを消せてしまい、
  carol も一覧できてしまいます。ファイルを消せるかどうかはディレクトリの w が決めるので、
  w を渡した相手には、スティッキービットで「持ち主だけ」と絞る必要があります。

【alice のファイルが 664 になる理由】

  sudo -u alice で動くコマンドの umask は 0002 です。Ubuntu の /etc/login.defs が
  USERGROUPS_ENAB yes なので、ユーザ名と同じ名前の主グループを持つユーザには、
  PAM（pam_umask）がグループの w を残す umask を設定します。だから bob も中身を書き換えられます。
