原因は2段あります。どちらの段から始まるかは、檻への入り方で変わります。

    umask      #=> docker exec で入ったなら 0000、podman exec で入ったなら 0022

【1段目】設定ファイル自身の権限（umask が 0000 のとき）

    logrotate -v /etc/logrotate.d/lab-app
    #=> error: Ignoring /etc/logrotate.d/lab-app because it is writable by group or others.

logrotate は root で動き、設定に書かれたコマンドを root で実行します。
だから他人が書き換えられる設定ファイルを読みません。
umask が 0000 だと、`>` で作ったファイルは 0666（誰でも書ける）になります。

    ls -l /etc/logrotate.d/lab-app     # -rw-rw-rw- なら直す
    chmod 644 /etc/logrotate.d/lab-app # すでに 0644 のときに打っても害は無い

umask が 0022 なら最初から 0644 で作られるので、この段は出ずに2段目から始まります。

【2段目】ログの親ディレクトリの権限

    logrotate -v /etc/logrotate.d/lab-app
    #=> error: skipping "/var/log/lab-app.log" because parent directory has insecure
    #   permissions ... Set "su" directive in config file
    echo $?    #=> 1（こちらは終了コードでも分かる）

    ls -ld /var/log      #=> drwxrwxr-x root syslog

/var/log は syslog グループが書けます。logrotate はそれを危険と見ます。
メッセージが言っている `su` ディレクティブは、どこかに既に書かれています。探してください。

    grep -n su /etc/logrotate.conf
