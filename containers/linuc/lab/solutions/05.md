詰まるところが2つあり、どちらも権限です。設定の中身は難しくありません。
（podman で入った場合は1つ目に当たらず、2つ目だけになります。理由は下の【罠その1】）

    cat > /etc/logrotate.d/lab-app <<'CONF'
    /var/log/lab-app.log {
        size 1k
        rotate 3
        missingok
        notifempty
        compress
        create 0640 syslog adm
        postrotate
            systemctl kill -s HUP rsyslog.service
        endscript
    }
    CONF
    chmod 644 /etc/logrotate.d/lab-app          # ← 罠その1（docker で入った場合に効く）

    for i in $(seq 1 60); do logger -p local3.info "かさ増し $i"; done
    ls -l /var/log/lab-app.log                   #=> 1k（1024 バイト）を超えていればよい

    logrotate -v /etc/logrotate.conf             # ← 罠その2（渡すファイルが違う）
    ls -l /var/log/lab-app.log*
    #=> lab-app.log（0 バイトで作り直されたもの）と lab-app.log.1.gz の2つ

【罠その1 — 設定ファイルが group/other に書けると丸ごと無視される】

  docker exec で入ったシェルは umask が 0000 です。`cat > file` や `printf ... > file` で
  作ると 0666（誰でも書ける）になり、次が出ます。

    warning: Potentially dangerous mode on /etc/logrotate.d/lab-app: 0666
    error: Ignoring /etc/logrotate.d/lab-app because it is writable by group or others.

  **終了コードは 0 です。** `Handling 0 logs` と出て正常終了します。
  エラー行を読まないと「成功したのに切れない」ように見えます。著者はこれで3回空振りしました。

  podman exec で入った場合は umask が 0022 なので、同じ操作で 0644 になり、この罠は出ません。
  自分の値は `umask` で確かめられます。どちらで入っても、`chmod 644` を打っておけば同じ状態になります。

【罠その2 — /etc/logrotate.d/<名前> を直接渡してはいけない】

  権限を直しても（podman で入った場合は最初から）まだ切れません。次が出ます。

    error: skipping "/var/log/lab-app.log" because parent directory has insecure
    permissions (It's world writable or writable by group which is not "root")
    Set "su" directive in config file to tell logrotate which user/group should be used

  こちらは終了コードが 1 になります。

    ls -ld /var/log
    #=> drwxrwxr-x 1 root syslog 4096 /var/log

  /var/log は syslog グループが書けます。logrotate はこれを危険と見て飛ばします。
  回避するための `su` ディレクティブは、**全体設定に既に書かれています**。

    grep -vE '^\s*#|^\s*$' /etc/logrotate.conf
    #=> weekly
    #   su root adm
    #   rotate 4
    #   create
    #   include /etc/logrotate.d

  つまり渡すべきファイルは /etc/logrotate.conf です。こちらを渡せば
  `su root adm` と `include /etc/logrotate.d` の両方が効きます。

    logrotate -v /etc/logrotate.conf

  設定だけで解くなら、自分の設定に書いても通ります。

    su root adm        # ブロックの中に1行足す

  この模範解答の設定は `create` と `postrotate` も自分で書いてあるので、
  単体で渡しても、切ったあとに新しい .log ができて rsyslog も開き直します。
  （`create` を書かずに単体で渡すと、全体設定の `create` を受け継がないので、
  新しい .log が作られません。）

  **なぜ Ubuntu 標準の /etc/logrotate.d/rsyslog は何も書いていないのに動くのか。**
  あれも単体で実行されることを想定していません。logrotate.conf から include され、
  そこにある `su root adm` を受け継いで動いています。
  設定の階層は「どのファイルを渡して実行したか」で変わります。

【3世代を超えたら】

    for r in 1 2 3 4; do
      for i in $(seq 1 60); do logger -p local3.info "回 $r 行 $i"; done
      logrotate -f /etc/logrotate.conf
    done
    ls -l /var/log/lab-app.log*
    #=> lab-app.log / .1.gz / .2.gz / .3.gz   ← 4世代目は捨てられる

【状態はどこに残るか】

    cat /var/lib/logrotate/status
    #=> "/var/log/lab-app.log" の行に、実際に切った日時が秒まで入っている
    #   （ほかの行は、初めて見たときの時刻を時の単位に丸めたもの）

  前回いつ切ったかを覚えているので、条件を満たさなければ何度打っても切りません。
  条件を無視させたいときだけ `-f` を使います。

【いつ走るのか】

  自分では常駐しません。systemd のタイマーが呼びます。

    systemctl list-timers logrotate.timer
    systemctl cat logrotate.timer
    #=> OnCalendar=daily / Persistent=true
