クライアントに基準を1行与えるだけです。

    echo 'server 127.0.0.1 iburst' >> /etc/chrony/chrony.conf
    systemctl restart chrony
    sleep 8

    chronyc sources -v
    #=> ^* localhost     8   6    17     2    +49ns[ +289ns] +/- 3392ns

    chronyc tracking
    #=> Reference ID    : 7F000001 (localhost)
    #   Stratum         : 9
    #   Leap status     : Normal

（ナノ秒の数値と時刻はあなたの環境で変わります。見るのは Reference ID と Stratum と
 Leap status の3行です。）

【なぜ時計を動かさずに「同期」になるのか】

  この檻の chronyd は -x 付きで起動しています。

    cat /etc/default/chrony
    #=> DAEMON_OPTS="-F -1 -x"

  -x は「時計を触らない」指定です。檻には CAP_SYS_TIME が無いので、
  触ろうとしても失敗します。実際に試せます。

    chronyc makestep          #=> 500 Failure
    date -s "2020-01-01 00:00:00"
    #=> date: cannot set date: Operation not permitted

  つまり chronyd がやっているのは「基準とのずれを測って報告する」ことです。
  ずれを実際に反映するかどうかは別の判断で、ローカル側の設定と権限が決めます。

【Stratum が 9 になる理由】

  基準サーバ側の設定を見てください。

    grep -vE '^\s*#|^\s*$' /etc/chrony/lab-ntp-server.conf
    #=> local stratum 8

  stratum 8 のサーバを基準にしたので、こちらは 9 になります。
  stratum は「基準から何段離れているか」です。

【試験との対応】

  ntpd 系では同じことを次の対応で見ます。chrony と ntpd は同時に入りません
  （どちらも Provides: time-daemon かつ Conflicts: time-daemon）。

    chronyc sources   ←→  ntpq -p
    chronyc tracking  ←→  ntpq -c rv
    /etc/chrony/chrony.conf ←→ /etc/ntp.conf
    ntpdate -q <host>   … 問い合わせるだけで時計を動かさない（この檻でも動く）
