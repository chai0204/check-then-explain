2段とも「受け手側の表」を書き換えるだけです。

    # ---- 1段目: システム全体の alias ----
    echo 'alice: bob' >> /etc/aliases
    cat /etc/aliases
    #=> postmaster: root
    #   alice: bob
    newaliases                       # テキストから .db を作り直す

    # ---- 2段目: bob 本人の .forward ----
    echo 'root' > /home/bob/.forward
    chown bob:bob /home/bob/.forward
    chmod 644 /home/bob/.forward

    # ---- 確かめる ----
    echo "2回曲がる" | mail -s "forward 経由" alice
    sleep 3
    grep -c "2回曲がる" /var/mail/root     #=> 1

    journalctl -t postfix/local -n 2 --no-pager
    #=> ...: to=<bob@lab.local>, orig_to=<alice>, relay=local, ... status=sent (delivered to mailbox)
    #   ...: to=<root@lab.local>, relay=local, ... status=sent (delivered to mailbox)

【chmod 644 を忘れると何が起きるか】

  何も壊れません。メールは **bob のメールボックスに入って終わります**。
  転送されなかった理由はログにだけ書かれます。

    warning: file /home/bob/.forward is world writable

  postfix は .forward に書かれた宛先へ配送します。つまり .forward を書ける人は
  他人のメールを自分に転送できます。だから「他人が書き換えられる .forward」を読みません。
  著者もこれで1回空振りし、/var/mail/bob に入っているのを見て原因を探しました。

【ログの読み方】

  1行に2つの宛先が出ます。

    orig_to=<alice>        … 送り手が書いた名前
    to=<bob@lab.local>     … postfix が決めた実際の配送先

  これが主題1.09 の3つを1本に繋ぐところです。
  「宛先が書き換わったこと」は、ログを見ないと分かりません。

【届かないときはどうなるか】

    echo x | mail -s "届かない宛先" nosuchuser@invalid.example
    mailq
    #=> Mail queue is empty

  キューには残りません。配送できないと postfix は**差し戻しを作り**、
  それを postmaster へ送ります。postmaster は /etc/aliases で root に向いています。

    cat /etc/aliases | head -1
    #=> postmaster: root
    ls -l /var/mail/root

  つまり「キューが空なら問題なし」ではありません。root のメールボックスを見ます。

【試験との対応】

    /etc/aliases     … システム全体。書き換えたら newaliases
    ~/.forward       … ユーザ本人。再作成は不要（テキストをそのまま読む）
    mailq / postqueue -p … キューを見る
    postfix / exim   … MTA の実装。どちらも sendmail 互換のコマンドを持つ
