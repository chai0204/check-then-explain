## wasi.wat

    (module
      (import "wasi_snapshot_preview1" "fd_write"
        (func $fd_write (param i32 i32 i32 i32) (result i32)))
      (memory (export "memory") 1)
      (data (i32.const 8) "hello from wasi\n")
      (func (export "_start")
        ;; iovec{ptr=8, len=16} を addr 0 に置く
        i32.const 0
        i32.const 8
        i32.store
        i32.const 4
        i32.const 16
        i32.store
        ;; fd_write(fd=1, iovs=0, iovs_len=1, nwritten=20)
        i32.const 1
        i32.const 0
        i32.const 1
        i32.const 20
        call $fd_write
        drop))

## 著者の環境で出た出力

    $ wasmtime run wasi.wasm
    hello from wasi

    $ node browser.mjs
    TypeError: WebAssembly.instantiate(): Import #0 module="wasi_snapshot_preview1" error: module is not an object or function

    $ wasmtime run mem.wasm
    $ echo "終了コード: $?"
    終了コード: 0

## 出力したのは誰か

`hello from wasi` を画面に書いたのは **wasmtime** です。

wasi.wasm がやったのは、①メモリに「8番地から16バイト」という情報を組み立てる
②もらった `fd_write` という関数を呼ぶ、の2つだけです。ファイルディスクリプタが何か、
標準出力がどこにあるかは一切知りません。

第2章の `env.log` と構造は同じです。違うのは、**関数の名前と形が WASI という規格で
決まっている**ことだけです。規格があるおかげで、あなたが書いた .wasm は
wasmtime でも wasmer でも同じように動きます。名前が合うからです。

## ブラウザ相当では

    module="wasi_snapshot_preview1" error: module is not an object or function

`{}` を渡したので `wasi_snapshot_preview1` というキーが存在せず、undefined が渡りました。
ブラウザには WASI がありません（Node でも `--experimental-wasi-unstable-preview1` などを
使って自分で組み込む必要があります）。

つまり **WASI を使った .wasm は、ブラウザでは動きません。** 逆に、ブラウザ向けに
`env` の import を前提にした .wasm は、wasmtime では動きません。

## 何も起きないという結末

ここが一番気をつけるところです。

    $ wasmtime run mem.wasm
    $ echo "終了コード: $?"
    終了コード: 0

**エラーが出ていません。終了コードも 0 です。そして出力もありません。**

mem.wasm は `_start` を export していないので、`wasmtime run` は呼ぶものを見つけられず、
何もせずに正常終了しました。「正常に、何もしなかった」わけです。

読者がここで「動いた」と判断してしまうのが最も危ない失敗です。
沈黙は成功の証拠になりません。**何が出るべきかを先に決めておく**必要があります。

## 「どこでも動く」の *どこ*

WASM の売り文句は「一度書けばどこでも動く」ですが、この演習で見たとおり
**.wasm 単体では何もできません。** 動くかどうかは、ホストが要求どおりの import を
用意しているかで決まります。

| .wasm が要求するもの | ブラウザ | wasmtime |
|---|---|---|
| 何も import しない | 動く | 動く（ただし `_start` が必要） |
| `env.*`（自分で決めた名前） | ホスト側で用意すれば動く | CLI からは渡せない |
| `wasi_snapshot_preview1.*` | **動かない** | 動く |

配布された .wasm を受け取ったとき、それがどちらなのかは
**実行する前に調べられます。** それが第5章です。
