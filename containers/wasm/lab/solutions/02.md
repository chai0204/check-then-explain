## imp.wat

    (module
      (import "env" "log" (func $log (param i32)))
      (func (export "run")
        i32.const 42
        call $log))

## host.mjs

    const bytes = await readFile("imp.wasm");
    const { instance } = await WebAssembly.instantiate(bytes, {
      env: { log: (n) => console.log("ホストが受け取った値:", n) },
    });
    instance.exports.run();

## ng.mjs

    import { readFile } from "node:fs/promises";
    const bytes = await readFile("imp.wasm");
    try {
      await WebAssembly.instantiate(bytes, { env: {} });
    } catch (e) {
      console.log(e.constructor.name + ":", e.message);
    }

## 著者の環境で出た出力

    $ wasmtime run --invoke run imp.wasm

    Caused by:
        0: failed to instantiate "imp.wasm"

    ホストが受け取った値: 42

## 同じ .wasm、3通りの結末

| ホスト | 渡したもの | 結果 |
|---|---|---|
| wasmtime | 何も渡せない（CLI から import は渡せない） | `unknown import: env::log has not been defined` |
| Node | `{ env: { log: 関数 } }` | **42 が出る** |
| Node | `{ env: {} }` | `LinkError: ... function import requires a callable` |

**モジュールは1バイトも違いません。** 変えたのは渡す側だけです。

## 42 を表示したのは誰か

`console.log` を呼んだのは **host.mjs のほう**、つまり JavaScript 側です。
WASM モジュールがやったのは「42 という数値をスタックに載せて、
もらった関数を呼ぶ」ところまでです。

WASM 側のコードを読み返してください。画面に出す方法はどこにも書かれていません。
`i32.const 42` と `call $log` の2命令だけです。

## 失敗の形がホストで違うこと

wasmtime は **instantiate（インスタンス化）の前に止まっています**。
`failed to instantiate` と言っているので、モジュールを検証した時点で
「env::log が要る。持っていない」と判断して実行を始めていません。

Node の LinkError も同じ段階の失敗です。`Link` という語が、
**モジュールとホストを結びつける工程で失敗した**ことを表しています。
`function import requires a callable` は「そのキーは存在したが、値が関数ではなかった」
という意味で、`env: {}` は `log` というキーが無いので undefined が渡り、
それは呼び出せないので拒否されました。

つまり **import は実行時に取りに行くものではなく、始まる前に揃っていなければならない**
契約です。これがこの教材の背骨です。

> **WASM は外の世界を一切知らない。できることは全部、ホストが import として手渡したものだけである。**
