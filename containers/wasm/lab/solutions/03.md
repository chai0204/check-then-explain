## mem.wat

    (module
      (memory (export "mem") 1)
      (data (i32.const 0) "hello wasm")
      (func (export "ptr") (result i32) i32.const 0)
      (func (export "len") (result i32) i32.const 10))

## read.mjs

    import { readFile } from "node:fs/promises";
    const { instance } = await WebAssembly.instantiate(await readFile("mem.wasm"), {});
    const { mem, ptr, len } = instance.exports;
    console.log("ptr =", ptr(), " len =", len());
    const bytes = new Uint8Array(mem.buffer, ptr(), len());
    console.log("組み立てた文字列 =", new TextDecoder().decode(bytes));
    console.log("線形メモリの実体 =", mem.buffer.constructor.name, mem.buffer.byteLength, "バイト");

## 著者の環境で出た出力

    $ wasmtime run --invoke ptr mem.wasm

    0

    $ wasmtime run --invoke len mem.wasm
    warning: using `--invoke` with a function that returns values is experimental and may break in the future
    10

    $ node read.mjs
    ptr = 0  len = 10
    組み立てた文字列 = hello wasm
    線形メモリの実体 = ArrayBuffer 65536 バイト

    $ wasm-objdump -x mem.wasm
    Data[1]:
     - segment[0] memory=0 size=10 - init i32=0
      - 0000000: 6865 6c6c 6f20 7761 736d                 hello wasm

## 返ってきたのは 0 と 10

関数が返したのは `0` と `10` という数値2つだけです。文字列はどこにも返っていません。

では `"hello wasm"` はどこにあるのか。**バイナリの Data セクションの中**です。
`wasm-objdump` の出力に `6865 6c6c 6f20 7761 736d` と、その右に `hello wasm` が
はっきり見えます。マジックナンバーと同じで、暗号化も圧縮もされていません。

## 「この範囲が文字列である」と決めたのは誰か

WASM 側のコードを読み返してください。「文字列」という語も概念も出てきません。
あるのは次の3つです。

- 65536 バイトのメモリ
- そのうち先頭10バイトに置かれたバイト列
- `0` と `10` を返す関数2つ

**「オフセット0から10バイトを UTF-8 の文字列として読む」と決めたのは Node 側のコードです。**
`TextDecoder` を呼んだのはホストです。WASM から見れば、それは単なるバイト列です。

`(ptr, len)` という渡し方は、言語の機能ではなく **両者の間の約束**です。
約束なので、片方が破れば壊れます。`len()` の戻り値を 5 に変えてみると
`hello` だけが出ます。WASM 側は何もエラーを出しません。

## 65536 バイトという数

線形メモリは**ページ単位**で確保され、1ページは 65536 バイト（64KB）です。
`(memory ... 1)` の `1` はバイト数ではなくページ数です。

`new Uint8Array(mem.buffer)` として範囲を指定せずに全体を見ると、
先頭10バイトの後ろは全部ゼロで埋まっています。使っていない領域も確保されています。

## 背骨との関係

> **WASM は外の世界を一切知らない。できることは全部、ホストが import として手渡したものだけである。**

第2章では「能力」が import 経由でしか来ないことを見ました。
この章で分かるのは、**データも同じ構造**だということです。

WASM が持てるのは数値と、1枚のバイト列（線形メモリ）だけです。
文字列・配列・オブジェクトといった構造は、その上にホストと合意した約束で載せます。
Rust や C から WASM を作ると、コンパイラがこの約束を自動で生成してくれますが、
やっていることは今あなたが手で書いたものと同じです。
