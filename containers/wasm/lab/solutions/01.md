## add.wat

    (module
      (func (export "add") (param i32 i32) (result i32)
        local.get 0
        local.get 1
        i32.add))

## コマンド

    cd ~/work/01
    wat2wasm add.wat -o add.wasm
    ls -l add.wasm
    xxd add.wasm
    wasmtime run --invoke add add.wasm 3 4

    printf '(module\n  (func (export "greet") (result string)\n    unreachable))\n' > str.wat
    wat2wasm str.wat -o str.wasm > observed.txt 2>&1
    cat observed.txt

## 41バイトの読み方

3行のうち、意味が読み取れるものを挙げます。

| バイト列 | 意味 |
|---|---|
| `0061 736d` | マジックナンバー。ASCII で `\0asm`。`file` コマンドがこれを見て判別する |
| `0100 0000` | バージョン。1 |
| `0160 027f 7f01 7f` | 型の定義。`60` が関数型、`027f 7f` が「i32 を2つ」、`017f` が「i32 を1つ返す」 |
| `0361 6464` | 長さ3の文字列 `add`。**export 名が平文で入っている** |
| `0020 0020 016a 0b` | 本体。`20 00` = local.get 0、`20 01` = local.get 1、`6a` = i32.add、`0b` = end |

**41バイトの中に、型・名前・命令のすべてが入っています。** 暗号化も圧縮もされていません。
`wasm2wat add.wasm` を打つと、ここからテキスト表現に戻せます。

## 警告について

`--invoke` で引数を渡したり戻り値を受け取ったりするのは experimental だと警告が出ます。
これは wasmtime の CLI の都合です。本来 WASM は「ホストのプログラムから呼ばれる」もので、
コマンドラインから直接関数を呼ぶのは wasmtime が便宜的に用意している入口です。

この警告自体が、背骨を示しています。**WASM モジュールは単体で起動するものではありません。**

## 文字列を返せないこと

    error: unexpected token string, expected ).

`string` という型は WAT の文法に存在しません。wat2wasm は型の位置に
`i32` `i64` `f32` `f64`（と参照型）しか受け付けないので、字句解析の段階で落ちます。

**実行時エラーではなくコンパイルエラー**であることが重要です。
「文字列を返す関数」は書けないのではなく、**書き表せません**。

では文字列はどうやって受け渡すのか。それが第3章です。
