  ~/work/04 で作業します。この演習は少し長いですが、WASM の移植性の正体が見えます。

【背景: WASI とは】

  WASM 自体には「画面に出す」命令がありません（第2章で確かめました）。
  そこで、ファイルや標準出力を扱うための import の名前と形を決めた規格があります。
  それが WASI です。

  標準出力に書く関数は次の形をしています。

    モジュール名: "wasi_snapshot_preview1"
    関数名      : "fd_write"
    引数        : (i32 i32 i32 i32) → i32 を返す
                   ①fd（1 = 標準出力）
                   ②iovec の配列の開始位置
                   ③iovec の個数
                   ④書けたバイト数を書き戻す位置

  iovec は「どこから何バイト」を表す8バイトの構造です。
  前半4バイトが開始位置、後半4バイトが長さです。メモリ上に自分で組み立てます。

【やること】

  1. wasi.wat を書いてください。仕様は4つです。

       ・wasi_snapshot_preview1 の fd_write を import する
       ・1ページのメモリを "memory" という名前で export する（名前は memory 固定）
       ・オフセット 8 に好きな文字列を置く（末尾に改行 \n を入れてください）
       ・"_start" という名前で export する関数を1つ持つ（名前は _start 固定）

     _start の中身は3段です。

       ・メモリのオフセット 0 に「文字列の開始位置（8）」を書く
       ・メモリのオフセット 4 に「文字列の長さ」を書く
         → メモリへの書き込みは  i32.const アドレス / i32.const 値 / i32.store
       ・fd_write(1, 0, 1, 20) を呼び、戻り値は drop で捨てる

  2. コンパイルして wasmtime で実行してください。--invoke は要りません。

       wasmtime run wasi.wasm

     文字列が出ましたか。**出したのは誰でしょうか。**

  3. 同じ .wasm を「ブラウザ相当」に渡します。browser.mjs を作り、
     import を何も渡さずに instantiate してください（第2章の ng.mjs と同じ形）。
     例外を捕まえて、名前とメッセージを表示してください。

     出力を ~/work/04/observed.txt に貼ってください。

  4. **逆向きも試してください。** 演習03で作った mem.wasm（WASI を使っていない）を
     wasmtime に渡してみてください。

       cp ../03/mem.wasm .
       wasmtime run mem.wasm
       echo "終了コード: $?"

     何が起きましたか。エラーは出ましたか。**出力は何かありましたか。**
     この結果も observed.txt に追記してください。
