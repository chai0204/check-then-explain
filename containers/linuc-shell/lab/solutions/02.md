置き場所を作り、いまのシェルに ~/.profile を読み直させます。

    mkdir -p ~/bin
    cp ~/work/02/today ~/bin/
    today
    #=> bash: today: command not found     ← まだ PATH に入っていない

    source ~/.profile
    echo $PATH
    #=> /home/lab/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
    today
    #=> 2026年10月13日

【なぜ置いただけでは動かないか】

  Ubuntu の ~/.profile には最初から次の処理があります。

    if [ -d "$HOME/bin" ] ; then
        PATH="$HOME/bin:$PATH"
    fi

  「ログインしたその瞬間に ~/bin が在れば足す」という処理です。
  あなたのシェルは ~/bin を作る前にログインしたので、足されていません。
  PATH は起動したときに1回決まり、あとから自動では変わりません。

【bash ~/.profile ではだめな理由】

  bash ~/.profile は、新しい bash（子のプロセス）を起動して読ませます。
  子が PATH を変えても、それは子が持っているコピーです。子が終わると消えます。
  source（または .）は、いまのシェル自身に読ませます。

【PATH="$PATH:$HOME/bin" と手で足してもよい】

  いまのシェルだけなら、それでも動きます。ただし次のログインでは消えます。
  新しいログインシェルで効かせるには、ログイン時に読まれるファイルに書く必要があります。
  この檻では ~/.profile が最初からその役をしているので、何も書き足さずに済みます。

  注意: ~/.bash_profile を新しく作ると、ログインシェルは ~/.profile を読まなくなります（演習01）。
  PATH を足すつもりで ~/.bash_profile を作ると、ログインしたシェルでは
  ~/bin の PATH も ~/.bashrc の alias も消えます。

【判定が2回探す理由】

  lab check はあなたのシェルの子として動き、PATH のコピーを受け取ります。
  だから「いまのシェルの PATH」を外から確かめられます。
  新しいログインシェルは env -i で環境を空にしてから bash -l で起動し、
  ~/.profile が PATH を作るところから確かめています。
