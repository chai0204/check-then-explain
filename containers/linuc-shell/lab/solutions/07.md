パイプをやめて、ファイルを while にリダイレクトでつなぎます。

（下の塊は、画面から写して貼り付けられるように、行頭に空白を入れていません）
cat > count.sh <<'EOF'
#!/bin/bash
# logs/ にある .log ファイルごとに行数を数え、最後に合計を出す。
total=0
for f in logs/*.log; do
    n=0
    while read -r line; do
        n=$((n + 1))
    done < "$f"
    echo "$f: $n 行"
    total=$((total + n))
done
echo "合計: $total 行"
EOF

    bash count.sh
    #=> logs/a.log: 3 行
    #   logs/b.log: 5 行
    #   logs/c.log: 2 行
    #   合計: 10 行

【なぜ 0 になったか】

  bash はパイプ（|）でつないだコマンドを、それぞれ別のプロセスで動かします。
  cat "$f" | while … done の while は子のプロセス（サブシェル）の中で回ります。
  子の中で n を増やしても、それは子が持っている n です。子が終わると消えます。
  親のシェルに戻ってくるのは、終了ステータスだけです。

    cat logs/a.log | while read -r line; do n=$((n + 1)); echo "中: n=$n"; done; echo "外: n=$n"
    #=> 中: n=1
    #   中: n=2
    #   中: n=3
    #   外: n=             ← 親の n は一度も変わっていない

  done < "$f" はリダイレクトで、新しいプロセスを作りません。
  while は親のシェルのまま回るので、n が残ります。

【for と while の使い分け】

  for は「並べたものを1つずつ」です。並べ方はいくつかあります。

    for f in logs/*.log        ワイルドカードで並べる
    for i in 1 2 3             そのまま並べる
    for i in $(seq 1 5)        コマンドの出力で並べる（seq は数の列を出す）

  while は「条件のコマンドが 0 を返す間」です。ファイルを1行ずつ読むなら
  while read -r line; do … done < ファイル が定番です。
