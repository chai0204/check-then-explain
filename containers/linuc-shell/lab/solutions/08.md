関数 line の中の i を local にします。

    sed -i '/^line() {/a\    local i' number.sh
    sed -n '3,7p' number.sh
    #=> line() {
    #       local i
    #       for ((i = 0; i < 20; i++)); do printf '-'; done
    #       printf '\n'
    #   }

    bash number.sh alice bob carol
    #=> 1: alice
    #   --------------------
    #   2: bob
    #   --------------------
    #   3: carol
    #   --------------------

【bash -x で見えるもの】

  直す前に、i に値を入れた行だけを抜き出すとこうなります。

    bash -x number.sh alice bob 2>&1 | grep -E '^\+ (i=|echo)'
    #=> + i=1
    #   + echo '1: alice'
    #   + i=21
    #   + echo '21: bob'
    #   + i=21

  1 の次が 21 です。間に呼んだ line の for が i を 20 まで進めていました。

  bash -x は「実行する直前の形（変数を展開した後）」を + 付きで出します。
  bash -v は「読み込んだ行をそのまま（展開する前）」出します。
  原因が変数の値にあるときは -x、どこまで読まれたかを知りたいときは -v が向きます。
  スクリプトの一部だけを見たいときは、その範囲を set -x と set +x で挟みます。

【関数は子のプロセスではない】

  スクリプトを bash x.sh で実行すると子のプロセスができ、変数は親に戻りません。
  関数は違います。呼んだシェルの中でそのまま動くので、変数を共有します。
  関数の中で exit すると、関数だけでなくスクリプト全体が終わります。
  関数の中で値を返して戻るのは return で、返せるのは終了ステータス（0〜255）だけです。

    function 名前 { … }      bash の書き方
    名前() { … }             sh（dash）でも使える書き方
