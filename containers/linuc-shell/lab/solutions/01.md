bob のホームには ~/.bash_profile があるので、ログインシェルが読むユーザ側の設定ファイルは
それ1つだけです（~/.profile も ~/.bashrc も読みません）。そこに足します。

    echo 'echo "ようこそ bob さん"' | sudo tee -a /home/bob/.bash_profile
    sudo cat /home/bob/.bash_profile
    #=> # ~/.bash_profile — 前任者が置いた設定
    #   export EDITOR=vim
    #   echo "ようこそ bob さん"

    sudo -iu bob
    #=> ようこそ bob さん           ← ログインしたので出る
    bash                           ← 子のシェル（ログインしない対話シェル）
    exit                           ← 子のシェルからは何も出ない
    exit

【~/.profile に書くと出ない理由】

  ログインシェルの bash は、次の3つを上から探して「最初に見つかった1つだけ」を読みます。

    ~/.bash_profile → ~/.bash_login → ~/.profile

  bob には ~/.bash_profile があるので、~/.profile は**一度も読まれません**。
  Ubuntu の ~/.profile に書いてある「~/.bashrc を読み込む」処理も、
  「~/bin を PATH に足す」処理も、bob のログインでは動いていません。

    sudo -iu bob
    type ll        #=> -bash: type: ll: not found（~/.bashrc の alias が無い）

【~/.bashrc に書くと子のシェルでも出る理由】

  ~/.bashrc は「ログインしない対話シェル」が起動するたびに読まれます。
  bash と打つたびに出てしまいます。しかも bob の ~/.bash_profile は ~/.bashrc を
  読み込んでいないので、肝心のログインでは出ません。ちょうど逆になります。

【前任者の設定を直すなら】

  ~/.bash_profile の末尾に、次の1行を足すのがふつうの直し方です。

    . ~/.profile

  こうすると ~/.profile → ~/.bashrc の順にいつもどおり読まれ、
  alias も ~/bin の PATH も戻ります。挨拶を ~/.profile に書いても出るようになります。

【sudo echo ... >> ファイル が失敗する理由】

    sudo echo 'echo "ようこそ bob さん"' >> /home/bob/.bash_profile
    #=> bash: /home/bob/.bash_profile: Permission denied

  >> を処理するのは sudo ではなく、いま打っているあなたのシェル（lab）です。
  sudo が root になるのは echo だけです。だから tee -a に root で書かせます。
