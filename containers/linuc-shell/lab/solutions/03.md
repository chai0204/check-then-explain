直すところは3つあります。先頭行、置き場所と所有者と権限、PATH です。

    cd ~/work/03
    sed -i '1s|.*|#!/bin/bash|' greet           # 1) 先頭行を bash に
    sed -i '1a PATH=/usr/bin:/bin' greet         # 2) 使う人の PATH に左右されないように
    head -3 greet
    #=> #!/bin/bash
    #   PATH=/usr/bin:/bin
    #   # 実行した人に挨拶する。全員が greet と打つだけで使えるようにしたい。

    sudo cp greet /usr/local/bin/greet           # 3) 置き場所・所有者・権限
    sudo chown root:root /usr/local/bin/greet
    sudo chmod 755 /usr/local/bin/greet
    ls -l /usr/local/bin/greet
    #=> -rwxr-xr-x 1 root root 248 /usr/local/bin/greet   （日時は省略）

    sudo -iu alice greet
    #=> こんにちは、alice さん。今日は 10月13日 です

【1) 先頭行 — bash greet は動くのに ./greet は動かない】

  #! の行を読むのはカーネルです。./greet と直接実行したときだけ、
  カーネルが先頭行を見て /bin/sh（Ubuntu では dash）を起動します。
  bash greet は「bash に greet を読ませる」なので、先頭行はただのコメントになります。
  sh greet も同じで、dash に読ませています。

  function は bash のキーワードで、dash では文法エラーになります。
  dash で動かす必要が無いなら、先頭行を #!/bin/bash にするのが確実です。
  （function を消して greet() { … } と書けば dash でも動きます）

【2) 置き場所と所有者と権限】

  /usr/local/bin は全員の PATH に最初から入っている、管理者が自分で置く場所です。
  root 以外が書き換えられると、誰かが中身をすり替えて、次に実行した人の権限で動かせます。
  だから所有者は root、権限は 755（rwxr-xr-x）にします。

  スクリプトは r と x の両方が要ります。
  実行ファイル（機械語）なら x だけで動きますが、スクリプトは
  カーネルが bash を起動し、bash がファイルを**読んで**実行するからです。

    sudo chmod 711 /usr/local/bin/greet
    sudo -u alice greet
    #=> /bin/bash: /usr/local/bin/greet: Permission denied
    sudo chmod 755 /usr/local/bin/greet             ← 戻しておく

【3) PATH — 使う人によって結果が変わる】

  スクリプトは、起動した人の環境変数のコピーを受け取って動きます。PATH もその1つです。
  Ubuntu の ~/.profile は ~/bin を PATH の**先頭**に足すので、
  ~/bin/date を置いている人が実行すると、greet の中の date はそちらが動きます。

  date という名前の偽物を先頭に置いた人として実行すると、違いが見えます。

    mkdir -p /tmp/fake
    printf '#!/bin/sh\necho 偽物\n' > /tmp/fake/date
    chmod 755 /tmp/fake/date
    sudo -u alice env PATH=/tmp/fake:/usr/local/bin:/usr/bin:/bin greet
    #=> こんにちは、alice さん。今日は 偽物 です        ← PATH を決める前
    #=> こんにちは、alice さん。今日は 10月13日 です    ← 2行目で PATH を決めた後

  先頭で PATH=/usr/bin:/bin と決めておけば、誰が実行しても同じ date と id が動きます。
  （/usr/bin/date のように1つずつ絶対パスで書いても同じ効果です）
