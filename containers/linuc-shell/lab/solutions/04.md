引数の数（$#）で入口を分け、全部の引数（"$@"）を for で回します。

    cat > mkbak.sh <<'EOF'
    #!/bin/bash
    # 使い方: mkbak.sh ファイル...
    if [ $# -eq 0 ]; then
        echo "使い方: mkbak.sh ファイル..." >&2
        exit 1
    fi
    for f in "$@"; do
        cp "$f" "$f.bak"
    done
    echo "$# 個コピーした"
    EOF

    bash mkbak.sh; echo "終了ステータス $?"
    #=> 使い方: mkbak.sh ファイル...
    #   終了ステータス 1

    bash mkbak.sh memo.txt "my notes.txt"
    #=> 2 個コピーした
    ls -1
    #=> memo.txt
    #   memo.txt.bak
    #   mkbak.sh
    #   my notes.txt
    #   my notes.txt.bak

【"$@" と $* の違い】

  シェルは、引数を渡す**前に**空白で語に切ります。"my notes.txt" と引用符で囲んで
  渡せば、スクリプトはそれを1つの引数（$2）として受け取ります。
  問題は、受け取ったものをもう一度展開するときです。

    for f in "$@"   → [memo.txt] [my notes.txt]          受け取ったとおり2つ
    for f in $*     → [memo.txt] [my] [notes.txt]        空白でもう一度切られる
    for f in "$*"   → [memo.txt my notes.txt]            全部が1つにまとまる

  受け取った引数を別のコマンドへそのまま渡すときは、"$@" 以外を使う理由はほぼありません。

【標準エラー出力と終了ステータス】

  使い方の表示を >&2 で標準エラー出力に出すのは、
  bash mkbak.sh > list.txt のように出力を保存されたときに、
  使い方の文がデータに混ざらないようにするためです。
  exit 1 は「失敗した」ことを、次に渡すコマンド（&& や if）に伝えます。
