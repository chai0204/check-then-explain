結果を表示するのではなく、exit で終了ステータスとして返します。

    cat > isuser.sh <<'EOF'
    #!/bin/bash
    # 使い方: isuser.sh ユーザ名
    if [ $# -eq 0 ]; then
        echo "使い方: isuser.sh ユーザ名" >&2
        exit 2
    fi
    if grep -q "^$1:" /etc/passwd; then
        exit 0
    else
        exit 1
    fi
    EOF

    bash isuser.sh lab;        echo $?     #=> 0
    bash isuser.sh nosuchuser; echo $?     #=> 1
    bash isuser.sh la;         echo $?     #=> 1（lab に前方一致しない）
    bash isuser.sh;            echo $?     #=> 使い方: isuser.sh ユーザ名 / 2

    bash isuser.sh alice && echo "alice は居る"
    #=> alice は居る

【元のスクリプトが常に 0 だった理由】

  exit を書かないスクリプトは、**最後に実行したコマンドの終了ステータス**で終わります。
  元の最後の行は echo で、echo は成功します。grep が 1 を返しても、
  その値は次の echo に上書きされて消えます。

  $? も同じで、「直前の1つ」のコマンドの値しか持っていません。

    ls /nonexistent; echo $?     #=> 2
    echo $?                      #=> 0   ← 1つ前の echo の値

  値を後で使いたいなら、すぐ変数に移します（rc=$?）。

【スクリプトが親に返せるもの】

  スクリプトは子のプロセスなので、変数を親に返せません。
  返せるのは終了ステータス（0〜255 の整数）1つだけです。
  だから「居る／居ない」のような判定結果は、表示ではなく終了ステータスで返すと、
  && や || や if からそのまま使えます。

  exit 256 と書くと 0 になります（256 で割った余りしか残らない）。
