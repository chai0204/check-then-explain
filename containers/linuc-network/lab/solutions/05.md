サービスが 127.0.0.1 でしか待ち受けていませんでした。待ち受けるアドレスを変えます。

    sudo ss -tlnp
    #=> LISTEN 0 10 127.0.0.1:8080 0.0.0.0:* users:(("ncat",…))
    #   LISTEN 0 4096 0.0.0.0:22   0.0.0.0:* users:(("sshd",…),("systemd",pid=1,…))

    nc -zv 127.0.0.1 8080
    #=> Connection to 127.0.0.1 8080 port [tcp/http-alt] succeeded!
    nc -zv 192.168.10.2 8080
    #=> nc: connect to 192.168.10.2 port 8080 (tcp) failed: Connection refused

  自分自身の 192.168.10.2 宛てでも断られます。待ち受けているのは「127.0.0.1 の 8080 番」で、
  「192.168.10.2 の 8080 番」には誰もいないからです。ポート番号だけでは決まりません。

【直す】

    systemctl cat lab-board | grep ExecStart
    #=> ExecStart=/usr/bin/ncat --keep-open --listen ${LISTEN_ADDRESS} 8080 --sh-exec …
    cat /etc/default/lab-board
    #=> LISTEN_ADDRESS=127.0.0.1

    sudo sed -i 's/^LISTEN_ADDRESS=.*/LISTEN_ADDRESS=0.0.0.0/' /etc/default/lab-board
    sudo systemctl restart lab-board
    ss -tln
    #=> LISTEN 0 10 0.0.0.0:8080 0.0.0.0:*
    sudo ip netns exec router curl http://192.168.10.2:8080/
    #=> lab-board: no news today

【表の読み方】

    0.0.0.0:8080   IPv4 のすべてのアドレスで待つ
    [::]:22        IPv6 のすべてのアドレスで待つ
    127.0.0.1:8080 ループバックだけ（その機械の中からだけ）
    127.0.0.53%lo:53  systemd-resolved（名前解決の中継）。この機械の中のプログラムのためだけの DNS

  ss と netstat は同じ表を出します（-t TCP / -u UDP / -l 待ち受け / -n 数字のまま / -p プロセス）。
  -p でプロセス名を見るには root が要ります（sudo）。
