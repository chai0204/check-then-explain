/etc/resolv.conf を、systemd-resolved のリンクから、ふつうのファイルに置き換えます。

    ls -l /etc/resolv.conf
    #=> /etc/resolv.conf -> ../run/systemd/resolve/stub-resolv.conf
    grep -v '^#' /etc/resolv.conf
    #=> nameserver 127.0.0.53 / options edns0 trust-ad / search .
    host server.lab.example
    #=> Host server.lab.example not found: 2(SERVFAIL)

【1行足すだけでは消える】

    echo 'nameserver 172.16.20.10' | sudo tee -a /etc/resolv.conf
    host server.lab.example
    #=> server.lab.example has address 172.16.20.10     ← 引ける
    sudo systemctl restart systemd-resolved
    grep -v '^#' /etc/resolv.conf
    #=> nameserver 127.0.0.53 …                         ← 足した行が無い

  リンクの先は systemd-resolved が起動のたびに作り直すファイルです（先頭に Do not edit. とある）。

【A: ふつうのファイルにする】

    sudo unlink /etc/resolv.conf
    printf 'nameserver 172.16.20.10\nsearch lab.example\n' | sudo tee /etc/resolv.conf
    ls -l /etc/resolv.conf
    #=> -rw-r--r-- 1 root root 43 … /etc/resolv.conf
    host server
    #=> server.lab.example has address 172.16.20.10
    getent hosts ns
    #=> 172.16.20.10    ns.lab.example

  書き方（resolv.conf(5)）:
    nameserver 172.16.20.10     問い合わせ先の DNS サーバ（1行に1つ。3行まで書け、上から順に試す）
    search lab.example          短い名前に付け足して試すドメイン（複数なら1行に空白で区切って並べる。
                                search の行を2つ書くと、後の行だけが効く）
    domain lab.example          search の古い書き方（1つだけ）。search と同時に書くと後の行が勝つ

【B: systemd-resolved に教える】

    sudo resolvectl dns lab0 172.16.20.10
    sudo resolvectl domain lab0 lab.example
    resolvectl status lab0
    #=> DNS Servers: 172.16.20.10 / DNS Domain: lab.example

  この方法は練習機の再起動で消えます。残すなら /etc/systemd/resolved.conf の
  [Resolve] に DNS=172.16.20.10 と Domains=lab.example を書きます。

【dig と host の違い（search）】

    host server             … search を使う → 引ける
    dig +short server       … search を使わない → 何も出ない（"server." という名前を聞いている）
    dig +short +search server   … search を使う → 172.16.20.10
