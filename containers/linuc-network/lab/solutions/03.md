接続（プロファイル）を作り、有効にします。

    sudo nmcli connection add type ethernet ifname enp0s18 con-name lab-dhcp
    #=> Connection 'lab-dhcp' (…UUID…) successfully added.     ← UUID は毎回変わる
    sudo nmcli connection up lab-dhcp
    #=> Connection successfully activated (D-Bus active path: …)

    nmcli device status
    #=> enp0s18  ethernet  connected  lab-dhcp
    ip -4 addr show enp0s18
    #=> inet 10.0.4.15/24 brd 10.0.4.255 scope global dynamic noprefixroute enp0s18
    #       valid_lft 86399sec …     ← dynamic = DHCP で借りたもの。残り時間が減っていく

【nmcli が触れるのは NetworkManager が持つ NIC だけ】

    nmcli device status
    #=> enp0s16 / enp0s17 / lab0 / lo は unmanaged

  unmanaged は「NetworkManager の持ち物ではない」という意味で、壊れているわけではありません。
  この練習機の NetworkManager は enp0s18 だけを持つよう設定されています。

    cat /etc/NetworkManager/conf.d/90-lab.conf
    #=> unmanaged-devices=*,except:interface-name:enp0s18

【固定アドレスにするなら】

    sudo nmcli connection modify lab-dhcp ipv4.method manual ipv4.addresses 10.0.4.50/24
    sudo nmcli connection up lab-dhcp          ← modify しただけでは反映されない。up し直す
    ip -4 addr show enp0s18
    #=> inet 10.0.4.50/24 … （dynamic が付かない）

  DHCP に戻す（判定は DHCP で見ます）:

    sudo nmcli connection modify lab-dhcp ipv4.method auto ipv4.addresses ''
    sudo nmcli connection up lab-dhcp

  よく使う設定の名前: ipv4.method（auto / manual）、ipv4.addresses、ipv4.gateway、ipv4.dns
  nmcli の最初の語（オブジェクト）: general（全体の状態・ホスト名）/ networking / radio /
  connection（接続）/ device（NIC）/ monitor（変化を見張る）

【Ubuntu では、作った接続は netplan の YAML になる】

    ls /etc/netplan/
    #=> 01-lab-mgmt.yaml  90-NM-…UUID….yaml

  Ubuntu の NetworkManager は、nmcli で作った接続を netplan の設定ファイルとして保存します。
  RHEL 9 以降の既定では /etc/NetworkManager/system-connections/ に置かれ、
  RHEL 8 までは /etc/sysconfig/network-scripts/ifcfg-<名前> に置かれます（演習 02 の解答の対応表の形）。
  どれでも nmcli から見れば同じです。
