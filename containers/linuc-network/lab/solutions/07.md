/etc/hosts に古い行が残っていて、DNS より先に読まれていました。

    dig +short www.lab.example
    #=> 172.16.20.10
    ping -c 1 www.lab.example
    #=> PING www.lab.example (172.16.20.99) …
    #   From router.lab.example (192.168.10.1) icmp_seq=1 Destination Host Unreachable

    grep '^hosts' /etc/nsswitch.conf
    #=> hosts:          files dns
    getent ahosts www.lab.example
    #=> 172.16.20.99    STREAM www.lab.example
    #   172.16.20.99    DGRAM / RAW …            ← 同じアドレスを接続の種類ごとに出す
    cat /etc/hosts
    #=> 172.16.20.99 www.lab.example     ← 前任者が書いた古い行

【直す】

    sudo sed -i '/www.lab.example/d' /etc/hosts
    getent ahosts www.lab.example
    #=> 172.16.20.10    STREAM www.lab.example …
    curl http://www.lab.example/
    #=> hello from www.lab.example (172.16.20.10, 80/tcp)

【道具ごとに見る表】

    dig / host / nslookup   DNS サーバに直接聞く。/etc/hosts も nsswitch.conf も見ない
    ping / curl / ssh       glibc の名前解決（NSS）。/etc/nsswitch.conf の hosts: の順に見る
    getent ahosts 名前      ping や curl と同じ関数（getaddrinfo）で NSS を引き、使う順に並べる。
                            先頭の行が ping の使うアドレス（ping が何を使うか確かめる道具）
    getent hosts 名前       NSS で引くが、IPv6 を先に聞き、見つかれば IPv6 のアドレスだけを出す。
                            IPv4 と IPv6 の両方を持つ名前では、ping の答えと形が違うことがある

  ただし Ubuntu の既定（/etc/resolv.conf が 127.0.0.53）のままだと、systemd-resolved が
  /etc/hosts も読んで答えるので、host にも /etc/hosts の答えが混ざります（第8章）。

【順番を変える】

    sudo sed -i 's/^hosts:.*/hosts:          dns files/' /etc/nsswitch.conf

  とすると DNS が先になります。/etc/hosts は DNS に無い名前の予備になります。
  これは練習機のすべての名前の引き方を変えるので、ふつうは古い行を消すほうを選びます。
