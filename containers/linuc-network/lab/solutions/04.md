返事をしていたのはサーバではなく、途中の古いルータでした。

    ping -c 3 172.16.20.10
    #=> From 192.168.10.254 icmp_seq=1 Destination Net Unreachable
    ip route
    #=> default via 192.168.10.254 dev lab0 onlink
    ip route get 172.16.20.10
    #=> 172.16.20.10 via 192.168.10.254 dev lab0 src 192.168.10.2

  サーバは生きています。IPv6 では届きます（IPv6 のデフォルトルートはルータ広告で正しく入っている）。

    ping6 -c 2 fd00:20::10
    #=> 64 bytes from fd00:20::10: icmp_seq=1 ttl=63 …

【いますぐ直す（再起動で戻る）】

    sudo ip route del default
    sudo ip route add default via 192.168.10.1
    ping -c 2 172.16.20.10
    #=> 64 bytes from 172.16.20.10: icmp_seq=1 ttl=63 …

  route でも同じことができます（試験には両方の形が出ます）。

    sudo route del default gw 192.168.10.254
    sudo route add default gw 192.168.10.1
    route -n
    #=> 0.0.0.0  192.168.10.1  0.0.0.0  UG  0  0  0 lab0

  先に消さずに足すと、ip と route で結果が違います（教科書の第4章に記録があります）。

    ip route add default via …    RTNETLINK answers: File exists（宛先 0.0.0.0/0 の行がもうある）
    route add default gw …        断られずに2本目が足される。後から足した行が先に並び、そちらが使われる

【戻ることを確かめる】

    sudo ifdown lab0
    #=> RTNETLINK answers: No such process     ← ファイルに書かれた .254 の経路を消そうとして、無かった
    sudo ifup lab0
    ip route show default
    #=> default via 192.168.10.254 dev lab0 onlink   ← ファイルの値に戻った

【設定ファイルを直す（再起動しても残る）】

    sudo sed -i 's/gateway 192.168.10.254/gateway 192.168.10.1/' /etc/network/interfaces
    ifquery lab0
    #=> gateway: 192.168.10.1
    sudo ifdown lab0
    sudo ifup lab0
    ip route show default
    #=> default via 192.168.10.1 dev lab0 onlink

【ssh が切れなかった理由】

    ip route get 10.0.2.2
    #=> 10.0.2.2 dev enp0s16 src 10.0.2.15     ← via が無い＝直接つながっている

  経路表では、宛先に一番細かく（長く）一致する行が選ばれます。
  10.0.2.2 は 10.0.2.0/24 の行に一致するので、デフォルトルートが無くても、間違っていても届きます。
  デフォルトルート（0.0.0.0/0）は、どの行にも当てはまらなかったときの最後の行き先です。
