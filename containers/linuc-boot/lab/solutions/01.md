外（lab@host）で打ちます。

    virsh start linuc
    #=> Domain 'linuc' started          ← 返るのは一瞬。中の OS はまだ起動していない

    virsh autostart linuc
    #=> Domain 'linuc' marked as autostarted

    virsh dominfo linuc | grep Autostart
    #=> Autostart:      enable

  起動の様子を見たいなら、別の端末で（抜けるのは Ctrl+]）:

    virsh console linuc

  30〜90 秒待って、コンソールに linuc login: が出たら lab check 01。

【running と「起動し終わった」は別】

  virsh start の直後でも virsh domstate は running と答えます。
  running は「QEMU のプロセスが動いていて、仮想の CPU に電気が来ている」というだけで、
  中の OS が起動し終わったかどうかは OS に尋ねないと分かりません。

    virsh qemu-agent-command linuc '{"execute":"guest-ping"}'
    #=> error: Guest agent is not responding: QEMU guest agent is not connected   ← 起動の途中
    #=> {"return":{}}                                                             ← 起動し終わった後

  判定も同じ2つ（libvirt の状態と、中の OS の応答）を別々に見ています。

【自動起動の印の正体】

    ls -l ~/.config/libvirt/qemu/autostart/
    #=> linuc.xml -> /home/lab/.config/libvirt/qemu/linuc.xml

  定義へのシンボリックリンク1本です。libvirt は自分が起動したとき（この檻ではコンテナの起動時）に
  ここを見て、印の付いた仮想マシンの電源を入れます。あなたの PC の端末で

    docker stop lab-linuc-boot
    docker start lab-linuc-boot

  と打つと、誰も virsh start を打たなくても練習機が起動します（第3章）。
  外すときは virsh autostart --disable linuc。
