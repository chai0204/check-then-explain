外（lab@host）で打ちます。

    ssh-keygen -t rsa                 # 保存先・パスフレーズ・確認の3つとも Enter
    #=> Generating public/private rsa key pair.
    #   Your identification has been saved in /home/lab/.ssh/id_rsa
    #   Your public key has been saved in /home/lab/.ssh/id_rsa.pub

    ssh-copy-id -i ~/.ssh/id_rsa.pub linuc
    #=> （初回なら）Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
    #   student@127.0.0.1's password:          ← student
    #   Number of key(s) added: 1

    ssh linuc                         # 何も聞かれずに入れる
    exit

【なぜ -t rsa が要るのか】

  何も付けずに ssh-keygen を打つと、OpenSSH 9.6（Ubuntu 24.04）は Ed25519 の鍵を作ります。

    ssh-keygen
    #=> Generating public/private ed25519 key pair.
    #   … /home/lab/.ssh/id_ed25519

  鍵のファイル名は種類で決まるので、試験に出る id_rsa / id_rsa.pub は -t rsa でしか作られません。

【どこに何が増えたか】

  外（接続する側）:
    ~/.ssh/id_rsa        秘密鍵（-rw-------）。手元から出さない
    ~/.ssh/id_rsa.pub    公開鍵（-rw-r--r--）。相手に渡してよい
    ~/.ssh/known_hosts   相手（練習機）のホスト鍵。初回の yes で書かれた

  練習機（接続される側）:
    ~/.ssh/authorized_keys   外の id_rsa.pub と同じ1行（ssh-rsa AAAA…）が増えた

  ssh-copy-id は authorized_keys に1行書き足すだけです。手でやるなら:

    cat ~/.ssh/id_rsa.pub | ssh linuc 'cat >> ~/.ssh/authorized_keys'

【それでもパスワードを聞かれるとき】

  練習機の sshd は、authorized_keys や ~/.ssh が他人（other）に書ける権限だと、その鍵を使いません。
  本家の OpenSSH（RHEL 系など）は group に書けるだけでも断ります。Ubuntu（Debian）の sshd は
  「グループのメンバーが本人だけなら group に書けても許す」改造をしています。試験では 600 と答えてください。
  理由は練習機のログにだけ出ます。

    ssh linuc "sudo journalctl -u ssh -n 20 --no-pager | grep -i refused"
    #=> Authentication refused: bad ownership or modes for file /home/student/.ssh/authorized_keys

    ssh linuc 'chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys'
