端末を2つ使います（どちらも外 lab@host）。

  端末1:  virsh console linuc          （練習機の画面。抜けるのは Ctrl+]）
  端末2:  ssh linuc sudo reboot         （再起動の合図を送る）

  端末1 に GRUB のメニュー（Ubuntu / Advanced options for Ubuntu / UEFI Firmware Settings）が出たら:

    1. ↑ を1回押す                 … 10 秒の数え下げが止まる（Ubuntu が選ばれたまま）
    2. e を押す                     … 起動に使うコマンドの編集画面（setparams 'Ubuntu' から始まる）
    3. ↓ を 10 回押して linux から始まる行へ（上から 11 行目。2段に折り返している）
         linux        /vmlinuz-6.8.0-142-generic root=UUID=… ro  console=tty1 console=ttyS0,115200
    4. Ctrl+E で行末へ行き、空白を1つ空けて 3 と打つ
    5. Ctrl+X で起動する

  起動したら確かめます。

    ssh linuc cat /proc/cmdline
    #=> BOOT_IMAGE=/vmlinuz-6.8.0-142-generic root=UUID=… ro console=tty1 console=ttyS0,115200 3
    ssh linuc systemctl is-active graphical.target multi-user.target
    #=> inactive
    #   active

    lab check 03

【何をしたのか】

  GRUB（ブートローダ）がカーネルに渡す引数を、この1回の起動だけ書き換えました。
  カーネルが使わない語は PID 1 の systemd に渡り、systemd は既定（default.target）の代わりにそれを目標にします。
  数字の 3 はランレベル3 で、systemd は runlevel3.target（→ multi-user.target）と読み替えます。
  設定ファイルは何も変えていないので、次に普通に起動すれば graphical.target に戻ります。

  同じ意味の書き方:
    3                                  ランレベルの数字
    systemd.unit=multi-user.target     ターゲットの名前で
  シングルユーザモードなら single か 1、または systemd.unit=rescue.target（第6章）。

【長い語を足すとき】

  この編集画面は横 80 桁のシリアル端末で、linux の行の2段目の残りは 20 桁ほどです。
  systemd.unit=multi-user.target のような長い語は右端の \ で折り返して表示され、
  行が二重に見えることもあります（描き直しの乱れで、中身は1行です）。打ち間違えに気づきにくいので、
  足した語が本当に渡ったかは、起動した後に cat /proc/cmdline で確かめてください。短い 3 や single なら折り返しません。
