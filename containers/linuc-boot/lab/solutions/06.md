    pgrep -a lab-hog
    kill $(pgrep -x lab-hog)                      # TERM を送る
    ps -o pid,stat,comm -p $(pgrep -x lab-hog)    # まだいる
    grep -E '^Sig(Ign|Cgt)' /proc/$(pgrep -x lab-hog)/status
    #=> SigIgn:	0000000000005007                  ← 1・2・3・13・15番を無視している（下の読み方）
    kill -KILL $(pgrep -x lab-hog)                # = kill -9。KILL は無視できない
    pgrep -a lab-hog; echo "終了コード $?"
    #=> 終了コード 1                               ← もういない

    lab check 06

【SigIgn の読み方】

  16進数のビット列で、右端のビットが1番のシグナルです。

    0x5007 = 0101 0000 0000 0111（2進数）
              ↑ ↑            ↑↑↑
              │ 13番（PIPE）  3番（QUIT）・2番（INT）・1番（HUP）
              15番（TERM）

  lab-hog は起動するとすぐ trap '' TERM INT HUP を実行し、この3つを無視するようにしています。
  残りの2つは、lab-hog が自分で決めたものではありません。QUIT は bash がいつも無視するもの、
  PIPE は systemd がサービスを起動するときに無視させるもの（IgnoreSIGPIPE=yes が既定）です。
  kill は合図を送るだけなので、受け取る側が無視すれば何も起きません。
  KILL（9）と STOP（19）だけは、受け取る側が無視も捕捉もできず、カーネルが直接処理します。

【名前で送る】

    pkill -KILL lab-hog        # 名前（正規表現）で
    killall -KILL lab-hog      # 名前（完全一致）で

【systemctl stop だと】

  lab-hog は systemd のサービスとして動いているので、sudo systemctl stop lab-hog でも止まります。
  systemd もまず TERM を送り、無視されると 10 秒待って（TimeoutStopSec=10s）KILL を送ります。
  判定はどちらでも合格にして、どちらで止まったかを表示します。
