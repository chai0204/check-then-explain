【nohup で動かす】

    nohup lab-count &
    #=> nohup: ignoring input and appending output to 'nohup.out'
    （Enter を押して、プロンプトを出す）
    （もう一度 Enter を押してから ~ と . を続けて押す）
    #=> Connection to 127.0.0.1 closed.

    lab check 07

    ssh linuc 'tail -3 ~/nohup.out'      # 数え続けている

【tmux で動かす】

    tmux new -s work
    lab-count
    （Ctrl+B を押してから d）
    #=> [detached (from session work)]
    （Enter → ~ → . で切断）

    lab check 07
    ssh linuc tmux ls
    #=> work: 1 windows (created …)
    ssh -t linuc tmux attach -t work     # 戻る。Ctrl+C で止め、exit で tmux を終える

【なぜ & だけではだめなのか】

  回線が切れると、ログインしていたシェルに SIGHUP（1番）が届き、シェルはそれを自分のジョブに配ります。
  & で動かしただけのジョブは HUP を受けて止まります。

    nohup  … HUP を無視するようにしてから起動する（/proc/PID/status の SigIgn の右端のビットが 1）
    tmux / screen … 端末ごと練習機の中に残すので、ssh のセッションの子ではなくなる

  ただし exit で普通に抜けたときは、bash は（huponexit が off なら）ジョブに HUP を配りません。
  だから & のジョブは exit では生き残り、切断で消えます（第9章）。判定は「切断されても生き残れる形か」を見ます。
