演習 01 — データベースを1個のファイルとして見る                     影響度 A / 目安 8分

  ~/work/01 で作業します。まだ移動していなければ、先にこれを打ってください。

      cd ~/work/01

  ここ以外のディレクトリでは、ファイルを作れないことがあります（理由は最後に書きます）。

【やること】

  1. sqlite3 で notes.db という DB を作り、次のテーブルを1つ置いてください。

       notes(id INTEGER PRIMARY KEY, body TEXT)

  2. そこに何か1行以上入れてください。body の中身は何でもかまいません。

  3. できたファイルについて、次の3つを自分の目で確認してください。

       ls -l notes.db            サイズは何バイトか
       file notes.db             file コマンドは何と言うか
       xxd -l 16 notes.db        先頭16バイトに何が書かれているか

  4. 最後に、この DB を動かしているサーバのプロセスを探してください。
     3通り打ってみてください。

       ps -ef                          ← いま何が動いているか、全部
       ps -ef | grep -c "[s]qlite"     ← sqlite を含む行を数える
       ps -ef | grep -c "sqlite"       ← 角括弧を外すとどうなるか

     下2つで結果が変わります。**なぜ変わるのか**を考えてください。
     そして、どちらが「本当の答え」でしょうか。

【できたら】

  lab check 01

【ヒントが欲しいとき】

  lab hint 01        3段階で出ます
  lab solve 01       模範解答（見ても構いません）

【この演習で確かめること】

  ・DB が「1個のファイル」であること
  ・そのファイルの先頭に何が書かれているか
  ・待ち受けているサーバのプロセスが存在しないこと

【詰まったら: unable to open database file が出る場合】

  Error: unable to open database "notes.db": unable to open database file

  このメッセージは「ファイルが開けない」と言っていますが、**原因はたいてい
  いまいるディレクトリに書き込めないこと**です。pwd を打って確認してください。

      pwd        ← /home/lab/work/01 になっていますか
      ls -ld .   ← 自分に w が付いていますか

  たとえば /home は root の所有なので、lab ユーザーはそこにファイルを作れません。

  なぜディレクトリの権限が関係するのか。SQLite は書き込みのとき、
  **DB ファイルの隣にもう1つファイルを作ります**。新しいファイルを作る操作は
  ディレクトリへの書き込みなので、DB ファイル側の権限だけでは足りません。

  ちなみに sqlite3 を引数なしで打つとプロンプトは出ます。
  これは**メモリ上の一時データベース**を開いていて、ファイルを作らないからです。

  この「メッセージが指すものと、実際の原因が違う」現象は第5章の主題です。
  いまここで踏んだなら、第5章は実質もう半分終わっています。
