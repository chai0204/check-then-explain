演習 05 — 書ける権限があるのに、書けない                            影響度 A / 目安 12分

  ~/work/05 で作業します。この演習がこの教材の山場です。

【やること】

  1. sub という名前のディレクトリを作り、その中に d.db を作ってください。
     t(n INTEGER) を置いて、1行入れます。

  2. できたものの権限を2つとも確認してください。

       ls -ld sub          ← ディレクトリの権限
       ls -l sub/d.db      ← DB ファイルの権限

     どちらに書き込み権限（w）が付いていますか。

  3. **DB ファイルには触らず、ディレクトリだけ**読み取り専用にしてください。

       chmod 555 sub

     もう一度2つの権限を確認してください。d.db の w はまだ付いていますね。

  4. この状態で、もう1行入れてみてください。

       sqlite3 sub/d.db 'INSERT INTO t VALUES(2);'

     何が起きましたか。メッセージを ~/work/05/observed.txt に貼ってください。

  5. **メッセージをよく読んでください。** そのメッセージは、何が readonly だと言っていますか。
     そして実際に readonly なのは何でしょうか。

  6. 読み取りはできますか。

       sqlite3 sub/d.db 'SELECT count(*) FROM t;'

  7. 原因を直して、2行目を入れられる状態にしてください。
     最終的に t が2行になっていれば完了です。

【できたら】

  lab check 05

【考えてほしいこと】

  DB ファイルに書き込み権限があるのに書けないのは、
  SQLite が **DB ファイル以外のものを、同じディレクトリに作ろうとしている**からです。
  それは何で、なぜ同じディレクトリでなければならないのでしょうか。
