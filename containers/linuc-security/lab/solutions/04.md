deploy に journalctl だけを sudo で許します。/etc/sudoers 本体は触りません。

    echo 'deploy ALL=(root) NOPASSWD: /usr/bin/journalctl' | sudo tee /etc/sudoers.d/deploy
    ls -l /etc/sudoers.d/deploy                  #=> -rw-r--r-- root root（tee で作ると 644。これは読まれる）
    sudo chmod 440 /etc/sudoers.d/deploy        # 推奨の 440 にそろえる
    sudo visudo -c                               #=> すべて parsed OK

確かめます（deploy になって打つ）。

    sudo -u deploy -i
    sudo -n -l                     #=> (root) NOPASSWD: /usr/bin/journalctl
    sudo -n journalctl -n 1        #=> ログが1行出る（許可）
    sudo -n id                     #=> sudo: a password is required（拒否）
    exit

【罠 — 持ち主と権限が緩いと読まれない】
  sudo は、次のどちらかに当たるファイルを読まずに飛ばします（警告は出すが従わない）。

    other が書ける（例: 666）          → sudo: /etc/sudoers.d/deploy is world writable
    root 以外のグループが書ける（例: 660 で group が deploy）
                                       → sudo: /etc/sudoers.d/deploy is owned by gid 1002, should be 0

  飛ばされると、許したはずの journalctl も通らなくなります。root:root の 664 は読まれますが、
  推奨は 440・root:root です。visudo -c は構文だけでなくこの持ち主と権限も確かめるので、
  置いた後に誰かが権限を変えても、visudo -c を打ち直せば見つかります。

【壊れた行は】
  いまの sudo（1.9 系。この練習機は 1.9.15p5）は、構文の壊れた行を捨てて残りで動きます
  （error_recovery。既定で有効）。ただし自分を許す行を壊せば、その権限を失います。
  古い sudo や error_recovery を切った設定では、壊れた sudoers で sudo 全体が止まります。

【要点】sudoers は /etc/sudoers.d/ に 440・root:root で置き、visudo -c で構文と権限を確かめます。
