5種類を作り、vdb6 の ext4 の予約を 1% にします。

    sudo mkfs.vfat -F 32 /dev/vdb1
    sudo mkfs -t ext3 -L NEWBOOT /dev/vdb2
    sudo mkfs.xfs -L ROOT /dev/vdb4
    sudo mkfs.btrfs -L VAR /dev/vdb5
    sudo mkfs.ext4 -L HOME /dev/vdb6
    sudo tune2fs -m 1 /dev/vdb6
    #=> Setting reserved blocks percentage to 1% (998 blocks)

    lsblk -o NAME,FSTYPE,LABEL,UUID /dev/vdb

【ラベルを BOOT にしない理由】

  この練習機自身の /etc/fstab は /boot を LABEL=BOOT で探しています。
  vdb2 にも BOOT と付けると、同じラベルが2つになり、LABEL=BOOT がどちらを指すか決まらなくなります
  （第8章で実際に起こして確かめます）。ここでは NEWBOOT にしました。

【予約とは】

  ext4 は、ディスクがいっぱいになっても root（とデーモン）が書けるように、既定で 5% を取っておきます。
  df の Avail（一般ユーザが使える量）が Size − Used より小さいのは、主にこの予約のためです。

    sudo tune2fs -l /dev/vdb6 | grep -E "^(Block count|Reserved block count)"

  残りの差は、ext4 が自分の管理作業のために取っておく分（reserved_clusters。ブロック数の 2%、
  上限あり）で、tune2fs -m 0 にしても残ります。マウント中なら次で読めます。

    cat /sys/fs/ext4/vdb6/reserved_clusters

  データ専用のディスクなら root の予約を 1%（や 0%）に減らしてよく、/ を置くディスクでは減らしすぎないこと。
