カーネルは HDD か SSD かを測っていません。装置が名乗った値（rotational）を /sys に出しているだけです。
その値は root が書き換えられ、udev の規則にしておけば起動のたびに書き換えられます。

    lsblk -d -o NAME,TRAN,ROTA,SIZE,MODEL
    #=> sda  sata  0 …  QEMU HARDDISK   ← 型番は HARDDISK なのに「回転しない」と名乗っている
    #   vdb  virtio 1 …

    cat /sys/block/vdb/queue/rotational
    #=> 1

【その場で変える（再起動すると戻る）】

    echo 0 | sudo tee /sys/block/vdb/queue/rotational
    lsblk -d -o NAME,ROTA /dev/vdb
    #=> vdb     0

【起動のたびに変える（udev の規則）】

    echo 'ACTION=="add|change", SUBSYSTEM=="block", KERNEL=="vdb", ATTR{queue/rotational}="0"' \
      | sudo tee /etc/udev/rules.d/60-lab-ssd.rules
    sudo udevadm trigger --action=add --subsystem-match=block --sysname-match=vdb --settle
    cat /sys/block/vdb/queue/rotational
    #=> 0

  起動のとき、udev は見つかったすべての装置について add イベントを処理します。
  trigger --action=add は、その1台分を手で起こすコマンドです（--settle は、udev が処理し終えるまで待つ。
  付けないと、すぐ後の cat が書き換わる前の 1 を読むことがあります）。判定もこれで確かめています。

【なぜ sda は SSD なのか】

  外（lab@host）で練習機の定義を見ると分かります。

    virsh dumpxml linuc | grep rotation_rate
    #=> <target dev='sda' bus='sata' rotation_rate='1'/>

  SATA の装置は、自分の回転数を答える欄（ATA の IDENTIFY の1語）を持っています。
  QEMU はそこに 1（回転しない）と答え、カーネルはそれを信じました。中身は vdc と同じ種類のファイルです。
