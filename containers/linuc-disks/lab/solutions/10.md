外したドライバは、次に挿したとき udev が読み込み直します。
止めるには「読み込む側」が読む表（/etc/modprobe.d/）に書きます。

    printf "blacklist usb_storage\nblacklist uas\n" | sudo tee /etc/modprobe.d/lab-usb.conf
    sudo modprobe -r uas                  # いま読み込まれている分を外す（usb_storage も一緒に外れる）

  新しいファイルを置いたことには、udev が自分で気づきます。外で USB メモリを挿して確かめ、抜いておきます。

    外で:  virsh attach-device linuc ~/vm/extra/usb-a.xml
    中で:  lsusb -t
           #=>     |__ Port 001: Dev 00N, If 0, Class=Mass Storage, Driver=[none], 5000M
           lsmod | grep -E "usb_storage|uas"      # 何も出ない
    外で:  virsh detach-device linuc ~/vm/extra/usb-a.xml

  USB 機器としては見えたまま、ドライバが付かないのでディスク（/dev/sdb）になりません。

【なぜ blacklist usb_storage だけでは足りないのか】

  挿した USB メモリの「別名」（modalias）は、2つのドライバに当てはまります。

    modprobe --resolve-alias $(cat /sys/bus/usb/devices/2-1:1.0/modalias)
    #=> uas
    #   usb_storage

  blacklist usb_storage は「別名で探したときに usb_storage を候補から外す」だけです。
  uas はそのまま読み込まれ、uas は usb_storage に依存しているので、依存として読み込まれます。

    modprobe --show-depends uas
    #=> insmod …/usb-storage.ko.zst
    #   insmod …/uas.ko.zst

【すでにあるファイルを書き換えたとき】

  udev は /etc/modprobe.d に「ファイルが増えた・消えた」ことには気づきますが、
  tee や > ですでにあるファイルの中身だけを書き換えたことには気づかず、前の中身のまま動きます
  （sed -i のように、ファイルを新しいものに置き換える書き換え方なら気づきます）。
  中身だけを書き換えたら udev を再起動します（第11章と同じ）。

    sudo systemctl restart systemd-udevd

【install 名前 /bin/false】

  blacklist の代わりに、読み込みそのものを失敗させる書き方もあります。

    echo "install usb_storage /bin/false" | sudo tee /etc/modprobe.d/lab-usb-install.conf

  modprobe で読み込もうとすると（udev からでも、手でも、uas の依存としてでも）失敗します。
  ただし insmod（ファイルを直接読み込む）は /etc/modprobe.d を読まないので止まりません。

【戻すとき】

    sudo rm /etc/modprobe.d/lab-usb.conf /etc/modprobe.d/lab-usb-install.conf

  ファイルを消したことにも udev は気づくので、再起動は要りません。
