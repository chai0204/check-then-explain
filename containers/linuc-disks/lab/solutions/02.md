パーティションテーブルは目次です。行を消しても中身は残っているので、
同じ位置・同じ大きさで行を書き戻せば、中身はそのまま読めます。

    cat ~/vdd-before.txt
    #=> /dev/vdd1 : start=        2048, size=      204800, type=83
    #   /dev/vdd2 : start=      206848, size=      204800, type=83

    sudo fdisk /dev/vdd
      Command (m for help): n
      Select (default p): p
      Partition number (1,3,4, default 1): 1
      First sector (2048-524287, default 2048):                    ← Enter
      Last sector, +/-sectors or +/-size{K,M,G,T,P} (2048-206847, default 206847):   ← Enter
      Partition #1 contains a ext4 signature.
      Do you want to remove the signature? [Y]es/[N]o: N           ← ここで N
      Command (m for help): w

    sudo mount -o ro /dev/vdd1 /mnt
    cat /mnt/aikotoba.txt
    #=> 合言葉: やまびこ
    sudo umount /mnt

  最後のセクタは、空きの終わり（vdd2 の手前）がちょうど 206847 なので Enter で揃います。

【sfdisk で書き戻す】

  保存した表をそのまま流し込んでも同じです。

    sudo sfdisk /dev/vdd < ~/vdd-before.txt

【Y と答えてしまったら】

  fdisk が消すのは ext4 の「印」で、実体はスーパーブロックの中の2バイト（場所 1080 の 53 ef）です。
  ext4 の構造もファイルも残っていますが、印が無いので blkid も mount も ext4 と認めません。

    sudo dd if=/dev/vdd1 bs=1 skip=1080 count=2 status=none | od -A d -t x1
    #=> 0000000 00 00                    ← 消された
    sudo dd if=/dev/vdd2 bs=1 skip=1080 count=2 status=none | od -A d -t x1
    #=> 0000000 53 ef                    ← 消されていない vdd2 の同じ場所

  この2バイトを書き戻すと、元の ext4 として読めます（著者が試して、e2fsck -fn で異常なし）。

    printf "\x53\xef" | sudo dd of=/dev/vdd1 bs=1 seek=1080 conv=notrunc status=none
    sudo blkid -p -o export /dev/vdd1     # TYPE=ext4 と元の UUID が戻る

  ふつうは e2fsck -b でスーパーブロックの写しから直しますが、この ext4 は 100MiB（ブロックが
  1つのグループにしか無い）なので、写しを持っていません。最初から N と答えるのが確実です。
