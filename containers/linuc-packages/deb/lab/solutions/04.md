台帳と照らし合わせて欠けを見つけ、同じ版を入れ直します。

    labbackup
    #=> bash: labbackup: command not found
    dpkg -l labbackup | tail -1
    #=> ii  labbackup  1.0  all  practice backup command    ← 台帳は「入っている」
    dpkg -L labbackup
    #=> … /usr/bin/labbackup …                              ← 台帳はこのファイルを覚えている
    dpkg -V labbackup
    #=> missing     /usr/bin/labbackup                      ← でも、ファイルが無い

    sudo apt reinstall labbackup
    #=> … 1 reinstalled …
    #   Unpacking labbackup (1.0) over (1.0) ...
    dpkg -V labbackup                                       # 何も出ない＝台帳どおり
    labbackup
    #=> labbackup 1.0: /etc を控えました（練習用なので、実際には何も保存しません）

【なぜ台帳は ii のままだったのか】

  台帳（/var/lib/dpkg/）を書くのは dpkg だけです。rm でファイルを消しても、
  台帳は書き換わりません。だから dpkg -l は「入っている」と答え続け、
  dpkg -L もファイルの一覧を出し続けます。ファイルがいま本当にあるかは、
  dpkg -V でディスクと照らし合わせて初めて分かります。

【dpkg -V の読み方】

    missing     /usr/bin/labbackup   台帳にあるのに、ファイルが無い
    ??5??????   /usr/bin/labbackup   中身の要約（ダイジェスト）が違う（5 の位置）。? は確かめていない欄
    何も出ない                         全部、台帳どおり

  違いがあっても終了コードは 0 のままです。出力が空かどうかで判断します。

【別のやり方】

    sudo apt install --reinstall labbackup    apt reinstall と同じ
