dpkg で入れると途中で止まり、apt が続きをやります。

    cd ~/work/07
    dpkg -I labnote_1.0_all.deb | grep Depends
    #=>  Depends: labnote-data (>= 1.0)

    sudo dpkg -i labnote_1.0_all.deb
    #=> dpkg: dependency problems prevent configuration of labnote:
    #    labnote depends on labnote-data (>= 1.0); however:
    #     Package labnote-data is not installed.
    dpkg -l labnote | tail -1
    #=> iU  labnote  1.0  ...       ← 展開済み・設定前で止まっている

    sudo apt --fix-broken install    # = sudo apt -f install
    #=> The following NEW packages will be installed:
    #     labnote-data
    dpkg -l labnote labnote-data | tail -2
    #=> ii  labnote       1.0 ...
    #   ii  labnote-data  1.0 ...
    labnote
    #=> labnote: labnote-data から読んだ1行です

【なぜ dpkg は依存を取ってこないのか】

  dpkg が読むのは、手元の .deb と、自分の台帳（/var/lib/dpkg/status）だけです。
  labnote-data がどこにあるかを知るには、リポジトリの目録が要ります。
  それを持っているのは apt です（/var/lib/apt/lists/）。

  dpkg は「依存が満たされていない」ことは分かるので、中身を展開したところで止まり、
  台帳に iU（展開済み・未設定）と書きます。ファイルは置かれているので、
  labnote を打つと動かずに失敗します。

【満たされない依存は、関係ないパッケージの操作も止める】

  labnote のように依存が満たされないまま残っている間は、apt install で別のパッケージを
  入れようとしても「E: Unmet dependencies. Try 'apt --fix-broken install'」で止まります。
  apt は台帳全体の依存が満たされた状態しか作らないからです。

  止める原因は iU そのものではなく、満たされない依存のほうです。依存が満たされている iU
  （たとえば dpkg --unpack で展開だけしたもの）なら、apt は断らずに、次の操作のついでに
  設定を済ませます。

【別解】

    sudo apt install ./labnote_1.0_all.deb

  ./ を付けると apt は名前ではなくファイルとして扱い、依存は目録から解決します。
  最後に N: Download is performed unsandboxed as root … という行が出ますが、失敗ではなく
  知らせ（Notice）です。apt は取ってきたファイルを、権限を絞った利用者 _apt に読ませる決まりですが、
  ~/work/07 は _apt が入れない場所なので、root のまま読んだ、と言っています。
  ./ を付けずに apt install labnote_1.0_all.deb と打つと、そういう名前のパッケージを
  目録から探して見つかりません。
