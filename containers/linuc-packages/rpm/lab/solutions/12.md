yumdownloader は目録を読んでファイルを取るだけで、入れません。入れるのは rpm です。

    cd ~/work/12
    yumdownloader labtool
    sudo rpm -ivh labtool-1.0-1.noarch.rpm
    #=> error: Failed dependencies:
    #   	labtool-data >= 1.0 is needed by labtool-1.0-1.noarch

    yumdownloader --resolve labtool        # 依存も一緒に取る
    ls -l
    #=> labtool-1.0-1.noarch.rpm
    #   labtool-data-1.0-1.noarch.rpm
    sudo rpm -ivh labtool-1.0-1.noarch.rpm labtool-data-1.0-1.noarch.rpm
    labtool
    #=> labtool: labtool-data から読んだ1行です

    yum list installed labtool labtool-data
    #=> labtool.noarch       1.0-1   @System   ← rpm で入れたものは @System
    #   labtool-data.noarch  1.0-1   @System

【yumdownloader の主なオプション（理論編に出たのは --resolve だけ。ほかは参考）】

    yumdownloader PKG                  カレントディレクトリに取る
    yumdownloader --destdir DIR PKG    DIR に取る
    yumdownloader --resolve PKG        まだ入っていない依存も一緒に取る
    yumdownloader --source PKG         ソース RPM（.src.rpm）を取る

  RHEL 8 以降の実体は dnf download です。ls -l /usr/bin/yumdownloader と打つと、
  リンク先として -> /usr/libexec/dnf-utils が見えます。dnf-utils は、呼ばれた名前を見て
  dnf の働き（ここでは dnf download）を呼ぶ道具で、yumdownloader --help の1行目も
  usage: dnf download です。
  RHEL 7 の yumdownloader は、yum-utils に入った独立した Python のプログラムです。使い方は同じです。

【rpm が依存を取りに行かない理由】

  rpm が読むのは、手元の .rpm と、自分の台帳（/var/lib/rpm）だけです。
  labtool-data がどこにあるかは、リポジトリの目録を読む yum（dnf）しか知りません。
  だから rpm は、足りないと分かった時点で何も入れずに止まります。
  （dpkg は展開まで進めて iU で止まりましたが、rpm は1つも入れません）
