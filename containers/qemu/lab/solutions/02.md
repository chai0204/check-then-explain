~/work/02 で打ちます。

    cd ~/work/02
    qemu-img create -f qcow2 -b /var/lib/lab-vm/linuc-guest.qcow2 -F qcow2 linuc.qcow2
    ls -l linuc.qcow2
    #=> -rw-r--r-- 1 lab lab 196928 …        ← 作った直後は 192KiB ほど。写しではない

    qemu-system-x86_64 -m 1536 -smp 2 -drive file=linuc.qcow2,if=virtio -display none -serial mon:stdio

  linuc login: が出たら Ctrl-a c で QEMU のモニタに切り替え、

    (qemu) system_powerdown

  練習機が止まると QEMU も終わり、プロンプトに戻ります。

    lab check 02

【何が起きたか】

  -b /var/lib/lab-vm/linuc-guest.qcow2 -F qcow2 は「読めないところは、この qcow2 に聞け」という指定で、
  linuc.qcow2 の頭（ヘッダ）に土台のパスとして書き込まれます。練習機が起動のあいだに書いたところ
  （ログや時刻の記録など）だけが linuc.qcow2 に入り、土台は1バイトも変わりません。
  sha256sum /var/lib/lab-vm/linuc-guest.qcow2 は、何度起動しても /var/lib/lab-vm/linuc-guest.sha256 と同じです。

【quit で止めると】

  quit は QEMU のプロセスをその場で終わらせます（電源を抜くのと同じ）。差分ディスクは壊れませんが、
  練習機の中の OS は後片付けをしないまま止まるので、次の起動でファイルシステムの回復が走ります。
  判定はその印を読みます。/ の ext4 は、使っているあいだ needs_recovery の印を立て、正しく止まるときに下ろします。
  quit で止めると印が立ったまま残るので ✗ になります（もう一度起動して system_powerdown で止めれば ✔）。
