~/work/05 で打ちます。

    cd ~/work/05
    qemu-img create -f qcow2 -b /var/lib/lab-vm/linuc-guest.qcow2 -F qcow2 linuc.qcow2
    qemu-system-x86_64 -machine q35 -m 1536 -smp 2 -drive file=linuc.qcow2,if=virtio \
      -netdev user,id=n0,hostfwd=tcp:127.0.0.1:2222-:22 -device virtio-net-pci,netdev=n0,addr=0x10 \
      -display none -serial file:serial.log -qmp unix:qmp.sock,server=on,wait=off -daemonize
    until ssh -o ConnectTimeout=3 linuc true 2>/dev/null; do sleep 3; done    ← 30〜60 秒
    ssh linuc ip -br a
    #=> lo        UNKNOWN  127.0.0.1/8 ::1/128
    #   enp0s16   UP       10.0.2.15/24 …
    lab check 05

  止めるとき:

    printf '%s\n' '{"execute":"qmp_capabilities"}' '{"execute":"system_powerdown"}' | socat - UNIX-CONNECT:qmp.sock

【それぞれの指定】

  -machine q35                  libvirt の練習機と同じチップセット。PCI のスロットの名前の付き方がそろう
  -netdev user,…,hostfwd=…      QEMU の中のネットワーク（ユーザモード）。外の 127.0.0.1:2222 を QEMU が待ち受け、
                                来た接続を練習機の 10.0.2.15:22 へ渡す
  -device virtio-net-pci,…,addr=0x10
                                NIC をスロット 0x10（16）に差す。練習機の中では enp0s16 になり、DHCP で 10.0.2.15 をもらう
  -daemonize と -serial file: / -qmp unix:
                                端末から切り離す。シリアルとモニタの行き先を別に決める（演習 01）

【練習機から見た接続相手】

    ssh linuc 'echo $SSH_CONNECTION'
    #=> 10.0.2.2 … 10.0.2.15 22               ← 相手は 10.0.2.2（QEMU が演じるゲートウェイ）に見える
