~/work/01 で打ちます。

    cd ~/work/01
    qemu-system-x86_64 -display none -machine graphics=off \
      -serial file:serial.log -qmp unix:qmp.sock,server=on,wait=off -daemonize
    lab check 01

  止めるとき:

    printf '%s\n' '{"execute":"qmp_capabilities"}' '{"execute":"quit"}' | socat - UNIX-CONNECT:qmp.sock

【それぞれの指定】

  -display none          画面（VNC など）を作らない
  -machine graphics=off  「この PC には画面が無い」とファームウェアに伝える。SeaBIOS はシリアルを画面の代わりにする
  -serial file:…         シリアルポートの出力をファイルに書く（いつもは端末につないでいた線の先を付け替えただけ）
  -qmp unix:…            モニタを、機械が読み書きする JSON の窓口（QMP）として UNIX ソケットで開く
  -daemonize             端末から切り離して後ろで動く（作業ディレクトリは / に移る）。-nographic と組み合わせるなら、
                         シリアル・モニタ・パラレルの行き先を全部指定する（-parallel none まで）

  -nographic は「-display none」「graphics=off」「-serial mon:stdio」（とパラレルポートを null に）をまとめた指定でした。
  切り離すと標準入出力が無くなるので、まとめ役を使わずに1つずつ書くほうが素直です。

【判定が見たもの】

  QMP の query-status（running）、/machine の graphics（false）、query-chardev の serial0 の行き先（file）、
  そのソケットを待ち受けている QEMU のプロセス（制御端末が無いこと＝端末から切り離されていること、serial.log を開いていること）、
  serial.log の中の SeaBIOS の文字。libvirt も、仮想マシンを動かしたまま同じ QMP で問い合わせています（第7章）。
