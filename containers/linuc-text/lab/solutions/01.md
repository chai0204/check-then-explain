環境変数として渡します。値を入れるだけでは足りません。

    export EDITOR=vi
    lab check 01

【EDITOR=vi だけでは通らない理由】

    EDITOR=vi
    bash -c 'echo "[$EDITOR]"'
    #=> []           ← 子のシェルからは見えない

  EDITOR=vi は、このシェルの中に「シェル変数」を1つ作るだけです。
  判定スクリプトは lab の子、lab はこのシェルの子なので、シェル変数は届きません。
  export を付けると環境変数になり、以後に起動する子プロセスすべてに写しが渡ります。

    export EDITOR
    bash -c 'echo "[$EDITOR]"'
    #=> [vi]

  見分け方: set はシェル変数も環境変数も全部出し、env は環境変数だけを出します。

    set | grep '^EDITOR='     # どちらでも出る
    env | grep '^EDITOR='     # export した後だけ出る

【EDITOR が空なのに nano が開く理由】

    ls -l /usr/bin/editor /etc/alternatives/editor
    #=> /usr/bin/editor -> /etc/alternatives/editor -> /bin/nano

  Debian / Ubuntu のプログラム（less・sudoedit・bash の fc など）は、
  エディタを指定する変数が1つも無いと /usr/bin/editor を開きます。
  見る変数と順番はプログラムごとに違います（less は VISUAL → EDITOR、
  sudoedit は SUDO_EDITOR → VISUAL → EDITOR、bash の fc は FCEDIT → EDITOR）。
  /usr/bin/editor は alternatives で nano を指しています（nano の優先度 40 ＞ vim の 30）。
  システム全体の既定を変えるのは update-alternatives --config editor（root が要る）、
  自分だけ変えるのが EDITOR です。

【sensible-editor が見る順番】

  sensible-editor は VISUAL → EDITOR の順に見ます。VISUAL があると EDITOR より先に使われます。
  どちらも無く ~/.selected_editor も無いとき、端末から起動すると、エディタを開く前に
  select-editor の選択画面を出し、選んだものを ~/.selected_editor に残します
  （以後は /usr/bin/editor より優先される。消せば元に戻る）。
  判定は標準入力を /dev/null にして起動しているので、この画面は出ません。

【1回だけ別のエディタにする】

    EDITOR=nano sensible-editor --version | head -1
    #=>  GNU nano, version 7.2

  コマンドの前に「変数=値」を書くと、そのコマンドにだけ環境変数として渡ります。
  シェルの EDITOR は変わりません。

【起動し直しても残す】

    echo 'export EDITOR=vi' >> ~/.bashrc

  ただしこの檻はホームディレクトリをボリュームに置いていないので、
  コンテナを終了すると ~/.bashrc の変更も消えます（作業と進捗のボリュームだけが残ります）。
