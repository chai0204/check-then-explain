PATH の最後に ~/work/02/bin を足します。

    PATH="$PATH:$HOME/work/02/bin"
    cd /tmp
    greet
    #=> greet: こんにちは。私は /home/lab/work/02/bin/greet として呼ばれました
    lab check 02

【名前だけでは見つからなかった理由】

  名前だけで打たれたコマンドは、シェルが PATH の並びを前から順に探します。

    echo "$PATH"
    #=> /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

  カレントディレクトリはこの並びに入っていないので、そこにあっても探されません。
  だから ./greet や bin/greet のように、場所を書いて打つ必要がありました
  （/ を含む名前は PATH を使わず、その場所を直接開きます）。

【相対パスで足すと /tmp から見つからない】

    cd ~/work/02
    PATH="$PATH:bin"          # ← 相対パス
    greet                     # ここでは動く
    cd /tmp; greet            # bin は /tmp/bin を指すので見つからない

  PATH の各要素は「探すときのカレントディレクトリ」から解釈されます。
  どこからでも同じ場所を指すのは、/ から始まる絶対パスだけです。

【引用符の中の ~】

  PATH="$PATH:~/work/02/bin" と書くと、~ は展開されずに文字のまま入ります。
  bash は探すときに ~ を補いますが、bash 以外（env や xargs が起動するとき）は補いません。
  $HOME と書けば、引用符の中でも展開されます。

【PATH を上書きしてしまったら】

  PATH=~/work/02/bin のように元の値をつながずに書くと、ls も lab も見つからなくなります。
  exit して起動し直せば元に戻ります（作業と進捗のボリュームは残ります）。
