演習 05 — 練習機の CPU から、仮想化支援の印を消す                  影響度 B / 目安 12分

  外（lab@host）で打ちます。TCG でも KVM でもできます（KVM が使えない檻でもできます）。

【いまの状態を見てください】（練習機が動いていれば）

    ssh linuc "grep -o -w -E 'vmx|svm' /proc/cpuinfo | sort | uniq -c"
    ssh linuc ls -l /dev/kvm

  練習機の CPU が仮想化支援の印を名乗っていると、練習機のカーネルは KVM を用意し、
  練習機の中にも /dev/kvm ができます（入れ子の仮想化の入口）。

【やること】

  練習機を起動し直し、練習機の CPU が vmx も svm も名乗らないようにしてください。
  練習機の中に /dev/kvm ができないことも確かめてください。

  -cpu で選んだ CPU のモデルの後ろに、機能を1つずつ足したり消したりする書き方があります。
  TCG なら、既定の型（qemu64）か max から消します。どちらも TCG では svm を名乗る型です
  （EPYC など、ほかにも svm を名乗る型はありますが、判定が見分けられるのはこの2つの名乗りだけです）。
  KVM なら host（あなたの PC の CPU をそのまま見せる型）から消します。
  もともと印を持たない型（TCG の Nehalem などの Intel の型、Intel の PC の KVM の既定の型）を選んでも、
  消したことにはなりません。

  判定では次を確かめます。

      練習機の中の /proc/cpuinfo に vmx も svm も無い
      練習機の中に /dev/kvm が無い
      TCG で動いているときは、練習機の CPU が qemu64 か max の名乗り（メーカー・モデル名・型番）のまま
      KVM で動いているときは、練習機の CPU があなたの PC の CPU を名乗っている（-cpu host から消した）

  あなたの PC の KVM が入れ子の仮想化を許していない（/sys/module/kvm_intel/parameters/nested が N、
  AMD は kvm_amd が 0）と、-cpu host にも初めから印がありません。そのときの KVM の判定は
  「前提不足」になるので、TCG でやってください。
