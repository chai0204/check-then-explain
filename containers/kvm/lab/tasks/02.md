演習 02 — この檻の lab が /dev/kvm を開けるようにする              影響度 B / 目安 10分

  あなたの PC の端末（コンテナの外）と、外（lab@host）で打ちます。
  KVM が使える Linux の PC が前提です。docker が動いているカーネルに KVM が無い環境では、
  判定は「前提不足」になります（そのときは本文の記録で読んでください）。
  macOS・Windows の Docker Desktop では、著者は試していません。

【いまの状態を見てください】（外で）

    ls -l /dev/kvm
    id
    grep -E '^(Groups|CapEff|CapBnd)' /proc/self/status

【やること】

  この檻を起動し直して、檻の中の lab が /dev/kvm を読み書きで開けるようにしてください。
  渡してよいのは /dev/kvm と、それを開くのに要るグループだけです。
  --privileged や --cap-add は使いません（判定は、特権が増えていないことも確かめます）。

  起動し直しても、進捗と練習機のディスクは残ります（どちらもボリュームに入っています）。
  起動のコマンドは実践編にあります。

  判定では次を確かめます。

      この檻に /dev/kvm がある
      lab が /dev/kvm を読み書きで開ける
      lab が持てる特権の上限（CapBnd）が docker の既定のままで、いま効いている特権（CapEff）も 0

【できたら】

    lab check 02
