あなたの PC の端末で（いまの檻は exit で抜けておく。--rm なのでコンテナは消え、ボリュームは残る）:

    docker run --rm -it --name lab-kvm --hostname host \
      --device /dev/kvm --group-add "$(stat -c %g /dev/kvm)" \
      -v lab-kvm-vm:/home/lab/vm -v lab-kvm-state:/home/lab/.lab \
      （実践編に書いてあるイメージ名）

  "$(stat -c %g /dev/kvm)" は、docker を打つ前にあなたの PC のシェルが展開します。
  著者の PC では 302、Ubuntu 24.04 では 993 のような番号になります。

入ると、最初の行にこう出ることがあります（害は無い）:

    groups: cannot find name for group ID 302

  檻の中の /etc/group に、番号 302 の名前が無いからです。カーネルが知っているのは番号だけで、
  名前は各ファイルシステムの /etc/group が持っています（第2章）。

外（lab@host）で:

    ls -l /dev/kvm
    #=> crw-rw-rw- 1 root 302 10, 232 … /dev/kvm     ← 権限と番号はあなたの PC のまま
    id
    #=> uid=1000(lab) gid=1000(lab) groups=1000(lab),302
    grep -E '^(Groups|CapEff|CapBnd)' /proc/self/status
    #=> Groups:	302 1000
    #=> CapEff:	0000000000000000                    ← いま効いている特権は無い（lab は root ではない）
    #=> CapBnd:	00000000a80425fb                    ← 持てる特権の上限は docker の既定のまま

    lab check 02

【渡したものは2つだけ】

  --device /dev/kvm      … ファイル（番号 10, 232 の文字デバイス）を置き、その番号を開くことを
                           コンテナの device cgroup に許させる。誰でも読み書きできるファイルを自分で作っても
                           （sudo mknod -m 666）、この許可が無いので root でも開けない（Operation not permitted）。
                           -m を付けずに作ると 0644 になり、lab では先にファイルの権限で断られる（Permission denied。第2章）
  --group-add <番号>     … lab の補助グループに、/dev/kvm の持ち主のグループの番号を足す。
                           0660 の /dev/kvm を開けるのは、このグループに入っているから

  特権は1つも増えていません。それを示すのは CapBnd（このコンテナのプロセスが持てる特権の上限）で、
  docker の既定のまま（00000000a80425fb）です。--privileged で起動すると 000001ffffffffff に、
  --cap-add で足すとそのビットが増えます。CapEff（いま効いている特権）は、lab が root ではないので、
  --privileged で起動しても 0 のままです。CapEff だけを見ても、渡しすぎたかどうかは分かりません。

  lab（CapEff は 0）のまま KVM を使えたので、KVM を使うのに特権は要りません。
  /dev/kvm を開ける人なら誰でも、カーネルに仮想マシンを作ってもらえます。
