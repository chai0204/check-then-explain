外（lab@host）で打ちます。TCG の場合:

    qemu-linuc stop
    qemu-linuc -accel tcg -cpu qemu64,-svm
    ssh linuc
    lscpu | grep -E '^(Vendor ID|Model name|Virtualization):'
    #=> Vendor ID:                               AuthenticAMD
    #=> Model name:                              QEMU Virtual CPU version 2.5+
    #=>                                          （Virtualization の行が無い）
    ls -l /dev/kvm
    #=> ls: cannot access '/dev/kvm': No such file or directory
    exit

    lab check 05

KVM の場合（Intel の PC。AMD の PC なら -svm）:

    qemu-linuc stop
    qemu-linuc -accel kvm -cpu host,-vmx

【何が起きているか】

  練習機のカーネルは、CPU に CPUID で尋ねた答えに vmx か svm があるときだけ、kvm_intel か kvm_amd を
  読み込み、/dev/kvm を作ります。答えを返しているのは、TCG でも KVM でも、QEMU が用意した答えの表です
  （KVM のときは、本物の CPU と KVM が持つ機能しか表に載せられない）。どちらの場合も、QEMU に
  「この印は付けない」と頼めば、練習機のカーネルは仮想化支援の無い CPU だと信じ、KVM を用意しません。
  入れ子の仮想化ができるかどうかは、練習機に見せる CPU の印1つで決まります。

【もともと印を持たない型では、消したことにならない】

  Intel の PC で -cpu を付けずに KVM で起動すると、既定の型（qemu64）はもともと vmx を持たず、
  名乗っていた svm も KVM では外されるので、初めから印がありません（第5章）。TCG でも、Nehalem などの
  Intel の型は初めから vmx も svm も名乗りません。どちらも印を消した結果ではありません。
  ところが練習機の中から見えるのは「いまの印」だけで、その型がもともと印を名乗っていたかは分かりません。
  そこで判定は、名乗りの決まっている型だけを見分けて、
    TCG のとき … qemu64 か max の名乗り（メーカー・モデル名・型番）のままなのに、印が無い
                  （どちらも TCG では svm を名乗る型。EPYC など、ほかにも svm を名乗る型はあるが、判定はそれを見分けない）
    KVM のとき … あなたの PC の CPU を名乗っている（-cpu host。メーカー・モデル名・型番が同じ）のに、印が無い
  ことを求めます。モデル名だけを付け替えた型（model-id=…）は、型番で見分けます。
  あなたの PC の KVM が入れ子を許していない（nested が N / 0）ときは、-cpu host にも
  初めから印が無いので、KVM の判定は「前提不足」になります。TCG でやってください。
