外（lab@host）で打ちます。

    qemu-linuc stop
    qemu-linuc -accel kvm -cpu host
    #=> （▶ のコマンド行の最後の行が  -accel kvm -cpu host 。svm の警告は出ない）
    #=> 練習機が起動し終わりました（…）

    ssh linuc
    lscpu | grep -E '^(Vendor ID|Model name|Virtualization|Hypervisor vendor):'
    #=> Vendor ID:                               GenuineIntel
    #=> Model name:                              Intel(R) Core(TM) Ultra 9 285H     ← あなたの PC の CPU
    #=> Virtualization:                          VT-x
    #=> Hypervisor vendor:                       KVM
    ls -l /dev/kvm
    #=> crw-rw---- 1 root kvm 10, 232 … /dev/kvm   ← 練習機の中にも KVM がある（入れ子の仮想化）
    exit

    lab check 04

  モデル名と印は、あなたの PC の CPU のものが出ます（AMD の PC なら AuthenticAMD・AMD-V・svm）。

【-cpu host が見せるもの】

  -cpu host は、KVM が渡せる本物の CPU の機能を全部、練習機に見せます。仮想化支援の印（vmx）も
  含まれるので、練習機のカーネルは kvm_intel を読み込み、練習機の中にも /dev/kvm ができました。
  練習機の中で、さらに仮想マシンを KVM で動かせる状態です（入れ子の仮想化）。

  これができるのは、あなたの PC の KVM が入れ子を許しているときだけです。許しているかは
  あなたの PC（とこの檻）で見えます。

    cat /sys/module/kvm_intel/parameters/nested      # AMD の PC なら kvm_amd
    #=> Y

  N（AMD は 0）なら、-cpu host でも vmx は練習機に渡らず、練習機の中に /dev/kvm はできません。

  判定は、モデル名だけでなく、メーカーと型番（family・model・stepping）も比べます。
  -cpu qemu64,model-id=… のように、名前だけをあなたの PC の CPU に付け替えた型は合格しません。

  TCG で -cpu host を頼むと、QEMU は起動しません。

    qemu-linuc -accel tcg -cpu host
    #=> qemu-system-x86_64: CPU model 'host' requires KVM or HVF
