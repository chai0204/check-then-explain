外（lab@host）で打ちます。

    qemu-linuc stop                  # TCG の練習機が動いていれば止める
    qemu-linuc -accel kvm
    #=> （▶ のコマンド行の最後の行が  -accel kvm ）
    #=> qemu-system-x86_64: warning: host doesn't support requested feature: CPUID.80000001H:ECX.svm [bit 2]
    #=> qemu-system-x86_64: warning: host doesn't support requested feature: CPUID.80000001H:ECX.svm [bit 2]
    #=> 練習機が起動し終わりました（QEMU を起動してから …秒。カーネルの最初の表示は …秒の時点）

  警告は Intel の CPU の PC で出ます（AMD の PC でも、kvm_amd の nested が 0 なら出る）。既定の CPU のモデル
  （qemu64）は AMD の仮想化支援（svm）を名乗るが、KVM は本物の CPU と KVM が持っている機能しか練習機に
  渡せないので、QEMU が「その印は付けられない」と断っています。

    readlink /proc/$(pgrep qemu)/fd/* | grep kvm
    #=> /dev/kvm
    #=> anon_inode:kvm-vm
    #=> anon_inode:kvm-vcpu:0
    #=> anon_inode:kvm-vcpu-stats:0
    #=> anon_inode:kvm-vcpu:1
    #=> anon_inode:kvm-vcpu-stats:1

  QEMU は /dev/kvm を開き、カーネルに仮想マシン（kvm-vm）と仮想の CPU 2個（kvm-vcpu:0・1）を作ってもらい、
  それをファイルとして持っています。練習機の命令は、このファイルを通して本物の CPU が直接実行します。
  （kvm-vcpu-stats は Linux 5.14 より古いカーネルの PC では出ません。）

    ssh linuc
    journalctl --no-pager -o cat -g 'Detected virtualization|Startup finished in .*kernel'
    #=> Detected virtualization qemu.
    #=> Startup finished in …s (kernel) + …s (userspace) = …s.        ← TCG の起動
    #=> Detected virtualization kvm.
    #=> Startup finished in …ms (kernel) + …s (userspace) = …s.       ← KVM の起動
    exit

  起動のたびに2行ずつ、起動した順に並びます。qemu・kvm は、起動のときに練習機が自分で名乗ったもので、
  -cpu …,kvm=off で起動すると KVM の上でも qemu と記録されます（第5章。本文では -snapshot を付けて残さない）。
  だから判定は、KVM かどうかを readlink と同じ QEMU のファイルで決め、この記録は時間を並べるのに使います。

    lab check 03

  時間はあなたの PC で変わります。同じディスク・同じ OS なのに、中の OS が数えたユーザ空間の時間が
  10 倍ほど違います。ただし外で測った時間（QEMU を起動してから起動し終わるまで）は、そこまでは縮みません（第4章）。

【-enable-kvm】

  -accel kvm の古い書き方が -enable-kvm です（-machine accel=kvm と書く例もある）。どれも同じように
  /dev/kvm を開きます。qemu-linuc -enable-kvm で起動して、readlink で確かめられます。
