名前から . を外し、実行権を付けます。そのうえで anacron に今日の分を走らせます。

    sudo mv /etc/cron.daily/lab-backup.sh /etc/cron.daily/lab-backup
    sudo chmod 755 /etc/cron.daily/lab-backup
    run-parts --test /etc/cron.daily
    #=> /etc/cron.daily/0anacron
    #   /etc/cron.daily/apport
    #   /etc/cron.daily/apt-compat
    #   /etc/cron.daily/dpkg
    #   /etc/cron.daily/lab-backup        ← 選ばれた
    #   /etc/cron.daily/man-db

    sudo anacron -f -n -s -d
    #=> Anacron 2.3 started on 2026-10-13
    #   Will run job `cron.daily'
    #   Will run job `cron.weekly'
    #   Will run job `cron.monthly'
    #   Jobs will be executed sequentially
    #   Job `cron.daily' started
    #   Job `cron.daily' terminated
    #   …
    #   Normal exit (3 jobs run)
    cat /var/backups/lab-backup.log
    #=> 2026-10-13 10:55:02 lab-backup ran

【chmod だけでは選ばれない】

  Debian 系の run-parts は名前に . を含むファイルを飛ばします（--lsbsysinit を付けたときなどは規則が変わる。
  RHEL 系の run-parts は別の実装で、backup.sh のような名前も走らせます）。
  パッケージが残す設定の退避ファイル（foo.dpkg-old など）を誤って実行しないための決まりです。
  拡張子 .sh を付ける習慣が、ここではそのまま「走らない理由」になります。エラーもログも出ません。

【誰が cron.daily を走らせているか】

  /etc/crontab の cron.daily の行は test -x /usr/sbin/anacron || … となっていて、anacron が入っていれば
  cron は何もしません。代わりに anacron が /etc/anacrontab の

    1   5   cron.daily   run-parts --report /etc/cron.daily

  に従って、「前回から1日以上たっていれば、5分待ってから」走らせます。前回の日付は
  /var/spool/anacron/cron.daily に書かれています。この Ubuntu では、起動時（anacron.service）と、
  7時から23時の毎時30分（anacron.timer）に anacron が起きて確かめます。
  RHEL 系では cron が毎時01分に /etc/cron.d/0hourly で /etc/cron.hourly を走らせ、その中の 0anacron が anacron を起こします。

【-f -n -s -d の意味】

    -f  日付を見ずに全部走らせる（今日もう走っていても）
    -n  待ち時間（5分）を飛ばす
    -s  ジョブを1つずつ順に走らせる
    -d  バックグラウンドに回らず、経過を端末に出す

  起動から15分ほどは、起動時に動いた anacron が cron.weekly と cron.monthly の順番待ちでロックを持っています。
  そのあいだは「locked by another anacron - skipping」と出て、その2つは飛ばされます（cron.daily が済んでいれば判定には響きません）。
