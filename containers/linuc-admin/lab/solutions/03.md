アカウントの有効期限を過去にします。鍵もファイルも残したまま、どの入口からも入れなくなります。

    sudo usermod -e 1 dave
    sudo chage -l dave | grep 'Account expires'
    #=> Account expires						: Jan 02, 1970
    sudo grep '^dave:' /etc/shadow
    #=> dave:!:…:0:99999:7::1:              ← 8列目が 1（1970-01-02。とうに期限切れ）

外の端末で:

    ssh -l dave linuc id
    #=> Your account has expired; please contact your system administrator.
    #   Connection closed by 127.0.0.1 port 2222

練習機の中で:

    sudo su - dave -c id
    #=> Your account has expired; please contact your system administrator.
    #   su: Authentication failure

戻すときは:

    sudo usermod -e '' dave

【passwd -l では止まらない】

    sudo passwd -l dave
    ssh -l dave linuc id            （外の端末）
    #=> uid=1002(dave) gid=1002(dave) groups=1002(dave)     ← 入れてしまう

  passwd -l は /etc/shadow の2列目の頭に ! を足して、パスワードの照合を必ず失敗させます
  （この Ubuntu では usermod -L と同じ !。RHEL 系の passwd -l は !! を足し、usermod -L は ! を足します）。
  鍵の ssh はパスワードを照合しないので、この列を読みません。man passwd にもそう書いてあります
  （"this does not disable the account ... To disable the account, administrators should use usermod --expiredate 1"）。

【止め方の比較】

    止め方                          パスワード  鍵の ssh   su（root から）
    passwd -l / usermod -L          止まる      止まらない  止まらない
    usermod -e 1 / chage -E 1       止まる      止まる      止まる
    usermod -s /usr/sbin/nologin    止まる      止まる      止まる（シェルが断る）※
    authorized_keys を消す           止まらない  止まる      止まらない

  期限（8列目）は PAM のアカウント検査が毎回読み、シェル（7列目）はログインのたびに起動されます。
  だから入口を問わず効きます。
  ※ root だけは su -s /bin/bash dave のように別のシェルを指定して入れます（root は何でもできるので、止める対象ではありません）。
  chage -E は日数で指定します。0 は「1970-01-01」と「期限なし」の扱いが実装で揺れるので、1 を使います。
