ユーザの表は5列＋コマンド、/etc/cron.d は6列目に実行ユーザを書きます。

    crontab -e
        * * * * * date >> /home/student/tick.log          ← この1行を書いて保存

    echo '* * * * * root id -un >> /var/log/lab-whoami.log' | sudo tee /etc/cron.d/lab-whoami

  crontab -e の代わりに、表を丸ごと渡すこともできます（今ある表は置き換わります）。

    echo '* * * * * date >> /home/student/tick.log' | crontab -

1分待ってから:

    tail -1 /home/student/tick.log
    #=> Tue Oct 13 11:05:01 JST 2026
    tail -1 /var/log/lab-whoami.log
    #=> root

【よくある間違い1 — ユーザの表に6列目を書く】

    * * * * * student date >> /home/student/tick.log

  cron は5列のあとを全部コマンドとして sh に渡します。sh は student というコマンドを探して失敗します。
  >> のリダイレクトはコマンドを探す前に処理されるので、tick.log は**空のファイルとしてできてしまいます**。
  エラーはジョブの出力としてメールで送られますが、この練習機には MTA が無いので捨てられます。
  2>&1 を足すと、ファイルの中にエラーが残ります。

    #=> /bin/sh: 1: student: not found

【よくある間違い2 — /etc/cron.d に実行ユーザを書かない】

    * * * * * id -un >> /var/log/lab-whoami.log

  cron は6列目の id をユーザ名として読み、そんなユーザはいないのでファイルごと捨てます。ログに出ます。

    journalctl -u cron | grep lab-whoami
    #=> Error: bad username; while reading /etc/cron.d/lab-whoami
    #=> (*system*lab-whoami) ERROR (Syntax error, this crontab file will be ignored)

【よくある間違い3 — ファイル名に . を入れる】

  /etc/cron.d/lab-whoami.cron のように . を含む名前は、エラーも出さずに無視されます
  （Debian 系の cron の決まり。run-parts と同じ名前の規則）。

【どこに保存されているか】

  crontab -e で書いた表は /var/spool/cron/crontabs/student にあります（Debian 系。RHEL 系は /var/spool/cron/student）。
  ファイル名がユーザ名なので、
  中に実行ユーザを書く必要がありません。直接編集せず、必ず crontab コマンドを通します。

    sudo ls -l /var/spool/cron/crontabs/

【片づけ】

    crontab -r
    sudo rm /etc/cron.d/lab-whoami
